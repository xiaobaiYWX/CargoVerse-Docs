## 三种状态

- **已实现**：已有当前代码／数据契约，注明源类与自动化或实机验证范围。
- **预留**：仅设计、占位入口或字段解析，没有完整功能；禁止使用“自动获得”等已生效语气。
- **待验收**：已有实现需要回归，或存在已知差异；注明复现条件、当前行为和通过标准。

一页可混合三种状态；不要用“全部完成”覆盖页面内的已知问题。具体清单统一维护于[重构状态与验收](../00_重构状态与验收清单.md)。

## 维护规则

1. 数据入口说明只给当前路径；废弃字段放在明确的移除说明或历史中。
2. JSON 示例不含说明注释，完整示例须引用真实有效资源；字段片段注明不是完整定义。
3. 修改字段同步更新示例、模板、命令、UI 数据来源和索引。
4. 版本号集中在运行时／状态页面，不从旧阶段记录复制。
5. 术语区分设备耐久、货物完整度、数量 t、质量，以及定义 ID 与实例 ID。
6. 不将保留的实体接口方块与已移除的容器接口参数混为一谈。
7. 不将测试通过写成实机验收通过；记录实际测试日期和范围。
8. 货币／地图／轨道等未全面重审的系统保持独立规范，不在整编中改动实现。

## 验收与归档

正式文档可以先行描述当前实现，不必等待所有预留玩法。临时重构目录整体结案仍以状态清单 R1～R5 及实机检查为准，未验收不能删掉这些限制说明。
