# 按变更范围选择验证

更新：2026-10-21。日常调整按影响范围运行验证，不默认重跑全量单元测试或全量服务端 GameTest。

| 变更 | 通常需要的验证 |
| --- | --- |
| 文档、索引 | 相关本地链接、参数与运行数据对账 |
| 逐物品属性、运输参数 | 只读属性核验、逐 ID 对账、相关运输规则与快照测试 |
| 质量计算、载荷状态 | 运输规则、载荷与冻结快照／存档的针对性单元测试 |
| 注册、标签加载、真实方块交互 | 增加受影响的服务端 GameTest 或开发存档检查 |
| 公共协议、广泛生命周期或跨系统重构 | 评估扩大测试集；发布验收可安排全量测试 |

执行前说明本次范围；发现问题后按证据扩大验证，不因小参数调整无条件跑完整服务器回归。没有执行的全量测试或实机工况应明确列为未验证，不复用旧结果冒充本次运行。

开发客户端运行期间不要重编译其正在读取的输出目录；先退出客户端，或使用独立 buildDirectory 做验证。Windows 测试类路径 JAR 按构建目录独立命名，并将实际绝对路径作为任务输入，避免隔离构建覆盖普通构建的类路径。运行中的客户端不会自动载入新编译类，代码修改应重启开发运行后验收。

例如本次运输质量更新仅运行：

```powershell
./gradlew.bat test --tests 'cn.or15.cargoverse.cargo.transport.*' --tests 'cn.or15.cargoverse.cargo.item.*' --tests 'cn.or15.cargoverse.cargo.CargoContainerSavedDataTest'
node tools/verify-item-properties.cjs
```

校验器只读取逐物品属性，不从文档生成或覆盖 JSON。修改对应物品文件后再更新文档投影；不补回已经删除的共享分组或成员标签。

千件运力、满柜起吊和航线平衡属于独立实机验证，不由单元测试替代。

载荷、身份、保存或装卸会话拆分可选择两组世界回归，不必启动全部其他系统：

```powershell
./gradlew.bat runGameTestServer '-PgameTestNamespaces=cargoverse_transport,cargoverse_logistics'
```

`cargoverse_transport` 覆盖真实物品载荷、隔离、时限、规则升级、交易回滚及自然目的地经验；`cargoverse_logistics` 覆盖玩家网络、区域、仓库管理和确认会话。修改计量时同时选择 `CargoMeasureTest`、`CargoContentContractTest` 及 `CargoTransferBackendTest` 等相关单元测试。默认全量 GameTest 包含这两组，不能因拆分命名空间而遗漏发布验收。
