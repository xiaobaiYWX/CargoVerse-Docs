# 数据包维护流程

## 数据入口

下表路径均相对 `data/<namespace>/`：

| 路径 | 用途 |
| --- | --- |
| `cargo_goods/<class>/<good>.json` | 具体货物定义 |
| `cargo_containers/<path>.json` | 货柜型号定义 |
| `manufacturers/<path>.json` | 制造商等级、货物偏好与签约价格修正 |
| `currency_groups/<path>.json` | 货币组 |
| `player_profiles/<path>.json` | 许可证等级门槛、调度点与雷达统计参数 |
| `starter_containers/<path>.json` | 基础货柜资格映射 |
| `trade_points/production_line_pools/<type>/<category>/<pool>.json` | 生产线池 |
| `trade_points/trade_points_definitions/<type>/<category>/<name>.json` | 贸易点定义 |
| `trade_points/trade_points_subfunctions/shop_definitions/<path>.json` | 物品商店定义 |
| `trade_points/trade_points_subfunctions/cargo_manufacturing_platform_definitions/<path>.json` | 货柜制造台定义 |
| `trade_points/trade_points_subfunctions/registration_point_definitions/<path>.json` | 注册点定义 |
| `trade_point_structure_bindings/<factory\|market\|resource>/<path>.json` | 世界结构与贸易点定义绑定 |
| `structure/<path>.nbt` | 货柜与建筑结构模板 |
| `physics_block_properties/<path>.json` | Sable 方块物理属性 |

子功能定义的资源 ID 不包含子目录名称。例如：

```text
data/cargoverse/trade_points/trade_points_subfunctions/registration_point_definitions/oasis.json
-> cargoverse:oasis
```

生产线池、贸易点定义和结构绑定中的 `type` 只使用 `resource`、`factory`、`market`，结构绑定类别必须与目标贸易点定义一致。

## 编写顺序

1. 定义货币组与 CargoGood。
2. 定义制造商、货柜型号、基础货柜映射和结构模板。
3. 定义生产线池及其输入选择器和输出货物。
4. 定义商店、货柜制造台与注册点子功能。
5. 定义贸易点，填写制造商、库存、价格、活跃度、繁荣度、生产池和模块引用。
6. 定义世界结构绑定，并在结构中布置贸易点信息柜、业务终端和所需定位点。
7. 执行 `/reload`，检查服务端日志后在测试世界验证完整业务链。

字段格式分别见[货物类型](../01货柜系统/01核心系统/05_货物类型.md)、[货柜定义](../01货柜系统/01核心系统/02_货柜定义系统.md)、[制造商定义](../01货柜系统/01核心系统/08_制造商定义.md)、[生产线池](../02贸易点系统/03_生产线池定义.md)、[贸易点定义](../02贸易点系统/04_贸易点定义.md)、[货柜制造台定义](../02贸易点系统/05_货柜制造台定义.md)和[注册点与基础货柜定义](../02贸易点系统/06_注册点与基础货柜定义.md)。

## 加载与发布

货物、制造商、货柜、基础货柜、三个贸易点子功能、生产线池、贸易点定义和结构绑定在同一数据快照中解析并完成交叉引用校验。任一资源出现未知字段、悬空引用、非法 ID、重复绑定或数值越界时，本轮数据不会部分发布。

同一资源 ID 按数据包优先级覆盖整项定义；数组不会自动拼接。删除或改名资源前必须检查全部引用。

玩家档案定义由独立监听器加载，并要求 `cargoverse:default` 存在。执行 `/reload` 后，服务端目录完成发布并向客户端同步展示所需的名称与图标资源 ID。

## 运行时数据边界

- 已制造货柜保存设备、兼容性和当前 Load 快照；
- 已注册贸易点保存抽中的生产线、输入绑定和模块定义 ID，不因重载重新随机抽取；
- 同一定义重新注册时会同步解锁等级、补充新增模块并移除定义中已删除的模块；
- 已抽中的定义在重载后不存在时，对应功能不可用，不会换成其他候选；
- CargoGood 缺失时保留已有资产与库存标识，但相关生产或交易停止；
- 手动放置的终端和定位点必须显式绑定，不使用默认贸易点或终端坐标回退。

## 构建检查

在模组工程根目录执行：

```powershell
.\gradlew.bat build --no-daemon test --rerun
```

构建负责资源、单元测试和 GameTest 预检；世界表面位置、多人竞争、运动结构与视觉效果仍需在 Minecraft 客户端检查。
