# 数据包维护流程

本文只记录当前开发格式。项目不保留旧格式兼容入口。

## 当前数据入口

| 目录 | 用途 |
| --- | --- |
| `cargo_definitions` | 货柜模板、可用 CargoType、倍率和词条。 |
| `cargo_value_constants` | CargoType 基础数值、货柜等级倍率与 `cargo_units`。 |
| `trade_points` | 贸易点资源方向、库存、生产、经济和出售模板池。 |
| `trade_point_structure_bindings` | 世界结构池与贸易点定义的加权绑定。 |
| `shop_definitions` | 普通物品商店商品。 |
| `shipping_stats_config` | 航运统计参数。 |
| `physics_block_properties` | Sable 方块物理属性。 |

已经删除且不得继续使用的旧入口：

- `cargo_terminal_definitions`
- `market_economy`
- `shipping_license`
- 独立 `cargo_sales` / `cargo_buybacks`

## 1. 制作货柜模板

结构保存到：

```text
data/<namespace>/structure/<path>.nbt
```

模板可以包含普通货柜方块、静态贴花、CargoType/Affixes 占位贴花和 `cargoverse:cargo_mass_placeholder`。质量占位方块用于在生成时补足数据包计算质量；没有占位方块时仍允许生成，但最终使用模板实际质量。

## 2. 编写货柜定义

文件位置：

```text
data/<namespace>/cargo_definitions/<path>.json
```

```json
{
  "template": "example:aui/atlas_s",
  "display_name": "Atlas S",
  "cargo_description": "示例货柜",
  "currency_id": "minecraft:emerald",
  "max_owned": 10,
  "cargo_level": "S",
  "max_integrity": 100,
  "cargo_type": {
    "ore": {
      "weight": 1,
      "mass_modifier": 1.0,
      "cargo_units_modifier": 1.0,
      "price_modifier": 1.0,
      "license_modifier": 1.0,
      "prosperity_modifier": 1.0,
      "affixes": []
    }
  }
}
```

- `cargo_type` 必须是对象。
- 类型倍率省略时均为 `1.0`；`cargo_units_modifier` 会按 CargoType 修正等级常量中的基础 `cargo_units`。
- 每个类型只读取前五个词条。
- 具体基础质量、价格和经验来自 `cargo_value_constants`。

## 3. 配置贸易点

文件位置：

```text
data/<namespace>/trade_points/<path>.json
```

- `output_resources` 定义贸易点产出的 CargoType、产出库存上限、自然增长和生产配方。
- `consumed_resources` 定义贸易点收购的 CargoType 及 `inputs_cargo_units` 库存。
- `cargo_sale.cargo` 只定义可参与出售列表抽取的货柜模板。
- 收购终端不使用模板白名单，只校验实际货柜 CargoType 是否存在于 `consumed_resources`。
- 普通出售货柜不维护独立货柜库存；购买时直接按货柜 `cargo_units` 扣除对应 `output_cargo_units`。

当前出售条目字段：

```json
{
  "cargo_definition": "example:aui/atlas_s",
  "weight": 1,
  "always_available": false,
  "required_prosperity": 0
}
```

## 4. 配置结构绑定

每个完整世界结构使用一个独立绑定文件：

```text
data/<namespace>/trade_point_structure_bindings/<path>.json
```

```json
{
  "structures_pool": "example:cloud_farm",
  "trade_point_id": [
    {
      "id": "example:cloud_farm",
      "weight": 1
    }
  ]
}
```

未填写或没有有效 `trade_point_id` 时自动使用 `cargoverse:default`。结构生成时会创建贸易点唯一 UUID，并直接写入结构内的全部终端。

## 5. 重载核验

修改数据包后执行：

```text
/reload
```

重点检查：

1. 货柜定义 CargoType 与贸易点资源方向是否有交集。
2. `cargo_value_constants` 是否包含所用 CargoType 和货柜等级。
3. 生产配方的输入类型是否启用了 `consumed_resources.<type>.inventory`。
4. 结构绑定的 `structures_pool` 是否与实际世界结构注册 ID 一致。
5. 终端是否共享结构生成时注入的贸易点 UUID。

数据包重载不会清空贸易点列表、投入库存、产出库存或交易日时间。
