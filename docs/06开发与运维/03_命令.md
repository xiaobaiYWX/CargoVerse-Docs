# 命令

> 已实现：货柜生成指令只创建空货柜，并新增向既有货柜添加指定货物的管理员指令。待验收：测试世界中的实际调用结果。命令会改变游戏状态，文档整编没有执行这些游戏内命令。

## 1. 章节用途

本文档集中记录 Cargoverse 项目实际注册的全部游戏内指令。

后续新增、删除或调整指令时，应统一更新本章节，至少记录：

- 完整语法；
- 所需权限；
- 参数范围；
- 对存档和游戏状态的影响；
- 玩家、命令方块与服务器控制台的使用差异；
- 一个可直接使用的示例。

当前所有项目指令都以 `/cargoverse` 为根节点。

## 2. 通用规则

### 2.1 权限

`/cargoverse` 根节点要求原版命令权限等级 2。

通常意味着：

- 单人游戏需要开启作弊；
- 多人服务器玩家需要具有足够的管理员权限；
- 服务器控制台可以直接执行；
- 命令方块需要服务器允许命令方块运行。

### 2.2 玩家选择器

带有 `[targets]` 的指令使用原版玩家选择器，支持：

```text
@s
@p
@a
@r
玩家名称
```

省略 `[targets]` 时，目标默认为执行指令的玩家。

服务器控制台不是玩家，因此从控制台执行这类指令时必须明确填写目标玩家。

### 2.3 参数记号

- `<参数>`：必填参数；
- `[参数]`：可选参数；
- `A|B`：从列出的值中选择一个；
- 指令中的 ID 区分实际含义，`tradePointId` 不是贸易点定义 ID。

## 3. 运输许可证

### 3.1 重置许可证

语法：

```text
/cargoverse license reset [targets]
```

作用：

- 将目标玩家的运输许可证经验和等级重置；
- 直接修改 `CargoShippingLicenseSavedData`；
- 不会删除玩家拥有的货柜；
- 不会重置航运风格统计或贸易点数据。

示例：

```text
/cargoverse license reset
/cargoverse license reset PlayerName
/cargoverse license reset @a
```

第一条重置执行者本人，第二条重置指定玩家，第三条重置所有在线玩家。

### 3.2 设置许可证等级

语法：

```text
/cargoverse license set <S|M|L|X|XL> [targets]
```

该指令是用于测试许可证登记显示和等级限制的管理员命令。

作用：

- 将目标玩家的运输许可证经验设置为所选等级在当前玩家档案定义中的最低经验门槛；
- 可选等级及经验门槛来自数据包中的 `data/cargoverse/player_profiles/default.json`，不是写死在命令中的固定经验值；
- 修改 `CargoShippingLicenseSavedData`，并使许可证等级、调度点上限及航运档案中的叠加印章在重新读取数据后同步变化；
- 不会修改航运风格统计、已有货柜、贸易点库存或其他玩家档案字段；
- 不会隐式登记航运档案。未在执照办理终端登记的目标会被跳过；若所有目标都未登记，则命令失败且不修改数据。

`targets` 只能选择当前在线玩家。省略时以执行者本人为目标；服务器控制台和命令方块执行时必须填写目标。

示例：

```text
/cargoverse license set M
/cargoverse license set XL PlayerName
/cargoverse license set L @a
```

第一条将执行者设为 M 级，第二条将指定玩家设为 XL 级，第三条将所有已登记的在线玩家设为 L 级。执行后重新打开“玩家航运档案”即可查看对应许可证印章。

## 4. 航运风格统计

### 4.1 重置航运风格统计

语法：

```text
/cargoverse shipping_stats reset [targets]
```

作用：

- 重置目标玩家的航运风格统计；
- 直接修改 `PlayerShippingStyleSavedData`；
- 清除已完成航段历史，以及目标玩家各货柜尚未完成的候选航段；
- 不会重置运输许可证；
- 不会删除货柜实例。

示例：

```text
/cargoverse shipping_stats reset
/cargoverse shipping_stats reset PlayerName
/cargoverse shipping_stats reset @a
```

## 5. 管理员模式

### 5.1 开启管理员模式

语法：

```text
/cargoverse admin_mode on [targets]
```

作用：

- 为目标玩家开启 Cargoverse 管理员模式；
- 允许玩家使用大型货柜制造台、贸易点信息柜、货柜装载机、货物卸载机及旧收购终端等现存配置入口；装饰性的旧贸易点终端没有配置功能；
- 绕过货柜实例的全部玩家操作保护，包括方块破坏、方块放置、左右键交互、物品右键、贴花扳手缩放和 Simulated 蜂蜜胶合并限制；
- 状态按玩家 UUID 保存；
- 不等同于授予原版 OP 权限。

绕过仅对开启管理员模式的玩家本人执行的操作生效。仅拥有原版 OP 权限但未开启管理员模式时，货柜保护仍然生效；自动化、环境破坏和其他玩家的操作也不会因为某位管理员开启了该模式而被全局放行。

示例：

```text
/cargoverse admin_mode on
/cargoverse admin_mode on PlayerName
/cargoverse admin_mode on @a
```

### 5.2 关闭管理员模式

语法：

```text
/cargoverse admin_mode off [targets]
```

作用：

- 关闭目标玩家的 Cargoverse 管理员模式；
- 不会撤销原版 OP 权限；
- 不会回滚玩家此前保存的终端配置。

示例：

```text
/cargoverse admin_mode off
/cargoverse admin_mode off PlayerName
/cargoverse admin_mode off @a
```

## 6. 贸易点

### 6.1 手动推进交易日

语法：

```text
/cargoverse trade_point advance <tradePointId>
/cargoverse trade_point advance <tradePointId> <days>
```

参数：

- `tradePointId`：游戏世界内贸易点实例的共享 ID，不是数据包中的贸易点定义 ID；
- `days`：需要跨越的交易日数量，可选，范围为 1～10000，省略时默认为 1。

按请求跨越的天数结算：

- 当前日有效交易价值与后续空白天活跃度衰减；
- 保存产线的生产倍率、输入消耗和输出余量限制；
- 具体 CargoGood 的动态价格恢复与待结算交易变化。

通过公式汇总离线区间，不逐日循环生产；库存保留小数。

执行完成后：

- 贸易点仍以服务器当前真实 `gameTime` 作为正常计时基准；
- 不会把正常下一交易日推迟额外的 `days` 天；
- 不会改变原版世界昼夜时间；
- 不会修改数据包中的 `ticks_per_day`；
- 不会重抽已保存的生产线／输入绑定；库存会按此次生产结果改变。

目标贸易点必须：

- 已由贸易点主终端注册；
- 位于指令执行者当前维度；
- 注册信息仍然有效。

如果贸易点不存在、未注册或位于其他维度，指令失败且不会修改经济状态。

示例：

```text
/cargoverse trade_point advance aa7f0caa-b50d-4e26-8a9e-8204eb
/cargoverse trade_point advance aa7f0caa-b50d-4e26-8a9e-8204eb 7
```

第一条推进一个交易日，第二条按七个交易日进行汇总结算。

天数范围仍为 1～10000。该命令会实际修改测试贸易点库存与经济状态，不是只读预览；请对测试实例使用。

## 7. 货柜管理员指令

### 7.1 生成空货柜

语法：

```text
/cargoverse summon <货柜容器定义ID> <X> <Y> <Z>
```

当前命令不再接收 CargoType／CargoGood 参数，只生成空货柜：

```text
/cargoverse summon cargoverse:aui/atlas_sd_s ~ ~1 ~
/cargoverse summon cargoverse:aui/atlas_sd_x 100 80 -20
```

- 需要权限等级 2；定义必须已加载并提供补全。
- 坐标是底面中心，支持相对坐标，目标区块必须已加载。
- 不扣货币或库存、不记购买交易；不是正式玩家获取货柜流程。
- 创建容器快照、满耐久和空 Load，执行模板放置、空柜贴花解析、质量占位、物理化及资产登记。该指令没有任何能够预装货物的参数。
- 玩家执行时归该玩家；控制台／命令方块使用系统零 UUID。
- 空间被占、模板缺失或物理生成失败会返回失败。

成功消息会返回新货柜的实例 ID。向该货柜添加测试货物时，需要把这个数字传给下一条指令。

### 7.2 向既有货柜添加货物

语法：

```text
/cargoverse container add_cargo <containerId> <cargoGoodId> <units>
```

参数：

- `containerId`：目标货柜的数字实例 ID，必须大于 0；
- `cargoGoodId`：已加载的 CargoGood 完整 ID，提供数据包补全；
- `units`：精确添加的货物单位数，范围为 1～1000000。

示例：

```text
/cargoverse container add_cargo 42 cargoverse:raw_resource/ore 12
```

该示例向实例 ID 为 `42` 的货柜添加 `12` 单位矿石类货物。

执行规则：

- 需要权限等级 2，可由玩家、命令方块或服务器控制台执行；
- 目标必须是已登记、有效且处于活动状态的货柜实例；
- 货柜必须允许该 CargoGood 所属的货物分类；
- 空货柜可以装入指定货物；已有货物时，只允许继续添加同一种 CargoGood；
- 指令按 `<units>` 精确添加，不会自动截断。剩余容量不足时整条指令失败且不修改货柜；
- 新装货物以完整度 `100%` 加入；继续装入同类货物时，沿用既有词条状态并按数量合并完整度；
- 货物快照、运输要求、货柜特殊设计和设计缺陷与正常装货流程采用相同的解析规则；
- 成功后会保存 Load，并安排刷新货柜物理质量和货物贴花；
- 不扣除贸易点库存、不收取货币、不生成购买记录，也不计入玩家航运风格统计或运输许可证经验。

这是用于构造测试状态的管理员指令，不替代正式的货柜装载机流程。

## 8. 接口负载监控

### 8.1 监控物理结构的接口负载

语法：

```text
/cargoverse physics monitor @v <time>
```

参数：

- `@v`：Sable 的“视线指向结构”选择器，选择执行玩家当前看向的单个 Sable 物理结构；
- `time`：监控时间，单位为秒，范围为 1～3600。

作用：

- 命令开始时记录目标结构 UUID，执行玩家之后移开视线不会改变监控目标；
- 无论选中的是连接器所在结构还是与其连接的货柜结构，都会监控两者之间的同一货柜接泊约束；
- 每个 Sable 物理子步采样一次换算后的线性载荷、角向载荷和接口负载率；
- 每秒向执行玩家输出该秒内三项数据各自的峰值；
- 监控到期后自动结束，不修改 SavedData、世界方块、物理结构或接口阈值；
- 同一玩家再次执行该命令会替换其当前监控会话。

输出格式：

```text
线性载荷=12345.678，角向载荷=4567.890，接口负载率=36.25%
```

三项峰值分别独立统计，不保证来自同一个物理子步。该输出主要用于采集载具普通启停、急刹、转向和碰撞时的实际接口负载，以调整 `linearCapacityPerConnector` 和 `angularCapacityPerConnector`。

使用限制：

- 需要原版命令权限等级 `2`；
- 必须由在线玩家执行，因为 `@v` 依赖玩家视线，服务器控制台和命令方块无法使用；
- 目标结构必须存在与货柜连接器建立的有效接泊约束，否则对应采样周期输出为零；
- 命令只负责观测，不会禁止接口按当前阈值正常超载断裂。

示例：

```text
/cargoverse physics monitor @v 30
```

该命令监控执行玩家当前看向的 Sable 物理结构 30 秒。

接口载荷、有效连接器数量与断裂阈值的计算方式详见[货柜连接器与货柜接口](../03功能方块/02_货柜连接器与货柜接口.md#超载断裂与阈值计算)。

## 10. 后续维护约定

新增指令时需要同步完成：

1. 在代码中注册命令并设置明确的权限要求；
2. 为成功和失败反馈添加本地化键；
3. 在本文档增加独立小节；
4. 更新“当前指令速查”表；
5. 说明指令是否修改 SavedData、世界方块、货柜实例或玩家数据；
6. 对批量参数设置硬上限，避免误操作造成长时间主线程阻塞；
7. 若指令只用于测试，应明确标注，避免整合包正式服务器误用。
