# 命令

## 1. 章节用途

本文档集中记录 Cargoverse 项目实际注册的全部游戏内指令。

后续新增、删除或调整指令时，应统一更新本章节，至少记录：

- 完整语法；
- 所需权限；
- 参数范围；
- 对存档和游戏状态的影响；
- 玩家、命令方块与服务器控制台的使用差异；
- 一个可直接使用的示例。

当前所有项目指令都以 `/cargoverse` 为根节点。

## 2. 通用规则

### 2.1 权限

`/cargoverse` 根节点要求原版命令权限等级 2。

通常意味着：

- 单人游戏需要开启作弊；
- 多人服务器玩家需要具有足够的管理员权限；
- 服务器控制台可以直接执行；
- 命令方块需要服务器允许命令方块运行。

### 2.2 玩家选择器

带有 `[targets]` 的指令使用原版玩家选择器，支持：

```text
@s
@p
@a
@r
玩家名称
```

省略 `[targets]` 时，目标默认为执行指令的玩家。

服务器控制台不是玩家，因此从控制台执行这类指令时必须明确填写目标玩家。

### 2.3 参数记号

- `<参数>`：必填参数；
- `[参数]`：可选参数；
- `A|B`：从列出的值中选择一个；
- 指令中的 ID 区分实际含义，`tradePointId` 不是贸易点定义 ID。

## 3. 运输许可证

### 3.1 重置许可证

语法：

```text
/cargoverse license reset [targets]
```

作用：

- 将目标玩家的运输许可证经验和等级重置；
- 直接修改 `CargoShippingLicenseSavedData`；
- 不会删除玩家拥有的货柜；
- 不会重置航运统计或贸易点数据。

示例：

```text
/cargoverse license reset
/cargoverse license reset PlayerName
/cargoverse license reset @a
```

第一条重置执行者本人，第二条重置指定玩家，第三条重置所有在线玩家。

## 4. 航运统计

### 4.1 重置航运统计

语法：

```text
/cargoverse shipping_stats reset [targets]
```

作用：

- 重置目标玩家的航运统计；
- 直接修改 `PlayerShippingStatsSavedData`；
- 清除运输次数、收益、平均完整度、承运时间和累计重量等统计；
- 不会重置运输许可证；
- 不会删除货柜实例。

示例：

```text
/cargoverse shipping_stats reset
/cargoverse shipping_stats reset PlayerName
/cargoverse shipping_stats reset @a
```

## 5. 管理员模式

### 5.1 开启管理员模式

语法：

```text
/cargoverse admin_mode on [targets]
```

作用：

- 为目标玩家开启 Cargoverse 管理员模式；
- 允许玩家使用贸易点终端、出售终端、收购终端等界面中的管理配置功能；
- 绕过货柜实例的全部玩家操作保护，包括方块破坏、方块放置、左右键交互、物品右键、贴花扳手缩放和 Simulated 蜂蜜胶合并限制；
- 状态按玩家 UUID 保存；
- 不等同于授予原版 OP 权限。

绕过仅对开启管理员模式的玩家本人执行的操作生效。仅拥有原版 OP 权限但未开启管理员模式时，货柜保护仍然生效；自动化、环境破坏和其他玩家的操作也不会因为某位管理员开启了该模式而被全局放行。

示例：

```text
/cargoverse admin_mode on
/cargoverse admin_mode on PlayerName
/cargoverse admin_mode on @a
```

### 5.2 关闭管理员模式

语法：

```text
/cargoverse admin_mode off [targets]
```

作用：

- 关闭目标玩家的 Cargoverse 管理员模式；
- 不会撤销原版 OP 权限；
- 不会回滚玩家此前保存的终端配置。

示例：

```text
/cargoverse admin_mode off
/cargoverse admin_mode off PlayerName
/cargoverse admin_mode off @a
```

## 6. 贸易点

### 6.1 手动推进交易日

语法：

```text
/cargoverse trade_point advance <tradePointId>
/cargoverse trade_point advance <tradePointId> <days>
```

参数：

- `tradePointId`：游戏世界内贸易点实例的共享 ID，不是数据包中的贸易点定义 ID；
- `days`：需要跨越的交易日数量，可选，范围为 1～10000，省略时默认为 1。

每跨越一个交易日都会执行：

- `natural_cargo_units_increase` 自然产出；
- `production.inputs` 输入货物库存消耗；
- `production.output_cargo_units` 产出货物库存增加；
- `stock_max` 产出库存上限钳制；
- 活跃度窗口结算；
- CargoType 动态价格恢复；
- 待结算交易统计归档。

执行完成后：

- 贸易点仍以服务器当前真实 `gameTime` 作为正常计时基准；
- 不会把正常下一交易日推迟额外的 `days` 天；
- 不会改变原版世界昼夜时间；
- 不会修改数据包中的 `ticks_per_day`；
- 不会重置出售列表或已有库存。

目标贸易点必须：

- 已由贸易点主终端注册；
- 位于指令执行者当前维度；
- 注册信息仍然有效。

如果贸易点不存在、未注册或位于其他维度，指令失败且不会修改经济状态。

示例：

```text
/cargoverse trade_point advance aa7f0caa-b50d-4e26-8a9e-8204eb
/cargoverse trade_point advance aa7f0caa-b50d-4e26-8a9e-8204eb 7
```

第一条推进一个交易日，第二条连续回放七个交易日。

大量天数会逐日执行经济结算。虽然指令限制为最多 10000 天，但在大型数据包或贸易点拥有大量 CargoType 时，不建议频繁使用极大的数值。

## 7. 管理员测试生成货柜

语法：

```text
/cargoverse summon <货柜定义ID> <CargoType> <X> <Y> <Z>
```

示例：

```text
/cargoverse summon cargoverse:aui_atlas_sd_s ore ~ ~1 ~
/cargoverse summon cargoverse:aui_atlas_sd_x machinery 100 80 -20
```

规则：

- 需要原版命令权限等级 `2`。
- `货柜定义ID` 必须是当前数据包已经加载的货柜定义；命令输入时提供自动补全。
- `CargoType` 必须是该货柜定义的 `cargo_type` 对象中实际声明的类型；命令会根据前一个参数提供自动补全。
- 坐标表示货柜结构底面中心位置，支持原版相对坐标 `~`。
- 目标坐标所在区块必须已经加载。
- 命令不扣除货币、贸易点产出库存，也不记录购买交易。
- 生成过程仍执行正式货柜生成链路，包括结构放置、贴花占位替换、质量占位方块赋值、Sable 物理化、运行时词条、完整度和实例 SavedData 登记。
- 如果由玩家执行，货柜所有者记录为该玩家；如果由服务器控制台或命令方块执行，则使用系统零 UUID。
- 生成区域已被其他物理结构占用、结构模板缺失或物理生成失败时，命令返回失败信息。

该命令仅用于管理员快速测试数据包货柜定义，不应作为正式交易或玩家获取货柜的入口。

## 8. 接口负载监控

### 8.1 监控物理结构的接口负载

语法：

```text
/cargoverse physics monitor @v <time>
```

参数：

- `@v`：Sable 的“视线指向结构”选择器，选择执行玩家当前看向的单个 Sable 物理结构；
- `time`：监控时间，单位为秒，范围为 1～3600。

作用：

- 命令开始时记录目标结构 UUID，执行玩家之后移开视线不会改变监控目标；
- 无论选中的是连接器所在结构还是与其连接的货柜结构，都会监控两者之间的同一货柜接泊约束；
- 每个 Sable 物理子步采样一次换算后的线性载荷、角向载荷和接口负载率；
- 每秒向执行玩家输出该秒内三项数据各自的峰值；
- 监控到期后自动结束，不修改 SavedData、世界方块、物理结构或接口阈值；
- 同一玩家再次执行该命令会替换其当前监控会话。

输出格式：

```text
线性载荷=12345.678，角向载荷=4567.890，接口负载率=36.25%
```

三项峰值分别独立统计，不保证来自同一个物理子步。该输出主要用于采集载具普通启停、急刹、转向和碰撞时的实际接口负载，以调整 `linearCapacityPerConnector` 和 `angularCapacityPerConnector`。

使用限制：

- 需要原版命令权限等级 `2`；
- 必须由在线玩家执行，因为 `@v` 依赖玩家视线，服务器控制台和命令方块无法使用；
- 目标结构必须存在与货柜连接器建立的有效接泊约束，否则对应采样周期输出为零；
- 命令只负责观测，不会禁止接口按当前阈值正常超载断裂。

示例：

```text
/cargoverse physics monitor @v 30
```

该命令监控执行玩家当前看向的 Sable 物理结构 30 秒。

接口载荷、有效连接器数量与断裂阈值的计算方式详见[货柜连接器与货柜接口](../03功能方块/02_货柜连接器与货柜接口.md#超载断裂与阈值计算)。

## 10. 后续维护约定

新增指令时需要同步完成：

1. 在代码中注册命令并设置明确的权限要求；
2. 为成功和失败反馈添加本地化键；
3. 在本文档增加独立小节；
4. 更新“当前指令速查”表；
5. 说明指令是否修改 SavedData、世界方块、货柜实例或玩家数据；
6. 对批量参数设置硬上限，避免误操作造成长时间主线程阻塞；
7. 若指令只用于测试，应明确标注，避免整合包正式服务器误用。
