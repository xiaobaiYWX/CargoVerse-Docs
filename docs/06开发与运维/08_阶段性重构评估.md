## 已完成的关键收口

### 数据与绑定

- CargoClass 只定义运输大类，CargoGood 定义具体货物；货柜兼容性只绑定 CargoClass。
- 容器定义不再持有制造价值和数量上限，制造价格来自制造台配方，持有上限由玩家档案调度点统一约束。
- 贸易点注册时固定生产布局、模块定义和模块内部抽取；功能终端只填写贸易点 UUID。
- 贸易点信息柜是手工站点唯一“UUID → 贸易点定义”管理入口；普通终端不再回退到默认定义。

### 交易与物理

- 装载、卸载、货柜制造和物品购买均由服务器重新读取权威状态。
- 装卸与售货机购买进入同一服务器身份的串行边界，并按步骤注册反向补偿。
- 货柜质量使用 `max(实例基础质量, 模板质量) + 当前 Load 质量`，连续交易在 20 tick 内合并一次物理结构刷新。
- 贴花与质量从原始模板受管理槽位二次刷新，支持普通世界、Sable 嵌入世界和暂不可访问时的持久化重试。

### 大型功能终端

- 七个正式世界表面终端：生产线终端、贸易点信息柜、仓库信息柜、货柜装载机、货物卸载机、货柜制造台、物品售货机。
- 货柜制造台按既有 input stock 标签匹配材料，实际制造会扣货币、库存和调度点并生成资产。
- 物品售货机按既有 output stock 标签匹配商品成本，购买会扣货币和库存并暂存结果。
- 售货机出货区是公共暂存区：任意玩家可领取，只插入可容纳数量；拆除终端时剩余物品只掉落一次。

### UI 与旧链路

- 仪表、按钮、滑轨的模型姿态、命中面和细高亮由组件同一锚点派生；仪表封装层统一提供命中高亮与准星旁用途信息。
- 旧装卸终端、旧单方块货柜制造机、旧商店终端的方块／方块实体／Screen／Menu／网络包／资源和业务类已删除。
- 旧贸易点终端降级为纯装饰方块，不再承载 GUI、绑定或经济逻辑。

## 当前主要风险

### P1：真实多人和网络时序

- 两名玩家同时购买最后一份售货机库存；
- 两名玩家同时制造或操作同一货柜；
- 重复输入、高延迟、断线重连和区块卸载边界；
- 一人购买、另一人领取及部分背包空间下的暂存一致性。

代码侧已有串行和补偿边界，但这些场景仍必须由真实双客户端验证。

### P1：世界表面与物理实机矩阵

- 七终端的四个合法水平朝向、远近距离、FOV、DPI 和低帧率；
- 斜面按钮／滑轨的模型、命中、高亮和按压行程；
- Create／Sable 运动结构或子世界中的射线、渲染和交互；
- 服务器关闭重进后，货柜质量、贴花、模块绑定及售货机暂存物。

### P1：尚未定案的数据语义

- 数据包重载后补装同一种 CargoGood 时，旧快照与新定义的质量、币种和兼容性来源；
- 同名运输词条是继续后值覆盖，还是改为参数合并；
- 当前整数历史累计字段面对小数 `t` 时采用四舍五入，若未来需要精确统计，应升级存档字段而不是重复扣库存。

### P2：玩法深度与内容

- 货柜维修、改装、清理、回收和完整耐久损坏循环；
- 制造商声望、正式配方网络、工厂／市场贸易点和平衡；
- 航运等剩余传统界面是否迁移为世界表面终端；
- 手工贸易点定义路径绑定问题此前被明确跳过，仍需单独回到该输入链路处理。
