# 贴花与货柜展示锚点

贴花系统用于在货柜、建筑、载具和其他方块结构表面展示货物类型、制造商和运输警示标志。普通装饰贴花是静态方块；货柜图案与条件展示使用绑定实例的持久锚点，空柜也保留槽位。两者均可随结构模板保存、加载和预览。

## 设计目标

- 使用真实方块参与结构保存和物理化，不使用实体。
- 不使用方块实体和 Ticker，避免持续服务端与客户端开销。
- 支持四个水平方向，并紧贴被点击方块表面。
- 支持 Create 扳手切换显示尺寸。
- 可在货柜结构预览界面中使用实际 BlockState 模型显示。
- 可以脱离货柜系统，用于车站、仓库、载具和地图装饰。

## 方块行为

普通装饰贴花共用静态方块实现，基础属性如下；动态锚点的差异见后文：

- 无碰撞。
- 不遮挡方块和光照。
- 可正常破坏并掉落对应贴花物品。
- Sable 物理质量为 `0.0`。
- 无 BlockEntity。
- 无随机 Tick、计划 Tick或方块实体 Ticker。
- 使用 `cutout` 静态方块模型渲染透明背景。
- 只占用一个锚点方块位置；扩大尺寸只改变渲染模型，不额外占据方块。

贴花放置时只接受四个水平面，BlockState 保存：

```text
facing=north|east|south|west
size=<该贴花组支持的尺寸>
```

`facing` 表示贴花向外显示的方向。实际模型和选择框位于锚点方块靠支撑墙的一侧。

普通贴花扩大时不再围绕模型中心向四周扩张，而是以锚点方块的一个边角为缩放原点，沿水平方向和下方展开。因此 `2x2` 严格覆盖 2×2 的视觉范围，`3x3` 严格覆盖 3×3 的视觉范围，不会因为中心落在四个方块交界处而额外占据 3×3。

## 尺寸与扳手操作

### 方形贴花

CargoClass、制造商徽章和货柜警示标志使用以下循环：

```text
1x1 → 2x2 → 3x3 → 1x1
```

### 横向字母 Logo

制造商字母 Logo 的比例约为横向 `1:3`，使用独立循环：

```text
1x3 → 2x6 → 1x3
```

`2x6` 通过客户端静态烘焙模型扩大，不依赖 BER 或方块实体。

### 操作方式

手持 Create 扳手右键贴花即可切换到下一档尺寸。尺寸和方向都保存在 BlockState 中，因此结构模板保存后能够完整恢复。

未绑定的两类货柜展示锚点同样支持三档方形尺寸；装配后布局冻结，不能通过扳手更改。

## CargoClass 分类贴花

原有货物图案注册 ID 保持为 `cargoverse:decal_<图案名>`，例如 `decal_raw_resource`、`decal_food`、`decal_logistics_equipment`。14 套图案加 none 空柜贴花继续可用，但不再对应四大形态枚举；物品基础属性通过 decal 字段直接指定已注册静态贴花 ID，参见[属性定义](../10数据包定义与模板/01_物品运输/README.md)。

原图案资源仍位于 `textures/block/decal/cargo_class/<id>.png`；空柜及源码默认使用 `none`。不存在的现行贴花声明会拒绝发布；已有载货引用的贴花被移除时显示 none，不重新按形态猜图。

## 货柜警示贴花

警示贴花仅按当前注册的 13 种货物运输条件提供，货柜能力不注册贴花。GUI 图集和世界独立 PNG 表达相同条件，但各自维护资源；方块、物品模型引用 `Type.decalArtwork`，保持原始长宽比。图案不会自动添加条件、保护能力或执行损耗。

| 含义 | 条件 ID（命名空间 cargoverse） | 方块 ID |
|---|---|---|
| 易碎品 | `fragile` | `cargoverse:decal_warning_fragile` |
| 保持正放 | `keep_upright` | `cargoverse:decal_warning_keep_upright` |
| 保持干燥 | `keep_dry` | `cargoverse:decal_warning_keep_dry` |
| 易腐坏 | `perishable` | `cargoverse:decal_warning_perishable` |
| 冷冻运输 | `frozen_transport` | `cargoverse:decal_warning_frozen_transport` |
| 低温敏感 | `cold_sensitive` | `cargoverse:decal_warning_cold_sensitive` |
| 高温敏感 | `heat_sensitive` | `cargoverse:decal_warning_heat_sensitive` |
| 避光储存 | `light_sensitive` | `cargoverse:decal_warning_light_sensitive` |
| 保持光照 | `requires_light` | `cargoverse:decal_warning_requires_light` |
| 气压敏感 | `pressure_sensitive` | `cargoverse:decal_warning_pressure_sensitive` |
| 碎料（围护 ≥1） | `fragments` | `cargoverse:decal_warning_fragments` |
| 粉料（围护 ≥2） | `powder` | `cargoverse:decal_warning_powder` |
| 易挥发（密封 ≥2） | `volatile` | `cargoverse:decal_warning_volatile` |

13 项贴花均使用 `textures/block/decal/transport/<条件名>.png` 的完整独立纹理，由默认方块图集自动收录，物品模型使用同一张独立图片。GUI 与仪表使用 `textures/gui/transport/icons.png` 中对应的条件区域，不读取货柜能力的等级图案作为警示。贴花维持四朝向、1x1／2x2／3x3、零质量、无方块实体的静态装饰行为。贴花物品本身属于普通无质量固体，不因为图案是易碎或冷冻就自动带上该运输条件。

货物警示只投影有效运输条件，不显示货柜能力，也不因保护已满足而隐藏要求。注册条件直接按冻结声明取图；过渡数值需求只投影明确对应条件，直接水损不猜成湿度条件。

## 结构模板与预览

### 持久展示锚点

| 角色 | 模板方块 ID | 展示来源 |
| --- | --- | --- |
| 货物图案 | `cargoverse:cargo_type_decal_marker` | 当前 Load 冻结的 decal；空柜为 none |
| 运输条件 | `cargoverse:affix_decal_marker` | 当前 Load 冻结的有效运输条件，按条件 ID 排序 |

两者都是无碰撞、零质量、无 Ticker 的方块实体，使用同一 `cargo_decal_anchor` 实体类型。槽位永远是实体结构的一部分；没有图案时画面透明，不把锚点换成空气。破坏或替换锚点不会掉出当前图案对应的物品。

未绑定时，货物位显示 none，条件位显示数字。主手右键条件位循环 `slot=0～15`，并在动作栏显示编号；Create 扳手切换 `1x1 → 2x2 → 3x3`。不同侧可以重复使用相同 slot。装配后冻结方向、尺寸、角色和序号，禁止继续编辑绑定锚点。扩大尺寸仍按边角锚定，模板范围必须包含锚点坐标。

### 布局、绑定与显示

生成顺序：放置模板 → 收集全部真实方块（含空展示位）→ 一次记录 `CargoPhysicalLayout` → 绑定展示及质量锚点 → 分配空柜质量 → 创建物理结构。布局存入货柜 Physical.Layout，不依赖后续版本的模板。

`CargoDecalPresentation` 是物理显示与预览共用的只读投影：

- 从当前 Load 的冻结声明取条件，不解析 GUI 合并文案；双向温度分别占位。未配置的材料条件及无倾角限制不显示。
- 普通物品、液体沿用各自冻结的 decal 和条件；不在柜体绘制物品三维模型，不为气体／生物虚构业务后端。
- 条件数量不受五个槽位限制；模板槽位不足只缺少图案，不影响条件执行。刷新结果返回缺失数量，首次图案变化时记录诊断，制作模板时按需补位。
- 图案资源包可更换纹理；数据包重载不改途中货物的冻结条件。物品侧声明已移除的图案回退 none，不能将锚点本身声明为货物图案。

### 更新与冲突

装卸、换货、损耗清空或物理映射变化进入现有持久化待刷新队列。执行时重新读取最新已提交资产；同一 ID 的请求合并，不发布调用者保存的旧快照。每个锚点保存最小绑定、图案引用及递增展示版本；同绑定的旧版本客户端更新被忽略。

数量变化仍可能需要更新质量，但展示相同时不发送图案包，也不重建展示模型。刷新只更新实例布局中方块状态、绑定 ID 均匹配的锚点；缺失、普通替换方块和其他实例的锚点均不覆盖、不认领、不自动补回。Sable 移动方块后只安排一次归属核验；离开原实例布局的部件解除绑定，质量部件同时撤销原有补充质量。

物理子世界不可读时保留请求，正常刷新先检查已加载状态，不为派生维护唤醒离线货柜。重启沿用资产刷新队列审计，不从模板重建布局。开发期条目格式为 12，旧格式货柜不迁移，需要重新生成；模板方块 ID 保持不变。

### 模型与预览

`CargoDecalAnchorModels` 通过 ModelData 选择已烘焙的静态贴花模型，进入普通区块及 Sable 标准网格渲染；没有 BER、实体或逐帧服务端查询。绑定与图案变化通过方块实体更新同步，资源重载重新烘焙。

已加载实例预览读取实际结构与同一冻结投影，不回查模板猜槽位；不可读实例的模板预览仍使用型号模板几何和冻结图案，不加载世界。缓存有界，按实例、物理映射、展示及质量区分。客户端预览只接收普通静态状态，不传第二份运输运行时。

## 性能说明

普通装饰贴花不使用方块实体或同步。动态锚点仅保存最小数据，无 Ticker、无持续网络同步和每帧 BER；图案不变时不请求网格更新。每帧只绘制已有网格。

实体货柜的派生刷新按事件入队，每 Tick 最多处理 8 个资产；展示只遍历实例的锚点列表，不扫描结构体积或原模板。质量刷新直接定位已记录的质量锚点，仅在质量分配改变或发布失败待重试时重建并发布物理体质量。结构基线仍由 MassTracker 测量，不代表已实现完整的增量质量／质心算法。

大型图案仍可能跨区段；锚点不可见时外伸部分可能随其被裁剪。真实客户端的标准 Sable 模型、跨区段及重载表现仍需按[待验收清单](../设计草案/待完成事项清单.md#动态贴花展示槽验收)核验；服务器测试不能替代视觉验收。

## 新增贴花流程

1. 将透明 PNG 放入贴花纹理目录。
2. 在 `ModBlocks` 对应贴花分类列表中加入稳定 ID。
3. 生成所需尺寸的方块模型。
4. 建立包含四个方向与尺寸组合的 blockstate。
5. 建立物品模型和中英文译名。
6. 添加 `sable:mass = 0.0` 的物理属性文件。
7. 将物品加入创造模式物品栏。
8. 执行完整构建，并在游戏中验证方向、选择框、尺寸循环、物理化和结构预览。
