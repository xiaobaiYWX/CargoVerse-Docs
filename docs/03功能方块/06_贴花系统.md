# 静态贴花系统

> 已实现：静态贴花、分类图标、预览解析，以及实体货柜装卸后的分类／词条贴花刷新。世界内最终观感仍纳入实机矩阵。

贴花系统用于在货柜、建筑、载具和其他方块结构表面展示货物类型、制造商和运输警示标志。贴花是普通静态方块，不与货柜实例强绑定，可以随 Minecraft 结构模板一起保存、加载和预览。

## 设计目标

- 使用真实方块参与结构保存和物理化，不使用实体。
- 不使用方块实体和 Ticker，避免持续服务端与客户端开销。
- 支持四个水平方向，并紧贴被点击方块表面。
- 支持 Create 扳手切换显示尺寸。
- 可在货柜结构预览界面中使用实际 BlockState 模型显示。
- 可以脱离货柜系统，用于车站、仓库、载具和地图装饰。

## 方块行为

所有贴花共用静态方块实现，基础属性如下：

- 无碰撞。
- 不遮挡方块和光照。
- 可正常破坏并掉落对应贴花物品。
- Sable 物理质量为 `0.0`。
- 无 BlockEntity。
- 无随机 Tick、计划 Tick或方块实体 Ticker。
- 使用 `cutout` 静态方块模型渲染透明背景。
- 只占用一个锚点方块位置；扩大尺寸只改变渲染模型，不额外占据方块。

贴花放置时只接受四个水平面，BlockState 保存：

```text
facing=north|east|south|west
size=<该贴花组支持的尺寸>
```

`facing` 表示贴花向外显示的方向。实际模型和选择框位于锚点方块靠支撑墙的一侧。

普通贴花扩大时不再围绕模型中心向四周扩张，而是以锚点方块的一个边角为缩放原点，沿水平方向和下方展开。因此 `2x2` 严格覆盖 2×2 的视觉范围，`3x3` 严格覆盖 3×3 的视觉范围，不会因为中心落在四个方块交界处而额外占据 3×3。

## 尺寸与扳手操作

### 方形贴花

CargoClass、制造商徽章和货柜警示标志使用以下循环：

```text
1x1 → 2x2 → 3x3 → 1x1
```

### 横向字母 Logo

制造商字母 Logo 的比例约为横向 `1:3`，使用独立循环：

```text
1x3 → 2x6 → 1x3
```

`2x6` 通过客户端静态烘焙模型扩大，不依赖 BER 或方块实体。

### 操作方式

手持 Create 扳手右键贴花即可切换到下一档尺寸。尺寸和方向都保存在 BlockState 中，因此结构模板保存后能够完整恢复。

例外：Affixes 警示贴花槽位固定为 `1x1`，不参与尺寸循环。

## CargoClass 分类贴花

注册 ID 为 `cargoverse:decal_<cargo_class>`。固定 24 类及其名称见[货物分类](../01货柜系统/01核心系统/05_货物类型.md)，例如 `decal_raw_resource`、`decal_medical_supply`、`decal_prefab_structure`。

每类已使用 V3.0 独立图标，位于 `textures/block/decal/cargo_class/<id>.png`；空柜或未知类使用 none。旧 ore／wood 等专用货物类型贴花不再注册，不能继续引用旧资源。

## 结构模板与预览

### CargoClass 占位贴花

模板作者可以使用：

```text
cargoverse:cargo_type_decal_marker
```

编辑模板时它使用 `none` 图标。该占位贴花保留普通方形贴花的尺寸循环：

```text
1x1 → 2x2 → 3x3 → 1x1
```

空柜生成时替换为 none；GUI 预览和世界实体都根据当前 Load 的货物分类解析对应 decal，并保留 facing／size。资源 ID cargo_type_decal_marker 因现有 NBT 模板引用而保留，Java 实现已是 CargoClassDecalMarkerBlock，不代表旧分类系统仍存在。

`cargo_type_decal_marker` 的 `2x2/3x3` 与普通方形贴花使用相同的边角锚定模型处理：以锚点方块边角为缩放原点，沿水平方向和下方展开，不以模型中心向四周扩张。

### Affixes 警示贴花槽位

模板作者可以使用：

```text
cargoverse:affix_decal_marker
```

槽位固定为 `1x1`，BlockState 额外保存：

```text
slot=0|1|2|3|4
```

模板中分别显示纯数字纹理 `0`～`4`。使用主手右键槽位即可循环：

```text
0 → 1 → 2 → 3 → 4 → 0
```

该交互只修改槽位状态，不取消右键事件，也不阻止 Create 扳手或其他物品继续执行自身逻辑。

预览解析时按 Load 最终运输词条顺序填充槽位；实际空柜生成时这些槽位解析为空气：

```text
slot=0 → 第一个词条
slot=1 → 第二个词条
slot=2 → 第三个词条
slot=3 → 第四个词条
slot=4 → 第五个词条
```

槽位没有对应词条、词条没有注册警示贴花时，占位方块替换为空气。词条数大于模板槽位数时，只显示排在前面的词条；多余词条不显示，但其运行逻辑仍然生效。

### 替换时机

实际生成顺序为：

```text
放置结构模板
→ 解析 CargoClass 与 Affixes 占位贴花
→ 收集最终货柜方块
→ 创建物理结构
```

占位方块不会进入最终物理货柜。后续刷新不会从实体当前方块反猜槽位，而是重新读取原始结构模板中的 CargoClass／Affix marker 坐标，再映射到普通世界或 Sable 嵌入世界。刷新只允许替换这些受管理槽位中的空气、marker 或已注册贴花；若玩家在槽位放入普通方块则保留该方块并记录冲突。

装货、部分卸货、卸空或物理映射变化会登记持久化刷新请求。物理子世界暂不可访问时请求保留并按预算轮转重试；服务器重启后会对全部有物理结构的货柜执行一次幂等审计，避免旧存档永久缺失贴花更新。

贴花作为普通方块保存在结构模板的 palette 和 blocks 中。模板会保留贴花方块 ID、`facing` 和 `size`。

货柜预览读取模板中的完整 BlockState，并通过 Minecraft 方块模型渲染器绘制，因此无需为贴花建立独立的预览数据协议。

需要注意：

- 扩大后的贴花仍只拥有一个锚点方块。
- 模板尺寸应覆盖贴花锚点，而不是只覆盖贴花视觉范围。
- 删除货柜结构时必须确保锚点位于货柜元数据记录的结构范围内。
- 大型贴花可能跨越渲染区段；锚点不可见时，超出部分可能随锚点一起被裁剪。

## 性能说明

普通方形贴花完全使用静态 JSON 模型。`2x6` 字母 Logo 在模型烘焙事件中包装为静态放大模型。两者最终都进入普通区块渲染批次。

贴花不会产生：

- 服务端每 Tick 逻辑；
- 方块实体存档；
- 方块实体同步包；
- BER 每帧独立渲染调用；
- 实体碰撞检查。

修改尺寸会更新一次 BlockState，并触发对应区块网格重建。正常静止状态下，其运行成本接近普通无碰撞装饰方块。

实体货柜刷新不是每 Tick 全量扫描：只有待刷新 ID 进入持久化队列，服务端每 Tick 最多处理 8 个；没有待办时无模板扫描成本。

## 新增贴花流程

1. 将透明 PNG 放入贴花纹理目录。
2. 在 `ModBlocks` 对应贴花分类列表中加入稳定 ID。
3. 生成所需尺寸的方块模型。
4. 建立包含四个方向与尺寸组合的 blockstate。
5. 建立物品模型和中英文译名。
6. 添加 `sable:mass = 0.0` 的物理属性文件。
7. 将物品加入创造模式物品栏。
8. 执行完整构建，并在游戏中验证方向、选择框、尺寸循环、物理化和结构预览。
