# 货柜装载机

> 已实现：大型多方块模型、管理员绑定、世界表面仪表与封装控件、贸易点输出库存购买和真实装载交易。资源 ID：`cargoverse:container_loader`。

货柜装载机替代已删除的 `cargo_loading_terminal`。普通玩家不打开传统装载 GUI，选择与交易直接在模型表面完成；管理员 GUI 只编辑贸易点实例 UUID 和扫描范围。

## 结构与绑定

- 模型覆盖 3 格宽、2 格高、2 格深，由控制器统一渲染；成员使用空模型避免重复绘制；
- 放置时检查全部结构格，拆除任一成员会清理完整结构；
- 结构模板生成时写入贸易点实例 UUID；
- 管理员模式右键任一成员才可打开绑定界面，服务端重新检查管理员模式、距离、控制器和结构；
- 配置内容与旧装载终端一致：贸易点实例 UUID、扫描中心偏移与扫描盒尺寸。

旧模型中的额外占位格已经清理；结构格数量和模型包围盒以当前 `ContainerLoaderBlock` 与资源测试为准，不再按早期设计图推断。

## 世界表面布局

终端定义两个透明 `OVERLAY` 画布，不绘制框架默认背景和内框：

- 竖直上方面板：货柜名称、当前装载量／最大容量、当前质量、货物名称与图标、词条、货柜耐久百分比、贸易点库存、货物总质量和总价；
- 下方斜面控制台：候选货物、货物库存与单位质量、货柜信息、数量滑轨和确认按钮。

物理控件全部来自统一组件：

- 上／下箭头切换扫描到的货柜；
- 左／右箭头切换贸易点可装载货物；
- 16 MCpx 滑轨，范围 `1..100`、步进 `1`，选择单次装载数量；
- 红色 `LOAD` 大按钮执行交易。

名称＋容量使用较长栏位，容量至少保留 9 个翻牌显示槽；质量使用较短栏位。对应的货物增减质量／数量仪表与主栏位保持同排语义。

## 装载交易

点击 `LOAD` 后调用服务端 `CargoLoadingService.tryLoadAtTradePoint`。服务端重新确认玩家所有权、货柜有效性、扫描范围、CargoGood 定义、容器兼容、当前装载内容、剩余容量、贸易点输出库存、币种和余额。

```text
有效装载数量 = min(请求数量, floor(当前输出库存))
```

若有效数量仍超过货柜剩余容量则拒绝，不自动缩减到容量。成功后扣除货币和贸易点输出库存，更新货柜 Load、购入成本与物理质量。货币、库存、货柜资产和贸易点记账处于同一个服务端串行补偿域；任一步抛出异常都会按反向顺序恢复此前状态。补装同一种货物时按数量混合完整度并保留运输时间状态。

提交完成后，质量与实体贴花进入统一、可持久化重试的物理派生状态刷新。同一货柜的连续交易采用 `20 tick` 尾触发窗口合并，最后一次交易结束满 20 Tick 后只刷新一次。质量取货柜资产的最新总质量，重写结构内质量占位方块；Sable 结构还会重建质量／惯量追踪并唤醒刚体。派生刷新失败不会把已经完成的经济交易回滚。

展示快照包含候选货柜、CargoGood、库存、质量、价格、币种、请求数量和超载状态；快照不是交易权威。

## 待验收

- 六向摆放、所有按钮方向、模型凹槽与细高亮边框的贴合；
- 滑轨在不同 DPI、灵敏度、高延迟与多人情况下的手感和会话互斥；
- 两客户端高延迟下的实际按钮竞争与断线重试；
- 装载后世界实体贴花与动态重量的实际观感、Sable 重载，以及数据包重载后的补装规则。
