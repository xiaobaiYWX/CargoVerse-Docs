# 航运风格统计与雷达图

玩家航运档案中的雷达图表示近期运输风格，不表示累计成长或历史总量。五个轴均为 `0.0～1.0` 的倾向值：运载量、货物价值、丰富度、广域度和可靠度。

## 统一统计窗口

默认窗口为最近 `3000` 个承运货物单位·航段。交易次数不参与窗口截断，将同一次装卸拆成多次点击不会改变统计结果。边界航段按剩余货量比例计入；累计量不足 `minimum_cargo_units` 时不绘制数据多边形。

统计仅在玩家登记航运执照后产生。旧累计运输次数、收益、重量和承运时间不会迁移为风格数据。

## 航段状态

系统为玩家名下每个货柜维护一个候选航段状态。玩家在同一贸易点进行任意次数的成功装卸时，只刷新货柜操作后的候选载荷；当货柜第一次在另一个贸易点成功装卸时，系统先用操作前载荷结算上一航段，再用操作后载荷建立下一航段。

因此不需要判断物理离港时刻：

```text
贸易点 A 最后一次装卸后的状态
→ 在贸易点 B 第一次成功操作前确认 A→B
→ 执行 B 的装卸
→ 操作后的状态成为 B 点候选载荷
```

部分卸货后再次补装不会拆出虚假航段。后续航段使用补装完成后的实际载荷和装载率。

## 五轴算法

### 运载量

```text
单航段倾向 = 货柜规格系数 × 航段起始装载率
运载量 = Σ(航段货量 × 单航段倾向) ÷ Σ航段货量
```

### 货物价值

使用装载时冻结的 CargoGood 单位基础价值：

```text
单项价值倾向 = 单位价值 ÷ (单位价值 + reference_unit_value)
货物价值 = 按窗口货量加权平均
```

### 丰富度

按 CargoGood ID 聚合窗口货量。设某货物占比为 `p(g)`：

```text
有效货物种类数 = 1 ÷ Σp(g)²
丰富度 = (有效货物种类数 - 1) ÷ (target_effective_goods - 1)
```

结果限制为 `0～1`。

### 广域度

每个航段的货量各以 50% 计入起点和终点。设某贸易点占比为 `p(t)`：

```text
有效贸易点数 = 1 ÷ Σp(t)²
广域度 = (有效贸易点数 - 1) ÷ (target_effective_trade_points - 1)
```

### 可靠度

每个航段使用完整度保持率：

```text
航段可靠度 = 到达完整度 ÷ 航段起始完整度
可靠度 = 按窗口货量加权平均
```

完整度保持率限制为 `0～1`，不会因为货物在更早航段已经受损而重复惩罚当前航段。

## 数据包配置

默认路径：

```text
data/cargoverse/player_profiles/default.json
```

```json
"radar_chart": {
  "window": {
    "mode": "recent_cargo_units",
    "cargo_units": 3000.0,
    "minimum_cargo_units": 100.0
  },
  "load_scale": {
    "size_factors": {
      "S": 0.2,
      "M": 0.4,
      "L": 0.6,
      "X": 0.8,
      "XL": 1.0
    }
  },
  "cargo_value": {
    "reference_unit_value": 100.0
  },
  "richness": {
    "target_effective_goods": 8.0
  },
  "coverage": {
    "target_effective_trade_points": 6.0
  },
  "reliability": {}
}
```

`size_factors` 必须完整包含 S、M、L、X、XL，并且从 S 到 XL 不得递减。特殊货柜规格参与统计前也必须显式提供系数。

## 持久化与重置

候选航段和滚动历史保存在：

```text
cargoverse_player_shipping_style
```

重置命令：

```mcfunction
/cargoverse shipping_stats reset [targets]
```

该命令会同时清除目标玩家的已完成航段历史和未完成候选航段，不影响许可证、货柜实例、市场库存或任务进度。
