# 航运统计与雷达图

本文档说明“航运终端”左侧五维雷达图的数据来源、图表计算方式、数据包配置格式以及维护命令。

## 功能定位

航运统计用于给玩家展示长期货运表现。它不是交易结算的核心逻辑，不直接影响货柜价格、许可证等级或货柜状态，而是作为航运终端中的个人档案展示信息。

当前雷达图包含五个维度：

- 航运次数
- 赚取金额
- 平均完整度
- 承运时间
- 总计重量

其中，图表绘制值和界面显示值是分离的：

- 界面显示值用于让玩家看到真实统计结果。
- 图表绘制值统一转换为 `0.0 ~ 1.0`，用于绘制雷达图。

## 数据来源

玩家航运统计保存在服务端 SavedData 中：

```text
cargoverse_player_shipping_stats
```

对应代码：

```text
src/main/java/cn/or15/vstrade/trade/PlayerShippingStatsSavedData.java
```

出售终端成功收购货柜后，会记录一次出售数据：

- 航运次数 +1
- 赚取金额累计本次出售获得的货币数量
- 总计重量累计本次出售货柜的结构重量
- 平均完整度累计本次出售时的完整度
- 平均完整度图表值按动态平滑公式更新
- 承运时间会在玩家名下存在未失效货柜时持续累计

航运终端打开时会同步玩家当前统计，并将服务端数据包配置一并发送到客户端用于绘图。

## 五项统计说明

### 航运次数

显示值：

```text
成功出售货柜的总次数
```

图表值：

```text
航运次数 / (航运次数 + shipping_count_k)
```

这是长期累计型指标，只会上升。

### 赚取金额

显示值：

```text
成功出售货柜获得的货币数量总和
```

图表值：

```text
赚取金额 / (赚取金额 + earned_amount_k)
```

当前只统计货币数量，不区分不同货币的实际价值。后续如果需要多货币折算，应在出售结算处先转换为统一价值，再写入统计。

### 总计重量

显示值：

```text
已出售货柜的结构重量总和
```

图表值：

```text
总计重量 / (总计重量 + total_weight_k)
```

重量来源于货柜结构预览的重量缓存。没有定义质量的方块默认按 Sable 质量 `1` 计算。

### 承运时间

显示值：

```text
玩家名下存在至少一个未失效货柜时累计的时间
```

图表值：

```text
承运时间 / (承运时间 + carrier_time_k_seconds)
```

承运时间替代了早期的“平均时间”。平均时间容易被囤货、延迟出售等行为污染，因此改为类似“承运经验时长”的成长型指标。

### 平均完整度

显示值：

```text
成功出售货柜时完整度的历史平均值
```

图表值不直接使用历史平均值，而是使用动态平滑分数：

```text
S_new = S + K * (I - S)
```

含义：

- `S`：当前图表完整度值，范围 `0.0 ~ 1.0`
- `I`：本次出售货柜完整度，范围 `0.0 ~ 1.0`
- `K`：完整度图表步长，对应 `integrity_score_step`

默认：

```text
integrity_score_step = 0.1
```

这样一次 100% 完整度交付不会直接把图表拉满，低完整度交付也会逐步拉低图表表现。

## 数据包配置

配置文件路径：

```text
data/cargoverse/shipping_stats_config/default.json
```

默认内容：

```json
{
  "shipping_count_k": 50.0,
  "earned_amount_k": 5000.0,
  "carrier_time_k_seconds": 21600.0,
  "total_weight_k": 500.0,
  "integrity_score_step": 0.1
}
```

字段说明：

| 字段 | 作用 | 默认值 |
| --- | --- | --- |
| `shipping_count_k` | 航运次数归一化 K 值 | `50.0` |
| `earned_amount_k` | 赚取金额归一化 K 值 | `5000.0` |
| `carrier_time_k_seconds` | 承运时间归一化 K 值，单位为秒 | `21600.0` |
| `total_weight_k` | 总计重量归一化 K 值 | `500.0` |
| `integrity_score_step` | 完整度图表值每次交付的变化步长 | `0.1` |

K 值越大，对应维度增长越慢；K 值越小，对应维度越容易接近满值。

## 重置命令

重置执行者自己的航运统计：

```mcfunction
/cargoverse shipping_stats reset
```

重置指定玩家的航运统计：

```mcfunction
/cargoverse shipping_stats reset <targets>
```

该命令只清除航运终端雷达图统计，不会影响：

- 运输许可证经验
- 已购买货柜实例
- 货柜状态
- 市场经济数据
- FTB 任务进度

运输许可证等级另有独立命令：

```mcfunction
/cargoverse license reset <targets>
```

## 维护建议

- 服务器正式开服前，可以根据经济规模调整 `earned_amount_k` 和 `total_weight_k`。
- 如果玩家早期雷达图成长太快，优先提高对应 K 值。
- 如果完整度表现过于抖动，降低 `integrity_score_step`。
- 如果完整度表现变化太慢，提高 `integrity_score_step`。
- 不建议把 `integrity_score_step` 设置为 `1.0`，否则会退化为“只看最近一次完整度”。
