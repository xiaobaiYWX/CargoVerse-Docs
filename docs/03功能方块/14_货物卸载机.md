# 货物卸载机

> 已实现：大型多方块模型、管理员绑定、世界表面仪表与封装控件，以及真实卸货、贸易点入库和货币结算。资源 ID：`cargoverse:cargo_unloader`。

货物卸载机替代已删除的 `cargo_handling_terminal`。普通玩家直接操作模型表面；只有管理员模式右键结构成员时，才复用装载机的贸易点 UUID 与扫描范围配置界面。

## 信息分区

上方竖直面板是贸易点收购区：

- CargoGood 图标与名称；
- 当前收购价格相对基础价格的涨跌；
- 按滑轨数量和单位价格计算的总价。

下方倾斜面板是货柜区，始终显示当前候选货柜的数据：

- 货柜名称；
- 当前货物名称；
- 当前数量／最大数量；
- 货物完整度百分比。这里表示货物完整度，不是货柜耐久。

当当前贸易点不能收购柜内货物时，上方 CargoGood 名称栏显示“无法出售此货物”，图标、价格和涨跌保持空白；下方货柜信息仍继续显示，不因不可出售而隐藏。

全部显示区域为透明 `OVERLAY` 表面，模型自身提供底板与边框。没有合适数据时保留仪表本体，只清空翻牌内容。

## 交互控件

- 上／下箭头切换扫描到的货柜；
- 16 MCpx 滑轨，范围 `1..100`、步进 `1`，选择出售数量；
- 绿色 `UNLOAD` 大按钮确认交易。

箭头、大按钮和滑轨都由公共组件创建。模型位置、命中面、动态滑块位置与细高亮边框由同一组件放置数据推导，终端不得再单独拼接高亮偏移。

## 卸货交易

点击 `UNLOAD` 后调用 `CargoUnloaderTransactionService.tryUnload`。服务端重新检查贸易点是否活跃、货柜所有权和有效性、CargoGood 定义、容器兼容性、贸易点是否需求该货物、输入库存容量和结算币种。

```text
有效卸货数量 = min(请求数量, 柜内数量, floor(贸易点输入剩余容量))
收入 = 单位基础价值 × 有效数量 × 当前收购修正 × 完整度比例
```

成功后向玩家发放货币，减少或清空 Load，更新物理质量，并记录贸易点销售、繁荣度经验、运输许可证经验和玩家航运风格航段。货币、货柜、贸易点、许可证经验和航运风格记录均注册反向补偿，并由同一服务端串行事务边界保护；卸空保留货柜资产，不删除设备。提交后质量占位方块、Sable 质量／惯量和实体贴花进入统一、可持久化重试的物理派生状态刷新流程；同一货柜的连续交易按最后一次交易后的 `20 tick` 尾触发合并。

## 待验收与风险

- 自动化已覆盖反向补偿顺序、同服务器交易互斥、同 Tick 重复动作抑制和完整 Load 生命周期；
- 仍需两客户端、高延迟、断线以及输入库存临界填满时的实机竞争；
- 六向、斜面、按钮边缘和滑块动态高亮的实机贴合；
- 部分卸货、卸空和重新装载的数据循环已有自动化覆盖；Sable 动态质量追踪已有服务器 GameTest，质量、贴花与重进后的世界观感仍需实机确认。
