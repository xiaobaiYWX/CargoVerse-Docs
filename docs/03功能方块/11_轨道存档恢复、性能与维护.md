# 轨道存档恢复、性能与维护

## 当前职责边界

| 部分 | 职责 |
| --- | --- |
| `CargoRailMount` | 轨道、止冲器和滑车的公共安装轴、旋转／镜像及扳手交互 |
| `CargoRailBlock` | 真实轨格、支撑与薄层碰撞、局部红石激活传播 |
| `CargoRailStopBlock` | 完整一格碰撞的被动止冲器，不具有捕获或充能逻辑 |
| `CargoRailTrolleyBlockEntity` | 滑车加载／卸载登记和自身挂轨 NBT |
| `StraightRailGeometry` | 模型锚点、坐标变换、局部候选查询和止冲行程边界 |
| `StraightRailTrolleys` | 每维度连接索引、对齐／滑动／锁定、阻尼及关节生命周期 |
| `StraightRailBodyRemovalMixin` | 在 Sable 销毁参与刚体前释放关节 |

只有滑车需要方块实体。轨道与止冲器不注册方块实体、不逐格 Tick，不使用旧路径图、运行时轨道组、接口空间分桶或全局恢复队列。

## 持久化

真实轨格与止冲器由世界方块状态保存。滑车自身 NBT 中的 `StraightRail` 保存以下内容：

| 字段 | 内容 |
| --- | --- |
| `Pos` | 当前真实轨格的 BlockPos 长整数 |
| `Body` | 轨道承载结构 UUID；静态世界使用零 UUID |
| `Axis` | 轨道轴 |
| `Facing` | 安装面朝外法线 |

不保存 native 关节句柄、瞬时阻尼、对齐进度或止冲行程缓存。仅在目标发生变化时标记滑车存档变更，不逐物理子步写存档，也不为挂轨记录增加客户端同步包。

## 恢复与清理

滑车加载时登记；在 Sable 物理模拟前验证保存目标。参与结构及区块已就绪、目标仍为同轴同面真实轨格、位置姿态符合恢复条件时，重建对齐和约束。已保存的断电连接允许恢复为固定状态，不要求先激活轨道。

区块或轨道承载结构尚未就绪时保留记录，按滑车错峰周期重试，不强制加载。已加载目标变为空气、止冲器、异轴／异面轨道，或归属、位置姿态明确失效时清除旧目标；随后只按正常规则寻找新的激活轨格。

区块卸载、滑车移除、结构卸载／删除、维度卸载都释放运行时关节和索引。临时卸载保留保存目标；确定性拆除清除目标。`StraightRailBodyRemovalMixin` 只处理关节释放，不再接管质量更新或覆盖质心。


## 性能与同步边界

- 轨格和止冲器没有方块实体、客户端特殊渲染器或逐格 Tick。
- 红石变化只刷新当前连续直线两侧各最多 8 格，不根据相邻 `powered` 值接力。
- 未挂轨滑车错峰每 5 Tick 查询局部 3×3×3 格及相交结构，不遍历所有轨道。
- 已挂轨滑车每游戏 Tick 校验真实轨格和参与方；阻尼按物理子步执行。
- 连续跨格保留同一 Generic 关节。止冲器双向前瞻最多各 64 格，遇断口或未加载边界即停止。
- 行程边界基于固定关节锚点计算，仅边界改变或关节重建时写入 native limit。
- 同一刚体通过 UUID 索引保证最多一条连接。
- 轨道外观走普通方块模型及 BlockState 同步，没有路径预览包、区间同步包或客户端路径缓存。
- 轨道模型、贴图资源集中在 `block/cargo_rail`，不沿用旧节点目录；滑车和止冲器分别维护。

不要重新引入全局轨道扫描、每轨格方块实体、曲线采样、质心覆盖或通用物理接管层。

## 回归检查

1. 六面安装的轨道、止冲器和滑车按同一轴向规则旋转与对齐。
2. 轨道保持 3px 碰撞层；止冲器保持完整一格碰撞。
3. 单源、双源和信号移除均正确更新；断口、错向和止冲器阻断传播。
4. 任意激活中段可捕获滑车；静态滑车、同刚体轨道及止冲器不作为新挂接目标。
5. 断电锁定、再次激活解锁、保存／重载和拆除释放行为正确。
6. 正反方向阻尼均每 Tick 保留 85%，物理子步分拆不改变衰减；低速归零。
7. 止冲器限位在两端、所有安装面及固定关节锚点偏移下正确，拆除／断轨后清除。
8. 干净构建后的 JAR 不包含旧节点、路径包、轨道渲染器或质心修改 Mixin。

按受影响功能选择相关测试，范围见[变更验证策略](../06开发与运维/06_变更验证策略.md)；实体运动、碰撞接触及美术对齐还应在游戏中实测。
