# 轨道存档恢复、性能与维护

本章面向维护者，说明货柜轨道的权威数据、恢复时序、索引和性能边界。

## 权威数据划分

轨道系统使用两类 SavedData：

| 数据 | 类 | 内容 |
|---|---|---|
| 轨道路径 | `CargoRailPathSavedData` | 区间 UUID、两个端点、轴与安装面、数学路径 |
| 滑台附着 | `CargoRailAttachmentSavedData` | 滑台 UUID、区间 UUID、接口位置及恢复所需状态 |

方块 BlockState 只保存节点自身的朝向和红石外观，不是路径或附着关系的权威来源。客户端轨道模型同样只是由路径数据派生的缓存。

保存和读取均受统一 SavedData 条目上限保护。载入时会丢弃重复端点、无效节点和使节点连接数超过2的路径。

## 运行时索引

为了避免反复全局遍历，服务端按维度维护以下主要索引：

| 索引 | 用途 |
|---|---|
| `groupsByPath` | 由路径 UUID 直接取得运行时轨道组 |
| `groupsAtNode` | 查找节点相邻区间与开放端点 |
| `connectionsByPath` | 取得某个区间上的全部滑台连接 |
| `connectionByCargoId` | 由滑台/物理结构 UUID 直接取得唯一连接 |
| `poweredByPath` | 缓存区间两端的红石计算结果 |
| 接口空间分桶索引 | 只查询开放端点附近的接口候选 |

路径删除、区间切换和滑台离轨必须同步维护这些索引。新增业务逻辑不得重新扫描所有轨道组或所有接口来代替索引查询。

## 捕获性能模型

旧式“每条轨道扫描全部接口”会形成轨道数与接口数的笛卡尔积。当前实现改为：

1. 只把拓扑开放端点加入捕获入口集合。
2. 滑台接口位置变化时增量更新世界空间分桶。
3. 捕获时只访问端点附近少量空间桶。
4. 对候选执行精确距离、速度和姿态检查。

因此，一条普通连续轨道组通常只有两处捕获查询位置，轨道中段不执行接口扫描。长轨道增加的是路径采样和已连接滑台维护成本，不会线性放大对全世界接口的搜索。

## 红石缓存

节点邻居变化时更新节点 `POWERED` 状态，并计算区间是否满足“两端均激活”。结果写入 `poweredByPath`。

PrePhysics 阶段只读取缓存结果并切换 Generic/Fixed，不重新遍历节点方块。修改节点红石传播逻辑时，应在服务器方块更新路径中刷新缓存，而不是把世界查询放回物理线程。

## PrePhysics 维护

以下操作在 Sable 物理模拟前执行：

- 处理待恢复附着。
- 检查当前约束句柄和 SubLevel。
- 更新 Generic 轨道帧与区间切换。
- 应用轴向阻尼。
- 更新轨道运行质心。
- 根据缓存红石状态切换 Generic/Fixed。

这样可以保证结构在受到本物理步重力前恢复约束，避免普通方块实体 Tick 或固定等待 Tick 导致滑台先掉离轨道。

## 待恢复队列与退避

存档加载、区块加载和 Sable SubLevel 恢复并不总在同一 tick 完成。持久化附着因此进入待恢复队列，而不是立即失败或每 tick 无限重试。

恢复流程为：

```text
读取附着记录
  → 路径与节点是否存在
  → 承载 SubLevel 是否存在
  → 滑台 SubLevel 是否存在
  → 从接口实际世界位置重新投影路径
  → 按红石缓存创建 Generic 或 Fixed
  → 成功后建立运行时索引
```

暂时缺少区块或 SubLevel 时使用递增退避，最长间隔 `200 tick`。确认路径、接口或物理结构永久无效时才删除附着记录。恢复过程不得依赖客户端、玩家是否在线或终端界面是否打开。

## 客户端渲染缓存

客户端按路径 UUID 缓存烘焙后的轨道段。缓存键必须包含路径几何与端点状态；新增或删除其他区间不应让无关路径消失。

渲染包围盒需要覆盖整条区间，而不能只使用起点方块实体的默认一格范围，否则起点离开屏幕后长轨道会被错误裁剪。

节点、模型左右轨和弯道采样均应从同一个路径坐标系派生。不要按起终点点击顺序增加局部镜像补丁，否则反向创建路径时会再次交换左右轨。

## 性能边界

当前主要常驻成本来自：

- 已连接滑台：每物理步投影、约束帧、阻尼和质心维护。
- 开放端点：周期性查询附近空间桶。
- 客户端可见路径：轨道段模型渲染。
- 拓扑或红石变化：重建相关局部索引与状态缓存。

不会对每个轨道模型片段创建方块实体或服务端 tick。视觉采样数量只影响客户端模型构造和渲染，不会直接增加 Sable 约束数量。

多人服务器下建议：

- 用更多短区间组织复杂路网，但避免大量没有用途的开放端点。
- 不要把捕获逻辑恢复为全局扫描。
- 不要在 PrePhysics 中读取大范围世界方块。
- 路径修改后只失效受影响 UUID 的缓存和连接。
- 新增变轨节点时保留“普通节点最多两条连接”的约束。

## 已知设计边界

- 普通节点不承担三岔或多岔变轨；变轨应使用未来专用节点。
- 单区间最多一次90°转弯，不能表达任意样条曲线。
- 区间最大16格，不适合一次跨越超长距离。
- 滑台必须从开放端点入轨，不能从轨道中段直接吸附。
- 轨道碰撞仍由世界与滑台实际方块决定；渲染模型不是实体碰撞轨。
- Generic 动态路径依赖物理步维护，不等同于 Sable 原生曲线关节。

## 修改检查清单

修改轨道系统后至少验证：

1. `A → B` 与 `B → A` 的模型左右轨一致。
2. 地面、墙面、天花板节点均可铺设、捕获和恢复。
3. 平面弯道与跨平面弯道可双向通过。
4. 任一端点破坏后路径、渲染和连接同时清除。
5. 节点连接数达到2后服务器拒绝第三条路径。
6. 两端红石组合正确切换 Generic/Fixed。
7. 区块卸载、重载和服务器重启后约束在 PrePhysics 恢复。
8. 强制脱轨后按当前结构恢复自然质心。
9. 多个开放端点和多个滑台存在时不会互相抢占同一滑台。
10. 长轨道离开起点视锥后仍正常渲染。
