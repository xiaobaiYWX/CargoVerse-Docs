# 数据定义与维护

本页说明特殊订单数据如何落盘、如何挂载到贸易点，以及数据包重载对运行状态的影响。具体数值应先在 [Markdown 设计模板](../10数据包定义与模板/13_特殊订单/README.md) 中完成，再同步到 JSON。

## 文件位置与资源 ID

特殊订单定义放在：

```text
data/<namespace>/trade_points/trade_points_subfunctions/special_order_definitions/<path>.json
```

资源 ID 由命名空间和相对路径组成。例如：

```text
data/cargoverse/trade_points/trade_points_subfunctions/
special_order_definitions/market/test_station/a_to_b.json
```

对应：

```text
cargoverse:market/test_station/a_to_b
```

特殊订单不再使用独立的订单池定义目录。

## 挂载到贸易点

订单列表直接内置在发布贸易点定义的 `modules.special_orders` 中：

```json
{
  "modules": {
    "special_orders": {
      "offer_slots": 5,
      "orders": [
        {
          "order": "cargoverse:market/test_station/a_to_b",
          "min_prosperity_level": 2,
          "weight": 1
        }
      ]
    }
  }
}
```

| 字段 | 作用 |
| --- | --- |
| `offer_slots` | 本贸易点每天尝试展示的订单数，范围 `1..5` |
| `orders[].order` | 特殊订单定义 ID |
| `orders[].min_prosperity_level` | 该订单进入候选列表所需的最低繁荣等级 |
| `orders[].weight` | 满足条件后参与抽取的正整数权重 |

繁荣度限制属于具体订单条目，而不是整个订单模块，因此同一贸易点可以同时发布基础任务和高繁荣度任务。

## 已删除或拒绝的旧字段

以下内容属于普通货柜或旧版订单结构，不应再出现在特殊订单定义中：

| 旧字段／内容 | 当前替代方案 |
| --- | --- |
| `cargo_good`、`cargo_units` | 只填写 `cargo_display_name` 供玩家识别 |
| `capacity`、空柜质量 | 直接填写 SP 货柜 `total_mass` |
| `dispatch_points` | 特殊订单不消耗玩家调度点 |
| `special_designs`、`design_defects` | 需要的运输要求直接写入 `constraints` |
| `shipment.transport_affixes` | 使用独立的 `constraints` |
| 顶层 `time_limit` | 使用 `cargoverse:time_limit` 限制 |
| 外部订单池定义 | 使用贸易点 `modules.special_orders.orders` |

## 重载与存档规则

- 未领取的每日订单由当前数据包定义和当日种子生成；重载后按新定义工作。
- 已领取委托使用领取时锁定的目的地、限制、截止时间和奖励，不因普通数值调整而重算。
- 删除订单定义会使相关活动委托进入清理流程，因此不要在仍有玩家运输时直接移除线上订单 ID。
- 修改文件路径等于更换资源 ID；仅修改显示名或参数不会创建新 ID。
- 贸易点模块引用不存在的订单 ID、订单引用不存在的 CargoClass、模板、贸易点定义或物品时，应在数据加载阶段修正，而不是留到玩家领取后处理。

## 推荐维护流程

1. 在[特殊订单数据设计模板](../10数据包定义与模板/13_特殊订单/README.md)中创建或调整 Markdown 设计稿。
2. 检查目的贸易点定义、距离范围、限制组合和奖励曲线是否自洽。
3. 将确认后的字段同步到订单 JSON。
4. 在发布贸易点的 `modules.special_orders.orders` 中挂载订单并设置繁荣度与权重。
5. 使用测试贸易点 A／B 验证每日抽取、生成、运输、交付和奖励结算。
