核心思路：

> **活跃度只在有交易的当天被推高；之后无人造访的空白天数直接用指数衰减一次算完。**

---

# 一、推荐活跃度模型

使用这种更新公式：

```
activity_new = activity_old + response_rate × (target_activity - activity_old)
```

当某天有交易时：

```
target_activity = clamp(daily_trade_value / expected_daily_trade_value, 0, 1)
```

当某天没有交易时：

```
target_activity = 0
```

如果连续很多天没有交易，不需要循环每天更新，而是直接：

```
activity_after_idle = activity_before_idle × (1 - response_rate) ^ idle_days
```

这就是关键。

例如：

```
activity = 0.8
response_rate = 0.25
无人造访 10 天

activity = 0.8 × 0.75^10 ≈ 0.045
```

不需要跑 10 次循环，更不需要跑几千次。

# 二、运行时需要保存的数据

贸易点运行时只需要保存：

```
{
  "activity": 0.42,
  "last_activity_day": 128,
  "current_day_trade_value": 350.0
}
```

字段含义：

```
activity                  当前活跃度，范围 0~1
last_activity_day          上次结算活跃度的世界天数
current_day_trade_value    当前未结算日期内累计的有效交易价值
```

世界天数：

```
current_day = game_time / ticks_per_day
```

# 三、每次打开终端时的结算逻辑

当玩家打开贸易点终端，或者贸易点被加载时，执行一次 lazy update。

假设：

```
current_day = 当前世界天数
last_day = last_activity_day
elapsed_days = current_day - last_day
```

## 情况 1：同一天

```
elapsed_days <= 0
```

不结算活跃度，直接使用当前 activity。

---

## 情况 2：经过了 1 天

说明需要把上一天的交易量结算掉。

```
target = clamp(current_day_trade_value / expected_daily_trade_value, 0, 1)
activity = activity + response_rate × (target - activity)
current_day_trade_value = 0
last_activity_day = current_day
```

---

## 情况 3：经过了很多天

例如贸易点 2000 天没人打开。

流程：

```
1. 先结算 last_activity_day 那一天残留的 current_day_trade_value。
2. 后面的空白天数直接指数衰减。
3. 不逐日循环。
```

公式：

```
activity_after_trade_day =
activity + response_rate × (target - activity)
```

```
idle_days = elapsed_days - 1
```

```
activity_final =
activity_after_trade_day × (1 - response_rate) ^ idle_days
```

然后：

```
current_day_trade_value = 0
last_activity_day = current_day
```

# 四、伪代码

```
void updateActivity(TradePointRuntime runtime, ActivityConfig config, long gameTime) {
    long currentDay = gameTime / config.ticksPerDay();
    long lastDay = runtime.lastActivityDay();

    long elapsedDays = currentDay - lastDay;

    if (elapsedDays <= 0) {
        return;
    }

    double activity = runtime.activity();

    // 先结算 lastDay 当天累计的交易价值
    double load = runtime.currentDayTradeValue() / config.expectedDailyTradeValue();
    load = clamp(load, 0.0, config.maxDailyLoad());

    double target = clamp(load, 0.0, 1.0);

    double response = config.responseRate();

    activity = activity + response * (target - activity);

    // 后续无人交易的空白天数直接指数衰减
    long idleDays = elapsedDays - 1;

    if (idleDays > 0) {
        activity = activity * Math.pow(1.0 - response, idleDays);
    }

    runtime.setActivity(clamp(activity, 0.0, 1.0));
    runtime.setCurrentDayTradeValue(0.0);
    runtime.setLastActivityDay(currentDay);
}
```

这样即使经过 5000 天，也只计算一次 `Math.pow()`。

# 五、交易发生时怎么记录

每次完成交易时，不直接改 activity，只累计当天交易价值。

```
void recordTrade(TradePointRuntime runtime, CargoGood good, double amount, TradeSide side) {
    double weight = side == TradeSide.INPUT
        ? config.inputTradeWeight()
        : config.outputTradeWeight();

    double value = amount * good.baseValue() * weight;

    runtime.currentDayTradeValue += value;
}
```

这样可以避免玩家通过频繁小额交易刷交易次数。

活跃度只看：

```
交易货物数量 × 货物基础价值
```

不看交易次数。

# 六、activity 对产出的影响

活跃度最终只影响生产倍率：

```
activity_multiplier =
min_multiplier + activity × (max_multiplier - min_multiplier)
```

例如：

```
"production_multiplier": {
  "min": 0.8,
  "max": 1.5
}
```

则：

```
activity = 0.0 → 0.8x
activity = 0.5 → 1.15x
activity = 1.0 → 1.5x
```

产线生产时：

```
actual_output =
line.output.amount
× random_multiplier
× activity_multiplier
```

input 消耗也同步乘同样倍率：

```
actual_input =
line.output.amount
× input.consumption_rate
× random_multiplier
× activity_multiplier
```

这样活跃度提高的是“贸易点生产规模”，不是免费提高转换效率。
