# 货物与贸易工程边界

更新：2026-11-27。本页只描述当前数据、交易、权限和同步职责；未实现工作单独列出。

## 1. 首版边界

实际物品和液体（包含标准 Fluid 气体）闭环已接入共用资产封套、带类型身份、原生数量／操作份数、时钟及确认后端分发；实体存取及自然／玩家贸易交易已接入通用后端。液体以整数 mB 保存、每 1000mB 常规装卸，完整规则见[液体运输](<../../02系统规则/货物与货柜/13_液体运输.md>)。固体货柜每件占 1 个容量单位。装卸组大小取精确物品的最大堆叠量并冻结；固体质量按实际件数乘单件质量计算。

一柜只存一种物品及一种完整组件状态；名称、耐久、附魔等不同变体不能混装。首版拒绝已知非空嵌套容器及无法无损编码的内容。缺失物品或损坏载荷隔离并保留原文，不降级为空柜。

## 2. 数据职责

| 数据 | 现行职责 |
| --- | --- |
| CargoKind / CargoKey / CargoMeasure | 类型化选择键、原生计量与操作步长；物品按最大堆叠组、液体按 1000mB 操作 |
| CargoContent / CargoTransportRules | 真实载荷与冻结规则的通用读取／原生减量边界，已注册物品、液体与生物实现 |
| ItemCargoIdentity / ItemCargoPayload | 原生物品 ID、完整组件、整数数量 |
| ItemTransportProfile / ItemTransportSnapshot | 分类、单位质量、固定扣量要求；装载时冻结 |
| CargoContainerSnapshot | 设备、分类许可、容量、空柜质量 |
| CargoLoad / CargoContent.session | 通用载荷封套、冻结数值会话、取得成本与原生扣量 |
| CargoTransferOrderService / CargoTransferBackends | 共用确认与货柜占用生命周期，按类型进入真实后端；已接入物品、液体与生物后端 |
| ResourceTableDefinition / TradePointResourceCatalog | schema 3 站点报价、库存策略、每日额度与交付经验 |
| PlayerTradeVaultInventory | 通用物品接口适配、精确变体报价及短周期观察缓存，不拥有实物库存 |
| TunnelStorageLinks / PlayerTradeFluidInventory | 入口频率网络索引、通用流体接口观察与报价；不拥有库存，转移通过原生接口及回执 |
| PlayerTradeLogisticsNetwork | 实际转移时的有界寻路与可达缓存，不承担归属，不保存途中货物 |

不保留抽象货物目录、全局物品基础价、全局经验或另一套仓库账本。运输可用性不代表自然贸易点必须收售该物品。

## 3. 仓储与交易

实际物品和流体保存在支持 NeoForge 通用接口的容器中，包括箱子、木桶、炼药锅及 Create 保险库／储罐。玩家在终端和容器接口安装同频的物流隧道入口，再以实体管线连通。库存浏览只读取同频网络内已加载的容器，真正转移时还需核验隧道路径；原链接器不参与连接，不强制加载区块。

出售、收购终端分别维护本台报价，管理者点击本体空白处进入对应编辑器；货物装载机和货柜卸载机通过物流隧道与仓储转移实物，独立于公共交易。核心仅维护站点身份、授权及结算账户，站点绑定在终端 GUI 中选择，默认发现范围 32 格。

仓储没有独立玩法数量配额；多方块和双箱去重，所有容器遵守自身原生接口规则与内部技术预算。管线断开保留地址关联和报价，暂停实际装卸；不会清除容器内容或改变站点归属。详情见[入口与频率网络](<../../03组件手册/玩家物流/02_物流隧道入口与链接器.md>)及[物流隧道](<../../03组件手册/玩家物流/04_物流隧道.md>)。

交易重新校验实际库存、货柜、范围、绑定和资金，失败回滚本次变更，不用整仓旧快照覆盖 Create 当前内容。不为读取仓库强制加载区块。

## 4. 自然站点报价与经验

价格设置在具体交易处，不属于物品运输参数。schema 3 使用精确 item/components、type=liquid 的 fluid/components 或 type=living 的 entity、本地 unit_price、可选出售 stock、收购 daily_limit，以及收购侧许可证经验，未配置经验为 0。贸易点繁荣度和制造商交付声望由独立物资供应结算。物品按最大堆叠组、液体按每 1000mB、生物按只配置报价／库存／限额／经验；尾量正常成交，金额按比例向上取整数、经验每笔向下取整。载荷保存原生 pcs／mB 或逐只生物数据。

运输许可证经验按收购目的地判定。向已注册的自然贸易点交付时按实际成交份数和目的地报价结算，手动放置与世界生成的自然贸易点均适用。物资供应单独推进公共繁荣度与个人制造商声望。

不再记录来源批次或维护 FIFO 来源。自产、管理员补入及玩家保险库中转货物到自然目的地成交时均按报价奖励；仓库装卸本身不奖励。只计算实际成交件数，成功付款、货物和两类经验在同一补偿事务内提交，失败或重复请求不得重复奖励。

8个制造商天空主站与16个地面小站的资源表已接入，A／B指令测试站按互补分组覆盖固体、液体和生物。各站当前商品和报价见[交易列表](../../05内容数据/03贸易点/交易列表/README.md)，配置规则见[资源表定义](../../04数据规范/贸易点/03_资源表定义.md)。

## 5. 权限、建点与 Sable

- 核心管理、商品配置和站点绑定通过相应界面操作，提交时校验设备及站点权限。物流接入通过隧道入口配置。
- 副终端管理界面对所有者、委任管理员和 CargoVerse 管理员模式开放。未绑定的副终端由放置者或管理员模式配置。公共交易控件对所有玩家开放。
- 核心放置后无主，手持结算器插入槽位即可认领，所有者为插入者；不限制认领数量。核心外壳右键打开名称与授权菜单，认领后仅所有者可交互。
- 仅所有者可拉动弹出拉杆，动画完成后再次核验所有权并从基座抛出带原余额的结算器；同时解除归属、绑定和授权，停用公共交易并使旧菜单失效。终端本地报价、核心方块和外部容器内容保留。缺少收购、出售或航标塔只影响对应接入灯，不阻止其他交易。
- 核心授权只查询本存档 `playerdata/*.dat` 已有玩家，按名称或 UUID 匹配；本地 UUID 缓存仅提供这些记录对应的名称，不联网查询或生成离线 UUID。新玩家尚无保存记录、或本地缺少对应名称时直接拒绝添加，不引入兜底。
- 玩家贸易点设施可放置在 Sable 上，但不能绑定或使用，服务端校验并提示；不删除方块或仓库物品。
- 限制设施不限制货柜本身，静态贸易点仍可装卸 Sable 运来的货柜。

## 6. 存档与同步

开发期破坏性重构，不迁移旧抽象货物、完整度、自有仓库或旧经济数据，也不建立兑换表。

货柜、载荷、经济存档和网络版本统一见[当前数据契约](<../../02系统规则/货物与货柜/07_运行时与存档.md#当前数据契约>)。旧实例条目不迁移，测试货柜需重建；未知原生类型整包隔离，不落入物品分支。载荷不记录来源批次；商品 GUI 向打开菜单的所有者定向同步有界显示行。

运输配置与物品标签在标签绑定后编译并原子发布，冲突保留上一完整代，不在装卸 tick 扫描全注册表。

## 7. 界面与统计收尾

HUD 显示实际数量、剩余保护时间和质量，不恢复完整度或吨数。玩家信息柜无全局基准价，不显示伪涨跌，模型基座保留；普通站点信息柜仍以当地报价为基准。

航运风格货值轴改用出发时实际货物取得成本 / 件数，保留小数并存档，不读取固定 0 或旧基础价；不计空柜成本。风格统计不等于运输经验资格，算法见[航运风格](<../../02系统规则/玩家档案/08_航运风格统计与雷达图.md>)。

## 8. 运输参数约定

### 8.1 分类与质量

三种源码形态为 solid／liquid／living，当前实际物品均为 solid。2315 份逐物品 JSON 直接声明质量、准入、贴花和条件；缺失时源码默认 solid／0.1 Kpg／standard／无条件／none 贴花。内置质量保持一位小数，零质量仍占容量并执行损耗和结算。

同一物品在不同形态目录重复声明时拒绝新一代；不用文件顺序、注册名或配方猜分类。追加要求完整身份和冻结规则一致，reload 不改途中货物。物品悬停隐藏分类及默认来源，仅保留必要的装载限制和运输需求，后台形态数据仍用于既有业务。

### 8.2 固定数量损耗

数值模型按原因扣固定整数原生数量，不是百分比；不足时扣到零，不生成损坏货物。旧按 ID 行为引擎不再运行；注册配置及已注册条件／能力求值已接通，内置数据已配置，正式参数校准与实机验收仍需继续，详细查看已由 PDA 覆盖，不继续深化设备操作，见[实际完成度](<../../02系统规则/货物与货柜/14_运输数值运行时.md>)。撞击按相隔 10 tick（0.5 秒）的两次速度向量差判断，缓冲增加耐受；急加速、急刹、急转与碰撞同等处理，一事件只扣一次，不作自由落体特判。倾角条件独立结算。环境采样只结算实际条件，不模拟未加载时的未知环境。

损耗后立即按剩余数量计算质量；交易按实际转移件数计价，不再叠加完整度折价。具体参数见[当前运输规则](<../../05内容数据/01运输物品/固体/03_交付形态与运输条件.md>)。

### 8.3 数值年龄与生命周期

持续不符合条件才推进对应的计时，恢复符合后重置。冷冻和保温共用这套规则，停机或观测缺失的时间不计入。

追加前结算有效观测，并保留整柜当前的条件计时，部分卸货同样保留状态。原生入库结束卸出货物的本次运输，卸空再装按当前规则初始化。
