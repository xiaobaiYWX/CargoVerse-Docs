# 文档维护约定

更新：2026-11-07。目录按阅读目的划分，不按 Java 包、方块注册类型或历史开发顺序划分。

| --- | --- | --- |

| 完成阶段记录、旧分类、旧新数值对照 | 99历史资料 | 当前实现或发布状态结论 |

## 单一维护位置

- 系统规则说明为什么及何时发生；组件手册说明怎么操作；数据规范说明字段怎么表达；内容数据说明具体配了什么。其他章节以链接连接，不复制整段参数。
- 同一数据表只保留一个当前维护入口。通用 JSON 示例必须标为示例，不能替代运行数据；逐物品查阅仍由当前 JSON 同步。
- 单个贸易点的目录保持完整，内部保留总体说明、结构设计、定义设计和生成规则。通用结构制作规范单独维护，避免在每站复制。
- 单个制造商／系列／型号仍逐级查阅。模板归属遵循 NBT 实际命名，缺失和错引在型号页明确标注；预留、验证与历史兼容型号不放进正式型号表。
- 生存获取方式、文档查阅分类和运输准入分别维护，不因目录归类修改运行参数。

## 页面状态与内容

页面开头注明用途或状态；草案和历史资料必须显式标记。测试通过只说明该次测试范围，不代表实机、多人或全部内容已经验收。首页和总索引不重复滚动变化的总数、模板完成数或待办状态。

组件页建议包含用途、安装条件、操作、状态反馈、限制、相关规则。规范页包含加载路径、字段与单位、校验、示例、具体实例入口。内容页包含 ID、现值、来源、设计理由与待核对项。模板见仓库 templates。

## 链接与变更

- 使用 UTF-8 和相对路径；有空格的 Markdown 目标用尖括号，不记录本机私人绝对路径。
- 文档移动时同步更新 Markdown 链接、图片、章节锚点引用和 Obsidian 文件引用；不得更改运行数据包路径来迎合文档目录。
- 完成草案后把生效规则并入相应正式页，旧对照归历史；不保留两个相互矛盾的正式版本。
- 修改数字或行为时先核对当前代码／JSON；本轮重排主要改变归属和引用，未开展全项目运行行为复验。
