# 运输条件与货柜能力：类型和参数

本页记录源码已注册的参数协议，**注册、参数解析、运行求值、内置数据投放是四个不同层次**。下表 13 类条件、11 类能力均已接入运行求值；这不代表内置内容已全部赋值或设备操作界面已完成。

运行链路及当前内容数量见[运输数值运行时](14_运输数值运行时.md)；未完成规格、候选参数及待办统一见[待完成事项清单](../../设计草案/待完成事项清单.md#运输条件与能力专项)。

## 配置归属

| 位置 | 职责 |
| --- | --- |
| `TransportTypes` | 源码统一注册 ID、参数类型、语义位置、名称／说明翻译键、图标及共用过程分类 |
| `TransportConfiguration` | 严格解析、组合校验，编译到既有直接比较、范围暴露和老化过程，不创建逐 ID Handler |
| 逐物品／逐流体文件 | 身份、质量、贴花、准入，以及 `transport_conditions: {注册ID: 参数对象}` |
| 货柜定义 | `abilities: {注册ID: 参数对象}`；介质、容量、空重、模板、制造材料仍在原位置 |
| 运行会话 | 工作模式／目标、实际状态、累计量及本次冻结声明，作者不填写动态状态 |

物品路径为 `data/<namespace>/cargoverse_item_properties/solid/<item>.json`；流体路径为 `data/<namespace>/cargoverse_fluid_properties/liquid/<fluid>.json`。一份文件只对应一个实际对象，价格和经验属于贸易报价，不在运输属性中声明。

物品／流体新注册格式使用 **schema 3**，与 `transport`、`transport_requirements` 互斥；货柜沿用其原有 **schema 1**，但 `abilities` 与根级 `transport_capabilities`／`thermal_control` 互斥。没有独立条件／能力定义目录、公共档位文件、profiles、继承覆盖或规则脚本。

## 运输条件

表内省略统一命名空间 `cargoverse:`。`loss` 的原生数量单位见下文。

| ID | 名称与读取对象 | 参数 | 当前运行 |
| --- | --- | --- | --- |
| `fragments` | 碎料，要求有效围护 ≥1 | `loss`；运输运动期间围护不足才累计散落损耗 | 可执行 |
| `powder` | 粉料，要求有效围护 ≥2 | `loss`；运输运动期间围护不足才累计散落损耗 | 可执行 |
| `volatile` | 易挥发，要求有效密封 ≥2 | `loss`；密封不足时累计挥发损耗 | 可执行 |
| `perishable` | 易腐坏，实际温度驱动老化 | 正整数 `budget_ticks`、`temperature_rates`、不含 grace 的 `loss`；可选 `preferred_temperature` | 可执行，推荐目标参与自动控制 |
| `frozen_transport` | 冷冻运输，内部温度上限 | `max_temperature`、`loss`；可选 `preferred_target` | 可执行，推荐目标参与自动控制 |
| `cold_sensitive` | 低温敏感，内部温度下限 | `min_temperature`、`loss`；可选 `preferred_target` | 可执行，推荐目标参与自动控制 |
| `heat_sensitive` | 高温敏感，内部温度上限 | `max_temperature`、`loss`；可选 `preferred_target` | 可执行，推荐目标参与自动控制 |
| `light_sensitive` | 避光储存，内部光照上限 | 整数 `max_light` 0～15、`loss` | 可执行；15 归一为无约束 |
| `pressure_sensitive` | 气压敏感，内部气压范围 | 非负 `min_pressure`／`max_pressure` 至少一项、`loss`；可选 `preferred_target` | 可执行，推荐目标参与自动控制 |
| `fragile` | 易碎品，4 tick（0.2 秒）窗口内速度向量变化上限 | 正数 `max_velocity_change`、正整数 `damage_amount` | 可执行；超过最终耐受，一事件只扣一次 |
| `keep_upright` | 保持正放，内部承载面倾斜 | `max_tilt_degrees` 0～180、`loss` | 可执行；180 归一为无约束，0 是严格正放要求 |
| `keep_dry` | 保持干燥，内部湿度上限 | `max_humidity` 0～100、`loss`；可选 `preferred_target` | 可执行 |
| `requires_light` | 保持光照，内部光照下限 | 整数 `min_light` 0～15、`loss` | 可执行；0 归一为无需求 |

温度使用有限 TU，不是摄氏度；气压为非负相对系数，1 是参考压力。湿度为 0～100 游戏指数，不宣称真实相对湿度。易碎耐受为格／游戏秒的速度向量变化，不是加速度或 J。窗口内最大速度向量差严格超过 `max_velocity_change + velocity_change_bonus` 才损坏，急加速、急刹、急转与撞击同样处理，无自由落体特判。新批次窗口为 4 tick，旧合法窗口继续冻结；玻璃首轮基础耐受 10、每事件损失 1 pcs；缓冲增量 2／8 分别提高到 12／18。事件、暂停与倾角规则见[运行公式](16_运输观测与生命周期.md)，正式分配仍须实运校准。

### 组合与校验

- 未配置表示没有相应需求，不从名称、配方、制造商或用途推断。碎料／粉料／易挥发只配置损耗，不允许填写 `required_level` 覆盖固定阈值；不需要该条件时删除对应条目。物理边界 0 仍有效。
- 注册参数对象不能统一用数值 0 替代，必要字段与正整数损耗必须齐全。碎料和粉料占用同一个围护需求位置，不得同时声明、重复扣货。
- 冷冻与高温敏感共占 `temperature.max`，同时声明报重复，不能靠显示两个名字重复扣货。
- 温度上下限可组合，范围不得倒置；各边界的周期、数量和暴露余数独立，共用一份实际温度及温度风险摘要。
- 推荐目标检查一致性及是否处于最终安全范围，并参与自动控制；未推荐则只做最小必要调节。光照上下限也检查组合区间不得倒置。
- 未知 ID／参数、缺字段、非有限值、非法范围、非整数扣量、重复语义均报错。流式 JSON 入口拒绝重复键，不让 Gson 后值覆盖前值。

### 共用损耗

```json
"loss": {"grace_ticks": 100, "interval_ticks": 200, "amount": 1}
```

`grace_ticks` 为非负累计不利暴露预算，`interval_ticks` 为正周期；首次扣量发生在累计达到 grace＋interval 时。安全期间暂停累计，保留余数，不重新赠送预算。时间使用服务端 tick，20 tick＝1 游戏秒，不跟随现实墙钟。

`amount` 为正整数原生数量：固体 pcs、液体 mB，不是栈或桶。周期结算使用商／余数，合计封顶到现存数量，不逐物品、逐 mB 或逐周期遍历。

易腐坏用 `budget_ticks` 表示保存预算，`loss` **只能**包含 `interval_ticks` 和 `amount`。有效老化时间耗尽预算后开始周期扣量；直接温度损伤期间不叠加同源老化损耗。独立风险仍可并行。

### 老化曲线

```json
"temperature_rates": {"breakpoints": [20, 40], "rates": [0.2, 0.5, 1]}
```

采用分段常数：T＜20 为 0.2，20≤T＜40 为 0.5，T≥40 为 1。断点严格升序、最多 32 个，速率数＝断点数＋1，速率为有限正数且不超过 1000000。空断点配一个速率表示恒定老化。预算／周期等计时参数的源码上限为 10¹² tick；该安全上限不是内容推荐值。

内部计算不按 UI 精度舍入；界面一位小数不参与是否越界的判断。这里只确定结构，不为所有食品规定同一保存时长。

## 货柜能力

| ID                    | 参数                                                               | 当前运行                                  |
| --------------------- | ---------------------------------------------------------------- | ------------------------------------- |
| `containment`         | 整数 `level` 0～2                                                   | 直接防护，可执行                              |
| `sealing`             | 整数 `level` 0～2                                                   | 直接封存、有限压湿交换及泄压期间有效屏障可执行               |
| `cushioning`          | 非负 `velocity_change_bonus`                                       | 以格／游戏秒直接增加易碎耐受，不乘比例、不自动正放             |
| `vacuum_insulation`   | 正数 `exchange_time_seconds`                                       | 被动换热，可执行；不是抽空货物腔                      |
| `thermal_control`     | `supported_modes`、`target_min`／`target_max`、正数 `rate_per_second` | 按需自动调温可执行，初次默认自动，显式关闭保留；操作 GUI 待接入    |
| `light_blocking`      | 整数 `reduction` 0～15                                              | 削减外部传入亮度，可执行                          |
| `pressure_resistance` | 非负 `max_difference`                                              | 最大压差约束可执行；不主动增压                       |
| `pressure_control`    | 方向、目标范围、正数调节速度                                                   | 按需自动增压／减压，可执行；受壳体压差约束                 |
| `humidity_control`    | 方向、目标范围、正数调节速度                                                   | 按需自动加湿／除湿，可执行                         |
| `orientation_control` | 空对象 `{}` 或 `level: 1`                                                      | 有正放需求且自动开启时，内部承载面近似正放；真实倾角未知时不补零，撞击独立 |
| `internal_lighting`   | 整数 `max_light` 0～15                                              | 遮光后直接补足最低需求，可执行，不渐变                   |

温控方向仅为 `cooling`／`heating`，压力方向为 `pressurizing`／`depressurizing`，湿度方向为 `dehumidifying`／`humidifying`；双向设备列出两项，不写 `automatic`。压力目标非负，湿度目标在 0～100，范围不得倒置。温压湿速度分别按 TU、相对压力系数、湿度指数／游戏秒解释。

能力定义只声明配备和物理支持；自动／关闭选择属于运行实例，推荐目标由货物侧声明，最终控制范围受设备限制。环境设备沿用持久工作设置，初次默认自动、无需求待机；不能从静态能力条目推断实际环境已达标。此轮不新增能源、燃料或耗材成本。

当前默认自动与按需输出已接入服务端；独立设备操作、权限界面及故障状态反馈仍待接入，旧手动温控只作为内部兼容路径，不新增手动目标 GUI。被动／主动过程、围护隔热候选表和压湿减半时间见[运行公式](16_运输观测与生命周期.md)。

能力等级与实际响应参数分别声明：围护、密封继续使用 `level` 0～2；缓冲、真空隔层、温压湿调节及承压可额外填写整数 `level` 1～3，未填时为 1。遮光、补光和当前二态的朝向保持只接受 1。等级随冻结声明保存，供 GUI、仪表和 PDA 选择对应等级图案；速度耐受增量、时间、调节速度、削光量和压差仍按所填参数计算，不从等级自动生成强度，也不按连续数值反推等级。新增能力档位时应同时设置其 `level` 与实际参数。

未配主动设备不会自动开启；普通壳体仍有被动换热基线。液体柜至少显式配置密封 1，否则定义拒绝发布，不由介质自动补齐。液体柜本身液密与货物是否易挥发是两件事，不能把所有液体默认加上易挥发标签。

## 可执行格式示例

以下只演示协议，不是正式货物的平衡参数：

```json
{
  "schema_version": 3,
  "form": "solid",
  "unit_mass": 0.1,
  "decal": "cargoverse:decal_none",
  "admission_policy": "standard",
  "transport_conditions": {
    "cargoverse:powder": {
      "loss": {"grace_ticks": 0, "interval_ticks": 1200, "amount": 1}
    }
  }
}
```

流体使用相同的条件协议，基础质量字段改为 `mass_per_bucket`，1000mB 的质量由该字段声明；其余流体身份和整桶交易规则不在这里改变。

货柜局部示例：

```json
{
  "abilities": {
    "cargoverse:containment": {"level": 2},
    "cargoverse:sealing": {"level": 1},
    "cargoverse:cushioning": {"level": 2, "velocity_change_bonus": 2},
    "cargoverse:vacuum_insulation": {"level": 1, "exchange_time_seconds": 123.4},
    "cargoverse:thermal_control": {
      "level": 2,
      "supported_modes": ["cooling"],
      "target_min": 0,
      "target_max": 80,
      "rate_per_second": 0.27
    },
    "cargoverse:light_blocking": {"level": 1, "reduction": 7}
  }
}
```

## 仍在使用的过渡输入

这是当前资源依赖，不是另一个目标方案。物品／流体 schema 1 的 `transport_requirements` 仍可被读取为待清理资料，但不执行旧行为或生成有效需求；schema 2 的 `transport` 仍支持围护、密封、速度变化、液态水接触、亮度上限、温压范围及老化。其 `impact` 只接受 `max_velocity_change`／`damage_amount`，旧 J 的 `tolerance` 字段及旧机械配置不猜测迁移。

柜体 `transport_capabilities` 仍可读取围护／密封 0～2，以及缓冲／隔热／调温／遮光／承压 0～3；非零调温必须有根级 `thermal_control`。现行换算值见[观测与生命周期](16_运输观测与生命周期.md#过渡等级的运行换算)。

玻璃已迁入 schema 3；其余内置迁入 schema 3／`abilities` 与旧解析器删除仍待实施。逐内容迁入不能机械复制旧字母，也不能把旧字段一删、全部无需求当作平衡完成。未知旧载荷原文隔离与开发期不做猜测迁移的边界不变。
