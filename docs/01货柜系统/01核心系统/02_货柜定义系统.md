# 货柜容器定义

## 目录与身份

`data/<namespace>/cargo_containers/<path>.json` → `<namespace>:<path>`。

一个文件定义一种货柜物理型号。S、M、L、X、XL 型号不包含预装货物、货物数量或运输任务，制造后允许玩家按兼容性装载精确物品变体。

容器 ID 与结构模板 ID 是不同资源；例如容器 `cargoverse:aui/atlas_sd_s` 引用模板 `cargoverse:cargo/aui/atlas/aui_atlas_sd_s`。

## 内置示例

以下示例直接同步当前 Atlas S 定义；专用模板分配见[现行货柜目录](../../10数据包定义与模板/03_货柜/README.md)。

```json
{
  "schema_version": 1,
  "template": "cargoverse:cargo/aui/atlas/aui_atlas_sd_s",
  "manufacturer": "cargoverse:aui",
  "display_name": "AUI Atlas 标准干货柜 S 型",
  "description": "实际物品运输货柜；承载形态与运输保护以本定义为准。",
  "size_class": "S",
  "trade_currency": "cargoverse:void_byte",
  "dispatch_points": 1,
  "capacity": 50,
  "empty_mass": 20,
  "allowed_cargo_classes": [
    "solid"
  ],
  "special_designs": [],
  "design_defects": [],
  "tags": [
    "series.aui.atlas"
  ],
  "cargo_class_capacity_modifiers": {}
}
```

## 字段

| 字段 | 约束与职责 |
| --- | --- |
| `schema_version` | 必填整数，当前为 1 |
| `template` | 必填结构 ID，指向 `structure/<path>.nbt` |
| `manufacturer` | 必填，必须引用已加载制造商 |
| `display_name` | 必填非空字符串，直接显示；不解析多语言 key 或组件对象 |
| `description` | 可省略为空；填写时为直接非空字符串，可含换行和格式字符 |
| `size_class` | 必填；S/M/L/X/XL 为常规规格。SP 为保留类别，不参与规格排序、许可证等级和常规制造 |
| `trade_currency` | 当前必填且只能为固定结算单位 `cargoverse:void_byte` |
| `dispatch_points` | 必填整数，1～1000000；active 普通自有货柜占用的调度点数。SP 受托资产保留物理参数但不计入常规调度点 |
| `capacity` | 必填非负整数，物品按最大堆叠组、液体按 1000mB；未开放专项显式为 0 并标记 not_manufacturable，不省略容量或介质 |
| `empty_mass` | 必填有限非负数，最大 1000000；空柜目标质量，不是单件货物质量 |
| `allowed_cargo_classes` | 必填数组，必须且只能声明一个 solid／liquid／living；空数组、多种或重复介质均拒绝。旧用途类不再接受为新定义许可，历史资产另读冻结快照 |
| `cargo_class_capacity_modifiers` | 可省略对象；键必须同时存在于 `allowed_cargo_classes`，值为有限正倍率；`none` 不允许配置 |
| `special_designs` | 可省略；能够消除的运输词条 ID 列表 |
| `design_defects` | 可省略；装载时附加给货物的运输词条对象 |
| `tags` | 可省略；不替代形态匹配。现行 not_manufacturable 禁止制造，deferred_content 标识未开放内容 |

容器没有 `interface_type` 字段，也不会从 ID、目录或名称推导接口属性。描述中的“SD 接口”等只是展示文案；实际连接能力由结构里的接口方块决定。

## 数值和装载边界

基础容量、按 CargoClass 的容量修正、空重、防护和缺陷均由货柜定义独立维护，制造商定义不再参与货柜数值或词条解析。公式见[数值计算](06_货柜数值与词条常量.md)。货柜没有本体耐久，货损直接扣当前 Load 的原生数量（pcs／mB），不是完整度百分比。固体 capacity 的 1 单位表示一种完整组件状态物品的最大堆叠组；液体 capacity 的 1 单位表示 1000mB，换算时检查溢出。货柜定义不接受 `base_value`；制造价格只读取[货柜制造台定义](../../02贸易点系统/05_货柜制造台定义.md)中具体配方的 `currency_cost`。

装载许可比较实际物品运输配置中的 CargoClass 是否存在于 `allowed_cargo_classes`，不从物品 ID 路径推导。货柜定义不枚举具体物品；同一允许分类下的新物品沿用该类容量，仍需通过内容准入。制造时保存设备和分类容量快照，实际制造币种和金额另存为购买快照；物品交易使用站点 VB 报价，不从货柜制造成本反推货物价值。

货柜数量不再按定义分别使用 `max_owned` 限制。当前内置数据按常规规格统一为 S=1、M=2、L=4、X=6、XL=8 点；玩家总预算由[玩家档案](09_玩家档案与货柜调度点.md)按许可证等级提供。当前运行时仅计算 active 且未标记 starterContainer 的普通自有资产；基础资产的有效占用为 0，不修改型号定义和原设备快照中的调度点；pending_removal 及资产级 invalid 不占点。内部货物失效不改变 active 资产的占用。若重载后占用超过新预算，只阻止继续获得货柜，不删除存量资产。

即使同属一个 CargoClass，不同物品或不同完整组件状态仍不能混装。运输要求和设计缺陷最终写入 Load 的运输快照，不是货柜自己的永久词条。

## 数据边界

已制造货柜保存设备与兼容性快照，Load 保存冻结货物规则，重载不重写旧载货。旧 schema 1 货物可以卸出、禁止追加；清空后的旧柜在下一次成功装载时原子升级为同 ID 新定义，失败保持原资产。没有对应能力的旧 Reclaimer 明确拒绝新装载。改变 template 不会自动重建既有物理结构。

依据：`cargo/data/CargoContainerDefinition.java`、`CargoDataSet.java`、`cargo/CargoContainerSnapshot.java`。

当前使用三大形态与独立准入，实际物品统一为 solid；流体装卸已开放，活体、专用柜体和产品平衡仍待专项深化。模板职责、当前引用和原 NBT 候选见[制作清单](../../10数据包定义与模板/03_货柜/模板重分配与搭建清单.md)。
