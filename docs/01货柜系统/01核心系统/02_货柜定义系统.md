# 货柜容器定义

> 已实现：独立设备定义、直接文本、厂商物理修正和兼容性快照。货柜定义不再保存制造价值，制造币种与加工费用由贸易点绑定的货柜制造台配方提供。待验收：重载补装的一致性，见[状态清单 R2](../../00_重构状态与验收清单.md)。

## 目录与身份

`data/<namespace>/cargo_containers/<path>.json` → `<namespace>:<path>`。

一个文件定义一种货柜物理型号。常规 S/M/L/X/XL 型号不包含预装货物、货物数量或运输任务，制造后允许玩家按兼容性装载具体 CargoGood。`size_class = SP` 只预留给[特别订单货柜](10_SP特别订单货柜.md)：它的货物与订单由独立订单系统在生成实例时写入，不得作为普通空柜制造或装载。

容器 ID 与结构模板 ID 是不同资源；例如容器 `cargoverse:aui/atlas_sd_s` 引用模板 `cargoverse:cargo/aui/atlas/aui_atlas_sd_s`。

## 已实现：实际内置示例

## 字段

| 字段 | 约束与职责 |
| --- | --- |
| `schema_version` | 必填整数，当前为 1 |
| `template` | 必填结构 ID，指向 `structure/<path>.nbt` |
| `manufacturer` | 必填，必须引用已加载制造商 |
| `display_name` | 必填非空字符串，直接显示；不解析多语言 key 或组件对象 |
| `description` | 可省略为空；填写时为直接非空字符串，可含换行和格式字符 |
| `size_class` | 必填；S/M/L/X/XL 为常规规格，SP 为特别订单类别标记。SP 不参与规格排序、许可证等级和常规制造 |
| `trade_currency` | 当前必填，必须引用已定义的 currency_groups；不能用普通物品 ID 代替货币组。SP 的合同奖励币种不读取此字段，而从特别订单实例取得 |
| `dispatch_points` | 必填整数，1～1000000；普通自有货柜占用的调度点数，与货柜状态无关。SP 受托资产保留物理参数但不计入常规调度点 |
| `capacity` | 必填非负整数，基础容量，单位 t |
| `empty_mass` | 必填有限非负数，最大 1000000；空柜目标质量，不是每 t 货物质量 |
| `max_durability` | 必填有限正数，最大 1000000；与货物完整度独立 |
| `allowed_cargo_classes` | 必填数组，每项为固定 CargoClass ID；空数组不支持任何货物，未知分类拒绝加载 |
| `special_designs` | 可省略；能够消除的运输词条 ID 列表 |
| `design_defects` | 可省略；装载时附加给货物的运输词条对象 |
| `tags` | 可省略；普通字符串标签，当前不替代 `allowed_cargo_classes` 匹配 |

容器没有 `interface_type` 字段，也不会从 ID、目录或名称推导接口属性。描述中的“SD 接口”等只是展示文案；实际连接能力由结构里的接口方块决定。

## 数值和装载边界

制造商容量、质量和耐久倍率在解析时应用；按具体货物的容量修正使用完整 CargoGood ID。公式见[数值计算](06_货柜数值与词条常量.md)。`base_value` 已从货柜定义中删除，继续填写会拒绝加载；制造价格只读取[货柜制造台定义](../../02贸易点系统/06_货柜制造台定义.md)中具体配方的 `currency_cost`。

装载许可只比较 CargoGood 路径首段解析出的 CargoClass 是否存在于 `allowed_cargo_classes`。货柜定义不枚举具体 CargoGood；同一允许分类下由数据包新加入的 CargoGood 自动兼容。制造时仍会把当时已加载货物的厂商容量修正保存为逐货物容量快照；以后新增的同类货物没有旧的专用修正时使用货柜基础容量。实际支付的配方币种和金额另存为购买快照。货物交易继续使用 CargoGood／Load 币种，不从货柜制造成本反推货物价值。

货柜数量不再按定义分别使用 `max_owned` 限制。当前内置数据按常规规格统一为 S=1、M=2、L=4、X=6、XL=8 点；玩家总预算由[玩家档案](09_玩家档案与货柜调度点.md)按许可证等级提供。登记在玩家名下的普通自有货柜都会占用点数，销毁并移除资产记录后释放；状态变化不会绕过占用。若重载后占用超过新预算，只阻止继续获得货柜，不删除存量资产。SP 属于受托订单资产，设计上不占常规调度点，改用独立的进行中特别订单数量限制；该部分尚未实现。

同一个 CargoClass 下的不同 CargoGood 不能混装。运输要求和设计缺陷最终写入 Load，不是货柜自己的永久词条。

## 预留／待验收

- 预留：专用货柜词条、维修、改装、清理及回收玩法。
- 待验收：数据包重载后补装的参数来源与合批约束尚未统一；不要承诺“所有快照永不变化”。
- 旧整柜模板、价格常量及货物内联子对象不再是数据入口。删除旧字段不是把它们移到本文件里保留。
