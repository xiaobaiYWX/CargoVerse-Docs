# 多类型载荷与计量边界

实际物品、液体与标准流体气体已接入共用资产、装卸确认和事务机制。配置、余量与结算规则见[液体运输](13_液体运输.md)；活体尚未开放。

## 代码职责

| 层 | 当前入口 | 职责 |
| --- | --- | --- |
| 类型与身份 | `CargoKind`、`CargoIdentity`、`CargoKey` | 原生表示类型、精确身份及带类型选择键 |
| 计量 | `CargoMeasure` | 原生整数数量与操作份数换算、整份边界、尾量及质量 |
| 内容 | `CargoContent`、`CargoTransportRules` | 真实数量、冻结规则、质量、运输会话、贴花、显示及原生减量 |
| 资产 | `CargoLoad`、`CargoContainerSavedData` | 唯一载荷封套、取得成本、异常状态和权威账本 |
| 保存 | `CargoContentCodec` | 按类型选择真实编解码器，不将未知内容当成物品 |
| 确认生命周期 | `CargoTransferOrderService` | 会话、货柜占用、重验、防重放、取消和强制关闭 |
| 业务分发 | `CargoTransferRequest`、`CargoTransferBackends` | 带类型请求，仅注册真实已实现的后端 |
| 物品实现 | `ItemCargoLoad`、`ItemCargoTransferBackend` | 原生物品与组件、保险库槽位事务和物品报价 |
| 标准流体实现（液体／气体） | `FluidCargoLoad`、`FluidCargoTransferBackend`、`FluidCargoService` | 原生 FluidStack、储罐事务、整桶报价和确认投影 |
| 报价身份 | `CargoQuoteIdentities` | 按声明的原生类型解析，不从同名 ID 猜注册表 |
| 显示来源 | `MonitorIconSource`、`MonitorIconTextures` | 纹理、物品、流体和静态生物来源，统一生成平面图像并缓存 |

液体与气体共用真实 FluidStack 载荷和 Create 储罐事务，没有独立库存账本；不预建无消费者的活体存储适配器。新介质需要自己的真实内容、编解码器和事务后端才能开放；仓库页面或形态许可不能代替实现。

## 数量与单位

| 表示 | 原生数量／显示单位 | 操作份数 1／定义容量 1 |
| --- | --- | --- |
| 实际物品 | 实际个数，`pcs` | 1 组（`stack`），等于该完整 ItemStack 的最大堆叠数；通常为 64／16／1 |
| 液体 | 整数 `mB` | 1000mB |
| 生物 | 实体个数，暂用 `mob` | 尚未开放；设计为每次操作1只、定义容量按舱位，数量与空间分开 |

柜型只声明一种介质。固体 `capacity: 50` 表示 50 组：最大堆叠 64 的物品可装 3200pcs，最大堆叠 16 的物品可装 800pcs，不可堆叠物品可装 50pcs。不是按仓库中现有物品栈的数量计量。最大堆叠量从精确物品及组件读取，首次装载冻结为 `StackSize`，不会在途中重载时重新猜测；追加须与冻结规则兼容。液体／气体容量 50 表示 50000mB。

库存和载荷仍保存原生整数，旋钮输入整组／整份。实际转移量为请求份数换算后的原生量、来源库存和目标可用空间三者最小值；自然点收购还受剩余原生额度限制。**不再向下裁成整组或整桶**：70pcs 的库存可以响应 2 组请求，300mB 也可正常装载、卸载或出售。普通交易与管理装卸采用同一尾量规则，管理装卸仍免费。

## 换算职责与调整入口

| 换算对象 | 当前入口 | 现行规则 |
| --- | --- | --- |
| 操作份数 → 原生数量 | `CargoMeasure.nativeAmount`／`transferableAmount` | 固体按冻结最大堆叠数、液体／气体按 1000；按原生量截取实际可转移量 |
| 定义容量 → 原生容量 | `CargoContainerSnapshot.capacityFor`／`capacityForForm` | 固体先取得具体物品的堆叠量再转换；未选择物品时只能展示组容量 |
| 原生数量 → 载货质量 | `ItemTransportSnapshot.massFor`／`FluidTransportSnapshot.massFor` | 原生数量÷每份原生量×每份质量，全部载荷计算后向上取至 0.1Kpg |
| 原生货损 → 剩余载荷 | `TransportEvaluator`／`CargoContent.removeAmount` | 条件固定扣量仍是 pcs／mB；不因交易以组操作而扩大成一整组 |
| 成交量 → 金额 | `CargoMeasure.priceFor` | 实际原生量÷每份原生量×单价×各价格修正；整笔最终向上取整数 |
| 成交量 → 经验 | `NaturalTransportExperienceService` | 自然目的地每组／每桶经验×实际成交份数，每笔向下取整，不累计余数 |
| 原生库存／每日额度 | `TradePointInventoryService`／`TradePointAcquisitionLimit` | 自然报价库存按份配置，扣减保留原生尾量；每日额度保存原生已收数量，尾量不占整份；单日原生计数不超过 int 上限 |
| 载货质量 → 物理质量 | `CargoMassPlaceholderHelper` | 结构基线与定义空重取较大值后加已取整载货质量，经已绑定锚点补足 |

金额使用十进制定点运算，在原生量与全部修正合并后只取整一次；质量也只对整份载荷取整，不对每件／每 mB 分别向上取整。容量或请求乘法、价格越界在修改库存和钱包前拒绝。预览冻结操作步长与实际原生量，确认时重新校验，结果变化需重新确认。

例如每组 64pcs、单价 10VB、每组质量 0.1Kpg：32pcs 成交 5VB、质量 0.1Kpg；70pcs 成交 11VB、质量 0.2Kpg。每桶 10VB、1Kpg 的液体：300mB 成交 3VB、质量 0.3Kpg；1mB 成交 1VB、质量 0.1Kpg。经验每份 2 点时，300mB 产生 0 点，1300mB 产生 2 点。

仓库与货柜数量仍以 pcs／mB 精确展示；操作控件显示组或每 1000mB 的份数，确认界面同时展示实际转移份数与原生量。空固体柜没有物品身份，不把其组容量标成 pcs。气态 Fluid 同样归入 liquid 运输类型；生物仍未开放。

## 报价与显示

自然站 schema 3 支持省略类型的 `item`／`components` 物品行，以及 `type: "liquid"`＋`fluid`／`components` 流体行。内部流体选择键使用保留的 `cargoverse:liquid/<namespace>/<path>` 空间，组件变体追加摘要，完整组件原文仍是身份依据。流体 ID 不写入物品字段，也不与同名物品共用库存。

价格和目的地经验属于报价，不属于运输属性。物品报价按组、液体／气体报价按每 1000mB；原有 `license_experience_per_item`／`prosperity_experience_per_item` 字段保留名称，但表示每个操作单位的经验。活动值与制造商贡献也按实际份数折算，吞吐计数保留原生量以免丢失尾量。来源类型不影响自然目的地经验资格；向玩家点交付和管理装卸不发经验。

图标监视器先将动态来源生成 64px 平面图像，再使用原有裁剪、闪烁及扫描动画绘制。缓存最多 256 项，每帧最多生成 2 项，退出世界或资源重载时释放；不会在每个方块的每一帧重新绘制实体模型。静态生物显示入口不等于已完成生物运输。

## 存档与验证

版本和不迁移规则统一见[当前数据契约](07_运行时与存档.md#当前数据契约)。`Load.Content` 保存 `Version/Type/Data`，原生内容中保存 `TransportSession`，不再执行旧时钟。旧运输状态不迁移，保留原文隔离；数值运行边界见[运输数值运行时](14_运输数值运行时.md)。

未知类型、缺失注册内容或坏数据完整保留并隔离，不转为空柜。流体解码成功不代表对应存储接口可用；交易仍检查当前有效网络、原生存储、精确组件、可用空间与钱包，并对失败执行补偿。

相关单元和世界测试覆盖保存、计量、身份、尾量、物品／流体装卸、确认取消和回滚，以及自然目的地经验。客户端视觉、Sable 运动货柜和多人压力另行验收。
