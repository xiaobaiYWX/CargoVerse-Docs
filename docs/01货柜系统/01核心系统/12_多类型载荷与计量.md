# 多类型载荷与计量边界

实际物品与液体业务已接入共用资产、装卸确认和事务机制。液体的正式配置、余量与结算规则见[液体运输](13_液体运输.md)；气体和生物尚未开放运输。

## 代码职责

| 层 | 当前入口 | 职责 |
| --- | --- | --- |
| 类型与身份 | `CargoKind`、`CargoIdentity`、`CargoKey` | 原生表示类型、精确身份及带类型选择键 |
| 计量 | `CargoMeasure` | 原生整数数量与操作份数换算、整份边界、尾量及质量 |
| 内容 | `CargoContent`、`CargoTransportRules` | 真实数量、冻结规则、质量、时钟、贴花、显示及原生减量 |
| 资产 | `CargoLoad`、`CargoContainerSavedData` | 唯一载荷封套、取得成本、异常状态和权威账本 |
| 保存 | `CargoContentCodec` | 按类型选择真实编解码器，不将未知内容当成物品 |
| 确认生命周期 | `CargoTransferOrderService` | 会话、货柜占用、重验、防重放、取消和强制关闭 |
| 业务分发 | `CargoTransferRequest`、`CargoTransferBackends` | 带类型请求，仅注册真实已实现的后端 |
| 物品实现 | `ItemCargoLoad`、`ItemCargoTransferBackend` | 原生物品与组件、保险库槽位事务和物品报价 |
| 液体实现 | `FluidCargoLoad`、`FluidCargoTransferBackend`、`LiquidCargoService` | 原生 FluidStack、储罐事务、整桶报价和确认投影 |
| 报价身份 | `CargoQuoteIdentities` | 按声明的原生类型解析，不从同名 ID 猜注册表 |
| 显示来源 | `MonitorIconSource`、`MonitorIconTextures` | 纹理、物品、流体和静态生物来源，统一生成平面图像并缓存 |

没有独立液体账本，也不预建无消费者的气体或生物存储适配器。新介质需要自己的真实内容、编解码器和事务后端才能开放；仓库页面或形态许可不能代替实现。

## 数量与单位

| 表示 | 原生数量／显示单位 | 当前操作份数 1 |
| --- | --- | --- |
| 实际物品 | 个数，`pcs` | 1 个物品，不是物品栈 |
| 液体 | 整数 `mB` | 1000mB |
| 标准流体表示的气体 | `mB` | 共用计量工具具有 1000mB 档位，气体业务及最终步长仍待专项确认 |
| 生物 | 实体个数，暂用 `mob` | 基础工具为 1 个；捕获、容积与状态规则未实现 |

柜型必须声明且只声明一种介质。固体定义容量直接表示 pcs；液体定义容量 1 表示 1000mB。配置容量与原生容量在公共入口换算一次，负值和溢出拒绝进入事务。终端快照显式携带介质，空液体柜不会因缺少货物 ID 而误显示 pcs。

普通转移量为请求、来源库存及目标空间三者最小值，再向下取到操作步长。液体质量计算使用完整原生量，不丢弃尾量，也不逐 mB 循环。损耗和时限扣原生数量，成功追加刷新保护时间，部分卸货不刷新；有限补算避免逐间隔循环。

## 报价与显示

自然站 schema 3 支持省略类型的 `item`／`components` 物品行，以及 `type: "liquid"`＋`fluid`／`components` 液体行。内部液体选择键使用保留的 `cargoverse:liquid/<namespace>/<path>` 空间，组件变体追加摘要，完整组件原文仍是身份依据。流体 ID 不写入物品字段，也不与同名物品共用库存。

价格和目的地经验属于报价，不属于运输属性。普通液体装卸、报价库存和经验按实际成交整桶份数，界面及货柜载荷显示原生 mB。来源类型不影响自然目的地经验资格；向玩家点交付和管理装卸不发经验。

图标监视器先将动态来源生成 64px 平面图像，再使用原有裁剪、闪烁及扫描动画绘制。缓存最多 256 项，每帧最多生成 2 项，退出世界或资源重载时释放；不会在每个方块的每一帧重新绘制实体模型。静态生物显示入口不等于已完成生物运输。

## 存档与验证

货柜根版本 5、条目格式 10、内容封套 1、物品载荷包络 2、液体载荷包络 1；网络协议 69。`Load.Content` 保存 `Version/Type/Data`，时钟保存 `AmountPerInterval`。开发阶段不迁移旧条目，测试货柜需重建。

未知类型、缺失注册内容或坏数据完整保留并隔离，不转为空柜。流体解码成功不代表对应存储接口可用；交易仍检查当前有效网络、原生存储、精确组件、可用空间与钱包，并对失败执行补偿。

相关单元和世界测试覆盖保存、计量、身份、尾量、物品／流体装卸、确认取消和回滚，以及自然目的地经验。客户端视觉、Sable 运动货柜和多人压力另行验收。
