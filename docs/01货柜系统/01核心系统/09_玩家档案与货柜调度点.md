# 玩家档案与货柜调度点

玩家档案是服务端数据包中的玩家规则定义。第一版统一使用 `data/cargoverse/player_profiles/default.json`，资源 ID 为 `cargoverse:default`；该定义必须存在且结构完整，否则数据包重载失败。

## 完整结构

```json
{
  "schema_version": 1,
  "display_name": "默认玩家档案",
  "radar_chart": {
    "window": {
      "mode": "recent_cargo_units",
      "cargo_units": 3000.0,
      "minimum_cargo_units": 100.0
    },
    "load_scale": {
      "size_factors": {
        "S": 0.2,
        "M": 0.4,
        "L": 0.6,
        "X": 0.8,
        "XL": 1.0
      }
    },
    "cargo_value": {
      "reference_unit_value": 100.0
    },
    "richness": {
      "target_effective_goods": 8.0
    },
    "coverage": {
      "target_effective_trade_points": 6.0
    },
    "reliability": {}
  },
  "license": {
    "initial_level": "S",
    "levels": [
      { "level": "S", "required_experience": 0.0 },
```

## 字段约束

| 字段 | 约束与职责 |
| --- | --- |
| `schema_version` | 必填整数，第一版固定为 1 |
| `display_name` | 必填非空字符串，档案显示名 |
| `radar_chart` | 必填完整对象；定义统一的近期货量窗口、货柜规格系数、单位价值基准，以及丰富度和广域度的归一化目标值 |
| `license.initial_level` | 必填许可证等级，当前为 S |
| `license.levels` | 必须按 S、M、L、X、XL 完整且唯一排列；经验为非负整数并严格递增，首级为 0 |
| `cargo_container_points.point_budget_by_license` | 必须完整包含 S、M、L、X、XL；预算为非负整数且随等级不下降 |

## 调度点规则

货柜定义使用 `dispatch_points` 表示持有成本。内置换算为 S=1、M=2、L=4、X=6、XL=8。

占用依据唯一货柜运行时仓库按玩家所有权实时汇总，当前运行时只计算 active 资产。pending_removal 和资产级 invalid 不计入占用，但其记录不会因此直接消失；待删除资产仍保留物理身份直到删除完成。仅内部货物失效而资产仍为 active 时继续占点。获得新货柜前，服务端检查 `当前占用 + 新货柜成本 <= 当前许可证预算`。

数据包重载可能降低预算或提高成本。若玩家已经超限，现有货柜完整保留，只拒绝后续新增，直到销毁货柜、提高许可证等级或再次调整数据后恢复可用额度。

许可证经验仍保存在玩家 SavedData 中，档案只定义“累计经验对应哪个等级”；修改阈值不会重写或清零玩家经验。
