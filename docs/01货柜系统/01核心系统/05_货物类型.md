# 实际物品身份与装载形态

## 内容身份

一个货柜只保存一种物品 ID 和完整组件状态，名称、耐久、附魔、染色等变体不能混装。1 组物品占 1 容量单位，最大堆叠量随完整组件身份读取并冻结，质量按每组定义；不定义独立商品身份或把标签当作物品本身。

## 现行装载形态

| 形态 | ID | 基本承载 |
| --- | --- | --- |
| 独立固体 | solid | 物品栏中的完整物品，含器皿、包装及粉粒类物品 |
| 液体 | liquid | 原生 FluidStack 与精确组件，已接入 1000mB 整份装卸及交易 |
| 气体 | gas | 气体内容，尚未开放运输 |
| 活体 | living | 实际活体实体，尚未开放运输 |

none 只表示空柜或显示回退，不作为装载许可。形态由逐物品属性 JSON 声明，缺失时采用源码默认 solid；不按用途、价格、品牌或物品名称推断。物品载荷、流体载荷和活体载荷是不同的数据对象：物品栏中的水桶、药水和鱼桶仍是物品外壳，不据此宣称已经支持内部流体或活体。当前实际物品全部为 solid，不能通过修改 form 直接启用其余三类运输。

## 准入、保护与质量

分类决定基本承载，admission_policy 决定能否安全保存恢复，运输词条决定缺少保护时的风险。非空嵌套容器、无法恢复的组件和被明确阻止的对象不因同属 solid 获得准入。未知已存载荷保留原文并隔离。

现行配置为 2315 份逐物品 JSON，按物品命名空间／形态归档，直接维护质量、准入、运输条件和贴花，没有条件集或成员标签。缺失时为 solid／0.1 Kpg／standard／无条件／无贴花。内置质量为 0～1 的整数或一位小数，零质量仍占容量和执行损耗。

## 护目镜提示与贴花

佩戴 Create／航空学护目镜后，物品悬停只补充必要的装载限制和运输需求，不显示形态分类或默认分类来源：

- blocked：只显示红色“无法装载”，不再追加运输需求。
- empty_storage：显示黄色“仅允许空容器”，有运输需求时另列词条名称。
- standard：只在有运输需求时显示“运输需求：词条名称”，不附加括号解释。
- 无额外需求或未适配默认物品：不新增运输提示行；尚未收到客户端元数据时也不显示。

以上仅是物品 ID 层面的提示，不代表贸易点已经报价，也不能代替服务端对具体组件状态和容器内部内容的检查。名称、耐久和药效仍属于精确变体身份。

分类目录仅在登录和数据包同步时分包发送，完整后原子替换，退出清空；悬停只查缓存，不扫描标签或请求网络。货柜贴花与分类独立，由物品 JSON 的 decal 指定注册静态贴花方块 ID，装载时与运输规则一起冻结。模板提供替换槽位，不根据四大形态自动选择图案。

液体使用独立的逐流体属性，默认每 1000mB=1Kpg；不是给物品属性改 form。`c:gaseous` 气体不走液体分支，气体与生物运输尚未开放。液体质量、计量、尾量和配置见[液体运输](13_液体运输.md)。
