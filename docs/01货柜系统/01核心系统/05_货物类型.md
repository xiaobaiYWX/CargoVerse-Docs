# CargoClass 与 CargoGood：货物定义

## 一级分类 CargoClass

固定硬编码分类，决定货柜兼容范围、公共分类及货柜上的分类贴花。数据包不能注册新一级类。普通 CargoGood 格位仍使用具体货物的 `icon`；货柜制造台的 Cargo Class 投影器直接使用 CargoClass 分类贴花，只显示允许运输的大类图标，不显示文字或 CargoGood 图标。

| CargoClass ID | 中文名 |
| --- | --- |
| `none` | 无 / 未识别默认货物 |
| `agriculture` | 农业产品 |
| `aquatic` | 水产生鲜 |
| `livestock` | 活体生物 |
| `raw_resource` | 原始资源 |
| `processed_resource` | 半成品资源 |
| `refined_resource` | 精加工资源 |
| `energy_fuel` | 能源燃料 |
| `chemical_material` | 化工原料 |
| `hazardous_material` | 环境危害材料 |
| `machinery` | 机械设备 |
| `vehicle` | 完整载具 |
| `electronics` | 电子设备 |
| `mechanical_parts` | 机械零件 |
| `construction_material` | 建筑材料 |
| `prefab_structure` | 预制结构 |
| `general_supplies` | 日常通用补给 |
| `medical_supply` | 医疗物资 |
| `tools_equipment` | 工具器械 |
| `weapon_armor` | 武器护甲 |
| `valuables` | 贵重物品 |
| `research_sample` | 科研样本 |
| `anomalous_cargo` | 异常货物 |
| `special_resource` | 特殊资源 |

分类贴花统一位于 `assets/cargoverse/textures/block/decal/cargo_class/<id>.png`，保持原始宽高比。各类已使用各自 V3.0 贴花，不再全部使用 none。这些图片不再作为终端的默认货物图标。

未知目录类按 none 分类，但不改写货物 ID。例如 `my_pack:future/rice` 与 `my_pack:none/rice` 仍是不同货物。分类兜底不是“缺失货物定义也允许交易”。

## 二级货物 CargoGood

`data/<namespace>/cargo_goods/<class>/<good>.json` → `<namespace>:<class>/<good>`。

货物路径严格两段，不再加额外嵌套目录。JSON 不重复写 id、cargo_class 或 cargo_type。库存、价格和装载状态仍以完整 CargoGood ID 区分；只有货柜的装载许可按 CargoClass 判断，同类货物不会因此合并库存或允许混装。

## 内置示例

文件：`cargo_goods/agriculture/agriculture.json`。

```json
{
  "schema_version": 1,
  "display_name": "农业产品",
  "tech_level": 2,
  "tags": [],
  "trade_currency": "cargoverse:enderite",
  "unit_mass": 2.0,
  "base_value": 10,
  "license_experience_per_unit": 1.0,
  "prosperity_experience_per_unit": 0.5,
  "base_integrity": 100.0,
  "transport_requirements": [
    { "id": "cargoverse:time_limit", "time_tick": 48000 }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `schema_version` | 必填整数 1 |
| `display_name` | 必填直接非空字符串，最长 256 字符，不解析翻译 key |
| `icon` | 可选完整纹理资源 ID，最长 256 字符；格式为 `namespace:textures/.../name.png`；省略时直接显示问号，不能填 null、空串、外部 URL 或相对路径段 |
| `tech_level` | 必填非负整数；生产线输入选择器会使用 |
| `tags` | 可省略为空；普通字符串标签，禁止重复和空白标签，不是 Minecraft 物品 tag |
| `trade_currency` | 必填，引用已加载的货币组 |
| `unit_mass` | 必填有限非负数，每 1t 的质量，最大 1000000 |
| `base_value` | 必填非负整数，每 1t 的基础价值 |
| `license_experience_per_unit` | 必填有限非负数，每 1t 基础许可证经验，最大 1000000 |
| `prosperity_experience_per_unit` | 必填有限非负数，每 1t 基础繁荣经验，最大 1000000 |
| `base_integrity` | 必填有限正数，最大 1000000；不是容器耐久 |
| `transport_requirements` | 可省略为空；最多 5 个不重复的已支持运输词条，详见词条章节 |

货物 ID 最长 256 字符，当前目录上限 16384 项。具体数值以加载器校验为准，数据包 JSON 不放说明注释。

## CargoGood 专属 UI 图标

货柜外部分类贴花继续使用 CargoClass；普通 GUI 中的库存、区域货柜列表、搭建台、收购终端和贸易地图统一使用 `client/gui/CargoGoodIcon`，世界表面装载机／卸载机通过同一展示目录向 `IconMonitor` 提供图标。不要用专属 UI 图标替换结构模板中的分类贴花。

以下是给自定义小麦添加图标的字段片段，不是完整货物定义，也不表示内置已添加小麦或对应美术：

```json
{
  "display_name": "小麦",
  "icon": "my_pack:textures/gui/cargo_goods/agriculture/wheat.png"
}
```

文件对应关系：

```text
数据包：data/my_pack/cargo_goods/agriculture/wheat.json
货物 ID：my_pack:agriculture/wheat
资源包：assets/my_pack/textures/gui/cargo_goods/agriculture/wheat.png
```

- `icon` 不要求与货物同命名空间，也不强制按货物 ID 推导路径；多个货物可以共用一张图。
- PNG 属于客户端资源包。服务器数据包只声明路径；图片必须随 MOD、客户端配套资源包或服务器资源包提供，不会通过货物目录网络包发送。
- 图标使用静态 PNG，建议 32×32 透明背景；实际按图片宽高比适配现有图标格，不改变 GUI 尺寸，也不增加图标宽高配置。
- 回退顺序：CargoGood 指定图标 → `cargoverse:textures/gui/cargo_goods/none.png` 问号图标。任何分类都使用同一规则，不读取 CargoClass 贴花，也不按分类目录推导 UI 图片。
- 客户端缺图或 PNG 损坏只影响显示，不拒绝交易；失败路径缓存并记录警告，避免逐帧重复读取和刷日志。连问号资源都损坏时最后绘制文字 `?`。
- JSON 字段类型、资源 ID 和路径格式错误仍属于定义校验错误，不能混同为“客户端缺少图片”。服务器不检查图片文件存在性。
- 数据包重载完成后同时替换名称和图标目录；资源包重载清理纹理检查缓存；退出服务器清空目录与缓存。已有货柜按货物 ID 查询当前 UI 图标，无需改存档。

默认资源 `assets/cargoverse/textures/gui/cargo_goods/none.png` 为 32×32 RGBA 问号。现有 20 个默认货物尚未配置专属 `icon`，现在统一显示问号；悬停仍显示各货物名称，不会因为共用默认图标而合并货物身份。新货物按上述方式提供美术即可，不需要改渲染代码。

组件使用方式及坐标／提示层约定见 [UI 信息显示与数据入口](../../06开发与运维/02_UI信息显示与数据入口.md)。

## 接入其他系统

1. 为容器 `allowed_cargo_classes` 配置固定 CargoClass ID；该类下的所有 CargoGood 均可装载。
2. 如需厂商特定容量，使用 `container_traits.cargo_modifiers` 的同一 ID。
3. 创建产出该货物的生产线，或让输入 selector 匹配它的科技等级和标签。
4. 贸易点引用生产线池，由解析结果生成实际输入／输出库存，不手写旧货物销售列表。
5. 普通商店需要关联货物时使用 `cargo_good`，不要填分类名称。

贸易点各槽初始库存为 0；仅有货物定义不会自动给贸易点生成库存。默认 20 个货物是测试内容，不限制数据包添加或删除。

## 重载与现有货物

- 引用不存在的货物、厂商或货币组会使关联新数据集合校验失败；删除货物需同时处理定义引用。
- 登录和成功重载会同步货物展示目录（名称＋可选图标路径）；客户端分块收齐后整体替换，退出服务器清空。
- 货柜已有 Load 保存货物快照；定义被删除不会直接清空玩家货物，但相关交易会禁用。
- 补装会重新使用部分当前定义参数，尚有一致性问题，不能当作已完成的严格快照隔离。
