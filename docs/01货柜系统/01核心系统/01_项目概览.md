# 项目概览

Cargoverse（通商惠工）是一个面向服务器跑商玩法的货柜交易系统。它的核心目标是让玩家从买入终端购买货柜，将货柜作为物理结构运输到出售终端，再根据货柜状态、市场行情和终端偏好获得回收价格。

当前工程运行于 NeoForge 1.21.1，并使用 Create Aeronautics / Sable 物理结构作为货柜载体。旧版 Valkyrien Skies 链路已经移除，货柜定义以数据包 JSON 为唯一主要数据源。FTB Quests 是可选兼容模组，只提供购买与售出计数任务，不参与货柜购买、出售、持有和运行时存档的核心流程。

## 系统组成

### 数据层

- `data/<namespace>/cargo_definitions`
  - 存放货柜定义。
  - 每个 JSON 文件代表一种完整货柜。

- `data/<namespace>/structure`
  - 存放货柜结构模板。
  - 模板 ID 会被货柜定义中的 `template` 字段引用。

- `data/<namespace>/trade_points`
  - 存放贸易点定义以及各贸易点独立的动态经济参数。
  - 用于控制繁荣度、活跃度、货物类型敏感度、价格浮动和每日回归速度。

- 出售货柜池已并入 `data/<namespace>/trade_points` 的 `cargo_sale`。
  - 存放出售终端货柜池、显示数量、权重和繁荣度门槛。

- 收购终端不使用模板池，只扫描真实货柜并按贸易点 `consumed_resources` 判断 CargoType。
  - 存放收购终端允许收购的货柜及繁荣度门槛。

### 运行时层

玩家购买货柜后，系统会记录一个货柜实例。实例会保存：

- 对应货柜定义 ID
- 物理结构 ID
- 持有玩家
- 当前完整度
- 最大完整度
- 是否失效
- 失效原因
- 购入价格
- 生成来源终端

这些数据用于 HUD 与终端显示、结算收购价格、限制同时持有数量，以及在出售或清理后移除对应物理结构。

### 交互层

- 买入终端：通过贸易点 ID 读取内嵌出售池，并配置生成偏移。
- 出售终端：通过贸易点 ID 读取内嵌收购池，并配置检测范围。
- 商店终端：配置商店定义和贸易点 ID，价格、库存及刷新速度受贸易点影响。
- 航运终端：显示玩家名下货柜、运输许可等级和升级进度，并提供货柜删除入口。
- 货柜信息 HUD：玩家装备 `create:goggles` 或 `aeronautics:aviators_goggles` 后，对准货柜即可查看统一运行时信息。
- 货柜连接器/货柜接口：用于货柜和运输载具之间的锁定连接。
- 装饰性货柜方块：用于搭建货柜结构模板。

## 设计原则

- 数据包负责定义货柜内容，核心交易流程不依赖 FTB。
- CargoType 初始词条与参数统一写在 `cargo_value_constants` 中，货柜定义只声明 `blocked_affixes` 防护能力；文本和翻译写在语言文件中。
- 所有累计型货损统一扣除货柜完整度，不再让每个词条维护独立耐久。
- 货柜失效后应尽快退出持续检测集合，降低服务器负担。
- 货物类型价格偏好统一写入贸易点定义，子终端只负责通过 `tradePointId` 绑定贸易点实例。
