# 项目概览：实际物品与货柜资产

货柜是可反复装卸的所有权资产，货物是实际 Minecraft 物品，不再存在独立的抽象货物定义。

| 对象 | 职责 |
| --- | --- |
| ItemCargoIdentity / ItemCargoPayload | 物品 ID、完整组件与整数个数 |
| ItemTransportProfile / ItemTransportSnapshot | 分类、单位质量与固定扣量要求；装柜时冻结 |
| CargoContainerDefinition / CargoContainerSnapshot | 型号、模板、分类许可、容量和空柜质量 |
| CargoContainerInstance | 所有权、实际物品载荷、设备与物理位置 |
| PlayerTradeVaultInventory / ItemTradeOffer | 只保存精确变体报价与短周期观察；实际物品在 Create 保险库，由贸易点仓库收发器定位，无固定 5000 仓容 |
| ResourceTableDefinition / TradePointResourceCatalog | 站点精确物品报价、供需限额与收购侧经验；不维护全局物品价格 |
| NaturalTransportExperienceService | 按自然生成目的地和实际成交件数计算交付经验，和物品运输参数分离 |

1 个实际物品占 1 个容量单位，不是一个物品栈，也不再使用 t 表示数量。总质量 = 空柜质量 + 物品数量 × 单位质量。

一柜只装同一种物品及同一种组件状态；补货要求身份和冻结运输规则一致。货损直接扣物品数，不保存独立完整度。卸空后留下同一货柜，继续归原玩家。

玩家贸易点的公共装卸交易始终正常支付 VB，所有者和授权管理员也不例外；恢复的可选仓库管理终端提供独立免费装卸及所有者专用 SET 商品管理，核心不再提供 SET 入口但仍保存报价；实际物品始终使用 Create 保险库存储。自然贸易点 schema 3 已支持实际物品报价及交付经验，40 张自然站买卖表待落数据，A／B 两张指令测试表已填入互补的 149 种实际物品；结构、制造、物品商店和注册模块保留。不自动映射旧货物，不再保留未启用的全局商品目录。
