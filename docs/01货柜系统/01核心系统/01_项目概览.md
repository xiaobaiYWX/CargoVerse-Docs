# 项目概览：货柜资产与货物运输

> 已实现：三类定义、统一运行时、基础交易闭环。待验收：实体贴花、重载补装一致性、交易异常恢复和完整实机流程。参见[状态清单](../../00_重构状态与验收清单.md)。

货柜是玩家长期持有的物流设备，不是预装货物的商品模板。制造空柜和买卖货物是两笔独立交易。

## 职责划分

| 对象 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| CargoClass | 硬编码一级分类和货柜上的分类贴花 | GUI 货物图标、单价、具体货物库存 |
| CargoGood | 具体货物的质量、价值、币种、科技等级、标签、经验和运输要求 | 货柜结构与厂商 |
| CargoContainerDefinition | 型号、NBT 模板、制造商、空柜数值和兼容 CargoClass | 指定具体 CargoGood 或当前装载数量 |
| ManufacturerDefinition | 制造商特性；声望结构预留 | 当前并无完整玩家声望玩法 |
| CargoContainerInstance | 所有权、容器快照、当前 Load、耐久、物理位置及状态 | 重新从模板随机生成货物 |
| 贸易点／生产线 | 具体输入输出、库存、生产、价格和活跃度 | 拼接预装货柜销售列表 |

## 已实现：基础玩家流程

1. 在大型货柜制造台支付配方货币并消耗贸易点输入库存材料，生成空货柜。
2. 在装载终端选择货柜、产出库存和整数交易数量，查看预览后付款装载。
3. 运输时执行 Load 上的运输词条，不将货物完整度当成货柜耐久。
4. 在需求对应货物的卸货终端按数量交易；完全卸空后货柜仍归玩家。
5. 继续使用同一货柜。当前单柜仅支持一种完整 CargoGood ID，不能按同一大类混装。

货物数量使用小写 `t`，例如 `10t`。它是项目货物单位，不由质量反推；货物质量等于每 t 质量乘数量。

## 已实现：定义与运行分离

新定义引用使用完整命名空间 ID；货物分类不替代货物身份。创建资产时保存容器快照，装载时保存货物快照。GUI 读取服务端提供的显示／交易快照，不拥有权威库存。

当前数据目录、字段和例子见[容器定义](02_货柜定义系统.md)、[货物定义](05_货物类型.md)、[制造商](08_制造商定义.md)、[贸易点](../../02贸易点系统/05_贸易点定义.md)。

## 预留与限制

机械台维修／改装／清理、搭建台回收、货柜专用词条和制造商声望尚未形成玩法。旧收购终端保留整柜收购入口，不等同于新卸货或回收系统。

旧整柜模板／集中数值常量入口已停用；本项目不迁移旧开发存档。新格式和版本见[运行时与存档](07_运行时与存档.md)。
