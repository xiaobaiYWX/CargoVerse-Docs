# 货柜运行时与存档

> 已实现：统一资产、容器快照、装载快照、物理派生状态刷新队列和无旧格式迁移的存档。装卸补偿、动态质量刷新与完整存取循环已有自动化覆盖；数据包重载语义和世界内物理恢复仍需实机验收。

## 权威数据结构

以下为 Java 运行数据的分组示意，不是可放进数据包的 JSON：

```text
CargoContainerInstance
├─ containerId / ownerId / instanceId / containerDefinitionId
├─ container: CargoContainerSnapshot
│  ├─ displayName / description / templateId / manufacturerId / sizeClass
│  ├─ dispatchPoints / capacity / emptyMass / maxDurability
│  ├─ allowedCargoClasses[]
│  ├─ cargoCapacityProfiles[] { goodId, capacity }（只保存容量修正，不决定许可）
│  └─ purchaseCurrencyId / purchasePrice
├─ durability
├─ load: CargoLoad
│  ├─ good: CargoGoodSnapshot
│  │  ├─ goodId / displayName / unitMass / baseValuePerUnit
│  │  ├─ licenseExperiencePerUnit / prosperityExperiencePerUnit / baseIntegrity
│  │  └─ affixIdsRaw / affixDefinitionsJson
│  ├─ units / integrity / affixState
│  ├─ settlementCurrencyId / acquisitionCost / loadedGameTime
│  └─ status / invalidReason / statusSinceEpochMillis
├─ physical: CargoPhysicalState（可无）
│  ├─ dimensionId / physicsProvider / physicsId / physicsRuntimeId
│  └─ templateId / origin / sizeX / sizeY / sizeZ / blockCount
└─ status / invalidReason / createdGameTime / statusSinceEpochMillis / sourceTerminal
```

仓库入口为 CargoInstanceRepository，权威持久化为 CargoContainerSavedData。展示快照和物理定位不是另一份货物状态源。物理元数据不保存独立货物类型或运输词条。

同一 SavedData 另保存待物理删除和待物理派生状态刷新队列。刷新队列只保存 containerId；目标总质量、分类、词条、模板与物理映射仍从统一货柜资产读取，不复制第二份状态。读取时兼容早期开发版的 `PendingAppearanceRefreshes` 键，后续统一写为 `PendingPhysicalRefreshes`。

## 已实现：空柜与载货柜

| 状态 | 容器资产 | Load | 目标总质量 |
| --- | --- | --- | --- |
| 空柜 | 保留所有权、设备快照、耐久和物理信息 | Java 为 CargoLoad.EMPTY；NBT 不写 Load | emptyMass |
| 载货柜 | 同一资产不变 | 保存一种具体货物、整数 t 数、完整度和运输状态 | emptyMass + unitMass × units |
| 部分卸货后 | 同一资产不变 | 原货物快照／完整度／词条状态保留，减少 units，购入成本按剩余比例折算 | 按剩余数量计算 |
| 卸空后 | 同一资产不变 | 清空整个 Load | emptyMass |

空柜没有需要运行的货物词条，不表示为“装有 none 货物”。真实的 none 分类货物仍可以有自己的 CargoGood ID 和数据。

货物有效性与设备有效性分别记录。货物损坏不等同于设备耐久损坏；专用货柜损伤与维修循环仍预留。

## 已实现：NBT 与版本

NBT 使用 `Equipment` 保存 container 快照；`Load.Good` 保存货物快照；`Physical` 保存物理映射。字段全表以 CargoContainerInstanceCodec 为准，不把 Java 小写字段名当作 NBT 键。

设备快照不再保存 `BaseValue`。制造时实际使用的 `currency_cost.currency` 与舍入后的 `currency_cost.amount` 分别进入 `PurchaseCurrencyId` 和 `PurchasePrice`，用于追踪本次取得成本，不再从货柜型号或制造商倍率重新计算。

| 项目 | 当前值 |
| --- | --- |
| 货柜 SavedData 文件标识 | cargoverse_container_runtime_v2 |
| 货柜 DataVersion | 4 |
| 货柜条目 FormatVersion | 4 |
| 贸易点经济 DataVersion | 8 |
| 网络协议 | 22（制造台世界表面显示及交互同步） |

文件标识中的 v2 是已有名称，不等于当前 DataVersion。贸易点版本见 TradePointStateCodec，网络版本见 CargoVerseNetwork。以上不表示轨道、地图等独立存档也使用同一版本。

不读取／转换旧开发格式。未提供旧存档迁移器；升级测试使用新世界或备份后的测试世界，不手动删除整个世界目录。

## 已实现与待验收：快照边界

- 已实现：设备按 CargoClass 保存兼容白名单；同一白名单分类下新增的 CargoGood 自动可装载。制造时已存在货物的专用容量保存于资产，后加入的同类货物没有逐货物快照时回退到基础容量。
- 已实现：部分卸货不重建剩余货物快照；定义缺失时保留 Load 但禁止相关交易。
- 待验收 R2：补装只按完整货物 ID 判断同种货物，尚未严格区分不同参数版本；当前会重建整批 Good 快照。
- 已实现：容量检查和物理目标质量都使用资产内已存设备／货物快照；装卸后以 `emptyMass + unitMass × units` 重新计算权威总质量。
- 已实现：提交后的统一物理刷新会重写真实结构中的质量占位方块并刷新贴花；连续装卸事务采用尾触发合并，每次交易把刷新时点推迟到最后一次交易后的 `20 tick`，同一货柜在窗口内只执行一次二次刷新。Sable 结构使用嵌入世界局部坐标，随后重建质量／惯量追踪、发布统计并唤醒刚体。结构暂不可访问时持久化重试。
- 已实现：预览和世界实体从同一 Load 解析贴花；实体槽位来自原始模板，不由当前贴花状态反推。
- 已实现：装卸使用同一服务端串行事务边界，保存、库存、货币、经验和统计均注册反向补偿；故障注入、竞争串行和完整 Load 生命周期已有自动化测试。
- 已自动化：真实 Sable 子世界内的质量占位方块刷新及刚体追踪质量变化已有服务器 GameTest；重新绑定、两客户端高延迟竞争和关闭服务器后的世界表现仍按验收矩阵实机执行。

不得把容器耐久、Load 完整度、货物数量或物理质量互相推导为同一个字段。
