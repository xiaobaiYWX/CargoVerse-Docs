# 运输数值运行时

当前物品和液体共用数值运输会话，由已有货柜账本保存；不新建运输库存、平行载荷或独立损耗账本。旧按词条 ID 分派的 Handler、旧扣量调度器和限时时钟已退出并删除。

**阶段边界：第二轮接通运行与生命周期，第三轮尚未完成内置内容赋值和 UI 投影。** 目前内置逐物品／逐流体文件仍可采用 schema 1；其中旧 `transport_requirements` 只保留定义／显示资料，不再执行旧损耗。没有新 `transport` 的内容，其数值物性为空，不自动把旧 ID、字母或旧保护设计换算成新能力。不要将本阶段当成所有正式货物的平衡已经完成。

## 数据到实例

| 层次 | 当前入口与职责 |
| --- | --- |
| 逐内容属性 | ItemPropertyDefinition／FluidPropertyDefinition：身份、准入、质量、贴花及类型化物性 |
| 柜体能力 | CargoContainerDefinition：七项能力与调温支持，不删除内容固有物性 |
| 本次冻结 | TransportSnapshot：物性、承运能力、调温约束及完整候选换算表 |
| 实例会话 | CargoContent.session：TransportSession，内含设置、温度／压力、年龄、暴露余数和冲击去重 |
| 运行取样 | TransportWorldSampler／TransportEnvironmentSampler：加载中的真实世界点、速度、重力及环境 |
| 求值与提交 | TransportEvaluator → CargoTransportService 的不可变提案 → 现有 Repository／装卸事务 |

### 新逐物品格式

仍是一物一文件，路径示例 `data/minecraft/cargoverse_item_properties/solid/iron_ingot.json`。schema 2 不允许同时填写旧 `transport_requirements`；不需要敏感性时可省略 `transport`。

```json
{
  "schema_version": 2,
  "form": "solid",
  "unit_mass": 0.1,
  "decal": "cargoverse:decal_none",
  "admission_policy": "standard",
  "transport": {
    "water_exposure": {
      "loss": { "grace_ticks": 0, "interval_ticks": 20, "amount": 1 }
    }
  }
}
```

上例只说明格式，不是铁锭正式怕水设定。液体对应路径 `cargoverse_fluid_properties/liquid/<fluid>.json`，同样使用 schema 2 和 `transport`，质量字段仍为 `mass_per_bucket`；`loss.amount` 为原生 mB，不是桶数。完整物性字段见[数值字段草案](../../设计草案/运输词条重构草案/运输数值字段与能力等级.md)，不会按词条字符串选择行为类。

柜型可声明 `transport_capabilities`，字段为 `containment_level`、`sealing_level`、`cushioning_level`、`insulation_level`、`thermal_control_level`、`light_blocking_level`、`pressure_resistance_level`。围护／密封为 0～2，其余 0～3。调温等级非零必须同时提供 `thermal_control`。液体腔不得低于液密等级 1。

当前未赋新能力的内置液体柜临时按基础液密 1，其余 0；固体柜为全 0。这不是对各系列最终能力的认定。正式七项赋值和旧 `special_designs`／`design_defects` 数据清理属于第三轮，旧设计字段目前不参与求值或删改固有物性。

## 装卸与暂停

- 首笔正数装载的事务提案冻结当时规则，并以有效环境初始化必要内部温度／压力；必要输入未知则拒绝该提案，不编造默认值。取消或失败不保存新会话。
- 追加前使用新模型结算已有有效观测；身份、质量规则和本次计算约束必须兼容。追加继承当前温度、压力、年龄、余数及冲击状态，不刷新整柜保护时间。
- 部分卸出继承剩余会话。原生 ItemStack／FluidStack 不写入运输年龄；全部卸空或损耗归零清会话，保留资产和调温设置。
- 调温设置可在冻结的模式／目标范围内调整，修改设置不重置温度或年龄。空柜只保留设置，不进行预冷模拟；操作 UI 属于后续显示接入。
- 首次恢复只重建观测基线，不按存档时间差补算。不可用物理结构、缺失维度、超长采样间隔或未知环境不外推安全值。
- 物理绑定、位置元数据或资产启用状态变化时切断连续性；native 质量／质心基准变化也使用不同的连续性键。
- 数量、状态及既有交易补偿沿同一资产提交。损耗按固定原因汇总、封顶后一次减原生数量；查询和同 tick 重试不重复扣量。

## 运行成本与分辨率

只为实际需要运输模拟的有效载荷建任务；无物性的空载／普通内容不持续模拟。环境每 20 tick 按货柜 ID 错峰；需要冲击的载荷每 tick 采样，使用去重事件而非每次子步扣货。同载体在同 tick 共享基础姿态、native 速度和质量中心，货柜参考点与环境各自计算。

Sable 采样使用已加载结构的完整姿态，将模板局部中心变换到父世界；点速度为质心线速度加世界角速度旋转项，采用当前 provider 的 block／游戏秒和 rad／游戏秒尺度。不使用储存区群系、姿态原点或玩家位置代替参考点，不为观测唤醒 holding 结构或加载区块。

TU／J 仍使用候选 `candidate_v0`，不是摄氏度或真实碰撞冲量。每 tick 运动和每 20 tick 环境都有短时事件盲区；未实现子步峰值损耗、任意外部传送事件兼容或完整真实气候标定。大型坐标的原生姿态精度及真实飞行器路线仍须按需实机验收，不再维护单独记录器、分析器或强制校准工具流程。

运行保存只在实际状态变化时提交；仅温度、年龄或冲击基线变化不重建空间索引，不触发物理质量刷新。数量／质量、载体或贴花来源变化仍进入现有派生刷新队列。

## 保存与开发边界

- 根账本 DataVersion 保持 5，条目 FormatVersion 为 11，内容封套为 2；物品内容 3，液体内容 2。
- `TransportSession` 保存完整冻结规则、设置和动态状态，恢复不还原环境／速度连续基线。
- 不迁移旧运输状态。格式 10 条目的资产外壳仅用于定位和隔离；旧内容或未知／坏会话保留整个 Load 原文，禁止重新装货，不视作空柜覆盖。
- 旧定义／图标显示投影尚未全部移除，不能据旧 Tooltip 判断新能力已经生效；请等待第三轮显示与正式数据切换。

开发验证按范围运行数值模型／物品／流体单元测试，以及 `cargoverse_transport_model,cargoverse_transport` 专项 GameTest。它们覆盖 native 数量、状态保存、实际坐标、装卸确认和事务补偿，不代替多人压测与最终内容验收。
