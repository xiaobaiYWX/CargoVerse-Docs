# 货柜结构模板

正式制作结构前，请同时阅读[货柜结构制作规范](10_货柜结构制作规范.md)。

货柜主体方块 `cargoverse:cargo_block_*` 的 Sable 质量统一为 `0`。货柜实例的目标质量由设备空重快照与 Load 货物质量之和 控制；模板中来自其他模组的结构件和显式放置的压载块仍保留各自质量，并构成无法被虚拟质量降低的模板结构质量。

## 实例不可编辑规则

结构模板在制作阶段可以正常放置、拆除和调整贴花；货柜实例完成唯一一次 Sable 物理化后，其整个子结构进入只读状态：

- 禁止破坏或放置方块。
- 禁止空手或持物右键触发方块交互。
- 禁止工具通过右键修改 BlockState，包括 Create 扳手缩放贴花。
- 禁止左键工具行为继续作用于实例方块。
- 禁止所有以货柜实例为目标的 `RightClickItem`。服务端会使用 Sable 射线结果识别命中的货柜并在物品逻辑执行前取消，因此水桶、模组液体容器以及其他持有物都不能对货柜实例执行右键物品行为。

保护判定直接识别带有 `VsTradeCargoBoxId` 的 Sable `ServerSubLevel`，不会依赖货柜仍位于最初生成坐标。因此货柜移动或旋转后保护仍然有效。

货柜结构模板决定货柜生成到世界中后的具体方块结构。模板通常由结构方块、KubeJS 数据包或其他结构导出工具生成。

## 文件位置

```text
data/<namespace>/structure/<path>.nbt
```

示例：

```text
data/cargoverse/structure/cargo/box_test.nbt
```

对应模板 ID：

```text
cargoverse:cargo/box_test
```

货柜定义中这样引用：

```json
{
  "template": "cargoverse:cargo/box_test"
}
```

## 命名规则

模板 ID 的格式是：

```text
命名空间:`structure` 下的相对路径，不带 `.nbt` 后缀
```

例如：

```text
data/my_pack/structure/cargo/heavy/iron_box.nbt
```

对应：

```text
my_pack:cargo/heavy/iron_box
```

## 生成原点

货柜生成原点统一为结构模板的底面中心点。玩家从大型货柜制造台制造货柜时，系统会将制造台配置的生成点作为该底面中心点，并根据模板尺寸自动反推结构实际放置角点。

货柜定义 JSON 不再支持 `offset` 字段。大型货柜制造台保留 X/Y/Z 生成偏移配置，用于整体移动底面中心点；默认值为 `(0, 1, 0)`。这样可以避免不同货柜模板各自维护偏移值，也能让大、小货柜在终端处保持一致的生成规则。

## 模板制作建议

- 使用本模组的货柜方块搭建主体，以保证物理重量和视觉风格一致。
- 需要与运输载具连接时，在模板合适位置放置货柜接口。
- 避免在货柜模板中放置会产生大量实体或复杂红石更新的内容。
- 模板修改后，需要重新加载数据包或重启游戏，让结构文件被重新读取。

## 常见问题

### Template not found

如果提示：

```text
Template not found: cargoverse:cargo/box_test
```

请检查：

- 文件是否位于 `data/cargoverse/structure/cargo/box_test.nbt`
- 文件后缀是否为 `.nbt`
- 货柜定义中的 `template` 是否拼写一致
- 数据包是否成功加载
