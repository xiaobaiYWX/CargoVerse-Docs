# 货柜搭建器

货柜搭建器是独立于贸易点的蓝图制造设备。已接入专用终端模型和表面UI，蓝图暂用纸张模型，材料界面仍使用简易GUI。原有贸易点制造终端仍保留，尚未进行获取渠道切换。

## 本体与表面UI

模型位于`block/cargo_builder/body`，使用独立`cargo_builder.png`纹理。底部横跨三格，中央面板占用上方一格；放置前校验四个成员位置，只有中央控制器保存库存和Tick。左右副方块为半格高，中央上部使用面板包围盒。任意成员被拆除都会清理同组成员并按同一托管记录返还；不删除被外部替换的新方块，不重复返还。

| 模型编号 | 功能 |
| --- | --- |
| 1 | 翻牌仪表显示所选蓝图对应的货柜名称，无蓝图显示`---` |
| 2 | 绿色状态灯：正在搭建；完工等待／暂停时熄灭 |
| 3 | 黄色状态灯：蓝图所需材料不足，材料输入变更后最多一秒刷新 |
| 4 | 红色状态灯：开工或完工检查确认有方块、物理结构或其他施工区域占用 |
| 5 | 绿色大按钮：开始搭建，复用同一服务端开工检查 |
| 6 | 黄色大按钮：打开材料GUI，外壳普通右键不再打开GUI |

编号1～4的仪表基座保留，5、6仅作原始定位，运行时替换为封装大按钮。显示、按钮模型、射线命中与按压反馈使用现有World UI框架，跟随四个水平朝向。状态灯不新增施工中的遮挡扫描，红灯由规定的开工／完工检查驱动。

## 使用流程

1. 将搭建器放在静态世界中，输出方向由放置朝向确定；预览和实际建造区域位于操作面的背面，底面与搭建器同高：默认操作面朝北时向南建造，旋转后同样留出玩家操作面。已经开工的任务继续使用冻结的位置。
2. 放入对应蓝图和材料。蓝图占一个专用槽，材料使用另外36个槽；材料栏支持漏斗和Create物品接口，自动化不能取放蓝图。
3. 查看世界中的半透明货柜投影与界面的材料需求，点击表面绿色按钮或GUI中的“开始搭建”。生存模式保留航运注册、型号许可证和调度点检查；创造模式跳过这三项检查，但仍需要蓝图、材料和有效净空。
4. 当前内置配方统一施工400 tick，即正常20 TPS下20秒；投影从下向上逐层变为实体外观。施工期间这些只是视觉工作件，不是可操作或拆取的半成品方块。
5. 完工后一次放置实际结构、转换运行时锚点并进行Sable组装，蓝图回到专用槽，材料消耗。生成的货柜归启动施工的玩家所有。

搭建器由放置者或管理员操作。首版没有转速、动力或VB加工费，不要求贸易点绑定。搭建器本身可合成：7个铁锭、1张纸、1个工作台，配方为`IPI / ICI / III`（I铁锭、P纸、C工作台）。

蓝图目前通过创造物品栏或管理员测试指令取得，不把普通纸当成任意型号蓝图：

```mcfunction
/give @s cargoverse:cargo_builder
/cargoverse_builder blueprint cargoverse:aui/atlas_sd_s
```

指令支持当前配方ID补全；正式蓝图获取渠道仍待确定。

## 施工、遮挡与返还

### 无人机施工演出

搭建器左右平台各停靠一台折叠无人机，两台复用同一份折叠模型；机身、两侧旋翼组件、桨叶和焊接臂分部渲染。开工后两侧组件按±90°展开，起飞后焊接臂展开135°，围绕货柜外框随打印层升高。桨叶独立转动；每轮40tick在焊点之间加速、减速移动，随后停留24tick焊接，仅在停留作业时发射光点与火花。两台无人机错开节奏，焊接时固定工作高度与点位，离开后再追随当前打印层。100%等待净空或施工暂停时保持展开悬停并停止施工粒子；完成后先收焊接臂、返航、落回平台并折叠。拆台直接清除视觉，不生成真实无人机实体或额外掉落。

轨迹与阶段均在客户端根据现有任务ID、施工进度及货柜体积计算，不新增无人机位置同步、寻路或世界扫描。离搭建器64格外不绘制无人机，32格外不发射施工粒子；每台每6tick至多发射4个粒子，并有全客户端每tick24个的上限。视图状态弱引用所属方块实体，不保存世界引用。实际飞行、停靠和工具姿态仍需客户端视觉验收。

### 施工生命周期

- 开始时检查完整模板体积中的世界方块、Sable物理结构、区块加载与世界边界，并检查其他搭建器已预约的施工区域。失败不扣材料、不收走蓝图。
- 开始后将实际材料和蓝图转入施工托管；相应货柜以`building`状态预留资产和调度点，不能作为已完成货柜使用。
- 施工中不扫描遮挡，也不持续放置实体方块。放入障碍物不会直接取消进度。
- 达到100%时再次检查净空；有遮挡则保留100%进度与全部托管物，每20 tick重试一次。障碍移除后自动完成。
- 完成前拆除搭建器，包括100%等待阶段，直接取消并掉落全部托管材料、蓝图和未使用的输入物品；不留下半成品，进度清零。
- 正常区块卸载或服务器重启保留施工，未加载时不推进；若设备被移动到物理结构上则暂停。已完成后拆除搭建器不删除成品。

开始与完成的检查均复用`CargoSpawnAreaValidator`，不是逐tick空间扫描。客户端仅获得方块状态预览、进度和短状态，不获得托管材料或完整结构方块实体NBT。

## 数据与代码职责

独立配方位于`data/<namespace>/cargo_builder_recipes/<path>.json`，蓝图通过完整配方ID引用；当前为54款可制造货柜提供配方，初始材料与许可取自既有制造配方，运行时不查询贸易点或其繁荣度。

| 字段 | 规则 |
| --- | --- |
| `schema_version` | 固定1 |
| `container` | 一个现行货柜定义ID |
| `duration_ticks` | 整数20～72000，内置当前400 |
| `required_license` | S／M／L／X／XL／SP |
| `item_costs` | 1～8项；每项为`ingredient`及整数`count`（1～4096） |
| `ingredient` | 只声明`item`或`tag`其中一个 |

材料匹配复用既有分配器，精确物品和标签重叠时不能重复抵扣同一材料。配方错误时保留上一批有效配置；施工冻结开工时的模板、耗材、工时和设备快照，数据重载不改写已开始任务。首版最多同时托管4096个施工任务，模板总体积上限32768格。

`CargoBuilderRecipes`只负责独立配方；`CargoBlueprints`负责纸张蓝图身份和测试指令；`CargoBuilderBlockEntity`负责输入、检查、托管与施工生命周期；`CargoContainerSpawner.spawnPrepared`执行冻结模板的最终生成。施工记录与托管物放在唯一的`CargoContainerSavedData.BuilderJobs`内，方块实体仅保存所有者、普通输入和任务引用，不另建一套货柜账本。

## 验证边界与后续

已通过8项服务端GameTest，覆盖开工拒绝、施工不持续检查、完工阻塞／恢复、保存并重新创建方块实体、施工中及100%等待时拆台返还、重复清理、四朝向生成、跨机器施工区域预约、真实Sable成品遮挡、材料接口与权限，以及副方块拆除联动、表面按钮与状态同步。四朝向仪表位置与原始模型基座匹配、按钮前向／背向射线通过针对性单元测试。无人机节奏与轨迹验证覆盖停靠、环绕净空、减速停留、粒子作业阶段和循环连续性；本阶段相关单元测试与材料、调度点、预览回归一并验证。

本体、表面UI、无人机停靠／施工演出及背面建造方向已由玩家初步确认。本阶段保留简易材料GUI，下一轮接入正式GUI；各尺寸特殊模型、资源重载及多人规模继续按需验收。正式GUI、动力设计、蓝图获取、旧制造渠道切换，以及强制断电下跨区块／账本的一致性和多人规模性能，列入统一[待完成事项](../../设计草案/待完成事项清单.md#货柜搭建器)。正常保存恢复测试不代表已验证任意硬崩溃时刻。
