# 货柜搭建器

货柜搭建器是独立于贸易点的蓝图制造设备。已接入专用终端模型和表面UI，蓝图暂用纸张模型，材料界面已接入专用图集。原贸易点制造终端已改为带公开定影器的蓝图打印机，按贸易点目录收费写入蓝图。

## 本体与表面UI

模型位于`block/cargo_builder/body`，使用独立`cargo_builder.png`纹理。底部横跨三格，中央面板占用上方一格；放置前校验四个成员位置，只有中央控制器保存蓝图和Tick。左右副方块为半格高，中央上部使用面板包围盒。任意成员被拆除都会清理同组成员并按同一托管记录返还；不删除被外部替换的新方块，不重复返还。

| 模型编号 | 功能 |
| --- | --- |
| 1 | 翻牌仪表显示所选蓝图对应的货柜名称，无蓝图显示`---` |
| 2 | 绿色状态灯：正在搭建；完工等待／暂停时熄灭 |
| 3 | 黄色状态灯：蓝图所需材料不足，相邻容器变更后最多一秒刷新 |
| 4 | 红色状态灯：开工或完工检查确认有方块、物理结构或其他施工区域占用 |
| 5 | 绿色大按钮：开始搭建，复用同一服务端开工检查 |
| 6 | 黄色大按钮：打开材料GUI，外壳普通右键不再打开GUI |

编号1～4的仪表基座保留，5、6仅作原始定位，运行时替换为封装大按钮。显示、按钮模型、射线命中与按压反馈使用现有World UI框架，跟随四个水平朝向。状态灯不新增施工中的遮挡扫描，红灯由规定的开工／完工检查驱动。

## 使用流程

1. 将搭建器放在静态世界中，输出方向由放置朝向确定；预览和实际建造区域位于操作面的背面，底面与搭建器同高：默认操作面朝北时向南建造，旋转后同样留出玩家操作面。已经开工的任务继续使用冻结的位置。
2. 在中央方块背面紧邻放置材料容器（默认操作面朝北，则容器在南面），将材料存入该容器。搭建器从朝向自身的一面读取原生物品接口，不扫描周边多个容器或强制加载区块。手持蓝图右键搭建器任意结构部件放入，空手右键机身取出；按钮点击优先执行开始搭建／打开GUI。机顶显示已写入蓝图的蓝色模型，空白载体显示白色。施工与100%等待阶段不可取出托管蓝图；沿用放置者／管理员权限。搭建器不再有材料槽或物品自动化接口。
3. 查看世界中的半透明货柜投影与界面的材料需求，点击表面绿色按钮开工。生存模式保留航运注册、型号许可证和调度点检查；创造模式跳过这三项检查，但仍需要蓝图、材料和有效净空。
4. 当前内置配方统一施工400 tick，即正常20 TPS下20秒；投影从下向上逐层变为实体外观。施工期间这些只是视觉工作件，不是可操作或拆取的半成品方块。
5. 完工后一次放置实际结构、转换运行时锚点并进行Sable组装，蓝图恢复为空白并回到专用槽，机顶纸面变白，随后空手右键机身取回，材料消耗。生成的货柜归启动施工的玩家所有。

搭建器由放置者或管理员操作。首版没有转速、动力或VB加工费，不要求贸易点绑定。搭建器本身可合成：7个铁锭、1张纸、1个工作台，配方为`IPI / ICI / III`（I铁锭、P纸、C工作台）。

## 空白蓝图与测试工具

同一个`cargoverse:cargo_blueprint`物品有空白／已写入两种数据状态，均不堆叠。纸＋蓝色染料可合成空白货柜蓝图；创造栏只提供空白载体。管理员仍可用`/cargoverse_builder blueprint <配方ID>`直接取得测试蓝图。

单方块`cargoverse:cargo_blueprint_printer`现为“货柜蓝图测试工具”，使用原版制图台外观，仅创造玩家或权限等级2以上管理员可用，无生存合成配方。右键打开GUI，自动枚举全部有效制造配方对应的可制造货柜蓝图，不读取贸易点投放表、不维护单独JSON目录或硬编码型号清单。增加有效制造配方后自动进入目录；底层配方仍由正式制造系统提供，保证领取的蓝图可供搭建器使用。

分页选择型号后直接领取，不需要空白蓝图、材料或VB。输出槽仅允许取出，已有蓝图未取走时不能覆盖；关闭GUI时输出物归还玩家，背包无法接收时掉落。每次领取仍复核权限、距离、方块存在和配方有效性。此工具不改变大型贸易点蓝图打印机的收费及定影器逻辑。

打印机写入当前有效的配方ID，不复制材料与模板。一次已写入蓝图对应一次成功制造：开工失败不消耗；施工与100%等待时托管原蓝图；未完成拆台掉落已写入蓝图；正常完成返回空白载体。正式贸易点蓝图打印机沿用模块目录、繁荣／许可门槛与费用，使用世界中的公开定影器存取；详见[贸易点蓝图打印机](../../02贸易点系统/05_货柜制造台定义.md)。

## 材料GUI

图集为`textures/gui/cargo_builder.png`，主界面227×200。顶部只读显示蓝图和型号名称；蓝图显示使用独立投影槽，禁止取放、拖拽、快捷栏交换、丢弃及创造复制，不直接暴露真实蓝图库存。施工中同样显示托管蓝图。每种材料一张只读卡片，显示物品图标、左上角红叉／绿勾和当前数量／所需数量，数量不会超出需求。预览数值由服务端配方分配器计算，标签与精确材料重叠时不重复计数；不能从卡片放入或取出物品。施工中改为显示冻结的托管材料，不因相邻容器被拆除或数据重载而清空。

底部显示进度条，右下角勾选按钮仅保存退出，E／Esc同样关闭；GUI不提供开工入口，不绘制玩家物品栏。开工先模拟验证相邻容器可提取的完整材料，再实际转入施工托管；实际提取拒绝则返还已取部分，无法塞回的材料掉落在搭建器旁，不消耗蓝图。容器中的无关物品与多余材料始终留在原处，搭建器拆除只返还已经托管的材料。

## 施工、遮挡与返还

### 无人机施工演出

搭建器左右平台各停靠一台折叠无人机，两台复用同一份折叠模型；机身、两侧旋翼组件、桨叶和焊接臂分部渲染。开工后两侧组件按±90°展开，起飞后焊接臂展开135°，围绕货柜外框随打印层升高。桨叶独立转动；每轮40tick在焊点之间加速、减速移动，随后停留24tick焊接，仅在停留作业时发射光点与火花。两台无人机错开节奏，焊接时固定工作高度与点位，离开后再追随当前打印层。100%等待净空或施工暂停时保持展开悬停并停止施工粒子；完成后先收焊接臂、返航、落回平台并折叠。拆台直接清除视觉，不生成真实无人机实体或额外掉落。

轨迹与阶段均在客户端根据现有任务ID、施工进度及货柜体积计算，不新增无人机位置同步、寻路或世界扫描。离搭建器64格外不绘制无人机，32格外不发射施工粒子；每台每6tick至多发射4个粒子，并有全客户端每tick24个的上限。视图状态弱引用所属方块实体，不保存世界引用。实际飞行、停靠和工具姿态仍需客户端视觉验收。

### 施工生命周期

无人机旋翼运行时使用原版蜜蜂飞行循环声，声音位置跟随各自无人机，音量随展开／收拢变化；焊接停留阶段在施工点间隔12tick播放原版铲子扑灭篝火的熄火声，移动、等待净空时不播放焊接声。声音属于客户端方块音效，具有距离衰减；停靠、拆除、卸载及切换世界会结束循环，不增加服务端声音包。

- 开始时检查完整模板体积中的世界方块、Sable物理结构、区块加载与世界边界，并检查其他搭建器已预约的施工区域。失败不扣材料、不收走蓝图。
- 开始后将实际材料和蓝图转入施工托管；相应货柜以`building`状态预留资产和调度点，不能作为已完成货柜使用。
- 施工中不扫描遮挡，也不持续放置实体方块。放入障碍物不会直接取消进度。
- 达到100%时再次检查净空；有遮挡则保留100%进度与全部托管物，每20 tick重试一次。障碍移除后自动完成。完工后的输出等待最多3600个已加载游戏tick（正常20TPS下3分钟）；到期先取消任务，不再扫描输出区域，清空进度并回到待机。材料优先返还到开工时记录的供料位置和接口面，容器不存在、区块未加载或无法接收的余量掉落在搭建器旁；已写入蓝图返还原槽，不恢复为空白。不自动重新开工。
- 完成前拆除搭建器，包括100%等待阶段，直接取消并掉落全部托管材料、蓝图和蓝图槽内物品；不留下半成品，进度清零。
- 正常区块卸载或服务器重启保留施工，未加载时不推进，输出等待计数随账本保存，重载不重置；若设备被移动到物理结构上则暂停。已完成后拆除搭建器不删除成品。

开始与完成的检查均复用`CargoSpawnAreaValidator`，不是逐tick空间扫描。客户端仅获得方块状态预览、进度和短状态，不获得托管材料或完整结构方块实体NBT。

## 数据与代码职责

独立配方位于`data/<namespace>/cargo_manufacturing_recipes/<path>.json`，蓝图通过完整配方ID引用；当前为54款可制造货柜提供配方，制造材料、工时和搭建许可独立维护，并通过`container`绑定货柜定义；原制造台也复用该配方，贸易点仅维护投放与蓝图打印费。

完整字段与校验约定统一见[独立货柜制造配方](../../10数据包定义与模板/15_货柜制造配方/README.md)，本页仅维护设备生命周期与交互。

材料匹配复用既有分配器，精确物品和标签重叠时不能重复抵扣同一材料。整批依赖校验通过后统一发布；施工冻结开工时的模板、耗材、工时和设备快照，数据重载不改写已开始任务。首版最多同时托管4096个施工任务，模板总体积上限32768格。

`CargoManufacturingRecipes`提供共用制造配方；`CargoBlueprints`负责纸张蓝图身份和测试指令；`CargoBuilderBlockEntity`负责输入、检查、托管与施工生命周期；`CargoContainerSpawner.spawnPrepared`执行冻结模板的最终生成。施工记录与托管物放在唯一的`CargoContainerSavedData.BuilderJobs`内，方块实体仅保存所有者、蓝图槽和任务引用，不另建一套货柜账本。

## 验证边界与后续

已通过15项服务端GameTest，覆盖开工拒绝、施工不持续检查、完工阻塞／恢复、保存并重新创建方块实体、施工中及100%等待时拆台返还、重复清理、四朝向生成、跨机器施工区域预约、真实Sable成品遮挡、材料接口与权限，以及副方块拆除联动、表面按钮与状态同步。四朝向仪表位置与原始模型基座匹配、按钮前向／背向射线通过针对性单元测试。无人机节奏与轨迹验证覆盖停靠、环绕净空、减速停留、粒子作业阶段和循环连续性；本阶段相关单元测试与材料、调度点、预览回归一并验证。

本体、表面UI、无人机停靠／施工演出及背面建造方向已由玩家初步确认。材料GUI已使用专用图集，不绘制玩家物品栏；各尺寸特殊模型、资源重载及多人规模继续按需验收。各尺寸客户端专项验收、动力与打印价格／施工工时平衡，以及强制断电下跨区块／账本的一致性和多人规模性能，列入统一[待完成事项](../../设计草案/待完成事项清单.md#货柜搭建器)。正常保存恢复测试不代表已验证任意硬崩溃时刻。
