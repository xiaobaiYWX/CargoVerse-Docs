# 形态、运输条件与准入边界

形态仅有三种：独立固体 solid、液体 liquid（包括标准 Fluid 气体）、活体 living。Minecraft 的颗粒与粉末没有稳定分界，因此不再作为装载大类；所有现有实际物品声明均为 solid。直接流体的真实载荷与装卸已接入，气态 Fluid 统一使用 liquid，玩家点活体装卸已实现。

- 形态：决定货柜基本承载是否匹配，不按用途或制造商判断。
- 运输条件：直接写进每个物品文件的 transport_conditions，可组合围护需求、冲击耐受、温区保存曲线等，不引入条件集。
- 特殊能力与实际状态：货柜能力影响五组内部数据，围护和封存另作直接比较；按物品条件求损耗，不按名称直接豁免。缺少保护显示具体风险，不自动拒装或授予万能保护。
- 准入：独立验证完整组件、嵌套库存及可恢复性，不因形态匹配自动放行。

蛋糕、马铃薯、火药和石块都属于 solid，但可分别声明不同贴花和运输要求。空瓶与药瓶同属 solid，不代表可以在一个货柜混装不同物品或组件状态。水桶和生物桶仍是携带内容的物品，不能直接当作裸流体或活体闭环已经实现。

新条件以[条件／核心数值对应](<04_词条与完整度系统.md>)为准；旧 V／D／O／I 数据不参与损耗或生成标签。细粉对应围护 2，易碎对应缓冲后的冲击，易腐坏对应实际温度驱动的老化；固体首轮已逐项赋值，未配置条件的完整普通物品明确为空条件。质量独立于物品用途与报价，价格和经验属于具体贸易报价。

当前文档采用创造栏主题分组，T 分组仅保留历史迁移对照；两者都不决定运行分类。JSON 是唯一属性维护源，目录与声明的 form 必须一致。

## 获取方式与文档主分类

管理员与默认生存无法正常获取的物品单列 99。刷怪蛋按物品管理，不视作活体货物。禁止运输不等于无法获取；缺少配方也不等于无法获取。多个创造栏中的同一 ID 只保留一个主条目，跨目录材质族仍需一起校核。详见[专项细化安排](<../../90设计草案/物品运输属性专项细化.md>)。
