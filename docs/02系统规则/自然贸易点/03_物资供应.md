# 自然贸易点物资供应

使用专用方块 `cargoverse:material_supply_terminal` 提交货柜内的物资。终端绑定自然贸易点实例并使用站点卸载点识别货柜。灰色 `SCAN` 按钮扫描并选中货柜，`SET` 打开当前需求清单。清单每次显示三项，超出可滚动。每项显示图标、原生单位的剩余量和进度条，悬停可查看名称及已提交量。右下角勾选按钮关闭清单。

拉下确认杆会打开私有提交确认页，展示待提交的数量、质量、柜内余量和当前需求余量。制造商经验条展示个人点数、到下一级的门槛和本次增量，成功后播放更新动画。独立站点的经验条显示 `---`。按叉号可取消仍待处理的确认。

结构模板内的终端在自然生成时自动绑定。管理员在现有站点加装终端后，可空手潜行右键终端，从列表中选择贸易点。

各玩家共同推进当前阶段。每笔仅扣除未完成数量，尾量可按原生单位提交。当全部需求完成时立即提升一级繁荣度。满级的制造商站点进入常态供应，每轮清单完成后开启新一轮。无制造商归属的站点满级后停止供应。

个人制造商声望 = 本次交付量 ÷ 该需求目标量 × 需求配置声望。数值即时入账并保留小数。供应业务不结算 VB 或许可证经验。

## 数据配置

自然站定义的 `supply_table` 指向 `data/<namespace>/trade_points/supply_tables/<路径>.json`。表使用 `schema_version: 1`。按当前等级从零索引 `stages`，每个元素是一组非空需求。阶段数量决定最高繁荣度。制造商站点配置非空 `repeatable`，独立站点省略该数组或设为空数组。

需求字段为 `id`、货物身份、`quantity`，以及可选的 `reputation`。同阶段的需求 ID 和货物身份各自唯一。货物身份与常规报价相同，物品可按完整组件匹配，流体使用 `type: "liquid"` 和 `fluid`，生物使用 `type: "living"` 和 `entity`。数量以组、1000 mB 或只填写。声望按整项需求配置，默认为 0。

首笔有效交付将当前阶段的需求与目标存入站点实例。后续重载保持已有进度和目标，新阶段或新循环使用当前数据包。各站点独立保存繁荣度和进度，共用一个供应表的站点也各自结算。
