# 气体运输首版设计

> **设计草案，未实现。** 本页补齐基于 NeoForge 通用标签和流体机制的气体运输方案，不改变当前固体运输条件优先的顺序，不开放气体柜制造或添加气体。计量、质量、存储设备及首批对象仍需确认。

## 官方机制与项目设计

依据项目使用的 NeoForge 21.1.233 本地源码核验：

| 官方机制 | 可用内容 | 不包含的能力 |
| --- | --- | --- |
| Tags.Fluids.GASEOUS／c:gaseous | 标记常温下呈气态的 Fluid；不是物品标签 | 不提供具体气体、压力、压缩或气密模拟 |
| FluidStack | 流体身份、整数数量与组件 | 不是独立 GasStack，也不自动定义标准状态体积 |
| IFluidHandler | 容量／有效性查询、模拟及执行填充／抽取 | 不保证跨设备原子事务，也不保证气密 |
| FluidType | 密度、温度、黏度等描述属性；桶基准数量为 1000 | 不提供通用罐内实时压力或相变模型 |

官方依据：[Tags](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/common/Tags.java)、[FluidStack](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/fluids/FluidStack.java)、[IFluidHandler](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/fluids/capability/IFluidHandler.java)、[FluidType](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/fluids/FluidType.java)。

isLighterThanAir() 依据密度是否不大于零表示“比空气轻”，不是气体判定。重气体不能因此被划成液体，负密度不能使载货质量变负或自动提供升力。FluidType 温度也不等于罐内实时温度。

以下均为 CargoVerse 设计约束或建议，不是上述 API 自动提供的行为。

## 识别、身份与准入

- **以 c:gaseous 识别气态流体候选**，判断实际 Fluid，不按名称、贴图、密度、桶方向、烟雾粒子猜测。
- 标签只决定 gas 候选分类，不直接授予装载许可；仍需注册对象、组件可恢复、真实接口、兼容柜型、容量与运输条件校验。
- 未命中标签不表示一定可装液体柜，仍需液体侧准入。缺标的气体应核实具体 ID 后补标准标签，不添加名称推断兜底。
- c:gaseous 是 Fluid 的静态分类，不描述某份组件载荷的当前物相。同一 ID 靠组件切换物相等特殊内容不默认兼容。
- 一柜一种流体 ID 及一种完整组件状态；按与 FluidStack.isSameFluidSameComponents 一致的规则判断，不因同标签、同名或同 FluidType 而混装。
- 源／流动态归一须显式确定，不无条件合并共享 FluidType 的不同 ID。提供方若将混合气体注册成一个流体，可按该身份审阅；本模组不自行配比混气。
- 物品栏中的气瓶、装填桶仍属物品，不自动抽出内部内容。空气方块、环境大气、烟雾及 Create 蒸汽表现不自动成为可运输气体。
- 不自建气体填充内容空缺。正式开放前必须核实实际依赖注册表中存在可供给、可存储、可交付的气态流体；没有实际对象时保持未实现状态。

## 标准流体存取的复用边界

首版面向通过 FluidStack／IFluidHandler 暴露的气态流体。液体和气体可复用经过验证的身份保存、数量、容量和转移事务，但业务上分别检查 liquid／gas 柜型与条件，不表示两类柜能互换。不另造一套通用气体 API；只有出现真实共用代码时才提取，不预建空接入层。

第三方自有 GasStack／化学品接口不在首版范围，后续按实际需求独立适配。接口拒收的气体不能强行写入其库存。

后续玩家贸易点气体存储端沿用已实现的[物流隧道归属机制](玩家贸易点物流网络设计与实施清单.md)，不恢复连接器远程绑定。网络只确认归属和可达性，不自动赋予气密能力，也不保存途中气体；气体仓库及真实转移事务仍未实现。

isFluidValid 或模拟填充成功只证明接口接受，不证明设备气密、耐压或防腐。Create 储罐与管道是否合适须核验，不能仅因实现了流体接口就默认全部合格。保险库与物品仓库收发器不变成气体库存。

## 数量、容量与质量

**首版建议固定容量、整数流体数量，不实现动态压缩。** 存取原样保留接口数量；如采用 mB 显示，1000 mB 仅对应一个接口桶基准，不擅自等同现实升、标准立方米或摩尔。数量上限须与接口 int 范围一致，合计、质量及金额需防溢出。

容量单位、最小转移量、各柜容量、报价单位及损耗取整仍待确认。不得出现压缩后一个内部单位能换出多个外部单位的数量漏洞，也不沿用物品“个数”作为气体单位。

货物质量由经审阅的气体参数按剩余数量计算，不能直接套 FluidType 密度或物品默认 0.1 Kpg。如未来使用密度换算，必须明确体积、参考状态与单位，不能只对负密度取绝对值。首版建议非负质量、按内容变化刷新，不逐 Tick 解状态方程。

## 气密、压力与条件

| 范围 | 首版建议 | 未自动包含的内容 |
| --- | --- | --- |
| 承载 | 专用 gas 柜及已实现的气体存储能力；不满足则拒装 | 普通液体密闭不自动等于气密 |
| 气密 | 明确的柜型能力校验 | 漏气触发、扣量和修复规则须另定，不先写无行为词条 |
| 压力 | 固定容量，不显示伪实时压力 | 压力档、压缩能耗、超压后果待确认；不把装载率或环境气压当罐压 |
| 温度与相变 | 不自动液化、汽化、膨胀或传热 | 低温液化内容须明确物相及对应流体 ID，不靠标签代替冷链 |
| 危险性 | 仅对有明确数据及行为的内容启用 | gas 标签不自动授予易燃、腐蚀、毒性；不照搬物品扣件规则 |
| 外观 | 独立声明贴花，随运输规则冻结 | 标签不决定具体图案；无真实压力数据不绘制压力读数 |

这是最小范围建议，并非最终确认数值。Boreas 完整耐压与温度适配仍为目标；不做压力模拟时，说明和界面必须明确简化边界。

## 属性、标签重载与存量

建议每个受支持 Fluid ID 独立维护基础属性，直接写质量、准入、条件与贴花；与液体共享流体侧格式的实际共用部分，不复制物品 JSON。目录、schema 和缺失策略待流体数据契约确认，本轮不创建空属性文件或注册表。

属性 gas 分类应与 c:gaseous 一致，冲突时报告并拒绝新配置，不静默改为 liquid。仅有标签成员而没有受审阅参数、组件恢复和实际接口，不采用物品默认值自动放行。

标签与属性在同一完整数据代校验发布，失败保留上一完整代。成功装载冻结形态、质量、条件、贴花及内容身份；标签后续变更不重解释途中气体、不换壳或清货。规则不一致时禁止新装载／追加，已有载荷仍应可安全卸出；对象或组件无法恢复时隔离保留原始数据。

冻结载荷不冻结目的地状态，每次实际转移仍检查目标接收能力、容量、权限、区块加载和实际返回量。

## 装卸、交易与性能

- SIMULATE 只用于预检，不锁定库存。EXECUTE 可部分成功；以实际身份及数量为准，处理源端改变、目标拒收、重复请求和中途取消。
- 跨设备操作需明确提交、补偿或持久化保留方案，不能假定 IFluidHandler 保证原子性。禁止向世界释放／蒸发气体充当交付或回滚。
- 强制终止只能停止后续操作，不复制已转移内容或抹去未结算余额；卸载、拆除、重启后仍须数量守恒、无幽灵库存。
- 价格与经验属于具体站点报价，按实际交付量结算，计量和金额取整确认后接入；免费管理装卸、公共收费及自然点经验资格不因 gas 改变。
- 玩家贸易点功能方块的 Sable 限制保持，载具气体柜的质量刷新、结构拆分和端口失效独立验收。
- 分类查缓存，不逐 Tick 扫标签／注册表；无全世界搜索和强制区块加载。仅同步必要读数和配置，不逐 Tick 广播完整库存或组件。

## 柜型与开工前待确认

现有 [Boreas 压力气体柜](<../10数据包定义与模板/03_货柜/赫利俄斯能源集团/Boreas 压力气体柜/README.md>) M／L 两款仍未实现、未开放制造、容量未定。规格、空重、模板及 HD 接口约定在系列目录维护，本页不复制数值。

恢复实施前确认：

1. 至少一种真实存在的 c:gaseous 流体、来源、组件及真实接收端；不假设当前环境必然有气体。
2. 是否采用固定容量／不压缩建议；容量、最小转移量、质量、报价单位及损耗取整。
3. 认可的气密存储设备、站点绑定锚点、实际接口，以及储罐拆分／重组和权限处理。
4. 流体属性格式与标签冲突策略；首版是否必须包含压力档、泄漏或其他危险性。
5. 实际模板、终端、显示和投放范围；无内容不添加合成占位配方。

## 验收门槛

- 同标签但不同 ID／组件不能混装；已标记重气体不被当液体，未标记内容不靠负密度自动准入。
- 来源减少量、货柜增量、交付量与实际损耗守恒，往返不因压缩换算复制数量。
- 模拟成功但执行部分成功、目标拒收、来源改变、强制停止、拆除及重启后仍可恢复有效内容。
- 标签增删、属性修改、注册对象缺失和畸形组件分别验证，不能因重载改写或丢弃已有载荷。
- 空／满载和损耗后的质量非负且正确；气密与液密不混同，无假压力显示。
- 复用液体事务的部分做真实回归，气体识别、条件及 Sable 行为另测。没有真实气体时可用测试夹具验证接口，但不得据此宣称正式兼容或制造已完成。

完成后将真实契约合并到正式章节并删除对应待确认内容，不维护历史副本。
