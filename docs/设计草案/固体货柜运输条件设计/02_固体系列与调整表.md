## 关键调整

### Silo 与 Boreal

两者均支持 solid，不能恢复粉末／颗粒白名单。Boreal 依靠大容量和较低防护投入承接耐受粗散料；Silo 为细粉提供二级密闭和 D。石材进 Silo 完全合法，只是不一定值得为无关保护付费。Silo 保持已导出的 L／X／XL，不重新添加已取消的 M。

### Apollo

原封装敏感品柜扩展为“危险固体也适用”，补足围护 2，以覆盖火药的围护需求；受热防护须按共同模型给出明确能力，不把 I 当成所有温度风险的永久豁免。保留 M／L／X，稳定 ID 不按旧文件尾缀重建；初始权益仍为现有 Apollo M。保护优势伴随已有较高空重与投入，不把 I 发给所有通用柜。

当前 Apollo 没有防震 V；易震动敏感的危险固体若明确同时需要 V，会有剩余风险。不能由“危险品柜”名称自动获取全部保护。火药首版需求不含 V，不受此缺口影响。

### Eden 与 CryoVault

Eden 覆盖 X／XL 的大宗食品，目标 V/D/O/C；Harvest 继续 S／M／L 的耐储存农产运输，不自动升级为冷链。这样购买食品货柜不等于所有农产品被强制冷藏。

CryoVault 保留 S／M／L 与稳定 ID，**本轮建议将首发定位由深冷保存调整为小批保鲜**，拟显示名“CryoVault 低温保鲜柜”，目标 V/D/O/C。这使小量蛋糕、生鲜运输也有专柜，不必一开始使用 Eden X。该调整尚未修改正式目录标题、JSON、模型或配方；原 Z 深冷目标明确暂缓，不与 C 一起假装完成。

两个保存系列的 C 均表示延缓老化定位；四倍等效时长仅保留为初测参考，实际温度范围、保存工艺和生效条件待统一模型确认，不依品牌暗改语义。CryoVault 的二级密闭不能替代危险品保护，也不构成冷藏粉末的额外类别。

### 竞争和系列数量

AUI 4 条固体线、SPL 2、DMC 3、VBS 2、HEC 3（含 Reactor 预留）、HRI 1、BDS 2、REX 2。连同非固体占位，原制造商产品线总数不变。HRI 本轮只有 Explorer 一条固体线，已有多个规格；不为数量均衡新增职责重复的系列。

Vulcan／Express／Sentinel／Reliquary 允许防护竞争，实际容量、空重、制造材料和获取渠道继续区分。Silo／CoreVault／Express 的密闭能力也可重叠，分别覆盖大宗、小批耐用和轻型配送。

## 型号与结构执行约束

- 当前规格、接口、已导出结构、型号 ID 和初始权益不变；不得因为职责更新重新分配用户已搭建的模板。
- 增加等级 2 时核验封口、内衬和检修门；等级仅为目标，当前外观有缝时先改模板或降低实际能力，不凭文档给保护。
- 保鲜柜核验隔热与蓄冷结构，给蛋糕等设置固定托盘；未导出合格模板前仍不开放制造。
- 火药用 Apollo 时核验可封闭腔体及干燥内衬，危险标记不等于模型会爆炸。
- 本轮不改变最新 0～1 Kpg 物品质量，不用满载方块的放置质量替代运输质量，也不擅自扩大货柜容量。
- 后续若增加保护导致制造成本需调整，按实际配方材料评估；不在本轮杜撰全新的价格倍率或材料清单。
