# 玩家贸易点物流网络设计与实施清单

核对日期：2026-10-23。范围为管理核心、物流隧道、功能设备、仓库和后续运输专项的连接方式，不是整个 CargoVerse 的完成度统计。

本页是持续更新的完整设计与实施清单，不是历史方案。已实现规则的操作依据见[物流隧道与激活网络](../11玩家贸易点/06_物流隧道与激活网络.md)；本页保留必要的已实现基线，便于区分剩余工作。后续建议不因列在此页就视为已经批准实施。

## 1. 状态约定

- **已实现**：当前源码已有对应运行路径；不等于所有实机情况都已验收。
- **部分实现**：基础路径已落地，仍使用明确列出的临时规则。
- **待实现**：尚无完整运行能力；涉及数值或交互的细节仍需确认。
- **待验收**：功能代码已有，但指定的客户端、区块或多人场景尚未实测。与“待实现”分别记录。
- **不纳入**：当前方案明确不做的功能，不计作遗漏或待办。

## 2. 完整目标与数据流

玩家先注册贸易点，再铺设实体物流隧道，最后从管理核心激活。隧道支持平面四向和斜上／斜下的固定轴延伸，不直接竖直连接；设备只有在有效路径内才属于该贸易点并可参与业务。只有斜通本体不转弯、不分支；上下端点可以直接转弯或分支，不必再外延一格。它解释仓库与装卸设施间的连接，不重新建立虚拟库存或逐格运输模拟。

```text
已注册的贸易点管理核心
  └─ 平面／固定轴斜通：最短路径距离、核心占用、断线检测
       ├─ 仓库收发器 → Create 保险库：最多 3 组，物品业务已实现
       ├─ 仓库收发器 → Create 普通储罐：最多 5 组，当前只读
       ├─ 公共装载机／卸载机、仓库管理终端、信息柜、航标
       ├─ 装卸终端主标记点＋三根外围杆：区域随终端归属，不独立接网
       ├─ 气体仓储端：待实现，须先确认实际存储和介质
       └─ 生物围栏／存储端：待实现，须先确认实体与唯一性
```

功能终端和仓库不是网络中继。隧道不提供原生物品／流体接口，不能用 Create 原生管道代替本模组隧道接入。气体与生物设施接入相同的归属／可达性机制，但内容和事务由各自专项实现，不强行统一为物品库存。

## 3. 管理核心、注册与激活

| 项目 | 状态 | 当前规则或剩余工作 |
| --- | --- | --- |
| 管理核心命名 | 已实现 | 显示名为“贸易点管理核心”，保留 `player_trade_point` 注册 ID |
| 放置与注册分离 | 已实现 | 放下无主；AUTH 打开 GUI，长按 3 秒注册／注销 |
| 所有者数量限制 | 已实现 | 默认 3 个，按 UUID 跨维度统计；未加载或停用仍占名额 |
| 网络激活／解除 | 已实现 | PWR 激活、STOP 解除；不要求先装齐终端或结算器 |
| 激活与交易就绪分离 | 已实现 | 激活不保证可交易；业务另验库存、资金、本次设备和区域 |
| 配置与派生归属分离 | 已实现 | 报价、管理员、账户由核心保存，设备归属由有效路径派生 |
| 核心界面细化 | 部分实现 | 复用既有按钮、组件灯和激活状态；详细网络规模、故障位置等专用面板尚未制作，是否增加及布局待确认 |

注销／拆除释放名额并清理网络。STOP 只解除激活，不删除报价和授权；注销会清除报价、授权及统计并返还结算器。两者均不删除原生仓库内容。

## 4. 隧道、传播与核心竞争

| 项目 | 状态 | 当前规则或剩余工作 |
| --- | --- | --- |
| 平面四向连接 | 已实现 | 独立方块 `player_trade_logistics_tunnel`，可分支、回路，支持旋转／镜像；不直接竖直连接，斜接需互相匹配的坡道端口 |
| 专用模型拼接 | 已实现 | 直通／转角／三通／四通核心，按连接旋转组合；连接处加法兰，孤立或单端开口加中断接口；物品栏使用独立完整模型 |
| 临时配方 | 已实现 | 一根 Create 流体管道加一个红石粉制作；只是合成材料，不继承其流体管网 |
| 激活反馈与故障外观 | 部分实现 | ACTIVE 已切换工作贴图；独立故障外观、详细接口识别仍待细化 |
| 斜上／斜下连接 | 已实现 | 四个朝向、每格升降一格，双向寻路；专用斜通不叠加法兰／封口，两端节点保留一个斜向接头，其余三个方向可直接平接、转弯或分支 |
| 斜向节点模型 | 已实现 | 使用普通直通／转角／三通／四通与法兰／封口，斜向侧叠加共用衔接件；上下端同位置、仅水平转向；相邻斜段被拆除后节点自动恢复平面布局；相邻区块未加载时暂保留待核验 |
| 有效布局状态 | 已实现 | 85 种有效布局 × 激活两态，共 170 种；不把连接开关与斜向属性作无效组合；计划 Tick 收敛并按实际端口相互验证 |
| 有限传播 | 已实现 | 默认最短隧道路径 32 格，服务器 `logisticsRange` 可配 1～128；不是直线半径 |
| 距离计数 | 已实现 | 贴核心第一格隧道计 1；设备可贴最后有效隧道格，不通过终端穿越距离 |
| 搜索上限 | 已实现 | 每核心单次最多 4096 个节点、128 个候选端点；超限拒绝或暂停路径可用性，不部分提交超限结果 |
| 先激活核心优先 | 已实现 | 已激活范围覆盖另一核心时，后者不能激活；覆盖外核心不因远端物理相连一律被禁用 |
| 已激活网络后来相接 | 已实现 | 保留既有占用，形成边界，不夺取对方节点或设备，不自动合并贸易点 |
| 释放与重新竞争 | 已实现 | 停用／拆除后释放占用，其他核心可重新尝试激活；不自动替其他玩家激活核心 |
| 拓扑修改权限 | 已实现 | 已占用隧道拆除及紧邻占用网络扩建仅限所有者；不授予管理员改线权，不替代领地保护 |

完整配置示例见[现行网络规则](../11玩家贸易点/06_物流隧道与激活网络.md#距离与数量边界)。默认值变更不覆写已有服务器配置。

## 5. 端点发现、区域与连接工具

| 项目 | 状态 | 当前规则或剩余工作 |
| --- | --- | --- |
| 自动发现与写入归属 | 已实现 | 激活时发现核心有效路径内的受支持端点；激活后改线也会重新核验 |
| 多方块核心解析 | 已实现 | 从终端成员解析实际控制块，不给每个占位块分配独立业务身份 |
| 大型终端接口面 | 已实现 | 六类终端同步新版模型／贴图，仅接入绘制接口的底层背面成员；核心起点、模型、寻路及审批共用判定；收发器沿用平面连接，外围标记杆无网络入口 |
| 放置者确认 | 已实现 | 正常放置记录玩家；他人放置设备不自动认领，由核心所有者确认 |
| 连接工具职责 | 部分实现 | 远程选择核心、绑定和解绑已移除；现可诊断归属／激活并确认接入，完整故障与距离诊断未实现 |
| 确认交互范围 | 已实现 | 六类大型终端可点击任意成员，按实际入口确认唯一相邻已占用网络；外围区域杆只诊断主终端归属，不执行接入审批；不能借其他墙面绕过入口 |
| 单个功能终端 | 已实现 | 现有装卸机、管理终端、信息柜、航标可作为端点；每种功能仍单槽 |
| 多台同类终端 | 待实现 | 端点集合、排程、冲突提示和相关同步需专项细化，不能仅取消数量检查 |
| 主终端装卸区 | 已实现 | 主装卸终端替代一角，配三根同类杆成区；主角按底层地面计算，外围杆无隧道入口，不能独立成区 |
| 装卸机与区域配对 | 已实现／部分实现 | 区域直接由主终端持有，并随其绑定、停用与拆除；主终端和普通杆复用旋转模块。当前每种终端仍一台，多机与多区域排程未实现 |

六类大型终端已取消临时的任意成员接入。专用入口及旋转规则见[物流隧道与激活网络](../11玩家贸易点/06_物流隧道与激活网络.md)。无有效路径时，连接工具不能成为绕过隧道的绑定入口。

## 6. 断线、保存、区块与 Sable

| 项目 | 状态 | 当前规则或剩余工作 |
| --- | --- | --- |
| 拓扑变化失效 | 已实现 | 放置、拆除、相关邻接或区块变化使有关网络失效，排队在服务端更新阶段重建 |
| 失效期间业务 | 已实现 | 先拒绝业务；第一版重建前可短暂影响整个有关网络，不声称逐端点无间断切换 |
| 断线归属清理 | 已实现 | 重建后失去全部路径的端点停用并清理归属；存在范围内备用通路则保留 |
| 重新连接 | 已实现 | 激活核心自动重新发现已获准端点；不恢复已停用核心的激活 |
| 卸载区块 | 已实现 | 保留已知占用／端点预留，但经过未加载部分的路径不能交易；不强制加载 |
| 保存与恢复 | 已实现 | 按维度保存有限拓扑、归属和接入许可；恢复时重新验证，不凭存档 UUID 直接开放业务 |
| 原生存储安全 | 已实现 | 网络不保存内容；断线、STOP 或核心拆除不清空 Create 物品／流体 |
| Sable 限制 | 已实现 | 核心、隧道及功能端点只在静态世界参与网络，不做设施坐标投影；不限制运输货柜本身 |
| 复杂场景验证 | 待验收 | 跨区块真实卸载／重载、快速组装／拆解、重启后竞争，以及多人并发改线须实机覆盖 |

网络失效不等同拆除核心，也不释放所有者配额。Sable 中设施不可使用；派生归属依当前网络清理，原生内容和核心身份不受此清理影响。

## 8. 性能与同步

| 项目 | 状态 | 当前规则或剩余工作 |
| --- | --- | --- |
| 事件驱动拓扑重建 | 已实现 | 隧道无方块实体／独立 Tick；空间索引标记相关网络，不每 Tick 遍历所有端点做 BFS |
| 查询与修改分离 | 已实现 | 库存可用性查询及保存不触发拓扑重建，避免卸载／保存反复调度 |
| 最小同步 | 已实现 | 同步隧道方块状态和既有终端摘要，不广播整张网络或完整原生库存 |
| 改线成本控制 | 部分实现 | 已有事件合并、路径和节点上限；范围内相关改线仍可能重建整个网络，未实现逐分支增量重算 |
| 大量网络预算 | 待实现 | 跨网络每 Tick 工作预算／分帧重建未加入；是否需要及阈值由压测决定，不将当前硬上限视为性能承诺 |
| 多人服务器性能 | 待验收 | 统计空闲、激活、批量改线、区块边界与原生仓库重组的耗时和同步量，尚无承载规模结论 |

## 9. 不纳入当前方案

- 不建立物品、流体或生物的“隧道途中库存”；不模拟传输速度、堵塞或逐格动画。
- 不让同一物理隧道自动混装介质，也不按管内流体划分贸易点归属。
- 不借 Create 原生管网的流体能力实现核心归属，不恢复连接器远程绑定。
- 不通过加载票强制保持区块，不将 Sable 上的设施转换到世界坐标参与网络。
- 不自动合并多个管理核心的报价、资金、管理员或库存所有权。
- 不为尚无真实消费者的气体／生物创建空库存适配层，不承诺任意第三方存储兼容。

## 10. 后续推进与验收

1. **第一版基本路径：已实现。** 注册 → 铺隧道 → PWR → 自动接入 → 物品装卸 → 断线清理 → STOP，覆盖物品及流体仓库读数。
2. **第一版实机验收：待验收。** 斜通与节点接缝、碰撞手感、备用通路、区块边界、多人改线、原生仓库重组和实际载具货柜。验证结果决定是否增加调度预算。
3. **交互与接口面细化：部分实现／待确认。** 平面／斜向模型、工作贴图及坡道端点约束已接入；六类大型终端的专用接口面与任意成员确认已完成，详细故障反馈仍待制作。
4. **装卸局部化：部分实现。** 本机区域配对已完成；多终端集合与排程仍待专项评估，保持每种主终端单槽仍是当前限制。
5. **非固体闭环：待实现。** 每种介质先有真实存储及可靠事务，再接入同一网络；遵循各专项确认顺序，不同时铺开空框架。

当前物流接入验证：27 项物流／原生仓储专项世界测试覆盖四向爬坡、上下坡寻路、端点直接转弯／分支、斜通本体禁止侧支、断线／补回、四向上下端点拆坡后平接、斜通激活状态、装卸长杆的四向占位／碰撞／拆除、四向六类终端的专用入口、普通墙面拒绝接入、终端＋三杆成区／四杆拒绝、归属派生、拆除／断网／存档与加载顺序，以及实际装卸确认、仓库管理交易和非所有者改线拒绝。专项命令：`gradlew runGameTestServer -PgameTestNamespaces=cargoverse_logistics`。测试不代替上述实机待验收场景。

文档变更不重复跑代码全量测试。后续代码按变更范围选取解析、资源、事务或世界测试；没有实测的项目继续明确标记，不以“已实现”冒充“已验收”。

阶段收尾的定向验证为 27 项上述世界测试及 13 项单元测试：隧道资源 4 项、终端模型资源 3 项、区域几何 2 项、设备／就绪类型隔离 2 项、表面控件／朝向 2 项。设备枚举现只含真实端点，区域与结算器使用独立显式就绪位；隧道仍参与改线权限与事件更新。液体基础装卸已接入；剩余深化与验收集中在[液体运输首版设计](液体运输首版设计.md)，不由状态灯或仓库页面推断业务能力。
