# 生物运输首版设计

> **本轮暂停详细设计，仅保留待实现占位。** 以下既有专项资料供后续参考；当前优先[固体货柜运输条件设计](固体货柜运输条件设计/README.md)，本轮不实施本页任务。
> **待确认、未实现。** 本页准备实际活体运输，不表示活体保存、捕获、释放或交易已经接入。首批实体、容量、状态和设备尚需确认。

## 已确定的边界

- 生物指世界中的实际活体实体，不是食品、作物、刷怪蛋或装有生物的桶。
- 活体载荷与物品载荷使用不同数据，不能把实体伪装成一个物品来套用 Create 保险库。
- 只对明确支持并通过恢复验证的实体开放；不承诺任意第三方实体兼容。
- 捕获、保存和释放必须保证唯一性；失败时保留有效载荷，不生成重复实体或静默删除。
- 价格和经验在具体交易处配置，不与实体运输基础属性绑定。
- 玩家贸易点功能方块的 Sable 限制保持；不预先添加通用空适配层或完整生态模拟。
- 后续生物围栏／存储设施沿用已实现的[物流隧道归属机制](玩家贸易点物流网络设计与实施清单.md)，不恢复连接器远程绑定；围栏模型、存储、捕获与释放仍待确认和实现，网络连通不等于已有实体库存。

## 开工前待确认

| 事项 | 必须明确的约定 |
| --- | --- |
| 首批对象 | 陆生／水生先做哪一种，允许的实体 ID，以及玩家、首领、特殊实体的明确排除 |
| 容量 | 按只数、体型或空间预算计量；一柜能否混种，成年／幼体如何区分和占用容量 |
| 基础属性 | 单体质量及变体差异、运输条件、贴花、缺失定义的安全边界；确认后再定实体属性格式 |
| 捕获 | 手动或终端范围捕获、玩家权限、驯服归属，载客／骑乘、拴绳、装备和携带库存的处理 |
| 状态保真 | 名称、年龄、生命值、变种、驯服、装备等保留范围；AI、成长、饥饿与计时是否暂停 |
| 唯一性 | UUID 策略、从世界移除与写入载荷的提交时机，释放失败、重启及重复请求的处理 |
| 释放 | 释放地点、净空和水环境检查、跨维度规则；缺空间或区块未加载时如何保留内容 |
| 维持条件 | 是否消耗水、通风介质或其他资源，其质量与失效后果；不默认永久保活或完整模拟 |
| 站点与交易 | 从世界还是专用设施交付，贸易点是否持有实体库存、如何绑定与报价；不能复用物品保险库作为隐含存储 |

鱼桶和蜂箱等物品的当前准入限制不随此页自动放开；如果后续支持它们的内部内容转换，需要单独定义和验证转换事务。

## 实施顺序建议

1. 选定一种实体及捕获／释放位置，确认状态范围、容量、质量和唯一性策略。
2. 完成单体捕获、持久化和原样释放；在关闭、卸载和重启后验证只能恢复一份实体。
3. 实现已确认的批量规则、净空与水环境检查，以及必要的运输状态和失效行为。
4. 接入实际设备、界面、绑定与权限，再扩展站点收取／交付和具体交易。
5. 在普通世界与 Sable 货柜验证后，再逐个扩大实体白名单；水生专项不能仅靠换模型完成。

## 验收门槛

- 捕获与释放前后的实体类型、数量和约定状态一致，UUID 不造成重复存在或原实体被错误覆盖。
- 权限拒绝、重复请求、取消、强制终止、净空不足和无法释放时不吞生物、不增生物。
- 载荷损坏或实体类型缺失时保留可诊断原始数据，不按空柜覆盖。
- 区块卸载、服务器重启、结构拆除／拆分和跨维度流程符合已确认规则，不留下幽灵实体或库存。
- 舱内成长、维持条件、损耗和剩余质量按实际实现显示，不沿用物品固定扣件逻辑冒充生物状态。
- 客户端只同步必要摘要；完整实体数据不逐 Tick 广播，不做全世界实体搜索或强制区块加载。
- 先验证受影响的保存／恢复与事务，再验证世界交互；视觉、真实载具运输和多人性能另行验收。

完成后把已实现契约并入正式章节，删除相应待确认段落，不留历史副本。
