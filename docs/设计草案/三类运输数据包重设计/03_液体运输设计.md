# 液体运输设计

> FluidStack 共用一条运输通道。首批按实际依赖注册的流体设计，不恢复独立气体货柜类型。

## 首批流体

| 流体主体 ID | 每桶质量候选 | 条件候选 | 对应选择 |
| --- | ---: | --- | --- |
| `minecraft:water` | 1 | 无额外条件 | Cistern；液体柜至少液密1 |
| `minecraft:lava` | 1.5 | 无额外保存条件 | Cistern也可运输；当前无材质耐热协议，不能暗称只有耐火柜可装 |
| `create:honey` | 1.2 | 无 | Cistern；长期稳定的食品基准 |
| `create:chocolate` | 1 | perishable：预算36000，断点10／30，倍率0.25／1／2，推荐8 | 短途Cistern，长途Boreas |
| `create:potion` | 1 | light_sensitive：光≤5；宽限3600、间隔1200、1000mB | Crucible遮光保存 |
| `aeronautics:levitite_blend` | 0.8 | 首轮无额外条件 | Cistern；不从悬浮用途猜测挥发或失压分解 |
| `cargoverse:magma_gas` | 0.1 | volatile：宽限0、间隔1200、1000mB | 密封2的Boreas／Crucible |

Create potion 的避光是**新玩法候选**，并非原版药水会见光变质的事实。本候选统一给minecraft:potion、splash_potion、lingering_potion配置相同光照上限5、宽限3600、间隔1200、每次1pcs；散装药液每次1000mB。药水瓶仍额外易碎，散装药液本身不因此自动易碎，避免只在一种包装形态上施加限制。

巧克力每次老化损耗1000mB，其他曲线同物品食品。熔岩按原生稳定流体处理：现有系统没有内部热源、容器材质腐蚀、燃烧爆炸或相变产物机制，不能用高温敏感反过来表示它会烫坏货柜。需要这些玩法时另做功能提案。

岩浆气体质量从当前1改为0.1仅为候选；它是现有测试气体，不能当成所有气体默认密度。未知模组流体继续沿用现有 fallback，不从流体名字或原生 density 自动决定运输限制。

## 注册和路径核对

主体ID来源：本工程 `ModFluids.java`、Create 6.0.10 的 `AllFluids`、航空学1.3.0的 `AeroFluidsNeoForge` 与 levitite_blend 配方。原生源／流动变体要按实际流体注册表展开，不能仅按字符串拼接。

已知本工程同时注册 `cargoverse:flowing_magma_gas`，其质量与条件必须与源流体一致。原版 water/lava 的流动变体同理。Create／航空学的流动ID在批量落地时从注册导出核定；不要给 potion 虚构一个不存在的 flowing_potion。

液体组件必须原样保存，尤其 potion 的药效与扩展组件。当前按 Fluid ID 配置条件，不能声称同一 potion ID 的不同药效已经拥有不同保存规则。

## 柜型分工

Cistern 是便宜的常规液密运输；Boreas 为温控与气密大宗运输；Crucible 为遮光、稳压、温控的样品运输。后两种共享气密是合理竞争，不应靠禁止普通水进入专业柜拉开差距。

没有“玻璃类液体柜”：包装破碎条件属于真实运输对象。若未来确实有受冲击失稳的流体，仍可用 fragile 并以 mB 扣量，框架无需隔离词条；当前不凭空给水添加易碎。

## 配置样例：岩浆气体

```json
{
  "schema_version": 3,
  "form": "liquid",
  "mass_per_bucket": 0.1,
  "decal": "cargoverse:decal_energy_fuel",
  "transport_conditions": {
    "cargoverse:volatile": {
      "loss": {"grace_ticks": 0, "interval_ticks": 1200, "amount": 1000}
    }
  }
}
```

六款现有液体柜均沿用原ID与当前占位模板，清单中标注模板状态。补齐真实外观不要求改变液体属性路径。第一批暂不新增液体系列，先让三组明确分工成立。
