# 落数据顺序与验证

> 本页规定下一阶段的落地顺序与通过标准，不记录已完成流水。全项目待办仍统一维护在 [待完成事项清单](../待完成事项清单.md)。

## 推荐落地顺序

1. 从当前注册及属性文件生成逐ID对照：保留质量、贴花、准入；将明确条件展开为schema3，其余物品明确为空条件。先形成新旧差异清单，再写资源。
2. 将可用货柜替换为新的abilities与候选空重，清理重复旧能力字段和旧词条展示。同步系列筛选；保留全部兼容ID与制造商初始引用。
3. 添加已核验的流体主体与流动变体定义；对带组件的药水做往返。液体柜至少显式密封1，气体敏感性由volatile单独决定。
4. 测试A/B列入全部可用的新组合与代表货物；自然站按自身业务维持选择，不能把测试全目录直接复制到自然站。新模板未就绪的复启柜仍不可制造。
5. 生物沿当前新接入后端与BioPod验证配置，先核对environment及living_chamber并测试捕获释放、逐只生命损耗；Aquarium通过水生环境验证后再启用。不回退已加入的BioPod容量与验证标签。

默认普通物品不等于删除属性文件。首轮保留显式定义，便于追踪每个ID的质量、准入及贴花；是否减少冗余文件可另做维护优化，不混入玩法设计。

## 首批航程场景

以5分钟短程、15分钟标准程、30分钟长程作为候选观察窗口，均指已加载且运输系统实际推进的游戏时间，不把卸载离线时长算入。

| 同批货物 | 对照货柜 | 应观察到的差异 |
| --- | --- | --- |
| 3200pcs完整石料 | Courier S／Atlas S | 都无条件货损，只有柜体自重和被动能力差别 |
| 3200pcs细粉 | Atlas S／CoreVault S | 前者围护不足每分钟8pcs，后者消除逸散；容量不同时按相同实际装量另做对照 |
| 易受潮粉料 | Silo／Vulcan | 干燥装入后前者只能延迟受潮，后者主动降湿；围护2不等于自动除湿 |
| 玻璃 | Atlas／Hermes／Sentinel | 速度变化耐受10／12／15；完全相同轨迹下缓冲有明确收益 |
| 蛋糕 | Courier／Express／Harvest | 分别暴露于朝向、老化的不同风险，不宣称其中一个全面保护 |
| 牛奶或生肉 | 普通柜／Harvest | 热环境15分钟左右耗尽保鲜预算；冷藏延长，不刷新旧批预算 |
| 普通冰 | Harvest／CryoVault | 比较暖装降温阶段；仅设备最终目标够低不代表途中无损 |
| 120桶岩浆气体 | Cistern／Boreas | 前者约每分钟损失1桶，后者消除密封不足损失 |
| 带药效组件的药液 | Cistern／Crucible | 分别暴露与遮光；卸出药效组件完全一致 |
| 鸡／牛 | BioPod各规格 | 在新后端中分别核验只数、舱位、货重、每只生命和释放身份 |

碎料若以3200pcs装载，在持续不合格的30分钟中候选损失240pcs，即7.5%；岩浆气体120桶则损失30桶，即25%。这是原生定量扣损导致的介质差异，不应假装比例一致。测试时同时覆盖1组／1桶小批量，防止小批次在提示出现前已全部损失；过重时优先调该商品间隔或扣量，不加一套隐含比例机制。

## 静态可达性检查

以下仅按当前交换模型推算，不代表实机已通过：

- Harvest隔热时间常数240秒、制冷0.3TU/s；外温70、目标8时，目标处回热约62÷240=0.26TU/s，小于制冷。理论可达，但从70冷到8约需8分钟，不能承诺装货后立即冷藏。
- 同条件运输普通冰，降到10TU约需7分钟；其宽限180秒、下一周期60秒后可能已有损耗。CryoVault常数480秒、制冷0.6TU/s，降到10约需112秒，因此深冷柜有明确的暖装优势。
- 密封2压差交换半衰期600秒；外压0、内压1时初始泄漏约0.0012/s，稳压0.02/s有余量。密封1时交换更快，仍须核验具体目标处的平衡，不能仅看设备存在。
- 密封1湿度交换半衰期300秒；外湿100、内湿40时回湿约0.14/s，除湿1/s足以维持。气密只减慢交换，不把未知观测当成永远合格。

温度公式包含外部环境、初始内部值和控制方向；动态环境变化、暂停与实际采样会影响结果。火／熔岩接触100TU、压湿极端值、转弯与碰撞仍要实机记录。不能据静态推算给全部型号盖上“无损运输”结论。
