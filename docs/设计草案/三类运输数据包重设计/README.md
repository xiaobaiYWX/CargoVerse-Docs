# 三类运输数据包重设计

> 设计草案 · 2026-11-03 · 本轮只形成统一方案，不修改运行数据、结构模板或源码。所有新数值均为候选，尚未通过实机航程校准。

## 本轮结论

货物按运输对象分成物品、液体、生物三条通道；同一通道内用运输条件区别保护需求，用货柜能力提供保护。物品用途、制造商归属及贸易分类不再决定某柜能否装载。粉末、碎料仍是物品；气态 Fluid 仍走液体通道。

普通物品可以用普通柜，专业柜的价值是减少特定运输损耗。没有对应运输条件的货物，不为了让某种柜有用而强行添加限制。货柜等级也不形成“高一级即可全面替代”的单一路线。

本方案沿用已经注册的 13 种运输条件和 10 种货柜能力，不增加词条注册表、配置继承系统或另一套货物定义。本文的“参数档案／能力组合”只是编写清单；实际落数据时展开成现有 JSON 字段。

## 当前工程基线

扫描 `src/main/resources/data`：2315 份物品属性，其中 2304 份 schema 1、11 份 schema 3；3 份流体属性；5 份实体属性；73 份货柜定义。数量不含没有属性文件的默认物品，不能当成全部游戏注册物品数量。

现有物品属性已覆盖 minecraft、create、aeronautics、simulated、offroad、cargoverse。运输质量按最大堆叠组计算；不是按一个放置后的方块体积计算。现有固体货柜空重仍明显偏向旧尺度，本方案单列候选调整，不连带改变贸易价格或经验。

收尾核对时，工作区已新增 living 装卸后端、实体生活环境与 living_chamber 字段，BioPod S/M/L已配置16/32/64舱位并标为 validation_content。旧《生物运输设计》的“仅识别”状态说明尚未同步。本方案按最新字段设计，区分“源码已接入”和“正式验证通过”；本轮未运行活体捕获释放测试，Aquarium仍为容量0的预留内容。

## 本轮不改动的边界

保留资源 ID、已有模板引用、贸易点布局及所有用户当前修改。隐藏旧型号先作为兼容定义保留，不删除存档可能引用的 ID。能力不足是可见的运输风险，不额外增加未经实现的装载禁令。

制造商初始货柜继续引用既有型号：初始资产的调度点豁免不等于该型号所有后续制造品都免费。测试 A/B 的制造台最终覆盖可用正式型号；BioPod可沿现行验证内容路径测试，Aquarium与缺模板的复启柜按各自条件另行开放。

本目录是新内容设计入口；现行协议仍以 [运输类型与参数](../../01货柜系统/01核心系统/15_运输类型与参数.md) 为准。生物后端边界沿用 [生物运输设计](../生物运输设计.md)，不在本轮另建一份实现架构。
