# 制造商与货柜产品线

> 已实施系列能力，当前投放详见[正式货柜目录](../../10数据包定义与模板/03_货柜/README.md)。22条目标产品线：现行可用、候选复启、生物验证及水生预留分开。定位重叠可以形成竞争，不能为了每家公司数量相同而制造无用途系列。

## 能力组合的确切展开

统一使用 `cargoverse:` 命名空间。下表数值为各系列默认组合，没列出的能力不写；不把“未配备”转写成词条式设计缺陷。

| 简称 | 能力ID后缀 | 参数 |
| --- | --- | --- |
| 围1／围2 | containment | level=1／2 |
| 密1／密2 | sealing | level=1／2 |
| 缓2／缓5／缓8 | cushioning | level=1／2／3，velocity_change_bonus=2／5／8 |
| 正放 | orientation_control | level=1 |
| 遮15 | light_blocking | level=1，reduction=15 |
| 隔240／隔480 | vacuum_insulation | level=1／2，exchange_time_seconds=240／480 |
| 干燥 | humidity_control | level=1，supported_modes=[dehumidifying]，target_min=20，target_max=60，rate_per_second=1 |
| 稳压 | pressure_control | level=1，supported_modes=[pressurizing,depressurizing]，target_min=0.5，target_max=1.5，rate_per_second=0.02 |
| 保鲜 | thermal_control | level=1，supported_modes=[cooling,heating]，target_min=2，target_max=40，rate_per_second=0.3 |
| 温稳 | thermal_control | level=2，supported_modes=[cooling,heating]，target_min=0，target_max=60，rate_per_second=0.3 |
| 深冷 | thermal_control | level=3，supported_modes=[cooling,heating]，target_min=-20，target_max=80，rate_per_second=0.6 |
| 生物调温 | thermal_control | level=1，supported_modes=[cooling,heating]，target_min=5，target_max=45，rate_per_second=0.3 |

温稳、深冷是本表产品名称，不是新增能力ID。“深冷”组合仍可加热至80TU，表示设备覆盖范围，而非强制把所有货物冻结。实际目标来自货物需求和已保存设备状态。

BioPod的密封2与0.02/s稳压必须作为一个组合应用，不能保留旧候选密封1；否则很低外压下可能无法补足泄漏。它的遮光15用于避光活体，不给普通牲畜额外增加光照需求。精确参数与JSON见[生物运输数据设计](04_生物运输设计.md)。

设备初次按需自动；不附赠瞬时预冷，也不恢复用户已关闭的设备。遮光与隔热不是同一能力，气密与主动稳压也不是同一能力。

## 为什么不继续拆出更多系列

- SPL Cargo L归入Courier的尺寸延伸；Cargo M的旧兼容定义继续隐藏。
- DMC TitanHaul X／XL归入Boreal，消除同业务另起一条系列。
- BDS Bastion L／X归入Sentinel。Fortress以大宗气密、高缓冲和高空重保留差异。
- HEC Reactor与Apollo重复，继续隐藏；Reclaimer没有当前可用的独立玩法，暂缓。
- VBS Eden X／XL候选作为Harvest大尺寸复启，不以“生态”名称另造功能。
- AUI Nomad、HRI Archive维持兼容，不重新挂回常规制造表。

以上是显示系列与制造目录整理。原资源ID、存档引用和模板路径均不改名；下一步如确需变更标签，要同步更新所有基于系列标签的制造筛选。

## 制造与入门

八家初始型号继续各保留一款；HEC沿用Apollo实际M型，不重新制造过小的Reactor S。各厂入门柜不必都无能力，不应为了外观一致取消制造商特色。

制造表沿用实体材料＋加工费。落地时按能力增加精密件、密封件、保温或温控部件成本，但不引入新抽象材料库存；制造材料与加工费已在正式总表更新，不把新空重按比例折算成制造材料。Reliquary维持当前特殊获取边界，不因为本方案给了能力就加入所有自然站。

## 能力JSON示例：Harvest

```json
{
  "cargoverse:containment": {"level": 1},
  "cargoverse:sealing": {"level": 1},
  "cargoverse:vacuum_insulation": {"level": 1, "exchange_time_seconds": 240},
  "cargoverse:thermal_control": {
    "level": 1, "supported_modes": ["cooling", "heating"],
    "target_min": 2, "target_max": 40, "rate_per_second": 0.3
  },
  "cargoverse:light_blocking": {"level": 1, "reduction": 15}
}
```

该对象放入现有货柜定义的 `abilities`，不是完整货柜文件。容量、空重、模板、制造商等基础字段另按逐型号表保留或修改。
