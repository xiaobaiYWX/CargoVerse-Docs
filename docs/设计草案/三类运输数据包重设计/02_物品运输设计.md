# 物品运输设计

> 面向现有 2315 份属性。保留三态准入策略、既有质量和贴花；下面只重新设计保护需求。

## 归类顺序

先确定该 ID 是否为实际可运输物品，再判断完整包装、散料形态及物理脆弱性，最后判断保存环境。不能由“食物”“建筑”“工具”“研究样品”的用途标签直接推导货柜兼容性。

没有敏感性的物品明确写空 `transport_conditions`。这代表已设计为普通货物，不等于漏填。现有 `blocked` 不改为 standard；`empty_storage` 仍只允许符合现行空存储条件的物品，不能以清空限制的方式扩大覆盖。

以下选品规则在批量阶段展开为**确定的物品 ID 清单**，不是新增按后缀实时分类系统；模组新物品不会因为名字相似自动继承限制。

沙和砾石是物品散料；砂岩、混凝土块、矿块是固结块，不继承散料损耗。可用同一普通柜装载，只是散料可能丢失。泥土和灵魂土首轮按完整块处理，避免泛化到所有自然方块。

三种药水瓶（potion／splash_potion／lingering_potion）同步采用液体章节的避光候选：光照上限5、宽限3600、间隔1200、每次1pcs；其他玻璃瓶不自动继承药液的保存限制。

瓶装物保持直立不是默认需求：原版药水与牛奶桶被视为封装商品，没有证据表明其运输时开口。蛋糕候选同时添加 `keep_upright`：最大倾角30°，宽限60 tick、间隔200 tick、1 pcs；它是必须正放的少量教学物品，不把该要求加给全部食品。

末影龙蛋、刷怪蛋、创造物品及有特殊世界关联的物品，继续按既有准入审查；“小型脆壳物”不包含所有名称以 egg 结尾的条目。

## 保鲜曲线

候选统一为：预算36000 tick；断点10、30 TU；对应倍率0.25、1、2；推荐8 TU；预算用尽后每1200 tick扣一次。64堆叠的食品每次8 pcs；16堆叠每次2 pcs；不可堆叠食品每次1 pcs。批量阶段读取真实注册最大堆叠数，再固化为整数 `amount`，不在运行时引入比例货损。

这对应恒定环境下约120／30／15分钟有效运输后进入损耗阶段。调温过程中要累计实际老化，不能按最终冷藏温度倒算整个航程；追加不刷新已有预算。普通短途允许不用冷柜，长航程冷柜更有价值。

耐储食品暂不配置腐坏，比设置几乎永远不会触发的超长计时更清晰。寒冷地区装载的保温柜可延长保鲜，但常温装载后保温不会自行制冷。

## 配置样例：蛋糕

```json
{
  "schema_version": 3,
  "form": "solid",
  "unit_mass": 0.1,
  "decal": "cargoverse:decal_food",
  "admission_policy": "standard",
  "transport_conditions": {
    "cargoverse:keep_upright": {
      "max_tilt_degrees": 30,
      "loss": {"grace_ticks": 60, "interval_ticks": 200, "amount": 1}
    },
    "cargoverse:perishable": {
      "budget_ticks": 36000,
      "temperature_rates": {"breakpoints": [10, 30], "rates": [0.25, 1, 2]},
      "preferred_temperature": 8,
      "loss": {"interval_ticks": 1200, "amount": 1}
    }
  }
}
```

此候选保留当前蛋糕质量、贴花与准入字段。普通柜仍可装蛋糕；Harvest 延长保存、Express 稳定朝向，二者并非完整替代。若蛋糕成为常规大量长途货物，再评估冷柜是否需要选配朝向保护；不直接给所有柜补齐全部能力。

## 旧内容如何处理

现有旧字段中有202项易碎、68项防潮、10项易燃、4项正放声明。它们只作为待复核来源，不能机械迁移：完整铁窗框是否仍脆弱、原料是否真的怕湿、燃料是否会在当前TU下失稳，都要根据实体商品决定。

新表第一批覆盖上述确定族系；其他物品清楚保留普通运输。后续逐 ID 名单必须同时列出“新增条件／取消旧条件／继续普通”，尤其审核 Create、航空学的装配中间件，不能用所有 machinery 都易碎的方式补覆盖率。
