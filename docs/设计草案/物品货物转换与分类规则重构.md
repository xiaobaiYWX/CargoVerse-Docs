# 实际物品货物：确认规则与设计边界

更新：2026-10-20。原讨论稿已整合为现行约定；实施状态以[工程基线](货物系统重构工程方案.md)与正式章节为准，不再维护打包机和自有仓库的平行方案。

## 内容身份、分类与价格分离

1. **内容身份**保存实际物品 ID、完整组件和整数个数；一柜一个精确变体，不按名称、标签或哈希互换物品。
2. **运输属性**通过共享运输 JSON 与物品归属标签确定分类、单位质量及词条。未命中用唯一默认规则，多重命中报错，不逐字段叠加。
3. **交易报价**由具体站点设置收售范围、价格、库存/限额和交付经验，不给每个物品赋全局基础价；可运输不代表可交易。

当前 14 类与首批 77 组、1122 个物品已落地，详细参数和覆盖边界见[运输配置](../10数据包定义与模板/01_物品运输/README.md)。原版、Create 与航空学均属于基础设计范围，其他未配置物品仍有通用兜底，不代表已逐项平衡。

## 数量与损耗

1 个物品 = 1 个货柜容量单位，不按物品栈，质量独立计算。首版拒绝已知非空嵌套容器；组件无损保存，不因耐久或附魔不同而还原为默认物品。

运输词条直接扣固定整数数量，不使用独立完整度、百分比折价或损坏货物副产物。时限为保护期后的周期扣量，追加先结算再刷新，部分卸货不刷新，仓库存储不继续运输损耗；详见[时限](货物系统重构工程方案.md#83-时限)。

## 仓储和设备的最终简化

实际物品由 Create 保险库保存，贸易点仓库收发器提供稳定的附着绑定点；不直接绑定整个可拆分的保险库。容量由原生槽位和堆叠决定，不再固定 5000，也不维护自有库存或物品缓冲。

独立打包机仍删除，物品自动化直接连接保险库。可选仓库管理终端已恢复，提供免费管理装卸与所有者专用 SET；报价仍由核心保存，核心不再提供商品入口。公共装卸仍对所有玩家正常结算。详见[玩家贸易点](../11玩家贸易点/README.md)。

## 经验与收购目的地

许可证和目的地繁荣度经验只看收购目的地：自然→自然、玩家→自然均按自然目的地实际成交件数和当地收购报价结算，每件缺省 0；玩家目的地及手动普通目的地不奖励。货柜不再保存来源批次，不向物品注入来源组件。

内置 40 张自然站表仍为空，A／B 两张指令测试表已填充；报价 schema 3 和经验结算已实现，自然站填表与经济平衡仍待落地，不是恢复旧抽象货物目录。

## 权限和固定节点

所有者独占核心、商品设置、授权名单和绑定/解绑；授权管理者只获得管理类终端权限，公共终端对所有人开放。

玩家贸易点按所有者跨维度默认限 1，可配置。所有设施可放在 Sable 上，但不能绑定或使用并提示；货柜仍可物理运输。拆核心后无冷却或创建费，后续防频繁拆装另做。

## 后续专项范围

流体、实体尚未实现，不编写空适配层。以后必须分别设计计量、存储、恢复与防重复边界，不能把它们混成普通物品或仅按外壳质量处理。

开发期不做旧存档迁移，不保留抽象货物与新物品双轨；未知或损坏的新载荷仍应保留原文并隔离，而非静默丢弃。
