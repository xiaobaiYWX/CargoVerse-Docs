# 数值驱动的运输要求、货柜能力与货损设计

> **重构草案，未实现。** 更新：2026-10-23。本页统合原液体词条候选、固体围护与保鲜方案，进一步收敛为少量固定数值维度；是共同机制的唯一草案入口。只调整设计文档，不改变现有代码、JSON、途中载荷或货柜能力。

## 一、要解决的问题

“词条”目前同时指代货物性质、货柜保护、设计缺陷、触发器和表现名称，导致同一个名字在不同位置含义不同。增加更多名称或互斥表无法解决这一问题。

源码核对结果：

- `CargoDataSet.transportFor／fluidTransport` 先收集货物需求，再按 `special_designs` 删除同 ID 需求，最后将 `design_defects` 加入或覆盖需求。缺陷会给原本没有该需求的货物强加条件，而不只是削弱货柜。
- `ColdChainAffixHandler` 在“不足以降雪的环境”扣货，`ColdProofAffixHandler` 在“足以降雪的环境”扣货。两者直接叠加，会覆盖全部环境，无法表达“保持低温但不可冻结”。
- `FlammableAffixHandler` 累积光照／群系热量，达到阈值进入持续损耗状态；附近水会清除热量和燃烧状态。它不只是一个高温布尔判断，水中恢复也不能自动套给所有“遇热失稳”表现。
- 易碎处理使用速度变化采样，保持方向使用姿态，受潮使用雨水／邻近水，避光使用亮度，限高使用高度，放射性对附近玩家施加效果。这些可以共享调度和部分结算，但不能全部退化为同一个时间扣货词条。

上述是现状，不是新模型已经生效的声明。底层共享程度应按“观测、触发、状态、后果”判断；仅后果都是扣数量，不足以说明两种风险完全相同。

## 二、以数值为事实来源，词条为显示层

| 部分 | 所属对象 | 回答的问题 | 示例 |
| --- | --- | --- | --- |
| 运输要求 | 货物 | 什么状态下可安全运输？ | 温度允许范围、所需围护、震动容许值 |
| 能力与缺陷 | 货柜 | 实际提供什么条件？有什么结构短板？ | 缓冲、密闭、控温范围；缓冲不足、密封薄弱 |
| 行为规则 | 共用运行层 | 何时不满足要求，如何积累风险，产生什么结果？ | 暴露计时、热量累积、事件货损、周期货损 |
| 显示表现 | 货物／货柜界面 | 玩家如何理解该条规则？ | 易燃、遇热失稳、挥发、散失，以及具体风险原因 |

设计流程为：

`原始环境／物理观测 → 货柜能力经缺陷修正 → 货物实际所处条件 → 比较货物要求 → 触发与状态 → 结算后果`

词条是上述规则的可读摘要，不再直接充当相互删除的保护开关。固体、液体、气体、生物共用此模型；形态只决定基本承载与原生数量单位，不决定可选词条池。

每个货物保存一份运输要求数值，每个货柜保存一份最终能力数值。运行时不注册“粉末逸散”“碎石散落”“矿渣掉落”“液体挥发”等独立行为 ID，也不读取显示词条决定保护关系。

新增内容只填写已有字段。例如碎石、粉末分别需要围护 1、2；新矿渣需要围护 1，继续走同一个比较器。显示文案可叫“易散落”或“细粉料”，不会增加行为、状态或互斥判断。

**保留固定的能力字段与底层计算器，取消一物一词条的行为扩展。** 字段键、物品／流体 ID、翻译键仍需稳定标识；它们不是注册新词条的理由。新增名称、图标与说明属于内容工作；新增现有字段无法表达的物理行为才需扩展底层，不能承诺任意未来机制只靠改数值实现。

本草案不引入任意脚本、表达式或显示词条到规则的注册表。逐物品／逐流体属性内直接填写数值；翻译键只负责文案，不修改规则。

### 2.1 建议的核心数值

按七组组织，包含十一项候选能力数值。分组方便理解，不代表重新引入七种货物分类。此表是候选字段语义，非当前可加载 JSON；现有九类处理行为仍需逐项迁移，不能为压缩字段数而暗中删除。

| 核心组 | 货柜数值 | 货物侧数值／约束 | 比较方式与用途 |
| --- | --- | --- | --- |
| 围护 | 围护等级 E | 最低围护 Ereq | E ≥ Ereq；粗料、粉末、碎石、矿渣共用 |
| 密封 | 密封等级 S | 最低密封 Sreq；水分敏感程度 | S ≥ Sreq；液体渗失、挥发、固体升华及外部进水使用相同屏障能力 |
| 温度 | 隔热等级 I、制冷能力 C、升温／防冻结能力 H | 安全下限 Tmin、上限 Tmax；必要的受热阈值与恢复参数 | 三项能力影响同一内部热状态；最终仅比较这一个状态与允许范围 |
| 遮光 | 遮光等级 L | 可承受亮度上限 | 从外部亮度计算内部暴露，再与上限比较；高遮光只保证更少光照 |
| 机械 | 壳体强度 R、缓冲等级 B、固定等级 F | 可承受冲击／姿态范围 | 分别表示抗外部损伤、冲击传递衰减、方向固定；坚固不自动等于缓冲良好 |
| 对外屏蔽 | 危险屏蔽等级 X | 已声明的对外影响强度 | 计算剩余外泄影响；没有危险源就没有作用，不用于判断一切“危险品” |
| 接触相容 | 耐蚀隔离等级 A | 最低接触防护 Areq | A ≥ Areq；仅为首版耐蚀抽象，不与密封或屏蔽等级混用 |

等级建议只取少量非负整数，例如 0～3；每一维独立定义等级含义、上限与全局换算，不能认为“等级 2”在不同维度等强。围护先使用已有的 0～2。温度、冲击等观测量不强行取整为柜型等级。具体阈值和衰减表在实施前确定，不让制造商或单件货物各自定义一套等级含义。表中字母仅作数学说明，不复用旧 V/D/O/I 词条 ID；实际字段应使用清晰的语义名称。

对于密封这一共用能力，货物仍需明确数值要求适用的观测：向外逸散是在载货期间发生，外部进水只有实测水接触时才发生。两者复用同一屏障数值，不能因为“怕湿”而在晴天持续扣货。可用观测种类由底层固定，不因新增物品名注册触发器；同一维度同时出现多个不利观测时使用一份既定扣量计划，不按显示标签叠加。

缺省需求为无额外要求，缺省能力为不提供专项保护；缺省温度／亮度／冲击限制为不约束，不是数值 0。负需求、反向范围、越界等级和未知字段应报错，不悄悄回退默认。

壳体强度本轮只描述现有受损事件下的防护计算，不因此添加柜体耐久系统。旧限高行为仍保留数值高度上限，暂不假装由壳体强度推导气压适应；保存期是时间参数，不为它再造一个“食品专属能力等级”。若后续确需独立保存工艺，可增加明确的老化速率修正，不能伪装为制冷。

### 2.2 围护与密封的最小层级示例

| 等级 | 围护 E | 密封 S |
| --- | --- | --- |
| 0 | 无散料围护，只提供基础承载 | 无专项密封保证 |
| 1 | 粗颗粒围护 | 液密；在游戏模型中也覆盖液态水侵入隔离 |
| 2 | 精细防散失 | 气密；在游戏模型中覆盖等级 1 |

密封 2 覆盖 1 是拟采用的游戏简化，不宣称符合现实密封标准。若未来确需透气防水等差异，应明确扩展屏障属性，而不是添加“某货物例外”的词条 ID。密封等级不自动提升围护、耐蚀、遮光或物理形态兼容。

液体设备仍需满足基础液密条件；不能为了制造损耗给正常水配置一个高于基础罐的密封需求。气体运输尚未因此开放，压力容许范围也不从气密等级自动推出。

| 示例货物 | 围护需求 | 密封需求 | 含义 |
| --- | ---: | ---: | --- |
| 松散碎石 | 1 | 0 | 防掉落；其他独立风险另填 |
| 粉末 | 2 | 0 | 防逸散；怕湿者另填水分敏感参数 |
| 新增矿渣 | 1 | 0 | 直接复用粗料规则，无需新 ID |
| 普通水 | 0 | 1 | 基础液密罐即可，形态仍须兼容 |
| 某种粘稠液体 | 0 | 1 | 示例只要求防渗失；不能仅凭名称自动推断耐蚀或无挥发性 |
| 明确易挥发介质 | 0 | 2 | 液体或固体均可声明气密要求 |

上表仅说明配置方法，不批量给全部粉末、液体或模组商品赋值。围护 2 的固体柜自然覆盖围护 1 的碎石；如果同柜能防逸散却不能防掉石，就应检查形态、安全准入及其他独立要求，而不是补词条白名单。

### 2.3 直接结算，不建立按词条 ID 的冲突处理器

对等级需求先计算缺口：`gap = max(0, required - effectiveCapability)`。需求为 0 时没有这一风险；gap 为 0 时不触发该维度货损；gap 大于 0，再结合运动、进水等实际暴露条件进入共用计时。初版不自动让缺口倍增损耗，先沿用明确配置的周期与整数扣量，避免新增未平衡的倍率。

遮光、缓冲等衰减型能力使用固定全局换算表得出实际暴露值，不把亮度 15 和缓冲等级 2 直接相减。温度采用范围；保存期采用预算。这几种比较器数量固定，新增商品只填数据。

每个货物对每个计算维度只填写一份最终要求和一份损耗配置。两个显示名称不产生第二个运行实例，也没有按名称求交集的步骤。温度直接填写一对有效上下限，加载时检查 Tmin ≤ Tmax；如果将来有模板继承，在编译属性时合成，运行时仍只有一份值。

界面示例：“细粉易散失——需围护 2，当前 1；运输中有货损风险”。更换“细粉易散失”为“矿粉漏失”不改变任何结果；更改实际需求 2→1 才会改变结果。显示层可以自行选名称，但关键数值说明必须由运行数据生成，防止文案与效果相反。


## 三、显示必须区分货物要求、正向设计、负向缺陷

下表是显示用语，不是额外字段注册清单；例如防潮与气密使用同一密封维度的不同能力门槛。每个设计维度提供成对的正负描述，但不要求用货物词条的字面反义词作为缺陷。例如“冷链”的反义词不是“加热”；需要明确缺的是哪项能力。

| 维度 | 货物要求显示 | 货柜正向设计 | 货柜负向缺陷 | 缺陷的具体意义 |
| --- | --- | --- | --- | --- |
| 缓冲 | 易碎／震动敏感 | 缓冲防护 | 缓冲薄弱 | 降低冲击衰减能力，不给石块凭空添加易碎属性 |
| 固定 | 需保持直立 | 稳固固定 | 固定松动 | 降低姿态／固定防护，不生成“货物需固定”的新性质 |
| 防潮 | 需干燥运输 | 防潮隔离 | 易进水 | 降低水分隔离能力；只有声明受潮敏感的货物受影响 |
| 围护 | 易散失 | 可靠围护 | 围护不足 | 降低固体围护等级 |
| 气密 | 易挥发／需气密保存 | 气密封存 | 气密不足 | 降低气密能力，不等于只对液体生效 |
| 接触兼容 | 腐蚀性／需隔离接触 | 耐蚀隔离 | 衬层耐蚀不足 | 降低接触防护，只响应相应接触需求 |
| 热隔离 | 需稳定温度 | 隔热保温 | 保温不足 | 减弱隔热／维持能力，不代表柜内主动变冷或变热 |
| 低温维持 | 需低温保存 | 低温维持 | 制冷能力不足 | 缩小可维持温度范围，不给任意货物加冷链需求 |
| 防低温 | 需防冻结 | 防冻结温控 | 防冻结能力不足 | 减弱下限保护，不等于增加制冷效果 |
| 避光 | 光敏／需避光 | 遮光防护 | 遮光不足 | 增加货物实际光照暴露 |
| 高度环境 | 需限制运输高度 | 高空适应防护 | 高空适应不足 | 降低已声明的高度风险防护；不虚构已实现气压模拟 |
| 对外屏蔽 | 放射性／需屏蔽 | 辐射屏蔽 | 屏蔽不足 | 降低对外影响隔离；非放射性货物不会产生辐射 |
| 保存时间 | 易腐／保存期有限 | 延缓老化 | 保鲜能力不足 | 降低延缓老化效果，不让无时限货物自动腐败 |

“不提供某种保护”不自动等于一个缺陷。普通柜没有制冷能力，只显示不提供低温维持；本应有该能力但低于型号基准时，才显示“制冷能力不足”。缺陷必须带可核验的修正量或最终能力，不保留无实际行为的装饰性负面词条。

正负项在同一维度合成一次。例如围护基础 2、缺陷降低 1，最终为 1；不能界面一边显示完全防散失，另一边又无条件给所有货物加散失。推荐当前静态型号直接填写最终数值；只有确需解释基础与修正时才保留分解，先聚合同类修正，再限制在合法范围。禁止靠配置先后顺序覆盖。显示应为“围护 1（基础 2，缺陷 -1）”。

**“会主动制冷”属于设备工作状态，不能伪装为“冷链缺陷”。** 若未来存在恒定深冷、持续发热等柜型，必须显示其实际条件及可调范围；装入不耐低温的货物后，由共同温度比较产生冻结风险。本轮不引入主动故障、随机失控或能源系统。

## 四、底层复用：共享行为组件，保留风险原因

| 共用组件 | 输入与状态 | 可复用表现 | 不应混淆的部分 |
| --- | --- | --- | --- |
| 条件暴露 | 条件成立期间累计有效 tick，达到周期结算 | 散失、挥发、腐蚀、受潮、温度不适 | 条件来源与所需防护各自明确 |
| 阈值累积 | 受热等输入累积，达到阈值进入风险状态，按恢复规则退出 | 易燃、遇热失稳、受热分解 | “水能灭火”不能默认恢复已分解货物 |
| 物理事件 | 速度变化、冲击等采样达到阈值 | 易碎、震动失稳 | 稳定高速不等于受到冲击 |
| 姿态暴露 | 超过允许倾角的累计时间 | 倾倒洒落、固定不良下散失 | 姿态与冲击不是同一种事件 |
| 保存期／老化 | 有效运输年龄、保护预算、老化速度 | 食品腐败、试剂失活 | 温度达标不意味着永不老化 |
| 后果结算 | 整数扣量或已有对外效果 | 破碎、烧损、挥发、腐蚀损耗 | 同一显示名称不自动触发爆炸、世界破坏或柜体损坏 |

“周期货损”只实现扣量调度一次，不分别为每种表现编写计时器。允许调用现有对外效果；世界爆炸不因名字写了“爆炸”就开放。若以后新增爆炸后果，需要独立定义范围、作用目标和触发频次；届时仍可复用受热触发。

散失与挥发共享条件暴露和扣量，但散失可要求“运动／倾斜且围护不足”，挥发可要求“气密不足”。腐蚀也可调用同一结算器，条件则是接触兼容不足。避免把所有持续货损合并为“密封柜全部解决”。

行为组件应明示：触发条件、累计方式、保护期、周期、每次扣量、条件恢复后的处理及特殊状态恢复条件。第一阶段普通暴露采用“累计不利暴露时间，安全时暂停”，不按每次进入安全状态清零；需要恢复／冷却的阈值累积另行明确。防止通过间歇停船反复洗掉接近完成的散失周期。

底层能力共用，但参数不跨单位盲用：固体扣整数个、液体扣整数 mB。数量不足最多扣到零，扣量同步影响质量；气体、生物的原生计量仍须专项定义。货物单价不参与风险计算。

## 五、消除冷链与保温冲突：用共同状态和范围比较

同一货物的温度条件归一化为允许区间 `[Tmin, Tmax]`，不是几个独立的冷／热扣损开关。下限表示不可过冷，上限表示不可过热。冷链和防冻结可以同时存在，它们共同表达“冷藏但不可冻结”。

此处 T 是**游戏抽象热状态**，不直接标注摄氏度。现有群系温度、是否可降雪、有效光照不使用同一尺度，必须通过明确的环境适配统一；不能把当前易燃的蓄热计数当成环境温度。尺度、阈值和适配函数在实施前校准，本稿只用符号关系举例。

- 每个货物直接配置一对上下限，不再分别挂“冷链”“保温”规则。仅未来存在数值模板合成时，编译阶段才取下限最大值和上限最小值。
- 若 `Tmin ≤ Tmax`，需求成立；边界相等允许表示单一目标状态。
- 若 Tmin > Tmax，是该货物定义自相矛盾，应在加载校验时报错并指出来源；不靠排序选一个，也不容许它进入永远受损的运行状态。
- 货柜先得到经过缺陷修正的可维持范围 K；范围内可选的目标与货物需求取交集。有交集时，按统一策略选择离当前状态最近的安全目标，不同品牌不暗用不同选择规则。
- 货物需求有效、柜型能力无法满足时，这是运输适配不足，不是数据错误。遵循风险运输原则提示具体低温／高温风险；不把货物定义判为非法。
- 普通柜不具备自由选温能力，只能使用环境经实际被动能力修正后的状态；有保温结构不等于能主动把任意环境改成安全温度。
- 同一货物在同一时刻只用一个有效温度求值，不会同时判定低于 Tmin 又高于 Tmax；不让冷链保护与保温保护相互删除。

例如货物要求“低于常温、但高于冻结边界”，一个能维持该中间范围的柜型可以同时满足；只能维持深冷状态的柜型则可能过冷。保温不足表示维持能力弱，不表示主动加热，因此它与低温需求不构成名称上的互斥。

易燃中的受热触发可使用共同热环境输入，但其“达到阈值后持续烧损”的状态单独保留。降低当前温度是否停止已触发风险，应由恢复规则决定，不应由“温度重新安全”统一撤销全部历史状态。

## 六、围护不再向全保护等级扩张

只在确有包含关系的维度内使用等级。固体围护仍为 0 开放、1 粗料围护、2 精细防散失；2 覆盖 1。**密封、耐蚀、遮光不是围护 3／4／5 级。** 液密与气密按第 2.2 节拟合入密封维度，防外部液态水也复用此屏障；不为受潮再添加一套同义等级。

液密属于液体承载设备的基础条件，不能默认让所有普通水持续泄漏。气密是另一能力，细粉密闭柜不自动成为气罐；耐蚀隔离也不自动提供气密。形态与设备兼容仍先检查，不能凭一个高等级词条让固体柜装入流体。

等级不足最终转换为统一风险条件，不再给载荷添加另一套用途分类。首版接触兼容可以只支持一个明确的“耐蚀隔离”能力，不立即构造材质反应表；后续扩展也沿同一能力维度，不按液体单建体系。

## 七、按数值维度计算，避免重复处罚

1. **唯一要求**：每个货物每维一份最终数值，不保留任意数量的同义规则列表。重复字段／配置应报错；显示文案的数量不改变计算次数。
2. **最终能力**：货柜推荐直接维护最终能力数值。若保留基础与缺陷修正，只在构建货柜属性时计算一次，运行时读取最终值。设计缺陷名称不再触发独立处理器。
3. **一次比较**：围护、密封、热状态、光照、机械等各执行固定计算。不注册“粉末逸散”“矿渣散失”等新通道，也不建立按这些名称两两比较的冲突表。
4. **固定累计槽**：需要持久状态时按底层计算维度／已支持事件保存，例如密封暴露时间、热累积值。两个描述复用同一计算结果，不各自拥有计时器。
5. **独立风险并存**：受潮与散失具有不同输入，即使调用同一扣量器也可并行；相同数值缺口的一次结算不能因多个显示名称重复扣货。先汇总本轮应扣整数数量，再封顶到剩余货物，一次提交。
6. **危险源与防护分开**：货物对外影响强度为零时，任何低屏蔽柜也不会凭空产生辐射。耐蚀、密封与辐射屏蔽互不替代。
7. **无观测不编造**：缺少物理数据时标记采样不可用；区块卸载不补造环境暴露。时间预算与环境采样的时钟由共用层确定，不因显示名不同而改变。

静态要求、柜体最终能力和动态状态各保存一份；缺陷只作用一次。运行快照冻结哪些数值以及旧载荷如何兼容，要在迁移实现时明确，不读取新名称反推旧行为。

## 八、固体食品与液体保存统一处理

食品保鲜作为保存期行为，不再用 C 去删除所有 time_limit。保鲜能力影响老化速率，温度风险检查实际状态；两者可组合，不能重复为同一“变质”再配置一份超时扣货。

原固体稿提出蛋糕普通柜 20 分钟、保鲜柜等效 80 分钟以及生鲜 40／160 分钟。这些保留为**待测的数值示例**，不再作为已确定的独立 C 实现规则。若保鲜加成依赖冷藏条件，必须只在实际条件达标时应用；若采用不依赖温度的保存工艺，要直接写“延缓老化”，不能以“制冷”命名却没有温度行为。

耐储存农产品可不声明保存期。液体试剂可以使用同一保存期行为；普通水不会因此自动获得时限。完整解包后的原版物品生命周期仍按现有边界处理，不在本轮引入全世界物品腐败系统。

旧稿的“不刷新食品年龄”与当前运输追加刷新保护期规则有差别，不能当作已经兼容。迁移时须统一确认时间状态随补货、部分卸货、重载、转移及停服的行为；在实现与测试前保持现行语义，不通过文档直接改变正在运输的货物。

## 九、现有配置迁移方向

| 现行行为／字段 | 目标含义 | 迁移注意 |
| --- | --- | --- |
| fragile | 冲击耐受要求＋缓冲能力＋物理触发 | 保留采样边界，不把速度值直接当冲击 |
| keep_upright | 姿态容许范围＋固定能力 | 与散失共享姿态输入，不重复定义世界姿态 |
| moisture_proof | 水分暴露要求＋防潮能力 | “防潮”正向名与“易进水”缺陷名分开 |
| cold_chain／cold_proof | 温度上限／下限＋控温能力 | 现有二分环境不足以表达冷藏区，需统一适配和参数校准 |
| flammable | 受热累积／持续状态＋货损，显示易燃 | “遇热失稳”可复用组件，但不能继承水灭火等不适用恢复条件 |
| light_sensitive | 光照容许范围＋遮光能力 | 光照也可输入热量采样，光敏损耗与受热损耗原因仍区分 |
| height_limit | 高度容许范围＋明确的高度防护 | 不暗自升级为气压或缺氧模拟 |
| radioactive | 对外影响源＋屏蔽能力＋已有玩家效果 | 不强行归入货物持续扣量 |
| time_limit／食品保鲜提案 | 保存期与老化修正 | 不永久豁免；计时迁移显式处理 |
| 围护／挥发／腐蚀提案 | 能力比较＋条件暴露＋共用周期货损 | 不分别新增三套状态调度框架 |
| special_designs | 货柜最终能力数值及显示说明 | 不再通过删除同 ID 货物要求表示保护；显示不参与计算 |
| design_defects | 对货柜能力的负向修正 | 不能机械翻译旧数据：旧缺陷会强加风险，必须逐项审阅 |

完整规范化规则、来源和所需状态应进入下一版载荷快照；新旧快照不可混合追加。旧载荷保留原行为或经明确迁移，不由一次资源重载重新解释。序列化字段、版本号与最终参数本轮不定稿，避免把概念示例误当作可直接加载 JSON。

## 十、设计验收与实施顺序

先确定固定数值维度、全局换算与缺省值，再迁移现有行为，最后扩展内容文案；不再为新增货物性质注册行为词条 ID。

- 冷藏＋防冻结求出非空范围时可安全运输；矛盾范围在配置阶段报错。
- 制冷能力不足不强加冷链需求；固定深冷条件可能伤害怕冷货物，界面明确原因。
- 高围护柜不自动气密或耐蚀；普通无需求石块不因缺少冷链／防潮而损耗。
- 固体散失、液体挥发共用周期结算，同样的词条能跨形态配置。
- 相同数值换任何显示名，损耗结果一致；重复显示同一效果不增加运行实例。独立风险可并行且扣量不超剩余货物。
- 易燃与遇热失稳复用蓄积触发时，恢复条件仍各自正确；不自动产生世界爆炸。
- 正向能力＋负向缺陷得到唯一可解释的最终值，调换定义顺序结果不变。
- 同一温度状态不可能同时过冷与过热；主动条件、货物要求和被动保护在 UI 中分栏。
- 暴露间歇、追加、卸货、区块卸载、重载、重启和快照转换逐项验证，禁止多个表现重复运行计时器。
- 货柜系列容量、空重、模板及制造配方本轮不改变；待最终能力确定后再评估平衡。
