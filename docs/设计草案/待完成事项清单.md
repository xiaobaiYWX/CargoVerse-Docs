### 代表内容校准起点

先选红石粉、玻璃／鸡蛋、蛋糕／浆果、耐储存根茎及水等代表内容确认需求、损耗和合理航程，再分批赋值。以下是首轮测试基准，**不是直接投放全部物品的正式参数**。

常规航程取 10 分钟（12000 tick），长途取 20 分钟（24000 tick），均为实际运行的游戏时间，不是墙钟或卸载离线时间。物品测试载荷取 1000 pcs；持续环境损耗每批先取固定 10 pcs，不是随剩余数量变化的 1%。使用容量足够的柜型或测试样本，不为样本扩大正式货柜容量。

| 代表条件／货物 | 首轮候选参数 | 按现有累计损耗协议解释 |
| --- | --- | --- |
| 玻璃／鸡蛋 | 4 tick（0.2 秒）速度窗口；玻璃基础耐受 10 格／游戏秒、每事件 1 pcs，缓冲示例加 2／8 | 玻璃已接入；鸡蛋及最终耐受待实测，不持续追加计费 |

### 待验收与建议顺序

- [ ] **状态与守恒。** 新增因素的阈值相等安全、预算余数、损耗汇总、事件去重、追加／部分卸出／设备切换／重启不洗状态；固体 pcs、液体 mB，原生卸出边界不变。
- [ ] **未知与异常。** 缺湿度／气压／姿态、断样、载体切换、畸形冻结配置及 reload 失败不补零、不继续假算、不吞货；重复查询／提交不重复扣量。
- [ ] **环境候选与实机取样。** 核验真实世界／Sable 位置的群系雨雪、屋顶下增湿、基础水接触、密封与烘干共同作用；验证候选围护隔热倍率、有限压湿交换及泄压阶段屏障。光照按每秒直接合成验收，不再讨论渐变。
- [ ] **代表实运。** 验证静止、匀速、机动、撞击、倾斜、湿度变化、压差与泄压、温区穿越、补光和设备停用；真实客户端、Sable 路线、区块生命周期和多人负载有证据后再关项。
- [ ] **成本与同步。** 对加载环境柜／易碎柜、载体数量和未加载资产分别做规模验收；当前无跨柜总预算。按现有 4 tick 增量环形窗口、按需取样和运行缓存／事件提交分离的实现，实测剩余对象分配、真实物理采样及整账本自动存档，不把已落地的优化重复列为待实现；保留逐 tick 速度语义、短周期基础帧共享和环境错峰。记录 CPU 耗时、分配／GC、存档停顿及网络量，不逐件、逐 mB、逐离线 tick 或逐条件创建第二套广播／账本。

建议先完成设备界面与权限，并以代表货物校准参数、分批迁入内容；旧输入只在实际资源退出后删除。内容投放、客户端体验和实机规模分别验收。

### 开工约定

- [ ] **待确认：真实对象。** 核实至少一种实际注册、带 `c:gaseous` 标签的 Fluid，其来源、组件及真实接收端。没有实际内容则不开放制造，不自造气体填补空缺；空气方块、烟雾和 Create 蒸汽表现不是自动货源。
- [ ] **待确认：首版范围。** 建议固定容量、不动态压缩；若采用 mB，1000mB 只是接口桶基准，不冒充升、标准立方米或摩尔。容量、最小转移量、报价单位、损耗取整及非负质量均需核定；不得直接按 FluidType 密度计重或把负密度当升力。
- [ ] **待确认：气体设备。** 确认认可的气密存储、真实接口、收发锚点、权限、拆分／重组规则；接受 IFluidHandler 填充不等于设备气密、耐压或防腐，不默认认可普通 Create 储罐。
- [ ] **待确认：压力和风险范围。** 决定首版是否涉及压力档、泄漏、温度、相变及危险性；不以环境气压、装载率或 FluidType 温度冒充罐内实时状态。不因 gas 标签自动增加易燃、毒性或腐蚀。
- [ ] **待确认：数据契约。** 与现有逐流体属性契约衔接，明确 gas 标签／声明冲突、缺失参数、默认值与安全卸出策略，不直接沿用物品默认值。根据实际共用代码复用字段，不预建空注册表。
- [ ] **待确认／实现：Boreas。** M／L 专用结构、容量、气密／承压能力、显示与正式投放；无真实气体时不增加合成占位配方。

### 接入与正确性

- [ ] **待实现：识别与准入。** `c:gaseous` 识别标准流体候选，不按名称、贴图、密度或烟雾推断；缺标签需核对 ID 后补标准标签。同 ID 依组件改变物相等特殊内容不默认兼容；源／流动态归一显式确定。
- [ ] **待实现：精确气体身份。** 一柜一种 Fluid ID 及完整组件，不按同标签、名称或 FluidType 混装；气瓶／装填桶仍按物品运输，不自动抽取；不自行配比混气。
- [ ] **待实现：真实业务后端。** 沿用[物流归属](../11玩家贸易点/06_物流隧道与激活网络.md)，复用已验证的 FluidStack 身份、数量及事务，但分别校验 gas 柜和气密端点；保险库和普通液体柜不自动转换为气体仓库。
- [ ] **待实现：属性重载与冻结。** 标签和属性整代校验，失败保留上一完整代；装载冻结身份、形态、质量、需求与贴花；变化不重解释途中货物，规则不一致禁止新装／追加但保留安全卸出。对象或组件无法恢复时隔离保留原始数据。
- [ ] **待实现：转移与结算。** 以实际执行身份／数量为准，处理模拟后库存变化、部分执行、目标拒收、取消、强制停止及补偿；不得向世界蒸发气体当回滚。质量、价格与经验按确认计量和实际成交量计算，合计防溢出。
- [ ] **待验收：守恒与恢复。** 往返不因压缩或单位换算复制数量；标签增删、缺注册对象、畸形组件、重启／拆除／区块卸载后保留有效内容；空满及损耗后质量正确，无虚假压力显示。
- [ ] **待验收：实际设备与载具。** 验证气密规则、真实接口、Sable 货柜质量和结构拆分；只同步必要摘要，分类查缓存，不做全世界搜索或强制加载。

第三方独立 GasStack／化学品接口不在首版范围，出现明确需求后再评估适配。标准标签不是独立气体 API，也不自动提供压缩、压力或气密。机制参考保留：[NeoForge Tags](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/common/Tags.java)、[FluidStack](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/fluids/FluidStack.java)、[IFluidHandler](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/fluids/capability/IFluidHandler.java)、[FluidType](https://github.com/neoforged/NeoForge/blob/1.21.1/src/main/java/net/neoforged/neoforge/fluids/FluidType.java)。

## 生物专项

**待确认，尚未开放。** 目标是实际活体，不是食品、作物、刷怪蛋或生物桶；只开放通过恢复验证的实体，不承诺任意第三方兼容。

### 开工约定

- [ ] **待确认：首批实体。** 陆生／水生先后、允许 ID、玩家／首领／特殊实体排除及逐步扩大白名单的门槛。
- [ ] **待确认：容量与基础属性。** 只数、体型或空间预算、一柜是否混种、成年／幼体占用；单体质量、变体、运输需求、贴花及缺失定义的安全策略，确认后再定属性格式。
- [ ] **待确认：捕获与权限。** 手动或终端范围捕获、归属／驯服权限、载客／骑乘、拴绳、装备和携带库存如何处理。
- [ ] **待确认：状态保真。** 名称、年龄、生命、变种、驯服及装备保留范围；AI、成长、饥饿和计时是否暂停。
- [ ] **待确认：唯一性与事务。** UUID 策略、世界移除与载荷写入提交顺序、重复请求、释放失败和重启恢复规则。
- [ ] **待确认：释放与维持条件。** 地点、净空、水环境、跨维度规则；水／通风或其他耗材及其质量、失效后果，不默认永久保活或完整生态模拟。
- [ ] **待确认：站点库存与交易。** 世界或专用设施收交、实际实体库存、报价与经验；不使用保险库伪装活体存储。鱼桶／蜂箱内部内容若要转换，另定和验证转换事务。

### 接入与验收

- [ ] **待实现：最小唯一性闭环。** 先完成一种实体单体捕获、持久化、原样释放，再处理批量、环境及失效行为；关闭、卸载和重启只能恢复一份。
- [ ] **待实现：真实围栏／存储端。** 沿用物流隧道归属与权限，接入实际设施、界面、存储及转移，不恢复连接器远程绑定；静态生物图标不等于运输实现。
- [ ] **待确认／实现：BioPod／Aquarium。** BioPod S／M／L 与 Aquarium M／L 的模板、容量、环境维持、制造和投放；有水箱模型不等于已实现水生保存。
- [ ] **待验收：身份与状态。** 类型、数量、约定状态一致，UUID 不重复、不覆盖原实体；损坏载荷或缺实体类型保留可诊断原始数据，不覆盖为空柜。
- [ ] **待验收：失败与生命周期。** 权限拒绝、重放、取消、强制终止、净空不足不吞／增生物；重启、区块卸载、拆除／拆分、跨维度无幽灵实体。
- [ ] **待验收：显示与性能。** 维持条件、成长、损耗和质量按真实实现显示；仅同步摘要，完整实体数据不逐 Tick 广播；无全世界实体扫描、无强制加载。普通世界和 Sable 货柜通过后再扩白名单。

## 物流与终端细化

现行操作、端口、预算和局部重算见[物流隧道与激活网络](../11玩家贸易点/06_物流隧道与激活网络.md)，本节只列未完成交互与验收；复杂图回退完整搜索是当前正确性策略，不作为残留删除。

- [ ] **待确认：核心专用网络面板。** 是否增加详细规模、故障位置和路径反馈，确认后再定布局与实现，不把已有激活状态灯算作完整诊断面板。
- [ ] **待确认／实现：故障反馈。** 连接工具的完整故障／距离诊断、设备接口识别反馈及隧道独立故障外观；按实际交互需求细化。
- [ ] **待验收：客户端线路。** 四向坡道接缝、节点连接件、工作态贴图、接口识别及实体碰撞手感。
- [ ] **待验收：真实生命周期。** 跨区块卸载／重载、快速组装／拆解、服务器重启后的占用竞争、备用路径切换及原生仓库拆分／合并。
- [ ] **待验收：多人业务。** 多台同类终端共享库存、各自区域与独立选择；同时确认、货柜占用、权限拒绝、跨网络连接冲突和频繁改线不复制或吞货。
- [ ] **待验收／调优：真实负载。** 用 `/cargoverse logistics` 比较空闲、激活、批量／密集改线、多网络、区块边界和仓库重组的节点量、局部命中／回退、草稿作废、队列、耗时与同步量；据实调整 Tick 预算。同步发布／绑定阶段仍须实测，不把节点额度当严格毫秒上限，不提前承诺承载规模。

不默认增加航标多台、跨区域自动派单、全图任意增量算法、隧道途中库存、逐格输送或强制区块加载；这些不是本轮遗漏待办。
