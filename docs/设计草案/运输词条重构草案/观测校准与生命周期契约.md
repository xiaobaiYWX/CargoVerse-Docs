## 二、统一观测结构与时间契约

服务端观测至少包含：货柜与物理载体身份、实际世界坐标、server tick、provider 采样序号／时间、坐标或载体切换标记、各因素值及各自有效性。来源有变化、维度切换、传送、组装／拆解、暂停恢复都会断开运动连续性。

- 环境参考点采用模板中心转换到真实世界后的点；静态货柜也有该点。不是直接读取 Sable 的姿态原点或玩家脚下。
- 首版近场检测只读中心与相邻六个世界方块，不扩大为全世界扫描。检查区块可读性后采样，不强制加载；范围未加载导致无法确认时标未知。
- TU、气压、亮度、水接触分别记录有效性。单项失效不强制停止无关因素，但温度失效时必须同时暂停内部温度求值、温度损伤和温度相关老化。
- 时间单位是服务端游戏 tick，速度观测归一到每游戏秒；TPS 下降只改变现实耗时，不把一 tick 当实际墙钟秒。
- 建议环境每 20 tick 一次，运动每 tick 一次；只对实际有相应需求的已加载载荷调度，不让所有空柜维持模拟。
- 每个环境有效窗口最多 20 tick；窗口两端观测有效、身份连续才按左端输入近似推进。超过预期窗口或端点未知时不跨空档外推。这是采样近似，不承诺观察到两次采样之间的短暂进水／热源。
- 恢复首个观测只重建基线，下一次连续有效观测才推进。任何延迟查询与交互都复用同一权威累计结果，不重复结算。
- 需要状态的首次装载，缺少必要初值时拒绝该次提交并提示；尚未扣款扣货。无温压需求的普通货物不因无关观测缺失而无法装载。

运动 provider 可能以物理子步更新，但对外必须提供带时间戳、未被 UI 舍入的样本。不得把同一个缓存速度重复读取三次视为三个新物理样本。现有缓存若不满足此约束，需扩展观测适配，不能凭估计补齐。

## 三、环境 TU：固定来源与可替换的校准配置

### 3.1 采样输入

首版从真实世界参考点读取：

1. 群系基础温度 b；其值不是 TU，也不是摄氏度。
2. 有效天空光 S：扣除昼夜暗度，且参考点可见天空才贡献太阳暴露；S 限制在 0～15。
3. 实测降雨接触，不以“世界正在下雨”代替被雨淋到。
4. 中心与相邻六格的水接触、熔岩／火接触。火包括直接火、灵魂火，以及点燃状态的营火；不把普通方块亮度当作热源。
5. 维度。支持显式的维度基础热度覆盖；没有配置则走通用群系映射，不从维度名字推断气候。

湿度、凝露、远处岩浆、机器内部发热、任意模组自定义热源均不在首版来源中。热源范围是设计近似，模型制作不能把贴图里的火光当成有效热源。

### 3.2 V0 候选映射（供观测实验）

候选配置名建议为 `environment_calibration_version`，采样语义与常数均有版本：

- 非覆盖维度基础热度：`Tbase = 20 + 20 × clamp(b, -0.5, 2.0)`。
- 干燥普通暴露：`Tout = Tbase + 10 × S / 15`。
- 实测雨接触时，在上式基础上减 5 TU。
- 水接触时改用 `Tout = Tbase`，不叠加太阳和雨冷却；水提供当地温和边界，不被视为任何维度中的固定冷源。
- 直接火／熔岩接触时取 `Tout = 100 TU`，优先于水和天气。此处统一是第一轮简化，不比较真实火焰温度。
- 维度显式配置只替代 Tbase；若确需改变接触规则，另改统一配置并更新版本。
- 最终输入都必须有限；取样失败返回未知，不能以 40 TU 静默补齐。例示范围不是所有世界的硬边界。

例：b＝1、无水无雨、S＝0，得到 40 TU；同点 S＝15 得到 50 TU。b＝0 的阴影为 20 TU。真实游戏是否合理必须用下表校准，不依据这些例子立即给食品指定最佳温区。

太阳增温属于环境边界；柜体隔热与调温之后才得到 Tin。遮光只影响内部亮度，不额外减一次太阳增温，避免把同一能力隐式当隔热。

### 3.3 接入前校准门槛

需要保存实际样本记录（world／维度、位置、tick、b、S、雨水／热源标记、Tout、版本），不能只截图报“感觉冷”。

| 场景 | 校核目的 |
| --- | --- |
| 冷、温和、炎热群系，白天／夜晚 | 群系与日照顺序可解释，变化符合拟定尺度 |
| 同点室外、阴影／屋顶、降雨、水接触 | 太阳／雨／水分支只按规定输入变化 |
| 地下普通照明与真实火／熔岩 | 灯光不产生未经定义的热源效果 |
| 主世界及项目可用其他维度 | 默认与覆盖行为明确；不强行保证维度“真实气候” |
| 移动货柜与同位置静态探针 | 世界坐标相同时环境读数一致 |
| 卸载边缘与输入未知 | 不加载区块，不填默认温度，不跨缺样补算 |

单位测试可固定上述输入与分支结果；实机必须检查分布与变化速度，之后才决定 V0 是否成为首个发布版本。修改常数不新增词条 ID，但需更新校准版本。

## 四、冲击指标 J：运动突变代理，不宣称真实碰撞冲量

### 4.1 坐标、速度与采样

适配层对外输出世界坐标下货柜参考点的速度 v（block／游戏秒）及角速度（rad／游戏秒）。当前工程从 Sable 的 latestLinearVelocity／RigidBodyHandle 读取值，界面将速度当作每秒数值使用；这不能代替 provider 单位、原点与采样时基的验证。

若 provider 给的是质心速度，需要使用 `v_point = v_com + omega × (point - center_of_mass)` 取得货柜参考点速度；必须核实速度的定义原点。不能默认姿态位置就是质心，也不能在已经是点速度时再加一次旋转项。接口无法可靠给出这些信息时，先报告不支持该来源，不把角速度随意折算为冲击分。

仅对连续、不同采样时间、相同载体的样本计算。传送、维度切换、载体切换、重启、卸载恢复与缺样均丢弃速度差并重新建基线。不得用“大位移阈值”把真正高速碰撞一概忽略。

### 4.2 J 的候选计算

建议以惯性突变计算代理强度，消除重力和正常支撑基线。设 Δt 为有效采样间隔的游戏秒：

`a = (v_now - v_prev) / Δt`
`a_excess = max(0, length(a - g_world) - length(g_world) - a_noise)`
`J_external = a_excess / a_reference`

g_world 使用同一位置和时间尺度的航空学／物理重力向量，不能硬编码地球重力。V0 暂用 a_noise＝1 block/s²、a_reference＝20 block/s²；这些是待校准常数，不是 SI 碰撞强度或原版物理事实。

- 静止支撑：a≈0，扣掉支撑基线后不产生冲击。
- 匀速直线：同样不触发。
- 自由落体：a≈g，不把重力本身当碰撞；着地减速仍可能产生强突变。
- 急刹、骤转、碰撞：可能产生高 J。
- 持续大加速度或高速旋转同样可能被代理识别。这是模型局限，不谎称能准确区分碰撞和所有正常机动。

J 是每采样点的候选强度，缓冲只作用一次：`J_effective = J_external × cushioning_ratio`。与货物 tolerance 比较后才决定是否损伤。

### 4.3 事件去重

V0 建议以统一门槛将连续突变合为一个事件：J≥0.2 开始；J≤0.1 且连续 3 个有效 tick 才结束；记录峰值与事件序号。物品不各自设一套事件门槛。可声明的货物 tolerance 需不低于有效观测分辨率，否则必须校验报错或提高采样精度，不能悄悄漏掉小冲击。

同一事件内，一旦经缓冲后的峰值严格超过耐受，最多扣一次 damage_amount，并记录已结算；之后峰值更高也不重复扣。持续高强度状态不靠超时不断开启新事件。恢复平稳后再次冲击才能形成下一事件。

暂停／缺样切断观测，但要保留上一事件是否已结算的去重信息；恢复需先观察连续平稳窗口才重新武装事件判定，避免暂停接触反复算撞击。该边界可能漏掉恢复瞬间的一次冲击，是暂停模型的明确取舍，不补造未知事件。

不允许用旧的每 20 tick 速度差直接宣称满足本契约。每 tick 采样仍可能漏掉一个 tick 内完全恢复的碰撞；首版必须注明该分辨率限制。若实测不足，应改 provider 事件／子步峰值适配，而不是把所有 tolerance 降得极小补偿漏检。

### 4.4 必须完成的观测实验

| 实验 | 要验证什么 |
| --- | --- |
| 直线恒速 5／10 block/s，持续 20 游戏 tick | 位置差与速度单位一致，单次采样序号不重复 |
| 静置、平稳起步／停车、自由落体 | 噪声基线与重力处理，不误称匀速碰撞 |
| 不同速度接触同一刚性障碍 | J 峰值具有可解释的趋势，事件不连扣 |
| 对向连续反弹、保持接触、短间隔两次撞击 | 能区分一个持续事件与平稳后的独立事件 |
| 载具边缘货柜旋转、中心货柜对照 | 参考点速度和质心换算正确 |
| 不同 TPS、物理子步、缓存来源切换 | 游戏时基一致；变化来源标记连续性 |
| 传送、组装、卸载／重启恢复 | 不把位置跳变当碰撞，不刷新可重复扣货事件 |
| 测试信号中一 tick 内往返冲击 | 记录采样盲区，决定是否需要 provider 峰值接口 |

先以机械测试载荷记录原始速度、g、Δt、a_excess、J、事件序号和缓冲后值；不先改正式玻璃或食品耐受。暂时达不到契约时该因素显示未校准，不宣称其货损已经可以正式投放。

## 五、追加、卸出与暂停的确定语义

### 5.1 第一次装入与追加

- “装载时冻结”发生在空柜第一笔**正数成功提交**时，不在预览、选择菜单或制造时冻结。
- 首笔提交在事务内读取同一代定义，冻结规则并初始化必要 Tin／Pin；取消、失败、零数量尝试不新建运输批次。
- 追加前结算已有效观测的旧载荷，再对精确身份、冻结兼容性、容量等重新校验。
- 追加不刷新 effective_age、暴露预算、余数、内部 T／P、压力释放和事件去重状态。新数量继承整批当前状态，不做数量加权“返老还童”。
- 首版不计算新原生货物的混合温度或追加开口泄压；这是追加原子事务的简化，不悄悄赋予预冷和增压动作。
- 需要多批各有寿命时属于未来批次模型，不在当前一柜一状态中临时叠加。

### 5.2 卸出和原生边界

- 部分卸出先结算，再转移真实数量；剩余货物保持全部累计状态。
- 原生 ItemStack／FluidStack 保留原有身份和组件，不写入本模组运输年龄、剩余预算或运输冻结规则。
- 卸入背包、保险库、储罐等原生库存即结束这部分数量的运输寿命。之后重新装载是新一次运输，明确接受卸空再装能重开生命周期，不声称防止此操作。
- 全部卸空或损耗至零，清除载荷的冻结规则与动态状态；保留货柜身份、调温设置等资产数据。
- 不在本轮新增柜间直传；未来若是保持运输载荷的直传，应继承冻结规则和年龄，不能伪装为原生卸出刷新。
- 金额、转移量与寿命状态一次事务提交，失败不得让数量回滚而年龄或扣量提交两次。

### 5.3 暂停与恢复

区块卸载、物理载体实际不可用和服务端停机暂停全部运输更新。暂停期间不老化、不变温、不泄压、不累计危险暴露；因此存在暂停保存的游戏边界。

读取存档不以 now－last_sample_tick 补算。恢复只建立新观测基线，已保存 Tin／Pin／年龄／余数继续保留；内部状态不跳回环境或最佳温区。

单因素未知只暂停其依赖链；例如 TU 未知则暂停温度与老化，其他有效的水接触、光照可以继续。气压未知不当真空；无物理观测不当静止。界面必须标出不能评估的因素。

“卸载”指世界／物理载体卸载，不是从货柜取走一部分货物。仍加载的剩余货物继续运行，不能由一次部分卸货暂停整柜。

## 六、能力冻结：装载冻结，制造不永久锁定

### 6.1 冻结什么

首笔成功装载冻结一份完整 `TransportRuleSnapshot`：

- 货物物性、质量、贴花以及与追加有关的准入规则。
- 七项最终能力。
- 该次调温设备支持方向、目标范围等不可变约束。
- 等级换算表、环境 TU 映射、J 校准配置及求值语义版本的可恢复引用或实际值。

**只有版本号不够。** 途中规则必须能在重启后恢复。首版优先随快照保存必要的不可变解析数值；代码语义用版本识别。未知版本隔离，不自动用最新常数重解释。采样事实可共用原始观测，但不同冻结版本的 TU／J 转换分别按本次规则进行，不能共用一个最新转换值偷偷改变旧货。

### 6.2 不冻结什么

当前实际温度、压力、年龄、余数等是动态状态；工作模式／目标可由玩家修改，但仅允许本次冻结的支持方向与目标范围。更改目标不会刷新任何寿命，也不会立刻更改实际温度。

制造只记录型号身份与制造时实际资产信息；本方案仅决定七项运输能力不制造锁定，不借机改变容量、空重或现有模板的资产契约。

### 6.3 reload 与空柜

- 装载中的柜保留本次能力；新定义不能自动升级、降级或更改其 TU／J 换算。
- 空柜下一次装入读取最新完整定义，既有空柜与新制造同型号柜采用同一套当前运输能力。
- 有货时界面优先显示本次冻结能力；可以附“定义已更新，下次装载生效”，不能显示新能力同时按旧能力计算。
- 追加必须精确身份一致，且当前解析出的货物和承运数值与冻结规则兼容。仅显示文案变化不阻止追加；物性、能力、换算或准入等计算内容变化则拒绝追加并允许正常卸出。
- 定义删除：已冻结载荷仍可按其可恢复规则处理与卸出；空柜无法解析定义时禁止新装载，不随便赋默认能力。
- 空柜的旧目标设置若已不被新型号支持，切为 off 并提示重新设置，不静默选择另一个可能有害温度。支持范围仍合法的模式／目标可保留。
- reload 只原子发布完整有效的新定义。运行中的装卸确认必须重验代次和兼容性，不能跨代提交。

与制造冻结相比，此边界避免同型号长期存在多代隐藏能力，同时保证途中规则稳定；代价是卸空后可能采用新平衡，制造界面和装载预览须明确告知。

## 七、旧运输词条引擎退出

重构最终版本只运行新数值求值器。删除旧行为分派、Handler、旧完整度／时限结算残留及 special_designs／design_defects 加删风险逻辑；改造显示投影而不保留旧执行入口。

旧辐射、持续燃烧、定向等不在七项模型内的行为本轮不保留运行分支，也不伪装为某个新等级。未来如需恢复，先设计独立物理作用，再接入新的统一系统。

保留物品／流体身份、事务、仓库、钱包、质量更新、结构和可复用绘制工具；它们不是旧词条引擎，不能因为文件名带 Affix 就盲删。

新作者 schema 2 拒绝旧 transport_requirements 并报告资源路径。当前内置 schema 1 数据尚待第三轮切换，只保留旧资料且不再执行行为；该阶段状态已明确公示，不能当成正式无风险设计或内容验收通过。开发期旧载荷不做“翻译成七项”的猜测迁移：保留原始记录并隔离，提供明确诊断，不执行旧引擎、不覆盖为空柜。不自动清世界或删除用户货物；是否另做显式恢复工具留待实际旧数据需求。

新内置数据在同一次切换中完成格式一致性。无敏感性内容显式采用无额外要求，未设计内容标为未赋值；不能把全部旧字段删掉就称为平衡完成。

## 八、内容与架构分开验收

等级换算表、TU/J 的 V0 常数只用于模型与观测验证。下一阶段先做测试样例，再按真实路线赋值：

- 固体系列最终七项能力，尤其隔热与调温组合。
- 逐物品的耐受、预算、老化曲线和损耗速率。
- 液体密封需求、温压敏感性和原生 mB 损耗。
- 如需经济调整，再结合容量、航程、日补、收入与获取成本单独评估。

本轮不改变容量、质量、价格或配方。先验收正确性：冻结、暂停、追加、守恒、单位与观测一致；后验收可玩性，不用架构测试通过冒充内容平衡完成。

## 九、实施门槛

1. TU／J 的观测接口、有效性、世界坐标和时基按本页接入；必要专项测试已保留，不维护独立录制器／分析器或强制校准工具流程。
2. 运行取样采用当前 Sable provider 的每秒世界质心速度与旋转修正，使用每 tick 采样，不以旧 20 tick 间隔差替代；候选尺度先服务当前架构与测试，正式内容仍须实机验收。
3. 单元测试固定输入验证 V0 分支、边界、事件去重；实机记录确认是否采用或调整候选系数。
4. 追加后年龄不变、原生卸出无运输寿命、卸载／停机不补算。
5. 制造不锁七项能力；空柜首笔提交冻结；reload 前后追加、展示、卸出和重启一致。
6. 新引擎完整接管后删除旧运行路径，坏数据隔离且无双重扣货。
7. 上述通过后再批量赋正式物性和产品能力，逐项保留校准版本及测试证据。
