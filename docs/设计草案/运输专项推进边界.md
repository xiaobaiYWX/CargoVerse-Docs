# 运输专项推进边界

本页只维护后续专项和验收边界，不保存历史方案。实际物品与基础液体装卸已经落地，共用职责见[多类型载荷与计量](../01货柜系统/01核心系统/12_多类型载荷与计量.md)，现行规则见[工程边界](../00一级系统总览/02_货物与贸易工程边界.md)及[液体运输](../01货柜系统/01核心系统/13_液体运输.md)。

## 已实现基线

- 源码四种介质 solid／liquid／gas／living，当前开放 solid 和 liquid；物品栏中的物品统一为独立固体，液体不通过桶物品冒充。
- 共用带类型身份、资产封套、原生数量、操作份数、冻结规则、时钟、确认及补偿事务；仅注册真实业务后端，不增加无消费者的空适配层。
- 物品 1pcs 一步；液体整数 mB 保存、常规 1000mB 一步，尾量保留，全部实际量参与计重。液体尾量只在管理卸载时完整免费回收，公共交易不结算尾量。
- 2312 份逐物品属性、独立逐流体属性都是维护源；质量、词条与贴花不由报价或文档分组推断。液体无定义时默认每桶 1Kpg，气体标签 c:gaseous 不走液体分支。
- 45 款固体柜使用实际结构；Cistern／Crucible 的 M／L 四款已开放基础液体业务和测试制造，使用 AUI 同规格占位，容量暂定 120000／240000mB。其余 15 款专项不制造。
- 玩家点使用最多 3 个保险库、5 个普通储罐；仓库切换、液体报价和表面交互已接入，气体仓库与生物围栏尚未接入。网络归属、库存观察、配置和实际事务分层维护。
- 价格和经验由交易处决定，40 张正式自然站表仍为空；测试目录不代表正式经济设计完成。自然目的地经验按实际成交份数发放，不限制来源。

## 下一步工作

1. [液体后续设计与验收](液体运输首版设计.md)：补齐逐流体内容、专用柜体结构、最终容量和正式投放；材料保护、泄漏、腐蚀等新条件独立实现，不因模型命名自动生效。
2. [气体运输](气体运输首版设计.md)：确认首批内容、操作步长、质量、存储端点和容量。c:gaseous 只识别标准流体表示的气体候选，不提供压缩、压力或气密；不默认桥接独立气体 API。Boreas 未开放制造。
3. [生物运输](生物运输首版设计.md)：确认实体白名单、容量、状态保留及捕获／释放唯一性。不能通过保险库存实体，静态生物图标不等于运输实现。

气体和生物的实施顺序由后续需求决定，不随液体上线自动开放。[固体货柜运输条件](固体货柜运输条件设计/README.md)的围护、温控与危险品保护继续独立推进，不作为其他介质的隐含前置条件。

## 持续维护与验收

- 属性按 ID 独立维护，装载时冻结；reload 不改途中质量、词条和贴花，追加必须完整身份与冻结规则一致。物品悬停不恢复分类及默认来源展示。
- 容量、原生单位、操作单位、价格和经验单位明确；不逐 mB 或逐计时周期循环，不因数量大产生线性计算。
- 拒绝、取消、重放、空间不足、失败回滚、结构拆分／合并、断线和重启不得复制、吞货或生成影子库存。服务端最终校验，不强制加载仓库区块。
- 客户端单位布局、平面图标与扫描、特殊组件流体、资源重载需要视觉复核；Sable 货柜质量和装卸、多人并发与持续自动化需要实机验收。玩家贸易点设施的 Sable 限制不取消。
- 按[变更验证策略](../06开发与运维/06_变更验证策略.md)选择受影响检查，不每次全量测试；自动回归不等于完成视觉和压力验收。
