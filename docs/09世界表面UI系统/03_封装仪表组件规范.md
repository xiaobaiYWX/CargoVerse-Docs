# 封装仪表组件规范

## 1. 定位

封装仪表是世界表面 UI 框架与具体终端之间的客户端组件层。终端不再独立拼接相同的数字牌、进度条、监视器或状态灯，而是创建仪表实例、传入展示数据并指定矩形范围。

```text
业务状态／不可变 ViewState
            ↓
终端组合层 client.gui.terminal
            ↓
封装仪表 client.gui.instrument
            ↓
GuiGraphics 或 WorldUiRenderContext
```

仪表只负责视觉表达，不读取方块实体、不查询服务端、不发包，也不决定业务权限。终端组合层只负责布局与数据映射，方块实体 renderer 只负责构造展示快照并调用统一世界绘制入口。

## 2. 公共约定

### 2.1 双渲染目标

每个正式仪表同时提供：

- `render(GuiGraphics, ...)`：传统 GUI、测试界面或物品预览；
- `render(WorldUiRenderContext, ...)`：世界表面 UI；
- 有状态动画时提供 `renderAnimated(...)` 与 `createAnimationState()`。

两套入口必须共享数值换算、布局和动画判定，不能形成两份行为不同的实现。

### 2.2 原生尺寸与适配

仪表以素材原生像素为布局坐标。`InstrumentLayout.fit` 在目标矩形中等比缩放并居中，`fitLeft` 用于状态灯等需要整体左对齐的组件。调用方可以给出更大的矩形，但不得依赖非等比拉伸修复布局。

### 2.3 动画状态

动画状态是客户端可变对象，必须按“控制器 + 独立仪表实例”隔离：

```java
private final InstrumentStateCache<AnimationState> animations =
    new InstrumentStateCache<>(ignored -> new AnimationState());
```

`InstrumentStateCache` 使用访问顺序维护，默认最多保留 256 个控制器状态，避免长期浏览世界后无限增长。不要让两个语义独立的仪表共享同一个 `SplitFlapDisplay.AnimationState` 或 `IconMonitor.AnimationState`。

### 2.4 光照

默认规则是“结构受光，辉光自发光”：

| 内容 | 光照规则 |
| --- | --- |
| 仪表外壳、边框、翻转牌、柱体、指针、普通文字 | 使用环境光 |
| 图标监视器内部图标 | 自发光并轻微频闪 |
| 紧凑型百分比条的橙红数字 | 自发光并轻微频闪 |
| `GREEN`／`YELLOW`／`RED` 状态灯 | 自发光并轻微频闪 |
| `OFF` 状态灯 | 使用环境光 |

终端组合层不得把整个画布改成全亮。新增发光内容必须具有明确的设备语义，并在仪表内部通过 `drawEmissive*` 实现。

### 2.5 颜色与资源

- 默认显示背景：`#333333`；
- 默认文字：`#EBD8B5`；
- 共享颜色从 `CargoUiPalette` 读取；
- 运行时素材位于 `assets/cargoverse/textures/gui/instruments/<instrument>/`；
- 原始美术位于 `美术资产/通商惠工/GUI/通用素材/封装仪表/`；
- 组件内通过 `InstrumentTextures` 解析资源路径，不在各仪表重复拼接根路径；
- GUI 着色必须通过公共着色工具应用，并在 `finally` 中复位，避免颜色泄漏到后续绘制。

### 2.6 瞄准高亮与用途提示

每个仪表实例必须在构造时持有 `InstrumentInfo`。该对象描述当前实例的业务用途，而不只是组件类型；例如同一个翻转字符牌在不同位置应分别声明为“货柜名称”“制造费用”或“材料页码”。默认构造器仅供测试或没有更具体语义的通用场景使用。

普通世界表面仪表在完成自身等比适配后，把**实际绘制矩形**交给 `InstrumentHoverFeedback`。公共反馈层使用当前表面的 `SurfaceAnchor` 做准星射线命中，并直接沿这一个矩形绘制高亮边框；终端不得保存另一套命中矩形、高亮偏移或悬停状态。这样目标矩形、等比缩放、命中范围和边框不会各自漂移。

命中后的文字不绘制在倾斜世界表面，而由 `InstrumentHoverHud` 显示在准星旁边。若同一视线同时命中多个可见仪表，本帧只显示距离玩家最近的候选。打开 Screen、隐藏 HUD 或超出世界交互距离时不显示提示。HUD 只提供客户端识别反馈，不产生网络包，也不授予任何业务操作权限。

`HolographicProjection` 不属于平面画布，因此在自身封装中用投影底座的真实世界范围完成水平面命中，并沿底座边缘绘制高亮；它仍向同一个准星 HUD 提交 `InstrumentInfo`。空投影仍保留底座的提示能力。

## 3. 现有仪表

### 3.1 翻转字符牌 `SplitFlapDisplay`

用途：名称、页码、倒计时、整数、单位及短状态码。

- 构造时固定槽位数，可选左、中、右对齐；
- 原生单槽宽 `14px`、高 `41px`，总宽为 `(槽位数 + 2) × 14px`；
- 保持 Minecraft 原版字体渲染，支持 Unicode 码点裁切与填充；
- 相邻数字正向或反向变化只翻转 1 次；
- 非相邻数字、字母和符号变化翻转 12 次，随机内容仅使用字母和数字；
- 每次翻转 `0.06s`，多个变化槽位从前向后间隔 `0.2s` 启动。

```java
SplitFlapDisplay display = new SplitFlapDisplay(
    8, SplitFlapDisplay.Alignment.LEFT);
SplitFlapDisplay.AnimationState state = display.createAnimationState();
display.renderAnimated(context, "LINE 3/3", bounds, outward, state);
```

### 3.2 百分比值 `PercentageMeter`

用途：库存、燃料、材料量等纵向百分比。

- 输入为归一化 `0..1`，非有限值与越界值由公共规则收敛；
- 纵向显示 10 个离散分段；
- 下方三位翻转牌显示 `000..100`；
- 原生尺寸 `70×123px`；
- 数字动画复用翻转字符牌。

### 3.3 增减指示器 `DeltaIndicator`

用途：增长率、变化量、趋势或带单位的有符号数值。

- 指针输入归一化为 `-1..1`，对应中心左右各 `90°`；
- 首槽显示 `+`／`-`，其后是固定数量数值槽，再后是调用方指定数量的单位槽；
- 单位正常占用翻转牌，不是仪表外的固定标签；
- 原生高度 `44px`，宽度为 `51 + 总槽位数 × 14 + 14px`；
- 指针、旋转中心与素材坐标由组件内部维护。

```java
DeltaIndicator indicator = new DeltaIndicator(3, 1);
indicator.renderAnimated(context, normalizedTrend, delta, "%",
    bounds, outward, state);
```

### 3.4 紧凑型百分比进度条 `CompactPercentageBar`

用途：横向空间有限的百分比摘要。

- 输入为归一化 `0..1`；
- 进度由 10 个独立图块拼接，不横向拉伸单张进度纹理；
- 右侧两位橙红辉光数字带轻微亮度频闪；
- 当前两位读数在满值时显示 `99`，进度分段仍可达到 10／10；
- 原生尺寸 `128×36px`。

“满值显示 99”是当前两位素材约束，不应在终端层自行改写；若未来需要显示 `100`，应统一调整组件与素材。

### 3.5 图标监视器 `IconMonitor`

用途：货物、贸易点等级、设备或状态图标。

- 原生尺寸 `48×42px`；
- 调用方必须同时传入纹理及源图宽高，组件在可视区内保持比例缩放，不变形拉伸；
- 外壳受环境光影响，图标内容自发光并轻微频闪；
- 图标切换时按 `2×2` 逻辑像素，从上到下、从左到右扫描更新；
- 空槽必须调用 `renderEmpty`，这会同时重置该槽动画状态。

```java
IconMonitor.Icon icon = new IconMonitor.Icon(texture, sourceWidth, sourceHeight);
monitor.renderAnimated(context, icon, bounds, outward, state);
```

### 3.6 状态灯 `StatusLight`

用途：选择状态、占用状态、运行状态和错误提示。

| 状态 | 语义 | 发光 |
| --- | --- | --- |
| `OFF` | 关闭、空槽、未达到 | 否 |
| `GREEN` | 正常、当前选中 | 是 |
| `YELLOW` | 运行中、已有内容但未选中 | 是 |
| `RED` | 错误 | 是 |

灯体原生尺寸 `8×9px`。标签可为空；提供标签时显示在灯右侧，整个组件保持左对齐。状态灯只表达调用方传入的状态，不自行推断业务含义。

### 3.7 缩微胶卷阅读机 `MicroficheReader`

用途：为长文本和简单图案提供可变尺寸的缩微胶卷显示区域。它本质上是一层显示滤镜：终端只提交有序文字行和图标，组件统一处理排版、投影底色、裁切、频闪和换页动画。

- 内容底色以 `#CDCCAB` 为中心基准色，组件使用五层内嵌色带构成边缘暗、中心亮的投影渐层；
- 整个投影填色区域共用同一组轻微亮度频闪，文字、图标和边框不参与频闪；
- 原始资源只有左上角 `14×16px`、上边 `20×6px` 和左边 `10×10px`，其他方向由组件内部镜像生成；
- 横边以 `20px` 为单位、竖边以 `10px` 为单位按整数像素平铺，末段只裁切，不拉伸像素画；
- 最小外框尺寸为 `28×32px`；小于该尺寸会拒绝绘制；
- `contentBounds(...)` 返回扣除左右 `10px`、上下 `6px` 后的内容矩形，文本和图标始终裁切在该区域内；
- `Content` 包含有序 `TextLine` 和相对内容区定位的 `SimpleIcon`；文字样式会被剥离并固定显示为黑色，图标保留贴图原色；
- 文字排版由组件固定为左边距 `2px`、上边距 `2px`、`0.65×` 字号和 `8px` 行进间距；调用方只决定文字行顺序，不得为单行另设坐标、缩放或行距；
- 内容变化时执行 `350ms` 下滑切换：旧页向下退出，新页同步从内容区上方滑入，动画结束后只保留新页；
- 图标在目标矩形中保持原始宽高比，滑动过程中的越界部分按纹理 UV 裁切；
- 图框、填色和黑色内容均使用环境光，不具有自发光语义；
- 同时提供普通 GUI 与世界表面渲染入口，调用方不得自行拼接边框、滤镜颜色、频闪或换页动画。

内部职责固定分为三层：`MicroficheReader` 只管理内容、投影底色和换页状态；`MicroficheFrameRenderer` 只管理图框资源、镜像和平铺；图标的等比适配、UV 裁切、GUI 着色复位及世界表面纹理绘制统一复用 `InstrumentTextureRenderer`。其他仪表若需要裁切纹理，不得再复制这一套渲染代码。

```java
MicroficheReader reader = new MicroficheReader();
MicroficheReader.AnimationState animation = reader.createAnimationState();
MicroficheReader.Content page = new MicroficheReader.Content(
    List.of(
        new MicroficheReader.TextLine("ARCHIVE 01"),
        new MicroficheReader.TextLine("LONG TEXT...")),
    List.of(new MicroficheReader.SimpleIcon(
        iconTexture, 16, 16, new SurfaceRect(140, 4, 20, 20))));
reader.renderAnimated(context, page,
    new SurfaceRect(16, 12, 180, 96),
    WorldUiRenderLayers.CONTENT, animation);
```

每个独立阅读机必须持有自己的 `AnimationState`，正式终端通过 `InstrumentStateCache` 按控制器隔离状态。调用方把长文本拆为有序 `TextLine`，组件按固定行距依次排布；自动换行、滚动和复杂矢量图形不属于该组件。

### 3.8 全息投影 `HolographicProjection`

用途：在世界中直接显示完整货柜微缩模型。它不把三维模型投影或压缩到二维画布，而是由一个实体底座建立世界坐标基点，并在底座上方逐块渲染服务端同步的 `CargoStructurePreviewSnapshot`。

- 底座使用原生 `3×1×3 MCpx` 方块模型，按原尺寸绘制，不做九宫格拼接；
- `baseCenter` 表示底座在方块实体局部坐标中的底面中心；货柜底面中心自动与底座中心对齐；
- `Settings.modelScale` 控制每个货柜方块在世界中的缩放尺寸，必须为有限正数；
- `Settings.modelHeight` 控制货柜底面到投影底座顶面的净高度，单位为方块，必须为有限非负数；
- 货柜保持完整 X／Y／Z 深度和直立姿态，玩家可以通过移动世界视角观察其不同侧面；组件不再应用 GUI 预览使用的 28°／45° 固定观察角；
- 底座使用环境光并保持稳定；货柜模型使用公共 `InstrumentFlicker` 生成的近全亮动态光级产生轻微频闪；
- 无快照或空快照时仍显示底座，但不绘制占位模型或文字；
- 该组件是世界空间三维仪表，不提供普通 GUI 渲染目标。普通 GUI 中既有的货柜预览仍使用 `CargoStructurePreview`，两者共享同一服务端快照而不共享坐标变换。

```java
HolographicProjection projection = new HolographicProjection(
    InstrumentInfo.localized("container_preview"));
projection.render(cargoPreviewSnapshot, blockState, poseStack, buffers,
    packedLight, packedOverlay, renderOrigin,
    new Vec3(0.5D, 1.0D, 0.25D),
    new HolographicProjection.Settings(0.04F, 0.10D));
```

## 4. 终端组合规范

正式终端组件放在 `client.gui.terminal`，推荐结构如下：

```java
public final class ExampleTerminalDisplay {
    private static final SplitFlapDisplay TITLE = new SplitFlapDisplay(
        12, SplitFlapDisplay.Alignment.RIGHT,
        InstrumentInfo.localized("example_title"));
    private static final StatusLight STATUS = new StatusLight(
        InstrumentInfo.localized("example_status"));

    private final InstrumentStateCache<AnimationState> animations =
        new InstrumentStateCache<>(ignored -> new AnimationState());

    public void render(WorldUiRenderContext context, ExampleViewState state) {
        AnimationState animation = this.animations.stateFor(state.animationKey());
        // 只做 surfaceId 分派、数据格式化和矩形排布。
    }
}
```

组合层允许：

- 按 `surfaceId` 分派不同显示面；
- 把业务值格式化为仪表输入；
- 定义固定 `SurfaceRect`、标签和图标描述；
- 选择共享调色板中的语义色。

组合层禁止：

- 复制仪表纹理路径或拼接算法；
- 实现另一套翻转、频闪或扫描动画；
- 直接读取服务端单例或方块实体；
- 绘制公共背景、表面内框或交互命中描边；
- 把整块显示面切换为 emissive。

## 5. 新增仪表流程

1. 确认需求可在至少两个终端复用，而不是单个终端的一次性装饰；
2. 在美术源目录中确定原生尺寸、分片边界和透明区域；
3. 将运行时纹理放入独立的 `textures/gui/instruments/<instrument>/` 目录；
4. 实现普通 GUI 与世界表面两个入口，共享布局与数值算法；
5. 在组件封装中持有 `InstrumentInfo`，并让世界入口以实际绘制范围调用统一瞄准反馈；
6. 明确哪些部分受环境光、哪些部分允许自发光；
7. 有动画时提供独立状态对象，并保证首次显示稳定、切换可中断或收敛；
8. 添加数值边界、动画判定、资源存在性和架构约束测试；
9. 先在仪表测试方块中观察，再接入正式终端；
10. 更新本文档中的组件表、输入范围和视觉约束。

## 6. 组件检查

- [ ] 普通 GUI 与世界表面显示相同内容、比例和状态；
- [ ] 目标矩形变化时保持原生宽高比；
- [ ] NaN、无穷、越界数值和过长文本有确定行为；
- [ ] 多个控制器或同面多个组件不会串用动画状态；
- [ ] GUI 着色在绘制后复位，不污染其他 HUD／Screen 内容；
- [ ] 低光环境中外壳变暗，明确的辉光内容仍可见；
- [ ] 瞄准每个仪表时边框严格贴合实际绘制范围，准星旁显示该实例的具体用途；
- [ ] 相邻或重叠仪表只显示最近目标，打开 Screen、隐藏 HUD 和超距时不残留提示；
- [ ] 组件测试、资源测试、架构测试和终端组合测试通过；
- [ ] 在 Minecraft 客户端检查最终视觉结果，不以自动化测试替代视觉检查。
