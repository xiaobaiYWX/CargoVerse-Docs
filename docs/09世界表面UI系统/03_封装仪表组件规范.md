# 封装仪表组件规范

## 1. 定位

封装仪表是世界表面 UI 框架与具体终端之间的客户端组件层。终端不再独立拼接相同的数字牌、进度条、监视器或状态灯，而是创建仪表实例、传入展示数据并指定矩形范围。

```text
业务状态／不可变 ViewState
            ↓
终端组合层 client.gui.terminal
            ↓
封装仪表 client.gui.instrument
            ↓
GuiGraphics 或 WorldUiRenderContext
```

仪表只负责视觉表达，不读取方块实体、不查询服务端、不发包，也不决定业务权限。终端组合层只负责布局与数据映射，方块实体 renderer 只负责构造展示快照并调用统一世界绘制入口。

指南针无需业务数值，但其方位也通过不可变 `Compass.Orientation` 显式接入：宿主在绘制前读取安装参考与所属子世界姿态，组件只做方向到刻度盘的映射，不自行获取 Sable 参数。

## 2. 公共约定

### 2.1 双渲染目标

每个正式仪表同时提供：

- `render(GuiGraphics, ...)`：传统 GUI、测试界面或物品预览；
- `render(WorldUiRenderContext, ...)`：世界表面 UI；
- 有状态动画时提供 `renderAnimated(...)` 与 `createAnimationState()`。

两套入口必须共享数值换算、布局和动画判定，不能形成两份行为不同的实现。

### 2.2 原生尺寸与适配

仪表以素材原生像素为布局坐标。`InstrumentLayout.fit` 在目标矩形中等比缩放并居中，`fitLeft` 用于状态灯等需要整体左对齐的组件。调用方可以给出更大的矩形，但不得依赖非等比拉伸修复布局。

### 2.3 动画状态

动画状态是客户端可变对象，必须按“控制器 + 独立仪表实例”隔离：

```java
private final InstrumentStateCache<AnimationState> animations =
    new InstrumentStateCache<>(ignored -> new AnimationState());
```

`InstrumentStateCache` 使用访问顺序维护，默认最多保留 256 个控制器状态，避免长期浏览世界后无限增长。不要让两个语义独立的仪表共享同一个 `SplitFlapDisplay.AnimationState`、`IconMonitor.AnimationState` 或 `DialMeter.AnimationState`。

### 2.4 光照

默认规则是“结构受光，辉光自发光”：

| 内容 | 光照规则 |
| --- | --- |
| 仪表外壳、边框、翻转牌、柱体、指针、普通文字 | 使用环境光 |
| 图标监视器内部图标 | 自发光并轻微频闪 |
| 紧凑型百分比条的橙红数字 | 自发光并轻微频闪 |
| 圆盘形仪表的三位辉光数字 | 自发光并轻微频闪 |
| `GREEN`／`YELLOW`／`RED` 状态灯 | 自发光并轻微频闪 |
| `OFF` 状态灯 | 使用环境光 |

终端组合层不得把整个画布改成全亮。新增发光内容必须具有明确的设备语义，并在仪表内部通过 `drawEmissive*` 实现。

### 2.5 颜色与资源

- 默认显示背景：`#333333`；
- 默认文字：`#EBD8B5`；
- 共享颜色从 `CargoUiPalette` 读取；
- 运行时素材位于 `assets/cargoverse/textures/gui/instruments/<instrument>/`；
- 原始美术位于 `美术资产/通商惠工/GUI/通用素材/封装仪表/`；
- 组件内通过 `InstrumentTextures` 解析资源路径，不在各仪表重复拼接根路径；
- GUI 着色必须通过公共着色工具应用，并在 `finally` 中复位，避免颜色泄漏到后续绘制。

### 2.6 瞄准高亮与用途提示

每个仪表实例必须在构造时持有 `InstrumentInfo`。该对象描述当前实例的业务用途，而不只是组件类型；例如同一个翻转字符牌在不同位置应分别声明为“货柜名称”“制造费用”或“材料页码”。默认构造器仅供测试或没有更具体语义的通用场景使用。

普通世界表面仪表在完成自身等比适配后，把**实际绘制矩形**交给 `InstrumentHoverFeedback`。公共反馈层使用当前表面的 `SurfaceAnchor` 做准星射线命中，并直接沿这一个矩形绘制高亮边框；终端不得保存另一套命中矩形、高亮偏移或悬停状态。这样目标矩形、等比缩放、命中范围和边框不会各自漂移。

命中后的文字不绘制在倾斜世界表面，而由 `InstrumentHoverHud` 显示在准星旁边。若同一视线同时命中多个可见仪表，本帧只显示距离玩家最近的候选。打开 Screen、隐藏 HUD 或超出世界交互距离时不显示提示。HUD 只提供客户端识别反馈，不产生网络包，也不授予任何业务操作权限。

`HolographicProjection` 不属于平面画布，因此在自身封装中用投影底座的真实世界范围完成水平面命中，并沿底座边缘绘制高亮；它仍向同一个准星 HUD 提交 `InstrumentInfo`。空投影仍保留底座的提示能力。

### 2.7 载具专用仪表的输入约定

载具专用仪表沿用普通仪表封装和双渲染目标。使用仪表的地方自行读取 Sable 的速度、朝向等所需数据，并直接传给组件；仪表只负责绘制及与输入对应的动画。是否安装在 Sable 结构上只影响数据是否可用，不改变仪表组件的职责。

```text
使用仪表的宿主按需读取参数 → 该仪表的输入 → 绘制与动画
```

- 组件只接收自己需要的标量、向量或专用输入记录，不接收 `SubLevel`、物理刚体等 Sable 运行时对象；
- 参数读取、坐标转换、单位换算和数据是否可用由当前使用方负责；仪表只处理数据到画面的映射、动画与绘制；
- 不建立统一载具接入层、通用数据快照或参数总线，也不要求所有仪表经过相同的数据入口；
- 每个仪表必须说明输入名称及类型、单位、坐标系、正方向、有效范围、无数据的传入方式和对应的动画行为；
- 无物理结构或参数暂不可读时，使用方按该仪表约定传入无数据状态，不把未知速度或姿态伪造为有效 0；航迹偏差仪是明确例外，按设计将静止／无方向回退为船头对齐；
- 普通方块状态仍可显示仪表外壳及未接入表现。测试宿主可直接传入样例数据，使用相同绘制入口；
- 指南针在普通世界也有有效方位，由使用方提供静态世界参考；这一行为不能推广为其他载具参数的默认值。

### 2.8 绘制、几何和宿主的职责

`InstrumentLayout` 处理原生坐标适配及 GUI 旋转贴图，公共旋转入口负责枢轴变换、层级与矩阵／颜色复位；仪表只传入各自的素材坐标、旋转角及层级，不再复制相同的 pose 操作。世界绘制继续使用 `WorldUiRenderContext` 的旋转原语，不创建另一套世界画布。

`AttitudeIndicatorGeometry` 与 `TrackDeviationIndicatorGeometry` 分别负责天地窗口和航迹扇区；航迹缓存保存不可变整数像素行，不保存浮点画布矩形或宿主引用，至多覆盖 361 个规范化角度。颜色、纹理、GUI／世界缩放仍由仪表组件处理。姿态仪最近一组填充缓存保持在组件实例内。

测试宿主中的服务端速度采样、是否同步的判断和客户端方位换算保持私有实现；不将其提升为正式仪表必经的数据服务。显示面与四个仪表矩形统一定义在 `VehicleInstrumentTestWorldUi`。载具测试动画按世界会话隔离，缓存不会强引用已经离开的世界。现有注册名、素材路径和组件公开调用方式保持不变。

## 3. 现有仪表

### 3.1 翻转字符牌 `SplitFlapDisplay`

用途：名称、页码、倒计时、整数、单位及短状态码。

- 构造时固定槽位数，可选左、中、右对齐；
- 原生单槽宽 `14px`、高 `41px`，总宽为 `(槽位数 + 2) × 14px`；
- 保持 Minecraft 原版字体渲染，支持 Unicode 码点裁切与填充；
- 相邻数字正向或反向变化只翻转 1 次；
- 非相邻数字、字母和符号变化翻转 12 次，随机内容仅使用字母和数字；
- 每次翻转 `0.06s`，多个变化槽位从前向后间隔 `0.2s` 启动。

```java
SplitFlapDisplay display = new SplitFlapDisplay(
    8, SplitFlapDisplay.Alignment.LEFT);
SplitFlapDisplay.AnimationState state = display.createAnimationState();
display.renderAnimated(context, "LINE 3/3", bounds, outward, state);
```

### 3.2 百分比值 `PercentageMeter`

用途：库存、燃料、材料量等纵向百分比。

- 输入为归一化 `0..1`，非有限值与越界值由公共规则收敛；
- 纵向显示 10 个离散分段；
- 下方三位翻转牌显示 `000..100`；
- 原生尺寸 `70×123px`；
- 数字动画复用翻转字符牌。

### 3.3 增减指示器 `DeltaIndicator`

用途：增长率、变化量、趋势或带单位的有符号数值。

- 指针输入归一化为 `-1..1`，对应中心左右各 `90°`；
- 首槽显示 `+`／`-`，其后是固定数量数值槽，再后是调用方指定数量的单位槽；
- 单位正常占用翻转牌，不是仪表外的固定标签；
- 原生高度 `44px`，宽度为 `51 + 总槽位数 × 14 + 14px`；
- 指针、旋转中心与素材坐标由组件内部维护。

```java
DeltaIndicator indicator = new DeltaIndicator(3, 1);
indicator.renderAnimated(context, normalizedTrend, delta, "%",
    bounds, outward, state);
```

### 3.4 紧凑型百分比进度条 `CompactPercentageBar`

用途：横向空间有限的百分比摘要。

- 输入为归一化 `0..1`；
- 进度由 10 个独立图块拼接，不横向拉伸单张进度纹理；
- 右侧两位橙红辉光数字带轻微亮度频闪；
- 当前两位读数在满值时显示 `99`，进度分段仍可达到 10／10；
- 原生尺寸 `128×36px`。

“满值显示 99”是当前两位素材约束，不应在终端层自行改写；若未来需要显示 `100`，应统一调整组件与素材。

### 3.5 图标监视器 `IconMonitor`

用途：货物、贸易点等级、设备或状态图标。

- 原生尺寸 `48×42px`；
- 调用方必须同时传入纹理及源图宽高，组件在可视区内保持比例缩放，不变形拉伸；
- 外壳受环境光影响，图标内容自发光并轻微频闪；
- 图标切换时按 `2×2` 逻辑像素，从上到下、从左到右扫描更新；
- 空槽必须调用 `renderEmpty`，这会同时重置该槽动画状态。

```java
IconMonitor.Icon icon = new IconMonitor.Icon(texture, sourceWidth, sourceHeight);
monitor.renderAnimated(context, icon, bounds, outward, state);
```

### 3.6 状态灯 `StatusLight`

用途：选择状态、占用状态、运行状态和错误提示。

| 状态 | 语义 | 发光 |
| --- | --- | --- |
| `OFF` | 关闭、空槽、未达到 | 否 |
| `GREEN` | 正常、当前选中 | 是 |
| `YELLOW` | 运行中、已有内容但未选中 | 是 |
| `RED` | 错误 | 是 |

灯体原生尺寸 `8×9px`。标签可为空；提供标签时显示在灯右侧，整个组件保持左对齐。状态灯只表达调用方传入的状态，不自行推断业务含义。

### 3.7 缩微胶卷阅读机 `MicroficheReader`

用途：为长文本和简单图案提供可变尺寸的缩微胶卷显示区域。它本质上是一层显示滤镜：终端只提交有序文字行和图标，组件统一处理排版、投影底色、裁切、频闪和换页动画。

- 内容底色以 `#CDCCAB` 为中心基准色，组件使用五层内嵌色带构成边缘暗、中心亮的投影渐层；
- 整个投影填色区域共用同一组轻微亮度频闪，文字、图标和边框不参与频闪；
- 原始资源只有左上角 `14×16px`、上边 `20×6px` 和左边 `10×10px`，其他方向由组件内部镜像生成；
- 横边以 `20px` 为单位、竖边以 `10px` 为单位按整数像素平铺，末段只裁切，不拉伸像素画；
- 最小外框尺寸为 `28×32px`；小于该尺寸会拒绝绘制；
- `contentBounds(...)` 返回扣除左右 `10px`、上下 `6px` 后的内容矩形，文本和图标始终裁切在该区域内；
- `Content` 包含有序 `TextLine` 和相对内容区定位的 `SimpleIcon`；文字样式会被剥离并固定显示为黑色，图标保留贴图原色；
- 文字排版由组件固定为左边距 `2px`、上边距 `2px`、`0.65×` 字号和 `8px` 行进间距；调用方只决定文字行顺序，不得为单行另设坐标、缩放或行距；
- 内容变化时执行 `350ms` 下滑切换：旧页向下退出，新页同步从内容区上方滑入，动画结束后只保留新页；
- 图标在目标矩形中保持原始宽高比，滑动过程中的越界部分按纹理 UV 裁切；
- 图框、填色和黑色内容均使用环境光，不具有自发光语义；
- 同时提供普通 GUI 与世界表面渲染入口，调用方不得自行拼接边框、滤镜颜色、频闪或换页动画。

内部职责固定分为三层：`MicroficheReader` 只管理内容、投影底色和换页状态；`MicroficheFrameRenderer` 只管理图框资源、镜像和平铺；图标的等比适配、UV 裁切、GUI 着色复位及世界表面纹理绘制统一复用 `InstrumentTextureRenderer`。其他仪表若需要裁切纹理，不得再复制这一套渲染代码。

```java
MicroficheReader reader = new MicroficheReader();
MicroficheReader.AnimationState animation = reader.createAnimationState();
MicroficheReader.Content page = new MicroficheReader.Content(
    List.of(
        new MicroficheReader.TextLine("ARCHIVE 01"),
        new MicroficheReader.TextLine("LONG TEXT...")),
    List.of(new MicroficheReader.SimpleIcon(
        iconTexture, 16, 16, new SurfaceRect(140, 4, 20, 20))));
reader.renderAnimated(context, page,
    new SurfaceRect(16, 12, 180, 96),
    WorldUiRenderLayers.CONTENT, animation);
```

每个独立阅读机必须持有自己的 `AnimationState`，正式终端通过 `InstrumentStateCache` 按控制器隔离状态。调用方把长文本拆为有序 `TextLine`，组件按固定行距依次排布；自动换行、滚动和复杂矢量图形不属于该组件。

### 3.8 全息投影 `HolographicProjection`

用途：在世界中直接显示完整货柜微缩模型。它不把三维模型投影或压缩到二维画布，而是由一个实体底座建立世界坐标基点，并在底座上方逐块渲染服务端同步的 `CargoStructurePreviewSnapshot`。

- 底座使用原生 `3×1×3 MCpx` 方块模型，按原尺寸绘制，不做九宫格拼接；
- `baseCenter` 表示底座在方块实体局部坐标中的底面中心；货柜底面中心自动与底座中心对齐；
- `Settings.modelScale` 控制每个货柜方块在世界中的缩放尺寸，必须为有限正数；
- `Settings.modelHeight` 控制货柜底面到投影底座顶面的净高度，单位为方块，必须为有限非负数；
- 货柜保持完整 X／Y／Z 深度和直立姿态，玩家可以通过移动世界视角观察其不同侧面；组件不再应用 GUI 预览使用的 28°／45° 固定观察角；
- 底座使用环境光并保持稳定；货柜模型使用公共 `InstrumentFlicker` 生成的近全亮动态光级产生轻微频闪；
- 无快照或空快照时仍显示底座，但不绘制占位模型或文字；
- 该组件是世界空间三维仪表，不提供普通 GUI 渲染目标。普通 GUI 中既有的货柜预览仍使用 `CargoStructurePreview`，两者共享同一服务端快照而不共享坐标变换。

```java
HolographicProjection projection = new HolographicProjection(
    InstrumentInfo.localized("container_preview"));
projection.render(cargoPreviewSnapshot, blockState, poseStack, buffers,
    packedLight, packedOverlay, renderOrigin,
    new Vec3(0.5D, 1.0D, 0.25D),
    new HolographicProjection.Settings(0.04F, 0.10D));
```

### 3.9 圆盘形仪表 `DialMeter`

用途：用连续旋转指针和三位辉光数字同时显示数值，适用于需要表达多个整圈的读数。

- 基座原生尺寸 `126×121px`，指针素材 `15×45px`，运行时资源位于 `textures/gui/instruments/dial_meter/`；基座保留，不由终端自行拆分或重绘；
- 直接传入实际数值，不传 `0..1` 归一化比例；每增加 100 单位顺时针旋转一圈，0／25／50／75 分别朝左／上／右／下；
- 指针按原始数值连续插值，变化用 `250ms` 平滑过渡，跨越整百不会反向绕行；首次显示直接就位，过渡中再次变值从当前角度继续；
- 数显显示目标实际值，四舍五入为整数，正数不足三位补零，不对读数取模；三位槽支持 `-99..999`，超出显示范围时显示 `---`，有限数值的指针仍按实际值旋转；
- `NaN` 或无穷值显示 `---` 并隐藏指针、重置动画；恢复有限数值时直接就位；
- 基座和指针使用环境光，指针绘制在基座及数显的最上层，不被数显面板遮挡；三位数字使用公共辉光频闪和与紧凑型百分比条一致的橙红色 `CargoUiPalette.INSTRUMENT_READOUT`（`#FF7043`），数字中心位于原生 Y=79（较初版下移 1px）；
- 普通 GUI 与世界表面共享角度、读数和动画算法；世界入口使用适配后的实际矩形提供统一悬停反馈。

组件实例和动画缓存创建一次，不能每帧重新创建：

```java
private static final DialMeter DIAL = new DialMeter();
private final InstrumentStateCache<DialMeter.AnimationState> dialAnimations =
    new InstrumentStateCache<>(ignored -> DIAL.createAnimationState());

// 世界表面；animationKey 为当前控制器的稳定标识。
DIAL.renderAnimated(context, value, new SurfaceRect(322, 8, 126, 121),
    WorldUiRenderLayers.CONTENT, dialAnimations.stateFor(animationKey));

// 普通 GUI；guiAnimation 同样应提前创建并持久保留。
DIAL.renderAnimated(graphics, font, value, x, y, 126, 121, guiAnimation);
```

正式终端应通过 `new DialMeter(InstrumentInfo.localized("业务用途"))` 提供已配置翻译的具体用途。默认构造器适合通用预览。开发测试方块右侧已接入该组件：每秒 25 单位在 `0 → 300 → 0` 间往返，24 秒一周期，可观察连续多圈旋转、反向回落和超过 100 的真实读数。

### 3.10 指南针 `Compass`

用途：根据接入的世界方向对齐方位，不接收业务数值、玩家朝向或自定义指针角度。

- 原生外框 `128×122px`；新版 `compass_dial.png` 包含固定外壳及红色指针，`compass_pointer.png` 为独立的 `101×101px` N/E/S/W 刻度盘；运行时资源位于 `textures/gui/instruments/compass/`；
- 红针固定不转，方位刻度盘按安装参考的世界水平方位反向旋转，让 N/E/S/W 始终对应世界的北／东／南／西；世界北为 `-Z`，东为 `+X`；
- 无论水平、竖直或倾斜安装，统一使用虚拟水平罗盘计算，再把结果映射到显示平面，不根据摆放姿态切换投影规则；
- 普通世界固定安装时读数保持稳定；使用方自行读取安装参考和子世界渲染姿态，将计算出的 `Compass.Orientation` 直接传入；随载具转动更新，观察玩家移动或转头不会改变方位；
- GUI 和世界入口都接收同一份 `Compass.Orientation`；省略方位的重载只提供北朝上的静态预览，不会自行查询世界、玩家或 Sable；
- 无数显、辉光或自定义数值接口；外壳、红针和方位刻度均使用环境光，等比适配和准星提示遵守公共仪表规范。

所需输入为 `Compass.Orientation`，其中 `right` 和 `forward` 分别表示虚拟水平罗盘的右方向与前方向，类型均为世界坐标 `Vec3`，必须有限且非零。世界北为 `-Z`，东为 `+X`。外部按水平罗盘准备方向后传入，组件把右方向映射为刻度盘旋转角；右方向因载具翻滚接近竖直时，以前方向保持方位。无需提供玩家朝向、位置或任意业务读数。静态预览可以显式使用 `Compass.Orientation.NORTH_UP`。

```java
private static final Compass COMPASS = new Compass();

// worldRight/worldForward 由当前使用方自行读取或计算。
Compass.Orientation orientation = new Compass.Orientation(worldRight, worldForward);

// GUI 和世界表面共用这份方向数据，不传入业务数值或指针角度。
COMPASS.render(context, orientation, new SurfaceRect(8, 8, 128, 122),
    WorldUiRenderLayers.CONTENT);
COMPASS.render(graphics, orientation, x, y, 128, 122);

// 无方位的重载仅用于北朝上的静态预览。
COMPASS.render(graphics, x, y, 128, 122);
```

蓝色的载具仪表测试方块最左侧已接入指南针。测试宿主自行读取所在结构的插值姿态；可旋转测试方块或所属物理结构，检查刻度盘反向转动、红针固定以及观察者转头时显示稳定。普通方块状态仍显示静态世界方位。

### 3.11 姿态仪 `AttitudeIndicator`

用途：显示横滚和俯仰姿态，由使用仪表的地方直接提供角度，组件只绘制天地、刻度和姿态指针及其动画。

| 输入 | 单位与约定 | 边界 |
| --- | --- | --- |
| `rollDegrees` | 度，正值为右倾，负值为左倾，0 为水平 | 每 360° 环绕；动画跨 ±180° 走最短路径 |
| `pitchDegrees` | 度，正值为抬头，负值为低头，0 为水平 | 限定在 `-90..90`；宿主负责把自身坐标及符号转换到这一约定 |

- 原生外框 `128×122px`；使用 `attitude_frame.png`、`scale.png`（`102×73px`）和 `pointer.png`（`102×16px`），运行时资源位于 `textures/gui/instruments/attitude_indicator/`；
- 蓝天和棕地由程序绘制，使用圆形原生像素遮罩，边缘被外框覆盖；不会把倾斜的矩形填充暴露到表盘之外；
- 水平时天地分界位于表心；每度俯仰对应 `1.5px`，抬头使地平线下移、蓝天增多，低头则相反；
- 天地、地平线与俯仰刻度按横滚角的反方向旋转；填充中绘制 5° 短刻度、10° 长刻度；原始刻度层只跟随横滚转动；
- 表盘框和姿态指针固定，指针位于最上层；填充、原始刻度及外壳均使用环境光，没有自发光内容；
- `render(...)` 直接显示输入；`renderAnimated(...)` 使用独立 `AnimationState` 做 `250ms` 平滑变化，首次直接就位，中途变值从当前状态继续；
- 任一角度为 `NaN` 或无穷值时，窗口显示深色无数据底，不绘制有效天地、俯仰或横滚刻度，保留外框及固定姿态指针；动画状态重置，恢复有效输入后直接就位；
- GUI 和世界表面共用天地几何、数值约定和动画状态实现。组件不获取 Sable 参数、玩家状态或方块实体数据；普通方块也可以接收测试样例。

```java
private static final AttitudeIndicator ATTITUDE = new AttitudeIndicator();
private final InstrumentStateCache<AttitudeIndicator.AnimationState> animations =
    new InstrumentStateCache<>(ignored -> ATTITUDE.createAnimationState());

// rollDegrees / pitchDegrees 由使用方获得，单位为度，依照上表转换符号。
ATTITUDE.renderAnimated(context, rollDegrees, pitchDegrees,
    new SurfaceRect(144, 8, 128, 122), WorldUiRenderLayers.CONTENT,
    animations.stateFor(controllerKey));

// GUI 使用相同两个输入；guiAnimation 在绘制循环之外创建并保留。
ATTITUDE.renderAnimated(graphics, rollDegrees, pitchDegrees,
    x, y, 128, 122, guiAnimation);
```

该组件已移至载具仪表测试方块中间。宿主按自身安装朝向，将 Sable 客户端插值姿态转换为横滚与俯仰，直接调用 `render`，避免再次平滑导致延迟；未属于物理结构时传入无数据。正式使用方应按实际数据更新节奏选择直接绘制或平滑绘制，不在组件内部新增统一物理接入层。

### 3.12 垂直速度表 `VerticalSpeedIndicator`

用途：区分上升和下降，并显示垂直速度绝对值。

| 输入 | 单位、方向与范围 |
| --- | --- |
| `verticalSpeed` | m/s；正数为上升、负数为下降、0 为无垂直运动。使用方自行获得数据并换算单位；仪表不读取 Sable 或玩家状态。 |

- 原生尺寸 `128×122px`，运行时目录 `textures/gui/instruments/vertical_speed_indicator/`；表盘、`15×45px` 指针及两个 `22×18px` 箭头为四张独立素材，表盘中已有两位翻牌槽框；
- 当前输入为正时只显示蓝色上升箭头，为负时只显示红色下降箭头；零速（包括负零）和非有限输入均隐藏两个箭头。方向直接使用当前输入，不依赖数字取整或指针平滑结果，反向时立即切换；
- 指针只走右侧 180° 半圆，0 朝右、+25 右上、+50 朝上、-25 右下、-50 朝下；独立钳制在 ±50，超出后保持对应端点；
- 数显为绝对速度四舍五入后的两位整数，不足两位补零，独立钳制到 99。例如输入 `75` 或 `-75`，数显均为 `75`，指针分别停在上端和下端；输入 `±120` 时数显为 `99`；
- 直接复用 `SplitFlapDisplay` 字符动画和 `SplitFlapFrameRenderer`，只在素材已有槽位中绘制数字，不重绘或叠加翻牌外框；
- `renderAnimated(...)` 同时启用公共翻牌动画和 250ms 指针平滑过渡，正负反向时指针经过零位，状态按仪表实例独立保留；
- 指针始终最后绘制，世界表面层级高于数字，GUI 位于公共翻牌字符层之上；不会被表盘、槽框或数字遮挡；
- `NaN` 或无穷输入显示 `--`，隐藏指针并重置动画；恢复有效速度后直接就位，缺失数据不显示为 0；
- 表盘、数字、蓝色上升箭头、红色下降箭头和指针均受环境光影响，没有辉光数显或额外方向标签。

```java
private static final VerticalSpeedIndicator VERTICAL_SPEED = new VerticalSpeedIndicator();
private final InstrumentStateCache<VerticalSpeedIndicator.AnimationState> animations =
    new InstrumentStateCache<>(ignored -> VERTICAL_SPEED.createAnimationState());

// verticalSpeed 由使用方获得，单位 m/s，向上为正。
VERTICAL_SPEED.renderAnimated(context, verticalSpeed,
    new SurfaceRect(280, 8, 128, 122), WorldUiRenderLayers.CONTENT,
    animations.stateFor(controllerKey));

// GUI 使用相同输入；guiAnimation 提前创建并保留。
VERTICAL_SPEED.renderAnimated(graphics, font, verticalSpeed,
    x, y, 128, 122, guiAnimation);
```

载具仪表测试方块在姿态仪右侧提供该组件。测试方块在服务端直接读取所属结构的真实世界线速度，每 4 tick 检查一次，并在向量变化至少 0.01 m/s、可用性改变或水平静止／运动状态切换时同步到客户端；该表只使用 Y 分量。仪表复用翻牌及指针动画；无物理结构时显示 `--` 并隐藏指针。组件仍不获取任何 Sable 参数。

### 3.13 航迹偏差仪 `TrackDeviationIndicator`

用途：显示载具的实际水平运动方向相对船头的偏差，观察高速转弯时的漂移；不是指南针，不显示玩家视角或世界北向。

输入 `deviationDegrees`，单位度，顺时针／右侧为正：0 向前，+90 向右横移，-90 向左横移，±180 倒退。有限角度按 360° 环绕，并以较小夹角显示白色填充。使用方自行从船头方向和实际运动方向计算该角度，组件不获取 Sable、世界或玩家数据。

- 原生 `128×122px`；资源目录 `textures/gui/instruments/track_deviation_indicator/`，包含表盘、独立 `15×51px` 指针和 `21×34px` 载具图标；
- 红色船头线固定朝表盘上方，动态指针围绕表盘中心转动；白色扇区显示两者之间不超过 180° 的偏差，向前对齐时无扇区；
- 填充限制在内部圆形区域，不覆盖固定红线和外围刻度；GUI 与世界表面使用相同像素几何；
- 绘制层级为表盘 → 白色扇区 → 动态指针 → 固定载具图标，载具图标始终最上层；所有内容受环境光影响；
- 指针任何情况下均不隐藏：静止、纯垂直运动默认对齐船头线；`NaN` 或无穷输入同样回退为 0°。只有归一化角度恰好为 0° 时隐藏填充，不设置角度死区；
- 直接绘制传入角度，不在内部叠加运动方向采样、坐标映射或额外平滑层。

```java
private static final TrackDeviationIndicator TRACK = new TrackDeviationIndicator();

// deviationDegrees 由宿主计算，右偏为正；静止／无方向时默认 0°。
TRACK.render(context, deviationDegrees,
    new SurfaceRect(416, 8, 128, 122), WorldUiRenderLayers.CONTENT);
TRACK.render(graphics, deviationDegrees, x, y, 128, 122);
```

载具仪表测试方块将该表放在最右侧。宿主读取自身所在结构同步的世界水平线速度，以船头水平投影为参考，计算 `atan2(forwardX * velocityZ - forwardZ * velocityX, forwardX * velocityX + forwardZ * velocityZ)`；结果转换为度。水平静止、船头水平投影接近零或无物理结构时默认 0°。滚转和俯仰不会额外旋转仪表内固定载具图标；速度同步会保留水平静止／运动之间的切换，即使速度变化不足常规同步阈值。

### 3.14 载具仪表数值精度

指南针朝向、姿态仪横滚／俯仰读数与动画目标、航迹偏差角均以 1° 为步长取整；垂直速度表的数显与指针目标以 1 m/s 为步长，对绝对值四舍五入后恢复正负。动画插值仍可使用小数，避免整数目标导致动画失效或反复被细小噪声重启。

只对仪表读数取整，不提前取整宿主的物理速度向量或四元数，否则低速航迹与姿态计算可能失真。方向信息单独保留：垂直速度的上／下箭头继续依据原始输入符号；航迹非零但不足半度的偏差显示为 ±1°，只有原始角度归一化后恰好为 0° 才不绘制扇区。零速和非有限数据仍遵守各组件原有规则。

姿态仪缓存最近一组整数姿态的填充结果；航迹偏差仪按整数角度缓存扇区（最多 361 项，所有实例共用），像素循环使用整数定点判断。重复读数不再每帧重建这些填充形状；缓存不包含世界、载具或方块实体对象。

### 3.15 通用圆盘形仪表 `ClampedDialMeter`（圆盘仪表2）

与 `DialMeter` 分开封装，不改变其每 100 单位转一圈及辉光数显契约。

- 仅接收外部实际数值，单位和数据来源由调用方决定；基座原生 `126×118px`，运行时贴图在 `textures/gui/instruments/clamped_dial_meter/`；
- 指针目标取整并钳制 0～100，对应 -125°～125°，0 在左下、50 向上、100 在右下，不环绕；
- 三位翻牌数显独立取整并钳制 000～999；负数按 0，NaN／无穷显示 `---` 并隐藏指针、重置动画；
- 基座已包含翻牌框，只调用公共翻牌字符绘制与动画，不再叠加第二套框；数字中心为原生 Y=98.5；
- 基座、数字和指针都受环境光影响；数字为公共金色 `CargoUiPalette.ACCENT`，不是旧 `DialMeter` 的橙红辉光数字；
- 指针在最上层；GUI 与世界表面共用数值和布局规则，世界表面提供实际绘制矩形的统一名称提示；
- 指针过渡 250ms；调用方提前保留独立 `AnimationState`，不能让重复安装的两个实例共用状态。

```java
private static final ClampedDialMeter PRESSURE =
    new ClampedDialMeter(InstrumentInfo.localized("vehicle_air_pressure"));

// state 是该基座该槽位的独立状态；调用方将气压系数转换成整数百分比。
PRESSURE.renderAnimated(context, relativePressurePercent, bounds,
    WorldUiRenderLayers.CONTENT, state);
```

通用测试方块右侧以 `0、25、50、75、100、250、999、1200、250、100、50、0` 的每秒序列预览独立钳制；正式气压计模块由基座宿主读取当前位置气压，不由组件获取。

## 4. 终端组合规范

正式终端组件放在 `client.gui.terminal`，推荐结构如下：

```java
public final class ExampleTerminalDisplay {
    private static final SplitFlapDisplay TITLE = new SplitFlapDisplay(
        12, SplitFlapDisplay.Alignment.RIGHT,
        InstrumentInfo.localized("example_title"));
    private static final StatusLight STATUS = new StatusLight(
        InstrumentInfo.localized("example_status"));

    private final InstrumentStateCache<AnimationState> animations =
        new InstrumentStateCache<>(ignored -> new AnimationState());

    public void render(WorldUiRenderContext context, ExampleViewState state) {
        AnimationState animation = this.animations.stateFor(state.animationKey());
        // 只做 surfaceId 分派、数据格式化和矩形排布。
    }
}
```

组合层允许：

- 按 `surfaceId` 分派不同显示面；
- 把业务值格式化为仪表输入；
- 定义固定 `SurfaceRect`、标签和图标描述；
- 选择共享调色板中的语义色。

组合层禁止：

- 复制仪表纹理路径或拼接算法；
- 实现另一套翻转、频闪或扫描动画；
- 直接读取服务端单例或方块实体；
- 绘制公共背景、表面内框或交互命中描边；
- 把整块显示面切换为 emissive。

## 5. 新增仪表流程

1. 确认需求可在至少两个终端复用，而不是单个终端的一次性装饰；
2. 在美术源目录中确定原生尺寸、分片边界和透明区域；
3. 将运行时纹理放入独立的 `textures/gui/instruments/<instrument>/` 目录；
4. 实现普通 GUI 与世界表面两个入口，共享布局与数值算法；
5. 在组件封装中持有 `InstrumentInfo`，并让世界入口以实际绘制范围调用统一瞄准反馈；
6. 明确哪些部分受环境光、哪些部分允许自发光；
7. 有动画时提供独立状态对象，并保证首次显示稳定、切换可中断或收敛；
8. 添加数值边界、动画判定、资源存在性和架构约束测试；
9. 先在仪表测试方块中观察，再接入正式终端；
10. 更新本文档中的组件表、输入范围和视觉约束。

## 6. 组件检查

- [ ] 普通 GUI 与世界表面显示相同内容、比例和状态；
- [ ] 目标矩形变化时保持原生宽高比；
- [ ] NaN、无穷、越界数值和过长文本有确定行为；
- [ ] 多个控制器或同面多个组件不会串用动画状态；
- [ ] GUI 着色在绘制后复位，不污染其他 HUD／Screen 内容；
- [ ] 低光环境中外壳变暗，明确的辉光内容仍可见；
- [ ] 瞄准每个仪表时边框严格贴合实际绘制范围，准星旁显示该实例的具体用途；
- [ ] 相邻或重叠仪表只显示最近目标，打开 Screen、隐藏 HUD 和超距时不残留提示；
- [ ] 组件测试、资源测试、架构测试和终端组合测试通过；
- [ ] 在 Minecraft 客户端检查最终视觉结果，不以自动化测试替代视觉检查。
