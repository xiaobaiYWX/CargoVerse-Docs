# 世界表面 UI 框架

## 定位与边界

World Surface UI 用于把信息和按钮直接绘制在世界中的方块表面。玩家瞄准特殊区域并在世界中交互，不需要先右键打开传统界面。

它不是 `Screen` 的世界渲染分支，也不从 `AbstractContainerScreen`、`AbstractWidget` 或 `AbstractContainerMenu` 继承。传统界面仍可保留；两套界面只允许复用业务服务、展示快照、格式化工具和贴图，不能相互持有 UI 实例。

生产线终端、贸易点信息柜和仓库信息柜负责生产、经济与库存展示；制造台、装载机、卸载机、售货机和注册终端负责具体业务。管理员 GUI 只保留贸易点与定位点绑定等文本配置。`InstrumentTestBlock` 用于独立预览仪表。

## 分层结构

| 层 | 主要类型 | 职责 |
| --- | --- | --- |
| 公共定义 | `WorldUiDefinition`、`WorldUiSurfaceDefinition`、`WorldUiSurfaceKind`、`WorldUiRegion`、`SurfaceRect` | 定义逻辑画布、显示／控制表面职责、区域与服务端动作 ID；注册时拒绝越界、重复和重叠 |
| 公共几何 | `SurfaceAnchor`、`SurfaceTransform`、`SurfaceHit` | 把画布放到任意六向世界平面；世界命中与画布坐标互转 |
| 目标快照 | `WorldUiTargetSnapshot`、`WorldUiController`、`WorldUiPart` | 描述控制器、结构版本、表面几何；多方块成员统一解析到控制器 |
| 公共命中 | `WorldUiHitResolver` | 客户端悬停与服务端执行共用同一套纯命中算法 |
| 客户端绘制 | `WorldUiRenderContext`、`WorldUiRendererRegistry`、`WorldUiWorldRenderer`、`WorldUiSurfaceDecorationRenderer` | 按固定层级执行默认纯色背景、终端内容、公共内框和当前交互区域描边；具体装饰 renderer 不暴露给业务终端 |
| 封装仪表 | `SplitFlapDisplay`、`PercentageMeter`、`DeltaIndicator`、`CompactPercentageBar`、`IconMonitor`、`StatusLight`、`MicroficheReader`、`HolographicProjection`；内部共享 `InstrumentTextureRenderer` 等基础设施 | 封装贴图拼接、数值规范化、动画、比例适配、裁切和发光语义；普通平面仪表支持 GUI 与世界表面，全息投影直接在世界空间绘制完整三维结构；终端不得复制公共仪表或货柜微缩渲染流程 |
| 交互控件 | `WorldUiButtonInstance`、`WorldUiButtonModelFrame`、`WorldUiSliderInstance`、`WorldUiSliderModelFrame`、`WorldUiButtonSet`、`WorldUiSliderSet` | 组件实例统一声明模型参考坐标、命中面、细高亮、动画和服务端动作；按钮不承载通用输入，滑轨只提交预定义范围内数值 |
| 终端组合 | `client.gui.terminal` 下的 `*Display` | 只负责把展示快照映射为仪表、图标、文本与布局，不复制仪表内部渲染算法 |
| 服务端动作 | `WorldUiActionRegistry`、`WorldUiInteractionService` | 重新检查方块、距离、区块、结构、表面和动作区域后调用服务端 handler |

源码根目录分别为：

```text
cn/or15/cargoverse/worldui/
cn/or15/cargoverse/worldui/action/
cn/or15/cargoverse/client/worldui/
cn/or15/cargoverse/client/gui/instrument/
cn/or15/cargoverse/client/gui/terminal/
```

## 定义规则

定义由代码显式注册，不由数据包注入可执行动作。每个定义至少有一个表面；每个表面使用固定逻辑画布尺寸，最大单边为 4096。交互区域采用左上包含、右下不包含的半开矩形，因此两个相邻按钮可以共享边界而不会同时命中。

所有表面必须通过 `WorldUiSurfaceDefinition.display(...)` 或 `WorldUiSurfaceDefinition.control(...)` 明确职责，不再提供会隐式推断类型的构造方式。框架用无贴图色块填充纯色 `#333333` 背景。终端内容绘制完成后，再使用 `corner.png` 与 `side.png` 沿画布边界向内自动拼接 8px 内框。四个角块通过 90° 旋转复用，每条边只绘制一张边段并沿边长拉伸，不做平铺。模型上的独立按钮面声明为 `CONTROL`，从而不填充显示背景、也不套用屏幕内框。表面职责与是否包含 `WorldUiRegion` 分离，因此触摸屏可以同时拥有默认显示样式和交互区域。

同一表面内禁止：

- 重复的 `elementId`；
- 超出画布的区域；
- 面积重叠的交互区域；
- 未明确指向 `ResourceLocation actionId` 的按钮。

示例仅表示注册方式，不是已接入的终端：

```java
var definition = new WorldUiDefinition(
    ResourceLocation.parse("cargoverse:example_terminal"),
    List.of(WorldUiSurfaceDefinition.display("main", 256, 128, List.of(
        new WorldUiRegion("confirm", new SurfaceRect(184, 96, 56, 20),
            ResourceLocation.parse("cargoverse:example_confirm"))
    )))
);
WorldUiDefinitionRegistry.GLOBAL.register(definition);
```

## 表面坐标

`SurfaceAnchor` 使用以下约定：

- `origin`：画布左上角的绝对世界坐标；
- `right`：画布 X 正方向的单位向量；
- `down`：画布 Y 正方向的单位向量；
- `normal`：朝向玩家的表面法线；
- 必须满足 `right × down = normal`；
- `worldWidth/worldHeight`：实际世界尺寸；
- `canvasWidth/canvasHeight`：逻辑画布尺寸；
- `interactionFace`：允许点击的方块面，必须与法线一致。

构造时会拒绝非有限数值、非单位向量、非正交坐标和错误手性。自动化测试覆盖上下、南北、东西六个方向；相同逻辑坐标在各方向均映射到相同画布位置。

客户端绘制调用方还需传入其渲染器的 `renderOrigin`。框架会将绝对世界坐标转换为当前 `PoseStack` 的局部坐标，因此表面不要求位于控制器方块自身，也可跨越多方块墙。

## 无界面交互与安全边界

方块接入 `WorldUiInteractionService.dispatch` 后，服务端按以下顺序处理：

1. 点击结果必须对应实际点击的结构成员方块；
2. 点击成员与控制器区块必须已加载，检查不得强制加载新区块；
3. 玩家到实际命中点必须在允许距离内；
4. 成员通过 `WorldUiPart` 解析控制器；
5. 控制器方块实体必须实现 `WorldUiController`，且结构仍然有效；
6. 控制器位置、定义 ID、表面 ID、画布尺寸和当前几何快照必须一致；
7. 服务端从玩家眼睛和视线重新发射射线并计算画布坐标，不接受客户端提交的按钮 ID 或画布坐标；
8. 命中注册区域后，按其 `actionId` 调用该按钮明确绑定的服务端 handler；按钮层没有通用输入值；
9. handler 仍需检查库存、权限、冷却、所有权和具体业务状态；
10. 只要命中已注册的 `WorldUiRegion` 就统一播放一次原版 UI 按钮声；若同时属于封装按钮，还会向跟踪控制器区块的客户端广播一次不携带业务输入的短按压反馈。业务成功或失败都不返回操作栏文字，也不改变反馈。点偏、只命中非交互显示面时不播放。

客户端 `WorldUiHoverResolver` 只预测准星反馈，不具备业务权威。`WorldUiWorldRenderer` 使用该结果调用统一描边层；终端 renderer 不得自行保存 `hoveredSurface`、重复解析射线或临时绘制按钮边框。

## 世界绘制入口

`WorldUiRenderContext` 当前提供：

- 按逻辑画布矩形绘制带裁剪的世界贴图；
- 用无贴图世界四边形填充颜色，供默认背景和终端内容色块使用；
- 按 90° 步进旋转世界贴图，供公共角块和边段复用；
- ARGB 着色；
- 按画布像素比例绘制 Minecraft 字体；
- 不传颜色时使用与普通 GUI 相同的默认正文色 `#EBD8B5`；标题、警告和状态色仍由终端显式指定；
- 画布点到当前渲染局部坐标的转换；
- 当前 `surfaceId`、画布尺寸和 `SurfaceAnchor` 查询。

公共颜色统一放在 `CargoUiPalette`，Z 层级统一放在 `WorldUiRenderLayers`。业务 renderer 不得直接复制普通背景、正文色、边框层级或悬停色的数值；只有终端特有的语义色才允许新增到共享调色板。`fillCanvas` 用于整面色块，`canvasBounds` 用于需要完整画布范围的布局计算。

公共定义和动作只在 `WorldUiBootstrap` 注册，客户端内容 renderer 只在 `WorldUiClientBootstrap` 注册。方块、方块实体和 renderer 构造器不得产生注册副作用。终端 renderer 按定义 ID 注册到 `WorldUiRendererRegistry`，接收不可变的终端专用 `WorldUiViewState`，并使用 `WorldUiWorldRenderer.render(target, state, ...)` 标准入口；显式传入全局 registry 的重载只保留给隔离测试和自定义 registry。状态类型在运行时校验，错误类型不会被静默强转；状态 revision 与目标几何 revision 不一致时本帧不绘制。`WorldUiWorldRenderer` 负责逐表面检查定义／锚点画布一致性，随后通过唯一装饰管线按“`DISPLAY` 默认背景 → 终端内容 → `DISPLAY` 公共内框 → 封装按钮按压脉冲 → 当前交互区域描边”的顺序绘制。终端 renderer 不得重复填充默认背景，也不得自行拼接这两类框线。

框架为正式世界表面终端及开发仪表测试方块注册 renderer，但不全局遍历世界方块。每个终端由控制器方块实体 renderer 调用公共入口，避免逐帧扫描世界。

### 开发用仪表测试方块

早期五个 `world_ui_test_screen_*` 已完成分辨率选型并清理。当前 `InstrumentTestBlock` 是临时开发设施：它提供一块可扩展到方块轮廓之外的显示媒介，用于同时预览所有封装仪表，不代表正式终端的物理尺寸、排布或数据同步方式。测试方块是实心结构，主显示面从朝向外侧的相邻位置采样环境光，顶部按钮和滑轨从上方相邻位置采样；不得直接使用控制器方块内部光照，也不得用全亮掩盖采样错误。

### 光照与发光边界

- `WorldUiRenderContext` 的普通贴图、文字与色块使用方块实体 renderer 传入的环境光；
- 仪表外壳、翻转牌、百分比柱体、指针和普通标签默认受环境光影响；
- 缩微胶卷阅读机的图框、由边暗向中心亮的 `#CDCCAB` 投影底色、黑色文字和原色图标均使用环境光，不具有自发光内容；频闪只作用于整个投影填色区域；
- 全息投影底座使用环境光，悬浮的完整三维货柜使用近全亮动态光级，只有货柜模型参与轻微频闪；
- 图标监视器的图标、紧凑型进度条的辉光数字、非 `OFF` 状态灯是当前允许的自发光内容；
- 发光必须由封装仪表内部显式调用 `drawEmissive*`，终端组合层不得为了“看得更清楚”把整面切成全亮。

### 分辨率选型约束

正式表面统一按 MCpx 密度选型：普通终端默认使用 8 逻辑像素／MCpx（单方块为 128×128）；近距离精细内容使用 16 px／MCpx（256×256）；大字体状态显示使用 4 px／MCpx（64×64）；多方块大型信息展示使用 1 px／MCpx（16×16）。32×32 仅保留为开发测试档。

多方块表面必须先按完整物理显示区域计算统一逻辑画布。例如 `40×19 MCpx` 的普通终端画布为 `320×152`，不能为结构中的每个方块分别创建 128×128 画布后再由终端临时拼接。

## 终端接入

生产线终端已经验证以下接入路径：

- 多方块结构成员、控制器与各显示／按钮表面的相对布局；
- 终端专用定义、不可变展示状态和 renderer；
- 服务端动作 handler 与业务服务调用；
- 必要的服务端到客户端状态同步和 revision 失效策略；
- 准星命中任意交互区时由框架统一描边，正确按键由框架统一播放声音；
- 主屏和五槽位副屏由框架自动拼接公共内框，五个实体按钮面显式标记为 `CONTROL`；
- 结构缺失、旋转、舰船／子世界坐标和控制器卸载时的退化行为。

贸易点信息柜进一步验证了同一框架中的多显示面与仪表组合：

- 摘要面组合倒计时翻转牌、活跃度增减指示器和当日贸易额翻转牌；
- 名称面显示绑定贸易点定义的 `display`；
- 繁荣度面组合六个图标监视器与状态灯，未达到等级不显示图标，当前等级显示绿色状态灯；
- 管理员传统 GUI 仍只承担 UUID 绑定等维护输入。

仓库信息柜验证了大尺寸单显示面与库存快照组合：

- 方块结构为横向三格、纵向两格、约半格厚，以下层中间方块为控制器并由一个方块实体 renderer 绘制完整模型；
- 2×2 库存区域组成一个 256×256 逻辑画布，不额外绘制贸易点标题牌或底部分页牌；
- 输入和输出库存各自独立分页，每页四项；左列上下按钮控制 Input 上一页／下一页，右列上下按钮控制 Output 上一页／下一页；
- 侧栏使用一个不填充背景、不添加公共内框的 `OVERLAY` 表面，在模型预留窗口中分别绘制 Output 和 Input 页码；
- 每项组合 CargoGood 图标监视器、名称／数量翻转牌和库存占比进度条，不在终端内重复仪表算法；
- 服务端每秒刷新一次最多 64 项的排序快照，只有展示内容变化时才推进 UI revision 并同步客户端；
- 四个翻页按钮优先经过公共世界 UI 命中与服务端动作链路；只有没有命中按钮时，CargoVerse 管理员右键结构成员才打开传统 UUID 输入框，退出自动保存；服务端重新检查管理员模式、距离和控制器类型。

货柜装载机与货物卸载机使用透明 `OVERLAY`、斜面板、动态滑轨和服务端交易服务，管理员界面保存贸易点 UUID 与多个定位点 ID。制造台与注册终端绑定单一生成点；注册终端的四按钮和微缩胶片投影也使用公共组件。
