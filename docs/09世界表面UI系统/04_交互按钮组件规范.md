# 交互控件组件规范

## 1. 当前边界

交互按钮组件只表达“哪个按钮被按下，以及调用哪个明确的服务端动作”。它仍不承担通用数据输入协议，也没有步长、通道、选择值或任意客户端参数。

普通按钮与带文字大按钮适合翻页、确认、启动、停止等瞬时动作；钮子开关适合启用／停用等保持型布尔状态。按钮文字只是短标签，不构成文本输入。滑轨是独立组件，只接受组件实例预先声明的最小值、最大值和步进，不会把任意动作或文本交给客户端。UUID、自由文本和复杂配置继续使用传统 GUI。

## 2. 唯一按钮链路

```text
WorldUiButtonComponent（可复用按钮组件）
        ├─ 模型资源、命中尺寸与局部按压方向
        ├─ WorldUiButtonModelFrame：模型参考点、局部三轴、交互面高度与高亮间隙
        ├─ 按下／弹起时序和模型行程
        └─ 创建 WorldUiButtonInstance
                         ↓
WorldUiButtonInstance（终端中的具名组件实例）
        ├─ 唯一按钮 ID
        ├─ place(...) 从模型参考中心生成 CONTROL SurfaceAnchor
        ├─ 同一锚点驱动 renderer、服务端命中和客户端细高亮
        └─ 向 WorldUiButtonSet 安装动作的唯一业务入口
                         ↓
WorldUiButtonSet（底层声明与注册）
        ├─ actionId
        ├─ 明确的服务端 ButtonHandler
        └─ WorldUiButtonAnimationSpec
                         ↓
WorldUiInteractionService（服务端重新发射射线并解析命中）
        ├─ 执行该按钮绑定的 handler
        ├─ 播放统一按钮声
        └─ 广播 WorldUiButtonPressPacket（仅按钮键）
                         ↓
客户端瞬时反馈
        ├─ WorldUiButtonPressRenderer：区域短脉冲
        ├─ WorldUiButtonComponentRenderer：普通按钮按下并弹起
        ├─ WorldUiLargeButtonComponentRenderer：颜色模型和顶面文字同步下压
        └─ WorldUiToggleComponentRenderer：底座静止、拨杆按状态旋转
```

`WorldUiRegion` 与 `WorldUiButtonSet` 仍是底层类型，但新终端不得直接拼接实体按钮的模型、尺寸、命中或高亮。正式实体按钮先创建 `WorldUiButtonInstance`，再通过实例的 `install(...)`、`place(...)` 和客户端 renderer 复用同一份 ID、尺寸、模型框与动画数据。底层 `Builder.button(...)` 已限制为按钮包内部可见。显示面内没有独立模型的触摸区域仍可直接通过按钮集声明。

## 3. 声明实体按钮

终端选择组件并传入按钮 ID、业务动作 ID 与明确的服务端回调：

```java
private static final WorldUiButtonInstance CONFIRM_BUTTON =
    WorldUiButtonComponents.NORMAL.instance("confirm",
        WorldUiButtonDirection.RIGHT);

private static WorldUiButtonSet<MyController> createButtons() {
    var builder = WorldUiButtonSet.builder(DEFINITION_ID, MyController.class);
    CONFIRM_BUTTON.install(builder, CONFIRM_ACTION,
        (context, controller) -> controller.confirm());
    return builder.build();
}
```

`install(...)` 自动使用组件内置画布、动画规格并建立覆盖整个按钮画布的 `CONTROL` 表面。终端放置实体按钮时调用同一实例的 `place(...)`，只传模型参考中心、表面右／下／法线和交互面，无需再次填写按钮 ID、尺寸或高亮偏移。

## 4. 组件同源定位与细高亮

`WorldUiButtonModelFrame` 属于组件，不属于终端。它保存模型源文件中的参考中心、局部 `right/down/normal`、模型顶面到交互面的距离，以及高亮离模型表面的安全间隙。`WorldUiButtonPlacement` 用终端提供的模型参考中心创建 `SurfaceAnchor`；`WorldUiButtonPlacementTransform` 再从该锚点反推完全相同的模型姿态。

因此同一个按钮只有一个空间事实来源：

```text
终端模型参考中心 + 面板三轴
            ↓
组件 ModelFrame + instance.place(...)
            ↓
SurfaceAnchor
  ├─ 服务端射线命中
  ├─ 客户端悬停细边框
  └─ renderer 反推模型姿态与按压动画
```

终端可以调整按钮的模型参考中心以贴合面板，但不能再增加独立命中中心、渲染平移或高亮 Z 偏移。若模型顶面仍盖住边框，应修正组件 `ModelFrame` 的交互高度／高亮间隙，或修正终端传入的模型参考中心；不能只移动边框。

滑轨采用同样原则。`WorldUiSliderInstance.place(...)` 以轨道模型原点、当前服务端值和 `WorldUiSliderModelFrame` 算出移动滑块的当前锚点；轨道／滑块 renderer 从该锚点反推模型原点，所以滑块数值、模型、命中和高亮始终共用一条链路。

启动注册仍由定义统一完成：

```java
List<WorldUiSurfaceDefinition> surfaces = new ArrayList<>();
surfaces.add(WorldUiSurfaceDefinition.display("main", 256, 160));
surfaces.addAll(BUTTONS.surfaces());
WorldUiDefinitionRegistry.GLOBAL.register(
    new WorldUiDefinition(DEFINITION_ID, surfaces));
BUTTONS.register();
```

## 5. 普通按钮

`WorldUiButtonComponents.NORMAL` 是第一种正式封装按钮：

- 模型与贴图：`block/world_ui/button/normal`；
- 按键帽尺寸：3×2 MCpx，高 1 MCpx；
- 命中画布：3×2；
- 局部按压方向：`-Y`；
- 按下时间：0.04 秒；
- 弹起时间：0.08 秒；
- 行程：1 MCpx；
- 状态：瞬时，不写入方块实体，动画结束自动复位。
- 箭头方向：实例传入 `UP`、`RIGHT`、`DOWN`、`LEFT`，方向基于按钮局部顶视布局，不是世界绝对方位；
- 旋转中心：模型坐标 `(8,0,8)` MCpx；
- 水平箭头：模型旋转后命中尺寸自动由 3×2 交换为 2×3，并保持中心位置不变。

通用小按钮贴图以向上箭头为原始方向，只注册一套模型。组件 renderer 根据实例方向旋转整个按钮，所以终端不应为四个方向复制模型或贴图。终端整体转向时，箭头随终端局部坐标一起转动。

组件模型由 `WorldUiButtonComponents.modelLocations()` 在客户端统一注册。新增组件不再向 `CargoVerseClient` 添加单独模型常量。

## 6. 钮子开关

`WorldUiButtonComponents.TOGGLE_SWITCH` 是保持状态的两段式组件：

- 底座模型：`block/world_ui/button/toggle_switch/base`；
- 拨杆模型：`block/world_ui/button/toggle_switch/handle`；
- 底座与命中尺寸：2×4 MCpx；
- 模型初始角度：X 轴 `-22.5°`；
- 开启角度：X 轴 `+22.5°`；
- 枢点：模型坐标 `(8, 1, 9)` MCpx；
- 状态切换插值：0.15 秒；
- 状态所有权：服务端业务控制器，必须保存并同步布尔状态。

组件实例仍只负责按钮 ID、命中、动作注册和渲染参数。具体设备决定布尔值存在哪里，以及是否允许玩家切换：

```java
private static final WorldUiToggleInstance POWER_SWITCH =
    WorldUiButtonComponents.TOGGLE_SWITCH.instance("power_switch");

POWER_SWITCH.install(builder, POWER_SWITCH_ACTION,
    (context, controller) -> controller.togglePower()
        ? WorldUiActionResult.success()
        : WorldUiActionResult.rejected());
```

客户端渲染时传入服务端已同步的当前状态：

```java
WorldUiToggleComponentRenderer.render(POWER_SWITCH, controller.powered(),
    level, DEFINITION_ID, controllerPos, referenceState,
    poseStack, bufferSource, light);
```

第一次看见组件时直接采用当前状态角度；只有之后的状态变化才播放旋转，避免区块加载时从错误位置扫过。组件模型以关闭角度导出，因此 renderer 围绕同一枢点追加 `0°..45°` 旋转。拨杆角度只用于表现，实际状态不能从客户端动画倒推。

## 7. 四颜色带文字大按钮

`WorldUiButtonComponents.LARGE_BUTTON` 是 4×3×1 MCpx 的自动复位按钮。实例必须选择 `GREY`、`GREEN`、`YELLOW`、`RED` 四种颜色之一，并传入一个非空短标签：

```java
private static final WorldUiLargeButtonInstance START_BUTTON =
    WorldUiButtonComponents.LARGE_BUTTON.instance("start",
        WorldUiLargeButtonColor.GREEN, Component.literal("启动"));

START_BUTTON.install(builder, START_ACTION,
    (context, controller) -> controller.start()
        ? WorldUiActionResult.success()
        : WorldUiActionResult.rejected());
```

组件特性：

- 模型目录：`block/world_ui/button/large_button`；
- 尺寸与命中画布：4×3 MCpx；
- 颜色：灰、绿、黄、红，均使用原始 16×16 贴图；
- 文字：普通 `Component`，最多 16 个 Unicode 码点；
- 文字区域：按钮顶面中央 3.5×2 MCpx；
- 排版：水平、垂直居中，按实际字体宽度自动等比缩小；
- 光照：与按钮模型相同，使用场景 `packedLight`，不自发光；
- 动画：0.04 秒按下、0.08 秒弹起、1 MCpx 行程，文字和按键帽同步移动。

客户端 renderer 需要额外传入字体：

```java
WorldUiLargeButtonComponentRenderer.render(START_BUTTON,
    level, DEFINITION_ID, controllerPos, referenceState,
    poseStack, bufferSource, font, light);
```

颜色和标签属于组件实例的静态配置，不能由客户端点击包提交。需要动态改字或动态改色时，应由服务端状态决定并创建明确的视图配置，不能把任意文本作为交互参数回传。

## 8. 声明显示面触摸区域

同一显示面内的触摸按钮没有独立实体模型，使用底层 `region(...)`，但仍走相同的可信动作和反馈链路：

```java
private static final WorldUiButtonSet<MyController> BUTTONS =
    WorldUiButtonSet.builder(DEFINITION_ID, MyController.class)
        .region("main", 256, 160, "confirm",
            new SurfaceRect(184, 124, 56, 20), CONFIRM_ACTION,
            (context, controller) -> controller.confirm())
        .build();
```

显示面仍获得默认背景和公共内框，触摸区域获得与实体按钮相同的悬停描边、按钮声和按压脉冲。重复元素、重复动作、越界区域、区域重叠，以及 CONTROL 表面与同名显示区域混用都会在构建或定义注册时拒绝。

## 9. 服务端职责

按钮 handler 接收 `WorldUiActionContext` 和已经验证类型的控制器：

```java
(context, controller) -> {
    if (!controller.canOperate(context.player())) {
        return WorldUiActionResult.rejected();
    }
    return controller.performAction()
        ? WorldUiActionResult.success()
        : WorldUiActionResult.rejected();
}
```

框架负责重新检查方块、距离、区块、结构和射线命中；handler 仍负责权限、所有权、库存、冷却及业务状态。客户端不会提交按钮 ID、动作 ID 或业务参数，反馈包只包含服务端已经解析出的按钮位置键。

声音和动画表达“玩家正确按中了按钮”，不是业务成功提示。因此业务状态暂时不允许操作时，只要服务端确实重新命中按钮，仍会播放声音和按压动画；业务结果不会额外发送操作栏文字。

## 10. 自动复位动画

`WorldUiButtonAnimationSpec` 定义按下时长、回弹时长和模型行程。普通按钮采用按下 0.04 秒、弹起 0.08 秒和 1 MCpx 行程。

服务端不保存 `pressed` 状态，只广播一次已经确认命中的按钮键。客户端以本地时间计算按下—弹起曲线，到达总时长后从有上限的瞬时缓存中移除，因此按钮必然自动回到静止位置，不需要复位包或方块实体 tick。

## 11. 组件模型渲染

终端 renderer 只遍历已经声明的组件实例：

```java
for (var button : PHYSICAL_BUTTONS) {
    WorldUiButtonComponentRenderer.render(button, level, DEFINITION_ID,
        controllerPos, referenceState, poseStack, bufferSource, light);
}
```

组件 renderer 会加载组件自己的模型，读取组件自己的局部按压方向，并从注册规格读取行程。调用方不再直接调用 `WorldUiButtonModelAnimation`，也不维护按钮模型数组。

普通按钮与大按钮只提供局部直线位移；大按钮额外让文字共用同一按压变换。钮子开关使用独立的保持状态旋转 renderer。带骨骼动画、三挡开关或持续状态动画应建立新的组件类型，不能塞进现有组件的 handler。

## 12. 按住拖动滑轨

`WorldUiSliderComponents.HORIZONTAL` 将轨道模型、滑块模型、移动行程、命中面、范围换算、数值标签和拖动会话封装为一个控件。轨道按实例传入的 MCpx 长度只沿 X 轴伸缩，滑块保持 1×2.5 MCpx 原始比例，并在两端各保留 1 MCpx 边距。

```java
private static final WorldUiSliderInstance VOLUME =
    WorldUiSliderComponents.HORIZONTAL.instance(
        "volume", 16.0D, 0.0D, 100.0D, 1.0D);

VOLUME.install(builder, VOLUME_ACTION,
    MyController::volume,
    (player, controller, value) -> controller.setVolume(value));
```

实例参数依次为滑轨 ID、轨道长度、最小值、最大值和步进。范围必须能被步进完整划分；组件会把输入限制到范围内并量化。渲染时传入服务端已经同步的当前值，组件在滑块上方绘制按步进精度格式化的数值：

```java
WorldUiSliderComponentRenderer.render(VOLUME, controller.volume(),
    referenceState, poseStack, bufferSource, font, packedLight);
```

交互链路不是一次按钮脉冲：玩家必须先瞄准当前滑块按住右键，服务端重新发射射线并确认只命中了随滑块移动的 1×2.5 MCpx 命中面，然后签发短时会话；客户端在右键持续按住期间按横向鼠标位移发送归一化位置，无需继续瞄准滑块。默认完整量程需要约 480 个横向鼠标像素，灵敏度由组件统一配置。会话激活期间客户端独占“使用物品”键位，取消原版重复方块／物品交互和挥手，但不修改按键的物理按下状态，因此仍可可靠检测松键；松开右键、打开 GUI、离开世界都会立即发送结束并退出本地捕获。服务端每个采样重新检查会话令牌、维度、距离、区块、控制器类型、结构和滑轨表面，再按实例范围与步进计算业务值。会话在断线、换维度或 40 tick 无心跳后清理。

滑轨值必须由控制器保存并同步，客户端只负责临时输入和表现。终端不得信任客户端提交的最终业务数值、范围、步进、动作 ID 或控制器位置。

## 13. 接入清单

- [ ] 新实体按钮从 `WorldUiButtonComponents` 选择组件并创建具名实例；
- [ ] 通用箭头小按钮显式传入局部方向，不复制四套方向模型；
- [ ] 动作通过实例的 `install(...)` 声明，不调用底层 `Builder.button(...)`；
- [ ] 表面锚点通过同一实例的 `place(...)` 创建，不重复按钮 ID、尺寸或高亮偏移；
- [ ] 模型、命中与高亮共用同一放置锚点；终端不再单独平移 renderer 或绘制边框；
- [ ] 不在终端中手写 CONTROL 表面后再单独注册动作；
- [ ] 每个按钮具有唯一表面／元素 ID 和动作 ID；
- [ ] 每个按钮回调只表达一个明确动作，不承载通用输入数据；
- [ ] handler 仍执行权限与业务状态检查；
- [ ] 保持型开关状态由服务端保存和同步，客户端只读取状态渲染；
- [ ] 大按钮标签使用短 `Component`，不把显示文字当作客户端输入参数；
- [ ] 滑轨范围、步进和轨道长度由组件实例声明，业务只提供 getter／setter；
- [ ] 滑轨命中锚点使用当前服务端值生成，使可点击区域跟随滑块而非覆盖整条轨道；
- [ ] 滑轨 setter 保存并同步状态，不从客户端包读取范围、步进或动作 ID；
- [ ] 不在终端 renderer 中重复实现悬停框、声音或按压脉冲；
- [ ] 模型通过 `WorldUiButtonComponentRenderer` 绘制，不在终端 renderer 中拼接按压动画；
- [ ] 在多人、按钮边缘、不可操作状态和结构刚被破坏时复测。
