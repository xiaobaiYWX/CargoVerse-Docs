# 自动化实物转移

更新：2026-11-20。记录实物接口与自动装载机的复用边界。现行设备用法见[货柜卸载机](<../../03组件手册/玩家物流/06_货柜卸载机.md>)。

| 层 | 当前职责 | 接入装载机时 |
| --- | --- | --- |
| 识别与节拍 | `CargoOpticalBeam` 负责客户端与服务端共用的首命中求交。方块实体持有红石状态、目标和动画周期。 | 复用光束。装载机根据自身模型定义发射位置、朝向及选定规则。 |
| 路由与仓储 | `TunnelNetworks` 提供频率索引，`PlayerTradeLogisticsNetwork` 提供实际可达入口。入口解析接触面的物品、流体或围场接口。 | 对可达入口按介质查找货源，保留原生侧面限制与多方块去重。 |
| 实物提交 | `PhysicalTransfer.Source` 提供精确身份、原生数量、计量步长与载荷，`Destination` 计划接收并执行变更。预览只读，提交时重新规划。 | 用仓储作为货源，货柜作为目的地。物品精确组件、空柜准入、相同身份追加、容量和冻结运输参数由货柜目的地核验。 |

实际转移从已完成的可达路径取同频入口。库存浏览使用同频索引和自己的查询上限。可达视图未就绪时按服务端剩余预算推进。仓储查询只读取请求介质的能力，能力缓存只保留句柄和空结果，实际数量、空间、围场占用在原生端读取。

接口的两端均可由非货柜设备实现。预览没有占用承诺，提交在服务端串行锁内读取新状态，按原生整数处理数量，并共用补偿日志。定量请求先按源的 `CargoMeasure` 将组数换算为原生量，再以货源余量为上限。自由批次可接受部分数量。公共确认会话、报价、权限和结算由贸易入口处理。

当前 `CargoContainerTransferSource` 提供货柜扣减与占用校验。`PhysicalStorageDestinations` 提供物品接收及生物围场接收。自动卸载机已接入这两路；流体继续通过贸易及仓库终端处理。玩家终端和卸载机共享 `EnclosureCargoRelease` 的放置与恢复逻辑。释放先记录意图，再保存货柜扣减及意图，最后生成原 UUID 的实体并刷写实体区块；错误按事务回滚，已提交的恢复意图可在重载时继续处理。新端点接入时须核对自身原生存储的持久化边界。

回归覆盖移动货柜首命中、动画与光束解耦、断电收尾、定量尾数、同网混合仓储、断线隔离、独立围场卸载、失败恢复和非货柜库存转移。客户端资源显示、多人并发吞吐及高密度生物落盘成本需分开实测。

本轮通过 931 项 JUnit、193 项 GameTest、正式 JAR 校验及构建。路径回归验证了大量同频但不连通的入口不会占用一台设备的实际可达视图。
