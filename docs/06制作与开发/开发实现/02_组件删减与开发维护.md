# 组件删减与开发维护

更新：2026-11-13。记录当前开发基线与组件下架边界，制作目录继续维护型号、模板和资源的具体状态。

## 重型套件退出

重型接口（含主、副方块）与重型连接点已整体移除。正式 JAR 不再包含对应注册、物品、动力输入、对接状态机、约束、恢复队列、模型动画、贴图和掉落；专用测试、物品属性及使用手册同步退出。

普通货柜连接器／接口、直线轨道和磁吸系统继续维护，规则分别见[连接与轨道目录](<../../03组件手册/连接与轨道/README.md>)。通用动画、粒子和终端生命周期仍由其他组件使用。

旧存档中的下列 ID 不再注册，不提供自动替代映射：

- `cargoverse:heavy_docking_interface`
- `cargoverse:heavy_docking_interface_part`
- `cargoverse:heavy_connection_point`

升级前备份世界。存档里已有的物品、方块或物理连接不能作为升级后继续可用的内容；需要按当前组件重新搭建并实机验收。

## 结构与命名边界

15 个历史货柜模板及地层采样站模板中的 68 个已下架部件已清除，NBT 调色板及索引同步更新，结构主体和定义 ID 保留，没有改装成普通接口。

涉及货柜模板系列为 AUI Nomad／Titan、BDS Fortress、DMC TitanHaul、HEC Reactor 和 VBS Eden。其余仍沿用 HD 字符串的定义或文件名只是历史命名，不能据此推导接泊能力。既有“可制造”标记仅表示定义开放，不能替代模板、接口装配和实运验收。使用这些旧结构前，应重新制作连接部件；G2 制作按[新版模板系列代号](<../../05内容数据/02货柜/README.md#型号与模板命名>)维护，不自动开放待制作型号。

普通固体模板目录保留 45 项；受影响条目的 SHA-256 与清理后的 NBT 一致。

## 当前内容与验证

当前共 90 个货柜定义；Cistern、Boreas、BioPod、Aquarium 的 X／XL 共八款已配置定义与配方，但因缺指定模板保持不可制造。自然厂站提供 96 个投放条目、覆盖 58 种型号；同一型号可以由多个站点投放。可制造模板检查覆盖 63 个定义：45 个普通固体、8 个基础型、7 个液体、3 个生物。

放置方向使用原生点击面与局部视线顺序；宽贴花保持右上角锚点并向左、向下扩展，最大为 3×9。组件用法分别见轨道、贴花手册。

在代码仓库运行：

```powershell

node tools/verify-container-templates.cjs
```

本轮结果：906 项 JUnit、196 项 GameTest 和正式 JAR 校验全部通过；离线模板校验通过。完整日志保存在代码仓库 `build/cleanup-workspace-verification-final.log`，构建目录不提交。当前 GameTest 使用 `build/testing/run-gametest`，旧根目录测试世界和历史日志已移出工程归档；开发存档保留。测试目录结构与可选开关以代码仓库 `testing/README.md` 为准。

这些结果覆盖自动化数据、注册、服务端行为和发布边界，不代替客户端视觉、多人、旧存档迁移和长时间物理运输验收。


## 围场替换阶段（2026-11-20）

`enclosure_core`与`enclosure_fence`替代旧`player_bio_packer`和`player_biological_area_marker`，旧ID、四角黄色区域入口、旋转标记资源和导入脚本已删除，不保留旧存档自动映射。玩法见[围场核心与标记围栏](<../../03组件手册/玩家物流/05_围场核心与标记围栏.md>)。

实现分为连接图与外轮廓（`EnclosureTopology`）、内部列与容量（`EnclosureRegion`）、已加载世界缓存及边界标识（`EnclosureAreas`）、单次释放名额（`EnclosureAdmission`）。仅控制器拥有方块实体；围栏连接和有效标识进入原版区块网格，不增加逐围栏Tick或逐帧渲染。缓存失效后分预算处理区块、重验核心和差量更新标识；稳定状态不反复扫描边界。仪表每10tick读取缓存，仅显示变化时同步。

模型更新使用代码仓库`node tools/import-enclosure-models.cjs <生物围场目录>`，一次生成本体、围栏分件、柱顶有效标识、物品display和分格碰撞体。模型仍保留四个仪表基座，移动基座时同步核对`EnclosureCoreWorldUi`的表面锚点与5、6号围栏接点，不能只重导贴图。

本阶段931项JUnit、32项相关GameTest以及正式构建／发布包检查通过。GameTest选择`cargoverse_biological,cargoverse_logistics,cargoverse_storage_links`，日志位于代码仓库`.gradle/enclosure-wrapup-validation.log`，不提交构建或测试世界；客户端模型、仪表视觉和多人高密度性能仍需实机验收。


## 入口频率网络阶段（2026-11-20）

入口取代旧链接器承担网络匹配：空白入口放置生成`NetworkId`，手持入口右键复制频率后放置加入同网。出售、收购与自动装卸设备的指定接口只安装入口，不直接接管线；同频终端共享仓储，实际装卸仍需有效实体路径。旧`tunnel_linker`保留方块、物品与模型，但已移除方块实体、终端地址绑定、目标外框及旧持久地址索引，旧地址不会自动迁移。玩家仓库管理终端及旧区域标记杆已移除，原注册 ID 无迁移映射。

频率唯一保存在入口方块实体，`TunnelNetworks`仅维护按世界／频率划分的已加载位置索引，无额外SavedData或库存副本。终端不再保存用于旧链接器匹配的设备UUID；各台报价、站点身份及商业权限保持独立。安装方向、频率、入口与管线变更会使相关可达缓存失效。

区块恢复采用非阻塞轮转：围场每Tick最多检查8个候选、处理2个就绪区块；物流几何继续消耗共享工作预算。未完成FULL加载的区块保留待办并放到队尾，避免堵住后续就绪区块或丢失刷新。

回归覆盖复制／清除频率、安装时避让终端GUI、保存与空白掉落、同频共享、异频隔离、断线拒绝、双箱去重和物品／流体／生物转移。完整测试及构建日志位于代码仓库`.gradle/tunnel-network-final-validation.log`；客户端工作贴图、放置朝向和多人吞吐仍需实机验收。
