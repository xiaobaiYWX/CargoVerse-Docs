# 自然贸易终端实现

玩家操作见[货物出售终端](../../03组件手册/货柜与装卸/13_货柜装载机.md)、[货物收购终端](../../03组件手册/货柜与装卸/14_货物卸载机.md)和[货运无人机](../../03组件手册/货柜与装卸/15_货运无人机.md)。本页说明实现职责与扩展边界。玩家装卸终端的固定区域与交互见[玩家终端](../../03组件手册/玩家物流/01_玩家终端与地图.md#2-公共货物出售与收购终端)。

## 组件职责

| 层次 | 主要入口 | 职责 |
| --- | --- | --- |
| 方块与碰撞 | `ContainerLoaderBlock`、`CargoUnloaderBlock`、对应 `Shapes` | 多方块装配、四向碰撞与控制器识别；整体模型由控制器渲染 |
| 终端状态 | 出售、收购和供应终端的 `BlockEntity` | 绑定、数量选择、区域检测、表面快照与短期飞行状态 |
| 表面布局 | `ContainerLoaderSurfaces`、`CargoUnloaderSurfaces` | 各自的仪表、按钮及滑轨锚点 |
| 共用几何 | `CargoTradeTerminalGeometry` | 模型像素到方块及世界坐标的变换；不包含选货、报价或交易动作 |
| 表面显示 | `CargoSalesDisplay`、`CargoAcquisitionDisplay` | 只读取视图状态，显示实际货物和计划交易数据 |
| 目录 | 两套独立的 `Menu`、`Row`、`SnapshotPacket`、`Screen` | 共用图集，各自维护目录与选择语义 |
| 交易 | `CargoTransferOrderService`、`CargoTransferPreviewService`及各介质服务 | 私有确认、提交时重验、实际转移、结算、经验与失败恢复 |
| 物资供应 | `TradePointSupplyService`、`TradePointSupplyProgress` | 需求快照、尾量截断、繁荣升级、循环供应和个人声望结算 |
| 搬运表现 | `CargoDroneVisuals`、`CargoDroneFlight`、`TradeCargoDroneRenderer` | 成交后生成冻结目标的视觉状态，客户端插值模型与纸箱 |

玩家出售终端复用 `CargoSalesDisplay`、模型几何和货运无人机，使用独立的 `PlayerCargoSalesCatalogue`、菜单、屏幕及收发包，不复用自然站的经济表查询。`PlayerCargoArea`只按本台控制器、朝向和对齐设置计算固定范围。对齐变更由服务端重验核心管理权限，选货使用稳定 ID。

玩家收购终端复用 `CargoAcquisitionDisplay`、收购模型几何和双机搬运，保持独立的 `PlayerCargoAcquisitionMenu`、报价行、快照与客户端本地选卡状态。共同的 `PlayerCargoAreaAlignmentButtons`完整裁切 18×18 图集按钮，通过 `PlayerCargoAreaAlignmentPacket`提交菜单绑定的设置请求；出售选货包只处理稳定货物 ID，不夹带区域设置。

固定终端实现 `PlayerTradeOperationController`。每台玩家货物交易终端持有 `PlayerTradeInventory`，其中商品配置只保存于本台；`PlayerTradeContext` 显式组合本台库存与可选核心账户，三种介质后端不能通过核心寻找库存。

`PlayerTradeStationBinding` 使用站点空间索引列出附近已加载核心（列表不按权限预筛选），管理员菜单由 `PlayerTradeInventoryMenu` 统一承载，交易终端固定对应出售／收购模式。`PlayerTerminalStationsPacket` 定向同步有界列表，`BindPlayerTerminalPacket` 绑定当前菜单，提交时重新检查设备、权限、范围与目标名额。

`PlayerTradeLogisticsNetwork` 仅缓存设备起点的物理可达性，不持久化核心占用图。事件使受影响视图失效，旧草稿不能发布；预算、节点／端点上限及原生结构验证边界见[物流隧道](../../03组件手册/玩家物流/04_物流隧道.md)。`PlayerTradeStorageAccess` 从收发器附着点解析并去重原生控制器，不维护核心仓库索引。

## 浏览与成交边界

出售目录选货需要服务端确认并更新终端表面；收购目录选货只保留在当前客户端屏幕。收购菜单无物品槽位、无选货提交包，也不接受菜单按钮包执行交易；玩家收购菜单只额外接受独立的管理员区域设置请求；商品编辑和站点归属在独立的管理员菜单处理。打开目录不扫描装卸区、不要求货柜存在，目录检查仅在菜单打开期间进行，内容变化才发送快照。

收购菜单绑定打开时的玩家、终端对象和贸易点。服务端检查距离、结构、绑定和站点可用状态；快照包按菜单类型及菜单 ID 匹配，并限制行数。目录展示实际浏览者的签约报价；表面预计收入使用当前货柜所有者的条件，最终金额以确认提交时的玩家及授权重验为准。

灰色 `SCAN` 按钮触发一次区域扫描。周期刷新和交易确认只按已选货柜 ID 核对位置，拖动滑轨据此重算计划量。货柜离开范围后清除本次选择。实际载荷不按本站报价过滤；未报价货物仍显示，确认拉杆负责拒绝不可交易的载荷。每日收购额度统一通过 `TradePointAcquisitionLimit`换算原生余量，不在 GUI 维护第二份限额。

## 确认与供应

出售和收购使用同一确认页，服务端验证本次选择、数量和结算条件。成功后数值动画播到最后一帧，客户端在下一次界面 tick 自动退出。需要重验的预览和失败状态保留在页面。

供应终端使用独立的需求清单和提交确认图集。确认会话检查需求阶段和轮次，状态变化会触发重验。货柜扣量、站点进度与个人制造商声望在同一事务提交。客户端只绘制快照，经验条成功后播放变化。详见[物资供应](<../../02系统规则/自然贸易点/03_物资供应.md>)。

## 动画生命周期

物品后端同时投影玩家装载与卸载预览，方向决定柜内、钱包与仓库增量符号；实际事务继续由现有玩家交易服务完成。固体、流体与生物均进入同一确认会话。

真实事务提交成功并释放会话后才尝试发布视觉状态。视觉异常被隔离，不能撤销成交或要求玩家重试。动画进行期间的新成交正常执行，但不覆盖当前动画、不排队补播，也不重新取样目标位置。

服务端仅保留起始 Tick、冻结世界目标和搬运方向，通过方块实体更新同步；不将动画写入存档。客户端共用机体、纸箱和旋翼分件，派生两端的路线及收购双机错峰。运行边界覆盖整段双机流程，渲染包围盒同时包含终端和冻结目标。

动画不创建实体、掉落物、路径搜索或逐 Tick 坐标广播。移动结构缺少实际世界坐标时跳过视觉表现，不回退到存储空间坐标，不强制加载区块。时长与停靠表现见正式无人机手册。

## 资源维护与核验

终端本体与物品 `display`模型分别绑定各自导出的纹理；同名导出文件不能视为相同 UV。纸箱与无人机是动态分件，不重新烘焙进终端本体。收购和出售 GUI 只共用 `natural_cargo_sales.png`；其中预留按钮区域不自动注册行为。售罄标记在货物图标和选中效果之后，以更高 GUI 深度绘制。

定向单元测试覆盖四向表面与碰撞、原生计量、额度、快照边界及动画生命周期；运输 GameTest 覆盖实际成交、视觉防重入和只读目录不改表面。客户端接缝、命中手感、移动载具表现及多人实运仍按[待完成事项清单](../../90设计草案/待完成事项清单.md#终端仪表与交互调整)验收。

四款交易终端使用独立静态模型与颜色：自然出售／收购为单无人机，玩家出售／收购为双无人机，其中自然收购与玩家出售将面板左右镜像。`CargoTradeTerminalGeometry.mirrorX` 只移动锚点位置，保留文字与组件坐标轴的可读方向。自然终端将归属制造商作为显示字段同步，客户端在预注册纸箱模型中选择；无归属使用默认纸箱。供应终端沿用双机收购表现。飞行占用时间按无人机数量计算，单机 170 tick、双机 202 tick。
