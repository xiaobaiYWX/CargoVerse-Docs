# 标准货柜对接实现

更新：2026-11-13。本文维护标准货柜对接的代码边界、保存协议、资源接入与诊断计算，不代替[组件使用手册](<../../03组件手册/连接与轨道/01_货柜连接器与接口.md>)。重型接口是独立系统，不复用标准接口的频率编组或固定约束规则。

## 责任边界

| 模块 | 职责 |
| --- | --- |
| `CargoDockingPortBlockEntity` | 主动／被动端点的生命周期组合，不另建业务状态机 |
| `CargoDockingFrequency`／`CargoDockingGroupKey` | 频率编解码、NBT 与结构内组身份；组键使用 UUID 和整数编码，不使用显示字符串 |
| `CargoDockingStateMachine` | 红石边沿、搜索倒计时和主动方块状态 |
| `CargoDockingPairingService`／`CargoDockingRestorer` | 筛选、磁力引导、持久目标恢复及重试 |
| `CargoDockingCompleteness` | 从结构已加载的区块实体位置统计全部标准接口；数量预检及最终完整覆盖判定，不以附近索引计数 |
| `CargoDockingSupportValidator`／`CargoDockingSupportSnapshot` | 一对一副匹配与不可变匹配快照；优先保留有效旧匹配，失效时重新匹配 |
| `CargoDockingConnectorGroupManager`／`CargoDockingPortIndex` | 共享状态、主／副归属、空间索引及稳定诊断目标表 |
| `CargoDockingConstraintController`／`Factory`／`Smoother` | 唯一固定约束及短时姿态平滑；不拥有频率或 GUI 状态 |
| `CargoDockingFrequencyMenu`／`UpdateCargoDockingFrequencyPacket` | 绑定实体的服务端编辑会话、数据同步及提交复核 |
| `CargoDockingFrequencyScreen`／`CargoDockingClientAnimation` | 本地选择预览、滚轮交互及主动接头动画 |
| `CargoDockingLoadMonitor`／`CargoDockingPhysicsMonitor`／`CargoDockingCapacity` | 命令会话期间读取冲量、计算参考负载率和汇总峰值，不解除约束 |

## 不变量与恢复

- 同组必须完整覆盖目标货柜的全部标准接口。数量预检只是必要条件，不能替代距离、世界朝向、占用和一对一匹配；多余主动连接器可以不参与连接。
- 同组只拥有一个主连接器和一个真实固定约束。副连接器通过匹配快照表示，不产生额外约束；所有权解除与索引清理沿组生命周期执行。
- 持久逻辑目标独立于物理句柄有效性。句柄丢失时暂停运行时配对并进入恢复，不直接改为搜索其他货柜。
- 恢复检查端点身份、已加载状态、不同结构、组可配对性、被动端占用、局部及世界朝向、表面距离与完整覆盖。拒绝超出容差的恢复，不强制移动两艘结构；等待期间有界退避重试，失败安全关闭。
- 标准被动连接点为静态模型，不再拥有 `PortVisualState`、动画控制器或独立广播包。纯显示需要不写被动端 BlockState，防止触发 Sable 结构更新；主动接头读取现有连接器状态。
- 断开、改频和实体移除清理归属及诊断目标。监控表直接遍历稳定运行时记录，不在每个物理子步重建全组列表；无监控会话时不读取冲量。

## 频率与保存协议

频率编码为 `band * 10 + channel`，范围 `0..259`；字母下标 `0..25`，信道 `0..9`。显示格式只由 `CargoDockingFrequency.format` 生成。运行时组键为结构 UUID 与该编码值。

主动端 NBT 分别保存 `DockingBand`、`DockingChannel`，缺失、类型错误或越界时使用 `A-0`。此前物品编组和单数字 `DockingFrequency` 不迁移、不猜测转换。`SearchTicksRemaining`、`RedstonePowered` 和 `RestoreEndpoint` 继续由 `CargoDockingPortPersistence` 保存；物理句柄及匹配缓存不序列化。

菜单数据同步使用一个整数；提交包携带菜单 ID 和编码值。服务端检查当前菜单、编码范围、玩家权限、方块身份、已加载区块及投影世界距离。客户端点击确认后等待菜单数据确认再关闭；取消不提交，不因本地预览绕过最终验证。

## 资源与客户端

- 保持现行注册 ID。主动底座按三态选择贴图，接头由 `CargoDockingConnectorRenderer` 独立渲染；被动 `twistlock` 使用静态模型。锚点、尺寸和动画时间以[组件手册](<../../03组件手册/连接与轨道/01_货柜连接器与接口.md#标准半格模型>)为准。
- GUI 资源为 `assets/cargoverse/textures/gui/cargo_docking_frequency.png`，贴图采样尺寸 `256×256`，菜单显示左上角 `174×97` 区域。最终编号在左侧；频率和信道在右侧，分别位于 `(82,21)`、`(82,44)`，命中范围均为 `77×18`；文字、滚轮和悬停框使用同一坐标常量。
- 最新被动模型由 `cargo_docking_port.json` 保存完整导出设置，方块基座和物品通过继承引用，避免手持／GUI display 分叉。旧把手、抓爪及旧纹理不再加载；参考完整模型不重复叠加进方块渲染。

## 载荷诊断

命令语法、目标选择和输出节奏统一见[命令页](<../运维与验证/03_命令.md#物理接口监控>)。下列值仅用于测试物理载荷，不再是断裂阈值：

```text
线性载荷 F = |线性冲量| / Δt
角向载荷 T = |角向冲量| / Δt
参考负载率 = max(F / (N × linearCapacityPerConnector),
                  T / (N × angularCapacityPerConnector))
```

`N` 为完整匹配的连接器数量。配置节点 `cargoDockingDiagnostics` 的 `linearCapacityPerConnector` 与 `angularCapacityPerConnector` 均默认为 `100000.0`。参考负载率超过 100% 仍是有效诊断结果，不触发断裂。旧 `cargoDockingOverload` 与 `graceTicks` 不再读取；生产计算只保留可复用样本，不保留超载判定包装。

## 验证边界

单元测试覆盖频率往返、同结构编组隔离、协议及副匹配、冲量换算与无效样本清零。`CargoDockingGameTests` 覆盖真实约束、逻辑恢复、安全拒绝、完整覆盖、改频、数量不足倒计时与允许多余连接器。

每个 Sable GameTest 独立批次，前后清理并处理子世界移除队列。夹具以真实模型锚点初始化，不假设相同出生坐标等于锚点重合；倒计时夹具不依赖逐 tick 强制传送物理句柄，而在搜索期间检查候选仍在范围内。测试网格和发布隔离规则沿用[变更验证策略](<../运维与验证/06_变更验证策略.md>)，不修改生产捕获容差。

固定像素、截图外观及导出 display 由客户端实机验收，不保留像素颜色快照测试。自动化通过不代表多人重连、超远坐标或大型接口阵列已完成实机验收。
