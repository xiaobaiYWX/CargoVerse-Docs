# 模板系列归属与核对规则

更新：2026-11-06。撤销此前“历史合并后可以跨系列沿用模板”的解释。

## 命名是归属依据

`cargoverse:cargo/spl/cargo/spl_cargo_mc_l` 固定表示 SPL 制造商、Cargo 系列、MC 接口、L 规格。它不能计作 Courier 的 L 模板。同理 TitanHaul 不属于 Silo、Reactor 不属于 Apollo、Bastion 不属于 Sentinel、Recycle 不属于 Reliquary、Eden 不属于 Harvest。

当前文档仍按正式设计的系列名称列需求；定义资源 ID 可为存档兼容保留旧拼写，但不能用旧 ID、标签改写或显示名合并来改变 NBT 归属。实际规格以定义 size_class 对照 NBT 文件末尾规格；接口独立列出，不由旧引用推定。

## 状态分开判定

| 状态 | 判定 |
| --- | --- |
| 已绑定正确模板 | 制造商、系列、规格匹配，当前引用就是该 NBT |
| 正确 NBT 已有／引用错误 | 有同制造商、同系列、同规格文件，尚未正确接入；还需核对接口 |
| 模板缺失 | 正式规格在本系列目录无对应 NBT，其他系列同尺寸不能抵扣 |
| 未规划 | 正式产品线没有该规格，不生成补建任务 |
| 非正式内容 | 预留、关闭、验证或兼容内容独立记录，不计入正式缺失 |
| 未使用 NBT | 全部 81 个定义均未引用；被错误引用的文件仍算有引用 |

## 特别核对

- Apollo 当前正式规格为 M／L／X，旧定义 ID 后缀分别是 S／M／L。现有 Apollo NBT 为 SD-S／M／L；本轮匹配 M／L，X 确实缺失。Reactor HD 模板不能当作 Apollo 模板，已有 Apollo SD 文件接入前需重新核对接口设计。
- Courier S／M 自有 MC 模板存在，L 不存在；Cargo L 是独立 Cargo 系列资产。
- Silo 当前全部 L／X／XL 缺失本系列模板；待制作名称按稳定定义的 SD 约定标出，不沿用 TitanHaul 的 HD 接口作为已完成事实。
- Boreal X／XL 已有 boreal 命名的 SD 模板，虽然定义 ID 仍含 titanhaul_hd，实际 NBT 仍属于 Boreal；ID 的历史拼写不能反过来把文件判给 TitanHaul。

## 维护入口

逐型号结论写在[正式目录](<../../../05内容数据/02货柜/README.md>)的制造商、系列、型号页。所有预留内容移至[非正式内容](<../../../90设计草案/货柜/预留与验证/README.md>)；未引用文件按真实系列独立维护在[未使用 NBT 系列表](<../../../05内容数据/02货柜/未使用NBT系列清单.md>)。

本轮没有重命名或复制 NBT，没有把缺失型号换绑其他系列；运行引用问题仍待后续接入处理。
