# 按变更范围选择验证

更新于 2026-11-09。日常调整按影响范围运行验证，不默认重跑全量单元测试或全量服务端 GameTest。

| 变更 | 通常需要的验证 |
| --- | --- |
| 文档、索引 | 相关本地链接、参数与运行数据对账 |
| 逐物品属性、运输参数 | 只读属性核验、逐 ID 对账、相关运输规则与快照测试 |
| 质量计算、载荷状态 | 运输规则、载荷与冻结快照／存档的针对性单元测试 |
| 注册、标签加载、真实方块交互 | 增加受影响的服务端 GameTest 或开发存档检查 |
| 公共协议、广泛生命周期或跨系统重构 | 评估扩大测试集；发布验收可安排全量测试 |

执行前说明本次范围；发现问题后按证据扩大验证，不因小参数调整无条件跑完整服务器回归。没有执行的全量测试或实机工况应明确列为未验证，不复用旧结果冒充本次运行。

## 源码与发布检查

生产源码和资源在 `src/main`。JUnit、离线测量与 GameTest 统一放在可选的 `testing/` 目录。默认 `./gradlew.bat build` 构建并校验正式 JAR，可在省略整个测试目录的工程副本中执行。普通客户端与服务器使用生产源码集。

开发验证显式启用 `-PwithTests`。`verifyCargoVerse` 执行 JUnit 与正式 JAR 检查。`runGameTestServer` 启动专用服务端，夹具与测试 Mixin 只随该运行配置加载。全量回归使用 `./gradlew.bat -PwithTests verifyCargoVerse runGameTestServer`。Windows 也可使用 `testing/run.bat`，参数 `-Suite` 可选 `unit`、`verify` 或 `game`。

`verifyReleaseJar` 随默认 `check` 执行，按当前生产源码核验包内类、数据、贴图与 Mixin 配置的来源。需要真实注册、权限、网络、持久化、物理或事务的场景继续由自动测试覆盖。固定像素、图集布局和显示效果由人工视觉验收。

专用 GameTest 的物理基准网格固定在 `(0,-59,0)`。原版会将测试随机放至约 ±1500 万格；实测在 `(14000000,-59,14000000)`，货轨夹具初始距离由近原点的 0 变为 0.5 格，随后接触位移导致离开捕获范围。普通实机捕获已由玩家确认，当前修正只固定测试环境，不调整生产捕获容差。测试专用 Mixin 与配置仅由 `runGameTestServer` 加载，正式 JAR 不包含。

超远坐标原生物理精度属于独立工况，可用 `./gradlew.bat -PwithTests runGameTestServer '-PgameTestNamespaces=cargoverse' '-PgameTestOriginX=14000000' '-PgameTestOriginZ=14000000'` 复现；该探针可能在初始对齐断言失败。双精度几何投影另有大坐标单元测试，通过不代表原生物理场景没有误差，也不代表已完成实机可用坐标范围验收。

开发客户端运行期间不要重编译其正在读取的输出目录；先退出客户端，或使用独立 buildDirectory 做验证。Windows 测试类路径 JAR 按构建目录独立命名，并将实际绝对路径作为任务输入，避免隔离构建覆盖普通构建的类路径。运行中的客户端不会自动载入新编译类，代码修改应重启开发运行后验收。

例如运输质量或条件参数更新可运行：

```powershell
./gradlew.bat -PwithTests test --tests 'cn.or15.cargoverse.cargo.transport.*' --tests 'cn.or15.cargoverse.cargo.item.*' --tests 'cn.or15.cargoverse.cargo.CargoContainerSavedDataTest'
```

逐物品属性以 Java 解析／资源测试为准；真实注册、已发布规则和物理取样由相关 GameTest 验证，不维护另一份 JavaScript 运输 schema。修改对应物品文件后再更新文档投影；不从文档生成或覆盖 JSON，不补回共享分组或成员标签。

千件运力、满柜起吊和航线平衡属于独立实机验证，不由单元测试替代。

交易故障注入仅位于`testing/gametest`，通过专用CargoTradeFaultMixin在真实变更／补偿登记后触发；正式交易类不保留测试开关。JUnit用失败操作验证补偿，GameTest验证真实业务回滚。测试Mixin只由runGameTestServer显式启用，不加入普通客户端／服务器或正式JAR；修改相关边界同时运行verifyReleaseJar。

载荷、身份、保存或装卸会话拆分可选择两组世界回归，不必启动全部其他系统：

```powershell
./gradlew.bat -PwithTests runGameTestServer '-PgameTestNamespaces=cargoverse_transport,cargoverse_logistics'
```

`cargoverse_transport_model` 覆盖条件编译、环境输入、瞬时运动缓存、冻结及物理参考点；涉及这些链路时可与 `cargoverse_transport` 一并选择。`cargoverse_transport` 覆盖真实物品载荷、隔离、时限、规则升级、交易回滚及自然目的地经验；`cargoverse_logistics` 覆盖玩家网络、区域、仓库管理和确认会话。修改计量时同时选择 `CargoMeasureTest`、`CargoContentContractTest` 及 `CargoTransferBackendTest` 等相关单元测试。默认全量 GameTest 包含这两组，不能因拆分命名空间而遗漏发布验收。

动态展示／质量部件的真实放置、Sable 组装、空态保留、换货刷新及精确质量分配也在 `cargoverse_transport_model`。货箱信息 PDA 的受保护货柜交互入口在 `cargoverse_inspection`；这两组可按需合并运行，不必启动整个贸易网络回归。客户端缺图、图集等级选择及扫描动画仍需开发存档视觉验收。

生物识别专项使用 `./gradlew.bat -PwithTests runGameTestServer '-PgameTestNamespaces=cargoverse_biological'`，覆盖四向围栏／入口接点、多方块拆除、凹形闭环、合并与支线、边界标识恢复、物种共享容量及卸货前数量重验；连同`cargoverse_logistics,cargoverse_storage_links`验证真实接线与交易路径。逐物种属性解析可定向运行 `EntityPropertyDefinitionTest`；识别通过不代表已验收生物捕获释放或客户端视觉。
