# 美术资源整理与合图

本文供美术导出和代码接入共同使用。按批次迁移现有资源，保留现行画面、交互、方块和物品注册 ID，以及结构模板中的引用。共享图集用于集中维护同一套视觉元件。界面底图、模型 UV、游戏运行时拼图分别使用各自的导出方式。

## 当前运行资源

本阶段已合并交易目录、站点绑定与对齐、六级繁荣度图标、菜单边框、地图标记底片和手册导航控件。下文的旧路径和矩形保留为迁移对照。第二批将繁荣度品牌底图与展屏组件归入五张图集，并将删除、定位、返回和百科条目底片并入手册控件。收尾批次将 21 张地图标记并入原有地图图集，四组字节相同的模型材质改为共用，六张无现行引用的 GUI 散图归档。

| 收尾判断 | 现行安排 |
| --- | --- |
| 地图标记与布局素材 | 玩家、原版结构和默认结构图标已与标记底片共用 256×256 图集。各标记保留源尺寸和结构对应关系。地图底图、LOD 和地表纹理按各自渲染入口维护。 |
| 模型材质 | 无人机、空白与已写入蓝图槽以及展屏正面使用 `block/shared` 下的共享纹理。保留原尺寸、UV、模型 ID 和维护所需的 Blockbench 源稿。 |
| 运行时仪表 | 封装仪表和世界边框由现有 Atlas JSON 拼接。时钟 134×151 与贸易额 139×133 无法在一张 256×256 画布内原尺寸并排或叠放，继续使用独立贴图。 |
| 手册正文、品牌与动画 | Markdown 直接引用的插图继续提供独立地址。手册与方块贴花的品牌 Logo 已发现 16 组字节一致的导出，统一由品牌源稿管理，并保留两个用途的独立替换入口。手册整页底图、动画帧、流体序列与模板贴花按各自格式导出。 |


手工裁切的运行图集统一使用 256×256 画布。原本不足 256 的画布在右侧或底部补透明像素，保留画面布局和原始选区。大于 256 的完整手册底图、独立厂商图样、印章和动画帧保持原用途与实际尺寸。运行时拼接出来的世界表面图集由引擎决定尺寸。

## 外部美术交付目录

外部美术目录的 `资产索引.md`、`GUI/98-通用素材/图集与导出清单.md` 与 `_归档/归档索引.md` 已按现行资源更新。14 套专用菜单的 PNG 集中到各功能目录的 `导出/`，商品展示、世界表面边框与航运手册底图沿用各自的导出入口。世界表面边框的两个仍在使用的图元已从废案目录移回。

## 2. 先判断资源走哪条导出路径

手排图集使用 **RGBA PNG、整数像素、原始比例**。从左上角用半开矩形记录 `u, v, width, height`。切片之间留空，首批目标位置已预留间隔；若某条渲染路径使用线性过滤，则按实机结果给对应切片扩边。手排图集的裁切使用 256×256 画布。迁移前的 227×256、252×254 等尺寸仅用于核对旧路径。切片的像素矩形、界面上的绘制位置、点击范围、图层和颜色各自记录，其中后四项沿用现有页面逻辑。已有一个共享入口时优先扩展它。

## 5. 模型整理顺序与交付表

先以四个自然／玩家交易终端做样板，再推广到供应终端、展示器、搭建器、物流隧道与其他组件。模型名称建议用现行功能名的英文 `snake_case`。同一功能下把现行工作工程、贴图源稿、可重建的导出和对照图区分开。旧模型中的数字编号可以保留为对照，正式导出使用稳定的语义名。

| 每个模型要标注的项 | 标注方法 |

## 6. 按批执行、验证和撤回

| 批次 | 工作内容 | 完成条件 |
| --- | --- | --- |
| 0 · 基线 | 核定现行源稿，记录尺寸、旧裁切和引用，同一画面留对照。标记运行时使用的资源、兼容别名、调试稿和未知项。 | 首批每个切片可追溯到源稿和运行引用。尚未核清的文件留在原处。 |
| 1 · 小件试迁 | 依照第 3 节先做商品卡和对齐按钮，再做繁荣度图标。新增共享导出后同时切换全部相关代码。旧图只清除已移出的区域，继续保留页面仍在读取的部分。 | 裁切矩形落在画布内，源／目标切片 RGBA 一致，交易目录和繁荣度各入口实机通过。源稿和导出的现行入口已登记。 |
| 2 · 品牌与常用菜单 | 接着迁移站点绑定、共享按钮／边框、制造商标识、手册控件和地图标记。 | 每个共享元件只维护一套裁切定义。颜色、透明、文本省略、悬停、键盘／鼠标交互、默认品牌回退均维持现状。 |
| 3 · 模型与其余资源 | 分模型族合并母稿、整理导入规则；按第 4 节处理其他图集和动态资源。 | 资源重载可用，模型和贴图引用存在，四个水平朝向及镜像变体的模型、交互区域和端口一致。流体动画与粒子帧保持正常。 |
| 4 · 清理 | 对旧路径做全工程引用扫描，包括 Java、模型和祖先模型、注册代码、Atlas JSON、数据包、粒子声明、动画元数据及导出脚本。必要时检查第三方资源包的覆盖约定。 | 仍是有效引用目标或兼容别名的路径保留；无引用且经过实机核对的旧导出从运行目录移除，旧源稿归档。同步资产索引。 |

每批验收按影响范围执行：

- **静态检查**。核对纹理宽高与裁切、扩边、UV、贴图路径大小写、模型父级、图集中切片间距。记录使用同一切片的各处入口。旧 PNG 留在运行目录时，注明它当前承担的职责。
- **菜单实机**。在至少两档 GUI 缩放下看商品卡、选中、锁定、售罄、长站点名、滚动和悬停。关闭／重开菜单，确认按钮范围、管理员与访客入口、选中状态和原业务行为。
- **世界实机**。资源重载后检查朝向、镜像、屏幕拼接比例、品牌／默认背景、商品页换场裁切及动态贴图。对照模型时同时看轮廓、碰撞位置、可点击范围、动画枢轴和接入面。带透明贴花或纹理的部件看远近两档，确认边缘无串色。
- **打包检查**。在模组工程运行 `./gradlew.bat verifyReleaseJar` 核对实际打包资源，视觉仍以游戏画面为准。纯资源整理只验受影响的界面与模型；改到注册、交互或存档边界时增加对应测试。参照[按变更范围选择验证](<../运维与验证/06_变更验证策略.md>)。
- **撤回方式**。按图集或模型族分批提交。出现贴图丢失、UV 偏位或模型交互回归时，同批恢复旧图和相应的代码或模型引用，再从原切片或部件定义修正。
