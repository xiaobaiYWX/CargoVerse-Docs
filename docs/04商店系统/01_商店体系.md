# 物品售货机与商店定义

## 职责边界

物品售货机出售普通实体物品。商店商品不再关联 CargoGood、资源表或贸易点货物库存，购买时只从玩家携带的虚空结算器中扣除虚空字节（VB）。

- 贸易点注册时抽取并持久化商店定义与上架商品。
- 同一贸易点 UUID 下的售货机共享商品目录和当日有限库存。
- 每台售货机仍各自保存待领取物品。
- 手动放置的售货机初始 UUID 为空，管理员 GUI 只负责绑定贸易点 UUID。
- 商品价格会在服务端结算时应用该贸易点制造商的签约声望购买优惠。

## 文件位置与定义 ID

```text
data/<namespace>/trade_points/trade_points_subfunctions/shop_definitions/<path>.json
```

例如：

```text
data/cargoverse/trade_points/trade_points_subfunctions/shop_definitions/resource/general/default_shop.json
→ cargoverse:resource/general/default_shop
```

## Schema 3 模板

```json
{
  "schema_version": 3,
  "display_name": "默认资源商店",
  "catalog": {
    "draw_count": 5,
    "allow_duplicates": false
  },
  "offers": [
    {
      "id": "cargo_docking_connector",
      "weight": 1,
      "unlock_prosperity_level": 0,
      "result": {
        "type": "item",
        "item": "cargoverse:cargo_docking_connector",
        "count": 1
      },
      "price": 32,
      "stock": {
        "type": "unlimited"
      }
    },
    {
      "id": "iron_ingot_pack",
      "weight": 1,
      "unlock_prosperity_level": 0,
      "result": {
        "type": "item",
        "item": "minecraft:iron_ingot",
        "count": 3
      },
      "price": 64,
      "stock": {
        "type": "limited",
        "maximum": 24
      }
    }
  ]
}
```

顶层、`catalog`、`offers[]`、`result` 与 `stock` 都采用严格字段集合。未知字段、缺失字段、重复 offer ID、未知物品或越界数值会拒绝整轮数据发布。Schema 2 的 `price.currency`、`price.amount`、`output_costs` 和 `cargo_goods` 已删除，不提供兼容读取。

## 字段说明

### 顶层与目录抽取

| 字段 | 作用 |
| --- | --- |
| `schema_version` | 当前固定为 `3`。 |
| `display_name` | 商店定义显示名。 |
| `catalog.draw_count` | 贸易点注册时抽取商品的次数，范围 `0..256`。 |
| `catalog.allow_duplicates` | 是否允许同一 offer 重复出现在抽取结果中。重复行仍共享同一 offer 库存。 |
| `offers` | 候选商品数组，必须包含 `1..256` 项。 |

### `offers[]`

| 字段 | 作用 |
| --- | --- |
| `id` | 定义内唯一稳定 ID，只允许小写字母、数字、`_`、`.`、`-`；同时作为当日库存状态键。 |
| `weight` | 大于 `0` 才参与加权抽取。 |
| `unlock_prosperity_level` | 商品显示与购买所需的最低贸易点繁荣等级。 |
| `result.type` | 当前仅接受 `item`。 |
| `result.item` | 购买后进入待领取区的已注册物品 ID。 |
| `result.count` | 每一份商品生成的物品数量，最小为 `1`。 |
| `price` | 每一份商品的基础 VB 价格，可为 `0`；币种固定为虚空字节，不再填写货币 ID。 |
| `stock` | 商品的交易日库存策略。 |

### 无限库存

```json
"stock": {
  "type": "unlimited"
}
```

无限库存不创建当日销量记录，可持续购买，且不能填写 `maximum`。

### 有限库存

```json
"stock": {
  "type": "limited",
  "maximum": 24
}
```

`maximum` 表示每个交易日最多可以买多少“份”该 offer，范围 `1..1000000000`。例如 `result.count = 3`、`maximum = 24` 表示每日最多购买 24 份、合计产出 72 个物品。购买数量滑轨选择 5 时，一次消耗 5 份库存。

有限库存属于贸易点实例而不是某台售货机：同一贸易点的所有售货机共享当日已售数量。交易日推进时当日销量清空，库存直接恢复至 `maximum`；不做逐日回补，也不与资源表库存互相转换。

## 贸易点模块绑定

```json
"modules": {
  "item_shop": {
    "min_prosperity_level": 1,
    "definitions_pool": [
      {
        "weight": 1,
        "definition": "cargoverse:resource/general/default_shop"
      }
    ]
  }
}
```

贸易点注册时从 `definitions_pool` 抽取一个商店定义，再从该定义直接抽取 offer。商品是否进入候选池不再取决于贸易点资源表。抽取后的稳定 offer ID 保存在贸易点注册记录中，数据包重载不会因库存变化重新抽取目录。

## 价格结算

最终付款值按以下顺序计算：

```text
offer.price × 购买份数 × 制造商签约声望购买修正
```

结果按统一整数货币规则四舍五入并从玩家携带的虚空结算器中扣除。玩家未签约该贸易点制造商时，制造商修正为 `1.0`。世界表面仪表是多人共享显示面，只显示基础 VB 价格；最终服务端成交值以购买玩家自身的签约与声望为准。

## 购买事务

购买在服务器串行事务内完成：

1. 复核玩家许可证、终端结构、贸易点绑定和模块定义；
2. 重新读取繁荣等级、选中 offer、购买份数与当日共享库存；
3. 计算制造商优惠后的 VB 总价并检查虚空结算器余额；
4. 扣除 VB；
5. 有限库存记录本次已售份数，无限库存跳过；
6. 将结果物品写入该售货机的待领取区；
7. 将实际付款计入贸易点交易总额；
8. 提交后刷新仪表。

付款、有限库存、待领取物和经济记账均注册逆序补偿。任一步失败都不会留下部分成交状态。

## 待领取区

- 购买结果不会直接进入购买者背包。
- 任何玩家都可右键出货成员领取。
- 背包只能容纳一部分时，仅提取实际插入的数量。
- 待领取物跨存档和区块卸载保存。
- 多方块终端拆除时，剩余物品只在控制器位置掉落一次。
