# 商店体系

商店终端出售普通物品。商店定义只描述候选商品；某个贸易点能使用哪些商店定义，由贸易点定义中的 `shop_definitions` 决定。

`currency_id` 可以引用普通物品，也可以引用支持多面额和实体找零的货币组，详见[实体货币与多面额结算](../07货币系统/01_实体货币与多面额结算.md)。

## 商店定义

文件位置：

```text
data/<namespace>/shop_definitions/<path>.json
```

示例：

```json
{
  "commodity": [
    {
      "item": "minecraft:iron_ingot",
      "cargo_type": "ore",
      "cargo_units": 1,
      "display_name": "",
      "count": 3,
      "price": 64,
      "currency_id": "minecraft:emerald",
      "required_license": "S",
      "required_prosperity": 0.0,
      "weight": 1
    }
  ]
}
```

商品字段：

| 字段 | 说明 |
| --- | --- |
| `item` | 商品物品 ID。 |
| `cargo_type` | 商品接入贸易点价格与产出库存时使用的 CargoType。非法值按 `none` 处理。 |
| `cargo_units` | 每购买一份商品消耗的同类型 `output_cargo_units`，默认且最小为 `1`。 |
| `display_name` | 可选显示名；为空时使用物品默认名称。 |
| `count` | 每份商品实际获得的物品数量。 |
| `price` | 基础价格。 |
| `currency_id` | 支付物品 ID。 |
| `required_license` | 所需运输许可证等级。 |
| `required_prosperity` | 商品进入候选池所需的贸易点繁荣等级，默认 `0`。 |
| `weight` | 商品抽取权重。当前实现换算为 `max(1, 1000 / weight)` 张抽取票，因此数值越小越容易出现。 |

## 贸易点选择商店定义

贸易点定义通过下列字段声明可用商店：

```json
{
  "shop_definitions": [
    {
      "id": "cargoverse:default",
      "weight": 1
    }
  ]
}
```

- `id`：商店定义 ID。
- `weight`：该商店定义被终端选中的权重，数值越高越容易选中。
- 贸易点自然生成时，每个商店终端分别进行一次加权抽取。
- 抽取种子包含贸易点实例 UUID 和终端坐标，因此同一贸易点内多个终端可以得到不同商店定义。
- 选中结果写入商店终端运行时数据，存档重载、区块卸载和数据包重载都不会自动重抽。
- `shop_definitions` 为空时，终端不会获得商店定义，也不会生成商品列表。
- 管理员手动修改终端的 `tradePointId` 时，会依据目标贸易点定义重新完成一次绑定和抽取。

## 上架列表生命周期

商店终端不进行每日刷新：

1. 终端首次绑定贸易点时确定商店定义。
2. 从已满足 `required_prosperity` 的商品中抽取初始列表。
3. 列表容量直接读取贸易点当前繁荣等级对应的 `upgrade_list_count`。
4. 当繁荣升级使公共列表容量增加时，只向原列表追加新商品。
5. 已选商品不会因交易日结算、数据包重载或普通访问被替换。
6. 同一商店定义内不会重复抽取同一个商品索引。

若商店定义文件被修改并导致已保存索引越界，终端只移除无效索引，不会在容量未增加时自动补抽。

## 价格与共享库存

商品价格：

```text
最终价格 = 基础价格 × output_resources[cargo_type].sell_price_modifier
```

当前可购买份数：

```text
floor(output_cargo_units[cargo_type] / commodity.cargo_units)
```

商店与货柜出售终端共享贸易点的 `output_cargo_units`。例如：

```text
component output_cargo_units = 20
商品每份 cargo_units = 2
最多可购买 = floor(20 / 2) = 10 份
```

购买三份后：

```text
component output_cargo_units = 20 - 2 × 3 = 14
```

这一变化会同时影响绑定同一 `tradePointId` 的其他商店终端，以及出售相同 CargoType 货柜的终端。

## 服务端结算

客户端库存显示只是一份界面快照。结算时服务器会重新校验：

- 玩家仍打开对应商店菜单；
- 目标区块和终端仍有效；
- 许可证与繁荣等级；
- 货币数量；
- 各 CargoType 的共享产出库存。

购物车包含多个商品时，服务器先按 CargoType 汇总：

```text
所需库存[type] = Σ(商品 cargo_units × 购买份数)
```

所有类型同时满足后才会原子扣除。任何一种库存不足时整车交易失败，不会部分扣除。出货口仍有未领取商品时也不能再次结算。
