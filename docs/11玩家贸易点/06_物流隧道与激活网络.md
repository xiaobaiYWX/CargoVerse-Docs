# 物流隧道与激活网络

贸易点由管理核心激活的实体物流网络确定设备归属，不再逐个使用连接器远程绑定。注册、激活和可交易是三个不同状态。

本页描述已落地的操作规则。待确认、待实现及实机验收事项集中见[物流后续事项](../设计草案/待完成事项清单.md#物流与终端细化)；固体、液体（含气态 Fluid）业务和终端自有区域已接入，生物业务尚未开放。

## 搭建与操作

1. 放置“贸易点管理核心”（注册 ID 仍为 `cargoverse:player_trade_point`），通过 AUTH 界面注册到自己名下。默认每位玩家可注册 3 个，按 UUID 跨维度计数。
2. 使用“贸易点物流隧道” `cargoverse:player_trade_logistics_tunnel` 将核心与功能设备相连。它是独立方块，支持平面连接和固定轴斜上／斜下连接，不能直接上下连接；使用专用模型和贴图，不具备 Create 管道的流体接口，也不与原生管网互通。临时配方仍为一根 Create 流体管道加一个红石粉。
3. 点击管理核心绿色 PWR 按钮激活；不要求先搭齐所有业务设备或安装结算器。点击红色 STOP 解除激活，清除派生的设备归属。
4. 有效范围内的功能设备由服务端写入贸易点 UUID 和继承的所有者信息。核心保存报价、授权和结算账户，原生内容仍留在 Create 仓库。
5. 玩家正常放置的设备记录放置者；他人放置的设备不会因接通而自动认领。所有者用连接工具确认接入，六类大型终端可点击任意成员，但实际接入口必须邻接唯一已占用网络；工具不能绕过隧道远程绑定。外围区域标记杆只显示主终端派生的归属，不作为接入确认入口。

六类大型终端仅允许画有接入口的底层背面连接物流隧道，不再接受其他成员、上层或其他朝向的墙面。核心从自己的专用入口开始检测网络，功能终端本身不传导网络。具体成员如下（左右按终端正面视角）：

| 设备 | 接入口所在成员 | 允许方向 |
| --- | --- | --- |
| 贸易点管理核心 | 底层右侧 | 背面 |
| 玩家装载终端 | 底层后排中间 | 背面 |
| 玩家卸载终端 | 底层后排右侧 | 背面 |
| 仓库管理终端 | 底层后排中间 | 背面 |
| 玩家贸易点信息柜 | 底层左侧 | 背面 |
| 玩家贸易点航标塔 | 底层左侧 | 背面 |

表中方向随方块朝向旋转；普通平面隧道及斜向节点的平面端口均遵守同一限制。货物收发器保持现有接入规则；区域外围标记杆不再有物流接入口。

装载、卸载终端顶部后排右侧长杆占据第三层成员位置，使用细杆碰撞，叠加与普通杆相同的旋转模块。长杆是装卸区域的主标记点，逻辑角点位于其正下方的底层位置；再配三根同类外围杆成区，不能将顶部高度用于区域计算。长杆本身不作为物流入口。新放置终端会检查并创建该占位，正常拆除长杆或任一成员均清理整机；已有开发世界终端需拆下重放补齐占位。

仓库管理终端采用同样的长杆占位与地面角点规则，配三根绿色管理杆形成独立区域，装卸共用；不再借用公共装卸机区域。区域与杆仅是终端的激活零件，核心不检查区域状态，缺少区域时仅由本台提示并禁止装卸。

装载机、卸载机、仓库管理终端和信息柜允许同核心多台，端点集合总量仍受网络 128 个端点上限约束；航标塔暂保留一台。各台只操作自己的区域并保留独立选择，共享原生库存、核心报价及权限；提交时串行复核，货柜待确认占用不能被免费管理装卸绕过。不引入跨终端自动排程。核心实时摘要不携带完整端点地址集合。

## 平面模型拼接

- 核心按相邻连接选择直通、转角、三通或四通，模型只绕竖直轴旋转。
- 无连接时使用直通与两段中断接口，朝向轴由放置方向决定；单端连接时使用直通，另一端保留中断接口。
- 隧道互联处使用连接法兰补足相邻核心的空隙，每个方块绘制自身侧的连接部件；与受支持终端水平相邻时同样补法兰。
- 转角／三通／四通只在实际开口方向添加法兰，核心自带的封闭侧不再叠加中断接口。
- ACTIVE 状态切换侧面工作贴图，物品栏使用单独导出的完整模型；选择及实体碰撞范围跟随核心、法兰和封口轮廓。
- 平面功能保持不变；遇到有效的高低邻接时自动使用下述斜通和过渡节点模型，不旋转普通直通模型冒充坡道。

## 斜通与过渡节点

斜通参考动力铁轨，每前进一格水平距离升高或降低一格，支持东／西／南／北四种上升方向，同一路径可以双向传导，不是单向输送带。直接上下堆叠仍不连接，斜对角也必须有对应的坡道布局和互相匹配的端口，不能任意跳接。

朝南上升两格的完整示例（坐标相对下节点）：

| 方块 | 相对位置（X, Y, Z） | 模型与连接限制 |
| --- | --- | --- |
| 下端外侧普通隧道 | 0, 0, -1 | 可从这一格开始转弯或分支 |
| 下过渡节点 | 0, 0, 0 | 南侧斜接，其余三个方向可平接、转弯或分支 |
| 第一格斜通 | 0, 0, 1 | 朝南升高，无普通法兰或中断接口 |
| 第二格斜通 | 0, 1, 2 | 继续沿同轴升高，无侧支 |
| 上过渡节点 | 0, 2, 3 | 北侧斜接，其余三个方向可平接、转弯或分支 |
| 上端外侧普通隧道 | 0, 2, 4 | 可从这一格开始转弯、三通或四通 |

- 按上述位置铺设同一种隧道方块，邻接更新自动判定斜段及两端节点，不自动生成额外方块、不另收取连接件物品。
- 支持逐段从低往高或从高往低铺设。继续向上放置时，原上端节点若没有侧向分支、同层前向隧道及上方遮挡，会自动成为中间斜通；有分支或遮挡则保留原连接，不强行覆盖，移除限制后再判定。
- 斜通使用完整专用模型，不叠加普通法兰、中断接口或独立节点衔接件。进入核心有效激活路径时切换 `logistics_tunnel_oblique_on`，失去有效路径时恢复普通贴图。
- 上／下节点按实际开口使用普通直通、转角、三通或四通核心。每个连接方向添加普通法兰，斜向侧再叠加专用衔接件；孤立单口的背面添加中断接口。上下衔接件使用同一导出模型及相同位置／高度，只水平旋转，不竖向镜像。
- 只有斜通本体锁定沿坡道的水平轴、不能侧接。两端节点可直接转弯、分支或平接功能设备，不必额外外延一格普通隧道；每个节点仍只保留一个斜向接头，其他开口为平面连接。
- 已有转角／分支的平面布局不会被强行转换为坡道。先移除冲突支路或调整坡道落点，不能用爬坡绕过无分支约束。
- 坡道需要上方净空，不能把新隧道直接放进下方斜通的模型占用空间；通过命令等强行阻挡后，该斜通不可用于有效路径。
- 斜通本体保持轴向；上下节点发现相邻斜段已被拆除后自动退回平面布局，移除斜向接头，原方向可重新连接同层隧道，无需拆下节点重放。相邻区块未加载时暂保留节点身份，避免把卸载误判为拆除；区块加载后重新核验。

模型、双向网络寻路、归属确认、断线和改线权限共用端口规则。业务终端和收发器只接入普通平面端口或过渡节点的平面外侧，不接入斜通侧面或节点的斜向接头。收发器本身仍可六面附着仓库，具体隧道接入口必须满足上述约束。

方块状态使用 85 种有效布局与 ACTIVE，共 170 种（17 种平面、4 种斜通、64 种端点布局各两态），不把四向开关、斜向、朝向等属性作无效组合。相邻更新通过短延迟的计划 Tick 收敛，不新增方块实体或全体隧道的常驻 Tick。节点布局随有限拓扑持久化；跨未加载区块保留几何信息用于占用预留，但不开放业务。

## 距离与数量边界

服务器 `cargoverse-server.toml`：

```toml
[playerTradePoint]
maxPerOwner = 3
logisticsRange = 32
logisticsWorkPerTick = 512
```

`logisticsRange` 为最短路径经过的隧道格数，默认 32，可配置 1～128。直接贴核心的第一格隧道计为 1；设备接在第 32 格隧道旁时可被默认范围覆盖。斜通和过渡节点每个方块仍计 1 格，不按斜线长度折算。不是直线半径，分支和环路不增加剩余距离，也不能通过大终端跨越距离。

单次网络搜索最多 4096 个隧道节点、128 个候选设备控制器，超限拒绝或暂停路径可用性，不部分提交超限搜索。装载、卸载、仓库管理终端及信息柜允许多台，各自操作本地区域；航标暂限一台。每核心另有 3 个保险库、5 个普通储罐名额，不提供跨终端自动派单。

## 核心优先占用

- 激活时占用有效传播范围，不把范围以外的整条物理隧道永久划为私有网络。
- 核心处于另一个已激活贸易点的覆盖范围时，不能激活，原有注册、报价和建点名额保留。
- 解除激活后释放覆盖，其他核心可重新尝试。
- 新放置的物流隧道若将两个不同 UUID 的已激活贸易点接通，只破坏这次新放的隧道，并按原版方块破坏规则掉落一个隧道物品；不拆除已有线路、不停用两边核心、不转移原有设备归属。同一玩家名下的不同贸易点也适用。
- 判定只沿真实匹配的平面／坡道端口，终端只计算其专用接口。普通墙面、单纯靠近、上下堆叠不会触发；同一贸易点的分支／环路和未激活核心不构成双网络冲突。
- 放置冲突先阻止新隧道被网络认领，在安全的服务端更新阶段执行原版破坏和掉落，并向放置玩家提示。不会同时取消放置并生成掉落物，避免重复返还；领地等其他规则已取消的放置不会另行掉落。
- 破坏前先在排除待处理连接块的情况下核验旧网络归属，再复核冲突；同一 Tick 内先切断旧线、使支路释放后再接入另一贸易点，不会被旧归属缓存误判。此复核只在有待处理冲突时执行，并非全网增量重算或新增常驻隧道 Tick。
- 短周期批量铺设时也检查新隧道之间尚未分配归属的连接，扫描最多 4096 个已加载节点，不强制加载区块。已有占用边界仍作为保护，不因这一规则追溯破坏旧线路或自动合并贸易点；普通设备不充当核心之间的中继。

## 断线与生命周期

隧道放置、拆除、邻接变化、区块加载／卸载会使相关拓扑排队核验。普通改线只暂停依赖该处变化或无法证明安全的终端；持有未受影响路径证明的其他终端可以继续业务。区块状态、范围配置、重新激活及核心竞争等全局失效仍暂停相关网络。核验后只停用真正失联的端点，不承诺备用路径切换期间完全无间断。归属清理和重新接入在服务端更新阶段完成；库存查询与存档序列化不触发世界拓扑修改。

- 断线后只有失去全部有效路径的设备停用并清除归属；存在范围内备用路径时保留可用性。
- 重新接通后，激活核心自动发现并恢复接入，不必重新逐台绑定。
- 拆除、注销或解除激活核心，清除整个网络的派生归属，不删除原生物品、流体；解除激活也不删除核心报价和授权。
- 未加载区块不强制加载。旧拓扑仅用于保留归属／占用；穿越未加载部分的路径不可执行业务。恢复加载后重新核验，旧方块 UUID 不能绕过当前网络索引。
- 已接入隧道沿用所有者拆除保护，紧邻已占用网络扩建隧道也仅限所有者；关闭网络后不保留占用。管理员不获得修改拓扑的权限。领地与爆炸等外部保护仍独立。
- 核心、隧道和设备在 Sable 上均不能组成可用贸易点网络，不做坐标投影。核心身份与名额、Create 内容不因此丢失；断开的派生设备归属需返回静态世界后重新激活接入。

## 业务与第一版边界

注册不等于激活，激活也不等于所有业务均就绪。交易仍检查结算器、实际库存和本次装卸机／区域；某条支线断开不应注销核心或清空其他仓库。管理装卸仍免费，公共交易仍正常结算。

装卸区域由主装卸终端与三根同类杆形成，归属和业务可用性跟随该终端；外围杆不能独立成区、不能接隧道。区域宽深为正方形边长 2～18 格，高度仍为边长一半向上取整。断网保留几何但停用业务；主终端或外围杆拆除会解散区域。同类终端可多台，各自检测自己的区域，不提供跨终端自动排程。

通道仅约束可达性，不保存途中货物，不模拟逐格输送、速度、堵塞或跨类型介质混合。物品使用保险库原生槽位事务，液体使用普通储罐的提取／注入回执；均复用网络归属和路径校验。气态 Fluid 使用同一液体仓库；生物围栏仍待专项接入，不因连通网络就视为已经实现。

`PlayerTradeLogisticsNetwork` 按维度持久化有限拓扑与占用；运行时可用路径不直接从存档恢复，而是重新核验。管道不使用方块实体，不逐 Tick 对所有端点搜索；按空间索引处理拓扑事件。客户端只收到普通隧道方块状态和原有终端摘要，不广播整张网络图或整仓内容。

改线采用“已证明安全的局部核验＋复杂情况完整搜索”，共用版本号、工作预算及同一提交入口。现行约束如下：

- 以实际访问的隧道、前沿位置、设备成员及其几何邻域建立关注索引，不再因同一区块内任意设施事件就重建范围内所有网络。同位置重复事件去重，邻近位置汇总到同一网络待办；没有运行中的草稿时，整批变更合并为一个版本。
- 每次发布或释放只差量替换本网络的占用、位置关注和区块关注项，保留其他网络贡献。完整索引初始化仅在读取存档时进行；范围配置变化使相关网络重新核验，不先重建所有索引。
- ACTIVE 仅同步工作态外观，不触发邻居形状更新；避免已核验的线路在亮起时反向请求重复重建。
- `logisticsWorkPerTick` 默认 512，允许 16～65536，全服务端所有维度及网络共用。访问一个搜索候选位置、处理一个隧道工作态更新或检查一次待办核心计一个工作单元；空位、重复候选也计数，避免只统计成功节点或连续跳过卸载核心而绕过预算。各网络以最多 64 单元的小片轮转，维度顺序按 Tick 轮转；反复查询、点击激活或手动调用服务不能重置本 Tick 额度。
- 草稿保存队列、最短距离、候选端点及版本号，跨 Tick 续跑；期间再次改线、相关区块变化或范围变化会作废旧草稿。草稿不写设备归属，不向存档或客户端发布。完成核验后同步提交归属与本网络索引，隧道 ACTIVE 外观更新同样进入预算队列，可能稍晚于逻辑恢复。
- 每个已确认终端保存一条实际可用的路径及其设备／几何依赖。普通改线立即暂停依赖被触及或没有证明的终端，未受影响的终端保留可用性；有备用路径的受影响终端必须重新核验后才能恢复。大网络的激活请求可以进入待核验状态，不代表按下按钮的当 Tick 就完成接入。并发激活相连的核心按先后顺序确认，不能借分 Tick 核验绕过核心占用。
- 待破坏的冲突连接块不会被草稿认领；先核验改线后的归属再复核破坏，未确认的旧归属不用于提前破坏新隧道。预算用尽会延后处理，而不绕过额度做一次同步重建。

这是节点工作量预算，不是严格毫秒上限：原生区块装载时的隧道布局检查、放置冲突的有限扫描、端点绑定及单网络索引提交仍是有界同步操作。高负载下仍需实测这些阶段；没有将常数上限等同于服务器承载承诺。ACTIVE 已切换工作贴图，独立故障材质、完整路径与故障位置界面仍待细化。

### 局部重算与正确性边界

- 完整核验发布时，根据**全部互相匹配的隧道边**确认拓扑是否是单根、全程已加载的树；仅持有 BFS 父节点或搜索树不足以获得局部权限。环形图即使能生成完整父节点表，也不会被误认作树。
- 同核心平面树上的终端增删、末梢延长／修复及小分支断开，先尝试局部核验。当前硬边界为一批最多 16 个相关变更位置、局部最多 64 个隧道节点、最多 256 个探测位置；超出即回退，不为追求命中率放宽正确性。
- 切断旧树边后，先定位可能失联的部分，再逐点检查当前世界中的端口、周边新线和回接。只有确认不存在其他出口时才能释放孤立部分；不会直接按“搜索树下游”删除节点或端点。
- 新末梢只允许一条旧网接边。新环路、两个旧网接点，或从两处回到同一个旧节点，都属于替代路径／环路，回退完整搜索并重算最短距离。旧网络本来有环、涉及坡道／过渡节点、未加载区块、核心占用或其他不确定情况，也走完整搜索。
- 局部探测和局部可达性搜索都消耗同一个全服 Tick 额度；再次改线会废弃探测或搜索草稿。未被改线触及的独立路径证明可以继续使用，包括完整搜索回退期间的安全支线；受影响的路径先暂停，不能借旧 UUID 绕过。
- 局部结果复用未受影响的距离和端点，仅从已确认边界重新搜索变更部分，仍经过原有权限、数量上限、归属及存储绑定检查。候选结果在提交前不改写归属，不复制任何库存。
- 拓扑证明、路径证明及局部计划都是运行时缓存，不写入存档、不向客户端同步；加载存档后先完整核验。局部提交会重建当前有效的关注位置，避免保留历次改线留下的无效关注集合。路径缓存只保存实际路径节点，不为每个终端重复保存整条路径的几何邻域。

这是一条保守的局部快路，不是任意动态图的全增量算法。快照整理、图证明生成及本网络的索引差量提交仍有有界同步成本；完整搜索是正确性保障，不作为待删除的旧实现。

代码职责分为 `PlayerTradeLogisticsTopology`（只读图与路径证明）、`PlayerTradeLogisticsLocalRepair`（预算内现场核验，不写归属）和 `PlayerTradeLogisticsNetwork`（调度、完整／局部搜索及统一发布）。两条路径没有独立维护第二套库存或绑定事务。

### 运行诊断与调参

管理员命令 `/cargoverse logistics` 输出每个维度的网络／待核验／草稿数量、外观更新积压、事件总数／合并数／忽略数、重建开始／完成数、作废草稿与超限失败数、累计候选访问量、累计工作耗时、最慢工作片耗时、单网络索引提交次数和占用项差量。`checking` 不代表所有终端都暂停；`local=完成数/尝试数`、`fallback`、`localVisits` 和 `full` 分别显示局部完成、回退、局部访问量及实际创建的完整搜索次数，便于比较优化前后的完整搜索成本。`serverTick` 及其 `time`／`peakTime` 为全服共享工作量、额度及 Tick 内累计工作耗时／历史峰值，不是每维度各有一份；`lastTick` 保留上一 Tick 的工作量和耗时，避免命令执行在 Tick 尾调度之前只能看到零值。时间保留三位小数（ms）。统计仅存在服务端内存，不额外同步、逐方块写日志或写入存档。

调参时分别记录空闲、同位置连点、密集改线、多网络同时变更及区块重载前后的计数差值，关注业务暂停持续 Tick 数、草稿反复作废及队列是否长期积压。默认 512 是根据专项合成场景选取的保守初始值，不是整合包实服压测结论；实际多人验收后再增减预算。低预算专项以 64 单元强制跨 Tick，覆盖大图续跑、小网推进、再次断线、修复、查询只读和跨维度共用额度。

## 验证

网络专项可单独运行：`gradlew runGameTestServer "-PgameTestNamespaces=cargoverse_logistics,cargoverse_logistics_budget"`。原有同步功能夹具使用独立批次的大额度，避免批量构造线路时互相抢占预算；预算专项使用 64 单元、局部专项使用 32 单元验证真实异步约束，不通过跳过调度或远程绑定构造已就绪设备。局部专项覆盖终端增删、末梢延长／修复、断开一支保留另一支、超过局部上限的回退、环路替代路径和同一锚点的双回接；完整回归包含上述专项，日常仍按改动范围选择测试。

美术导出目录可通过工程工具 `node tools/import-logistics-tunnel-models.cjs <导出目录>` 重新同步；工具导入平面及斜向模型，重写纹理路径，生成 multipart 和工作态材质；上下端使用同一衔接件几何，不生成镜像模型。衔接件导出 JSON 的旧贴图引用按对应 BB 工程修正为专用 `logistics_tunnel_oblique_fixture`。资源测试枚举平面组合及四向斜段／节点附件，世界测试覆盖上下坡、端点直接转弯／分支、斜通锁轴、断线与修复；不代替客户端外观验收。

客户端坡道接缝和碰撞手感、复杂区块边界的实际卸载／重载、多人频繁改线及大量网络性能仍需实机验收；不能使用直接竖直连接替代坡道。
