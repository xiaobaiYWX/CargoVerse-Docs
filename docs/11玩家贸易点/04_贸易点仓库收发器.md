# 贸易点仓库收发器

注册 ID：`cargoverse:player_trade_vault_receiver`。每个贸易点最多连接 **3 个 Create 物品保险库多方块结构、5 个 Create 普通流体储罐多方块结构**，两种名额独立。每个结构使用一个收发器；仓库本身不响应终端连接工具。

## 使用

1. 在 Create 物品保险库或普通流体储罐外表面放置收发器，支持六面附着；不接受创造储罐、锅炉库存或其他存储方块。
2. 只可从收发器模型正面（本地北面，随 FACING 旋转）连接物流隧道；背面附着仓库，其他面不提供接口。六面附着保留，但朝上／下时正面竖直，当前隧道不支持竖直接口，因此不会接入网络。连接管理核心并激活后自动接入。同维度、静态世界，默认最多经过 32 格隧道；不是直线半径，详见[物流网络](06_物流隧道与激活网络.md)。
3. 绑定后使用亮起贴图；解绑后使用未激活贴图。亮起只说明已绑定，不保证当前区块加载或仓库没有冲突。
4. 切断对应隧道支线后释放失联收发器及仓库名额，保留其他有效路径；核心 STOP 解除整个网络激活。连接工具只诊断／确认接入，不再远程解绑；授权管理员不能修改拓扑。
5. 使用仓库管理终端 SET 切换固体／液体仓库：固体可以编辑商品和管理装卸；液体当前只查看原生流体库存、容量与表面仪表，不开放液体报价或货柜装卸。自动化直接连接 Create 保险库／储罐。

核心仍保留业务组件及收发器指示灯，但不要求先搭齐才能激活。物品交易要求可用保险库，液体业务要求可用普通储罐；只连接储罐也可激活与营业。收发器质量为 1000 Kpg，不保存实物或流体。重复连接同一原生结构会拒绝；达到对应类型上限时不再接入更多仓库。

## 拆分与合并

只保存收发器和其背后附着方块的位置，不把 Create 控制方块地址当作永恒仓库 ID。

- 每次访问从附着方块解析当前完整保险库或储罐，不固定保存旧控制器坐标。
- 拆分后只跟随收发器所在分体，另一组内容不计入库存。
- 同贸易点的已绑定仓库合并后按当前控制器去重，库存和容量只统计一次；原连接继续占用名额，防止再次拆分后绕过上限。
- 不同贸易点已绑定的仓库合并时，冲突结构不进入任何一方的可用库存，解除竞争绑定后恢复；其他无冲突结构不受影响。
- 附着方块被移除后，收发器按附着方块规则掉落并解绑；其他成员的重组交给 Create。不转接最近仓库。

## 不加载与 Sable

绑定和使用要求目标完整结构已加载，不创建区块票据。未加载连接仍占用名额，恢复后重新解析。收发器、核心或目标库存处于 Sable 时不可绑定／使用，不做移动坐标投影；不清空 Create 内容。

## 实现边界

`PlayerTradeStorageSavedData` 保存按核心、类型分组的收发器／附着点／维度索引。核心保存多收发器成员列表以参与连线、生命周期和解绑。`PlayerTradeVaultInventory` 聚合最多三个原生 `IItemHandlerModifiable`，复用槽位事务回执；`PlayerTradeFluidInventory` 观察最多五个原生 Create 普通储罐，按流体和完整组件分组，数量为 mB；`TankFluidTransfer` 在核验整笔计划后执行提取／注入并保留本次触及槽位的回滚回执。不接入任意第三方 IFluidHandler。观察缓存最多 10 Tick，结构解析不强制加载，完整组件不随显示行广播。没有自建库存副本。
