# 玩家贸易点：库存、报价与结算

## 1. 聚合库存

玩家贸易点按货物类型维护一条库存记录，不按每批货物分别保存。每种货物的固定库存上限为 **5000 单位**，记录内容包括：

- 当前数量；
- 整体平均完整度；
- 单位收购价和单位售价；
- 保留数量与收购目标；
- 最低收购完整度；
- 收购、出售是否启用。

存入货物时按数量对完整度进行加权平均：高完整度货物会提高库存质量，低完整度货物会降低库存质量。库存清空后完整度恢复为默认满值。装载给货柜的货物使用仓库当前平均完整度。

## 2. 出售配置

出售配置由单位售价和保留数量组成：

```text
实际可售数量 = max(0, 当前库存 - 保留数量)
```

- 保留数量范围为 `0..5000`，默认 `0`，即不保留、库存均可出售。
- 出售模式的商品列表只显示仓库中已有库存的货物。
- 单位售价是非负整数，不受 5000 限制。

## 3. 收购配置

收购配置由单位收购价、收购目标和最低完整度组成：

```text
剩余可收购数量 = max(0, 收购目标 - 当前库存)
```

- 收购目标范围为 `0..5000`，默认 `0`；目标为 `0` 时不建立收购额度。
- 收购模式可以配置全部可用货物，不要求仓库中已经存在该货物。
- 最低完整度范围为 `0..100%`，低于阈值的货物不能卸入贸易点，避免低品质货物污染聚合库存。
- 单位收购价是非负整数，不受 5000 限制。

玩家贸易点的资金来自真实结算器余额，因此单位售价不要求高于单位收购价；经营者可以自行承担由价格关系造成的盈亏。

## 4. 公共交易

### 其他玩家购买

公共装载机只提供已启用出售、具有可售数量且与当前货柜兼容的货物。交易成功后：

1. 从购买者的 VB 中扣款；
2. 向核心终端中的结算器入账；
3. 从贸易点库存扣除货物；
4. 以仓库平均完整度写入目标货柜。

### 其他玩家出售

公共卸载机只处理货柜内已有货物。交易还必须满足收购已启用、未超过收购目标、未超过总库存上限、达到最低完整度且结算器余额足够。交易成功后：

1. 从结算器余额扣款；
2. 向出售者支付 VB；
3. 从货柜移出货物；
4. 将货物按数量和完整度合并进贸易点库存。

实际收购付款会按交付货物完整度折算；完整度阈值决定是否接收，完整度本身仍会影响最终收入。

## 5. 管理者仓库装卸

玩家仓库终端为所有者和授权管理员提供不经过货币结算的内部装卸：

- 所有者或核心终端授权的管理员可执行；
- 使用贸易点已绑定的装载区域或卸载区域识别货柜；
- 不受公共出售开关、保留数量、收购开关、收购目标和结算器余额约束；
- 仍受货物兼容性、货柜容量和每种货物 5000 单位库存上限约束。

这一路径用于补货和回收自有货柜，不属于玩家之间的买卖。

## 6. 库存归属、迁移与永久清空

实际库存保存在玩家仓库终端，而不是核心终端或可携带物品中。这保证了货物只能经由世界中的物理货柜和装卸区域运输，不能通过拆下终端并放入物品栏的方式绕过运输系统。

- 仓库解绑或原核心被破坏时，库存继续留在原仓库终端中。
- 仓库重新绑定到新核心后，新贸易点直接使用该仓库已有的库存、平均完整度和交易配置。
- 只要任意货物仍有库存，仓库终端就拒绝被破坏；空配置本身不会被当成货物。
- 库存管理 GUI 左上角提供垃圾桶按钮，仅所有者可用。玩家必须将鼠标保持在按钮上并持续按住 5 秒；松开、移出按钮或关闭界面都会取消。
- 确认后会永久销毁全部抽象货物以及对应的出售、收购配置，并把仓库终端页码、装卸模式、选择项和数量设置恢复为初始状态。该操作不会生成物品、货柜或任何补偿。
- 清空完成后会同步刷新仓库表面 UI、信息柜与地图商品摘要；GUI 会立即关闭，避免旧输入重新写回已经清空的配置。

连续按住时间由服务端会话再次校验，客户端不能通过直接发送一次确认请求跳过 5 秒保护。
