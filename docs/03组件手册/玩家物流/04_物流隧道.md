# 物流隧道与本地仓储访问

物流隧道是 CargoVerse 内部共用的物品、流体及生物物流线路，只证明设备到仓储接口的真实可达性。它不保存运输中的内容，不模拟逐格移动、堵塞或不同介质混合，也不决定贸易点归属。

## 接入

交易终端经自己的唯一接口连接隧道，保险库、普通储罐和围场核心均经独立物流隧道入口接入，容器本身不直接接隧道。终端之间可以接在同一线路上，绑定到不同站点也不会冲突；各台在自己的最大路径距离内查找仓储。终端不作为跨越本体的管线捷径。

| 设备 | 有效物流接口 |
| --- | --- |
| 玩家出售终端（镜像模型） | 底层后排右侧成员的外侧，接口朝模型东面 |
| 玩家收购终端 | 底层后排左侧成员的外侧，接口朝模型西面 |
| 仓库管理终端 | 底层后排中间的背面 |
| 围场核心 | 左侧底层中部接口只安装独立入口，不直接接隧道 |
| 物流隧道入口 | 模型北面；背面附着原生仓库 |

方向随设备旋转。核心、航标塔和信息柜只需在 GUI 绑定站点，不接入物流线路；入口外侧的独立链接器显式记录终端，不绑定核心或独占某个仓库。

## 平面与坡道

平面按实际开口拼接直通、转角、三通、四通、连接法兰及中断接口。无连接时为直通加两段中断接口；管线互联处补法兰。

管线不能直接垂直连接。斜通每前进一格水平距离升降一格，四个水平方向均可双向通行。斜通锁定轴向，不侧接分支；两端节点可转弯或分支，按普通核心、法兰和斜向衔接件拼接。上下衔接件使用相同导出位置，只做水平旋转。

向上或向下逐段铺设均可延伸连续坡道；分支或净空冲突时保留原布局。破坏斜段后，相邻节点恢复平面开口；相邻区块未加载时保留几何，加载后核验。斜通本体使用专用模型，不额外叠加法兰或中断接口。

## 距离与内部安全预算

服务器 `[playerTradePoint].logisticsRange` 默认 32，可配置 1～128。距离从每台访问设备的接口开始，按最短路径经过的隧道方块计数；第一格计 1，坡道每格也计 1。与站点 GUI 绑定的 `bindingRange` 无关。

保险库和储罐均无独立玩法数量配额。为防止巨量连接，内部采用以下技术预算：

- 每台视图最多访问 4096 个隧道节点、128 个仓储端点；超限使整个视图不可用。
- 原生多方块验证累计最多 8192 个方块，物品合并视图最多 16384 个槽位；不逐件或逐 mB 扫描。
- `logisticsWorkPerTick` 默认 512，可配置 16～65536，全服务端与所有维度共享；搜索和管线工作态更新都消耗预算，各视图按最多 64 单元轮转，查询不能重置本 Tick 预算。
- 搜索和关注位置仅是运行时缓存，不保存整张网络或库存。长时间无人使用的视图会回收。

这些是技术安全边界，不代表服务器承载保证。达到边界时不能依靠部分结果继续成交。

## 改线与生命周期

每台设备持有自己的有界可达视图；相关位置或区块变化使受影响视图立即失效，未核验路径不允许库存操作。实际转移请求会排入分 Tick 搜索，旧草稿被移除，不能迟到发布。相关位置关注索引按视图增删，不重新索引所有站点。

实际转移请求核验过的可达管线在缓存有效期间显示工作态贴图。多台设备共享某段管线时，工作态按所有有效视图合并；它不表示站点所有权。断线不清空商品设置、站点绑定、原生存储或其他站点账户。线路连接不进行跨核心竞争、端点认领或新连接块破坏。

库存浏览沿显式地址读取已加载容器，不创建隧道搜索；只有实际转移才要求路径核验。未加载区块不强制加载，无法确认的路径暂停转移。区块加载回调仅记录待核验区块，不读取世界接口中的自身或邻区；在正常服务端 Tick 中使用非阻塞的就绪区块查询，每维度每 Tick 最多处理 8 个待核验区块，并消耗共享工作预算。区块卸载会取消待办。随后重新调度管线几何，并通过同一工作预算清除没有有效视图支撑的旧工作态贴图，避免重启后残留亮起，也避免 FULL 加载回调等待自身完成而卡住存档。多个入口指向同一原生控制器时只计一次；原生拆分合并仍从实际附着点重新解析。站点所有者和管理员权限只保护终端操作，原生仓库及外部自动化遵循实际物理接入。
