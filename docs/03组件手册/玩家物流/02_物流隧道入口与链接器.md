# 物流隧道入口与隧道链接器

注册 ID：入口 `cargoverse:logistics_tunnel_entrance`；链接器 `cargoverse:tunnel_linker`。入口可独立放置，不因背后没有容器而掉落；不再使用旧收发器 ID。

## 使用流程

1. 手持链接器右键出售、收购或仓库管理终端任一成员，记录终端的维度、控制器位置与设备 UUID。需要该终端的管理权限；无归属终端允许附近玩家配置。设定后提示“频率已设定”，物品显示附魔光效；手持时在当前维度已加载、64 格内的目标终端绘制闪烁外框。对空气右键清除手持物品的频率，不影响已放置的链接器。
2. 在容器相邻位置放置入口。模型南面背板朝向容器，模型北面接物流隧道；侧面放置时按该侧方向，地面／顶面放置时保持水平朝向玩家，避免将隧道接口朝上或朝下。
3. 将已配置的链接器作为独立方块放置在入口外侧。点击入口的顶面、底面或侧面，链接器朝外安装，占用相邻方块位置；不嵌入入口模型。链接器也可正常放置在其他位置，只有安装面紧贴入口时才接入其背后的容器。入口检测到已配置链接器时显示工作贴图。
4. 库存列表直接读取已显式连接的原生容器，断线时仍可浏览。实际装卸提交时才请求隧道连通核验；无法确认、断线、超出路径距离或超出安全预算时不允许修改库存。核验因共享 Tick 预算尚未完成时会提示稍后重试；不把该状态当作库存已满，也不通过浏览库存预热寻路。

一个链接器记录一台终端。同一终端可配置多个链接器和入口；一个入口也可在不同外侧安装多个链接器，使多台终端共享其容器。重复指向同一入口不会重复计算库存。站点归属仍在终端 GUI 选择，不由链接器或管线授予。

## 原生容器

物品走 NeoForge `Capabilities.ItemHandler.BLOCK`，流体走 `Capabilities.FluidHandler.BLOCK`，从入口背板接触的那一面访问，保留容器原有插入、提取及侧面限制。支持原版箱子、木桶、Create 保险库／储罐及其他正确实现通用接口的容器；不再要求物品接口可直接写槽，也不要求流体接口是单槽 `FluidTank`。

原版炼药锅直接复用当前 NeoForge 提供的流体接口，遵循其原生离散转移规则：完整水锅／岩浆锅按 1000 mB；部分水位可被识别，其可执行的填充、抽取量以接口模拟结果为准，不伪造连续液位。细雪不是流体货物。

Create 多方块仍按背板实际接触成员解析控制器并验证结构；同一控制器多个入口不重复计算，原版双箱同样去重。其他模组通过共享接口对象去重，不承诺识别所有模组自定义多方块。围场核心仅允许在左侧底层中部指定接口旁安装入口及链接器，不允许隧道直连；实体仍保存在实际围场中，交易提交时核验对应路径和剩余容量。

## 生命周期与守恒

- 绑定索引只保存地址和 UUID，不保存库存副本，不为浏览或恢复绑定强制加载区块。
- 终端重命名、站点换绑不改变设备 UUID；拆掉终端后原位重放会生成新 UUID，旧链接器不会自动绑定新设备。
- 只有右键兼容终端会设定频率，其他方块走普通放置逻辑。放置携带已设定的同维度频率，不为此加载远端终端；库存访问时按当前设备 UUID 校验。链接器无空手取回操作，正常破坏或潜行使用 Create 扳手回收即可，掉落／回收的是未配置链接器，不保留旧频率。
- 拆除链接器立即移除其地址索引；拆除入口不会额外掉落或销毁周围的独立链接器，链接器保留在原位置但无法提供库存。拆除容器不破坏入口，容器恢复后重新读取，不修改容器内容。
- 区块加载只登记链接器地址，不查询相邻方块；入口工作贴图在正常服务端 Tick 中恢复，避免加载回调等待邻接区块。
- 实际转移先模拟，再通过原生提取／插入／填充／抽取执行，失败使用回执补偿。通用接口必须正确实现模拟与执行；内部技术预算见[物流隧道](04_物流隧道.md)。
