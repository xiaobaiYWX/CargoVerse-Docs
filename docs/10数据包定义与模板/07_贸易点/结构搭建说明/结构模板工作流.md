# 结构模板工作流：多视角概念图到 NBT

新建与重制统一执行本流程。原“普通／一般流程”和“高级流程”停止使用。制作顺序为：**完整贸易点效果图 → 按总图拆分建筑或建筑分段 → 派生局部参考与尺度校准 → 分别搭建 → 按总图逐处拼接 → NBT 交付**。整站效果图是统一设计依据，分拆制作服务于还原整体；不能先各自设计几栋建筑，再用连廊补成一个站点。

## 两种交付方式

| 项目 | 拼接模板 | 整体贸易点 |
| --- | --- | --- |
| 设计对象 | 从完整站点设计中拆出的建筑、建筑分段或构筑物 | 同一完整站点设计，按建筑或建筑分段分别制作后合成 |
| 功能组织 | 各模块分工明确，共享场地、通路和一处收发平台 | 营业、仓储、作业、观察等功能成为同一结构内的分区 |
| 概念图范围 | 先有完整整站效果图，再从中派生各模块参考；局部不得改变总图中的体块关系 | 同样先有完整整站效果图，再派生各建筑或分段参考，最终按总图组合 |
| 尺寸边界 | 每个单体包围盒 X、Y、Z 均不超过 32 格，包含屋檐、外梯、支点等全部构件 | 按尺度基准与功能推导整体尺寸，具体任务约束优先 |
| 主要交付 | `building_01.nbt` 等模块及 `cargo_platform.nbt` | `station.nbt`，包含全部主体、必要连接和实际共用平台 |
| 平台文件 | 本站独立平台参与实际拼装 | 同时保留本站 `cargo_platform.nbt` 供单独调整；加载整站时不重复放置 |
| 连接记录 | 各模块的局部原点、朝向、地坪标高、连接接口及建议相对放置关系 | 各单体在整站中的偏移、朝向、标高、连接接口及拼接方式 |

两种方式具有相同的图像、尺度、材质和外观完成度要求。拼接模块可以是房屋，也可以是吊机、雷达、塔架、池组、泊位或开放框架；整体贸易点也可以由几个相连体量围成院落，不要求做成一栋封闭大屋。模块数量与功能有关，不固定为四栋建筑加平台。

**交付方式、制作拆分与连接方式分别确定。** 两种交付方式都从整站总图拆分制作。一栋复杂建筑可以分成两部分建造，再紧密拼接回同一建筑；两个直接相接的建筑也可分别制作。图中有明显间隔的建筑则保留间隔，通过连廊或广场等连接。制作对象不必是一栋四面完整的独立房屋，不能因拆成两个模型就在总图原本连续的建筑中插入间距。整体贸易点的中间模型是制作素材，不自动增加存档中的交付文件。

制作任务先说明采用哪种方式。已明确要求按单体拼装时选择拼接模板；明确要求整站或一个大型主体承载本站功能时选择整体贸易点。未指定时根据功能联系与现场拼装需求选择并说明依据；只有选择会实质改变任务范围且无法判断时再澄清。

## 1. 从描述整理设计内容

读取本站 `00_总体说明.md`、`01_外观与装饰参考.md` 与 `02_` 至 `04_` 功能结构说明，先确认需要启用的业务，再整理空间设计摘要，后续汇入外观参考与相应功能页：

- 站点身份、使用场景、功能清单与营业入口；哪些内容需要独立空间，哪些可以合并。
- 本站所属制造商及其点缀用特征色：以总体说明中的 `manufacturer` 和关联制造商设定为依据，不按出售商品的品牌推断归属；主体材质与主色由建筑功能确定。
- 本站可辨识的轮廓、结构形式、材质与配色，以及应保留的特色构件。
- 人员路线、作业区、楼梯与高处通路，航空收发平台及飞行接近方向。
- 先整理功能与主要体量需求，生成整站效果图后再确定建筑及制作分段清单；继承既有结构时明确使用范围，不提前固定为几栋独立房屋。
- 生图前的尺寸预算：目标 X × Y × Z、不可越过的边界、各功能区的大致占地，以及门、楼梯、柱跨与楼层的初始尺度。拼接单体不得超过 32 格，不把上限只留给后续生成脚本处理。

每个贸易点必须有一处实际收发共用平台，保留齐平的 H 标识、设备空间、人员连接和航空净空。在概念图阶段就纳入设计，不能完成主体后才发现没有位置。普通院落、装配坞或检修挑台不自动等同于收发平台。室内家具、货物陈列和实际业务设备未要求时留待后续布置，概念图重点表达建筑与可用空间。

描述与尺寸预算用于首次整站生图；总图确定后再提取总平面，记录占地、朝向、标高、入口、平台，以及哪些部分直接相接、哪些建筑有明显间隔。先在总图中判断体块关系，再约定制作分界和接口；不能先选定“全部分离＋连廊”，再让效果图迁就该方案。布局计入屋檐、外梯、支架、广场与实际通行宽度，具体尺寸通过可信局部校准。

### 制造商归属与特征色

**功能决定主体材质，制造商颜色作为清晰可见的局部识别。** 概念图阶段先按建筑用途、结构形式与使用环境确定主体材料、纹理及主色，再读取所属制造商设定，适当增加品牌色元素的数量、重复节奏和可见面积。主入口之外，在主要立面、屋檐或门架饰条、局部设备框架、平台边缘等位置形成呼应，避免整站只出现一两块很小的色板。品牌色仍不代替主体材料，不将整面墙、整片屋顶或全部框架涂满。首次生图提示词明确这些识别部位，并在 NBT 中保留其分布；多视角、各拼接模块和本站共用平台沿用一致的识别方式。

| 制造商 | 已确定的代表色／局部识别方式 |
| --- | --- |
| [天穹联合工业（AUI）](<../../02_制造商/aui.md>) | 青色、浅灰、白色 |
| [铁壁防务集团（BDS）](<../../02_制造商/bds.md>) | 深绿、深灰 |
| [深岩矿业集团（DMC）](<../../02_制造商/dmc.md>) | 黑色、黄黑警戒 |
| [赫利俄斯能源集团（HEC）](<../../02_制造商/hec.md>) | 红色、黑色 |
| [地平线研究院（HRI）](<../../02_制造商/hri.md>) | 蓝色、灰色 |
| [遗民贸易协会（REX）](<../../02_制造商/rex.md>) | 无固定点缀色；按回收机构定位表现 |
| [云港物流集团（SPL）](<../../02_制造商/spl.md>) | 橙色、白色、深灰 |
| [绿洲农业联盟（VBS）](<../../02_制造商/vbs.md>) | 黄绿色、白色 |

代表色总表见[制造商设计](<../../02_制造商/README.md#制造商代表色>)。DMC 的黄黑警戒以局部条纹表现；REX 可保留回收材料原色与修补痕迹，不为其补造固定配色。

特征色用于入口饰条、标牌、局部面板、边缘或短段识别色带，不因制造商归属将整面墙、整片屋顶或全部框架统一染成品牌色。主体保留按功能选择的材料及其颜色；材料本色恰好与品牌色相近时可正常使用。警示线与 H 标识按辨识和功能需要设置。同一制造商旗下建筑保持一致的局部识别方式，主体材料、空间与轮廓仍随用途变化。后续新增制造商优先使用其已有设定；尚无明确特征色时，在本站设计摘要中注明本次拟定方案，不把临时选色写成已确定的品牌设定。REX 的“无固定点缀色”是已确定设定，不适用临时补色。

此要求用于后续新建与重制，不自动重着色既有 NBT、概念图或实际预览；现有版本仍按真实交付记录。

## 2. 生成详细且一致的多视角概念图

**先生成完整贸易点效果图。** 从本站功能、风格、材料与尺寸预算出发，先制作一张完整整站主参考板，建立统一轮廓、建筑主次、相对比例、屋面关系、场地和共用 H 平台。主要视角必须看清完整站点，必要的俯视或背面可集中在同板；总平面是从该图提取的搭建记录，不能代替这一步。已有明确指定且适用的完整效果图可以作为本次总图沿用。

整站提示词仍需简化：将完整功能清单归并为必要的主要体量，内部分类、业务终端、货物品种和次级房间留在设计记录中，不把每项功能都列成独立建筑。简化的是输入和画面杂项，整站构图、直接相接或分离的关系、共用平台与必要交通必须清楚。

**从总图拆出制作对象，再派生局部参考。** 先标出每个建筑或建筑分段在总图中的位置、形体、比例、朝向、屋顶和连接面。局部生图必须引用整站图及对应区域，要求忠实展开该部分；引用用途包含几何与连接关系，不能仅以总图的材质风格为参考重新设计一栋房屋。必要时保留少量相邻接触面以说明接口，不引入无关背景建筑。同一建筑的两个制作分段要保留共同轴线、楼层和连续屋面，切面按接口表达，不擅自补成两栋完整房屋。

**一张整站主参考，必要对象各一张局部参考。** 拼接模板与整体贸易点都采用此规则。总图中清晰、无遮挡且足以搭建的部分可直接使用，不为所有分段机械补图；确需展开的对象默认一张派生参考板，在同一次生成中安排必要视角与尺度局部。同款重复建筑共用参考。不同对象的局部展开不属于同一对象的多版重画，但都从属于同一整站设计，不默认再生成“尺度校正版”“后视补全版”或“最终整站版”。

**参考优先级：整站总图决定整体形体和连接关系，派生局部图细化对应部位，平面与坐标负责落地。** 局部图若新增侧翼、改变屋脊方向、把相连体量分开或缩窄原有间距，不采纳这些偏离；必要时只修正该局部，不能反过来挪动整站以迁就局部图。一般遮挡、内部隔间及可推导的支撑通过同一设计的空间关系解决；图片数字标错优先修正尺度记录与坐标，不为此反复生图。

**辨认构件，不逐像素转译。** 以清晰可辨的轮廓、柱跨、门窗、屋面和连续构造为依据；阴影、反光、材质纹理、零碎噪点，以及无法形成合理连接的扭曲部分不直接转成方块构件。先结合该单体的平面、重复节奏与支承关系判断，关键关系仍不明时才按下文补局部图。此取舍不能成为省略清晰檐口、框架、楼梯和外观细节的理由。

只有影响搭建的关键部位确实无法从主图和空间关系判断时，才引用主图补一张限定范围的局部图，说明它只回答哪个问题。补图不能改写整站轮廓、比例或无关构件；超出范围的变化不采用。若确需整体改版，明确选定一张新的主参考并将旧图标为历史，不从多个相互矛盾的版本各取一部分拼成新的设计。

**尺寸与尺度识别从提示词开始。** 每个结构的首次生图就明确目标包围盒和最大边界，并给出原版两格高门、三格宽楼梯或实际要求的梯宽、柱跨数与跨度、层数及地坪／楼层标高。先估算必要空间是否能在预算内成立，再生成效果图。避免仅写“紧凑”“小型”而让图片生成任意尺寸的复杂场景；已知尺度不足时先减少跨度或调整功能组合，不能等 NBT 阶段再整体缩小。

俯视或正立面应有可读的一格网格、整体尺寸线或尺度条，近景同时显示完整标准门、连续台阶、柱脚和栏杆等参照物。文字标注与可见方块数量须能交叉判断；生图工具可能同时画错数字、网格密度和几何比例，提示词写明尺寸也不代表图形已满足该尺寸。多视角使用相同的尺寸预算与基准构件。新增尺寸约束若晚于生图，应先修正受影响的概念图，再继续结构落地。

主参考板按实际需要组织以下视图内容，不将表格当作必须逐项另行生图的清单。优先保留一个清晰主视图，再安排俯视、必要背面或局部；同一板内也可能存在不一致，需要明确哪个视图决定整体形体：

| 视图 | 必须能够辨识的内容 |
| --- | --- |
| 前侧三分之四视角 | 主入口、主要轮廓、近景门窗、柱脚、楼梯与材质细部 |
| 后侧三分之四视角 | 背面、另一侧立面、附属构件及连接关系，覆盖主视图遮挡处 |
| 俯视／轴测俯视 | 总占地、体量位置、屋面、开放区域、平台与通路关系 |
| 尺度近景或正立面 | 同一平面上的门、台阶、柱脚、窗格和柱跨，足以推算方块尺度 |

复杂楼梯或支撑的关键局部优先安排在主参考板内；简单构筑物无需凑齐四种视图。**不同建筑各给一个视角的四分板，不算单栋建筑的多视角参考。** 画面拥挤时先减少重复视角、文字和次要元素，保持主视图可读，不默认拆成多轮生成的独立图片。

提示词明确以下信息：

- 整站图为同一个完整贸易点的必要视角；派生局部图为总图中指定建筑、建筑分段或构筑物的必要视角。注明总图对应位置，统一入口方向、体量数量、柱跨节奏、楼层、窗组、屋顶与楼梯位置。
- Minecraft 原版方块可搭建的几何、材质纹理和构件尺度；弱透视或正交视图用于读比例，近景保留可辨识门与台阶。
- 本对象的目标 X × Y × Z 与上限；给出门高、梯宽、柱跨数量、楼层标高，明确屋檐、外梯、基础、支点全部计入包围盒。
- 由建筑功能确定的主体材质与主色，以及本站所属制造商的识别色和可见分布；适当增加重复饰条、局部面板等元素，明确品牌色不覆盖主体。各视角与各模块保持一致的品牌识别，主体材料可随模块用途变化，不能默认套用上一贸易点的颜色。
- 明确本图对象和继承关系。整站图包含建筑、连接、场地与共用平台；局部图展示指定部分，连接侧露出接触面、门洞、标高或屋檐退让。同一建筑的分段边界不增设封墙和独立檐口，分离建筑之间的空地不被新增房间填满。
- 使用清晰光照与简洁背景，避免雾、景深、植被或车辆挡住关键结构；不靠影视质感掩盖几何。
- 按本站风格使用丰富原版材料，遵循[材料规范](<../README.md#建筑材料选择>)，不自动换成统一陶瓦墙和灰色框架。
- 大面积窗墙、温室和采光顶明确采用连续的玻璃块或玻璃板。提示词区分玻璃自身接缝与独立承重构件，不要求用铁栅栏在玻璃面内绘制密集窗格。

对照主参考板内的入口、楼梯、窗组、柱列、屋脊与平台位置。存在冲突时以选定主视图及可信局部尺度统一解释，并记录落实方式；不能因次要视图更清楚就改换整体构图。仅在关键背面、支撑或楼梯关系确实无法推导时按上文补局部图，不以通用房屋函数替代本次空间设计。

## 3. 尺度校准与尺寸范围

**生图预算不是测量结果，图片标注不是落地尺寸。** 无论图片是否写出完整 X × Y × Z，都必须在编写主体坐标及锁定 NBT 包围盒之前，由局部构件独立推算一次尺度。用户明确的硬边界与功能要求继续有效；在满足这些要求的方案中，以可辨识构件及经交叉核对的图形比例为依据，生成图中的数字、背景网格和提示词中的估计尺寸只作待核对信息。

按以下顺序完成一次简短校准，不追加全量逐块测绘：

1. **找可信局部。** 选取至少两类可辨识构件，例如正常两格高的门扇，以及能识别踏面与上升关系的楼梯或台阶。测量门扇本身，排除门框、门楣与上亮窗；台阶区分半格踏步与整格高差。不能因旁边写了“2 格”或“3 格”就认为图形可靠，也不把砖缝、材质花纹当方块边界。
2. **推算一跨及楼层。** 先在同一立面、相近景深内比较门高、柱宽、窗高、梁高和柱跨，再由重复跨度及端部构件推算整面墙。水平与竖向分别判断，不用门高直接给地面两个轴套同一个像素比例；跨景深比较须考虑透视。
3. **从单体推到整体。** 逐项得到主体、附属空间、平台和通路的合理尺寸，再根据俯视关系组合。至少核对主建筑与平台、营业楼与主厅、建筑与通路的相对比例；保留了两格门高，不代表整体比例已正确。功能规定的 25×25 作业面用于检查空间需求，不能直接宣称图中的 H 区已准确画成 25×25。
4. **处理标注或视图冲突。** 局部推算与标注不符时，修正落地尺寸并记录依据，不为保留图上数字压缩柱跨或扩大附属区域。不同视图推算不一致时优先使用局部清楚、透视较弱且能相互印证的部分；仍无法判断的关键部位才补局部图。仅数字标错无需重生成整张图；实际图形与用户硬边界冲突时，则调整跨度或功能组织并修正参考设计。
5. **最后确定包围盒。** 用各部分及必要间距的实际总和得出 X × Y × Z，再写主体坐标。禁止先把标注尺寸写入数组边界，再反向挤入所有空间，也不将整个方块模型统一缩放。

外观参考页保留几行尺度记录即可：局部锚点、推算的柱跨／楼层、关键相对比例、采用尺寸及舍弃原标注的理由。未确定的尺寸注明估计范围，不把参考图或交付文件的尺寸表述成已经证实的还原结果。

拼接模板的每个单体包围盒 X、Y、Z 均不得超过 32 格，屋檐、外梯、基础和支点计入边界；概念图阶段就按此安排柱跨与功能，不能生成大体量后整体压缩门和楼梯。整体贸易点不套用该单体上限。旧 16／48／64 格指标不作为统一设计目标，实际尺寸由图中构件尺度、功能和通路共同推导；需要调整时优先缩减多余跨度或重新组织功能，不为了容纳细节把门厅、柱子和整个站点一起放大。具体任务另有尺寸或落点约束时优先遵守，并在概念阶段协调。

参考案例：[飞艇总装坞尺度校准](<../factory/飞艇总装与航修港/01_外观与装饰参考.md#01-概念图还原实验>)从 79 × 48 × 123 调整为 53 × 33 × 83，重新排布门、楼梯与构件，保留整体形象。它说明需要先校准尺度，不是今后所有贸易点都采用这组尺寸。

**整站尺寸参考：**整体贸易点的单边参考值提高为 76 格，替代此前的 64 格参考值。76 格不是 X、Y、Z 每轴的硬上限，也不是必须达到的设计目标，不要求做成正方形。狭长、折线或局部退让的场地，可在其他方向较短时适当延长一边；按实际占地、功能联系和构件尺度确定比例，不为了填满包围盒扩张建筑。拼接单体每轴不超过 32 格的要求继续有效。

NBT 设计尺寸与游戏内保存工具能力分别处理。Minecraft Java 1.21.1 原版结构方块每轴保存范围为 48 格；较大的完整模板后续修改，应使用支持对应尺寸的导出方式，或分区导出后合并。若任务明确要求仅用原版结构方块逐件保存，应选用能满足保存范围的模块划分；不得把整站文件静默截断。

## 4. 按图建立平面、柱网与构件

整站形体、尺度和主要空间关系确定后，各建筑或制作分段分别建立局部原点、包围盒与独立方块模型，依据总图及其派生局部参考搭建。应能单独生成、平移或旋转一个制作对象，而不是只将写入同一全局数组的代码拆成几个函数。同一建筑拆成两段时，共享柱网、地坪和屋面基准，接口面按最终连续结构制作，不把每段都封成独立房屋。整体贸易点内部的制作拆分不额外套用拼接交付的 32 格上限；尺寸由尺度校准与整站预算确定。

逐单体保留从平面到骨架再到围护的搭建顺序：

1. **平面与标高：**把图中的功能区转换为坐标范围，确定入口、通路、楼梯、平台、楼层及开放空间。
2. **基础与框架：**建立柱网、梁、桁架和支承。大跨度、挑台与塔架按图中受力关系组织，保留空隙与构件厚薄。
3. **楼板与围护：**完成墙面、门窗、楼地面、屋顶以及真实可达的楼梯和落点。
4. **外观构件：**还原檐口、窗框、柱脚、护栏、灯具、铺装、标线和辨识度高的外露设施；这些属于本次外观还原范围，不以“只做主体”为由全部省略。
5. **内部预留：**保留必要隔间、楼板、结构支承与交通，未要求的家具陈列和业务设备继续留空。

### 构件完整性硬规则

以下规则在生成脚本写入 NBT 前执行，属于搭建过程本身，不增加导出后的重复校验轮次。

1. **灯具不得替换结构。** 柱、梁、墙、窗框、屋面和楼板先完成并锁定，灯具最后放置。吊灯只能占用原本为空气的格子，上方必须有独立吊点、链条或连续梁底；灯具坐标与柱梁相交时移动到相邻开间中心，不能用灯笼覆盖一格柱子或截断墙面。连续柱列上的灯位由相邻两根柱子的中点计算，不直接复用柱坐标。壁灯同样使用独立支座，不能挖掉墙体后嵌入。
2. **半砖交界必须先封口。** 半砖用于檐口、压顶、薄屋盖或踏步时，先用完整方块、楼梯、墙体延伸或同层背衬封闭它与整块墙、梁、屋面的连接。不能只在墙顶外侧铺一层上半砖或下半砖，让另一半格形成贯通缝隙。长屋檐至少抽查两端、转角、柱边和不同高度屋面交接；有意设置的通风缝必须在设计记录中明确，并使用连续、等高且有边框的构造表达。
3. **局部重复构件按轴线生成。** 同一立面内预期成组的窗、门、柱间墙、檐口和装饰带，先确定局部中心线、端柱及统一开间，再由同一组坐标推导左右构件。禁止分别手写两侧宽度或靠目测补最后一格。建筑整体可以不对称，但单个对称窗组、门廊、山墙或重复开间不得无设计依据地相差一至两格。
4. **先验证骨架，再放细件。** 生成顺序固定为承重柱墙与梁板、墙顶封口、门窗开洞、屋面和楼梯，最后才是灯具、护栏、标牌与短饰条。细件放置函数不得静默覆盖既有非空气方块；确需替换时必须在该构件代码中明确写出替换范围和原因。

对预期局部对称的区域，只比较该窗组、门廊或重复开间的局部坐标，不强制整栋建筑镜像。检查内容以占位和边界一致为主，材料做旧、品牌色点缀及功能造成的有意差异可以保留。

从图中建立“构件／部位 → 原版方块与状态”的材料对应关系，同时看颜色、纹理、形状和厚度。延续概念阶段按功能确定的主体材料与局部品牌点缀，不在落地时扩大品牌色覆盖面。使用 1.21.1 原版内容，后续版本专有方块不写入 1.21.1 模板。一般规范只排除铁块、金块、钻石块、下界合金块、绿宝石块与信标；明确授权的实验例外仅作用于该次任务。

**玻璃面不混入铁栅栏模拟窗框。** 大面积玻璃墙、长窗、温室围护和采光屋顶统一使用连续的玻璃块或玻璃板，按设计选择普通或染色版本。概念图中的细网格、拼接缝、反光线和玻璃纹理不能直接转译成铁栅栏，也不以固定间隔插入 `iron_bars` 增加窗格。只有明确的独立柱、梁、主屋架或外缘窗框才按结构尺度使用建筑材料，保持玻璃面连续；铁栅栏用于实际独立的护栏、防护网等构件，与玻璃面分开表达。复用旧脚本时不沿用混合玻璃与铁栅栏的窗面生成逻辑。此规则适用于后续新建和重制，不自动改写既有 NBT 或历史交付记录。

脚本可以复用 NBT 编码、放置、几何、纹理读取等基础工具，完整平面和立面必须由本次参考图决定。不得以更换颜色的通用房屋、固定四栋批量模板或默认灰色大盒代替参考设计。调整大小时重新排列离散构件，保持双扇门、楼梯、栏杆与窗口完整，不直接对整个方块数组缩放抽样。新脚本优先使用共享的安全吊灯、封口檐边、等距轴线与局部镜像检查函数；旧脚本中的无条件 `put` 灯具、独立手写窗段和裸露半砖边不能直接复制到新结构。

### 按整站效果图逐处决定连接并完成拼接

各制作对象完成后，回到整站效果图确认相对位置、间隔、屋脊关系和连接处，再按提取的总平面以明确偏移与朝向组装。连接方式在总图确定后逐处识别并预留，最终组装继续以总图为准。它不是整站二选一的标签：同一站点可以同时有紧密连接的建筑分段、直接相接的两栋建筑，以及由连廊或广场相连的独立建筑。

| 拼接方式 | 连接设计与搭建要求 |
| --- | --- |
| 紧密拼接 | 适用于同一建筑拆成两部分制作，或总图中两个直接连接的建筑。接触处无独立室外间隔，按图连续衔接地坪、柱墙、楼板与屋面；指定共享构件归属及必要内部门洞，分段边界不重复封墙或添加双层檐口。制作分界不应变成新的外立面，禁止用未经设计的整房重叠代替接口。 |
| 连廊或广场连接 | 适用于总图中有明显间隔、属于不同体块的建筑。保留各栋外壳及图示距离；有连廊时制作首层通路、支承与必要屋盖，有广场时保留开放铺地、人员动线与场地，不自动改成有顶连廊。有高差时按图设置台阶或落点，屋檐和外梯计入间距。 |

例如：营业主厅与侧翼可拆成两个模型后紧密拼接；该完整营业楼与仓库之间再以广场或连廊连接。不能因站内存在连廊，就把主厅与侧翼也拉开；也不能因一处紧密连接，就把总图中的院落和建筑间隔全部填满。

在外观参考页中用简短接口表记录：相连单体、拼接方式、摆放偏移与朝向、首层标高、两侧门洞位置和净宽净高，以及共享构件归属或允许裁切的范围。普通独立单体只记录摆放关系，不逐格列坐标；平台、连廊和吊机的作业净空也纳入总体布局。

合并时区分实体、室内或通路所需空气，以及包围盒外部的无关空气。模块外围空气不覆盖邻栋，室内与门洞的必要空腔也不能因仅合并非空气方块而被其他模块填满。非接口范围发生实体相交或占用必要空腔时，调整摆放或连接设计，不能静默覆盖或直接丢弃冲突方块。旋转同时转换楼梯、门、轴向等方块状态，交界栏杆按实际邻接关系连接。

拼接阶段只定向处理接口：门洞与首层通路连续、共享墙柱完整、屋面与半砖交界封闭、外梯和屋檐互不穿插、H 平台及飞行接近区域不被占用。保持已完成单体的轮廓和细节，修改集中于约定连接范围；不因拼接重新缩放整栋建筑，也不追加每个中间模型的渲染与导出后校验轮次。

## 5. 导出 NBT 与必要对照

将方块位置、调色板、方块状态和尺寸编码为压缩 NBT。保持门上下半部、楼梯朝向、台阶层位与栏杆连接正确；空房和开敞空间按实际加载范围保存空气。默认不写测试实体、装满物品的容器、测试 UUID、绝对业务定位点或未要求的 Jigsaw。

从实际交付 NBT 读取原版模型和纹理，绘制与参考图接近视角的外观及必要分层平面。两侧被遮挡或存在具体疑点时才补相应预览；不得再用图片生成模拟“成品图”。概念图与 NBT 预览明确区分，离线预览不声称是游戏截图。

搭建阶段按已确定参考核对单体尺度、轮廓、柱跨、材质和交通，组装时按总平面处理连接处，生成代码保留格式、有效状态与坐标边界等必要约束。**搭建完成并成功导出后，不再重复校检 NBT，也不根据预览反复修改已确定的设计。** 实物预览用于展示和文档记录，不能成为持续改变体量、材质或构件的另一轮设计。仅在维护者后续指出具体问题并要求修正时再处理；最终游戏内验收与手工调整由维护者完成。

图片生成默认先有一张完整整站主参考板，再为确需细化的制作对象各派生一张局部参考，信息足以搭建即停止生图。普通尺度调整和接口处理不触发新一轮整体效果图；必要补图遵循限定范围及整站设计优先规则。实际 NBT 预览是交付模型的对照依据，不是另一套生成式设计参考。

## 6. 交付与文档同步

存档目录使用 `generated/cargoverse/structures/<大类>/<贸易点英文目录>/`，只放正式 `.nbt`；不附使用说明、备份、`_manifest`、校验报告或生成脚本。加载名称为 `cargoverse:<大类>/<贸易点英文目录>/<文件名>`，不含扩展名。路径示例见[贸易点目录](<../README.md#结构文件路径>)。

完整拼接方案交付多个主体与本站平台文件；完整整站方案交付 `station.nbt`，其内已有实际共用平台，并从相同设计保留独立 `cargo_platform.nbt` 供编辑。这个独立文件是同一平台的编辑组件，不在整站旁另放第二座。若只制作指定单体，应明确它尚不构成完整站点。重制仅覆盖本次指定文件；已有手工修改的平台需要结合当前任务保留或明确纳入重制范围，不能自动用通用版本替换。

整站的中间单体可保存在项目制作目录中，默认不另行提交到存档；独立制作不改变最终交付约定。拼接方案需要连廊或过渡构件时，将其纳入正式模块或并入指定建筑，确保交付的一套模板能组成设计中的完整站点。

`00_总体说明.md` 保留身份、经济、服务安排和文档入口。以下外观设计与交付信息集中在本站 `01_外观与装饰参考.md`；实际设备位置、作业范围、启用条件和绑定记录分别维护在生成／装载／卸载功能页：

- 拼接或整站交付方式、功能摘要、建筑及制作分段清单，以及从总图提取的总平面关系。
- 主体材料与建筑功能的对应关系；制造商归属、采用的点缀色及其局部使用部位。
- 完整整站主参考板放在前面，随后列出派生局部参考、对应总图位置、提示词、主视图方向及采用版本；注明各处紧密拼接或连廊／广场连接的依据。必要补图说明限定用途，其他版本标为历史而不并列为当前依据。
- 尺度基准、最终 X × Y × Z、地坪与楼层标高、实际材料对应。
- 文件名、结构 ID、平台是否已包含；单体摆放偏移、朝向、拼接方式和必要接口记录。
- 实际 NBT 预览与必要平面；明显简化和设备绑定状态。

图片放在文档库 `docs/assets/images/trade_points/` 下对应站点目录，沿用已有站点资产目录即可；概念与实物可分别使用 `concept/`、`actual/` 子目录。采用库内标准 Markdown 相对链接，公开说明不包含本机绝对路径、账号、用户名或临时工作目录。原分栋记录已合并，不再为装饰性建筑单开文档；功能页链接外观参考，不重复存放同一组图片。
