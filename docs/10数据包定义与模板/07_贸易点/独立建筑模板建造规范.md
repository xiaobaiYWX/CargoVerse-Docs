# 独立建筑模板建造规范

> 2026-09-14 更新：按用户确认的范围交付建筑主体，细节装饰与室内设计由用户完成。本文约定离线生成、直接交付至开发存档的单体建筑 NBT 模板；自然生成与结构绑定仍见[贸易点结构制作指南](../../02贸易点系统/02_贸易点结构生成层与制作规范.md)。

## 1. 制作与交付范围

- 一个独立建筑对应一个 `.nbt` 文件，一个贸易点可以包含多个建筑文件。
- 负责大体空间分区、柱网与框架、楼地面、必要隔墙、墙面与门窗、屋顶及楼梯，交付空间布局和主体连接合理的建筑 NBT，并同步概念图与文档。
- 细节装饰、纯装饰构筑物和室内设计由用户后续完成；默认不生成家具、柜台、货架、货物陈列、装饰设备、灯具、招牌、绿化或额外的表面修饰。
- 楼梯、门洞、平台及其承接结构属于主体，应随模板完成；分区与通道应支持后续室内布置。
- 由用户使用结构方块加载、调整、修补、装修、重新保存，并负责后续建筑组合和结构拼接。范围更新用于后续制作，已有模板仅在用户要求时修改。
- 本阶段不制作 Jigsaw 拼接、模板池、世界生成规则或贸易点绑定，不操作游戏进行放置和验收。
- 常规交付直接写入指定存档目录，不以 ZIP 数据包或 `.mcfunction` 作为主要交付物。
- 存档交付目录只放正式 `.nbt` 文件，不生成使用说明、`_manifest`、校验清单、备份文件或备份目录。概念图放文档库 `assets`，尺寸、结构 ID、设计和使用信息统一写入对应贸易点文档。

## 2. 方块与版本

- 仅使用原版 `minecraft:` 命名空间的方块。
- 以当前 Minecraft Java 1.21.1 已有的方块及方块状态为兼容基准；“1.21.1+”不表示可以在当前实例的模板中使用后续版本才新增的方块。
- 不使用 CargoVerse、Create 或其他模组方块。
- 文档提到的贸易点信息柜、业务终端、模组机器、货柜等内容，仅预留相应的空间、通道和操作区；具体设备、代用陈列与实际功能方块由用户后续布置。
- 不保存固定实例 UUID、`tradePointId` 或测试实例数据。默认交付建筑方块，不附带实体。

## 3. 交付目录与命名

当前唯一交付根目录：

```text
D:\仓库\天空遗民整合包\Skylands-2.0\10_HMCL_Client_Dev\.minecraft\saves\dev_world\generated\cargoverse\structures\trade_points
```

根目录以下按贸易点文档中的资源 ID 分类：

```text
trade_points/<类型>/<分类>/<贸易点英文ID>/<建筑英文名>.nbt
```

- 类型沿用文档的 `factory`、`market`、`resource`。
- 分类及贸易点英文 ID 沿用该贸易点文档中 `cargoverse:` 后的路径，不另外发明一套分类。
- 每个贸易点拥有独立目录；该点的主楼、厂房、仓库、温室、附属建筑分别保存。
- 路径及文件名采用小写英文、数字和下划线，中文名称放在交付说明中。
- 本地交付路径明确使用复数 `trade_points`；不要与模组内置数据包中的 `structure/trade_point/...` 路径混用。

例如 V01 梯田农林站的资源 ID 为 `cargoverse:resource/agriculture/terrace_farm`。以下仅演示目录，不代表已经生成这些文件：

```text
trade_points/
└─ resource/
   └─ agriculture/
      └─ terrace_farm/
         ├─ registration_house.nbt
         ├─ greenhouse.nbt
         └─ timber_shed.nbt
```

对应温室的结构方块加载／保存名称为：

```text
cargoverse:trade_points/resource/agriculture/terrace_farm/greenhouse
```

在结构方块中保持这一名称保存，即可将修改后的文件写回该存档的对应模板位置。默认不覆盖已有同名文件；仅在用户要求修订或重新生成对应模板时替换，不自动产生备份文件。

## 4. 建筑内容依据

- 以各贸易点独立文档的“身份与定位”“建议结构内容”“行走与装卸路线”和制造商建筑形象为主要依据。
- 收售货物用于确定仓储、接收和作业区域的空间需求；货物陈列与设备装饰留给用户完成。
- 同一贸易点的多个建筑保持材料、配色和建筑语言的一致性，并体现各自功能。
- 模板不必是房屋。任务需要独立设备或开放构筑物时，可制作其主要骨架、支撑与作业平台；纯装饰构筑物及设备细节由用户完成。
- 不同贸易点应在平面、轮廓、屋顶、结构骨架和作业组织上具有区别，不以同一营业楼、仓库或停机坪换材质来代替独立设计。2026-09-13 用户要求据此重做四个科研／遗民节点。
- 文档中的整站分区拆成适合独立加载和手工组合的建筑；不要求把整个贸易点塞进一个 NBT。
- 只交付单体建筑及必要的附属构件；整站场地布置、道路连接和地形修补由用户调整。

### 从平面开始的设计与建造顺序

2026-09-14 用户明确：参考建筑均从平面分区开始，后续模板沿用以下顺序。

1. **标出平面分区。** 先在水平面上大致安排建筑内各空间的用途、范围，以及入口、通道、楼梯和设备位置；由这些区域确定整体占地。
2. **确定柱距，搭建柱子和框架。** 根据分区边界、空间跨度及通行需要安排柱位，再连接梁、楼层和屋顶骨架。柱网服务于平面，各区域按需要调整柱距。
3. **搭建墙体与窗户。** 在已确定的框架之间设置墙、门、窗及屋面，保持入口、内部通道和各层连接符合平面安排。
4. **交付主体。** 完成空间布局、柱网框架、墙面屋顶和必要楼梯后交付 NBT，后续细节修饰与室内设计由用户完成。

设计时使用简洁的平面分区与柱位记录即可，不增加逐阶段审批或独立交付文件。生成代码也按此顺序组织，共用分区、柱位和高度数据。参考构件按已确定的空间与骨架选用，构件库可在实际制作中逐步积累。

任务包含独立设备或开放框架时，同样先确定占地、操作范围与人员通道，再建立主要支撑和主体；没有墙窗的构筑物跳过围护步骤，装饰细节留给用户。

### 航空货运与装卸空间

- 本项目的大部分货运由飞行载具完成。后续制作装卸空间时，默认优先采用户外开放平台，参考直升机停机坪、航空货运停机位或跑道式布局。
- 露天装卸区保留上方起降净空和通向场外的进出方向。屋檐、雨棚、横梁、灯架、树木和高货架布置在起降及载具通行范围之外。
- 区分载具停靠、货物暂存和人员操作区域；仓库可以邻接露天平台，实际装卸作业面尽量向平台开放。各区域在平面与文档中说明，标识、导向线、灯具和货物陈列由用户后续添加。
- 若采用跑道式方案，根据载具和站点用途留出直线进出空间；不要求每个贸易点都附带完整跑道。平台、跑道等仍可作为独立 NBT 交付，由用户组合。
- 需要室内装卸时，参考大型机库：宽大入口、高净空、宽敞连续的内部空间，支柱与设备尽量靠边，入口前留开阔场坪。避免将小型仓库门洞或低雨棚下的货位作为默认航空装卸位。
- 装卸平台、机库的尺寸首先满足载具外廓、货柜及操作净空，允许超过大型建筑约 32 格的参考尺度；未指定载具型号时按用途合理预留，不声称已适配所有载具。
- 本条用于后续制作及用户指定的重做任务；已有 NBT 是否改造由用户决定。

## 5. 尺寸与比例

- 小型建筑的水平长、宽以 **16 格左右**为参考。
- 大型建筑的水平长、宽以 **32 格左右**为参考。
- 这是设计参考，不是硬性上下限，不要求长宽相等，也不为了凑尺寸强行放大或缩小。
- 小型装饰建筑、棚亭和附属设施可以更小。
- 小工厂、大工厂及其他需要更大空间的建筑可以按用途扩大。
- 高度根据层数、屋顶、工业设备和空间功能决定，不设统一高度。
- 尺寸以实际使用空间和整体比例为依据，内部保留可通行的入口、楼梯和工作／装卸区域。

## 6. 概念图与文档同步

- 每次生成或重新生成建筑后，将本批概念图、建筑清单和设计说明同步至对应贸易点的独立 Markdown 文档。
- 文档使用的图片统一放在文档库内的 `CargoVerse-Docs/docs/assets/images/trade_points/<类型>/<分类>/<贸易点英文ID>/`，与 NBT 的贸易点分类一致；总览用 `overview.png`，单体外观用 `<建筑英文名>_exterior.png`。生成中间文件可以保留在 `CargoVerse-Assets`，文档不得直接嵌入库外图片。
- 默认复用生成数据制作简洁的离线体块概念图，每批提供一张总览和各单体外观图即可。剖视、多视角和精细渲染按需提供，不作为默认验收流程。
- 明确标注离线概念图／体块示意，不将其描述为游戏内截图或已验收效果。
- 文档图片引用使用指向库内 `assets` 的标准 Markdown 相对链接（正斜杠），不跨越 `docs` 文档库边界，不使用本机盘符绝对图片链接、`file://` 或 Obsidian 专用嵌入语法。例如 `resource/agriculture/梯田农林站.md` 引用总览：`../../../../assets/images/trade_points/resource/agriculture/terrace_farm/overview.png`。文档库可以独立复制，图片仍随文档一起解析。
- 同步内容包括中文建筑名、用途、NBT 文件名、完整结构 ID 或公共前缀、尺寸（X×Y×Z）、入口朝向、原点／地基层和必要预留区。新图替换对应版本，避免旧图与新模板混用。

## 7. 精简生成与用户验收

- 输出 Minecraft Java 1.21.1 可读取的压缩结构 NBT；只保留生成所需的轻量约束，例如方块名称／状态、坐标范围、写入成功及防止覆盖用户手工版本。
- 模板边界贴合建筑及必要附属构件，避免无用途的大范围空气边框。
- 不默认运行 NBT 往返校验、重复哈希核验、通道／灌溉／物理专项检查，也不增加游戏内检查、截图轮询或反复渲染复核。需要排查用户反馈的问题时，只检查相关部分。
- 校验和验收由用户完成；用户按问题严重程度决定手动修补还是要求重新生成，不因潜在小问题扩大任务范围。
- 简要说明完成的交付，不把未经执行的检查写成“已通过”。
