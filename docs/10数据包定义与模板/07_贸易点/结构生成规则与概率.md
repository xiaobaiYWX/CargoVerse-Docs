# 生成、结构发布与整合包适配

24 个天空大站与 16 个地面小站均在原版主世界生成。每站的群系、权重、高度、模板与绑定只维护在本站 `生成规则/00_生成规则.md`；模板尺寸、设备坐标、定位点参数和预览只维护在本站 `结构设计/00_结构总览.md`。本页说明公共规则与操作，不另列集中参数或交付验收总表。

## 默认生成规则

- 天空站各有群系标签，共用 `sky_platforms` 结构集；地面小站使用独立的 `ground_stations` 结构集。
- 天空站采用绝对高度悬浮，不做地表投影和地形融合；地面站使用地表投影，`terrain_adaptation` 为 `none`，具体偏移以单站页面为准。
- 全部默认站点位于主世界，物理货柜运输不要求跨维度。
- 群系标签表示允许范围；实际分布还受候选布点、站型权重及生成失败影响。变种群系需要明确列出，不自动继承。
- 天空与地面网格独立，不承诺跨组最小间距、出生附近保底或避开其他模组建筑。当前配置没有最近买方、邻站依赖或逐群系偏好权重字段。

扩大允许群系可能增加实际站数。降低稀有站权重时，应保留其群系中的常规候选，避免该站成为唯一可落地成员。供需按实际营业实例数评估，不能把结构集权重直接当作最终生成概率。

## 小站的投放与密度目标

G09～G16 已按各站生成页的群系、权重和高度加入现有 ground_stations 共享结构集。后续目标是适宜陆地区域小站与大站实例约为 3∶1；海洋和地面站不适宜区单列观察，不用类型数量推断实际比例。

现有 sky_platforms 与 ground_stations 的 spacing 均为 32；过滤前两组候选位置数量处于同一量级。增加小站成员只扩展站型，不自动提高候选密度。正式投放时应结合适宜群系面积、生成成功率、最近站距离及区域供需，统一调整共享布点；本批接入保持原共享布点参数。

## 模板与绑定

资源 ID 格式见[目录命名规则](<README.md#资源-id-与路径规则>)。世界结构通过独立绑定映射到唯一贸易点定义，起始模板池引用完整整站模板；NBT 加载 ID 不能直接代替世界结构 ID。

原始导出保存在 [CargoVerse-Assets/structures/tradepoints](<../../../../CargoVerse-Assets/structures/tradepoints/README.md>)，文件来源与发布记录由[资产清单](<../../../../CargoVerse-Assets/structures/tradepoints/manifest.json>)维护。`source_relative` 和 `file` 记录原始来源，`template` 记录发布 ID，原始与发布副本的校验值分别保存；不要求源文件路径和发布路径相同。S01 的模板名保留 `civic_distributionw`，经济定义名为 `civic_distribution`。

发布副本清理编辑时实例 UUID 与定位点绑定；世界结构放置时注入经济定义和实例关联。贸易点信息柜作为唯一实例锚点，收货／发货信息柜、装卸设备和其他服务共享该实例。货柜生成点只提供原点及偏移，装卸定位点才使用检测范围。

现有整站已包含自身业务设备和场地，旧分栋、平台与附件仍可作素材，不自动追加到整站。模板内的注册占位设备、售卖机或装饰屏幕不会自行增加业务；可选模组方块及其用途以本站实录为准。

## 修改与发布

1. 修改本站对应文档：经济身份在定义页，商品参数在正式资源表，生成参数在单站生成页；模板实录在结构总览。
2. 同一结构集的共享布点参数必须一致。只调整生成规则时，在模组工程目录运行：

```text
node tools/structure-templates/sync-trade-point-runtime.cjs --worldgen-only
```

该模式读取单站生成页，更新世界结构、群系标签、结构集及资产清单的生成记录，不重新导入 NBT、资源表、经济定义或制造配方。共享参数冲突时先修正文档。

模板变更按[结构制作规范](<../../02贸易点系统/02_贸易点结构生成层与制作规范.md>)和[结构模板工作流](<结构搭建说明/结构模板工作流.md>)完成导入、发布与绑定。仅修改 Markdown 不会改变已安装模组的运行资源。

## 生成指令与验收

每站生成页提供准确指令。使用 `/place structure <世界结构 ID>` 验证结构生成流程和经济绑定；直接放置 NBT 模板仅能检查模板本身，不能替代完整业务接入。

自然生成需要新区块验证群系分布、净空及地面落位。`/place structure` 不会重新运行地形密度生成，不能用它判断 `terrain_adaptation` 在自然生成中的效果。旧末地实例不会自动搬到主世界，已生成区块也不会自动补站。

发布后用新经济实例检查信息柜关联、装卸、制造与注册等本站实际提供的功能。已有实例保存资源目录与报价快照，普通 reload 不会替换旧目录，也不应靠补满一次性库存来验收。

结构引用、设备和高度范围的静态检查不能代替实机验收。当前仍需观察山体净空、站点分布、实际可营业密度、最近交易伙伴距离与运输体验。

## 整合包适配边界

CargoVerse 按独立模组维护原版默认规则。天空世界整合包通过额外数据包覆盖自己的放置规则；本目录未提供完成的整合包适配包。

| 内容 | 独立模组默认 | 整合包可调整 |
| --- | --- | --- |
| 环境 | 原版主世界群系和建造范围 | 群系、维度、自定义空岛高度与净空 |
| 布点 | 天空站与地面站各用一组候选网格 | 间距、权重、频率及世界生成器支持的放置约束 |
| 经济身份 | 世界结构绑定唯一贸易点定义 | 默认复用；业务变化时另建定义并修改绑定 |
| 商品供需 | 各实例独立库存、补货、收购与限额 | 根据实际来源和买方密度调整资源表 |
| 开局 | 不保证附近有节点，不附带初始飞艇或资金 | 预置节点、起步资金、任务引导与安全航线 |

### 覆盖文件

下表 `<站点路径>` 例如 `resource/sky_station/terrace_farm`。覆盖同一资源 ID 沿用 `cargoverse` 命名空间，新增适配专属资源使用自己的命名空间。

| 调整内容 | 数据包路径 |
| --- | --- |
| 布点间距、频率、成员权重与排斥 | `data/cargoverse/worldgen/structure_set/trade_points/<结构集>.json` |
| 群系、地表投影、起始高度与模板池 | `data/cargoverse/worldgen/structure/trade_point/<站点路径>.json` |
| 允许群系集合 | `data/cargoverse/tags/worldgen/biome/trade_sites/<标签>.json` |
| 起始模板与附属模块 | `data/cargoverse/worldgen/template_pool/trade_point/<站点路径>/start.json` 及子池 |
| 建筑 NBT | `data/<命名空间>/structure/trade_points/<站点路径>.nbt`；文件名例外以实际模板 ID 为准 |
| 世界结构与经济定义关联 | `data/cargoverse/trade_point_structure_bindings/<站点路径>.json` |
| 商品、报价、库存与收购限额 | `data/cargoverse/trade_points/resource_tables/<站点路径>.json` |
| 制造商、功能模块与经济身份 | `data/cargoverse/trade_points/trade_points_definitions/<站点路径>.json` |

结构集、世界结构和业务定义按同 ID 整体覆盖，不把候选权重当作追加列表。群系标签完全替换用 `replace: true`，扩充用 `replace: false`。新增模板池必须同时提供它引用的模板；新增世界结构 ID 需有对应独立绑定，绑定分类与经济定义分类一致。

默认世界结构定义没有可直接填写的维度白名单、出生保底半径、平坦空岛筛选、水源邻接或最近贸易伙伴字段。这些约束应使用整合包世界生成器已有能力，不写虚构字段。保留 ID 的结构集可用 `frequency: 0` 关闭随机布点；高优先级数据包不提供某文件，并不会删除低优先级同名资源。

生成覆盖只影响新区块，经济覆盖不会自动替换旧实例快照；修改密度也不会自动平衡其他站点库存。

### 可选开局建议（待实现）

整合包可提供带 500 VB 余额的虚空结算器及可到达的起步站群，让玩家先以少量货物尝试运输。这是未实现的引导建议，不是注册奖励或已发布服务；具体资金应按当前报价、可用货柜和载具承重验证。

起步区域优先安排口粮、净水、麦粒、原矿等货物的来源与可达买方，再连接工业和稀缺专线。小站不提供注册、领柜或制造，不能代替八家品牌入口。注册领取货柜与获得购货资金是独立条件。
