# 独立模组默认与整合包适配边界

CargoVerse 是独立模组。默认贸易点按原版主世界和末地的群系、地形、高度及原版世界生成流程设计；天空世界整合包以额外数据包表达自己的放置规则。本页是适配约定，尚未创建适配数据包。

## 默认与覆盖职责

| 内容 | 模组默认 | 整合包适配数据包 |
| --- | --- | --- |
| 地表贸易点 | 主世界常规大陆地形，末地原版外岛 | 空岛地表、自定义群系或其他维度 |
| 悬空贸易点 | 原版建造范围内的独立人工平台 | 按自定义空岛高度层重新设置高度、下挂和净空 |
| 候选群系 | 原版群系构成的模组标签 | 整体替换或显式加入整合包群系 |
| 密度与权重 | 通用四类结构集 | 根据岛屿密度、航行速度、地图规模覆盖参数 |
| 贸易点身份 | 一结构绑定一经济定义 | 默认复用；确需不同内容时另建定义并修改绑定 |
| 资源表 | 通用出售、收购与库存策略 | 按实际结构密度重新平衡日补、日耗和容量 |
| 开局引导 | 不承诺附近必有节点，不附带初始飞艇或资金 | 预制据点、起步货币、任务引导与安全航线自行配置 |
| 跨维度运输 | 不将特定整合包能力当作模组默认 | 使用整合包选择的运输方案，必要时调整异维度商品来源 |

悬空平台是建筑形式，不意味着必须使用空岛世界生成器。世界观可以保持天空航运背景，数据定义不能因此要求整合包专有维度或群系存在。

## 覆盖文件清单

以下 `<贸易点定义路径>` 例如 `resource/agriculture/terrace_farm`；覆盖同一资源 ID 时沿用 `cargoverse` 命名空间，新增适配专属资源则使用数据包自己的命名空间。

| 要调整的内容 | 数据包路径 |
| --- | --- |
| 出现间距、概率、权重和排斥 | `data/cargoverse/worldgen/structure_set/trade_points/<结构集>.json` |
| 群系、地形投影、起始高度、模板池 | `data/cargoverse/worldgen/structure/trade_point/<贸易点定义路径>.json` |
| 可生成群系集合 | `data/cargoverse/tags/worldgen/biome/trade_sites/<标签>.json` |
| 外观模板与模块概率 | `data/cargoverse/worldgen/template_pool/trade_point/<贸易点定义路径>/start.json` 及子池 |
| 空岛或悬空专属建筑模板 | `data/<适配命名空间>/structure/trade_point/.../*.nbt` |
| 改变结构对应的经济定义 | `data/cargoverse/trade_point_structure_bindings/<贸易点定义路径>.json` |
| 改变商品与库存 | `data/cargoverse/trade_points/resource_tables/<贸易点定义路径>.json` |
| 改变报价、制造商或功能模块 | `data/cargoverse/trade_points/trade_points_definitions/<贸易点定义路径>.json` |

结构集、世界结构及业务定义使用同 ID 整体覆盖，不把候选权重当作自动追加列表。群系标签要完全取代模组默认时使用 `replace: true`；只做扩充时使用 `replace: false`。修改模板池后必须同时提供所引用的模板，不能用缺失资源表示“以后补齐”。

只改变地形、概率和外观时无需新建资源表或修改 Java。若世界结构 ID 保持不变且业务核心功能一致，一对一结构绑定可以继续复用；新增世界结构 ID 时需新增独立绑定，且绑定目录类别仍与贸易点定义类别一致。

## 可用机制的边界

原版 `worldgen/structure` 没有本方案可直接填入的维度白名单、出生保底半径、寻找平坦大空岛、相邻水源需求或最近交易伙伴字段。适配数据包应使用其世界生成器已有的配置能力；不能把这些设计要求写成虚构字段。

`structure_set` 的 `frequency: 0` 可用于关闭一个保留 ID 的演示结构集随机布点。未来正式启用新设计时，旧 `cargoverse:cloud_farm` 演示集应退出默认自然投放；这一调整尚未写入数据包。单纯在适配数据包里不提供旧文件，不会删除较低优先级的默认资源。

生成覆盖只影响新区块；资源表覆盖不会自动重选已存在实例的货物目录。世界结构数量变化也不会让运行时自动平衡其他贸易点库存，作者应按自己的地图统计重算数值。
