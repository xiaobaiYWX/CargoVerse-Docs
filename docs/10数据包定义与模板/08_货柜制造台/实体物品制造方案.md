# 货柜制造台：实体物品材料方案

本页记录当前已经落地的 v2 实体物品制造架构。运行时只接受 `schema_version: 2` 与 `item_costs`，不提供 v1 `stock_costs` 兼容路径。

## 统一设计结论

将货柜制造调整为：**玩家携带实体材料到贸易点，在制造台支付加工费，由服务端扣除自己的物品，并在共用收发平台生成空货柜。**

贸易点负责提供制造目录、品牌定位、繁荣门槛及交付位置；材料来自玩家，与该站的 CargoGood 收购目录及出售库存无关。这里的实体材料是物品栏中的 ItemStack，不是地面掉落物，也不是抽象数量货物。

这是对现有制造业务材料来源的替换，无需恢复生产线。代价是要增加物品匹配、个人材料预览和物品扣除回执，但可以取消制造侧与资源表的匹配、缺料配方隐藏和抽象库存扣除依赖。

## 旧方案的问题与调整后的职责

| 问题 | 已移除的抽象库存方案 | 实体物品方案 |
| --- | --- | --- |
| 配方能否显示 | 材料标签必须匹配本站已有收购库存类型，否则整条隐藏 | 有效配方由本站目录提供；缺材料、许可或繁荣不足只显示原因，不因材料缺失消失 |
| 谁承担材料 | 玩家付费，但材料从贸易点公共收购库存扣除 | 操作玩家同时承担加工费与自己的实体材料 |
| 同配方跨站复用 | 要检查每站资源表、标签和库存变化 | 不论本站收购什么，都按相同物品配方制造 |
| 日常需求的影响 | 自然消耗与制造争用同一份库存 | 收购目录与制造材料互不依赖 |
| 玩家准备方式 | 先运入货物，再依赖站点库存保留 | 带齐清单中的物品即可，材料也可来自正常生存采集与合成 |
| 仍需保留的限制 | 制造目录、繁荣、许可、调度点、支付与生成范围 | 全部保留；取消的是材料库存耦合，不是所有贸易点绑定 |

制造台仍绑定贸易点 UUID，站点模块仍选定制造定义。不要为了移除材料依赖，同时把制造台改成无需站点的通用工作台；独立基地制造属于另一项玩法，本轮不扩展。

## 唯一实体材料输入源

材料统一来自操作玩家的原版物品栏，主背包和快捷栏作为同一输入源处理。不提供来源切换，不增加制造台输入仓、邻接箱子或贸易点库存回退路径。

首版只检查主背包 27 格和快捷栏 9 格。优先扣主背包，再扣快捷栏；快捷栏中的主手堆叠属于这 9 格之一，不能重复统计。不检查盔甲、副手、鼠标拖拽堆叠、末影箱、潜影盒内部、背包模组内部、附近箱子或地面掉落物。

每次操作只制造一只柜，不增加制造时间、队列、批量制造、能耗、流体输入、工具耐久或机器材料仓。大型货柜通过更多普通材料和较高加工费体现成本，避免强迫玩家一次携带超过可用物品栏容量的清单。

## 只保留实体材料制造

取消纯 VB 直接购买方案。每个站点对同一型号只提供一条实体材料制造配方，不再维护购买／制造双条目、模式切换、双套价格或无材料的兜底入口。材料不足即不能制造，不能由 VB 或贸易点库存补足。

VB 沿用既有加工费角色，与实体材料一并结算；它不是替代材料的另一种输入方式。基础货柜领取继续由注册点权益独立处理，不放进制造台作为空材料配方。

60 款型号已编制统一实体材料与加工费，当前每站固定配置制造台与一处生成点，制造目录按专业与配套任务区分，见[内容设计总表](<制造配方与投放总表.md>)。同型号跨站配方一致；旧纯 VB 总价与空材料草案已由 v2 制造台文档替换，新增内容待数据包接入。

制造仍要求相应许可、繁荣和调度点，产生普通空柜。S／M／L／X／XL 的规划繁荣门槛保持 0／1／2／3／4，模块门槛与条目门槛取较高者。材料与加工费共同体现造柜成本，不再相对旧纯 VB 总价设计购买折扣。实体物品也不折算成 CargoGood 数量。

## 定义格式

沿用目录 `trade_points/trade_points_subfunctions/cargo_manufacturing_platform_definitions/`、定义 ID、`recipes`、货柜引用和模块池。定义版本为 2，以 `item_costs` **替换** `stock_costs`，不并行保留两套材料来源。同一定义内 `cargo_container_definition` 不允许重复，确保一个型号只有一个制造入口。

| 字段 | 设计规则 |
| --- | --- |
| `schema_version` | 固定为 `2`；旧版本会被拒绝 |
| `recipes[].item_costs` | 必填，1～8 项；空数组或缺失均为错误，不存在纯货币分支 |
| `item_costs[].ingredient` | 对象，严格二选一：`item` 或 `tag`；首版不支持复合条件、NBT 或组件谓词 |
| `ingredient.item` | 完整物品注册 ID，如 `minecraft:iron_ingot` |
| `ingredient.tag` | 完整物品标签 ID，如拟议的 `cargoverse:manufacturing/frame_wood`，值中不加 `#`；不是 CargoGood 的字符串标签 |
| `item_costs[].count` | 消耗的物品个数，整数 1～4096；能跨多个堆叠凑足，不代表该物品堆叠上限增加 |
| `currency_cost` | 保留，只表达加工费，不能代替实体材料。内容设计统一使用整数 VB |
| 其他条目字段 | `id`、`cargo_container_definition`、`required_license_level`、`min_prosperity_level` 沿用现有语义 |

物品标签仅提供“若干物品任选”的替代关系，不引入旧 `match_mode`、货物数量 `amount` 或 CargoGood 映射。比如木料标签包含若干种木板，需求 8 个可以由 4 个橡木木板加 4 个云杉木板组成；所有候选按一件抵一件，不支持一块铁块自动抵九个铁锭。

以下仅是 Atlas S 的流程与字段示例，数量不是已验证的全局平衡结论。为减少首次设计依赖，示例直接使用原版物品 ID；它展示本站 Atlas S 唯一的实体材料制造条目，不是一份应覆盖所有站点的大目录。

```json
{
  "schema_version": 2,
  "display_name": "标准建材装配港货柜供应",
  "recipes": [
    {
      "id": "atlas_sd_s",
      "min_prosperity_level": 0,
      "required_license_level": "S",
      "cargo_container_definition": "cargoverse:aui/atlas_sd_s",
      "currency_cost": {
        "currency": "cargoverse:void_byte",
        "amount": 80
      },
      "item_costs": [
        {
          "ingredient": {
            "item": "minecraft:iron_ingot"
          },
          "count": 16
        },
        {
          "ingredient": {
            "item": "minecraft:oak_planks"
          },
          "count": 8
        },
        {
          "ingredient": {
            "item": "minecraft:glass"
          },
          "count": 4
        },
        {
          "ingredient": {
            "item": "minecraft:redstone"
          },
          "count": 2
        }
      ]
    }

```


## 匹配、扣料与特殊物品边界

1. 只由服务端统计操作玩家的有效槽位。数量不足时清楚显示“需要／可用／缺少”；不从其他玩家或站点库存补齐。
2. 首版只消耗普通材料堆叠，不消耗改名、附魔、损坏、装有物品或带非默认自定义组件的堆叠。数据包不能用宽泛标签绕过这条保护；玩家把珍藏材料改名后不会被自动扣走。
3. 含合成剩余物的候选不用于首版制造，例如要返还空桶的液体桶。首版不做容器返还、工具损耗、催化剂或配方副产物。加载时筛除不支持的候选，若一项没有可用候选则报出定义和条目位置并拒绝发布新数据；运行时也复核实际堆叠是否适用。
4. 配方中的标签必须存在且能解析出有效物品；未知物品、空标签、非整数或越界数量都作为定义错误处理。不会因为材料错误悄悄生成免费配方。
5. 单项允许跨堆叠扣除，不同项共享同一份剩余数量。某堆叠不能同时支付两项需求。对于重叠标签，必须求出整个配方的可行分配，不能单纯按声明顺序贪心扣料后误判缺料。
6. 例如需求“橡木或云杉木板 8 个”及“橡木木板 4 个”，玩家有云杉 8、橡木 4，应制造成功。先把橡木用进第一项后声称第二项不足，是错误行为。固定匹配优先级用于在多个可行方案中稳定选取，不得牺牲整体可行性。
7. 在整体可行的前提下，按主背包、快捷栏及槽位顺序确定消耗，向玩家展示真正选中的物品。首版不增加手工挑选替代材料的编辑器；需要保留某些普通材料时，将其移出参与扣料的背包范围。

个数上限只是数据格式防错上限，不是建议配方量。正式配方应以少量易懂的材料行为主，一般 2～4 项；不能将几十个抽象 CargoGood 单位直接照抄为物品数量。

## 玩家操作与界面

公共世界界面显示柜型、预览、类别兼容、价格、门槛以及材料需求清单；**不显示某个玩家背包中的可用数量**。当前制造仪表是公共设备快照，把个人背包数量写进它会导致多人互相覆盖。

建议流程：

1. 玩家在公共终端选择柜型，只有“制造”操作，不提供购买／制造模式选择。
2. 点击后打开仅该玩家可见的确认界面，服务端返回其选定条目、VB 成本、实际扣料清单、材料缺口、许可、繁荣、调度点和生成区状态。
3. 缺材料或门槛不满足时保留条目并说明原因。材料就绪时确认按钮显示“支付 80 VB 并制造”，清单在按钮上方清楚列出。
4. 玩家确认后服务端重新检查并执行；成功提示空柜交付位置，失败提示缺料、支付不足或生成区被占用等具体原因。

确认消息绑定玩家打开时选择的配方 ID、站点实例与定义版本，而不是执行时公共屏幕正在选中的行。其他人切换屏幕不改变自己的订单。若数据重载、价格或材料分配与已展示的清单变化，更新确认内容并要求重新确认，不静默换料或改价。

个人确认内容只是一份预览，不提前锁住或寄存材料；普通背包移动导致清单变化时重新预览即可。已提交请求的重复网络消息只执行一次，成功后的另一只柜必须作为新的操作重新确认。

## 服务端提交与失败处理

以一次同步的服务端操作完成：重新解析已选条目 → 检查权限、距离、绑定、许可、繁荣及调度点 → 检查模板与生成范围 → 对玩家背包生成完整扣料计划 → 确认资金足够 → 扣费与扣料 → 生成并注册空柜 → 记账并提交。

执行期间不等待制造计时或客户端响应，按平台串行提交并重查生成区；两名玩家共用一个平台时，后一请求必须重新检查前一只货柜形成的占用。缺一项材料、缺钱或范围不满足时都不进行部分扣费或扣料。

物品扣除需要记录原槽位、完整堆叠组件和精确数量的回执，生成、注册或记账失败时与支付回执一起撤销。只回退本次扣减，不能覆盖玩家整个背包快照；只恢复本次支付所修改的货币内容，避免整槽覆盖与物品恢复相互冲突。先移除本次产生的货柜和资产登记，再恢复材料并退款，不能让失败订单同时保留货柜和退回的成本。

在不跨 tick、不容许槽位中途编辑的正常提交路径中，应能原位恢复材料；不要默认把退款材料丢到公共平台。如果第三方回调造成原位恢复失败，必须保留未恢复数量与订单信息供恢复，不能吞掉材料或报告成功。本轮不扩大为跨机器物流退款系统；实现时应单独验证异常路径。

经济统计只记录实际支付的 VB，加工材料不虚构成一次 CargoGood 交货，不把材料计入货物交付或折算额外贸易经验。现有购买统计、普通资产归属和调度点逻辑沿用。退款、材料回执和资产生成的一致性必须验证；正常异常回滚不等于已解决服务器在写盘中断电的跨存储一致性问题，后者不能未经验证宣称安全。

## 当前实现分层

| 部分 | 当前职责 |
| --- | --- |
| 制造定义解析与重载 | 解析 v2 `item_costs`，校验物品／标签，不读取 CargoGood 材料标签 |
| 制造目录解析 | 保留贸易点模块和繁荣读取，删除 `hasRequiredStockTypes` 对配方的隐藏过滤；目录不再携带制造材料库存 |
| 材料匹配 | `CargoManufacturingItemMatcher` 对玩家物品槽位求完整分配 |
| 交易提交 | 物品扣除回执与支付回执共同进入补偿事务；保留空间校验、资产注册和交易回滚 |
| 公共仪表 | 材料图标改为真实物品及整数个数；只同步配方需求，不同步个人持有数 |
| 个人确认与网络请求 | 新增玩家专属需求评估、配方版本确认与重复提交防护 |
| 资源表与贸易点定义 | 资源表不因制造增减货物；贸易点仍通过现有模块引用定义，不增加生产槽位或材料匹配条件 |

这属于制造台自身的局部重构，涉及定义、材料评估、交互与事务；不是仅把 JSON 字段改名，也不要求重构 CargoGood 或贸易点生成系统。旧库存匹配类是否删除，实施时先查是否还有其他调用，不顺带删掉贸易点正常交易使用的库存服务。

## 当前数据边界

- v1 `stock_costs` 不自动换算，也不会被忽略；旧文件会以版本错误拒绝加载。
- 纯 VB 与空材料配方不属于现行制造台格式。每个型号先完成非空实体材料与加工费设计，再加入制造目录。
- 原默认测试目录保留 Atlas S 配方；24 个正式站点的制造目录现已同步，共 93 条配方、60 款货柜，详见[制造配方与投放总表](<制造配方与投放总表.md>)。
- 现有贸易点绑定 ID 和已领取／购买货柜快照不因材料方案改变而重写。新配方按新规则使用；重载使正在预览的订单失效，需重新确认。
- 后续按各厂材料设计逐条扩充制造目录，不再实现或测试纯货币购买分支。

## 后续验收重点

| 场景 | 预期 |
| --- | --- |
| 本站不收购任何制造所需 CargoGood | 仍能看见并使用实体物品配方 |
| 玩家材料不足／只有潜影盒内部有料／只有副手有料 | 显示缺料，不扣钱、不扣部分材料 |
| 同物品拆成多组普通堆叠 | 可合计扣除，剩余数量正确 |
| 重叠标签与具体物品共同需求 | 存在整体解即能制造，不重复支付同一件物品 |
| 改名、附魔、自定义组件、返还容器材料 | 按首版限制不被自动消耗，必要时报定义错误 |
| 他人切换公共界面／两人同时确认／重复请求 | 不串单，不重复扣款或重复交付；后到订单复核空间 |
| 清单预览后移走材料或重载配方 | 更新预览或拒绝旧确认，不静默换料改价 |
| 扣款后或生成中失败 | 恢复精确材料和 VB，无遗留空柜、登记或重复统计 |
| 材料数组为空／缺失，或带旧 `stock_costs` | 明确拒绝新定义，不退化为纯 VB 购买或抽象库存扣料 |
| 同站同型号出现多条配方 | 拒绝发布重复型号定义，只维护一个制造入口 |
