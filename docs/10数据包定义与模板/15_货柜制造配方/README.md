# 独立货柜制造配方

材料、搭建工时和搭建许可在独立配方中维护，由贸易点蓝图打印机、蓝图测试工具和搭建器共用。当前54份配方，关联54个可制造型号。

运行目录：`data/<namespace>/cargo_manufacturing_recipes/<path>.json`。相对路径构成配方ID；例如`cargoverse:aui/atlas_sd_s`。

| 字段 | 规则与职责 |
| --- | --- |
| `schema_version` | 固定1 |
| `container` | 已存在的货柜定义ID，直接决定此配方制造哪个型号；一个型号只允许一份制造配方 |
| `duration_ticks` | 20～72000的整数，内置当前400 |
| `required_license` | S／M／L／X／XL／SP，搭建器开工门槛 |
| `item_costs` | 1～8项实体材料 |
| `item_costs[].ingredient` | 严格二选一：`item`物品ID或`tag`原版物品标签ID |
| `item_costs[].count` | 1～4096的整数，实际物品个数 |

通过`container`建立配方到货柜定义的结果关联，加载时建立反向索引。未知货柜、同一货柜的重复配方、非法数量、无效材料均拒绝发布；未配置配方的型号不进入打印目录。货柜定义继续负责容量、空重、能力和结构模板，不再需要在不同贸易点重复填写材料。

贸易点制造台使用schema3投放表：条目通过`cargo_container_definition`找到唯一的共用制造配方，只维护投放、繁荣／许可门槛与VB打印费。贸易点打印机仅收取蓝图打印费，不扣材料或直接生成货柜。搭建器按蓝图配方ID读取同一材料表，使用相邻容器供料并托管施工；打印机只写入配方ID，不复制整份配方。

配方、货柜和贸易点依赖在同一批`CargoDataReloadListener`中预检并发布，错误不发布半批配置。已经开工的任务继续使用冻结模板、工时、材料与GUI投影。
