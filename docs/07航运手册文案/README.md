## 阅读目标

百科首先帮助玩家完成一次运输，再支持遇到问题时查阅，最后引导经营自己的贸易点与建设装卸设施。它不是数据包说明书，也不要求玩家先读完全部章节。

建议的首次阅读路线：**自备飞行载具、抵达天空站 → 注册与初始蓝图 → 制造第一只货柜 → 确认目的地 → 购买并装载 → 运抵并出售**。第一趟航运篇先说明抵达站点的前置条件。每个条目能独立解决一个问题，结束时提供一至两个下一步入口。

## 叙述口吻与世界观

手册设定为企业配发给运输员的工作手册，百科补充说明由一位从业多年的前运输员整理。以“我”的经验对“你”说话，带有适量的行业吐槽、亲历感和实用提醒；不采用严肃Wiki罗列语气，也不为叙述者额外编造姓名、阵营职务或重大经历。

幽默围绕玩家会遇到的实际处境展开，例如公司不配船、图纸不含材料、空船能飞不等于满载能飞。关键操作、费用和不可逆后果仍明确表达，不让笑话替代说明，不虚构处罚、赔偿、福利或额外限制。

天空大站集中设置注册终端，在设定上也是集团给新人的第一道入职考验：集团不提供载具，运输员须自备飞行与承载条件。搭方块或其他办法上站仍可注册，但取得许可证并不会自动解决货柜运输。正文体现这种区别，不将自备飞行载具写成终端额外执行的技术准入检查。

制造商背景继续由声望页面表达；老运输员可以吐槽工作经历与办事流程，不另写制造商宣传或揭露幕后设定。条目之间保持同一叙述视角，避免每段都塞入俏皮话。

按六个现有分类安排内容。条目清单是拟定范围，不表示已经完成；六篇已存在的中文条目保留原资源路径并重写，其余逐步新增，不创建空白占位文章。

## 单篇编写结构

每篇围绕一个玩家问题，按需要使用以下顺序，不强制每篇凑齐全部小节：

1. **用途**：一至两句话说明解决什么问题。
2. **准备**：必要的物品、资格、设备或场地。
3. **操作**：能照着执行的短步骤，说明点击或摆放对象。
4. **完成反馈**：玩家看到什么，才算成功。
5. **常见阻碍**：两三个最相关的表现与处理办法。
6. **下一步**：一至两个相关条目链接，不放全站链接墙。

概念条目用“规则＋例子”，设备条目用“准备＋操作＋反馈”。通常先以200～400字为目标，复杂流程可放宽到约600字，再按游戏内实际分页精简；字数不是像素排版保证。

文字用玩家能观察到的对象表达，不写Java类名、JSON字段、schema、存档迁移及测试报告。必须区分件、组、桶、舱位与质量，避免将数量单位当作吨。价格、库存、配方和柜型参数优先引导查看当前界面，只有教学必需的例子才写固定数字。

## 图片与条目之间的分工

流程篇优先一张能辨认设备与操作位置的截图；装卸区域、接驳和围场可各增加一张布置示意。初稿允许暂缺图片，但发布前不能留缺图资源引用。首页分类图标不替代操作示意，也不为每段重复放装饰图。

同一机制只在一篇讲完整。例如初始赠图由注册篇说明，施工步骤由蓝图篇说明，标准接口由接驳篇说明；其他篇只写当前步骤所需的一句话并链接。链接跳转没有返回历史，因此每篇仍需有足够上下文，不设计依赖连续跳转才能完成的流程。

## 外部稿件的存放与同步

本章独立于技术文档，采用以下结构；已开始的分类写入正文，尚未开始的分类不创建空目录和占位文章：

```text
07航运手册文案/
├─ README.md                         # 本规划、条目范围与审核标准
└─ zh_cn/
   ├─ getting_started/
   ├─ trading/
   ├─ containers/
   ├─ player_trade_points/
   ├─ map_and_navigation/
   └─ vehicle_instruments/
```

正式起稿后，正文按上述条目路径命名，可直接对应游戏资源，不再建立第二份中文文件名版本。每篇保留`order`和`icon`文件头，首行一级标题作为游戏标题；确认后的中文稿同步到工程同路径。英文在中文流程确认后跟进，路径与ID一致。

审稿状态、事实来源与待补图片使用独立作者注释记录，不显示在游戏正文中。状态采用“初稿／待操作核对／可同步／已同步待实机／已验收”；不能把文件写入资源视为实机阅读验收完成。初次编写时再逐条核对图标注册ID，不在本规划虚构占位物品ID。

原有六篇中文和一篇英文只是起点。启航指南已纠正注册直接领取成品柜的旧说法；其他分类中的十四种用途分类、仅通用兜底、液体与实体未开放以及链接器记录地址等旧叙述仍待逐篇重写。保留既有条目ID，避免破坏交叉引用；初期正文只链接已经核对的启航条目，不将过时条目作为下一步指引。

## 编写顺序与验收

**第一批：首次运输闭环。** 先写第一趟航运、注册、结算器、货物与货柜、蓝图施工、贸易操作、目的地、标准接驳及基础保护。优先消除旧正文中会导致新玩家走错步骤的内容。

**第二批：三类载荷与经营。** 液体、生物、围场、频率网络、玩家站点和报价；补充常见阻碍、状态检查及权限说明。

**第三批：持续经营与航行。** 繁荣、许可证与声望玩法、产业物资、航线、货柜轨道、配平和仪表。复杂设备操作以当前实现核对为前提，不编写制造商背景或货运磁铁内容。

每批完成后检查：

- 与当前机制、设备名称、交互方式和可用内容一致，未实现行为不当作现成功能。
- 正文能独立回答目标问题，准备条件、操作与成功反馈衔接，不要求玩家反复猜测点击对象。
- 内部链接目标存在；尚未发布的下一步条目不写成可点击入口。
- 图片和图标资源有效，当前渲染只使用支持的Markdown；游戏正文不使用表格、代码围栏、HTML或嵌套列表。本规划的表格与目录树只用于外部策划。
- 在游戏中检查目录标题、分页、图注、图片放大和返回操作；新玩家按第一批条目走通一趟运输后，再确认其作为入门路径。
- 中文与英文同ID；未译条目可按现有语言回退读取，不因存在旧英文就视为译文已同步。
