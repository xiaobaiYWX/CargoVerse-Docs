# 贸易点

## 1. 总体定位

贸易点以 `tradePointId` 为共享状态主键。同一 `tradePointId` 下的主终端、出售终端和收购终端读取同一套：

- 繁荣度与活跃度；
- CargoType 动态价格；
- `inputs_cargo_units`（消耗货物库存）；
- `output_cargo_units`（产出货物库存）。

各出售终端仍可维护自己的“展示槽位列表”，但不再维护独立的成品货柜库存。购买货柜会直接扣除贸易点共享的 `output_cargo_units`。

```text
tradePointId
├─ 繁荣度、活跃度、动态价格
├─ inputs_cargo_units（共享）
├─ output_cargo_units（共享）
├─ 出售终端 A：仅保存展示列表
├─ 出售终端 B：仅保存展示列表
└─ 收购终端：向 inputs_cargo_units 写入货物单位
```

## 2. 目标实现链路

本节是贸易点实现的主链路约束。后续修改应优先保证这条链路成立。

### 2.1 数据定义到运行状态

```text
数据包 trade_points/*.json
    ↓ TradePointDefinitionReloadListener
TradePointDefinition
    ├─ output_resources
    ├─ consumed_resources
    ├─ cargo_sale
    ├─ activity / dynamic_economy
    └─ ticks_per_day
    ↓ tradePointId 注册关系
TradePointEconomySavedData.TradePointState
    ├─ inputsCargoUnits
    ├─ outputCargoUnits
    ├─ CargoType 动态价格
    ├─ 繁荣度与活跃度
    ├─ 待结算交易统计
    └─ lastProcessedDay
```

约束：

- 数据包定义负责规则和上限，不直接保存世界实例状态；
- `TradePointState` 是共享经济状态的唯一权威来源；
- 状态按 `tradePointId` 隔离；
- 同一 `tradePointId` 的所有玩家和子终端共享库存；
- 出售终端不得重新建立本地成品库存。

### 2.2 正常交易日结算

```text
服务端 gameTime
    ↓ floor(gameTime / ticks_per_day)
当前交易日索引
    ↓ 与 lastProcessedDay 比较
elapsedDays
    ↓ 逐日回放
活跃度结算
    ↓
自然增长
    ↓
生产输入检查与批次计算
    ↓
扣除 inputs_cargo_units
    ↓
增加 output_cargo_units，并按 stock_max 钳制
    ↓
动态价格恢复与统计归档
    ↓
更新 lastProcessedDay 并写回 SavedData
```

正常交易日只使用单调递增的 `gameTime`。`dayTime`、昼夜循环和 `/time set` 不参与经济结算。

结算是惰性触发的：打开或同步贸易点终端、查询共享库存、进行购买或出售时都会先恢复到当前交易日。区块长期未加载时不会每 Tick 后台扫描，但下次访问会按经过天数补算。

### 2.3 手动交易日推进

```text
/cargoverse trade_point advance <tradePointId> [days]
    ↓
先恢复到当前真实 gameTime
    ↓
按 days 回放同一套每日结算函数
    ↓
结算结果写回 SavedData
    ↓
lastProcessedDay 恢复为当前真实 gameTime 对应日序
```

手动推进不维护第二套测试逻辑，不修改世界时间，也不把正常结算基准留在未来。详细指令说明参见[命令](../06开发与运维/03_命令.md#61-手动推进交易日)。

### 2.4 玩家出售货柜

```text
收购终端扫描货柜实例
    ↓ 服务端菜单、区块、实例和 CargoType 校验
计算收购价格与奖励
    ↓
清理货柜物理结构并发放货币
    ↓
若 consumed_resources.<type>.inventory.enabled=true
    ↓
inputs_cargo_units[type] += cargo.cargo_units
    ↓ 按 inventory.max 钳制
写回共享 TradePointState
```

这里的“出售”是玩家把货柜卖给贸易点，因此增加贸易点的输入库存。

### 2.5 玩家购买货柜

```text
出售终端展示固定“货柜定义 + CargoType”槽位
    ↓
读取共享 output_cargo_units[type]
    ↓
可购买数 = floor(output units / cargo.cargo_units)
    ↓ 服务端菜单、区块、槽位、货币和持有上限校验
生成货柜实例
    ↓ 成功后
output_cargo_units[type] -= cargo.cargo_units
    ↓
写回共享 TradePointState并同步终端显示
```

终端只保存展示槽位，不保存货柜库存。

### 2.6 服务端到客户端

```text
TradePointEconomyHelper.snapshot
    ↓
TradePointSnapshot
    ↓ TradePointStateSyncPacket
TradePointTerminalScreen.liveSnapshot
    ↓
输入库存进度条 / 产出库存进度条 / 活跃度 / 繁荣度 / 倒计时
```

客户端快照只用于显示，不能参与价格、生产、库存扣除或购买判定。界面打开期间按固定间隔请求完整状态快照，服务端仍是唯一可信来源。

### 2.7 核心不变量

- `inputs_cargo_units >= 0`；
- `output_cargo_units >= 0`；
- 输入库存不超过对应 `inventory.max`；
- 新增产出不超过对应 `output_resources.<type>.stock_max`；
- 购买成功后才扣除产出库存；
- 货柜生成失败不得扣除产出库存；
- 生产缺少任一必需输入时不得部分扣除；
- 数据包重载不清空库存、列表或结算时间；
- 所有经济写操作都在服务端主线程完成；
- UI 同步不能触发客户端侧经济计算。

## 3. Cargo Units

每个货柜实例拥有由货柜等级常数决定的 `cargo_units`。它表示贸易系统中的抽象货物单位，不是：

- 货柜数量；
- 方块数量；
- 物理质量；
- 出售槽位的数量上限。

例如 M 级货柜的 `cargo_units=20`：

- 玩家向贸易点出售一个该货柜，输入库存增加 20；
- 玩家从贸易点购买一个该货柜，产出库存减少 20。

## 4. 两套共享库存

### 4.1 inputs_cargo_units

`inputs_cargo_units` 是贸易点收购并供生产消耗的库存，按 CargoType 分项保存。

只有在 `consumed_resources.<cargo_type>.inventory.enabled=true` 时，该类型才建立可累计、可消耗的输入库存。

```json
"consumed_resources": {
  "ore": {
    "buy_price_modifier": 1.0,
    "required_prosperity": 0,
    "prosperity_experience_modifier": 0.5,
    "inventory": {
      "enabled": true,
      "initial": 0,
      "max": 500
    }
  }
}
```

字段：

- `initial`：新贸易点状态建立时的初始货物单位；
- `max`：该输入类型的库存上限；
- 玩家出售货柜时按 `cargo_units` 增加；
- 生产执行时按 `production.inputs` 扣除。

贸易点可以收购未启用库存的 CargoType，但这种交易不会积累 `inputs_cargo_units`，该类型也不能作为有效生产输入。

> [!WARNING]
> 同一个 CargoType 不应同时出现在 `output_resources` 和 `consumed_resources` 中。当前资源参数查询以 `output_resources` 为优先；产出资源的繁荣度经验倍率固定为 `0`。如果同一类型重复配置，收购交易虽然仍可完成，也会正常更新交易统计与输入库存，但不会增加繁荣度经验。贸易点设计时应将一种 CargoType 明确归入产出或消耗的一侧。

### 4.2 output_cargo_units

`output_cargo_units` 是贸易点已经生产完成、可供玩家购买的共享库存，同样按 CargoType 分项保存。

它通过两种方式增加：

1. `natural_cargo_units_increase`：每个交易日的自然增长；
2. `production`：消耗输入库存后产生的货物单位。

它通过购买货柜减少：

```text
对应 CargoType 的 output_cargo_units
    - 被购买货柜的 cargo_units
```

若剩余数量不足以支付货柜的 `cargo_units`，购买会被拒绝。

普通物品商店也使用同一库存。每购买一份商品，按照商店定义中的 `commodity.cargo_units` 扣除对应 CargoType 的 `output_cargo_units`。因此同一贸易点的商店终端和货柜出售终端会竞争同一份产出资源。

贸易点定义中的 `shop_definitions` 是商店定义候选池。自然生成时，每个商店终端独立加权抽取一次并持久化结果。商店商品列表容量读取当前繁荣等级对应的 `upgrade_list_count`；列表不按交易日刷新，仅在容量随繁荣等级增加时追加新商品。

## 5. 贸易点定义

### 5.1 核心字段

```json
{
  "display_name": "Default Trade Point",
  "node_role": "resource_site",
  "initial_level": 0,
  "upgrade_experience": [30, 80, 180, 400, 800],
  "upgrade_list_count": [3, 5, 9, 13, 20, 30],
  "ticks_per_day": 24000
}
```

- `display_name`：显示名称；
- `node_role`：贸易点类型和 GUI 角色；
- `initial_level`：新贸易点初始繁荣等级；
- `upgrade_experience`：各级升级所需经验；
- `upgrade_list_count`：各繁荣等级允许的普通出售槽位数；
- `ticks_per_day`：贸易点一个交易日的长度。

交易日索引、倒计时和结算基准统一使用单调递增的 `gameTime`。原版 `/time set` 和 `/time add` 只改变世界昼夜显示，不改变贸易点交易日，避免时间回拨导致重复结算或长期停滞。

管理员可以通过项目命令手动推进一个或多个交易日。完整语法、权限、参数和副作用统一参见[命令](../06开发与运维/03_命令.md#61-手动推进交易日)章节。

交易日索引和倒计时以世界 `GameTime` 计算，不使用受昼夜循环和 `/time set` 影响的 `DayTime`。因此即使关闭原版昼夜循环，服务器仍会按照实际运行 Tick 正常推进贸易日。

### 5.2 活跃度

```json
"activity": {
  "initial_activity": 0.0,
  "activity_window_days": 7,
  "expected_daily_trades": 10,
  "activity_step": 0.15,
  "restock_quantity_range": {
    "min": 1.0,
    "max": 1.5
  }
}
```

实际生产倍率在线性区间内按活跃度映射：

```text
multiplier = min + (max - min) × activity
```

该倍率作用于自然增长量和每批生产的产出量。输入配方消耗量保持为每批固定值。

### 5.3 动态经济

```json
"dynamic_economy": {
  "min_price_modifier": 0.7,
  "max_price_modifier": 1.3,
  "trade_price_step": 0.03,
  "daily_price_recovery_step": 0.05
}
```

动态价格按 `tradePointId + cargo_type` 独立保存。同一贸易点内，同 CargoType 的不同货柜定义共享价格冲击；不同贸易点互不影响。

## 6. 产出资源定义

```json
"output_resources": {
  "ore": {
    "sell_price_modifier": 1.15,
    "required_prosperity": 0,
    "natural_cargo_units_increase": 100,
    "stock_max": 500,
    "production": {
      "enabled": true,
      "inputs": {
        "agriculture": 5,
        "wood": 2
      },
      "output_cargo_units": 5
    }
  }
}
```

字段：

- `sell_price_modifier`：该贸易点出售此类型货物时的价格修正；
- `required_prosperity`：解锁所需整数繁荣等级；
- `natural_cargo_units_increase`：每个交易日的自然货物单位增长，默认 10；
- `stock_max`：该 CargoType 的 `output_cargo_units` 总上限，默认 500；
- `production.enabled`：是否启用配方生产，默认 `false`；
- `production.inputs`：每执行一批生产所需的固定输入货物单位；
- `production.output_cargo_units`：每批基础产出货物单位，默认 10。

`stock_max` 与 `production` 同级，即使在 `production.enabled=false` 时仍然生效，因为自然增长与生产共用同一个产出库存。

## 7. 每日生产

每日结算对每个已解锁的 `output_resources` 类型依次执行。

### 7.1 自然增长

```text
自然增长 = floor(natural_cargo_units_increase × 活跃度生产倍率)
```

结果写入对应 `output_cargo_units`，并钳制到该类型的 `stock_max`。

### 7.2 配方生产

每批实际产出：

```text
每批产出 = floor(output_cargo_units × 活跃度生产倍率)
```

每批输入消耗不乘活跃度倍率。例如：

```json
"inputs": {
  "agriculture": 5,
  "wood": 2
}
```

代表每一批固定消耗：

- 5 agriculture input cargo units；
- 2 wood input cargo units。

系统计算：

- 所有输入库存共同支持的最大批数；
- 距离输出 `stock_max` 尚需的有效批数。

取两者较小值后一次性扣除输入并增加输出。任一输入类型不存在、未启用库存或数量不足时，不执行不完整批次，也不会发生部分扣除。

空 `inputs` 的生产每天执行一批。

### 7.3 离线多日追赶

库存结算采用惰性执行，不要求终端或区块持续加载。当长时间无人访问后再次查询贸易点、打开终端或进行交易时，会根据已经过去的完整交易日逐日回放：

- 自然增长；
- 输入消耗；
- 生产产出；
- 库存上限钳制。

因此多日无人访问不会只得到一次补货。若库存已经满载且没有任何状态可继续变化，实现可以提前结束无效循环，但时间仍推进到正确交易日。

## 8. 收购流程

玩家出售货柜时：

1. 校验收购终端、菜单、区块加载和货柜实例；
2. 确认货柜 CargoType 属于贸易点已解锁的 `consumed_resources`；
3. 计算收购价格、繁荣度经验和许可证经验；
4. 完成货柜清理与货币发放；
5. 若该 CargoType 启用了 `inventory`，将货柜 `cargo_units` 加入共享 `inputs_cargo_units`；
6. 按输入库存 `max` 钳制。

同一 `tradePointId` 的所有终端和所有玩家共享该结果。

收购类型还必须遵守“产出/消耗类型不重叠”的定义约束。若同一 CargoType 同时存在于两侧，运行时会优先采用产出资源参数，其繁荣度经验倍率为 `0`。

## 9. 出售列表与购买流程

### 9.1 展示列表

`cargo_sale.cargo` 只决定哪些货柜模板有资格进入出售列表：

```json
{
  "cargo_definition": "cargoverse:aui_atlas_sd_s",
  "weight": 1,
  "always_available": false,
  "required_prosperity": 0
}
```

出售列表槽位由“货柜定义 + CargoType”唯一确定，因此：

- 同一货柜定义可以分别出现 ore 和 wood；
- 完全相同的“货柜定义 + CargoType”不会重复出现；
- 抽取优先按 CargoType 覆盖，并按 S、M、L、X、XL、SP 的等级顺序推进。

`cargo_sale.cargo` 不定义成品货柜库存。购买时直接按照实例的 CargoType 和 `cargo_units` 扣除贸易点对应的 `output_cargo_units`。

`always_available` 只影响列表槽位的固定展示和普通槽位占用，不绕过共享产出库存检查；购买仍需要足够的 `output_cargo_units`。

### 9.2 购买

购买数量由共享库存实时换算：

```text
当前可购买货柜数
    = floor(该 CargoType 的 output_cargo_units / 货柜 cargo_units)
```

购买流程：

1. 验证玩家打开了对应终端菜单；
2. 验证目标区块和终端；
3. 验证槽位确实处于当前展示列表；
4. 验证共享产出库存足够；
5. 验证并扣除货币；
6. 生成货柜实例；
7. 成功后从共享 `output_cargo_units` 扣除货柜 `cargo_units`；
8. 向客户端同步新的可购买数量。

服务端交易处理在主线程串行执行，因此多个玩家同时购买时共享同一库存，不会各自获得独立库存副本。

## 10. GUI 对接

贸易点总览：

- 左侧“消耗货物库存”读取 `inputs_cargo_units` 和 `consumed_resources.inventory.max`；
- 右侧“产出货物库存”读取 `output_cargo_units` 和 `output_resources.stock_max`；
- 两侧都使用 CargoType 图标、纯色进度条和 `当前值/最大值`。

出售终端的“库存剩余”不是本地库存，而是根据共享产出货物单位除以当前货柜的 `cargo_units` 得出的可购买货柜数。

## 11. 持久化与数据包重载

经济存档版本为 5，贸易点状态保存：

- `InputsCargoUnits`；
- `OutputCargoUnits`；
- 繁荣度、活跃度和交易统计；
- CargoType 动态价格；
- 最近交易窗口和最后结算日。

开发阶段不保留旧经济库存格式兼容。旧版本状态会按当前定义重新初始化。

数据包重载不会主动清空现有：

- 输入库存；
- 产出库存；
- 出售展示列表；
- 动态价格与贸易统计；
- 结算时间。

新定义会在后续正常读取和结算中生效。降低 `stock_max` 不要求立即删除已经存在的超额库存；后续增长会停止，并在正常结算时按当前上限处理。

## 12. 已移除字段

以下旧字段不再读取：

- `natural_cargo_output`；
- `natural_item_output`；
- `production.output_cargo_count`；
- `production.output_item_count`；
- 旧 `supplyByCargoType` 百分比供应量；
- 出售终端的 `visibleCargoStock`。

必须使用：

- `natural_cargo_units_increase`；
- `production.output_cargo_units`；
- `output_resources.<cargo_type>.stock_max`。
