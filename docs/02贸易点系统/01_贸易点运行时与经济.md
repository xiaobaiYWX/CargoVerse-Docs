# 贸易点运行时与经济

## 身份与库存方向

贸易点定义 ID 描述配置，例如 `cargoverse:resource/general/default`；贸易点实例 ID 区分世界中的不同站点。终端绑定实例，同一实例共享经济状态，不能把定义 ID 当成唯一站点身份。

贸易点信息柜是实例注册锚点，持有“实例 UUID + 贸易点定义 ID”。自然生成时，结构绑定选择定义并把同一 UUID 写入结构内终端；非自然生成时，信息柜自动生成 UUID，管理员在信息柜中填写已加载的贸易点定义 ID，再把该 UUID 手动填入其他终端。其他终端只保存 UUID，不允许输入贸易点定义路径，也不会在结构生成时接收定义副本。

手动放置不会隐式选择任何贸易点定义。信息柜的新实例只有自动生成的 UUID，定义字段为空；其他新终端的实例 UUID 也为空。空值不会回退到默认定义，也不会初始化产线或库存。未绑定终端仍绘制完整的世界表面仪表、按钮和滑块，但主状态仪表显示“未绑定”、其余数据栏保持空白或零位，服务端会拒绝这些控件发起的业务动作。`cargoverse:resource/general/default` 仅在结构绑定或管理员明确绑定时使用。

信息柜保存定义绑定时由服务端校验管理员模式、交互距离、控制器位置、资源 ID 格式和定义是否实际加载。无效定义不会覆盖原注册。对已有实例改绑另一份定义时，注册模块重新抽取，并清除该 UUID 的运行时经济状态；有资产的正式世界应优先新建 UUID。

产出库存 output 由贸易点向玩家出售，装载会减少它；输入库存 input 接收玩家卸下的货物，再由生产线消耗。输入与输出货物由初始化后的生产线布局派生。

每槽容量 = `capacity_per_slot × (1 + 当前繁荣等级 × capacity_growth_per_level)`。初始库存全部为 0；数量使用 double 保存，玩家装卸仍使用整数 t。

定义字段与完整 JSON 见[贸易点定义](04_贸易点定义.md)，生产线选择器见[生产线池](03_生产线池定义.md)。

## 初始化解析

首次创建贸易点经济实例时解析产线；实例 ID 提供稳定随机种子。只在初始化判断初始繁荣等级及贸易点 tech_level。

1. 按 production_pools 数组顺序处理，fixed 尝试指定内部 ID，允许 weight=0；random 按正权重无放回抽取。
2. 全局去重键为“完整池 ID + 内部产线 ID”；不同池的同名内部 ID 不冲突。
3. 候选先解析输入：优先复用已有 input_goods；否则尝试新增具体输入。
4. 输入选择顺序固定为科技等级、基础价值、分类常规程度、完整 ID 字典序。
5. 同一货物不能同时出现在输入与输出，输入也不能匹配该候选自身的输出。
6. 在临时集合中完成整条候选校验，失败不占槽，不污染后续候选。
7. 随机阶段输出未满只接收新增输出；输出满但输入未满才允许复用输出；两侧都满停止，包括后续固定引用。
8. 无可用候选时结束当前随机引用，不无限重试。

分类常规程度仅作为科技等级与价值相同后的选择顺序：普通分类 → 环境危害 → 特殊资源/科研样本 → 异常货物 → none。它不改变 CargoClass 的贴花或分类定义。

只有输出槽已满时，随机选择阶段才允许复用已有输出。

`all` 仍为标签集合完全一致，`any` 为至少一个标签匹配，空标签列表为不限制标签；都需满足科技范围。消费率为 0 的输入仍要绑定槽位，但不实际扣库存。

## 运行时与日结

持久化的是初始化结果，而非 selector：

```text
TradePointState
├─ 贸易点实例 ID、繁荣等级/经验
├─ activity / lastActivityDay / currentDayTradeValue
├─ productionLayout.selectedLines[]
│  ├─ poolId / lineId / displayName
│  ├─ output: cargoGood + amount
│  └─ inputs[]: cargoGood + consumptionRate + 每批数量
├─ productionLayout.lineSlots[5]: 有序产线键；空字符串表示空槽
├─ inputsCargoUnits: 具体货物 ID → double 库存
├─ outputCargoUnits: 具体货物 ID → double 库存
└─ 累计交易统计、各货物动态价格状态
```

selectedLines 内嵌具体输入绑定；input_goods/output_goods 由全部抽取结果派生，并要求库存键与布局完全一致。NBT 保存产出量、消费率和每条线所在槽位，读取时恢复每批消耗量，不查 selector。

- 每个贸易点固定拥有 5 个生产线槽位。初始化抽取后，前 5 条产线按抽取顺序自动填槽，超出的抽取结果保留但默认不启用。
- 只有已加入槽位的产线参与生产；产线不能重复占据多个槽位。
- 产线严格按槽位 1 → 5 的顺序执行，该顺序就是共享输入不足时的生产优先级；空槽直接跳过。
- 生产线终端左侧 `up`/`down` 只切换抽取结果预览；右侧 `slot_up`/`slot_down` 选择槽位，`confirm` 对当前槽执行添加／移除。槽位副屏固定显示 5 个槽位，只使用模型屏面上方未被操作台遮挡的 `10×15 MCpx`，对应 `80×120` 普通密度画布；底部约 4 MCpx 不绘制内容。
- 槽位调整只改变启用状态和执行顺序，不删除抽取结果、库存键或已有库存，也不发生 output 回流 input。
- 每条线产出与所有输入消耗使用**相同倍率**。
- 输入不足或输出余量不足时，按可执行比例缩小批次；不先扣输入再丢弃溢出产出。
- 库存保留小数，不向上取整产生免费货物；玩家现有整数 t 交易输入方式不变。
- 长时间离线按公式汇总每天生产倍率，再按产线数处理库存；不会按离线天数循环。
- 已有库存高于重载后的新容量时不删除库存，只暂停向该槽继续生产。
- 已保存的产线、绑定、批次量在重载后保持不变；新增/修改 selector 不触发旧点重抽。
- 若某绑定货物在新数据中不存在，该产线暂停，保留库存和绑定；恢复货物后继续运行。
- 升级只改变容量和经验，不自动抽取高等级新产线。

### 活跃度

装载／卸货货物交易仅累积：

```text
有效交易价值 = 实际交易 t 数 × CargoGood 基础价值 × 输入/输出方向权重
```

不使用付款金额、折扣或交易点击次数；货柜制造购买不计入货物活跃度。贸易点信息柜的世界表面仪表显示当日有效贸易额、活跃度和下一交易日倒计时；输入／输出库存由仓库信息柜显示。

跨日时先结算未结算交易日，再一次性计算其余空白天：

```text
load = clamp(currentDayTradeValue / expectedDailyTradeValue, 0, maxDailyLoad)
first = activity + responseRate × (clamp(load, 0, 1) - activity)
final = first × (1 - responseRate) ^ (elapsedDays - 1)
```

同日或世界时间回退不结算、不清空待结算价值。日结后将 currentDayTradeValue 清零并记录当前日期。

生产倍率为 `min + activity × (max - min)`，用等比级数求和计算离线区间总倍率。`random_multiplier` 固定为 **1.0**。

## 内置内容

默认点 `cargoverse:resource/general/default`：

- 固定矿石自然线：每批 12t，无输入。
- 固定木材自然线：每批 6t，无输入。
- 随机候选农业线：每批 12t 农业产品，消耗 6t 化工原料、12t 能源原料。
- 输入槽实际占用 2/4，输出槽实际占用 3/3，不强行填满输入。
- 化工原料补充 `fertilizer`，能源原料补充 `energy` 标签，供此测试链选择；其他货物的原有数据不因此泛化为可消耗物资。
- 0 活跃度时倍率 0.8，自然线一天分别生成 9.6t 矿石、4.8t 木材；没有输入时农业线不产出。



## 价格与交易记账

- `pricing.buy_price_multiplier` 是贸易点向玩家收购的倍率，即卸货。
- `pricing.sell_price_multiplier` 是贸易点向玩家出售的倍率，即装货。
- 关闭 dynamic_price 只关闭动态修正，基础倍率仍生效；活跃度不参与价格。
- 动态价格按货物维护并在日结恢复／应用待结算交易变化，不按 CargoClass 合并。
- 玩家许可证签发制造商与贸易点制造商相同时，最后应用制造商 `signed_courier_bonus`；不匹配时修正为 `1.0`。
- 玩家向有制造商归属的贸易点卸货时，按货物基础价值和最高匹配货物偏好增加该制造商声望；`manufacturer: "none"` 不产生声望。
- 货柜制造不消耗产出货物库存，也不计货物交易活跃度。
- 装卸与整柜收购都读取运行时实际库存；整柜入口检查整批货物能否容纳。
- 普通物品售货定义是独立子功能资源，绑定由 `modules.item_shop` 管理。贸易点注册时抽取定义和符合既有 output stock 类型的商品 ID 并持久化；所有绑定该实例的物品售货机读取同一选择，终端建筑是否生成不影响抽取。

制造商声望与签约价格公式见[制造商定义](../01货柜系统/01核心系统/08_制造商定义.md)。

## 加载与存档

`CargoDataReloadListener` 在同轮 prepare 中校验货物、容器、制造商、基础货柜、三个子功能定义、生产线池、贸易点和结构绑定，成功后整体发布。模块候选必须引用存在的对应定义。`TradePointDefinitionReloadListener` 只提供解析和读取门面。

贸易点经济 `DataVersion=8`，网络协议版本为 `34`。相同定义再次注册时保留已有选择，同步模块解锁等级、补充新增模块并移除定义中不存在的模块；改为另一份贸易点定义时重建该实例的运行时经济状态。已保存的产线批次、输入绑定、模块选择与库存不因单纯重载而重抽。货物缺失时暂停受影响产线并保留数据，容量缩小不删除超出上限的现有库存。

贸易点模块当前由生产线、物品商店、货柜制造台与注册点消费者读取。运行时保存抽中的模块定义 ID，并在同一贸易点实例的终端间共享。
