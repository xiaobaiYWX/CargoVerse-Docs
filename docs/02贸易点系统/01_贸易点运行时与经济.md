# 贸易点运行时与经济

更新：2026-10-20。实际物品资源表为 schema 3；内置 40 张自然站买卖表为空，A／B 两张指令测试表已填充，以下描述已实现的运行时，不代表已经填充自然经济内容。

## 身份与绑定

贸易点定义 ID 描述配置，贸易点实例 UUID 区分具体站点。信息柜是注册锚点，所属终端绑定实例 UUID 并共享经济状态。手动普通点由管理员使用终端连接工具配置；无有效定义、实例或锚点时业务不可用。自然生成结构内绑定锁定，不能再手动解绑或二次绑定。

## 资源目录初始化

定义通过 resource_table 引用资源表。首次建立状态时严格解析实际物品及完整组件，生成精确变体的出售/收购目录；同侧不能重复，同站同一变体不能双向交易。出售侧有 stock 才建立有限库存，省略为无限供应；收购侧 daily_limit 省略或 0 表示不设限。

站点保存报价、库存/额度策略与收购侧每件经验快照。普通 reload 不替换既有实例目录；验证新配置需新建实例或测试存档。不再引用抽象货物或全局商品目录，字段见[报价定义](03_资源表定义.md)。

## 出售库存与收购额度

出售库存仅为有限供应条目保存整数物品数，购买后扣减，各条目独立容量。自然站收购不保存实物仓库；交付计入所有玩家共享的当日额度，不转成出售库存，也不自动生产其他物品。

玩家贸易点使用另一套[Create 保险库存储规则](../11玩家贸易点/02_库存、报价与结算.md)，不能将自然站虚拟供需库存复制成玩家仓库。

## 贸易日结算

跨过完整贸易日时一次性处理补货、活跃度和动态价格，清空当日收购计数：

```text
出售库存 = min(容量, 当前库存 + 每日补货 × 经过天数)
```

未用每日额度不累积，活跃度不改变补货或额度。日长来自 ticks_per_day。

## 活跃度与繁荣度

```text
有效交易价值 = 实际转移件数 × 该方向站点基准 unit_price × 对应方向权重
负载 = clamp(当日有效交易价值 ÷ expected_daily_trade_value, 0, max_daily_load)
目标活跃度 = clamp(负载, 0, 1)
新活跃度 = 旧活跃度 + response_rate × (目标活跃度 - 旧活跃度)
```

活跃度用基准报价衡量吞吐，不用实际支付金额或点击次数替代。繁荣度经验由自然生成目的地实际成交数量 × 当地收购每件经验决定，默认 0；玩家目的地不奖励。完整目的地资格与失败回滚见[运输经验](03_资源表定义.md#运输经验资格)。

## 价格、制造商与声望

- 每个站点用自己的 unit_price 定价，应用动态行情和最后一层制造商签约修正；没有全局物品基础价格。
- 按实际转移数量结算，货损已经扣掉件数，不再乘完整度。
- 动态价格按精确物品变体独立记录并按贸易日恢复。
- 签约价格修正仅在许可证签发制造商与站点制造商匹配时生效。
- 制造商交货声望使用站点收购基准单价、实际交付件数及分类偏好，不与许可证/繁荣度经验混用。
- manufacturer 为 none 不产生制造商声望或签约修正。

普通物品商店、货柜制造台和注册点保留独立功能配置及结算边界，不向货物资源表隐式添加商品。

## 加载与存档

设备、运输、制造商、功能、资源表和站点定义与服务端物品标签统一校验发布。经济存档 DataVersion=15；货柜、内容封套和网络版本以[运输数值运行时](../01货柜系统/01核心系统/14_运输数值运行时.md#保存采样与性能)为准。开发期不迁移旧实例或旧抽象经济/完整度/自有仓库，不保留旧版本逐级转换链。损坏或未知原生类型的新载荷保留原文隔离，不静默恢复成空柜。

实现入口：TradePointState、TradePointStateCodec、TradePointInventoryService、TradePointAcquisitionLimit、TradePointDayProcessor、TradePointTransactionService、NaturalTransportExperienceService。
