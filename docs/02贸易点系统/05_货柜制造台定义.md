# 货柜制造台定义

货柜制造台使用玩家随身携带的实体物品作为制造材料，并从虚空结算器扣除 VB 加工费。贸易点只负责提供制造目录、繁荣门槛和货柜生成点；制造过程不读取或修改贸易点的收购库存，也不把材料登记为 CargoGood。

定义目录：

```text
data/<namespace>/trade_points/trade_points_subfunctions/
  cargo_manufacturing_platform_definitions/<path>.json
```

文件相对目录的路径就是定义 ID。例如 `resource/general/default.json` 对应 `cargoverse:resource/general/default`，由贸易点 `modules.cargo_manufacturing_platform.definitions_pool[].definition` 引用。

## 格式

```json
{
  "schema_version": 2,
  "display_name": "基础货柜制造台",
  "recipes": [
    {
      "id": "atlas_sd_s",
      "min_prosperity_level": 0,
      "required_license_level": "S",
      "cargo_container_definition": "cargoverse:aui/atlas_sd_s",
      "currency_cost": {
        "currency": "cargoverse:void_byte",
        "amount": 80
      },
      "item_costs": [
        {
          "ingredient": { "item": "minecraft:iron_ingot" },
          "count": 16
        },
        {
          "ingredient": { "tag": "minecraft:planks" },
          "count": 8
        }
      ]
    }
  ]
}
```

## 顶层字段

| 字段 | 格式 | 说明 |
| --- | --- | --- |
| `schema_version` | 固定为 `2` | v1 与 `stock_costs` 不受支持 |
| `display_name` | 非空字符串或 Component | 制造台定义名称 |
| `recipes` | 1～256 项 | 本定义提供的制造条目 |

## 配方字段

| 字段 | 格式 | 说明 |
| --- | --- | --- |
| `id` | `[a-z0-9_.-]+` | 文件内唯一的局部配方 ID |
| `min_prosperity_level` | 非负整数 | 配方最低繁荣等级；与贸易点模块门槛取较高值 |
| `required_license_level` | `S`、`M`、`L`、`X`、`XL`、`SP` | 玩家最低许可证等级 |
| `cargo_container_definition` | 已存在的货柜定义 ID | 结果货柜；同一制造台定义内不得重复 |
| `currency_cost` | 对象 | VB 加工费 |
| `item_costs` | 1～8 项 | 玩家承担的实体物品材料 |

`currency_cost.currency` 固定为 `cargoverse:void_byte`；`amount` 是 `0..2147483647` 的整数。金额为零只表示免加工费，不能省略材料。

## 实体物品材料

每项材料由 `ingredient` 和 `count` 组成：

| 字段 | 格式 | 说明 |
| --- | --- | --- |
| `ingredient.item` | 物品注册 ID | 指定一种物品 |
| `ingredient.tag` | Minecraft 物品标签 ID | 标签内任意普通物品均可参与 |
| `count` | 1～4096 的整数 | 实际消耗的物品个数 |

`item` 与 `tag` 必须严格二选一。标签不是 CargoGood 标签，不支持旧 `match_mode`、吨位、NBT 或组件谓词。标签需求可以由多个候选物品与多个堆叠共同满足。

以下物品不会参与制造：

- 带自定义组件的堆叠；
- 有合成剩余物的容器或工具；
- 盔甲、副手、鼠标拖拽物、末影箱、潜影盒内部、模组背包、附近容器与地面掉落物。

系统只扫描玩家主背包 27 格与快捷栏 9 格，并优先使用主背包。多个材料条件发生重叠时会为整张配方求出可行分配，不会把同一件物品重复计算，也不会因逐项贪心选择而误报缺料。

## 显示与确认

公共制造台仪表显示货柜信息、VB 加工费和配方材料的物品图标及数量，不显示任何玩家的持有量。

玩家按下制造按钮后，服务端生成私有确认页，显示：

- 本次货柜与加工费；
- 每项材料的需求、已分配数量与缺口；
- 本次实际选择扣除的物品；
- 许可证、繁荣、调度点、付款和生成区域状态。

确认请求绑定操作玩家、制造台坐标、配方、数据版本和材料分配，一次令牌只能提交一次。数据重载或背包材料分配变化后，旧确认不会静默改价或换料，而是刷新内容并要求再次确认。

## 制造事务

确认时服务端重新检查贸易点绑定、生成点、模板、许可、繁荣、调度点、VB 余额、实体材料和完整生成范围。验证通过后，在同一串行补偿事务中：

1. 扣除 VB；
2. 按确定的槽位计划扣除实体材料；
3. 生成并登记空货柜；
4. 记录设备交易。

任一步失败都会移除本次生成物、原位恢复材料并退款。制造材料不更新贸易点库存，不产生 CargoGood 交货记录。

实现入口：`CargoManufacturingPlatformDefinition`、`CargoManufacturingItemMatcher`、`CargoManufacturingOrderService`、`CargoManufacturingTransaction`、`CargoManufacturingDisplayService`。
