# 实际货物报价与运输经验

更新：2026-10-20。资源表现在使用 schema 3，为具体贸易点定义实际物品报价，不再引用抽象 CargoGood 或物品固有基础价。40 张自然站表仍为空、设计待发布；A／B 两张指令测试表已覆盖本轮设计的 149 种实际物品。

## 路径与完整示例

`data/<namespace>/trade_points/resource_tables/<resource|factory|market>/<分类>/<名称>.json`

资源 ID 是 resource_tables/ 后的路径，不含 .json。站点定义仍通过 resource_table 引用；共享同一张表表示共享报价模板，不代表物品自带价格。同一资源 ID 按数据包优先级整体覆盖。

以下仅为配置示例，未写入内置交易表：

```json
{
  "schema_version": 3,
  "sales": [
    {
      "rule_id": "iron",
      "item": "minecraft:iron_ingot",
      "unit_price": 7,
      "stock": {
        "initial": 100,
        "capacity": 500,
        "daily_restock": 20
      }
    }
  ],
  "acquisitions": [
    {
      "rule_id": "glass",
      "item": "minecraft:glass",
      "unit_price": 9,
      "daily_limit": 200,
      "license_experience_per_item": 2,
      "prosperity_experience_per_item": 3
    }
  ]
}
```

## 字段规则

| 字段 | 规则 |
| --- | --- |
| schema_version | 必填，当前仅接受整数 3；不迁移旧抽象格式 |
| sales / acquisitions | 必填数组，每侧最多 256 条；全局最多 4096 张表 |
| rule_id | 每侧唯一的规则键，最多 64 字符，使用小写字母、数字、下划线、点和连字符 |
| type | 可选，支持 solid／liquid；省略时为 item 字段的物品身份。液体必须声明 type=liquid 和 fluid，不能同时填写 item；独立 gas 和 living 类型仍拒绝 |
| item | 实际注册物品 ID，不能为空气；在服务端注册表中严格验证 |
| fluid | liquid 必填的已注册流体 ID；c:gaseous 气体同样使用 liquid 类型；完整示例见[液体运输](../01货柜系统/01核心系统/13_液体运输.md) |
| components | 可选原生组件补丁；省略表示该物品默认状态，不通配耐久、名称、附魔等所有变体 |
| unit_price | 每操作份的本地基准报价（物品 1pcs／液体 1000mB），必填非负整数 VB；允许明确设为 0，但缺少报价条目不等于免费 |
| stock | 仅出售侧，可省略；省略表示无限供应，填写后为有限库存 |
| stock.initial | 初始整数份数，默认 0，不超过 capacity |
| stock.capacity | 填写 stock 时必须有效且大于 0 |
| stock.daily_restock | 每贸易日补货整数份数，默认 0，达到上限停止 |
| daily_limit | 仅收购侧；非负整数，省略或 0 表示不设每日限额 |
| license_experience_per_item | 仅收购侧，每份合格交付的许可证经验（物品每组、液体每 1000mB），非负整数，默认 0 |
| prosperity_experience_per_item | 仅收购侧，每份合格交付的目的地繁荣度经验（液体每 1000mB），非负整数，默认 0 |

同一侧不能重复报价同一个完整组件变体，同一站点也不能同时出售与收购同一精确变体。不同变体可分别定价。未知物品/组件、非空嵌套内容、不合法参数拒绝新一代配置，不静默替换成普通物品。

原生物品、完整组件与货物身份关联；配置加载时注册精确变体以供装载/库存目录使用。运输分类、质量与词条仍由运输配置独立决定，报价不授予装柜许可。

实际收付款以本条 unit_price 为基准，再应用现有行情和签约修正。终端仪表、信息柜、交易预览与实际结算均使用该站报价；行情差值相对本条基准报价，不查全局物品价格。

## 运输经验资格

经验只由**收购目的地**决定，不再判断或记录货物来源。

| 来源 → 目的地 | 许可证经验 | 繁荣度经验 |
| --- | --- | --- |
| 自然贸易点 → 自然生成贸易点 | 实际成交件数 × 目的地收购配置 | 同左，增加在目的地 |
| 玩家贸易点 → 自然生成贸易点 | 同上 | 同上 |
| 玩家贸易点 → 玩家贸易点 | 无 | 无 |
| 自然贸易点 → 玩家贸易点 | 无 | 无 |

目的地自然生成身份由服务端结构实例目录、注册状态和维度核验，不根据 ID 前缀、所有者或客户端声明猜测。手动创建的普通点可以正常交易，但不作为自然生成目的地奖励经验。自产、探索所得、管理员补入或经过保险库中转的物品，都不因来源而被排除。

出发购买、仓库管理装卸和玩家贸易点交易本身不产生经验。许可证经验给实际交付玩家；繁荣度经验给收购目的地。交易金额、动态行情和制造商声望仍沿用各自机制。

## 成交数量、损耗与回滚

经验只计算自然目的地实际成功收购的份数（物品按冻结最大堆叠组、液体按 1000mB），尾量按比例折算后每笔向下取整，不保存小数余数；不按售价、原始装载量或完整度加权。每份经验默认 0，结果饱和到 int 上限。损耗、未成交货物、失败交易及重复卸空不会产生经验。

货柜不再保存来源批次，不向物品组件写入来源，也不再维护 FIFO 来源或来源数量一致性。一个货柜仍只装一种完整组件身份；部分卸货保留其余载荷与运输时钟，入库结束运输、再次出库按现行运输配置建立新快照。

货物、收付款、站点状态和两类经验在同一个补偿事务内提交，后续步骤失败恢复原状态。预览复用同一目的地判定，不作为独立领奖凭据。来源和距离不再参与奖励判定，也不额外限制同站回售；报价仍禁止同站同时收售同一精确变体。

## 实例快照与开发版本

报价在贸易点首次创建运行时状态时保存快照，普通 reload 不替换既有实例的目录或报价；测试新配置应使用新建站点/测试存档。服务器重启后，载荷中保存完整物品身份，因此可重新关联报价变体。

载荷实例格式为 10、内容封套 1、物品载荷包络 2；贸易点经济格式仍为 15，不提供旧开发货柜条目迁移。报价身份解析已按介质独立分发，已接入物品和液体库存目录；液体载荷包络为 1，报价库存保存操作份数，流体载荷与玩家仓库保存原生 mB。商品菜单由仓库终端提供，核心不提供商品管理入口。
