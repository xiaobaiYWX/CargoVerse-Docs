# 资源表定义

资源表定义贸易点出售和收购哪些货物、出售货物采用有限库存还是无限供应，以及收购货物是否具有每日额度。它不描述原料转化、生产配方或生产槽位。

## 路径与 ID

```text
data/<namespace>/trade_points/resource_tables/<resource|factory|market>/<分类>/<名称>.json
```

ID 取 `resource_tables/` 后的完整路径。例如：

```text
data/cargoverse/trade_points/resource_tables/resource/general/default.json
→ cargoverse:resource/general/default
```

同一完整 ID 按数据包优先级整体覆盖。单次重载最多加载 4096 份资源表，每一侧最多 256 条规则。

## 完整示例

```json
{
  "schema_version": 1,
  "sales": [
    {
      "id": "hematite_ore",
      "selector": {
        "match_mode": "all",
        "tags": ["ingredient.raw_resource.hematite_ore"]
      },
      "price_multiplier": 0.85,
      "create_inventory": true,
      "initial_amount": 0,
      "capacity_per_good": 160,
      "daily_restock_per_good": 12
    },
    {
      "id": "general_supplies",
      "selector": {
        "match_mode": "any",
        "tags": ["ingredient.general_supplies.durable_workwear", "ingredient.general_supplies.shelf_stable_rations"]
      },
      "create_inventory": false
    }
  ],
  "acquisitions": [
    {
      "id": "industrial_inputs",
      "selector": {
        "match_mode": "any",
        "tags": ["ingredient.chemical_material.compound_fertilizer", "ingredient.energy_fuel.biomass_briquettes"]
      },
      "price_multiplier": 1.15,
      "daily_limit_enabled": true,
      "daily_limit_per_good": 80
    }
  ]
}
```

## 顶层字段

| 字段 | 规则 |
| --- | --- |
| `schema_version` | 必填整数，当前只接受 `1` |
| `sales` | 必填数组；贸易点向玩家出售的货物规则 |
| `acquisitions` | 必填数组；贸易点向玩家收购的货物规则 |

`sales` 维护出售目录及可选库存，`acquisitions` 维护收购目录及可选每日额度。交付货物完成结算后离开贸易库存体系，不转入出售库存。

## 通用规则字段

| 字段 | 规则 |
| --- | --- |
| `id` | 规则内唯一；只允许小写字母、数字、下划线、点和短横线 |
| `selector.match_mode` | 必填，`any` 或 `all` |
| `selector.tags` | 必填非空字符串数组 |
| `price_multiplier` | 可省略，默认 `1.0`，范围 `0..1000`；该规则匹配出的每种货物各自使用此价格倍率 |

`any` 表示货物至少拥有一个指定标签；`all` 表示货物包含全部指定标签，允许同时拥有其他标签。资源表加载时按 CargoGood 完整 ID 排序匹配，并把具体货物清单写入贸易点实例。以后重载数据不会替已有实例重新选货。

每条规则必须至少匹配一个 CargoGood，否则整轮数据加载失败。同一侧的规则不能重复匹配同一种货物；同一贸易点也不能同时出售和收购同一种货物。

`price_multiplier` 是货物规则自身的基础价格修正，不再与站点级买卖倍率叠加。出售规则的倍率用于玩家购买价格，收购规则的倍率用于玩家交付收入。若同一标签规则匹配多种货物，它们会继承相同倍率；需要逐项定价时，应拆成多条只匹配目标货物的规则。

## 出售模式

仅出售规则必填 `create_inventory`：

- `false`：无限供应，不检查或扣减库存；只填写 ID、selector 和此开关，不能附带库存数值。
- `true`：有限库存，必须填写下表三个数值；没有存货时暂停出售。

## 出售库存

当销售规则的 `create_inventory` 为 `true` 时，必须增加：

| 字段 | 规则 |
| --- | --- |
| `initial_amount` | 每种匹配货物的新实例初始库存，`0..capacity_per_good`，单位 t |
| `capacity_per_good` | 每种匹配货物各自的库存上限，有限正数，单位 t |
| `daily_restock_per_good` | 每个贸易日为每种匹配货物补充的数量，可为 0，达到上限后停止 |

玩家购买会扣减对应出售库存。多种货物匹配同一规则时，每种货物都独立获得完整容量与补货量，不共享总容量。

## 收购与每日额度

收购规则不建立库存，也没有自然消耗或满库状态。除 `id` 和 `selector` 外，可以增加：

| 字段 | 规则 |
| --- | --- |
| `daily_limit_enabled` | 可省略，默认 `false`；是否启用每日收购额度 |
| `daily_limit_per_good` | 仅开关为 `true` 时必填，正整数；每种匹配货物在每个贸易点实例中的每日最大收购量 |

开关关闭时不能填写 `daily_limit_per_good`。同一规则匹配多种货物时，每种货物独享完整额度，不共享规则总额。额度由同一贸易点实例中的所有玩家共享；本次卸货超过剩余额度时整笔拒绝，不会自动截断。跨越该贸易点的下一个贸易日后计数直接清零，不进行逐日回落计算。

单次卸货量仍受玩家请求数量和柜内实际货量限制；许可证、所有权、货物兼容性和结算器校验照常执行。

交付照常发放货款、许可证经验、站点繁荣经验和制造商声望，并记录交易量与动态价格统计。交付不会增加出售库存，也不会触发材料转化。

旧版收购行中的 `create_inventory`、`initial_amount`、`capacity_per_good`、`daily_consumption_per_good`、`accept_when_full` 仍然禁止使用；每日额度不是库存。资源表 `schema_version` 仍为 1。

## 实例与存档

贸易点首次建立运行时状态时，将资源表解析后的具体 CargoGood、规则 ID、逐项价格倍率、出售侧库存参数和收购侧每日额度参数一起持久化。存档不保留 selector，也不因标签或资源表重载而改写既有实例。

经济存档使用 `DataVersion=12`，保存解析后的逐项价格倍率。版本 11 缺少该字段时按 `1.0` 迁移；版本 10 加载后以空的当日收购计数升级；版本 9 仍会先移除旧收购库存和收购策略。原出售余量、出售目录参数、成长、交易统计与模块绑定均保留，售罄的一次性批次不会重置。版本 8 及更早的生产线存档仍不支持迁移。

实现依据：`trade/resource/ResourceTableDefinition.java`、`ResourceTagSelector.java`、`ResourceTables.java`、`TradePointResourceCatalog.java`、`TradePointAcquisitionLimit.java`。
