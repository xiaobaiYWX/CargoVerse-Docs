# 资源表定义

资源表直接定义贸易点出售和收购哪些 CargoGood、出售货物采用有限库存还是无限供应，以及收购货物是否具有每日额度。它不再承担自动筛选、标签匹配、材料转化、生产配方或生产槽位。

## 路径与 ID

```text
data/<namespace>/trade_points/resource_tables/<resource|factory|market>/<分类>/<名称>.json
```

ID 取 `resource_tables/` 后的完整路径。例如：

```text
data/cargoverse/trade_points/resource_tables/resource/general/default.json
→ cargoverse:resource/general/default
```

同一完整 ID 按数据包优先级整体覆盖。单次重载最多加载 4096 份资源表，每一侧最多 256 条货物条目。

## 完整示例

```json
{
  "schema_version": 2,
  "sales": [
    {
      "cargo_good": "cargoverse:raw_resource/hematite_ore",
      "price_multiplier": 0.85,
      "inventory": {
        "initial": 0,
        "capacity": 160,
        "daily_restock": 12
      }
    },
    {
      "cargo_good": "cargoverse:general_supplies/durable_workwear"
    }
  ],
  "acquisitions": [
    {
      "cargo_good": "cargoverse:chemical_material/compound_fertilizer",
      "price_multiplier": 1.15,
      "daily_limit": 80
    },
    {
      "cargo_good": "cargoverse:energy_fuel/biomass_briquettes"
    }
  ]
}
```

## 顶层字段

| 字段 | 规则 |
| --- | --- |
| `schema_version` | 必填整数，当前只接受 `2` |
| `sales` | 必填数组；贸易点向玩家出售的 CargoGood 条目 |
| `acquisitions` | 必填数组；贸易点向玩家收购的 CargoGood 条目 |

`sales` 维护出售目录及可选库存，`acquisitions` 维护收购目录及可选每日额度。交付货物完成结算后离开贸易库存体系，不转入出售库存。

## 通用条目字段

| 字段 | 规则 |
| --- | --- |
| `cargo_good` | 必填 CargoGood 完整资源 ID，必须存在且不能是 `none` 预留货物 |
| `price_multiplier` | 可省略，默认 `1.0`，范围 `0..1000`；该货物独立使用此价格倍率 |

每个数组内不能重复填写同一种货物；同一贸易点也不能同时出售和收购同一种货物。资源表不会根据 CargoGood 的科技等级、分类或其他元数据自动扩展目录。

`price_multiplier` 是该商品自身的基础价格修正，不与站点级买卖倍率叠加。出售条目的倍率用于玩家购买价格，收购条目的倍率用于玩家交付收入。

## 出售与库存

出售条目省略 `inventory` 时表示无限供应，不检查或扣减库存。需要有限库存时填写完整对象：

| 字段 | 规则 |
| --- | --- |
| `inventory.initial` | 新实例初始库存，范围 `0..capacity`，单位 t |
| `inventory.capacity` | 库存上限，必须为有限正数，单位 t |
| `inventory.daily_restock` | 每个贸易日补充的数量，可为 0，达到上限后停止 |

玩家购买会扣减对应出售库存；库存为零时暂停出售。库存参数只属于当前 `cargo_good`，不存在共享容量。

## 收购与每日额度

收购条目不建立库存，也没有自然消耗或满库状态。省略 `daily_limit` 表示不限额；填写时必须为正整数，表示该 CargoGood 在每个贸易点实例中的每日最大收购量。

额度由同一贸易点实例中的所有玩家共享；本次卸货超过剩余额度时整笔拒绝，不会自动截断。进入该贸易点的下一个贸易日后计数直接清零，不进行逐日回落计算。

单次卸货量仍受玩家请求数量和柜内实际货量限制；许可证、所有权、货物兼容性和结算器校验照常执行。交付照常发放货款、许可证经验、站点繁荣经验和制造商声望，并记录交易量与动态价格统计。交付不会增加出售库存，也不会触发材料转化。

## 已删除的旧字段

资源表 schema 2 不再接受以下生产线与自动匹配遗留字段：

- `id`
- `selector`
- `match_mode`
- `tags`
- `create_inventory`
- `initial_amount`
- `capacity_per_good`
- `daily_restock_per_good`
- `daily_limit_enabled`
- `daily_limit_per_good`

需要多种货物时，为每个 CargoGood 分别建立一条显式条目。这样价格、库存和限额都能独立维护，也不会因 CargoGood 元数据变化而改变贸易目录。

## 实例与存档

贸易点首次建立运行时状态时，将资源表中的具体 CargoGood、逐项价格倍率、出售侧库存参数和收购侧每日额度一起持久化。既有实例保存资源目录快照，普通数据包重载不会替换它的目录和报价。

经济存档仍保留内部规则键，以兼容已有目录快照；新定义不再要求作者维护规则 ID，加载器会从 CargoGood ID 派生稳定内部键。

实现依据：`trade/resource/ResourceTableDefinition.java`、`ResourceTables.java`、`TradePointResourceCatalog.java`、`TradePointAcquisitionLimit.java`。
