# 资源表定义

资源表定义贸易点出售和收购哪些货物，以及每一种货物是否维护库存。它不描述原料转化、生产配方或生产槽位。

## 路径与 ID

```text
data/<namespace>/trade_points/resource_tables/<resource|factory|market>/<分类>/<名称>.json
```

ID 取 `resource_tables/` 后的完整路径。例如：

```text
data/cargoverse/trade_points/resource_tables/resource/general/default.json
→ cargoverse:resource/general/default
```

同一完整 ID 按数据包优先级整体覆盖。单次重载最多加载 4096 份资源表，每一侧最多 256 条规则。

## 完整示例

```json
{
  "schema_version": 1,
  "sales": [
    {
      "id": "hematite_ore",
      "selector": {
        "match_mode": "all",
        "tags": ["ingredient.raw_resource.hematite_ore"]
      },
      "create_inventory": true,
      "initial_amount": 0,
      "capacity_per_good": 160,
      "daily_restock_per_good": 12
    },
    {
      "id": "general_supplies",
      "selector": {
        "match_mode": "any",
        "tags": ["cargo.general_supplies", "cargo.food"]
      },
      "create_inventory": false
    }
  ],
  "acquisitions": [
    {
      "id": "industrial_inputs",
      "selector": {
        "match_mode": "any",
        "tags": ["ingredient.chemical_material", "ingredient.energy_fuel"]
      },
      "create_inventory": true,
      "initial_amount": 0,
      "capacity_per_good": 120,
      "daily_consumption_per_good": 6,
      "accept_when_full": false
    }
  ]
}
```

## 顶层字段

| 字段 | 规则 |
| --- | --- |
| `schema_version` | 必填整数，当前只接受 `1` |
| `sales` | 必填数组；贸易点向玩家出售的货物规则 |
| `acquisitions` | 必填数组；贸易点向玩家收购的货物规则 |

`sales` 与 `acquisitions` 分别维护目录和库存，不会自动转移，也不存在输入到输出的转化关系。

## 通用规则字段

| 字段 | 规则 |
| --- | --- |
| `id` | 规则内唯一；只允许小写字母、数字、下划线、点和短横线 |
| `selector.match_mode` | 必填，`any` 或 `all` |
| `selector.tags` | 必填非空字符串数组 |
| `create_inventory` | 必填布尔值；决定是否为每个匹配货物建立库存 |

`any` 表示货物至少拥有一个指定标签；`all` 表示货物包含全部指定标签，允许同时拥有其他标签。资源表加载时按 CargoGood 完整 ID 排序匹配，并把具体货物清单写入贸易点实例。以后重载数据不会替已有实例重新选货。

每条规则必须至少匹配一个 CargoGood，否则整轮数据加载失败。同一侧的规则不能重复匹配同一种货物；同一贸易点也不能同时出售和收购同一种货物。

## 无库存交易

当 `create_inventory` 为 `false` 时，该规则只包含通用字段：

- 出售不检查或扣减库存；
- 收购正常付款和结算，但不保存收到的货物；
- 不创建库存记录，不参与每日补货或消耗；
- 不能填写任何库存字段。

这用于只提供交易目录、不模拟本地仓储的贸易点。

## 出售库存

当销售规则的 `create_inventory` 为 `true` 时，必须增加：

| 字段 | 规则 |
| --- | --- |
| `initial_amount` | 每种匹配货物的新实例初始库存，`0..capacity_per_good`，单位 t |
| `capacity_per_good` | 每种匹配货物各自的库存上限，有限正数，单位 t |
| `daily_restock_per_good` | 每个贸易日为每种匹配货物补充的数量，可为 0，达到上限后停止 |

玩家购买会扣减对应出售库存。多种货物匹配同一规则时，每种货物都独立获得完整容量与补货量，不共享总容量。

## 收购库存

当收购规则的 `create_inventory` 为 `true` 时，必须增加：

| 字段 | 规则 |
| --- | --- |
| `initial_amount` | 每种匹配货物的新实例初始库存，`0..capacity_per_good`，单位 t |
| `capacity_per_good` | 每种匹配货物各自的库存上限，有限正数，单位 t |
| `daily_consumption_per_good` | 每个贸易日从每种匹配货物库存中消耗的数量，可为 0，最低降到 0 |
| `accept_when_full` | 满库存后是否继续付款收购 |

`accept_when_full: false` 时，收购量受剩余容量限制；`true` 时仍会完成结算，超过容量的部分视为当地即时消耗，库存保持上限。

## 实例与存档

贸易点首次建立运行时状态时，将资源表解析后的具体 CargoGood、规则 ID、库存开关和库存参数一起持久化。存档不保留 selector，也不因标签或资源表重载而改写既有实例。

开发阶段不读取旧生产线池、生产槽位或统一库存容量字段。旧经济状态版本会直接丢弃并按当前资源表重建。

实现依据：`trade/resource/ResourceTableDefinition.java`、`ResourceTagSelector.java`、`ResourceTables.java`、`TradePointResourceCatalog.java`。
