# 生产线池定义

## 路径与身份

`data/<namespace>/trade_points/production_line_pools/<resource|factory|market>/<分类>/<池名>.json`。

ID 从 production_line_pools 后取完整路径。分类可以嵌套；它只组织文件，不注册 CargoClass。例：`cargoverse:resource/general/default`。

同一完整池 ID 按数据包优先级整体覆盖，不拼接 lines。内部 lines[].id 在池内唯一，使用小写字母、数字、下划线、短横线、点；不同池可重名。

## 内置测试池

文件：`trade_points/production_line_pools/resource/general/default.json`。此示例引用的 CargoGood 和标签已在内置数据定义，不使用尚未定义的小麦 ID。

```json
{
  "schema_version": 1,
  "lines": [
    {
      "weight": 0,
      "id": "ore_natural",
      "display_name": "基础矿石采集线",
      "min_prosperity_level": 0,
      "tech_level": 0,
      "output": { "cargo_good": "cargoverse:raw_resource/ore", "amount": 12.0 },
      "inputs": []
    },
    {
      "weight": 0,
      "id": "wood_natural",
      "display_name": "基础木材采集线",
      "min_prosperity_level": 0,
      "tech_level": 0,
      "output": { "cargo_good": "cargoverse:raw_resource/wood", "amount": 6.0 },
      "inputs": []
    },
    {
      "weight": 1,
      "id": "agriculture_basic",
      "display_name": "基础农业生产线",
      "min_prosperity_level": 0,
      "tech_level": 1,
      "output": { "cargo_good": "cargoverse:agriculture/agriculture", "amount": 12.0 },
      "inputs": [
        { "consumption_rate": 0.5, "selector": { "match_mode": "any", "tags": ["fertilizer"], "min_tech_level": 0, "max_tech_level": 2 } },
        { "consumption_rate": 1.0, "selector": { "match_mode": "any", "tags": ["energy"], "min_tech_level": 0, "max_tech_level": 2 } }
      ]
    }
  ]
}
```

## 字段规则

| 字段 | 规则 |
| --- | --- |
| `schema_version` | 必填整数，当前只接受 `1` |
| `lines` | 必填数组，可为空；池内 ID 不可重复 |
| `weight` | 必填有限非负数，支持小数；`0` 保留定义但不参与随机抽取，不是自动兜底 |
| `display_name` | 必填非空字符串，直接显示；不支持多语言组件对象 |
| `min_prosperity_level` | 必填非负整数，调用方繁荣度必须大于或等于它 |
| `tech_level` | 必填非负整数，调用方科技等级必须大于或等于它；不自动改用输出 CargoGood 的科技等级 |
| `output.cargo_good` | 必填完整 CargoGood ID，必须在同轮货物数据中成功定义 |
| `output.amount` | 必填有限正数，一次生产的货物数量，单位 `t`；保留小数 |
| `inputs` | 必填数组；`[]` 表示无输入消耗，不等于禁用生产线 |
| `consumption_rate` | 每项输入必填有限非负数；`0` 不扣该项库存，仍要求 selector 可以解析出具体货物 |
| `selector.match_mode` | 可省略，默认 `all`；只接受 `all` 和 `any` |
| `selector.tags` | 字符串数组，可省略或 `[]`，表示不限制标签；去首尾空白、区分大小写、拒绝重复/空白标签 |
| `selector.min_tech_level` | 必填非负整数，包含下界 |
| `selector.max_tech_level` | 必填非负整数，包含上界，不能小于下界 |

加载上限：4096 个池、每池 1024 条生产线、每条 64 项输入。无效数值和数值溢出报错，不静默截断或修正。



## 选择器

- all 表示货物 tags 与 selector.tags 的集合完全相等，不是“包含所有要求标签”。
- any 表示至少有一个共同标签。
- selector.tags 为空表示不限制标签，两种模式都仍需通过科技等级上下界。
- 未知 CargoClass 的货物按 none 分类但保留完整 ID、标签和科技等级，可参与匹配。
- selector 无候选不会使整池定义失败，但该生产线当前不能绑定。
- weight=0 不参与随机抽取，不是自动兜底；贸易点 fixed 可以显式引用。
- 没有有效候选时结束当前抽取，不自动选权重为零的产线。

## 贸易点绑定与独立 draw 的区别

贸易点初始化使用稳定输入绑定：优先复用现有输入，否则按科技等级、基础价值、分类常规程度和完整 ID 顺序选择。输入／输出互斥，先整条验证再占槽，最终结果持久化，不在生产时重抽货物。

代码仍保留 ProductionLinePools.draw 这个独立接口；它按权重选线后为各输入随机挑选候选，只返回批次描述，不改库存。**不要把独立 draw 的随机输入行为写成贸易点的当前规则。**贸易点完整规则见[运行时](01_贸易点运行时与经济.md)。

## 批次数量

`每项输入消耗 = output.amount × consumption_rate`。

例如输出 12t、两项输入比例 0.5 与 1.0，则分别消耗 6t 和 12t。多个输入若绑定同一 CargoGood，消耗相加。inputs=[] 表示不消耗库存；consumption_rate=0 仍需有效绑定，但不扣该输入。

日结使用活跃度生产倍率，并按输入可用量与输出剩余容量同时限制产出／消耗。保留小数，不先扣料再丢弃溢出产物。

## 加载与边界

输出 cargo_good 必须是同轮有效定义，即使产线权重为零也必须校验。引用池的贸易点随同货物和池一起发布；删除被引用的货物或池需要同时修改关联定义。

内置农业自然示例池仍保留，但未引用的池不会自动为贸易点产货。工厂／市场的完整配方网络与数值平衡尚未完成。
