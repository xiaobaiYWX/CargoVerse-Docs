# 贸易点定义

本文记录当前可加载的贸易点定义格式、每个字段的校验规则、实际用途和生效时机。数据格式以 `TradePointDefinition` 和内置资源为准。

## 文件位置与定义 ID

```text
data/<namespace>/trade_points/
├─ trade_points_definitions/
│  ├─ resource/<分类>/<名称>.json
│  ├─ factory/<分类>/<名称>.json
│  └─ market/<分类>/<名称>.json
├─ production_line_pools/<resource|factory|market>/<分类>/<池名>.json
└─ trade_points_subfunctions/
   ├─ shop_definitions/<商店定义路径>.json
   └─ <后续功能定义目录>/<定义路径>.json
```

定义 ID 由 `trade_points/trade_points_definitions/` 后的相对路径生成。例如：

```text
data/cargoverse/trade_points/trade_points_definitions/resource/general/default.json
→ cargoverse:resource/general/default
```

路径至少包含“类型／分类／名称”三段。第一段只能是 `resource`、`factory` 或 `market`，后续分类允许继续嵌套，任一段都不能留空。类型目录目前只参与资源组织和 ID 校验，不会自动替代 `node_role` 或改变经济算法。

`production_line_pools` 是独立资源目录，不属于贸易点定义。旧的 `trade_points/type` 平铺目录不再加载。

所有贸易点额外功能定义都统一放在 `trade_points/trade_points_subfunctions/` 下，再由各功能自己的加载器剥离子目录并生成定义 ID。例如：

```text
data/cargoverse/trade_points/trade_points_subfunctions/shop_definitions/resource/general/default_shop.json
→ cargoverse:resource/general/default_shop
```

因此 `definition` 不包含 `shop_definitions/` 目录前缀。不同模块使用各自的定义注册表，同一个资源 ID 可以在不同功能定义目录中分别存在。

当前内置文件：`data/cargoverse/trade_points/trade_points_definitions/resource/general/default.json`。

## 顶层字段

| 字段 | 必填 | 格式与范围 | 当前作用 |
| --- | --- | --- | --- |
| `schema_version` | 是 | 整数，当前只能为 `1` | 定义格式版本；其他版本拒绝加载 |
| `display_name` | 是 | 非空字符串 | 贸易点信息柜、地图标记及其他展示使用的直接文本；会去除首尾空白，不接受翻译组件对象 |
| `node_role` | 是 | 非空字符串 | 保存贸易点的语义角色；当前没有运行时业务分支读取它，不会自动决定产线、库存或价格 |
| `ticks_per_day` | 是 | 整数 `1..2147483647` | 贸易日长度，用于日序号、日结、动态价格恢复、生产结算和倒计时；`24000` Tick 等于一个原版游戏日 |
| `tech_level` | 是 | 整数 `0..2147483647` | 首次创建实例时筛选生产线；贸易点等级必须不低于产线 `tech_level`。现有实例不会因修改此字段自动重抽产线 |
| `prosperity` | 是 | 对象 | 初始繁荣等级和逐级升级经验门槛 |
| `activity` | 是 | 对象 | 初始活跃度、有效交易价值换算、日结响应速度和生产倍率范围 |
| `pricing` | 是 | 对象 | 贸易点收购／出售的基础倍率，以及按具体 CargoGood 维护的动态价格参数 |
| `inventory_profile` | 是 | 对象 | 输入／输出可容纳的不同货物数量，以及每种货物的容量增长规则 |
| `production_pools` | 是 | 对象数组，可为空 | 首次创建贸易点实例时，按顺序固定选择或随机抽取生产线 |
| `modules` | 是 | 以模块 ID 为键的对象，可为空 | 为贸易点可选功能抽取并保存数据定义；是否实际生成对应终端不影响贸易点持有抽取结果 |

除 `pricing.dynamic_price` 中明确标注可省略的四个参数外，上表及下文列出的字段都必须出现。未知字段目前不会产生任何运行时效果，不应当作为扩展接口使用。

## `prosperity`：繁荣度

| 字段 | 格式与范围 | 当前作用 |
| --- | --- | --- |
| `initial_level` | 整数 `0..upgrade_experience.length` | 新贸易点实例的初始繁荣等级；同时参与初始产线门槛和初始库存容量计算 |
| `upgrade_experience` | 最多 100 个正整数，每项 `1..2147483647` | 数组索引表示当前等级，每项表示从该等级升到下一级需要的经验；数组长度就是最高繁荣等级 |

玩家向贸易点出售货物时，CargoGood 的繁荣经验按实际数量加入。经验达到当前等级门槛后逐级扣除门槛并升级；到达最高等级后剩余繁荣经验归零。

修改定义不会重置已有实例的等级与经验。后续升级使用当前已加载的门槛数组；修改初始等级只影响新实例。

## `activity`：活跃度与生产倍率

| 字段 | 格式与范围 | 当前作用 |
| --- | --- | --- |
| `initial_activity` | 有限数 `0..1` | 新实例的初始活跃度；只在首次创建时使用 |
| `expected_daily_trade_value` | 有限正数，最大 `1e15` | 达到目标活跃度所需的单日有效交易价值基准，不是点击次数或实际付款金额 |
| `max_daily_load` | 有限数 `0..1000` | 限制“当日有效交易价值 ÷ 目标值”的最大负载；小于 1 时会限制当日活跃度目标，大于等于 1 时活跃度目标仍最多为 1 |
| `input_trade_weight` | 有限数 `0..1000` | 玩家向贸易点出售／卸载货物时，对有效交易价值的方向权重 |
| `output_trade_weight` | 有限数 `0..1000` | 玩家从贸易点购买／装载货物时，对有效交易价值的方向权重 |
| `response_rate` | 有限数 `0..1` | 每个贸易日向本日目标活跃度靠拢的比例；`0` 表示不响应，`1` 表示当日直接达到目标 |
| `production_multiplier.min` | 有限数 `0..1000` | 活跃度为 0 时的每日生产倍率 |
| `production_multiplier.max` | 有限数 `min..1000` | 活跃度为 1 时的每日生产倍率，不能小于 `min` |

交易发生时只累计有效交易价值：

```text
有效交易价值 = 实际交易数量 × CargoGood.base_value × 对应方向权重
```

日结时：

```text
负载 = clamp(当日有效交易价值 ÷ expected_daily_trade_value, 0, max_daily_load)
目标活跃度 = clamp(负载, 0, 1)
新活跃度 = 旧活跃度 + response_rate × (目标活跃度 - 旧活跃度)
当日生产倍率 = min + 新活跃度 × (max - min)
```

跨越多个空白贸易日时，活跃度按 `(1 - response_rate)` 连续衰减，并用等比级数一次性汇总生产倍率，不逐日循环。

## `pricing`：收购、出售与动态价格

| 字段 | 必填 | 格式与默认值 | 当前作用 |
| --- | --- | --- | --- |
| `buy_price_multiplier` | 是 | 有限数 `0..1000` | 贸易点向玩家**收购**货物时的基础倍率，即玩家卸货所得价格 |
| `sell_price_multiplier` | 是 | 有限数 `0..1000` | 贸易点向玩家**出售**货物时的基础倍率，即玩家装货支付价格；普通物品商店也读取该基础倍率 |
| `dynamic_price.enabled` | 是 | 布尔值 | 是否启用按具体 CargoGood 维护的动态修正；关闭时动态因子固定为 1，但两个基础倍率仍生效 |
| `dynamic_price.min_modifier` | 否 | `0..1000`，默认 `0.7` | 动态修正下限 |
| `dynamic_price.max_modifier` | 否 | `min_modifier..1000`，默认 `1.3` | 动态修正上限 |
| `dynamic_price.trade_step` | 否 | `0..1000`，默认 `0.03` | 每笔已记录货物交易在下一次日结时施加的动态变化量；按交易笔数累计，不按本次货物数量累计 |
| `dynamic_price.daily_recovery_step` | 否 | `0..1000`，默认 `0.05` | 每个贸易日把动态修正向 `1.0` 拉回的绝对步长 |

当前价格方向如下：

```text
玩家装货价格倍率 = sell_price_multiplier × 对应货物的出售动态因子
玩家卸货价格倍率 = buy_price_multiplier × 对应货物的收购动态因子
```

玩家从贸易点购买货物，会使该货物的装货动态因子在日结时上升；玩家向贸易点出售货物，会使卸货动态因子在日结时下降。日结先向 `1.0` 恢复，再应用本日累计变化，最后限制在 `min_modifier..max_modifier`。跨越后续空白日时继续向 `1.0` 恢复。

## `inventory_profile`：库存槽与容量

`input_slots` 和 `output_slots` 都使用相同结构：

| 字段 | 格式与范围 | 当前作用 |
| --- | --- | --- |
| `slot_count` | 整数 `0..256` | 首次解析生产线时，该方向最多允许出现的不同 CargoGood ID 数量；不是物品栏格数，也不参与容量乘法 |
| `capacity_per_slot` | 有限数 `0..1e9` | 该方向中**每一种货物**在繁荣等级 0 时的容量，单位为 t |
| `capacity_growth_per_level` | 有限数 `0..1000` | 每升一级，相对基础容量增加的比例；`0.25` 表示每级增加基础容量的 25% |

每一种已解析货物的容量为：

```text
单种货物容量 = capacity_per_slot × (1 + 当前繁荣等级 × capacity_growth_per_level)
```

`input_slots` 限制生产线输入货物种类，输入库存接收玩家卸下的货物并供生产线消耗。`output_slots` 限制生产线产物种类，输出库存由生产产生并供玩家装载购买。具体货物 ID 来自首次解析并持久化的生产线布局，不直接写在贸易点定义中。

修改 `slot_count` 不会改变已有实例已经冻结的货物集合。修改容量和增长率会立即影响后续容量检查，但不会删除已经高于新上限的库存；超限货物只会暂停继续增加。

## `production_pools`：生产线引用

引用按数组顺序处理。每项必须包含 `pool` 和 `mode`，其余字段由模式决定。

### 固定引用

```json
{
  "pool": "cargoverse:resource/general/default",
  "mode": "fixed",
  "line_ids": ["ore_natural", "wood_natural"]
}
```

| 字段 | 规则与作用 |
| --- | --- |
| `pool` | 必填、带命名空间的生产线池 ID；池必须存在 |
| `mode` | 必须为 `fixed` |
| `line_ids` | 必填字符串数组；每项只能含小写字母、数字、下划线、点和连字符，在本引用内不能重复，且必须是该池内存在的生产线 ID |
| `draw_count` | 禁止出现 |

固定引用按 `line_ids` 顺序尝试产线。它可以选择 `weight=0` 的产线，但产线仍需满足初始繁荣等级、科技等级、输入输出互斥和槽位限制。

### 随机引用

```json
{
  "pool": "cargoverse:resource/general/default",
  "mode": "random",
  "draw_count": 3
}
```

| 字段 | 规则与作用 |
| --- | --- |
| `pool` | 必填、带命名空间的生产线池 ID；池必须存在 |
| `mode` | 必须为 `random` |
| `draw_count` | 必填整数 `0..1024`；表示最多尝试抽取多少条合格生产线 |
| `line_ids` | 禁止出现 |

随机引用只从 `weight>0` 的合格候选中按权重抽取。同一“完整池 ID＋内部产线 ID”不会在多个引用间重复入选。无法找到候选、槽位已满或候选不满足门槛时，实际选中数量可以少于 `draw_count`。

单个贸易点定义最多包含 256 个池引用；所有固定 `line_ids` 数量与随机 `draw_count` 之和不能超过 1024。引用池或固定生产线不存在时，整轮数据加载失败。

选中的产线布局在实例首次创建时持久化。数据包重载不会自动重抽，也不会因为修改 `production_pools`、`tech_level` 或 `slot_count` 改写已有实例。

## `modules`：贸易点功能定义

`modules` 是以模块 ID 为键的对象。每个模块声明解锁等级和一个带权定义池；贸易点注册时为每个模块抽取一个定义，并把结果保存在贸易点注册记录中。

```json
{
  "modules": {
    "item_shop": {
      "min_prosperity_level": 1,
      "definitions_pool": [
        { "weight": 3, "definition": "addon:shop/common" },
        { "weight": 1, "definition": "addon:shop/special" },
        { "weight": 0, "definition": "addon:shop/disabled" }
      ]
    }
  }
}
```

### 模块字段

| 字段 | 格式与范围 | 当前作用 |
| --- | --- | --- |
| `modules.<module_id>` | 模块 ID 只能含小写字母、数字、下划线、点和连字符；最多 64 个模块 | 标识终端功能。当前 `item_shop` 已完成消费链路；`cargo_manufacturing_platform` 已完成定义解析、引用校验、抽取和持久化，制造台消费者尚未实现 |
| `min_prosperity_level` | 整数 `0..最高繁荣等级` | 终端功能的解锁等级。等级不足时，终端保持锁定并提示所需等级 |
| `definitions_pool` | 1..256 个候选对象 | 注册时从其中抽取一个定义；至少有一个候选的权重必须大于 0 |
| `definitions_pool[].weight` | 整数 `0..1000000` | 加权抽取权重；`0` 表示保留候选但当前不会被抽中 |
| `definitions_pool[].definition` | 带命名空间的资源 ID，同一池内不能重复 | 被对应功能终端读取的数据定义 ID |

`item_shop` 必须引用存在的普通商店定义，`cargo_manufacturing_platform` 必须引用存在的[货柜制造台定义](06_货柜制造台定义.md)；任一引用缺失都会使整轮数据加载失败。其他尚未注册专用加载器的模块仍只执行通用抽取和持久化。

### 抽取与生命周期

- 抽取以“贸易点实例 UUID＋贸易点定义 ID＋模块 ID”为种子，同一个实例得到稳定结果；
- 结果在贸易点注册时写入 `cargoverse_trade_point_economy` 的注册记录，不依赖对应终端是否出现在结构中；
- 同定义重复注册时保留已有模块的已选定义、同步当前解锁等级、补抽新增模块并移除定义中已删除的模块；贸易点改绑另一份定义时重新建立模块选择；
- 数据包重载不会把已有模块重新随机，删除被选定义会使对应终端暂时不可用，恢复同 ID 定义后可继续使用；
- 旧存档没有模块字段时仍能加载，贸易点注册锚点再次注册时会补齐缺失模块。

当前 `item_shop` 与 `cargo_manufacturing_platform` 都已完成消费链路：物品售货机和货柜制造台只通过贸易点 UUID 读取注册记录中的模块选择，不接受终端级定义路径，也没有默认定义回退。功能终端是否真实存在不会反向改变贸易点模块选择，也不会让模块自动增加生产线或库存货物。

## 字段生效时机

| 生效时机 | 字段 |
| --- | --- |
| 新实例创建／注册时使用并冻结结果 | `tech_level`、`prosperity.initial_level`、`activity.initial_activity`、`inventory_profile.*.slot_count`、`production_pools`、`modules.*.definitions_pool` |
| 运行时持续读取当前定义 | `display_name`、`ticks_per_day`、`prosperity.upgrade_experience`、除 `initial_activity` 外的活跃度参数、全部价格参数、`capacity_per_slot`、`capacity_growth_per_level` |
| 注册时随抽取结果持久化，终端运行时读取 | `modules.*.min_prosperity_level`、已抽中的模块 `definition` |
| 当前仅保存定义元数据，不参与业务 | `node_role` |

结构生成通过 `trade_point_structure_bindings/<factory|market|resource>/...` 的严格加权候选池选择贸易点定义，并为世界中的贸易点创建独立实例 UUID。绑定目录类别必须与定义 ID 第一段一致，引用缺失或结构不完整会拒绝数据包重载。终端绑定的是实例 UUID，不是本页的定义 ID；同一实例的终端共享库存、繁荣度、活跃度和动态价格。

若运行时实例找不到已注册定义，解析器会使用安全回退定义维持读取：名称退回定义 ID、角色为 `resource_site`、贸易日为 24000 Tick、无生产池且输入／输出槽数为 0。正式结构绑定会校验定义存在，不应把回退行为当作正常配置方式。

## 已移除字段

下列旧字段会被明确拒绝，不能与当前格式混用：

- 顶层：`sales`、`acquisitions`、`initial_level`、`upgrade_experience`、`dynamic_economy`、`output_resources`、`consumed_resources`、`cargo_sale`、`shop_definitions`、`upgrade_list_count`；
- `activity` 内：`activity_window_days`、`expected_daily_trades`、`activity_step`、`restock_quantity_range`。

当前定义没有逐货物销售／收购清单、初始库存或内联货柜销售池。输入／输出货物由生产线布局派生，库存初始值为 0。普通商店定义位于 `trade_points/trade_points_subfunctions/shop_definitions`，货柜制造台定义位于 `trade_points/trade_points_subfunctions/cargo_manufacturing_platform_definitions`；两者分别通过对应的 `modules` 定义池绑定。

所有数值字段必须使用 JSON 数字，不能写成字符串，也不能是非有限值。定义加载与货物、容器、厂商和生产线池处于同一轮交叉校验；任何定义或引用错误都会阻止该轮新数据整体发布。

生产线解析和库存运行规则见[贸易点运行时与经济](01_贸易点运行时与经济.md)，池内字段见[生产线池定义](04_生产线池定义.md)，制造配方见[货柜制造台定义](06_货柜制造台定义.md)，结构绑定见[贸易点结构生成层与制作规范](02_贸易点结构生成层与制作规范.md)。
