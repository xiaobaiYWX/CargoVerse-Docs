## 基本信息

| 项目 | 当前内容 |
| --- | --- |
| 显示名称 | 云天农庄 |
| 预定定义 ID | `cargoverse:resource/agriculture/cloud_farm` |
| 预定数据路径 | `data/cargoverse/trade_points/trade_points_definitions/resource/agriculture/cloud_farm.json` |
| `node_role` | `resource_site` |
| 类型 | 资源点 |
| 定位 | 前期农业资源产地与基础补给点 |

云天农庄的目标是稳定输出农业货物，并接收维持农业生产的投入品。具体输入、输出和批次数量必须通过生产线池定义；贸易点定义本身不维护逐货物清单。

## 生产与库存方向

| 方向 | 内容定位 | 落地方式 |
| --- | --- | --- |
| 输出 | 农产品为主要产物，畜牧产品可作为后续独立产线 | 在生产线池中定义具体 CargoGood、产量、门槛和权重 |
| 输入 | 化工原料、能源或其他农业生产投入 | 由生产线输入选择器绑定具体 CargoGood；玩家卸货后进入 input 库存 |
| 自然生产 | 无输入的基础农业产线 | 使用空 `inputs` 的生产线 |
| 加工生产 | 消耗投入品的高价值农业产线 | 使用带输入选择器和 `consumption_rate` 的生产线 |

`inventory_profile.input_slots.slot_count` 与 `output_slots.slot_count` 只限制不同货物 ID 的数量；每种货物的容量由对应方向的 `capacity_per_slot` 和繁荣等级增长率计算。

## 当前格式边界

- 不配置逐货物初始库存；新实例库存从 0 开始。
- 不配置旧式 `sales`、`acquisitions`、`output_resources` 或 `consumed_resources`。
- 不在贸易点定义中配置货柜销售池；货柜购买属于独立设备销售流程。
- 不依赖升级时自动追加或重抽产线；当前产线布局在实例首次创建时冻结。
- 收购／出售基础倍率由 `pricing` 统一配置；当前没有逐货物静态价格倍率字段。
- 商店建筑是否生成仍由结构池决定；允许使用的商店定义通过 `modules.item_shop` 绑定，并在贸易点实例注册时抽取，见[随机功能定义](随机功能定义.md)。

在创建实际 JSON 前，需要先确定可用的具体 CargoGood、生产线池、输入／输出槽数、每种货物容量、活跃度目标和价格基础倍率。未确定的数值不在本页保留旧格式占位计划。
