# 新版商店定义结构

```
{
  "schema_version": 1,
  "display_name": "默认资源商店",

  "catalog": {
    "draw_count": 5,
    "allow_duplicates": false
  },

  "offers": [
    {
      "id": "cargo_docking_connector",
      "weight": 1,

      "unlock_prosperity_level": 0,

      "result": {
        "type": "item",
        "item": "cargoverse:cargo_docking_connector",
        "count": 1
      },

      "price": {
        "currency": "cargoverse:enderite",
        "amount": 32
      },

      "output_costs": [
        {
          "match_mode": "any",
          "tags": ["mechanical_part"],
          "amount": 1.0
        }
      ]
    },
    {
      "id": "iron_ingot_pack",
      "weight": 1,

      "unlock_prosperity_level": 0,

      "result": {
        "type": "item",
        "item": "minecraft:iron_ingot",
        "count": 3
      },

      "price": {
        "currency": "cargoverse:enderite",
        "amount": 64
      },

      "output_costs": [
        {
          "match_mode": "any",
          "tags": ["ore", "metal"],
          "amount": 1.0
        }
      ]
    }
  ]
}
```

---

# 字段说明

## 顶层字段

|字段|类型|作用|
|---|---|---|
|`schema_version`|整数|商店定义的数据结构版本。第一版固定为 `1`。|
|`display_name`|字符串 / Component|商店在 GUI 或调试信息中的显示名称。|
|`catalog`|对象|商品目录抽取规则。控制这个商店生成时抽取多少个商品。|
|`offers`|数组|商品候选池。贸易点生成时会从这里一次性抽取商品。|

---

## `catalog`

```
"catalog": {
  "draw_count": 5,
  "allow_duplicates": false
}
```

|字段|类型|作用|
|---|---|---|
|`draw_count`|整数|商店生成时从 `offers` 中抽取的商品数量。抽取后结果固定保存，不再随贸易点等级变化重新抽取。|
|`allow_duplicates`|布尔值|是否允许重复抽到同一个商品。第一版建议固定为 `false`。|

`catalog_size_by_level` 可以删除。
新的规则是：

```
商品目录大小 = catalog.draw_count
```

而不是：

```
商品目录大小 = catalog_size_by_level[贸易点等级]
```

---

# `offers[]`：商品候选项

```
{
  "id": "iron_ingot_pack",
  "weight": 1,
  "unlock_prosperity_level": 0,
  "result": {},
  "price": {},
  "output_costs": []
}
```

|字段|类型|作用|
|---|---|---|
|`id`|字符串|商品 ID。必须在当前商店定义内唯一。用于抽取结果保存、GUI 按钮、网络包和调试。|
|`weight`|整数 / 小数|抽取权重。数值越大，越容易被抽到。`weight <= 0` 默认不参与随机抽取。|
|`unlock_prosperity_level`|整数|商品显示/解锁所需贸易点繁荣等级。商品可以在生成时被提前抽中，但等级不足时先隐藏或置灰。|
|`result`|对象|玩家购买后获得的物品或结果。|
|`price`|对象|玩家购买该商品需要支付的货币。|
|`output_costs`|数组|商店出售该商品时，需要从贸易点 `output_stock` 中消耗的货物材料。使用 tag 模糊匹配。|

---

# `unlock_prosperity_level`

原来的：

```
"required_prosperity": 0.0
```

建议改成：

```
"unlock_prosperity_level": 0
```

原因：

1. 它表示的是贸易点等级，不是经验值；
2. 应该是整数，不需要小数；
3. `unlock` 比 `required` 更贴合“先抽中，等级到了再显示”的逻辑。

规则：

```
贸易点繁荣度 >= unlock_prosperity_level
→ 商品显示并可购买

贸易点繁荣度 < unlock_prosperity_level
→ 商品隐藏或置灰
```

建议 GUI 第一版直接隐藏，避免玩家看到太多暂时不能买的商品。

---

# `result`

```
"result": {
  "item": "minecraft:iron_ingot",
  "count": 3
}
```

| 字段      | 类型                   | 作用                      |
| ------- | -------------------- | ----------------------- |
| `item`  | ResourceLocation 字符串 | 玩家购买后获得的物品 ID。          |
| `count` | 整数                   | 玩家购买一次获得的物品数量。          |


---

# `price`

```
"price": {
  "currency": "cargoverse:enderite",
  "amount": 64
}
```

|字段|类型|作用|
|---|---|---|
|`currency`|ResourceLocation 字符串|购买该商品使用的货币 ID。|
|`amount`|整数 / 小数|购买一次需要支付的货币数量。|

这部分消耗的是玩家货币，不是贸易点库存。

---

# `output_costs`

```
"output_costs": [
  {
    "match_mode": "any",
    "tags": ["ore", "metal"],
    "amount": 1.0
  }
]
```

这是新版商店最关键的变化。

它替代旧字段：

```
"cargo_good": "cargoverse:raw_resource/ore",
"cargo_units": 1
```

新含义是：

> **购买该商品时，从当前贸易点已有的 `output_stock` 中，寻找符合 tag 条件的具体 CargoGood，并消耗指定数量。**

> [!WARNING]
注意，如果贸易点无符合的output则不会将该商品加入该贸易点的可出售商品池。

| 字段           | 类型    | 作用                                      |
| ------------ | ----- | --------------------------------------- |
| `match_mode` | 字符串   | 标签匹配方式。支持 `any` 和 `all`。                |
| `tags`       | 字符串数组 | 用于匹配贸易点 `output_stock` 中 CargoGood 的标签。 |
| `amount`     | 小数    | 需要消耗的货物数量，单位沿用 CargoGood 单位，当前一般为 `t`。  |

---

## `match_mode` 规则

```
any = CargoGood 只要拥有 tags 中任意一个标签即可匹配
all = CargoGood 必须同时拥有 tags 中全部标签才可匹配
```

例如：

```
{
  "match_mode": "any",
  "tags": ["stone", "ore"],
  "amount": 2.0
}
```

表示可以消耗任意石材类或矿石类 output 库存。

```
{
  "match_mode": "all",
  "tags": ["ore", "metal"],
  "amount": 1.0
}
```

表示必须消耗同时具有 `ore` 和 `metal` 标签的金属矿石类 output 库存。

# 商店购买流程

玩家点击购买商品时，建议流程固定为：

```
1. 检查当前贸易点是否绑定该商店定义。
2. 检查该 offer.id 是否在贸易点已抽取商品目录中。
3. 检查贸易点繁荣度是否 >= offer.unlock_prosperity_level。
4. 检查玩家货币是否满足 price。
5. 检查贸易点 output_stock 是否满足所有 output_costs。
6. 扣除玩家货币。
7. 从贸易点 output_stock 扣除匹配到的 CargoGood。
8. 给玩家 result.item。
```

重点是第 5 步：

```
只检查贸易点已有 output_stock。
不会从全局 CargoGood 表新增库存。
不会改变贸易点 output_goods。
不会改变贸易点 input_goods。
```

所以这不会破坏已经确定的贸易点经济结构。

# 多个 output 货物同时匹配时的消耗规则

如果贸易点 `output_stock` 里有多个货物都符合条件，例如：

```
cargoverse:raw_resource/iron_ore      20t
cargoverse:raw_resource/copper_ore    12t
cargoverse:raw_resource/tin_ore       8t
```

商品成本为：

```
{
  "match_mode": "any",
  "tags": ["ore"],
  "amount": 10.0
}
```

建议默认消耗顺序为：

```
1. 优先消耗 tech_level 较低的货物；
2. tech_level 相同，优先消耗 base_value 较低的货物；
3. base_value 相同，优先消耗库存数量较多的货物；
4. 仍然相同，用 CargoGood ID 字典序兜底。
```

这样可以避免商店优先吃掉高等级、高价值或特殊产出。

# 抽取与保存规则

商店定义中的 `offers` 是候选池。
贸易点生成时，模块解析结果应该保存已抽取的商品 ID。

例如运行时保存：

```
"resolved_modules": {
  "item_shop": {
    "definition": "cargoverse:shop_definitions/resource/general/default_shop",
    "selected_offers": [
      "cargo_docking_connector",
      "iron_ingot_pack",
      "stone_brick_pack",
      "basic_tool_pack",
      "coal_pack"
    ]
  }
}
```

之后：

```
贸易点升级不会重新抽商品。
贸易点重新加载不会重新抽商品。
玩家打开 GUI 不会重新抽商品。
数据包重载后，按 selected_offers 的 ID 重新解析。
```

如果某个已保存的 `offer.id` 在新数据包中不存在，建议：

```
跳过该商品；
不自动重新抽取
```
