# 10 世界表面 UI 系统

> 已实现：独立底层框架、可复用封装仪表、组件化实体交互控件，以及生产线终端、贸易点信息柜、仓库信息柜、货柜装载机、货物卸载机、货柜制造台和物品售货机。按钮／滑轨的模型姿态、命中面和细高亮边框由同一组件放置数据推导；显示装饰、按钮声与拖动会话由框架统一提供。预留：其余普通 GUI 的逐项迁移与禁用态。待验收：世界内交互、多人同步与运动结构兼容。

世界表面 UI（World Surface UI）用于把信息面板、状态指示和交互区域直接绘制到世界中的方块表面。玩家瞄准面板上的指定区域并在世界中操作，不需要先右键方块打开传统 GUI。

本章描述的是一套新的 UI 运行框架，不是把现有 `Screen` 缩放后贴到模型上。

## 系统目标

- 支持单方块表面以及横向、纵向多方块显示墙；
- 支持上、下、南、北、东、西六个方向；
- 允许一个终端拥有多个显示面和独立按钮面；
- 客户端直接在世界中绘制信息，并提供准星悬停反馈；
- 玩家通过瞄准世界中的区域进行交互，不打开 `Screen`；
- 服务端重新计算命中位置，不信任客户端提交的按钮或画布坐标；
- 传统 GUI 可以继续存在，两套系统共享业务服务而不是共享 UI 类。

## 与传统 GUI 的关系

```text
业务服务／展示快照／格式化工具／贴图
                 │
        ┌────────┴────────┐
        │                 │
传统 Screen／Menu      World Surface UI
        │                 │
屏幕鼠标交互           世界射线交互
```

World Surface UI 不继承或持有以下类型：

- `AbstractContainerScreen`；
- `AbstractWidget`；
- `AbstractContainerMenu`；
- 任何现有终端 Screen 实例。

一个功能可以同时提供世界面板和传统 GUI，但两者必须分别调用同一业务服务。世界面板不能模拟点击旧 Screen 的按钮。

## 第一版已经具备的能力

| 模块 | 当前能力 |
| --- | --- |
| 画布定义 | 固定逻辑尺寸、多个表面、`DISPLAY`／`CONTROL` 表面职责、代码注册 |
| 交互区域 | 元素 ID、矩形范围、服务端动作 ID；拒绝重复、越界和重叠 |
| 世界锚点 | 绝对世界原点、右／下／法线轴、实际尺寸与逻辑尺寸 |
| 坐标变换 | 世界命中转画布坐标、画布坐标转世界位置 |
| 客户端渲染 | 世界贴图、ARGB 着色、Minecraft 字体和局部渲染坐标转换 |
| 默认显示样式 | 所有 `DISPLAY` 表面先由程序填充纯色 `#333333` 背景；省略颜色的文字使用 `#EBD8B5` |
| 默认显示装饰 | 所有 `DISPLAY` 表面自动在画布边界内侧拼接公共角块，并在每条边拉伸一张边段；`CONTROL` 按钮面不绘制屏幕框 |
| 悬停预测 | 客户端使用公共命中算法解析当前区域 |
| 默认交互反馈 | 任意命中区域自动描边；正确按到按钮统一播放点击声，不发送操作栏文字 |
| 封装交互控件 | 按钮、开关与滑轨分别封装模型、动画、服务端绑定和 `ModelFrame`；同一 `place(...)` 结果同时驱动渲染姿态、命中面和细高亮边框 |
| 服务端分发 | 检查距离、区块、结构、控制器、表面和区域后调用动作 handler |
| 状态版本 | 目标与展示状态 revision 不一致时不绘制过期内容 |
| 封装仪表 | 翻转字符牌、百分比值、增减指示器、紧凑型进度条、图标监视器、状态灯、缩微胶卷阅读机和全息投影；每个实例持有自己的用途信息，命中时由封装层沿实际绘制范围高亮，并在准星旁显示用途；阅读机统一投影滤镜与滑页，全息投影以实体底座为基点在世界中绘制可调缩放和高度的完整货柜微缩模型；普通平面仪表支持 GUI 与世界表面，全息投影是世界空间三维组件 |
| 批量接入边界 | 公共定义由 `WorldUiBootstrap` 集中注册；客户端内容 renderer 由 `WorldUiClientBootstrap` 集中注册；终端组合仪表并提交内容，不重复实现公共装饰 |

七个正式终端已经接入。仓库信息柜以贸易点输入／输出库存快照为数据源；货柜装载机和货物卸载机通过实体箭头、大按钮和滑轨调用服务端装卸服务；货柜制造台显示容器定义、CargoClass 兼容图标、材料与费用；物品售货机显示商品、可购买余量、数量和费用，并把购买结果暂存在公共出货区。大型终端的管理员传统 GUI 只承担 UUID、扫描范围等复杂配置。`InstrumentTestBlock` 仅是开发期预览媒介，不属于正式玩法终端。

## 分辨率结论与测试媒介

早期五档分辨率测试方块已完成选型任务并从当前实现中移除。当前只保留一个仪表测试方块，用于独立观察封装仪表的比例、动画、频闪和双渲染目标行为；它可以把显示面扩展到方块边界之外，不应被当作正式模型布局模板。

仪表或正式终端实机检查时，至少在 1、2、4、8 格距离观察：

- 文字是否可辨认；
- 图标边缘是否稳定；
- 移动视角时是否闪烁；
- 白天、夜晚和不同 FOV 下的结果；
- 普通结构件是否正确受环境光影响；
- 只有辉光数字、图标监视器内容和点亮的状态灯保持自发光。

## 正式分辨率规范

实机对比后，正式终端不再把逻辑分辨率理解为固定的正方形画布，而是使用“每个 MCpx 对应多少逻辑像素”的密度比例。一个方块宽度为 `16 MCpx`，因此单方块正面在不同档位下恰好对应 16、64、128 或 256 逻辑像素。

| 规格 | 逻辑密度 | 单方块正面 | 推荐用途 |
| --- | ---: | ---: | --- |
| 大屏信息档 | 1 px／MCpx | 16×16 | 多方块大型信息屏、远距离阅读、极大图标和数字 |
| 大字体档 | 4 px／MCpx | 64×64 | 状态牌、告警、倒计时及需要明显字号的界面 |
| 普通终端档 | 8 px／MCpx | 128×128 | 常用终端的默认密度，兼顾信息量与可读性 |
| 精细屏幕档 | 16 px／MCpx | 256×256 | 近距离操作、局部细节、精细图表和高密度信息 |

`32×32` 测试档对应 2 px／MCpx，保留作调试和过渡对比，不作为正式默认规格。

任意显示区域的画布尺寸按下式计算：

```text
逻辑画布宽度 = 显示区域宽度（MCpx）× 逻辑密度
逻辑画布高度 = 显示区域高度（MCpx）× 逻辑密度
```

例如 `40×19 MCpx` 的显示区域：

| 用途 | 推荐画布 |
| --- | ---: |
| 大屏信息展示 | 40×19 |
| 大字体显示 | 160×76 |
| 普通终端 | 320×152 |
| 近距离精细屏幕 | 640×304 |

选择规格时先确定玩家的预期观察距离与内容用途，再计算整个显示区域的画布，不能把每块方块单独建立成互不相干的画布。

## 运行过程

### 世界绘制

```text
控制器提供几何快照
        ↓
校验定义 ID、表面 ID、画布尺寸和 revision
        ↓
WorldUiWorldRenderer 为每个表面建立绘制上下文
        ↓
统一装饰管线只为 DISPLAY 表面填充 `#333333` 背景；OVERLAY／CONTROL 保持透明
        ↓
终端 renderer 以逻辑画布坐标绘制贴图和文字
        ↓
统一装饰管线为 DISPLAY 表面向内拼接公共内框，并追加当前交互区描边
        ↓
框架转换到方块实体 renderer 的局部世界坐标
```

框架不会每帧扫描世界寻找终端。具体控制器的方块实体 renderer 负责调用公共绘制入口。

### 世界交互

```text
玩家瞄准并操作结构成员
        ↓
成员解析到控制器
        ↓
服务端检查距离、区块和结构有效性
        ↓
服务端用实际世界命中重新计算画布坐标
        ↓
命中 WorldUiRegion
        ↓
调用该按钮明确绑定的服务端 handler
        ↓
业务服务再次检查权限、库存、冷却和交易条件
```

客户端悬停结果只用于显示高亮，不能直接改变终端状态。

触摸区域的描边按 `WorldUiRegion.bounds` 绘制。实体按钮和滑块的动态描边则来自组件 `place(...)` 产生的当前 `SurfaceAnchor`：组件自带的 `ModelFrame` 定义模型参考点、局部轴、交互面高度和高亮间隙，客户端 renderer 从同一锚点反推模型姿态。业务终端不保存悬停状态，也不得为物理控件另写高亮坐标。服务端重新命中区域后，无论 handler 最终是否改变业务数据，都播放统一按钮声和短按压反馈；未命中时不播放。

## 表面设计原则

一个终端可以将功能拆分为不同物理区域：

- 主显示面：状态、列表、模型或图表；
- 次显示面：详情或告警；
- 按钮面：确认、翻页、优先级调整；
- 状态灯：只显示，不接受交互。

屏幕、状态牌等定义为 `DISPLAY`，会自动获得 `#333333` 纯色背景与公共内框；模型上的实体按钮面定义为 `CONTROL`，不填充显示背景，只保留命中描边和按钮声。一个带触摸区域的屏幕仍属于 `DISPLAY`，是否拥有交互区域与是否绘制默认样式互不冲突。普通正文应调用不带颜色参数的 `drawText`；标题、警告、禁用和成功状态才显式传入语义色。

普通面板、仪表外壳与翻转牌默认使用环境光。只有具备明确发光语义的内容可调用 emissive 绘制入口，目前包括图标监视器中的图标、紧凑型进度条辉光数字以及点亮的状态灯。

布局应按玩家在世界中的观察距离重新设计。传统 413×233 GUI 中的信息不应原样塞入一块方块表面；高频信息使用大字号和图标，复杂配置仍可保留传统 GUI。

## 后续阶段

下一阶段按终端逐个决定：

1. 多方块尺寸和每块方块承担的表面职责；
2. 哪些信息始终显示，哪些信息只在瞄准时显示；
3. 哪些动作适合世界按钮，哪些复杂设置保留传统 GUI；
4. 状态同步频率、revision 和失败反馈；
5. 结构旋转、拆除、卸载及多人同时操作规则。
