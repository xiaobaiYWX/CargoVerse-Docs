# 一、最终核心规则

> 历史设计依据（2026-08-28 整编标记）：原文保留，不作为全部已实现的承诺。当前实现已整理至[贸易点系统](02贸易点系统/README.md)，其与原方案的差异、预留功能和待验收问题见[状态清单](00_重构状态与验收清单.md)。

运行时解析结果应该满足这几个不变量：

```
input_goods ∩ output_goods = ∅

产线 input 只能绑定 input_goods
产线 output 只能写入 output_goods

任何 CargoGood 不能同时作为同一个贸易点的 input 和 output
```

所以之前说的：

```
后抽取产线优先检索 output_goods
```

应该废弃。

正确规则是：

```
后抽取产线只检索 input_goods。
如果 input_goods 中有满足 selector 的 CargoGood，则复用。
如果没有，则尝试新增 input_good。
如果 input 槽位已满，则这条产线不可加入。
```

---

# 二、产线解析顺序

对于一条候选产线，解析顺序建议固定为：

```
1. 检查产线是否重复
2. 检查繁荣度 / tech_level
3. 解析 input
4. 解析 output
5. 判断是否超过槽位上限
6. 加入 selected_lines
```

重点是：

> **先解析 input，再解析 output。**

因为你说得对，通常情况下：

```
input 种类 > output 种类
```

输入端更容易爆槽，所以应该优先判断 input 能不能被接受。

---

# 三、input 解析规则

对于候选产线的每一个 input selector：

```
{
  "consumption_rate": 0.5,
  "selector": {
    "match_mode": "all",
    "tags": ["fertilizer"],
    "min_tech_level": 0,
    "max_tech_level": 2
  }
}
```

解析规则：

```
1. 先在当前 input_goods 中查找可匹配的 CargoGood。
2. 如果找到，则绑定到已有 input_good。
3. 如果没找到，则从全局 CargoGood 表中选择一个可匹配的新 CargoGood。
4. 新 CargoGood 不能已经存在于 output_goods。
5. 新 CargoGood 不能等于当前候选产线的 output.cargo_good。
6. 如果 input 槽位还有空位，则新增到 input_goods。
7. 如果 input 槽位已满，则候选产线丢弃。
```

第 5 条很重要。

例如一条奇怪产线：

```
input selector 可以匹配 wheat
output 也是 wheat
```

这种必须禁止，否则会变成自循环。

---

# 四、output 解析规则

产线 output 是确定的：

```
"output": {
  "cargo_good": "cargoverse:agriculture/wheat",
  "amount": 12.0
}
```

解析规则：

```
1. 如果 output.cargo_good 已经存在于 input_goods，则候选产线丢弃。
2. 如果 output.cargo_good 已经存在于 output_goods，则复用已有 output 槽。
3. 如果 output.cargo_good 不在 output_goods：
   - output 槽位未满 → 新增 output_good
   - output 槽位已满 → 候选产线丢弃
```

这保证：

```
一个贸易点不会同时收购和出售同一种 CargoGood。
```

---

# 五、抽取优先级：先填 output，再补 input

你这里的判断也对：

> **output 应该尽可能占满所有槽位。**

所以随机抽取时不要完全随机接受产线，而应该分阶段。

---

## 阶段 A：优先扩展 output

当 output 槽位还没满时：

```
优先选择能够新增 output_good 的产线。
```

也就是：

```
output.cargo_good 不在 output_goods
并且不会导致 input 超槽
并且不会违反 input/output 互斥
```

这一阶段的目标是：

```
尽可能把 output_goods 填满。
```

如果某条产线的 input 需要新增货物，但 input 已满，就丢弃它。
但如果它的 input 都能复用已有 input_goods，就仍然可以加入。

---

## 阶段 B：output 已满后，才尝试复用 output

只有当：

```
output_goods 已满
并且
input_goods 还有空位
```

才进入第二阶段。

这时允许选择：

```
output.cargo_good 已经存在于 output_goods 的产线
```

目的不是扩展 output，而是：

```
在不增加 output 槽位的情况下，继续补充 input 结构和产线多样性。
```

例如：

```
output 已有 wheat
新产线也生产 wheat
但需要新的 input：water_supply
input 还有空位
→ 可以加入
```

---

## 阶段 C：两侧都满则停止

当：

```
input_goods 已满
output_goods 已满
```

第一版建议直接停止抽取。

即使存在完全复用 input/output 的产线，也不建议继续加。
否则贸易点可能抽到过多同质产线，导致产量难以控制。

---

# 六、最终抽取状态机

可以整理成这样：

```
while 可以继续抽取:

  如果 output 未满:
      从候选线中寻找“能新增 output 且不会超 input”的产线
      如果存在，按 weight 抽取并加入
      如果不存在：
          如果 input 未满:
              进入 output 复用阶段
          否则停止

  如果 output 已满 且 input 未满:
      从候选线中寻找“复用已有 output 且可以新增或复用 input”的产线
      如果存在，按 weight 抽取并加入
      如果不存在，停止

  如果 output 已满 且 input 已满:
      停止
```

更简化地说：

```
output 未满：只优先接收新 output 产线。
output 已满、input 未满：才接收复用 output 的产线。
任意候选线如果 input 无法解析，则丢弃。
```

# 七、候选产线是否可加入

可以把一条候选产线解析成：

```
new_inputs
new_output
reuse_inputs
reuse_output
```

判断条件：

```
1. 产线不能重复。
2. output.cargo_good 不能存在于 input_goods。
3. input 解析出的任何 CargoGood 不能存在于 output_goods。
4. input 解析出的任何 CargoGood 不能等于 output.cargo_good。
5. input 数量不能超过 input_slot_count。
6. output 数量不能超过 output_slot_count。
```

伪代码：

```
boolean canAcceptLine(Economy e, ProductionLine line) {
    if (e.selectedLines.contains(line.fullId())) return false;

    CargoGoodId output = line.output().cargoGood();

    // 输出不能已经是输入
    if (e.inputGoods.contains(output)) return false;

    ResolveResult inputs = resolveInputsOnlyFromInputSide(e, line);

    if (!inputs.success()) return false;

    // 输入不能吃 output
    if (inputs.allGoods().contains(output)) return false;

    for (CargoGoodId input : inputs.allGoods()) {
        if (e.outputGoods.contains(input)) return false;
    }

    int nextInputCount = e.inputGoods.size() + inputs.newGoods().size();

    int nextOutputCount = e.outputGoods.contains(output)
        ? e.outputGoods.size()
        : e.outputGoods.size() + 1;

    return nextInputCount <= e.inputSlotCount
        && nextOutputCount <= e.outputSlotCount;
}
```

# 八、input 匹配时的候选选择

当某个 input selector 需要新增具体 CargoGood 时，建议选择规则固定，避免随机结果太乱。

推荐优先级：

```
1. cargo_good.tech_level 越低越优先
2. base_value 越低越优先
3. cargo_class 越常规越优先
4. id 字典序兜底
```

例如 selector 需要 `energy`：

```
coal_fuel
biofuel
power_cell
unstable_relic_core
```

优先选：

```
coal_fuel
```

而不是直接选到高级电池或异常核心。

如果你希望贸易点更有随机性，可以在前几个候选中按权重随机，但第一版建议稳定优先。

# 九、解析结果示例

假设贸易点：

```
input_slot_count = 3
output_slot_count = 2
```

抽线过程：

## 第 1 条：小麦基础产线

```
output = wheat
input = fertilizer + energy
```

当前为空。

解析后：

```
{
  "input_goods": [
    "cargoverse:chemical_material/basic_fertilizer",
    "cargoverse:energy_fuel/coal_fuel"
  ],
  "output_goods": [
    "cargoverse:agriculture/wheat"
  ]
}
```

---

## 第 2 条：蔬菜基础产线

```
output = vegetable
input = fertilizer + energy
```

先检索 input：

```
fertilizer → 复用 basic_fertilizer
energy → 复用 coal_fuel
```

output 新增：

```
vegetable
```

解析后：

```
{
  "input_goods": [
    "cargoverse:chemical_material/basic_fertilizer",
    "cargoverse:energy_fuel/coal_fuel"
  ],
  "output_goods": [
    "cargoverse:agriculture/wheat",
    "cargoverse:agriculture/vegetable"
  ]
}
```

此时 output 已满。

---

## 第 3 条：高级小麦产线

```
output = wheat
input = fertilizer + energy + water_supply
```

output 已满，但这条产线 output 是已有的 `wheat`，所以允许进入第二阶段。

input：

```
fertilizer → 复用 basic_fertilizer
energy → 复用 coal_fuel
water_supply → 新增 purified_water
```

input 还有空位，所以加入。

最终：

```
{
  "input_goods": [
    "cargoverse:chemical_material/basic_fertilizer",
    "cargoverse:energy_fuel/coal_fuel",
    "cargoverse:general_supplies/purified_water"
  ],
  "output_goods": [
    "cargoverse:agriculture/wheat",
    "cargoverse:agriculture/vegetable"
  ]
}
```

此时 input 和 output 都满，停止抽取。

# 十、运行时生产绑定

解析完成后，产线运行时不再查 selector。

需要保存：

```
{
  "selected_lines": [
    "cargoverse:agriculture/basic#wheat_basic",
    "cargoverse:agriculture/basic#vegetable_basic",
    "cargoverse:agriculture/basic#wheat_advanced"
  ],

  "input_goods": [
    "cargoverse:chemical_material/basic_fertilizer",
    "cargoverse:energy_fuel/coal_fuel",
    "cargoverse:general_supplies/purified_water"
  ],

  "output_goods": [
    "cargoverse:agriculture/wheat",
    "cargoverse:agriculture/vegetable"
  ],

  "line_input_bindings": {
    "cargoverse:agriculture/basic#wheat_basic": [
      "cargoverse:chemical_material/basic_fertilizer",
      "cargoverse:energy_fuel/coal_fuel"
    ],

    "cargoverse:agriculture/basic#vegetable_basic": [
      "cargoverse:chemical_material/basic_fertilizer",
      "cargoverse:energy_fuel/coal_fuel"
    ],

    "cargoverse:agriculture/basic#wheat_advanced": [
      "cargoverse:chemical_material/basic_fertilizer",
      "cargoverse:energy_fuel/coal_fuel",
      "cargoverse:general_supplies/purified_water"
    ]
  }
}
```

生产时：

```
从 input_stock 扣除 line_input_bindings 中的货物
向 output_stock 增加 line.output.cargo_good
```

没有任何 tag 库存，也没有 output 回流 input。

# 十一、最终定稿规则

可以把规则写成这几条：

```
1. 贸易点通过产线池抽取产线。
2. 产线不得重复。
3. 贸易点最终库存只保存具体 CargoGood，不保存 tag 库存。
4. input_goods 和 output_goods 永远互斥。
5. 产线 input 只允许绑定 input_goods，不允许绑定 output_goods。
6. 产线 output 只允许写入 output_goods，不允许同时成为 input_good。
7. 抽取时先解析 input：能复用 input 则复用，不能复用则尝试新增 input。
8. input 槽位不足时，候选产线丢弃。
9. output 未满时，优先抽取能新增 output 的产线。
10. output 已满但 input 未满时，才允许抽取复用已有 output 的产线。
11. input 和 output 都满后停止抽取。
12. selector 只在初始化解析阶段使用，运行时生产不再查 selector。
```
