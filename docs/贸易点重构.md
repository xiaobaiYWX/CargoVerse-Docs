# 段分区说明

## 1. 基础身份字段

```
{
  "schema_version": 1,
  "display_name": "Default Trade Point",
  "node_role": "resource_site",
  "ticks_per_day": 24000,
  "tech_level": 2
}
```


---

## 2. 繁荣度配置

```
"prosperity": {
  "initial_level": 0,
  "upgrade_experience": [30, 80, 180, 400, 800]
}
```

含义：

```
initial_level = 贸易点初始繁荣等级
upgrade_experience[0] = 0 → 1 需要的经验
upgrade_experience[1] = 1 → 2 需要的经验
...
```

如果后面有些贸易点天生高级，可以这样：

```
"prosperity": {
  "initial_level": 2,
  "upgrade_experience": [30, 80, 180, 400, 800]
}
```

## 5. 定价配置

```
"pricing": {
  "buy_price_multiplier": 1.0,
  "sell_price_multiplier": 1.0,

  "dynamic_price": {
    "enabled": false,
    "min_modifier": 0.7,
    "max_modifier": 1.3,
    "trade_step": 0.03,
    "daily_recovery_step": 0.05
  }
}
```

这样更安全。

含义：

```
buy_price_multiplier = 贸易点从玩家手里收购货物的价格倍率
sell_price_multiplier = 贸易点卖给玩家货物的价格倍率
dynamic_price.enabled = 是否启用动态价格
```

第一版可以让大多数贸易点：

```
"dynamic_price": {
  "enabled": false
}
```

等后面经济稳定后再打开。

# 四、库存配置：最关键部分

```
"inventory_profile": {
  "input_slots": {
    "slot_count": 4,
    "capacity_per_slot": 120.0,
    "capacity_growth_per_level": 0.25
  },

  "output_slots": {
    "slot_count": 3,
    "capacity_per_slot": 160.0,
    "capacity_growth_per_level": 0.25
  }
}
```

这里的重点是：

> **贸易点只定义 input/output 各有多少个具体 CargoGood 槽位，以及每个槽位容量。**

不定义：

```
"fertilizer": {}
"energy": {}
"wheat": {}
```

最终运行时解析后才会得到：

```
{
  "input_goods": [
    "cargoverse:chemical_material/basic_fertilizer",
    "cargoverse:energy_fuel/coal_fuel"
  ],

  "output_goods": [
    "cargoverse:agriculture/wheat",
    "cargoverse:agriculture/vegetable"
  ]
}
```

容量计算建议：

```
actualCapacity = capacity_per_slot × (1 + prosperityLevel × capacity_growth_per_level)
```

例如：

```
capacity_per_slot = 120
capacity_growth_per_level = 0.25
prosperityLevel = 2

actualCapacity = 120 × (1 + 2 × 0.25) = 180
```

# 五、产线池引用

```
"production_pools": [
  {
    "pool": "cargoverse:agriculture/basic_field",
    "mode": "fixed",
    "line_ids": [
      "wheat_natural"
    ]
  },
  {
    "pool": "cargoverse:agriculture/basic_field",
    "mode": "random",
    "draw_count": 3
  }
]
```

建议规则：

```
production_pools 按数组顺序解析。
fixed 先尝试加入指定产线。
random 再按权重抽取指定数量。
产线不得重复。
```

`mode = fixed`：

```
{
  "pool": "cargoverse:agriculture/basic_field",
  "mode": "fixed",
  "line_ids": ["wheat_natural"]
}
```

用于固定基础产线。

`mode = random`：

```
{
  "pool": "cargoverse:agriculture/basic_field",
  "mode": "random",
  "draw_count": 3
}
```

用于按权重抽取随机产线。

# 六、功能模块

```json
"modules": {
  "item_shop": {
    "min_prosperity_level": 1,
    "definitions_pool": [
      { "weight": 1, "definition": "cargoverse:resource/general/default_shop" }
    ]
  }
}
```

模块是低一层的功能，不参与生成贸易点经济结构。当前已实现按贸易点实例注册时抽取并持久化功能定义；`item_shop` 和 `cargo_manufacturing_platform` 分别由物品售货机与货柜制造台读取，后续功能继续在 `trade_points/trade_points_subfunctions/` 下建立各自定义目录。

也就是说：

```
生产线决定贸易点的 input_goods / output_goods。
模块只能读取和消耗已经解析出的具体库存。
```

例如维修台需要机械零件，但该贸易点解析后没有任何机械零件库存，那么维修台就可以：

```
显示“缺少本地材料供应”
或者功能不可用
```

但维修台不能反过来让贸易点新增机械零件收购项。

现行模块统一使用解锁等级与定义池，不再接收下列旧式任意参数对象。以下内容仅作为历史构想：

```
{
  "id": "cargoverse:cargo_box_shop",
  "max_offer_count": 3,
  "refresh_days": 1
}
```

或者：

```
{
  "id": "cargoverse:vehicle_blueprint_shop",
  "min_prosperity_level": 2,
  "offer_count": 2
}
```
