# 实体货币与多面额结算

CargoVerse 不维护虚拟账户。玩家持有、支付、获得和找零的货币均为真实物品。

价格统一使用货币组的基础单位表示。高面额物品只压缩携带体积，不改变货柜、商品或动态经济的价格计算方式。

## 1. 文件位置

```text
data/<namespace>/currency_groups/<path>.json
```

文件路径决定货币组 ID。例如：

```text
data/cargoverse/currency_groups/enderite.json
```

对应：

```text
cargoverse:enderite
```

货币组 ID 可以和基础物品 ID 相同。解析 `currency_id` 时优先查找货币组；不存在货币组时按普通物品货币处理。

## 2. 定义格式

```json
{
  "display_name": "终末货币",
  "base_item": "cargoverse:enderite_slices",
  "denominations": [
    {
      "item": "cargoverse:enderite_slices",
      "value": 1
    },
    {
      "item": "cargoverse:enderite_block",
      "value": 8
    },
    {
      "item": "cargoverse:enderite_core",
      "value": 64
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `display_name` | 货币组显示名称。 |
| `base_item` | 值为 `1` 的基础货币物品。 |
| `denominations` | 货币组包含的实体面额。 |
| `denominations[].item` | 面额物品 ID。 |
| `denominations[].value` | 该物品对应的基础单位价值。 |

当前内置 `cargoverse:enderite` 货币组包含三种面额：终末晶片（1）、终末晶块（8）和终末晶核（64）。终末晶块可在同一格叠放 8 个，终末晶核可在同一格叠放 4 个；破坏后都会按方块状态记录的数量完整返还。

## 3. 校验规则

- 一个货币组必须包含 `1~16` 种面额。
- `base_item` 必须出现在 `denominations` 中且价值为 `1`。
- 面额价值必须为正整数，最大为 `1,000,000,000,000`。
- 同一货币组中物品 ID 和面额价值都不能重复。
- 面额按升序必须形成整数倍关系，例如 `1、10、100、1000`。
- 非法货币组不会加载，服务器日志会记录对应定义 ID 和原因。

整数倍面额链保证高面额优先算法可以稳定支付和找零，不需要维护任意面额组合的高成本搜索。

## 4. currency_id

货柜定义与商店定义继续使用原字段：

```json
"currency_id": "cargoverse:enderite"
```

解析顺序：

1. 查找同 ID 的货币组；
2. 若不存在，查找同 ID 的普通物品；
3. 两者均不存在则拒绝交易。

价格始终表示基础货币单位。例如价格 `1387` 表示 1387 个终末晶片单位，而不是必须提交 1387 个基础物品。

## 5. 支付与找零

服务端先统计玩家主物品栏和副手内所有面额的总价值，然后制定扣款组合。

处理顺序：

1. 优先使用不超过剩余价格的高面额物品；
2. 无法精确支付时，选择可以覆盖差额的最小面额物品；
3. 如果单个更高面额产生的找零更少，则直接使用该面额；
4. 暂扣选中的实体物品；
5. 交易成功后，把差额按高面额优先拆分为实体找零；
6. 交易失败时，退还全部暂扣物品，不发放找零。

找零只有两种去向：

- 玩家物品栏可以容纳时放入物品栏；
- 不能容纳的剩余物品直接掉落在玩家位置。

终端不维护独立找零库存，也不把找零写入商店输出口。

## 6. 发放货币

出售货柜发放结算金额时，金额按货币组从高到低拆分。

例如面额为 `1、10、100、1000`，发放 2387：

```text
2 × 1000
3 × 100
8 × 10
7 × 1
```

物品栏无法容纳的部分同样直接掉落在玩家位置。

## 7. 已接入链路

- 出售终端购买货柜；
- 物品售货机单项购买结算；
- 收购终端出售货柜后的货币发放；

所有链路使用同一个货币服务，普通单物品货币和货币组采用一致的原子扣款、退款与发放行为。

玩家航运档案中的货柜删除属于永久清除操作，不调用货币服务，也不会返还物品或货币。

## 8. 数据包重载

货币组由服务端数据包加载，使用 `/reload` 后更新。

重载只影响之后发生的交易。货柜运行时快照仍保存原始 `currency_id` 和基础单位金额，不会把已经生成的货柜转换为虚拟余额。
