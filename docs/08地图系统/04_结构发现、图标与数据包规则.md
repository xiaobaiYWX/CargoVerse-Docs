# 结构发现、图标与数据包规则

## 发现条件

自然结构不会因为区块进入客户端视距而自动显示。服务端每 20 Tick 检查一次玩家位置，检测节奏与原版 `CriteriaTriggers.LOCATION` 一致，并调用：

```java
StructureManager.getStructureWithPieceAt(playerPosition, structure)
```

只有玩家所在方块进入真实结构部件包围盒后才会发现该结构。这与原版“进入下界要塞”等位置进度使用的结构判定链一致，也能自动支持注册为标准 Minecraft 结构的其他模组内容。

发现记录以玩家为单位发送。网络包只包含新发现标记，不包含地形图片或完整结构列表。客户端持久化结构实例 ID、维度、结构 ID、图标集、可选显示名称与标记位置。

贸易点结构会从这条自然结构发现通道排除，防止贸易点网络与通用结构标记产生重复图标。

## 贸易点到访信息

贸易点沿用相同的“进入真实结构部件”判定，但发送独立的个人贸易点标记。同步内容包括贸易点实例 ID、显示名称、繁荣等级、位置、结构范围，以及该实例资源表中已经固定的具体货物：

- 收购货物取自 `resourceCatalog.acquisitionGoods`；
- 出售货物取自 `resourceCatalog.saleGoods`；
- 无库存交易规则同样属于货物目录，不会因为 `create_inventory: false` 而从地图隐藏；
- 地图不重新匹配标签，也不读取数据包当前版本来猜测商品，因此显示口径与实际贸易点实例一致。

只有到访过的贸易点才会进入玩家的本地标记缓存。再次进入贸易点时会更新繁荣等级和货物目录。

## 数据包目录

结构适配规则位于：

```text
data/<namespace>/trade_map_structure_markers/*.json
```

一个文件可以直接表示单条规则，也可以使用 `entries` 数组：

```json
{
  "entries": [
    {
      "priority": 100,
      "icon_set": "cargoverse:aircraft",
      "display_name": "飞行海盗船",
      "structures": [
        "shellbound_for_airship:airship_ship1"
      ]
    },
    {
      "icon_set": "cargoverse:ruins",
      "structures": [
        "#example:map_ruins"
      ]
    }
  ]
}
```

字段说明：

| 字段 | 必需 | 说明 |
|---|---|---|
| `structures` | 是 | 结构 ID 或以 `#` 开头的结构标签；数组内任一项匹配即可 |
| `icon_set` | 非隐藏规则必需 | 必须是 CargoVerse 已注册的结构图标集 |
| `display_name` | 否 | 地图悬停显示的纯文本名称，最长 256 字符 |
| `priority` | 否 | 数值越大越先匹配，默认 `0` |
| `hidden` | 否 | 为 `true` 时不显示这些结构，且不需要 `icon_set` |

解析时先检查所有规则的结构 ID，再检查结构标签。同类匹配按优先级、文件 ID 和文件内顺序稳定排序。一个结构只采用第一条命中的规则。

## 名称回退

`display_name` 是普通字符串，不解析翻译键或文本组件。

名称显示顺序如下：

1. 使用规则中的非空 `display_name`；
2. 原版结构使用 CargoVerse 内置的本地化结构名称；
3. 其他结构把 ID 路径转为可读文本，例如 `forgotten_airship` 显示为 `Forgotten Airship`。

结构 ID 始终保存在标记记录中，因此后续可以增加调试悬停信息而不改变发现逻辑。

## 已注册图标集

原版专用图标集：

```text
village                 pillager_outpost       mineshaft
woodland_mansion        jungle_temple          desert_temple
igloo                   shipwreck              swamp_hut
stronghold              ocean_monument         ocean_ruins
nether_fortress         end_city               bastion_remnant
ruined_portal           ancient_city           trail_ruins
trial_chambers
```

供其他模组和数据包复用的通用图标集：

```text
castle                  town                    portal_entrance
ship                    lighthouse              dungeon
aircraft                ruins                   factory
research_facility       watchtower              maze
farmstead               temple                  market
unknown_structure
```

所有 ID 使用 `cargoverse` 命名空间，例如 `cargoverse:aircraft`。未匹配任何规则的结构默认使用 `cargoverse:unknown_structure`。玩家方向图标是地图内部覆盖层，不属于数据包可用的结构图标集。

## GUI 行为

结构图标与地图地形使用同一套世界坐标变换。地图缩放低于 `0.4` 时标记按比例缩小，较高缩放时保持标记大小；鼠标命中区域使用实际绘制后的图标矩形。

悬停地图标记仅显示首次发现玩家、到访时间和归属模组等通用基本信息，不显示贸易商品。点击贸易点、普通结构或普通航标图标后，详情卡固定在地图视口右下角，不重复绘制三条通用信息：

- 普通贸易点：放大的名称、归属制造商、收购与出售货物图标；
- 玩家贸易点：放大的名称、第二行“玩家经营贸易点”、收购与出售货物图标；
- 普通结构或未绑定航标：仅放大的名称和第二行 XYZ 坐标，不显示制造商或贸易货物。

详情卡使用固定 `0.5` 显示比例，不随地图缩放，距离右侧和下侧视口边界各留 10px，避免纸张边框遮挡。名称与普通结构坐标按可用宽度适配字号。

详情卡上方统一提供三个按钮，使用原版按钮资源，带悬停高亮、提示与点击音效：

| 位置 | 功能 |
| --- | --- |
| 左上方指南针 | 将当前贸易点、结构或普通航标设为当前宿主的目的地（手册个人目标或当前引导台） |
| 关闭按钮左侧的居中按钮 | 将地图中心移至所选标记，保持缩放，不修改导航目标 |
| 右上方“×” | 仅关闭信息卡，不取消导航目标 |

点击空白地图、再次点击同一标记或拖动地图都不会关闭详情卡；点击其他结构或贸易点替换所选详情。选中点移出视口时仍保持卡片，直到点击关闭按钮或已知资料失效。关闭广播、破坏航标或撤下地图显示，不删除客户端资料，因此也不会取消已有目的地或航线匹配。卡片内部和按钮点击都不会拖动地图。普通结构和贸易点按类型及实例 ID 区分，重名或同 ID 不会互相串选。

制造商显示名称由服务端贸易点定义及制造商定义解析后下发。客户端使用标记缓存的可选元数据尾部保存该名称，兼容已有版本 5 的发现记录；旧记录未取得制造商信息时显示“未记录”，重新到访并收到更新后补齐。没有制造商归属的普通贸易点显示“无”。

地图界面不再绘制中心坐标与缩放系数，缩放和拖动交互保持可用。通用悬停卡片同样留出 10px 边距。

双击同一标记也可设置当前宿主的导航目标：两次点击须在 250ms 内，鼠标位移不超过 4 GUI 像素，类型和实例 ID 必须相同。单击仍只打开详情卡；拖动、缩放、空白点击或按钮点击会取消待配对状态。连续三击不会重复触发两次导航。

当前目的地的可见图标左侧绘制 `textures/gui/trade_map/markers/navigation_target.png`（38×38 源像素），跟随图标缩放；隐藏记录不因此重新显示。玩家标记使用 `markers/player.png`（26×52），以图标中心按玩家自身世界朝向旋转，北/东/南/西分别为 0°/90°/180°/-90°，地图不额外读取载具姿态。

潜在航线的“在地图上显示”按钮会在手册中展开地图、聚焦对应贸易点并打开卡片，但不设置导航目的地。个人目标的显示、保存范围与后续导航接入边界见[航运手册与玩家档案](../12航运手册与玩家档案/README.md)及[导航接口](../12航运手册与玩家档案/04_地图导航架构与接口.md)。
