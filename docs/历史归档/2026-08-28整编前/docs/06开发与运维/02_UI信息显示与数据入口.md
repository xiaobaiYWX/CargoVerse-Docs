# UI 信息显示与数据入口

本文档用于约束各个 GUI 显示货柜信息时的数据来源，避免在不同界面中重复拼接、拆分同一套业务信息。

## 核心原则

- 货柜基础信息统一通过 `CargoDisplayInfo` 组织。
- 终端价格预览统一通过 `CargoPricePreview` 传输。
- Screen 层只负责根据界面空间和颜色需求排版字段，不负责重新计算业务结果。
- 不再使用“完整句子字符串”作为网络数据包字段，也不在客户端通过 `split`、`indexOf` 拆价格、涨跌、完整度等业务数据。

## CargoDisplayInfo

`CargoDisplayInfo` 是面向 UI 的货柜信息包，适合货柜清单、买入终端、出售终端、航运终端等界面共用。

它负责收集并归一化这些字段：

- 货柜定义 ID、显示名称、货物类型、货柜等级
- 词条显示名、词条描述
- 基础价格、货币、最大持有数量
- 最大完整度、当前完整度、完整度比例
- 实例状态、失效原因、购入价格
- 结构重量、生成时间、持有者

如果某个界面已经拥有菜单快照或运行时快照，应先转换为 `CargoDisplayInfo`，再由界面按需显示其中字段。

## CargoPricePreview

`CargoPricePreview` 是终端列表和模型区使用的结构化价格预览包。

它包含：

- 货币 ID
- 当前价格
- 最终市场基础价格（CargoType 基础值经货柜等级和模板倍率修正，不含贸易点、动态经济与完整度修正）
- 较市场价百分比；高于市场价显示红色，低于市场价显示绿色
- 完整度比例
- 是否可交易
- 不可交易原因

买入终端和出售终端都应传输该结构，而不是传输已经拼好的描述文本。

## GUI 侧显示规则

Screen 可以做这些事：

- 将货币 ID 转为本地化物品名。
- 将价格字段格式化为 `绿宝石 x16` 这类显示文本。
- 根据界面区域决定换行、颜色、隐藏字段。
- 根据 `available` 或 `invalidReason` 显示按钮是否可用、状态说明。
- 买入与收购终端的词条使用警示贴花图标显示，鼠标悬停图标时显示本地化词条名称，避免多词条文本换行挤占信息区域。
- 买入终端库存示意采用 `5×3` 网格，库存数量仍显示真实数值；网格最多只用 15 个放大图标表达库存充足程度。
- 买入终端左侧货柜信息面板不再重复显示 `tradePointId`；库存网格使用释放出的底部空间。
- 收购终端中间区域底部独立显示贸易点 `acquisitions.resources` 中的全部可收购 CargoType；使用 CargoType 贴花图标，并在悬停时显示本地化类型名称。该列表由服务端菜单快照同步，不能从本轮随机收购项反推。
- 收购终端模型相对初始布局上移 10px，描述首行累计上移 35px；不再显示“自定义货柜信息”标题，描述区域默认显示 7 行并继续支持滚轮浏览。
- 收购终端模型预览安全框在不移动描述信息的前提下向下扩展 15px，防止描述上移导致模型被动缩小。

Screen 不应做这些事：

- 自己重新计算动态经济价格。
- 从一句预览文本中解析当前价格或涨跌。
- 直接依赖某个具体菜单 entry 类型来生成完整货柜信息。

## 后续维护建议

新增界面时，优先检查是否可以复用 `CargoDisplayInfo` 和 `CargoPricePreview`。如果需要新增字段，应优先扩展这两个结构，而不是在单个 Screen 内新建一套局部字段。
