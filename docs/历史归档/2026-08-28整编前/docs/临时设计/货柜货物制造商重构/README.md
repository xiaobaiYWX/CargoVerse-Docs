# 货柜、货物与制造商重构临时设计

> [!IMPORTANT]
> 第一版数据框架、装卸交易闭环、空货柜购买入口和第二版货柜运行时框架已经实现。旧运行时、旧物理元数据、旧快照结构、`cargo_definitions` 与 `cargo_value_constants` 数据入口均已删除，旧存档不会迁移。贴花刷新和货柜专用词条仍未完成。本目录继续作为重构期间的临时文档，不替代正式玩法文档。

## 1. 设计目标

本次重构将现有“一个货柜定义同时表示容器和商品”的结构拆分为三类数据定义：

```text
硬编码分类 CargoClass
    负责一级大类及其统一贴花；已接入 V3.0 的 24 张分类图标

货物定义 CargoGoodDefinition
    负责科技等级、标签，以及每个货物单位的质量、价值、经验、完整度和运输要求

货柜容器定义 CargoContainerDefinition
    负责物理模板、容量、空质量、耐久、可用货物和型号自身设计

制造商定义 ManufacturerDefinition
    负责制造商身份、对旗下容器的通用修正，以及未来的制造商声望规则
```

玩家存档中的“货柜实例”与“当前装载”是上述三类定义的运行时结果，不属于第四类数据包定义。

## 2. 核心边界

- 货柜是玩家可以长期持有、重复装卸和维修的物流资产。
- 货物是装入货柜的可变内容，卸货或报废后不影响货柜资产的存续。
- 货柜容器一次只能装载一种货物，已装载时只能追加相同货物。
- 一级 CargoClass 固定为 24 类，二级 CargoGood 可由任意命名空间的数据包增删。
- 货物路径为 `cargo_goods/<class>/<good>.json`；完整 ID 是库存、价格与兼容性的唯一键。
- CargoClass 的 `none` 是未知分类回退；内部 CargoGood 的 `none` 仅表示没有有效货物 ID。两者不混用，空柜通过不存在装载数据表示。
- 货物完整度与货柜容器耐久是两套不同数值。
- 货物定义只提供唯一基础价值；市场买入价、收购价和利润来源属于贸易点经济系统。
- 制造商只对已声明的系统作用域提供修正，不使用没有明确语义的通用“状态修正器”。

## 4. 数据与运行时关系

```text
ManufacturerDefinition
    └─ 提供制造商容器特性
             ↓
CargoContainerDefinition
    └─ 解析为最终货柜型号参数
             ↓
CargoContainerInstance ←── 玩家长期持有
    └─ CargoLoad ──→ 保存 CargoGoodSnapshot，来自 CargoGoodDefinition
             └─ 数量、完整度、来源、装载时间和词条运行状态
```

## 5. 临时文档合并条件

只有同时满足以下条件时，才将本目录内容合并到正式文档：

1. 三类数据的原子加载与校验已实现并具有测试。

3. 装卸后的物理质量、词条调度和贴花状态会正确更新。
4. 贸易点库存、定价、经验和繁荣度结算已转换到每单位货物模型。
5. 新存档结构已确定版本号，无兼容切换策略已通过自动化验证。
