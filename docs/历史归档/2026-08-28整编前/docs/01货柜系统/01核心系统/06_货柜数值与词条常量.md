# 货柜数值与词条常量

`cargo_value_constants` 用于集中维护所有 CargoType 的基础经济数值、货柜等级倍率、基础货物单位以及 CargoType 的初始词条。货柜定义只保留允许生成的货物类型、抽取权重、可选微调倍率和词条屏蔽能力，避免在每个货柜文件中重复维护相同数据。

## 文件位置

```text
data/<namespace>/cargo_value_constants/default.json
```

CargoVerse 内置文件位于：

```text
data/cargoverse/cargo_value_constants/default.json
```

数据包可以用相同资源 ID 覆盖内置文件。当前加载器将 `cargoverse:default` 作为唯一首选常量资源，不会合并多个常量文件；因此应把正式配置集中在一个 `default.json` 中。

## 顶层结构

```json
{
  "cargo_type_constant": {
    "ore": {
      "base_mass": 50,
      "base_buy_price": 120,
      "base_sell_price": 160,
      "license_experience": 10,
      "trade_point_experience": 5
    }
  },

  "cargo_level_constant": {
    "L": {
      "price_multiplier": 4.5,
      "license_multiplier": 3.5,
      "prosperity_multiplier": 3.5,
      "mass_multiplier": 4.0,
      "cargo_units": 40
    }
  },

  "cargo_type_affixes": {
    "electronics": [
      {
        "id": "moisture_proof",
        "damage_per_second": 2.0
      },
      {
        "id": "fragile",
        "speed_delta_threshold": 10.0,
        "damage_amount": 5.0
      }
    ]
  }
}
```

| 字段 | 必填 | 说明 |
| --- | :---: | --- |
| `cargo_type_constant` | 是 | CargoType 的基础质量、价格和经验。 |
| `cargo_level_constant` | 是 | 货柜等级倍率与基础 `cargo_units`。 |
| `cargo_type_affixes` | 否 | CargoType 的统一初始词条；未列出的类型默认没有初始词条。 |

## CargoType 基础数值

`cargo_type_constant` 的键是固定 CargoType。每个类型支持以下字段：

| 字段                       | 类型  | 约束             | 说明                        |
| ------------------------ | --- | -------------- | ------------------------- |
| `base_mass`              | 数字  | 必填，`0～1000000` | S 级、模板质量倍率为 `1.0` 时的基础质量。 |
| `base_buy_price`         | 整数  | 必填，非负          | 贸易点向玩家出售货柜时的基础价格。         |
| `base_sell_price`        | 整数  | 必填，非负          | 贸易点收购玩家货柜时的基础价格。          |
| `license_experience`     | 整数  | 必填，非负          | 基础运输许可经验。                 |
| `trade_point_experience` | 整数  | 必填，非负          | 基础贸易点繁荣经验。                |

推荐为所有固定 CargoType 提供数值，包括 `none`。当前类型清单见[[05_货物类型]]，正式平衡目标见[[../02内容设计/03_货柜数据常数|货柜数据常数设计]]。

## 货柜等级常量

`cargo_level_constant` 的键为 `S`、`M`、`L`、`X`、`XL` 或 `SP`。

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `price_multiplier` | 数字 | `1.0` | 同时作用于买入价和卖出价。 |
| `license_multiplier` | 数字 | `1.0` | 运输许可经验倍率。 |
| `prosperity_multiplier` | 数字 | `1.0` | 贸易点繁荣经验倍率。 |
| `mass_multiplier` | 数字 | `1.0` | 货柜目标质量倍率。 |
| `cargo_units` | 整数 | 无 | 必填，表示该等级的基础货物单位。 |

倍率必须是 `0～1000` 内的有限非负数，`cargo_units` 必须是非负整数。

## 最终数值计算

货柜定义的每个 CargoType 仍可提供五项模板微调倍率。省略时均为 `1.0`。

```text
最终质量 =
base_mass × 等级 mass_multiplier × 类型 mass_modifier

最终货物单位 =
round(等级 cargo_units × 类型 cargo_units_modifier)

最终基础买入价 =
base_buy_price × 等级 price_multiplier × 类型 price_modifier

最终基础卖出价 =
base_sell_price × 等级 price_multiplier × 类型 price_modifier

最终许可证经验 =
license_experience × 等级 license_multiplier × 类型 license_modifier

最终繁荣经验 =
trade_point_experience × 等级 prosperity_multiplier × 类型 prosperity_modifier
```

价格、经验和货物单位采用四舍五入后的受限整数。最终质量上限为 `1000000`。

## CargoType 初始词条

`cargo_type_affixes` 将货物固有运输风险集中到一张表中。键必须是规范的小写 CargoType，值是词条对象数组。

```json
{
  "cargo_type_affixes": {
    "fuel_resource": [
      {
        "id": "flammable",
        "ignition_temperature": 100.0,
        "sunlight_threshold": 12,
        "sunlight_heat_per_second": 1.0,
        "hot_biome_temperature_threshold": 1.5,
        "hot_biome_heat_per_second": 1.0,
        "cold_biome_temperature_threshold": 0.15,
        "cold_biome_cooling_per_second": 1.0,
        "shade_cooling_per_second": 0.5,
        "burning_damage_per_second": 2.0
      }
    ]
  }
}
```

规则：

- 每种 CargoType 最多配置 5 个初始词条。
- 同一 CargoType 内不能重复声明同一词条 ID。
- 裸 ID 如 `fragile` 默认属于 `cargoverse`，与 `cargoverse:fragile` 等价。
- 词条对象的参数、范围和运行效果见[[04_词条与完整度系统]]。
- 未知词条、错误字段类型或超过数量上限会导致数据包加载失败；数值参数是否钳制到允许范围，以具体词条章节的说明为准。

## 货柜词条屏蔽

货柜根节点通过 `blocked_affixes` 声明自身能够消除的运输风险：

```json
{
  "template": "cargoverse:aui/titan/aui_titan_sd_l",
  "blocked_affixes": [
    "fragile"
  ],
  "cargo_type": {
    "component": {
      "weight": 3
    },
    "electronics": {
      "weight": 1
    }
  }
}
```

货柜还可以通过根节点 `base_affixes` 为所有允许的 CargoType 追加自身携带的词条：

```json
{
  "blocked_affixes": [
    "fragile"
  ],
  "base_affixes": [
    {
      "id": "fragile",
      "speed_delta_threshold": 15.0,
      "damage_amount": 3.0
    }
  ]
}
```

最终词条按以下顺序生成：

```text
1. 读取 CargoType 初始词条
2. 移除 blocked_affixes 中列出的词条
3. 添加 base_affixes 中的货柜基础词条
4. 将最终词条和完整参数写入货柜实例快照
```

因此最终公式为：

```text
最终词条 = CargoType 初始词条 - blocked_affixes + base_affixes
```

屏蔽列表和基础词条都作用于该货柜的所有 CargoType。基础词条在屏蔽之后执行，所以同一个 ID 同时存在于两处时仍然生效；如果基础词条与未屏蔽的初始词条同名，则使用基础词条参数覆盖初始参数。最终去重后的词条数量不得超过 5 个，否则货柜定义加载失败。

## 已移除的内联格式

`cargo_type.<type>.affixes` 已经移除，不再提供兼容解析。货柜定义中出现该字段时，数据包加载会直接失败并提示将固有词条迁移到 `cargo_type_affixes`、将防护能力迁移到 `blocked_affixes`、将货柜附加词条迁移到 `base_affixes`。

## 重载与实例稳定性

执行数据包重载后，新的常量会影响之后生成或刷新到商店列表的货柜。已经生成的货柜会在实例快照中保留生成时的：

- 最终质量、价格、经验和货物单位；
- 最终词条 ID 与完整参数；
- 实际使用的结构模板 ID。

因此修改 `cargo_value_constants` 不会追溯改变世界中已经存在的货柜。

## 维护检查清单

修改常量表后应确认：

1. `cargo_type_constant` 覆盖所有实际使用的 CargoType。
2. `cargo_level_constant` 覆盖所有货柜定义使用的等级。
3. 每个等级都包含非负整数 `cargo_units`。
4. `cargo_type_affixes` 中没有未知类型、重复词条或超过 5 个词条的类型。
5. 货柜定义中不存在已移除的 `cargo_type.<type>.affixes`。
6. 功能货柜通过 `blocked_affixes` 表达其防护能力。
7. 货柜固有的附加限制通过 `base_affixes` 表达，并确认最终词条不超过 5 个。
8. JSON 使用清晰的多行缩进，并在游戏中执行一次数据包重载测试。
