# 词条与完整度系统

完整度是带词条货柜实例的统一货损值。所有累计型限制词条都会扣除同一个完整度，而不是各自维护独立损坏计数。最终实例没有任何词条时不创建完整度属性。注意!每个货柜的每个cargotype最多只可定义5个词条，超出的词条将直接舍弃，不会生效也不会进入词条扫描。

## 完整度规则

货柜定义中设置最大完整度：

```json
"max_integrity": 100
```

当最终 `cargo_type` 至少包含一个词条时，玩家购买后的货柜实例会拥有：

- 当前完整度
- 最大完整度

最终词条列表为空时：

- 实例不定义完整度，内部以 `maxIntegrity = 0` 标识。
- 终端、货柜信息工具和价格预览不显示完整度栏位。
- 出售价格和许可证经验直接使用正常值，不获得 `100%` 完整度的额外 `10%` 奖励。
- 此次运输不参与玩家平均完整度和完整度评分的累计。

当完整度降低到 `0` 时，货柜会被标记为失效，并从后续持续检测中退出。失效货柜不能正常出售，但玩家可以在航运终端中将其删除；删除失效货柜不会返还任何购买资源。

## 完整度与交易奖励

对于拥有完整度的货柜，完整度同时影响最终出售价格和运输许可经验。系统先根据完整度计算奖励倍率：

```text
完整度 = 当前完整度 / 最大完整度

完整度 = 100%：奖励倍率 = 1.10
90% <= 完整度 < 100%：奖励倍率 = 1.00
完整度 < 90%：奖励倍率 = 完整度 / 90%
```

最终奖励为：

```text
最终出售价格 = round(正常出售价格 × 奖励倍率)
最终许可经验 = round(基础许可经验 × 奖励倍率)
```

无完整度货柜的奖励倍率固定为 `1.00`。

以正常出售价格 `100`、基础许可经验 `25` 为例：

| 完整度 | 奖励倍率 | 最终价格 | 最终经验 |
| --- | ---: | ---: | ---: |
| `100%` | `1.10` | `110` | `28` |
| `95%` | `1.00` | `100` | `25` |
| `90%` | `1.00` | `100` | `25` |
| `81%` | `0.90` | `90` | `23` |
| `45%` | `0.50` | `50` | `13` |

这样，运输途中发生少量、难以完全避免的损耗不会降低收入；保持 `100%` 完整度则会获得完美运输奖励。

## 词条写法

词条统一写在 `cargo_value_constants/default.json` 的 `cargo_type_affixes` 中，不允许在货柜定义的 CargoType 内联词条。每个 CargoType 最多定义 5 个初始词条，数组顺序同时决定 Affixes 贴花槽位 `0～4` 的顺序。

```json
"cargo_type_affixes": {
  "agriculture": [
    {
      "id": "time_limit",
      "time_tick": 24000
    }
  ],
  "electronics": [
    {
      "id": "moisture_proof",
      "damage_per_second": 1.0
    }
  ]
}
```

货柜自身能够消除的限制通过根节点 `blocked_affixes` 配置；货柜本身附加给所有货物的词条通过根节点 `base_affixes` 配置。执行顺序为“CargoType 初始词条 → 屏蔽 → 货柜基础词条”，完整结构见[[06_货柜数值与词条常量]]。

词条显示文本不写在数据包中，而是写在语言文件中，方便后续翻译。

## 已支持词条

### 限时 `time_limit`

货柜必须在限定时间内完成运输。超时后货柜直接失效。

```json
{
  "id": "time_limit",
  "time_tick": 24000
}
```

参数：

- `time_tick`：限制时间，单位为游戏刻。`20 tick = 1 秒`，`24000 tick = 1 游戏日`。

失效原因：

```text
time_limit
```

### 防潮 `moisture_proof`

货柜入水会立即失效；在雨中暴露会持续降低完整度。

```json
{
  "id": "moisture_proof",
  "damage_per_second": 1.0
}
```

参数：

- `damage_per_second`：满足受潮条件时，每秒降低的完整度。

判定方式：

- 入水：立即失效。
- 淋雨：检测货柜中心点和包围盒 8 个角点。
- 中心点无遮蔽，或任意两个角点无遮蔽，即视为暴露在雨中。
- 普通方块遮挡会被计入遮蔽，物理结构自身遮蔽不额外处理。

失效原因：

```text
water_damage
rain_damage
```

### 防寒 `cold_proof`

货柜处于低温、可降雪生态群系时，会持续降低完整度。

```json
{
  "id": "cold_proof",
  "damage_per_second": 1.0
}
```

参数：

- `damage_per_second`：处于低温环境时，每秒降低的完整度。

失效原因：

```text
cold_damage
```

### 请勿倒置 `keep_upright`

货柜需要大致保持朝上。侧翻或倒置时，会持续降低完整度。

```json
{
  "id": "keep_upright",
  "damage_per_second": 1.0,
  "min_up_dot": 0.5
}
```

参数：

- `damage_per_second`：侧翻时每秒降低的完整度。
- `min_up_dot`：货柜朝上方向与世界上方向的最低点积，默认 `0.5`。

`min_up_dot` 越高，要求越严格；越低，允许倾斜角度越大。

失效原因：

```text
tipped_damage
```

### 易碎品 `fragile`

货柜速度在短时间内变化过大时，会一次性降低完整度。

```json
{
  "id": "fragile",
  "speed_delta_threshold": 3.0,
  "damage_amount": 5.0
}
```

参数：

- `speed_delta_threshold`：触发损坏所需的速度变化阈值。
- `damage_amount`：每次触发时降低的完整度。

失效原因：

```text
impact_damage
```

### 冷链运输 `cold_chain`

货柜必须处于满足原版降雪条件的低温生态群系；离开低温环境后持续降低完整度。

```json
{
  "id": "cold_chain",
  "damage_per_second": 1.0
}
```

- `damage_per_second`：不满足降雪条件时每秒降低的完整度，默认 `1.0`。
- 使用货柜物理中心所在位置进行生态群系判定。
- 完整度归零原因：`cold_chain_damage`。

### 高度限制 `height_limit`

```json
{
  "id": "height_limit",
  "height_threshold": 256,
  "damage_per_second": 1.0
}
```

- `height_threshold`：允许的最高世界 Y 坐标，默认 `256`；物理中心严格高于该值时触发。
- `damage_per_second`：超过高度阈值时每秒降低的完整度，默认 `1.0`。
- 完整度归零原因：`height_limit_damage`。

### 避光 `light_sensitive`

```json
{
  "id": "light_sensitive",
  "light_threshold": 7,
  "damage_per_second": 1.0
}
```

- `light_threshold`：允许的最高综合本地亮度，限制为 `0～15`，默认 `7`。
- `damage_per_second`：亮度严格大于阈值时每秒降低的完整度，默认 `1.0`。
- 天空光和方块光不区分，直接使用原版综合亮度。
- 完整度归零原因：`light_damage`。

### 放射性 `radioactive`

```json
{
  "id": "radioactive",
  "radius": 6,
  "effect_ids": [
    "minecraft:weakness",
    "minecraft:wither"
  ],
  "effect_duration_ticks": 120,
  "effect_amplifier": 0
}
```

- `radius`：影响半径，默认 `2`，强制限制为 `2～16`。
- `effect_ids`：药水效果 ID 数组，最多读取 16 项；非法或未注册 ID 不会产生效果。
- `effect_duration_ticks`：单次效果持续时间，限制为 `20～12000 tick`，默认 `120`。
- `effect_amplifier`：原版零起始效果强度，`0` 表示 I 级，限制为 `0～255`。
- 只遍历货柜所在维度的玩家，不扫描其他生物；旁观者不会受到影响。
- 放射性不会降低货柜自身完整度，也不会使货柜失效。

### 易燃物 `flammable`

易燃货柜会根据日照和生态群系温度积累隐藏温度。温度达到点燃阈值后进入燃烧状态，并持续降低完整度，直至货柜失效或接触水源灭火。

```json
{
  "id": "flammable",
  "ignition_temperature": 100.0,
  "sunlight_threshold": 12,
  "sunlight_heat_per_second": 1.0,
  "hot_biome_temperature_threshold": 1.5,
  "hot_biome_heat_per_second": 1.0,
  "cold_biome_temperature_threshold": 0.15,
  "cold_biome_cooling_per_second": 1.0,
  "shade_cooling_per_second": 0.5,
  "burning_damage_per_second": 2.0
}
```

参数：

- `ignition_temperature`：进入燃烧状态所需的温度，默认 `100.0`，限制为 `0.001～1000000`。
- `sunlight_threshold`：开始积累日照热量所需的最低天空光照，默认 `12`，限制为 `0～15`。
- `sunlight_heat_per_second`：满足强烈日照条件时每秒增加的温度，默认 `1.0`。
- `hot_biome_temperature_threshold`：视为炎热生态群系的原版基础温度阈值，默认 `1.5`。
- `hot_biome_heat_per_second`：处于炎热生态群系时每秒增加的温度，默认 `1.0`。
- `cold_biome_temperature_threshold`：视为寒冷生态群系的原版基础温度阈值，默认 `0.15`。
- `cold_biome_cooling_per_second`：处于寒冷生态群系时每秒降低的温度，默认 `1.0`。
- `shade_cooling_per_second`：未满足强烈日照条件时每秒降低的温度，默认 `0.5`。
- `burning_damage_per_second`：燃烧状态下每秒降低的完整度，默认 `2.0`。

温度计算规则：

- 强烈日照和炎热生态群系的升温可以同时生效并叠加。
- 阴凉冷却和寒冷生态群系冷却可以同时生效并叠加。
- 炎热与寒冷生态群系判定互斥；达到炎热阈值时不会同时应用寒冷冷却。
- 隐藏温度最低为 `0`，最高为 `1000000`。
- 日照判定使用货柜物理中心位置的天空光照，并要求该位置上方可以直接看见天空。
- 生态群系冷热判定使用货柜物理中心位置的原版生态群系基础温度。

燃烧与灭火规则：

- 温度达到 `ignition_temperature` 后，货柜进入燃烧状态。
- 燃烧状态不会因为进入阴凉或寒冷生态群系而自然结束；系统持续按照 `burning_damage_per_second` 扣除完整度。
- 货柜接触水时，无论是否已经燃烧，都会立即将温度归零；已经燃烧时同时灭火。
- 水体检测覆盖货柜物理中心及其上下、东南西北六个相邻位置。
- 燃烧货柜会从包围盒顶面持续喷出火焰和明显烟雾粒子。
- 完整度归零原因：`fire_damage`。

对应警示贴花：

```text
cargoverse:decal_warning_flammable
```

## 性能原则

持续检测型词条只检查仍然有效的货柜实例，并通过 100 tick 分桶调度摊开负载。完整度伤害和易燃物温度变化会按照实际经过 tick 折算为每秒数值。货柜一旦失效，就会退出后续检测集合，避免服务器中存在大量无意义检查。

易燃物环境检测沿用持续词条的分桶调度；燃烧粒子只遍历单独维护的燃烧货柜索引，不会为了视觉效果扫描全部货柜实例。
