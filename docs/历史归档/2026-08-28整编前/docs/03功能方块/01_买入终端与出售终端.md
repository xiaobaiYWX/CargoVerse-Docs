# 买入终端与出售终端

> 当前贸易点格式已取消 `cargo_buyback` 模板白名单。收购终端只检查扫描到的真实货柜实例及其 CargoType 是否匹配当前已解锁的 `acquisitions.resources`。买入终端展示贸易点固定出售列表；上架项按“货柜定义 + CargoType”组合判重，因此允许同模板不同类型或同类型不同模板共存。`always_available` 项不占普通列表槽位，但购买时仍需消耗共享产出库存。

收购终端的玩家出售列表只来自当前扫描范围内的真实货柜实例，不再为所有理论上可收购的货柜定义生成空占位项。扫描实例仍需属于操作玩家、具有有效运行时数据，且其 CargoType 已在当前繁荣度下解锁并存在于贸易点的 `acquisitions.resources`。

两个子终端都只通过 `tradePointId` 绑定主贸易点，不再填写独立的出售定义 ID 或收购定义 ID。模板池、资源方向、权重、库存基础值和繁荣度门槛统一来自该实例注册的贸易点定义。

相同 `tradePointId` 的终端共享贸易点定义、繁荣度、活跃度、输入库存、产出库存、出售列表和动态价格。子终端只保存自身的绑定 ID 与扫描或生成空间参数，不拥有独立的经济库存副本。

## 买入终端

玩家在买入终端购买贸易点产出的货柜。管理员只配置：

- `tradePointId`
- X/Y/Z 生成偏移

候选模板读取贸易点定义中的 `sales.cargo_pool.entries`：

| 字段 | 说明 |
| --- | --- |
| `cargo_definition` | 货柜模板定义 ID。 |
| `weight` | 第一阶段模板抽取权重。 |
| `always_available` | 为 `true` 时固定显示且不占普通列表槽位；购买仍检查并扣除对应 CargoType 的共享 `output_cargo_units`。 |
| `required_prosperity` | 所需贸易点繁荣等级。 |

刷新列表时按以下顺序生成最终上架项：

1. 按繁荣等级筛选 `sales.cargo_pool.entries`。
2. 排除与贸易点 `sales.resources` 没有任何类型交集的模板。
3. 按模板条目 `weight` 无放回抽取模板。
4. 对每个模板，在其 `cargo_type` 与 `sales.resources` 的交集中按类型 `weight` 抽取最终类型。
5. 将“模板 ID + 最终 cargo_type”固化到贸易点实例的共享出售列表。

价格、词条、运输许可经验、繁荣经验、动态经济键、CargoType 占位贴花、Affixes 槽位贴花、结构预览和实际生成都使用这份固化结果，不会分别重新随机。

普通货柜不再维护独立的终端货柜库存。玩家购买时检查运输许可等级、持有上限、货币、生成区域，以及该 CargoType 对应的贸易点 `output_cargo_units`；购买成功后按货柜 `cargo_units` 扣除共享产出库存并记录经济交易。

## 出售终端

出售终端扫描范围内的玩家货柜并回收。管理员只配置：

- `tradePointId`
- 扫描偏移
- 扫描宽度、高度和深度

货柜必须同时满足：

1. 实例属于当前玩家且处于可出售状态。
2. 实例最终 `cargo_type` 存在于贸易点 `acquisitions.resources`。
3. 贸易点繁荣等级达到该资源类型的 `required_prosperity`。

收购终端只列出扫描范围内实际发现且符合条件的货柜，不再抽取或保存独立的收购模板列表。

收购价格按照该实例最终类型的动态价格与贸易点资源倍率计算，再乘以完整度奖励。出售成功后发放该类型配置的 `license_experience` 和经贸易点修正后的繁荣度经验；若该类型启用了输入库存，则按货柜 `cargo_units` 增加共享 `inputs_cargo_units`，同时更新 CargoType 动态经济。

## 配置原则

- `sales.resources` 表示贸易点能向玩家产出的资源类型。
- `acquisitions.resources` 表示贸易点愿意从玩家手中消耗、收购的资源类型。
- 模板列表决定允许哪些结构型号参与交易，资源列表决定这些模板最终可以承载或被收购的货物类型。
- 子终端不读取独立的出售/收购定义目录；贸易点交易入口统一为 `trade_points`。
