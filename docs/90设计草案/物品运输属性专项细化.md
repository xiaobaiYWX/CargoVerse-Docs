## 专项审核顺序

| 顺序 | 分组 | 逐项要明确的内容 | 可交付结果 |
| --- | --- | --- | --- |
| 1 | 建筑、染色、自然方块 | 同材质加工前后与十六色变体；完整块、薄片、粉料、冰的差异 | 每个 ID 的质量与必要条件；跨创造栏同材质对照 |
| 2 | 食物饮品、原材料 | 耐储食品与鲜食、瓶体与内容、粉料与压制成品 | 温区、保鲜预算、围护、防潮、原生扣量逐项表 |
| 3 | 工具实用品、战斗用品 | 堆叠 64／16／1 与组件身份；不可分割货损边界 | 轻工具、重装备、仪表、弹药的质量与冲击方案 |
| 4 | 功能与红石、Create、航空、CargoVerse | 储物、封装、机构、外露部件与正常获取渠道 | 准入复核与真正需要保护的精密品清单 |
| 独立 | 管理员与非正常获取 | 命令、无限源、模板辅助、无物品掉落及实验内容 | 获取原因明确；不自动把此分类写成 blocked |

## 参数编写准则

- 单组质量用 0、0.1、0.2、0.5、1、1.5、2、3、5 等既有档位，最多一位小数。微小饰件可为 0，零质量仍占容量。
- 普通石料每组 1 Kpg；容量 50 组时货重 50 Kpg，不含柜体。方块按包装运输形态计量，不照放置后体积或现实密度给出吨级重量。
- 质量、易碎、腐坏、围护、干燥等逐 ID 审核；创造栏名称只决定查阅位置，不能给整栏物品一键套用同一属性。
- 同一物品重复出现在多个原版标签页时只维护一个主条目；玻璃、玻璃瓶、玻璃板等跨栏相关物品仍需一起复核。
- 持续损耗按默认每组相近比例设计，运行仍是整数 pcs 与固定间隔。64 堆叠每分钟 8 件、16 堆叠每分钟 2 件、1 堆叠每 8 分钟 1 件是同一比例的参考。
- 风险宽限和保鲜预算不随堆叠数量机械缩放；组件改变最大堆叠量时按现有冻结机制处理，不虚构逐组件独立配置。
- 每次改动在对应专项文档记录具体 ID、旧值、新值、理由与代表航程验证；改 JSON 后同步查阅表，不从 Markdown 反向覆盖数据包。

## 特殊获取与运输准入分开

目前 99 类 130 项，其中 16 项当前并非 blocked。这些不是分类错误，也不在本轮自动禁运；是否调整准入需要另按存档恢复与嵌套内容规则审核。

- 虫蚀方块、耕地、土径、紫水晶母岩、强化深板岩、蛙卵、紫颂植株等，世界方块存在不等于可获得对应物品。
- 普通战利品、村民交易品、加工中间产物即使没有合成配方，也不能直接认定为管理员内容；高草丛、大型蕨的村庄战利品渠道需要保留。
- 1.21.1 收纳袋配方位于内置 bundle 实验数据包；默认未启用时列入特殊获取。若整合包启用了该包或补了配方，改列工具页，不改运输属性来表达获取方式。
- Create 普通背罐和胶水虽可能禁止运输，仍不属于创造专用物品；内部 *_placeable 辅助物品与正常背罐分别统计。
- CargoVerse 玩家标记、设备、接口不能按名称统一判为管理员物品。模板标记、测试方块与占位物单独标注；其他设备的完整获取链尚未逐项验证。
