# 百科资源与条目制作

第五章节的手工首页保持六个入口，右侧子条目列表现在由真实 Markdown 资源生成。新增文章不需要注册 Java 页面，也不需要填写文字、图片的 x/y 坐标。

本文与[Markdown 与自动排版规范](06_Markdown与自动排版规范.md)构成首版条目制作基线。游戏内百科侧重用途、操作、反馈和限制，不编写复杂技术文档，也不引入链接返回历史。六章页面与百科首页的完整交互见[页面规则](02_六章内容与页面规则.md)。

## 快速新增一篇文章

在模组资源或资源包中创建：

```text
assets/cargoverse/handbook/entries/zh_cn/containers/my_container.md
```

文件内容例如：

```markdown
---
order: 200
icon: minecraft:chest
---

# 我的货柜说明

这里说明它有什么用，以及玩家需要了解的基本概念。

![货柜示意](cargoverse:textures/gui/player_shipping_profile/encyclopedia/containers.png){width=48 max_height=48}

## 使用方法

1. 完成准备。
2. 执行操作。
3. 检查反馈。

> [!WARNING]
> 在这里写清楚重要限制和不可逆后果。

进一步了解[货物与货柜](entry:cargoverse:containers/cargo)。
```

文件的条目 ID 是 `cargoverse:containers/my_container`；图片资源放在 `assets/<命名空间>/textures/` 内。图片目标必须写完整资源 ID，不能写 Windows 磁盘路径、相对路径或网站地址。

本例属于 `containers` 分类，出现在“货柜与运输”下。文章先按 `order` 排序，相同时按完整 ID 排序。没有文件头时顺序默认为 1000、目录使用书本图标；有 `icon` 时显示对应物品模型，物品不存在仍使用书本。子条目按钮使用 114×12 原生背景，物品模型显示为 10px，相邻按钮间留 3px 空隙，空隙不响应点击；名称为右侧箭头预留空间，过长时省略并提供完整标题提示。`# 标题` 是目录名称和正文页头，不在文件头重复填写。

## 六个分类

| 目录名 | 首页名称 |
| --- | --- |
| `getting_started` | 启航指南 |
| `trading` | 贸易与交易 |
| `containers` | 货柜与运输 |
| `player_trade_points` | 经营贸易点 |
| `map_and_navigation` | 地图与导航 |
| `vehicle_instruments` | 载具与仪表 |

这是玩家阅读分类，不是代码包的镜像。内容侧重用途、操作、反馈与限制，不需要展示内部存档结构或计算公式。

## 当前支持的正文

- 一个首行一级标题 `# 标题`，以及 `##`、`###` 小节标题。
- 空行分段；同段的源码换行自动合并，中文不凭空加空格，英文单词和句子正常衔接。
- `**强调**` 和行内反引号术语；正文按照真实字体测量，不按中文字数猜宽度。
- 一级无序列表和有序列表。长项可以续页，编号只在首次出现时绘制，后续页用续行符号。
- 独占一行的 PNG 图片和图注；可追加 `{width=48 max_height=48}`，也可以省略参数。
- 普通 `>` 提示、`> [!NOTE]` 提示和 `> [!WARNING]` 警告。
- `[文字](entry:namespace:category/article)` 内部链接，仅快速打开相应条目，不记录跳转历史；跨行链接的各段都可以点击。
- 独占一行的 `<!-- pagebreak -->`：转到下一张单页，不是跳过整个跨页。连续、首尾指令不制造空白页。
- 独占一行的 `<!-- 作者备注 -->` 注释，不参与布局。

不支持 HTML、脚本、外链、表格、代码围栏、嵌套列表、任意分栏或文字绕图。详细规则与转义写法见[规范](06_Markdown与自动排版规范.md)，可复制通用[条目模板](07_百科条目制作模板.md)。

## 自动排版和阅读

单页安全区仍为 130×200 逻辑像素，页头 28px、正文 158px，底部留给返回和页码。正文为 1.0 倍字号，不为挤入一页而自动缩小，也不使用省略号隐藏正文。条目标题最多两行，过长时省略并保留完整标题悬停提示。

普通段落自动续页；标题尽量与后面的内容保持一起。图片保持比例且完整显示，图注与图片同页；图注太长而无法容纳时显示明确的排版错误。长提示框会分成带“续”标签的新框，不丢掉后半部分。

一篇文章独立使用若干页，从左页开始，每次翻一整个跨页。奇数末页的右边保持空白，不自动拼下一篇文章。左页页码在左下角，右页页码在右下角；各有效页的页码内侧相隔 2px 放置原生 10×10 的返回图标（左页在页码右侧、右页在页码左侧），空白末页不显示。两个图标都返回百科章节首页，并保留首页分类和列表位置，不再显示文字返回或目录按钮。

点击图片打开居中放大层。关闭按钮或 Esc/E 先关闭放大层，不穿透到手册；再次按关闭键才退出手册。不同章节、重新打开手册及服务端档案刷新不会丢失当前文章；阅读状态仅保存在客户端会话中，不跨游戏重启保存。

## 语言与资源包

译文放入对应语言目录，相对条目路径保持一致，例如：

```text
assets/cargoverse/handbook/entries/en_us/containers/my_container.md
```

逐条选择当前语言，缺失时回退 `zh_cn`、再回退 `en_us`；同一文章使用一份完整译文，不拼接不同语言段落。使用资源包的完整同路径覆盖一篇文章或图片，优先级遵循 Minecraft 资源管理器。

正文与图片属于客户端资源，不属于服务端数据包；不要放在 `data/` 下。重命名文件会改变条目 ID，内部链接也要同步调整。

## 修改后如何刷新

- 编辑已经启用的文件夹资源包：保存后按 F3+T 重载资源，再进入百科即可；不需要重启或编译 Java。
- 编辑工程的 `src/main/resources`：先执行 `gradlew.bat processResources`，将新文件复制进开发运行时资源目录，再按 F3+T。单改源码目录不保证正在运行的客户端立即读到它。
- 资源更新会重新发现文章并清除排版、图片尺寸缓存，目录与正文按需重建。
- 字体/语言变化后重新测量分页；优先按原内容块的指纹和片段恢复位置，再回退源行号或有效页码。删除当前文章则返回分类首页。

## 制作检查

在文章页按 F8 开关辅助显示，可查看页头、正文、页脚和内容块边界；左上角显示条目 ID，悬停内容块显示源资源与行号。它只用于制作检查，默认关闭。

客户端日志会报告文件头、语法、链接、缺图和尺寸问题；加载错误只影响对应文章。不存在的链接使用错误颜色并禁止跳转，缺图显示占位框；语法错误或无法安全排版的文章显示错误说明，不伪装成完整正文。超过 200 条库诊断时只输出前 200 条及剩余数量，防止刷屏。

首版预算：

| 项目 | 上限 |
| --- | --- |
| 全部语言 Markdown 资源数量 | 1024 |
| 单个 Markdown 文件 | 128 KiB UTF-8 |
| 全部正文资源 | 8 MiB |
| 单篇内容块 | 2048 |
| 单篇图片块 | 64 |
| 单篇最终单页 | 256 |
| 单个 PNG 文件 | 8 MiB |
| PNG 尺寸 | 每边不超过 4096px，总像素不超过 4M |
| 单篇解析诊断 | 64 |
| 排版缓存 | 最近使用的 96 篇 |

单篇超限会明确报错；资源总数或总文本超限时拒绝该次百科库，不暗中只展示前一部分。图片先检查文件与尺寸再验证解码，不为未阅读的文章解码图片；缺图占位仍允许阅读文字。排版只在文章首次打开或内容/字体/语言失效后计算，不逐帧解析和分页。

## 条目交付检查清单

1. 从[条目模板](07_百科条目制作模板.md)复制，选择六类中的一个目录；路径使用稳定英文 ID，显示名称写在 `# 标题`。
2. 用真实截图或结构图替换示意图，替换模板中的物品 ID 和链接；不需要的章节直接删除，不保留空提示框或示例占位。
3. 在代码仓库 `CargoVerse-NeoForge-1.21.1` 中执行 `gradlew.bat test --tests "*Handbook*" --tests "*PlayerShippingProfileEncyclopediaPage*"`。校验遍历所有内置译文，检查语法、所选语言及回退视图中的目标链接、实际图片尺寸和分页边界，并检查资源文本预算。不同语言独立排版，英文译文也需要检查。
4. 按前述步骤重载，在游戏内检查中文/英文、常用 GUI 缩放、奇数末页、图注和长列表；自动测试使用替代字体度量，不能替代游戏内视觉验收。
5. 确认两侧页码旁图标都回到百科首页且保留分类/列表位置；图片放大、关闭与返回不得穿透到下层控件。
6. 提交正式条目时一并提交 Markdown 和引用图片；只有新增排版能力时才修改 Java 和制作规范，不逐篇微调坐标。

## 内置起步内容

当前六个分类各有一篇中文条目，用于验证机制说明、方块说明和操作教程三种写法；货物与货柜另有英文译文。这些起步内容使用现有分类图标示意，后续可直接替换为实际结构图和界面局部图，无需修改排版代码。百科内容仍需持续补充，不代表所有方块都已编写完成。
