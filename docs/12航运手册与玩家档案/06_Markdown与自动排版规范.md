# 百科 Markdown 与自动排版规范

首版制作基线 v1.0。本页规定游戏内正文接受的语法和排版行为，不是通用 Markdown 或 HTML 文档系统。资源路径、语言回退、重载、预算和检查流程见[条目制作](05_百科资源与条目制作.md)，首页和阅读按钮见[页面规则](02_六章内容与页面规则.md)。

新增普通条目只添加 Markdown 和 PNG，不写 Java、不填 x/y，也不按字数人工拆页。正文以帮助玩家理解用途、操作、反馈和限制为主；详细数值设计、实现方法和管理接口继续保留在外部文档。

## 1. 路径、分类和稳定 ID

```text
assets/<namespace>/handbook/entries/<language>/<category>/<name>.md
assets/<namespace>/textures/handbook/<category>/<name>.png
```

正文目录是固定入口；图片示例目录可按需要细分，但图片引用必须是完整的 `namespace:textures/...png`。

`assets/cargoverse/handbook/entries/zh_cn/player_trade_points/warehouse.md` 的条目 ID 为 `cargoverse:player_trade_points/warehouse`，不含语言和扩展名，也不取显示标题。相同条目的译文保持同一相对路径，允许分类内继续分子目录；重命名路径会改变 ID，链接必须同步修改。

分类限定为六个：`getting_started`、`trading`、`containers`、`player_trade_points`、`map_and_navigation`、`vehicle_instruments`。内容边界与显示名称见[六分类表](05_百科资源与条目制作.md#六个分类)。跨系统知识选择一个主分类，用简单条目链接关联，不重复维护全文。

## 2. 可选文件头

```markdown
---
order: 100
icon: minecraft:chest
---

# 仓库管理终端
```

- 文件头可省略；存在时必须位于文件开头，以两行独立 `---` 包围。
- 仅支持 `order` 和 `icon`，不是通用 YAML，不接受数组、对象、别名、表达式或多行值。
- `order` 为 1～9 位非负整数字面量，默认 `1000`；相同顺序按完整条目 ID 排列。
- `icon` 为已注册物品 ID，省略或物品不存在时用书本；不因此阻止阅读。
- 值按字面读取并去除两端空白，不写引号；重复键、未知键、无效值和未闭合文件头属于错误。
- 正文必须有唯一 `# 标题` 且在实际正文块之前；标题决定目录名称和重复页头，不在文件头重复填写。

## 3. 支持的正文语法

| 内容 | 写法 | 行为 |
| --- | --- | --- |
| 条目标题 | `# 仓库管理终端` | 唯一标题，不再占正文高度 |
| 小节标题 | `## 使用方式`、`### 权限` | 最深三级，不强制另起页 |
| 段落 | 普通文字，空行分段 | 同段源码换行合并 |
| 强调 | `**不可恢复**` | 粗体，按实际宽度折行 |
| 短术语 | 行内反引号 | 术语样式，内部按字面处理，可折行 |
| 无序列表 | `- 第一项` | 仅一级列表 |
| 有序列表 | `1. 放置终端` | 第一项决定起始号，后续连续编号 |
| 图片与图注 | `![图注](namespace:textures/handbook/example.png)` | 独占一行，图注在下方，空图注不占高度 |
| 普通提示 | `> 提示内容` | 相邻引用行合并为一个段落 |
| 类型提示 | `> [!NOTE]` / `> [!WARNING]` | 类型行不作为正文，后续引用行是内容 |
| 条目链接 | `[库存保护](entry:cargoverse:player_trade_points/warehouse)` | 只直达目标条目，不记录跳转历史 |
| 强制分页 | `<!-- pagebreak -->` | 独占一行，后续内容转到下一张单页 |
| 作者备注 | `<!-- 备注 -->` | 独占一行，不显示、不参与排版 |

标题标记后必须有空格。列表项可用空行分隔，不支持嵌套、缩进子段落和多块列表项。有序编号源码支持 1～6 位数字，后续项显示值由第一项连续递增。

### 段落换行

```markdown
这两行在源码里分开，
游戏中仍然属于同一个段落。

空行后才是下一段。
```

中文等 CJK 字符相邻时不插入空格；拉丁字母或数字连接时按标点和已有空白补接。不要依靠源码每行长度、行末两个空格、制表符或连续空格模拟版面；不支持 `<br>`。需要分开“标签”和“说明”时，使用不同段落或列表。

### 图片参数

默认图片不需要参数；确有需要时追加：

```markdown
![绑定工具](cargoverse:textures/handbook/linker.png){width=48 max_height=48}
```

- 只支持 `width`、`max_height` 两个正整数参数，可仅写一个，禁止重复键。
- `width` 为最大显示宽度，范围 1～130，默认 130；不是强制拉伸宽度。
- `max_height` 为最大显示高度，范围 1～158，默认 96；图注还会占用实际高度。
- 图片按真实纹理尺寸等比完整显示、水平居中，允许放大小图；不裁边、不变形，不按最大盒高额外留白。
- 图片与完整图注是一个块，不拆到两页；复杂截图应裁出重点或点击放大，不缩小整页文字。
- 目标只接受客户端 PNG 资源 ID，禁止磁盘路径、相对路径、`..`、URL、SVG 和动图。
- 参数是本框架扩展，外部编辑器不保证预览与游戏一致；图片资源应保留足够清晰度，而不是只提供 130px 缩略图。

### 提示框

```markdown
> [!WARNING]
> 销毁库存不会返还货物。
> **该操作不可恢复。**
```

支持普通提示、NOTE、WARNING，未知类型报错。框内只支持段落、强调、行内术语和条目链接，不支持图片、标题、嵌套引用和列表。相邻引用行合并成一个段落，空提示框属于错误。

框本身可放入整页时优先整体换页；超整页时按行拆成带相同类型及“续”标签的多个框，不静默丢字。颜色和边框由统一主题控制，正文不能自定义 HTML 颜色。

### 链接、转义和未支持内容

- 条目链接只接受稳定 ID，不支持外站、页码或标题锚点；显示标题不参与目标查找。
- 缺失链接使用错误样式和提示，禁止点击，制作日志报告来源；它不使其余正文不可读。
- 使用反斜线转义 `\\`、`\*`、`\#`、`\[`、`\]`、`\(`、`\)`、`\!`、`\>`、反引号、`\{` 和 `\}`。
- 不支持表格、斜体、删除线、代码围栏、数学公式、脚注、HTML、脚本、Ponder 指令、绕图、分栏或跨页大图。
- 分页和单行作者备注是明确识别的注释格式，不支持多行或嵌套注释。
- 普通未识别行内符号可能按字面显示；看似标题、列表、图片或文件头但违反规则的块级语法会诊断。不能以“编辑器能显示”为依据使用未支持语法。

## 4. 统一版式

书本逻辑尺寸 `361×256`，左页安全区 `(36,20,130,200)`，右页 `(183,20,130,200)`。下面均为逻辑像素，不是截图物理像素，作者不逐篇填写坐标。

| 区域或项目 | 当前值 |
| --- | --- |
| 每页内容宽度 | 130 |
| 页头 | 高 28，条目标题最多两行 |
| 正文 | 页内 y=28，宽 130，高 158，底边 y=186 |
| 页脚 | y=190，高 10，与正文间隔 4 |
| 页头标题 | 原版字体 1.25 倍，超过两行省略并提供完整悬停提示 |
| 正文、图注、提示内容 | 1.0 倍，不自动缩小，不以省略号裁掉正文 |
| 小节标题 | 1.0 倍粗体 |
| 行高 | `Font.lineHeight + 2`，通常为 11px |
| 段落、列表块、图片块间隔 | 4px，相邻间隔取最大值 |
| 小节标题间隔 | 上 6px、下 4px，页首不加上间隔 |
| 图注间隔 | 3px，空图注不保留 |
| 提示框内边距 | 4px，边框计入占用 |

标题在有效正文页重复，不在奇数末页的空白右页重复。页脚页码和返回图标的唯一规则见[条目阅读](02_六章内容与页面规则.md#条目阅读)。字号、宽度和命中区均按字体测量，不按中文字数猜测。

## 5. 自动分页

1. 段落按字体和可用宽度折行，可跨页；条件允许时页尾与续页至少各留两行。
2. 小节标题尽量与后两行、列表项起始部分或可容纳的图文块同页；连续标题作为链判断，避免页底孤立标题。
3. 列表采用按实际最宽编号测量的悬挂缩进，续行与正文对齐；长项跨页只在首次显示序号，续页使用续行符号。
4. 图片与图注整体移到下一页；整页仍容不下时在声明上限内缩图，图注本身过长则明确报错，不裁字、不无限重试。
5. 提示框片段分别计算边框、标签和内边距；图片不跨书脊，不跨两页。
6. 强制分页是下一张单页：左到右、右到下一跨页左侧。首尾和连续分页不制造无意义空白页，不提供故意保留空页的指令。
7. 新页不保留段前空隙，页尾段后空隙不单独生成新页。超高不可拆块必须报错，分页必须前进。
8. 长词、ID 和长链接必要时按字符簇折行；代理项和组合字符不拆坏，样式和链接命中区随行拆分。

## 6. 内容组织模板

模板约定说明顺序，不要求固定页数。可完整复制的文件见[条目模板](07_百科条目制作模板.md)，先替换示例资源与链接，删除不需要的小节。

| 类型 | 推荐组织 |
| --- | --- |
| 机制说明 | 一句话用途 → 基本概念 → 示意图 → 使用规则 → 注意事项 → 相关条目 |
| 方块或物品 | 用途 → 外观图 → 使用条件 → 操作步骤 → 状态反馈 → 限制、权限与破坏规则 |
| 操作教程 | 操作前提 → 编号步骤 → 局部图与对应说明 → 完成结果 → 常见问题 |

先让内容自动排版，只有明确的阅读需求才加手动分页，不默认拆成一张张固定页面。大型 GUI 适合“总体图 + 局部图 + 步骤”，不依赖一张整屏截图。

## 7. 实现与验收边界

资源生命周期与按需缓存由 `HandbookClient` 管理；`HandbookLibrary` 负责语言及目录；`HandbookMarkdown` 和不可变 `HandbookDocument` 负责内容；`HandbookTextLayout`、`HandbookPaginator`、`HandbookLayout` 负责测量与分页；`HandbookArticleReader` 和 `HandbookReadingState` 负责阅读交互。其他章节不改为 Markdown。

稳定渲染帧不重新解析、折行或分页；资源、语言、字体变化才使缓存失效。正文只读取客户端资源，不访问内容指定的本机文件、不联网、不执行脚本，也不写交易、导航或物理状态。图片按阅读需要测量并验证，不提前解码全库大图；正文与放大层使用同一纹理资源。

超限、缺图、无效链接、错误页和日志预算以[制作流程](05_百科资源与条目制作.md#制作检查)为准。F8 提供页面/块边界、条目 ID 和来源行号。已支持的语法、错误隔离、文字保留、图文分页、链接命中和资源回退有自动测试；真实字体、GUI 缩放与截图可读性仍需游戏内验收。

当前未接入搜索、任务解锁、阅读奖励、联网百科或 Ponder 教程。后续新增能力必须统一修改解析/排版规则和制作文档，不以单篇专用 Java 修补布局。
