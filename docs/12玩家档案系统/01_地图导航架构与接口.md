# 地图导航架构与接口

本节记录手册、公共个人导航会话与载具引导台之间的边界。手册与引导台自带地图共用画布和探索数据，目的地写入按宿主隔离；不提供路径规划、避障或自动到达。

## 职责划分

| 组件 | 职责 |
| --- | --- |
| `PlayerShippingProfileScreen` | 手册生命周期与输入分发，保证收图完成后再翻页 |
| `PlayerShippingProfileMapFoldAnimation` | 折叠贴图锚点、14 帧展开/收起与边框 |
| `PlayerShippingProfileRoutesPage` / `DestinationPage` | 只读航线与目的地展示、按钮绘制和页面内命中 |
| `TradeMapView` | 地图视口、平移、缩放；`focusTradePoint(id)` 居中并打开信息卡 |
| `TradeMapViewHost` | 标识当前前台地图，阻止后台预热抢占贴图焦点 |
| `NavigationGuideMapScreen` / `TradeMapInstrumentSelection` | 每个编辑器独立处理本台目标写入和高亮，不改变个人导航会话 |
| `TradeMapMarkerLayer` / `MarkerInfoPanel` | 标记绘制、选中卡片、悬停、导航/居中/关闭按钮 |
| `TradeMapSelectableMarker` | 结构、贸易点与普通航标的公共身份、名称、坐标和发现信息接口 |
| `TradeMapClientController` | 世界/维度会话，缓存和采样的生命周期，网络更新路由 |
| `TradeMapNavigationSession` | 个人导航目标的选择、解析、替换与清理，不依赖具体地图视图 |

| `PlayerNavigationService` / `NavigationTarget` | 服务端按玩家保存具名目的地会话，提供硬件可复制的世界坐标快照 |
| `NavigationGuideBlockEntity` / `NavigationGuideConfiguration` | 载具硬件独立目标/参数持久化与服务端配置校验，不依赖客户端地图类 |

## 四种互不混用的状态

1. 信息卡选中状态属于当前地图视图，仅决定哪张卡片打开。
2. 地图中心与缩放属于画布；快捷显示和居中可以改变中心，但不设定导航目标。
3. 当前导航目的地属于个人客户端会话，不因卡片关闭或手册销毁而丢失。
4. 引导台目标属于当前方块的具名世界坐标快照，随方块持久化，不跟随手册或地图标记实时变化。

标记引用使用 `(类型, 实例 ID)`。贸易点与结构来自不同存储，不能只用字符串 ID、显示名称或当前位置来混合查找。目标每次读取从当前会话标记库解析，避免长时间保存过时的名称和坐标。

## 当前查询入口

- `TradeMapClient.navigationDestination()`：只读目的地快照，没有目标时返回 `null`。
- `TradeMapClient.navigationDistance(destination)`：按玩家投影后的世界坐标计算水平直线距离。
- `TradeMapClient.potentialRoutes(cargoUnits)`：返回最多三条推荐，包含目的地实例 ID；无已知需求时 ID 为空、`demandKnown=false`。
- `TradeMapView.focusTradePoint(instanceId)`：目标仍在已知库中才居中并打开卡片，找不到返回 `false`；不改变导航目标。
- `TradeMapClient.createInstrumentView(destination, update)`：以目标读取和写入回调创建仪表专用地图视图，不修改个人导航会话。
- `TradeMapView.focusNavigationDestination()`：按当前宿主的目标引用居中并打开信息卡；`centerOnPosition(pos)` 可为未匹配标记的快照提供坐标聚焦。
- `TradeMapClient.clearNavigation()`：仅清除手册个人目标并同步服务端，不删除地图资料，不改写仪表。

目的地名称和坐标是防御性复制的展示数据。上面的地图查询接口位于客户端包，不能在专用服务器或方块服务端 Tick 中调用。手册选择通过 `SetNavigationTargetPacket` 同步名称、维度与坐标到公共 `PlayerNavigationService`，立即同步选择，移动标记的变化最多每秒同步一次；内容不变不重复发包。

## 生命周期和缓存

关闭/重新打开手册、翻页、收图以及服务端档案刷新，保持个人目标。退出世界、切换维度/玩家或已知目标资料不存在时清除；会话关闭同时清除推荐缓存。撤下地图标记不抹除已知资料，因此不会取消导航或影响潜在航线匹配。

推荐航程默认每 20 Tick 刷新，货量快照变化立即重算，贸易标记增删或报价目录更新后使缓存失效。缓存保存不可变货量副本，调用方原地修改 Map 也不会让更新检测失效。游戏时间回退时立即重新计算。

长期档案、客户端地图文件、手册阅读位置和个人目标四者保存范围不同：前两类已有各自持久化流程；后两类当前只在运行中的客户端保存。个人目标尚未写入地图文件或 SavedData。

## 航标显示与知识分离

唯一航标塔沿用 `player_trade_beacon` ID，绑定模式由核心归属决定。关闭广播、破坏或类型转换时，服务器撤下当前显示；客户端将记录标记为隐藏并移出空间索引，不删除已学习资料。恢复广播的增量记录再次显示同一 ID。

贸易点标记包携带 `fullPlayerSnapshot`，首批玩家航标快照协调显示、其余批次追加，不影响自然贸易点。普通航标快照也只协调显示。隐藏集合写入可选缓存尾部，旧缓存无需失效；导航和航线查询使用完整资料库，地图绘制使用可见索引。协议版本为 `50`，服务端共享标记 NBT 版本为 `4`，地图文件格式未因独立编辑器改变。

## 已接入的跨系统边界

客户端目标引用继续使用类型与实例 ID；服务端个人会话只保存玩家自己的具名坐标快照。服务器校验当前维度和世界坐标边界，不允许发包者修改其他玩家目标，但当前不验证“该玩家已经发现此标记”，不能把这项个人输入接口当作贸易点权限或探索授权。

航行引导台属于载具仪表系统。手持手册右键时显式复制 `PlayerNavigationService` 快照到自身 `Destination` NBT，后续个人选择变化不追踪，玩家离线不失效；跨维度不引导。引导台独立保存 PID 配置，历史控制状态只在运行时持有。个人服务在登录、登出、维度切换时清除会话，不写入玩家 SavedData。

空手右键引导台通过 `OpenNavigationGuideMapPacket` 读取当前方块快照并打开独立地图，潜行右键打开 PID 配置。独立地图的双击/导航按钮通过 `UpdateNavigationGuideDestinationPacket` 更新本台快照，清除也只作用本台。该包不经过 `PlayerNavigationService`；手册依旧使用 `SetNavigationTargetPacket`。目标与高亮回调由宿主注入 `TradeMapView`，地图层不直接调用方块实体或控制动力。

`NavigationGuideConfiguration.accessibleGuide` 为打开编辑器、手册写入、客户端关闭判定以及服务端目标/PID 更新共用只读访问规则：相同维度、已加载、正确方块类型、非旁观者和 8 格物理距离；客户端检查不能替代服务端复核。目标更新额外检查目的地维度与世界边界，不加载目的地区块。目的地是坐标输入，不代表探索授权，也不赋予目的地权限。

地图双击使用类型/实例 ID、250ms 间隔与 4 GUI 像素容差；拖动、缩放、空白点击及按钮操作取消待配对状态。目的地左侧高亮属于当前宿主，手册和不同仪表之间不串用。已存仪表快照只在目标变化时扫描已知库匹配高亮；无匹配仍保留目标并可按坐标聚焦。相同目标不重复发包，目的地文字只在目标变化时重建。

服务端控制只读取公共模型和 Sable 运行姿态，不调用 `PlayerShippingProfileScreen`、`TradeMapView` 或 `TradeMapClient`。网络传输、领域配置规则、物理数学与客户端动画分层；具体实现和性能边界见[航行引导台与 PID 控制](../13载具仪表/01_航行引导台与PID控制.md)。

当前 `TradeMapNavigationMarker` 表示唯一航标塔在未绑定模式下的普通命名标记，其同步和缓存与个人“当前目的地”分开。不要把选中个人目标写入公共标记库，也不要直接把客户端探索缓存当作载具控制指令来源。
