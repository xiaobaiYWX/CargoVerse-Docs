# 交付形态与直接运输条件

四种形态为 solid／liquid／gas／living；当前实际物品声明均为 solid。颗粒、粉末不是形态。运输条件直接在物品属性中填写，以下参数保持现有取值，不生成共享条件集。

## 本期生效保护

物品属性 transport_requirements 直接决定需求；清单仅为查阅投影。以下参数为本版统一基线，取代新装载的旧用途类需求；不是在旧需求上叠加。缺少对应保护时允许装载并显示风险。

| 码 | 需求 ID | 明确参数 | 行为 |
| --- | --- | --- | --- |
| V | cargoverse:fragile | speed_delta_threshold=3，loss_count=1 | 沿用物理相邻采样速度变化判定；每次触发损失 1 件，不模拟破碎碎片 |
| D | cargoverse:moisture_proof | loss_interval_ticks=1200，loss_count=1 | 沿用受雨／邻水采样；连续有效暴露 1200 tick 损失 1 件 |
| O | cargoverse:keep_upright | min_up_dot=0.5，loss_interval_ticks=200，loss_count=1 | 沿用姿态判定；连续有效倾斜 200 tick 损失 1 件 |
| I | cargoverse:flammable | 见下表 | 沿用现有热量累计与燃烧损耗，不新增世界爆炸或实体火焰 |

20 tick 约为正常运行下 1 秒；区块卸载／服务器停机不补算。环境／姿态损耗采用现有 CargoAffixRuntime 和调度器：一次有效观察未触发损耗条件即清除该词条未满周期的暴露计时，不跨安全间隔累计；多个不同风险分别计时，扣除量以实际剩余件数封顶。新周期首个物理采样不判冲击，不通过热重载重置已载货的风险状态。

| I 参数 | 固定值 |
| --- | ---: |
| loss_interval_ticks | 200 |
| loss_count | 1 |
| ignition_temperature | 100 |
| sunlight_threshold | 12 |
| sunlight_heat_per_second | 1 |
| hot_biome_temperature_threshold | 1.5 |
| hot_biome_heat_per_second | 1 |
| cold_biome_temperature_threshold | 0.15 |
| cold_biome_cooling_per_second | 1 |
| shade_cooling_per_second | 0.5 |

I 与当前燃料配置一致。燃烧状态和遇水归零沿用现行处理器；触发阈值为现有游戏刻度，不宣称摄氏度。参数中的小数为原接口必需的姿态／群系尺度，不为追求整数而改变判定。

## 后续保护列

| 码 | 后续目标 | 本期确定行为 |
| --- | --- | --- |
| C | 冷藏保鲜 | 不生成 cold_chain 或 time_limit；不腐败 |
| Z | 冷冻保存 | 不生成温控需求；不融化、不扣货 |
| H | 防冻结 | 不生成 cold_proof；不冻结 |
| L | 遮光 | 当前清单无指定对象，不生成 |
| R | 放射性屏蔽 | 当前清单无指定对象，不生成 |

这些条目不是本期实现待办，不能在普通装载 UI 显示为正在生效的风险。后续温控须独立定义维持资源、停供行为、损耗参数后再发布，禁止拿被动词条豁免冒充完整温控。货柜目标矩阵中的冷链能力同样不能提前生效。

## 柜体保护对应

货柜定义使用现有 special_designs 字段保存保护 ID。本期沿用货物需求 ID 与该集合一一对应的机制：防震→fragile、防潮→moisture_proof、定向固定→keep_upright、易燃保护→flammable。多项需求逐项豁免，不额外形成“高级柜全部免疫”。

火药和煤炭均为 solid。火药进入 Silo 可满足 D，I 仍有风险；进入普通 solid 柜同样可装但保留未满足的 D／I。缺少保护的警告必须列出具体 I；不是“不可运输”。

## 数量和质量

单位运输质量已按最新逐 ID 清单落地，只使用 0～1 Kpg 的整数或一位小数，默认 0.1。665 项设计记录为零（含排除项和空气），零质量不改变容量、准入和损耗。新十分位规则使用整数乘件数计量；已有货物保留冻结快照。正式规则与千件对照见[物品运输质量](<../01货柜系统/01核心系统/11_物品运输质量.md>)。
