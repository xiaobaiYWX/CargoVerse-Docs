# 交付形态与运输条件

更新：2026-10-28。形态决定基本装载，运输条件决定什么实际状态会造成损耗，两者分开维护。四种形态为 solid／liquid／gas／living；实际物品声明为 solid，直接泵入的液体使用独立流体数据。颗粒、细粉、易碎品、易腐食品不是新的形态枚举。

## 三层文档入口

能力、运行数值与货物需求分别维护，不在分类统计页重复另一套参数表：

- [货物运输条件](../01货柜系统/02货物运输条件/README.md)：逐物品／流体的需求与损耗，例如碎料、粉料、易挥发、易碎品。
- [货柜能力](../01货柜系统/03货柜能力/README.md)：围护、密封、缓冲、隔热及主动设备等实际响应。
- [货柜核心能力数值](../01货柜系统/04货柜核心数值/README.md)：有效围护／密封、内部温压湿光、速度变化及承载面倾角，各项单独说明来源和公式。

环境及能力先作用于核心数值，货物条件再判断损耗。缓冲提高易碎耐受，速度变化用相隔 10 tick 的相邻向量差；它不依赖加速度或自由落体判断。共同数据规则见[配置协议](../01货柜系统/01核心系统/15_运输类型与参数.md)，未完成内容见[统一清单](../设计草案/待完成事项清单.md#运输条件与能力专项)。

## 查阅表与资源的关系

逐物品属性 JSON 是唯一维护源，新格式为 schema 3 的 `transport_conditions`，现有 schema 2 的 `transport` 为过渡输入；同文件不能叠加两者。不建立共享条件集；价格、许可证经验和贸易点经验仍由交易表维护。

当前玻璃和水有数值代表配置，分别使用 schema 3 速度变化耐受与 schema 2 液密需求。红石粉、鸡蛋、蛋糕与浆果仍待逐内容赋值，不能据例子声称已经批量转换。

分类清单中旧保护字母／需求列不能作为运行效果依据；schema 1 的 `transport_requirements` 不执行旧损耗或生成生效标签。按 ID 检索时须打开 JSON 检查 schema 和实际条件，不能把旧资料机械换算成新等级。

物品形态、质量、准入、贴花与运输条件独立。没有额外条件的普通货物不因柜体缺少制冷或气密而扣货。保护不足通常不禁止装载，组件内容和安全准入仍须独立校验。

## 数量和质量

固体单位为 pcs，液体为 mB；运输损耗直接减少原生整数数量，不使用独立完整度。零质量物品仍占容量并按条件损耗。物品质量继续采用逐 ID 一位小数配置，默认 0.1 Kpg，不随词条重写改变。
