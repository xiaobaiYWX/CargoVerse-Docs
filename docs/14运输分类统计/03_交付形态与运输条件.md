# 交付形态与运输条件

更新：2026-10-26。形态决定基本装载，运输条件决定什么实际状态会造成损耗，两者分开维护。四种形态为 solid／liquid／gas／living；实际物品声明为 solid，直接泵入的液体使用独立流体数据。颗粒、细粉、易碎品、易腐食品不是新的形态枚举。

## 统一对应关系

**环境／运动与货柜能力 → 五组实际内部状态 → 货物条件 → 原生数量损耗；围护和封存保留直接防护比较。** 类型注册不恢复逐 ID 独立免疫或扣量引擎。

| 条件 | 物品数据 | 对应核心数值 | 设计例子 |
| --- | --- | --- | --- |
| 粗料／细粉 | 围护需求 1／2 | 围护等级 | 红石粉按细粉设计时需围护 2 |
| 易渗漏／易挥发 | 液密需求 1／气密需求 2 | 有效密封，必要时结合承压 | 水需液密，不自动要求气密 |
| 易碎品 | `max_velocity_change` 与事件扣量 | 4 tick 速度窗口最大向量差，对比基础耐受＋缓冲增量 | 玻璃基础 10，缓冲加 8 后为 18；超限一事件扣一次 |
| 保持正放 | 倾斜上限与暴露周期 | 内部承载面角度，已运行 | 朝向保持近似正放，但不削减速度变化 |
| 保持干燥 | 湿度上限与暴露周期 | 内部湿度，已运行 | 当前液态水接触不是湿度 |
| 易腐坏 | 保存预算与温区老化速率 | 隔热、调温共同影响的内部温度 | 蛋糕、浆果适温冷藏或寒区装载后保冷 |
| 怕冻／怕热 | 安全温度下限／上限 | 同一内部温度 | 制冷过度也可能伤害食品 |
| 光照要求 | 亮度上限／下限 | 内部实际亮度；上下限均已执行 | 遮光后按需补光，遮光不代表隔热 |
| 气压敏感 | 安全气压范围 | 密封、承压共同影响的内部压力 | 不用固定限高替代压力判断 |

条件协议、字段与可执行示例统一见[类型与参数](../01货柜系统/01核心系统/15_运输类型与参数.md)，未实现行为见[剩余目标](../设计草案/待完成事项清单.md#运输条件与能力专项)。速度窗口、倾角、湿度与光照过程已接入；液水和过渡等级仍服务已有资源，内容迁入时需避免同源双扣。

## 查阅表与资源的关系

逐物品属性 JSON 是唯一维护源，新格式为 schema 3 的 `transport_conditions`，现有 schema 2 的 `transport` 为过渡输入；同文件不能叠加两者。不建立共享条件集；价格、许可证经验和贸易点经验仍由交易表维护。

当前玻璃和水有数值代表配置，分别使用 schema 3 速度变化耐受与 schema 2 液密需求。红石粉、鸡蛋、蛋糕与浆果仍待逐内容赋值，不能据例子声称已经批量转换。

分类清单中旧保护字母／需求列不能作为运行效果依据；schema 1 的 `transport_requirements` 不执行旧损耗或生成生效标签。按 ID 检索时须打开 JSON 检查 schema 和实际条件，不能把旧资料机械换算成新等级。

物品形态、质量、准入、贴花与运输条件独立。没有额外条件的普通货物不因柜体缺少制冷或气密而扣货。保护不足通常不禁止装载，组件内容和安全准入仍须独立校验。

## 数量和质量

固体单位为 pcs，液体为 mB；运输损耗直接减少原生整数数量，不使用独立完整度。零质量物品仍占容量并按条件损耗。物品质量继续采用逐 ID 一位小数配置，默认 0.1 Kpg，不随词条重写改变。
