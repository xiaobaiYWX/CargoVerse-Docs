# 现行实现与待验收

## 当前实现

- 源码四大形态：solid 独立固体、liquid 液体、gas 气体、living 活体；物品与液体闭环已接入。玩家贸易点仓库最多连接 3 组保险库和 5 组普通流体储罐，液体具备原生库存、报价、公共确认装卸和免费管理装卸。
- 2312 份 schema 1 基础属性覆盖所有非空气注册 ID，按所属命名空间／形态／物品路径组织，运输条件直接声明。
- 属性文件是唯一维护源，无成员标签、共享 profile、条件集或默认 JSON。源码默认 solid／0.1 Kpg／standard／无条件／none 贴花。
- 准入为 standard 2114、empty_storage 61、blocked 137；61 个验空 ID 单独登记真实适配，不由属性文件授予未知适配。
- 原有质量和 V／D／O／I 参数保持不变；C／Z／H 不产生假运行行为，气体和活体载荷尚未开放。液体质量与词条由逐流体数据声明，默认每桶 1Kpg。
- decal 声明引用已注册静态贴花，随 schema 3 运输快照保存；物理货柜与型号预览不从形态猜贴花，卸空为 none。
- 客户端仍只同步形态、准入与风险元数据，协议 69；快照与配置失败均保留安全边界。
- 物品悬停不显示分类及默认来源，仅在佩戴护目镜时显示“无法装载”“仅允许空容器”和必要的运输词条；无需求普通物品不增加提示。

## 货柜与模板

45 款物品型号使用最终实际结构。Boreal、Silo 也允许 solid，不再将颗粒或粉末作为独立分类。Silo 三款、Reliquary 两款暂仅测试投放；4 款液体柜已开放基础业务和测试制造，使用同规格 AUI 占位结构，M/L 暂定 120000/240000mB；另 15 款专项未开放制造。液体专用结构与最终容量仍待平衡。

## 待完成与验收

当前物品运输属性与提示整理、基础液体运输已完成，可继续液体内容深化和气体、生物专项设计。物品条件的进一步平衡、正式自然站的实际物品报价、客户端视觉、满柜运力与多人性能仍需独立完成，不作为新专项已完成的前提或证明。

后续顺序以[专项总边界](<../设计草案/运输专项推进边界.md>)为准；[液体运输](<../设计草案/液体运输首版设计.md>)基础载荷／装卸／交易已实现，待专用结构、内容平衡及实机验收，[气体运输](<../设计草案/气体运输首版设计.md>)和[生物运输](<../设计草案/生物运输首版设计.md>)尚未实施。气体草案已明确 c:gaseous 识别和标准流体接口复用，但未开放气体载荷、压力模拟或 Boreas 制造；温控能源与任意第三方兼容不自动纳入首版。

验证使用只读 `node tools/verify-item-properties.cjs` 及受影响的规则、准入、快照和真实注册测试；自动回归不等于实机视觉或运力验收。

独立待核验问题：货轨滑车中段捕获的世界测试存在间歇失败，尚不能将整轮世界回归视为稳定全通过；不通过修改本轮运输属性来掩盖该问题。
