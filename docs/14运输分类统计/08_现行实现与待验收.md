# 现行实现与待验收

## 当前实现

- 源码四大形态：solid 独立固体、liquid 液体、gas 气体、living 活体；物品与液体闭环已接入。玩家贸易点仓库最多连接 3 组保险库和 5 组普通流体储罐，液体具备原生库存、报价、公共确认装卸和免费管理装卸。
- 2315 份基础属性按命名空间／形态／物品路径组织：2304 份 schema 1、0 份 schema 2，11 份 schema 3（玻璃与 10 个新警示贴花物品）。源码支持 schema 3 的注册条件，但绝大部分内容尚未迁入，不能将基础属性覆盖等同于运输需求已经逐项赋值。
- 属性文件是唯一维护源，无成员标签、共享 profile、条件集或默认 JSON。源码默认 solid／0.1 Kpg／standard／无条件／none 贴花。
- 准入为 standard 2117、empty_storage 61、blocked 137；61 个验空 ID 单独登记真实适配，不由属性文件授予未知适配。
- 原有质量和准入保持不变；旧 V／D／O／I 资料不再运行或产生标签。条件、货柜能力、五组内部状态及损耗分层，能力响应与物理演化分别处理。13 种条件／11 种能力已有参数协议，全部可执行；湿度、有限交换、温压湿自动控制、补光、速度窗口事件、正放及朝向保持已接通，独立操作界面仍待接入。气体和活体载荷未开放，缺定义液体默认每桶 1Kpg。
- decal 声明引用已注册静态贴花，随 schema 3 运输快照保存；物理货柜与型号预览不从形态猜贴花，卸空为 none。
- 客户端同步形态、准入与含冷冻运输名称的数值特性的有界元数据，协议 77；不重复发送整套派生数据。13 种条件与 10 种能力共用 GUI 图集，承压能力仍使用铁锭占位；世界条件贴花使用独立 PNG。图标不代表所有内容已赋值。
- 物品悬停不显示分类及默认来源，仅在佩戴护目镜时显示“无法装载”“仅允许空容器”和必要的运输词条；无需求普通物品不增加提示。

## 货柜与模板

45 款物品型号使用最终实际结构。Boreal、Silo 也允许 solid，不再将颗粒或粉末作为独立分类。Silo 三款、Reliquary 两款暂仅测试投放；4 款液体柜已开放基础业务和测试制造，使用同规格 AUI 占位结构，M/L 暂定 120000/240000mB；另 15 款专项未开放制造。液体专用结构与最终容量仍待平衡。

## 待完成与验收

当前整体完成度、资源数量和代码接入范围统一见[运行时](../01货柜系统/01核心系统/14_运输数值运行时.md)。未完成核心和内容应用只在[待完成事项清单](../设计草案/待完成事项清单.md#运输条件与能力专项)维护；红石粉、鸡蛋、蛋糕、浆果仍未正式赋新参数，详细设置 GUI、客户端视觉、真实路线和多人负载不能以基础装卸通过替代。

后续顺序以[专项总边界](<../设计草案/待完成事项清单.md>)为准；[液体运输](<../设计草案/待完成事项清单.md#液体深化>)基础载荷／装卸／交易已实现，待专用结构、内容平衡及实机验收，[气体运输](<../设计草案/待完成事项清单.md#气体专项>)和[生物运输](<../设计草案/待完成事项清单.md#生物专项>)尚未实施。气体草案已明确 c:gaseous 识别和流体接口复用；共用内部压力求值已实现，但气体实际载荷和 Boreas 制造未开放，不能将两者混称。温控能源与任意第三方兼容不自动纳入首版。
