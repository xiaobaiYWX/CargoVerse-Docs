# 基础属性、冻结快照与发布契约

更新：2026-10-28。文件定义、运行会话与网络版本分别维护，不用旧“词条豁免”字段代替现行数值规则。

## 单一维护入口

逐物品属性位于 `data/<命名空间>/cargoverse_item_properties/<form>/<物品路径>.json`。质量、形态、准入、贴花及运输条件在该文件维护。新注册格式为 schema 3 的 `transport_conditions`，与旧 `transport`／需求数组互斥；玻璃及新增警示贴花物品已用 schema 3；当前分布见[现行实现](08_现行实现与待验收.md)。流体采用独立属性目录。完整协议见[类型与参数](../01货柜系统/01核心系统/15_运输类型与参数.md)。

同一路径按数据包优先级覆盖；不同目录重复声明、目录／form 不一致、未知物品、错误参数和无效贴花均拒绝整代。缺失文件才用源码默认，错误文件不能降级为默认。发布失败保留上一完整代。

## 数据分层

| 数据 | 职责 |
| --- | --- |
| ItemPropertyDefinition／FluidPropertyDefinition | 路径身份、形态、准入、质量、贴花及物品／流体条件 |
| ItemTransportRules | 一次编译为物品 ID 直接查询，无标签扫描或条件集合并 |
| TransportTypes／TransportConfiguration | 源码类型、强类型参数、语义冲突校验及统一编译；未接入类型实际编译报错 |
| CargoContainerDefinition／TransportCapabilities | 当前已支持的直接防护、调节能力与调温约束，不限制新设计的能力数量 |
| TransportSnapshot | 冻结物品条件、货柜能力、调温约束与完整换算表 |
| TransportAbilityResponse／TransportDynamics | 分别负责能力响应和现有物理路径演化，不直接扣库存 |
| TransportSession／TransportState／TransportInteriorState | 五组内部状态、工作设置、年龄、暴露余数与事件去重；保存环境和累计倾角暴露，瞬时读数恢复为未知 |
| TransportEvaluator | 实际状态对照条件，生成风险和原生数量扣量提案 |
| CargoContentCodec | 按真实介质编解码；未知或损坏内容保留原文隔离 |
| TransportPresentation／ItemCargoClassifications | 只读解释和有界元数据，不运行另一套损耗 |

## 冻结与失败边界

首次成功的正数装载冻结规则；途中重载不改写。追加必须兼容冻结规则，继承温度、年龄和余数，不能刷新寿命。卸空清会话，保留货柜及工作设置。温度与压力未知时不伪造初始化值。

声明贴花也被冻结；资源无法解析时显示 none，不因此丢弃货物。原生 ItemStack／FluidStack 卸出不附加全世界腐败组件。

开发阶段不迁移旧运输状态。旧格式、未知或坏会话保留 Load 原文隔离，不当空柜覆盖，不允许在隔离内容上重新装货；恢复有效新会话时只重建观测基线，不补算停机时段。

版本统一在[当前数据契约](../01货柜系统/01核心系统/07_运行时与存档.md#当前数据契约)维护。条目保存实例展示／质量锚点布局，旧条目不迁移；温压及已知湿度保存，光照、机械读数与连续基线重建，无法解码的载荷原文隔离。运行链路见[运输数值运行时](../01货柜系统/01核心系统/14_运输数值运行时.md)。
