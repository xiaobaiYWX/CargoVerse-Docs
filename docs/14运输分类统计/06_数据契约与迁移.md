# 基础属性、冻结快照与发布契约

## 单一维护入口

基础属性 schema 1，路径为 `data/<物品命名空间>/cargoverse_item_properties/<form>/<物品路径>.json`。质量、四大形态、准入、贴花及直接运输条件在这一文件维护，不再发布 item_transport_profiles、成员标签或运输条件集。完整格式见[属性定义](<../10数据包定义与模板/01_物品运输/README.md>)。

同一路径按数据包优先级覆盖；同一物品从不同目录产生两份声明时拒绝整代。目录与 form 不一致、未知物品、错误字段、错误质量／损耗参数和无效贴花均不能静默回退。缺失文件才使用源码默认，不把畸形文件当作缺失文件。

## 当前与冻结数据

| 数据 | 当前职责 |
| --- | --- |
| ItemPropertyDefinition | 逐物品解析、路径身份与字段校验 |
| ItemTransportRules | 编译一次成为物品 ID 直接查询表；无标签扫描、继承或条件集合并 |
| CargoDataReloadListener | 与贸易、制造和注册配置协调原子发布；失败保留上一完整代 |
| ItemTransportSnapshot | schema 3 冻结质量、形态、条件、准入及 decal，比较包含贴花 |
| CargoContentCodec / ItemCargoLoadCodec | 内容封套按介质分发；目前仅注册真实物品，保存完整身份和冻结规则；损坏或缺内容时保留整包原文隔离 |
| ItemCargoClassifications | 发送界面筛选所需形态及提示所需准入／风险位，完整后原子替换；物品悬停不绘制形态 |

源码默认是 solid／0.1 Kpg／standard／无条件／cargoverse:decal_none。四大形态均使用字符串 ID；NONE 只表示空状态。新装载不接受 bulk、powder 或用途类。当前物品载荷管线拒绝将 liquid／gas／living 声明当作对应内容已实现。

## 存量与失败边界

已装货保持冻结规则和原物品组件；快照 schema 1／2 仍可恢复和卸出，但不能按新规则追加。不用删枚举或重新解释原物品来强制清档。空柜需要升级时先提出方案，仅成功装载才与新载荷一起保存；失败不更改实例身份或资产。

新快照还冻结声明贴花；热重载更改 decal 不重写途中外观。坏的或未知贴花引用不能作为有效新配置发布。已冻结引用因资源移除无法解析时显示 none，不因此丢失货物。

货柜根版本 5、实例格式 10、内容封套 1、物品载荷包络 2、液体载荷包络 1、贸易经济 15；网络协议 69。开发期不迁移旧实例条目，测试货柜需重建。时钟字段使用原生 `AmountPerInterval`；物品计时行为不变。文件 schema 与运输快照 schema 分别维护，不因字段同名联动修改交易格式。当前已拆分的共用边界见[多类型载荷与计量](../01货柜系统/01核心系统/12_多类型载荷与计量.md)。
