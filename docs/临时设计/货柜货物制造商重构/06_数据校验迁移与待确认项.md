> 分类重构补充：本文涉及的旧 CargoType、cargo_materials、单层货物 ID 与旧存档版本，以 [CargoClass / CargoGood 二级分类重构](16_货物二级分类重构.md) 为准；其余设计及历史记录保留。

> 第一版已经实现固定货物集合、引用、数值、词条 ID、组合词条上限和原子发布校验；装卸行为与统一存档迁移框架也已落地。实际历史世界迁移验证和词条参数合并仍需继续完成。

## 1. 货物定义校验

数据加载时必须验证：

- 20 个固定货物定义全部存在。
- 不存在 `none` 货物定义。
- 不存在集合之外的额外货物 ID。
- 单位质量、经验和完整度是有限数字并符合取值范围。
- 基础价值为非负整数。
- 运输要求不超过 5 项。
- 运输要求 ID 不重复且对应已注册词条处理器。
- 运输要求参数能被对应词条完整解析。

## 2. 货柜容器定义校验

数据加载时必须验证：

- 结构模板 ID 合法。
- 制造商引用存在。
- 规格和接口类型属于固定集合。
- 容量、空质量、耐久、基准价值和持有上限符合取值范围。
- `allowed_cargo` 中的所有货物引用存在且不重复。
- `special_designs` 中的词条 ID 合法且不重复。
- `design_defects` 中的词条定义合法且不重复。
- 货柜与其每个可用货物组合解析后，最终词条数不超过 5。
- 应用制造商修正后的数值不会溢出或变为非有限数。

结构模板是否真实存在可能需要服务端资源管理器，如果无法在 JSON 重载阶段验证，至少必须在服务器启动或首次使用前统一报告。

## 3. 制造商定义校验

数据加载时必须验证：

- `code` 不为空，并在最终制造商集合中唯一。
- 所有容器数值倍率都是有限非负数。
- `cargo_modifiers` 只引用固定货物 ID。
- 制造商特殊设计和设计缺陷使用已注册词条。
- 声望阶段 ID 不重复。
- 声望阶段阈值按从小到大的顺序严格递增。

## 4. 数据重载不变量

新定义集合生效后：

- 新购买或生成的货柜使用新定义。
- 新装载的货物使用新货物定义。
- 已有货柜保留其容器快照。
- 已装载货物保留其货物和词条快照。
- 玩家当前制造商声望属于运行时状态，不因数据重载清空。
- 贸易点当前库存和动态经济不因数据重载清空，除非存档版本迁移明确要求重建。

## 5. 从旧体系迁移的数值问题

现有货物常数是“货物类型基础值 × 货柜等级倍率”模型，不能将其原样写入新的每单位字段。

建议使用旧 S 级货柜作为初始标尺：

```text
新单位质量候选值 =
旧 S 级货物质量 ÷ 旧 S 级 cargo_units

新单位价值候选值 =
选定的旧 S 级价格锚点 ÷ 旧 S 级 cargo_units

新单位经验候选值 =
旧 S 级经验 ÷ 旧 S 级 cargo_units
```

这些只是初始换算标尺。旧系统中各等级的价格、质量和经验倍率并不与 `cargo_units` 严格成比例，因此仍然需要完整经济重新平衡。

## 6. 开发存档迁移建议

这一部分已按统一存档框架落地，当前实现边界为：

- 优先保留玩家已有货柜物理结构和归属。
- 旧货柜定义 ID 通过显式迁移表映射到新货柜容器 ID。
- 旧 CargoType 作为新的货物 ID，旧 `cargo_units` 作为初始装载数量。
- 旧完整度迁移到 `CargoLoad.integrity`，不迁移为货柜耐久。
- 旧实例没有容器耐久数据，迁移后初始化为新型号的最大耐久。
- 贸易点旧 CargoType 库存可以直接对应新的固定货物 ID，但旧库存规模是否保留需在数值平衡后决定。
- 开发阶段不保证迁移早于实际测试范围的历史存档。

具体存档节点、迁移触发条件和兼容层见[统一货柜存档框架实现映射](11_统一货柜存档框架实现映射.md)。

## 7. 待确认的业务规则

以下项目不阻止三类数据定义成型，但在实现完整交易流程前必须另行定案：

- 货柜耐久的损伤来源、修理成本、报废和拆解规则。
- 部分卸货时完整度、来源和限时词条状态如何分配。
- 不同快照版本、不同来源价格的同类货物是否可以合并。
- 货物完整度为零时的报废、廉价收购或特殊处理流程。
- 空柜购买、制造、二手出售和退役的终端与价格规则。
- 运输许可证限制是作用于货柜规格、货物类型，还是同时作用于两者。
- 同一贸易点原地装卸是完全禁止，还是仅不发放经验和繁荣度。
- 市场 `ask_multiplier` 和 `bid_multiplier` 的默认值与动态变化方式。
- 制造商声望的作用范围、状态存档、获取来源和阶段效果。

## 8. 实现前的最小验收集

数据层实现至少需要以下测试：

1. 20 个固定货物的完整加载与缺失拒绝测试。
2. 非固定货物 ID 的拒绝测试。
3. 制造商倍率、专用货物容量和货柜最终参数解析测试。
4. 货柜引用缺失制造商或货物时的拒绝测试。
5. 货物要求、制造商保护、货柜保护和两层缺陷的解析顺序测试。
6. 重复词条伤害参数叠加与最终五词条上限测试。
7. 同类货物数量加权完整度合并测试。
8. 不同货物无法同时装入同一货柜的测试。
9. 装货、追加、部分卸货和卸空后的质量计算测试。
10. 数据包重载不改变已有容器和装载快照的测试。
