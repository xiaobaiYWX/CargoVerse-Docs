## 1. 定位

货柜容器定义描述一种可由玩家长期持有的物流设备型号。它从现有 `cargo_definitions` 重构而来，但不再保存货物价值、货物单位质量、货物经验或当前装载状态。

货柜容器定义负责：

- 物理结构模板和显示信息。
- 归属制造商。
- 规格。
- 制造该型号时使用的交易货币组。
- 单个玩家的型号持有上限。
- 空柜基础价值。
- 标称容量、空质量和最大耐久。
- 可装载货物白名单。
- 型号自身的特殊设计和设计缺陷。

## 2. 文件位置

```text
data/<namespace>/cargo_containers/<path>.json
```

示例：

```text
data/cargoverse/cargo_containers/aui/atlas_sd_m.json
    → cargoverse:aui/atlas_sd_m
```

## 3. 完整示例

```json
{
  "schema_version": 1,
  "template": "cargoverse:cargo/aui/atlas/aui_atlas_sd_m",
  "manufacturer": "cargoverse:aui",
  "display_name": "AUI Atlas 标准货柜 M 型",
  "description": "Atlas 系列主力型号，在容量、重量和通用性之间取得平衡。",
  "size_class": "M",
  "trade_currency": "cargoverse:enderite",
  "max_owned": 3,
  "base_value": 800,
  "capacity": 20,
  "empty_mass": 45.0,
  "max_durability": 100.0,
  "allowed_cargo": [
    "cargoverse:ore",
    "cargoverse:wood",
    "cargoverse:component"
  ],
  "special_designs": [
    "cargoverse:moisture_proof"
  ],
  "design_defects": [],
  "tags": [
    "general_purpose"
  ]
}
```

上述数值只用于说明格式，不代表最终平衡数值。

## 4. 字段说明

| 字段                | 类型        | 必填  | 约束                  | 说明                  |
| ----------------- | --------- | :-: | ------------------- | ------------------- |
| `schema_version`  | 整数        |  是  | 当前为 `1`             | 货柜容器定义格式版本。         |
| `template`        | 资源 ID     |  是  | 必须指向可用结构模板          | 容器物理结构。             |
| `manufacturer`    | 资源 ID     |  是  | 必须存在对应制造商定义         | 型号归属的制造商。           |
| `display_name`    | 字符串       |  是  | 直接文本                | 容器在 UI 中的名称。        |
| `description`     | 字符串       |  否  | 默认为空                | 型号定位、用途和世界观描述。      |
| `size_class`      | 字符串       |  是  | `S/M/L/X/XL/SP`     | 规格、许可证限制和排序分类。      |
| `trade_currency`  | 资源 ID     |  是  | 必须指向已加载的货币组          | 购买空货柜时使用的交易货币组。     |
| `max_owned`       | 整数        |  是  | `>= 1`              | 玩家同时拥有的该型号容器上限。     |
| `base_value`      | 整数        |  是  | `>= 0`              | 空柜基准价值，不包含内部货物。     |
| `capacity`        | 整数        |  是  | `>= 0`              | 未应用制造商修正前的标称货物单位容量。 |
| `empty_mass`      | 数字        |  是  | 有限且 `>= 0`          | 未应用制造商修正前的空柜目标质量。   |
| `max_durability`  | 数字        |  是  | 有限且 `> 0`           | 未应用制造商修正前的货柜资产最大耐久。 |
| `allowed_cargo`   | 资源 ID 数组  |  是  | 不得重复                | 可装载的货物白名单。          |
| `special_designs` | 词条 ID 数组  |  否  | 默认 `[]`             | 该型号可以消除的运输要求。       |
| `design_defects`  | 词条对象数组    |  否  | 默认 `[]`             | 该型号会对所有货物附加或加重的限制。  |
| `tags`            | 字符串数组     |  否  | 默认 `[]`             | 用于搜索、分类和未来扩展的非权威标签。 |

## 5. 规格与容量

`size_class` 不再直接决定货物价值、货物质量或交付经验。它仅负责：

- 货柜规格显示。
- 运输许可证的购买和使用限制。
- 列表排序和内容设计分类。
- 在策划层约束容量、体积和结构规模，但不在运行时覆盖型号的 `capacity`。

型号的标称容量由 `capacity` 明确声明。某货物的最终容量由制造商特性进一步修正。

货柜定义和运行时快照均不保存接口类型。现有型号 ID 中的 `sd`、`mc` 等片段只保留为策划命名与显示习惯，加载器不会读取、推导或校验这些片段。

## 6. 交易货币

`trade_currency` 必须引用数据包 `data/<namespace>/currency_groups/<path>.json` 中成功加载的货币组。例如：

```json
{
  "trade_currency": "cargoverse:enderite"
}
```

- 不能在此字段直接填写普通物品 ID。
- 货币组缺失或定义无效时，引用它的整套货柜数据不会生效。
- 货柜搭建台的价格预览、扣款和制造快照统一使用该货币组。

## 7. 空质量与总质量

`empty_mass` 是数据层的空柜目标质量。实际物理结构可能已经比目标值更重，因此：

```text
最终空柜质量 =
max(结构实际质量, 制造商修正后的 empty_mass)
```

装载后：

```text
货柜总质量 =
最终空柜质量
+ 货物 unit_mass × 当前数量
```

制造商的空质量修正只影响容器空重，不得改变货物定义的 `unit_mass`。

## 8. 可用货物列表

`allowed_cargo` 是货柜能否装载某货物的唯一白名单来源。

- 制造商货物修正不能为货柜增加白名单外的货物。
- 空列表表示该容器不能装载任何普通货物，不得解释为允许全部。
- 无效货物 ID 会使整个货柜定义加载失败。
- 同一个货物 ID 不得重复。

## 9. 耐久与货物完整度

`max_durability` 表示容器资产自身的结构耐久，不是货物完整度。

```text
货柜耐久
    └─ 跟随货柜资产长期保存，卸货后不恢复

货物完整度
    └─ 跟随当前 CargoLoad，卸货或报废货物后消失
```

货物完整度归零不会直接删除货柜或将货柜标记为永久失效。货柜耐久归零后的维修、报废和拆解规则留待资产系统设计。

## 10. 特殊设计和设计缺陷

特殊设计只保存能被消除的词条 ID：

```json
{
  "special_designs": [
    "cargoverse:fragile"
  ]
}
```

设计缺陷保存完整词条参数：

```json
{
  "design_defects": [
    {
      "id": "cargoverse:fragile",
      "speed_delta_threshold": 10.0,
      "damage_amount": 5.0
    }
  ]
}
```

设计缺陷对所有允许货物生效。若缺陷与货物运输要求使用同一 ID，由该词条的专用合并规则叠加严重度，不在运行时保存两个重复 ID。
