## 1. 终端职责

货柜容器相关操作拆分为两个独立终端：

- **货柜搭建台**：负责制造与回收货柜。本阶段承接原空货柜购买流程，已经能够制造空货柜；回收流程仅保留为后续职责，尚未实现。
- **货柜机械台**：负责维修、改装与清理货柜。本阶段只注册占位方块和物品，尚无方块实体、菜单或业务界面。

原 `cargoverse:buy_terminal` 不再保留，现有制造入口及其方块实体、菜单、界面和网络协议统一迁移到 `cargoverse:cargo_assembly_terminal`。新的占位终端使用 `cargoverse:cargo_machinery_terminal`，两者不会再因名称或资源 ID 混用。

## 2. 货柜制造报价

搭建台为每个 `CargoContainerDefinition` 建立一个设备报价：

```text
制造价格 = 货柜 base_value × 制造商 value_multiplier
空柜质量 = 货柜 empty_mass × 制造商 empty_mass_multiplier
基础容量 = floor(货柜 capacity × 制造商 capacity_multiplier)
最大耐久 = 货柜 max_durability × 制造商 durability_multiplier
```

货物专属容量倍率不参与空柜报价。制造价格的预览和扣款直接使用货柜容器定义中的 `trade_currency`，该字段必须引用已加载的货币组。

## 3. 制造与生成

制造请求在服务端重新检查终端绑定、货柜定义、运输许可、最大持有数量、货币有效性、玩家余额和生成区域占用。付款使用可退款回执；只有物理结构成功生成并装配后才完成付款。

新实例具有以下初始状态：

- 运行时定义 ID 为货柜容器定义 ID。
- 不存在货物装载数据，货物数量为 `0t`。
- 无货物词条、无货物完整度。
- 物理质量为制造商修正后的空柜质量。
- 归当前制造玩家所有，可被货物装载终端扫描并装货。

设备制造会计入贸易点交易额和交易次数，但不会增减任何货物库存，也不会改写任一货物的供需数量和价格统计。

## 4. GUI 与资源边界

搭建台沿用原出售终端的三栏界面和管理员生成偏移设置：

- 左侧显示空货柜的规格、基础容量、空重、最大耐久与制造价格。
- 中间显示货柜模型和货柜描述。
- 右侧显示所有可制造货柜型号。
- 原中间下方“可出售货物类型”板块已删除，模型区域扩展到原板块位置。

搭建台显示的容量是未指定货物时的基础容量。装入具体货物后，最终容量仍由货物装载终端按“货柜 + 制造商 + 货物”组合重新解析。

机械台当前临时复用搭建台模型，仅用于占位辨认。玩家交互时会提示维修、改装与清理功能尚未开放；在专用交互设计完成前不会创建方块实体或菜单。

## 5. 无兼容切换

- `buy_terminal` 方块、物品、方块实体、菜单、界面翻译命名空间、网络协议 ID 和资源文件均已删除或更名，不提供旧存档兼容别名。
- Java 内部仍保留部分 `CargoSpawner` 类名，它们描述现有制造与结构生成实现，不属于资源 ID，也不会把搭建台重新解释为机械台。
- 当前数据集中的 52 个货柜型号会从 `cargo_containers` 自动加入搭建台列表。
- 货柜耐久已经进入统一货柜存档；货物装载后的完整度仍只表示货物完整度。
- 空柜贴花使用 `none` 解析，装卸后的物理贴花原位刷新仍属于后续工作。
