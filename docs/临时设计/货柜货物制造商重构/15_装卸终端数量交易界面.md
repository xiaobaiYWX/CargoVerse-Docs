## 1. 统一界面结构

装载终端和装卸终端共用三栏布局：

所有玩家可见的货物数量统一使用小写 `t`：一个货物单位显示为 `1t`，库存区间显示为 `40/500t`，装卸预演显示为 `+10t` 或 `-10t`。该缩写同样用于贸易点库存、货柜容量、终端详情和交易反馈。

```text
左侧                         中间                         右侧
├─ 贸易点货物库存            ├─ 无背景货柜结构预览         └─ 扫描范围内全部货柜
│  └─ 货物图标 + 库存进度条   ├─ 当前数值与交易后变化          ├─ 名称与耐久
└─ 当前货物详细信息          ├─ 交易数量输入栏                └─ 当前货物图标
   ├─ 当前单价               ├─ 装载/卸载按钮
   ├─ 相对基础市场价         └─ 本次交易总价
   ├─ 单位质量
   └─ 运输要求图标
```

库存进度条复用项目现有 `SolidProgressBar`，货物图标复用 `TradePointCargoIconRenderer`，运输要求复用货物词条图标渲染。右侧货柜中的货物只显示图标，鼠标悬停时显示货物名称。

装载与卸载界面的固定尺寸、面板坐标、库存行渲染、货物详情和格式化逻辑集中在 `CargoTransferScreenSupport`，避免两个界面继续分别演化。

界面直接采用与贸易点终端相同的 `413×233` 逻辑画布，并以 Minecraft GUI 尺寸 `5x` 作为制作与验收基准。终端不读取当前 GUI 倍率，也不执行运行时自动缩放；面板、结构预览、按钮、输入框、图标、列表行距和鼠标命中区全部直接按该画布坐标绘制。

中部结构预览使用接近整个中栏宽度的固定安全区域。以 GUI 尺寸 `5x` 验收时，模型本体相对初版累计上移 `20px`（逻辑坐标 `4px`），并放大 `20%`；安全区域顶部和左右边界不动，底部向下扩展 `25px`（逻辑坐标 `5px`）。容量、质量、完整度和耐久信息统一排列在预览下方。底部压缩为两行：第一行显示总价或当前交易状态，第二行并排显示交易按钮和数量输入框，按钮与输入框下沿同左右面板底边对齐。总价、条件提示、处理中及成功/失败反馈共享同一基线，并整体向下移动 `10px`（逻辑坐标 `2px`）。“交易数量”只作为输入框的低显提示，不再占用独立标签行。数量为空或为零时第一行显示“总价：0”，不提前显示库存、容量或数量错误；输入正数后才显示对应校验结果。

左上库存面板不再绘制额外标题，完整高度用于五行货物库存，并响应鼠标滚轮；左侧始终显示纵向滚动槽，直接复用 Minecraft 原版 `widget/scroller_background` 与 `widget/scroller` GUI 精灵。滚动条压缩为 `4px` 逻辑宽度，滑块保持原版固定 `32px` 逻辑高度；列表没有溢出时滑块停留在顶部，存在溢出时才沿轨道移动，不再把滑块拉伸成整条白色轨道。选中底色限制在滚动条后的内容区和面板内边缘之间，不覆盖滚动条，也不溢出右侧边框。尚未选择货柜或库存项不可交易时，库存行使用与面板一致的淡显进度槽并整体降亮度，不再保留突出的黑色槽底。左下详情不重复显示已由图标和选择状态表达的货物名称；单价不再用括号包裹货币名，单位质量显示为“质量：数值/t”，单价、较市场价、单位质量和运输要求按最小 `11px` 基线间距统一排列，其中“较基础市场价”缩写为“较市场价”，运输词条图标与文字起始位置左对齐。词条图标使用界面本地鼠标坐标判定，悬停时显示具体词条名称。右侧不再绘制“区域货柜”标题，列表直接从面板顶部内边距开始，可同时显示七个货柜条目，并同样始终在左侧显示原版纵向滚动槽；空货柜显示空载图标，已装货柜显示对应货物图标，图标在为原版滚动槽让出空间后仍向左收回，避免贴近面板右边框。

## 2. 选择顺序和禁用规则

交互顺序为：

1. 在右侧选择扫描到的货柜。
2. 在左侧选择可交易货物库存。
3. 输入交易数量并查看预演。
4. 点击装载或卸载按钮提交服务器事务。

装载端会根据当前货柜重新计算每种产出货物的可选状态。货柜不兼容、已经装有其他货物、货柜已满、贸易点无库存、繁荣度不足或货币定义无效时，对应库存行显示为禁用且不能选中。

卸载端只允许选中与当前货柜货物匹配、已解锁且尚未达到库存上限的消耗库存。右侧货柜列表始终保留扫描到的货柜，不因贸易点是否需求其货物而过滤；不能交易时只禁用交易动作并显示具体原因。

## 3. 数量预演

输入框只改变客户端预演，不直接修改货柜或贸易点库存。预演显示：

- 货柜当前装载量与本次增减单位数；
- 货柜当前总质量与本次质量增减；
- 货物当前完整度及装载后的混合完整度变化，或卸空结果；
- 货柜耐久；
- 按当前贸易点价格修正和货物完整度计算出的总价。

贸易点单价使用 `货物基础价值 × 当前市场修正`。相对基础市场价的百分比由市场修正计算，上涨显示红色，下跌显示绿色。

## 4. 数量裁剪与超载

数量规则由客户端预演和服务器事务共同调用 `CargoTransactionQuantity`：

```text
装载有效数量 = min(输入数量, 贸易点剩余产出库存)
装载超载     = 装载有效数量 > 货柜剩余容量

卸载有效数量 = min(输入数量, 货柜现有数量, 贸易点剩余消耗容量)
```

装载输入超过贸易点库存时，按剩余库存全部计算。经过库存裁剪后的数量仍超过货柜剩余容量时，界面显示“+超载”并禁用装载按钮；不会自动裁剪到货柜容量，因为那会隐藏玩家输入造成的超载。

卸载数量允许按贸易点剩余容量自动裁剪，因此不再要求整柜一次性卖出。

## 5. 服务器事务

两个交易数据包都携带玩家输入的单位数。服务器收到请求后重新执行扫描、所有权、货物兼容、贸易点库存、繁荣度、货币和数量校验，客户端预演不是可信交易依据。

装载成功后只增加实际单位数，按实际单位数扣除贸易点产出库存和玩家货币，并重算货柜质量与混合完整度。卸载成功后只移除实际单位数，按实际单位数和完整度支付货币、结算经验并增加贸易点消耗库存；剩余货物继续保留原装载快照与运行状态。
