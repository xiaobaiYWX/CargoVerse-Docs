## 1. 定位

制造商定义将目前仅存在于名称、描述和贴花中的制造商转换为正式数据对象。

制造商定义不只服务于货柜系统。当后续引入制造商商店、设备、合同、声望和其他内容时，继续在同一制造商定义下增加具有明确作用域的子结构。

## 2. 文件位置

```text
data/<namespace>/manufacturers/<path>.json
```

示例：

```text
data/cargoverse/manufacturers/aui.json
    → cargoverse:aui
```

现有内置制造商：

```text
cargoverse:aui
cargoverse:spl
cargoverse:dmc
cargoverse:vbs
cargoverse:hec
cargoverse:hri
cargoverse:bds
cargoverse:rex
```

制造商定义与货物定义不同，不限制为上述八个固定 ID。数据包可以添加新制造商，但只有被其他定义引用时才产生实际内容。

## 3. 完整示例

```json
{
  "schema_version": 1,
  "code": "AUI",
  "display_name": {
    "translate": "manufacturer.cargoverse.aui"
  },
  "description": {
    "translate": "manufacturer.cargoverse.aui.description"
  },
  "container_traits": {
    "capacity_multiplier": 1.1,
    "empty_mass_multiplier": 1.0,
    "durability_multiplier": 1.0,
    "value_multiplier": 1.0,
    "cargo_modifiers": {
      "cargoverse:ore": {
        "capacity_multiplier": 1.0
      }
    },
    "special_designs": [],
    "design_defects": []
  },
  "reputation": {
    "tiers": [
      {
        "id": "hostile",
        "min_reputation": -1000
      },
      {
        "id": "neutral",
        "min_reputation": 0
      },
      {
        "id": "trusted",
        "min_reputation": 1000
      }
    ]
  }
}
```

上述数值只用于说明格式，不代表 AUI 的最终平衡数值。

## 4. 顶层字段

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | :---: | --- | --- |
| `schema_version` | 整数 | 是 | 当前为 `1` | 制造商定义格式版本。 |
| `code` | 字符串 | 是 | 建议 2～8 个大写字母或数字 | 用于型号、标识和紧凑 UI 的制造商代码。 |
| `display_name` | Component | 是 | 必须可解析 | 制造商显示名称。 |
| `description` | Component | 否 | 默认为空 | 制造商定位和世界观描述。 |
| `container_traits` | 对象 | 否 | 省略时使用中性值 | 制造商旗下全部货柜容器的共性。 |
| `reputation` | 对象 | 否 | 当前仅预留阶段结构 | 制造商声望等级规则。 |

## 5. container_traits

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | ---: | --- |
| `capacity_multiplier` | 数字 | `1.0` | 对旗下货柜标称容量的通用修正。 |
| `empty_mass_multiplier` | 数字 | `1.0` | 对货柜空质量的通用修正。 |
| `durability_multiplier` | 数字 | `1.0` | 对货柜最大耐久的通用修正。 |
| `value_multiplier` | 数字 | `1.0` | 对货柜空柜基准价值的通用修正。 |
| `cargo_modifiers` | 货物 ID 到修正对象的映射 | `{}` | 对指定货物的专用容量修正。 |
| `special_designs` | 词条 ID 数组 | `[]` | 制造商旗下所有货柜共有的运输保护。 |
| `design_defects` | 词条对象数组 | `[]` | 制造商旗下所有货柜共有的设计缺陷。 |

所有倍率必须是有限非负数。具体上限在实现前根据物理质量和整数溢出边界统一确定。

### 5.1 指定货物容量修正

```json
{
  "cargo_modifiers": {
    "cargoverse:ore": {
      "capacity_multiplier": 1.3
    }
  }
}
```

该修正只在具体货柜的 `allowed_cargo` 已经包含相应货物时生效。它不能将原本不允许装载矿物的货柜变成矿物货柜。

## 6. 制造商数值解析

对于货柜容器定义 `container` 和它引用的制造商 `manufacturer`：

```text
最终基准容量 =
floor(container.capacity
      × manufacturer.capacity_multiplier)

指定货物的最终容量 =
floor(最终基准容量
      × manufacturer.cargo_modifiers[cargo].capacity_multiplier)

最终空质量目标 =
container.empty_mass
× manufacturer.empty_mass_multiplier

最终最大耐久 =
container.max_durability
× manufacturer.durability_multiplier

最终空柜基准价值 =
round(container.base_value
      × manufacturer.value_multiplier)
```

若某货物没有专用修正，其专用容量倍率为 `1.0`。

## 7. 声望定义与玩家状态

制造商 JSON 只保存声望规则，不保存任何玩家的当前声望分数。

```text
ManufacturerDefinition.reputation
    └─ 定义阶段 ID、阈值和未来效果

PlayerManufacturerReputationSavedData
    └─ 保存玩家 UUID + 制造商 ID + 当前分数
```

声望阶段示例：

```json
{
  "reputation": {
    "tiers": [
      {
        "id": "neutral",
        "min_reputation": 0
      },
      {
        "id": "trusted",
        "min_reputation": 1000
      }
    ]
  }
}
```

阶段必须按 `min_reputation` 从小到大严格递增，`id` 不得重复。

当前只确定阶段容器结构，不在本版设计中确定声望获取方式、阶段修正器、解锁规则和价格折扣。这些字段在声望系统设计完成后再增加，不预留无法校验的通用 JSON 对象。

## 8. 后续扩展原则

制造商后续功能应使用作用域明确的顶层字段：

```json
{
  "container_traits": {},
  "equipment_traits": {},
  "shop_rules": {},
  "contract_rules": {},
  "reputation": {}
}
```

禁止将未来的不同系统全部放入一个缺少作用域和类型约束的 `modifiers` 映射。
