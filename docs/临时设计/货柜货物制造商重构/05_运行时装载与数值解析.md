## 1. 货柜实例

玩家长期持有的货柜实例建议保存：

```text
CargoContainerInstance
├─ owner_id
├─ instance_id
├─ container_definition_id
├─ manufacturer_id
├─ physical_cargo_id
├─ asset_status
├─ current_durability
├─ max_durability
├─ resolved_container_snapshot
└─ load                       可为空
```

`manufacturer_id` 可以从容器定义推导，但仍建议写入实例快照，用于在定义被移除或更名后保留归属信息。

`resolved_container_snapshot` 保存购买或生成时已解析的：

- 显示名称和描述。
- 结构模板 ID。
- 规格和接口类型。
- 最终基准容量和各货物专用容量。
- 最终空质量目标。
- 最终最大耐久。
- 最终空柜基准价值。
- 可用货物列表。
- 解析后的特殊设计和设计缺陷。

数据包重载不追溯修改已有货柜快照。制造商声望造成的价格、商店或权限效果属于玩家当前状态，在交易时动态计算，不写入货柜静态快照。

## 2. 当前装载

每个货柜实例最多存在一个 `CargoLoad`：

```text
CargoLoad
├─ cargo_id
├─ amount
├─ integrity
├─ max_integrity
├─ loaded_at_game_time
├─ source_trade_point_id
├─ purchase_unit_price
├─ material_snapshot
├─ resolved_affixes
└─ affix_state
```

| 字段 | 说明 |
| --- | --- |
| `cargo_id` | 当前装载的固定货物 ID。 |
| `amount` | 当前货物单位数，必须大于 `0`。 |
| `integrity` | 当前货物完整度。 |
| `max_integrity` | 装载时快照的货物最大完整度。 |
| `loaded_at_game_time` | 本批当前运输周期的开始时间。 |
| `source_trade_point_id` | 货物来源贸易点，用于利润、经验和任务校验。 |
| `purchase_unit_price` | 实际装货时支付的单位价格，只用于历史、利润和退款核算。 |
| `material_snapshot` | 装载时货物静态参数快照。 |
| `resolved_affixes` | 结合货物、制造商和货柜后的最终词条定义。 |
| `affix_state` | 限时截止时间、燃烧温度等词条运行状态。 |

货物定义重载不追溯修改已装载货物的 `material_snapshot`。

## 3. 装载状态

货柜只需要以装载字段表示两种主要状态：

```text
load 不存在
    → 空柜

load 存在且 amount > 0
    → 已装载
```

“运输中”不作为必须持久化的独立状态。已装载货柜可以在产地停放，系统不必假定它已经开始移动。限时、冷链等运输要求从装载成功时开始计算。

## 4. 装货校验

向货柜装载新货物前必须按顺序校验：

1. 玩家是容器所有者，或具有明确授权。
2. 物理货柜位于装货终端允许的扫描范围内。
3. 货柜资产未报废，且当前不处于其他交易操作中。
4. `cargo_id` 存在于货柜快照的 `allowed_cargo`。
5. 若货柜已装载，其 `cargo_id` 必须与本次货物相同。
6. 追加后数量不超过该货物的最终容量。
7. 贸易点拥有足够货物库存。
8. 玩家拥有足够货币，并满足许可证、声望或合同限制。
9. 最终词条可成功解析，且不超过词条数量上限。

所有校验成功后才进入交易写入阶段。

## 5. 追加相同货物

追加相同货物时：

```text
new_amount = old_amount + added_amount

new_integrity =
(old_amount × old_integrity
 + added_amount × added_integrity)
÷ new_amount
```

`loaded_at_game_time` 不得因追加新货物而向后重置，否则玩家可以通过反复追加少量货物刷新限时运输。

默认规则：

```text
new_loaded_at_game_time =
min(old_loaded_at_game_time, added_loaded_at_game_time)
```

对于词条已建立截止时间的情况，取旧货物和新货物中更早的截止时间。

若两批货物的货物快照版本、词条参数或来源交易条款不同，暂不允许直接合并。是否引入货物分批状态留待实现阶段评估。

## 6. 词条解析

最终词条按以下顺序解析：

```text
1. 读取货物 transport_requirements
2. 移除制造商 special_designs
3. 移除货柜型号 special_designs
4. 合并制造商 design_defects
5. 合并货柜型号 design_defects
6. 按词条 ID 去重
7. 校验最终词条数量不超过 5
8. 将词条完整参数写入 CargoLoad 快照
```

特殊设计在设计缺陷之前生效。因此同一 ID 同时存在于保护和缺陷时，词条会被先移除，然后由缺陷重新添加。

### 6.1 重复词条的合并原则

运行时只保存一个词条 ID。货物要求与设计缺陷使用同一 ID 时，由每个词条处理器实现专用合并规则。

初步通用原则：

- `damage_per_second` 相加。
- `damage_amount` 相加。
- `time_tick` 和其他持续时间上限取更短值。
- 允许的光照、高度、倾斜等阈值取更严格值。
- 不能使用通用原则的参数由具体词条显式定义。

当货物和缺陷定义了参数完全相同的累计伤害词条时，伤害参数相加后自然形成双倍完整度损失。

## 7. 容量解析

某个货柜对某种货物的最终容量：

```text
capacity_for(cargo) =
floor(container.capacity
      × manufacturer.container_traits.capacity_multiplier
      × manufacturer.container_traits
          .cargo_modifiers[cargo].capacity_multiplier)
```

缺少专用货物修正时使用 `1.0`。最终值不得为负数。

容量修正只决定可以装载的货物单位数，不改变货物的单位质量和单位价值。

## 8. 物理质量刷新

每次装货、追加、部分卸货、完全卸货或报废货物后，都必须根据权威运行时数据重新计算目标质量：

```text
target_mass =
resolved_empty_mass
+ load.amount × load.material_snapshot.unit_mass
```

空柜时只使用 `resolved_empty_mass`。

重新分配质量占位方块后，必须通知物理引擎刷新质量。货柜运行时存档是质量的权威来源；物理层可以在区块重新加载时根据它重建质量。

## 9. 贴花与调度刷新

装载变化后还需要重新生成：

- 货物类型贴花。
- 最终运输要求贴花。
- 词条持续检测调度。
- 词条运行状态。

空柜必须：

- 恢复空柜或无货物贴花。
- 清除当前货物词条贴花。
- 从词条持续调度索引退出。
- 丢弃已卸货货物的限时、温度和伤害累积状态。

## 10. 市场价格与价差

货物定义只有一个 `base_value`，但贸易点必须分别定义或解析市场出售加价和收购折价：

```text
local_market_value =
cargo.base_value
× trade_point.local_price_modifier
× trade_point.dynamic_price_modifier

player_load_unit_price =
ceil(local_market_value
     × trade_point.ask_multiplier)

player_unload_unit_price =
floor(local_market_value
      × trade_point.bid_multiplier
      × integrity_reward)
```

建议约束：

```text
ask_multiplier >= 1.0
0.0 <= bid_multiplier <= 1.0
```

价差属于贸易点市场而不是货物定义。它用于防止玩家在同一贸易点立即装货和卸货获得无风险收益。

许可证经验、繁荣度经验和运输任务进度也应校验来源贸易点与当前贸易点不同，或满足最低运输距离、时间条件，避免原地反复交易刷取成长数值。

## 11. 装卸事务边界

一次装货或卸货操作同时涉及：

- 玩家货币。
- 贸易点共享货物库存。
- 货柜实例装载。
- 贸易点动态价格和统计。
- 货柜物理质量、贴花和词条调度。

服务端必须通过统一装卸服务处理，不得由终端、库存和货柜代码分别扣减。

业务存档中的货币、库存和装载结果是权威交易结果。物理质量、贴花和调度状态应设计为可根据权威数据重建，即使区块未加载或刷新中断也不会丢失货物。
