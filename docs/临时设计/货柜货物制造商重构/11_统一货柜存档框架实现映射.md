## 1. 新的唯一存档权威

货柜资产、当前装载和物理装配不再分别写入两套互相引用的存档。新的全局存档名为：

```text
cargoverse_container_assets_v1
```

该存档保存在主世界全局数据中，每个货柜由一个 `CargoContainerInstance` 完整表示，并以稳定的 `container_id` 建立玩家归属和物理空间索引。

```text
CargoContainerInstance
├─ owner / instance_id / container_definition_id
├─ Container
│  ├─ 型号与显示快照
│  ├─ 容量、空重和设备价值
│  └─ durability / max_durability
├─ CargoLoad（空柜时不存在）
│  ├─ material_id / units / cargo_mass
│  ├─ integrity / max_integrity
│  ├─ 货物价格、经验、结算货币和装载时间
│  ├─ 货物词条定义快照与运行状态
│  └─ 货物状态、失效原因和状态时间
├─ Physical（未生成或已拆除物理结构时不存在）
│  ├─ dimension / physics provider / physics id
│  └─ template / origin / size / block_count
└─ 货柜资产状态、创建时间和来源终端
```

`CargoInstanceSnapshot`、`CargoRuntimeSavedData.Entry` 和 `CargoBoxSavedData.CargoBoxEntry` 目前只作为旧 GUI、物理接口和迁移代码的兼容 DTO。它们不再是新存档的写入权威。

## 2. 货物与货柜状态边界

现有词条体系只允许修改 `CargoLoad`：

- 词条定义 ID、定义快照和每个词条的运行状态全部位于 `CargoLoad`。
- 限时、易碎、温度、受潮、倾斜、光照等词条只损伤货物完整度。
- 完整度归零时标记的是 `CargoLoad.status = invalid`，不会把货柜资产标记为失效，也无法修改货柜耐久。
- 失效货物不能继续交易或追加装载；卸空后整个 `CargoLoad` 被移除，货柜恢复为空柜资产。
- `Container` 和 `Physical` 的新存档节点均不包含货物词条字段。

未来的货柜专用词条不得复用 `CargoLoad` 的词条字段和处理器；应在货柜资产层建立独立定义、运行状态与调度入口。

## 3. 旧存档迁移

首次读取新存档时会扫描旧的：

```text
cargoverse_cargo_runtime
cargoverse_cargo_boxes
```

迁移会按旧 `ship_id` 合并运行时货物记录与物理记录，并写入统一实例：

- 旧货物类型、数量、完整度、价格、经验和词条状态迁移到 `CargoLoad`。
- 旧货物的 `invalid` 状态迁移到 `CargoLoad`，货柜本体初始化为活动状态。
- 旧实例没有货柜耐久时，按当前货柜型号解析出的最大耐久初始化。
- 旧物理提供者、物理 ID、模板和包围盒迁移到 `Physical`。
- 只有物理记录而没有运行时记录的旧货柜也会建立统一资产记录。

迁移完成后写入 `LegacyMigrationComplete`，以后不会重复导入。旧存档文件不会被删除或覆盖，可用于回退和人工排查。如果发现旧记录但数据包货柜定义尚未完成加载，本轮迁移会延后，避免用空定义永久完成错误迁移。

## 4. 写入与索引规则

- 所有业务写入统一经过 `CargoInstanceRepository`，最终进入 `CargoContainerSavedData`。
- 装货直接替换实例的 `CargoLoad`，卸货使用 `CargoLoad.EMPTY` 清空装载。
- 空柜购买直接创建统一实例，不再创建旧运行时存档记录。
- 物理生成、质量刷新、空间扫描和待移除队列均读取统一存档中的 `Physical`。
- 玩家持有索引、词条调度索引和失效货物索引由统一记录派生，不再进行运行时/物理孤儿配对清理。

## 5. 当前兼容边界

- 旧运输终端、货物详情和部分删除/回购代码仍读取兼容 DTO，但 DTO 是由统一实例即时生成的。
- 物理适配器仍接受旧 `CargoBoxEntry` 类型；其中数据来自 `CargoPhysicalState` 的即时视图，而不是旧物理存档。
- 旧存档类和旧编解码器暂时保留用于读取历史世界；待实际存档迁移验证完成后，再单独删除兼容层。
- 新存档格式版本为 1；后续字段变化必须在 `DataVersion` 或实例 `FormatVersion` 上增加显式迁移，不允许静默重解释旧字段。

## 6. 已覆盖的回归验证

- 货柜、货物装载和物理状态的统一 NBT 往返。
- 空柜不写入 `CargoLoad` 节点。
- 货物词条仅出现在 `CargoLoad`，不进入 `Container` 或 `Physical`。
- 货物失效后货柜资产仍为活动状态。
- 货物失效状态、原因和时间只在 `CargoLoad` 中往返。
- 业务代码不得绕过仓储入口直接写新旧 SavedData 的架构检查。
