# 贸易点产出货物结构切换

> 历史记录（2026-08-28 整编标记）：本页保留原设计／阶段实现文字，可能含已替代字段、版本和当时的验收结论，不是当前数据包规范。现行“已实现／预留／待验收”边界见[正式文档中心](../../README.md)和[状态清单](../../00_重构状态与验收清单.md)。
> 本页原文中的“正式文档暂不合并／当前实现契约”等表述仅代表记录当时状态；现行契约已分阶段整编。

> 分类重构补充：本文涉及的旧 CargoType、cargo_materials、单层货物 ID 与旧存档版本，以 [CargoClass / CargoGood 二级分类重构](16_货物二级分类重构.md) 为准；其余设计及历史记录保留。

> 本文记录 2026-08-26 完成的贸易点出售数据切换。贸易点不再定义、抽取或存储完整货柜商品，只定义可以产出和收购的货物。

## 1. 新的定义边界

```text
TradePointDefinition
├─ sales.resources
│  └─ 每种产出货物的价格修正、繁荣度门槛、自然增长、库存上限和生产配方
└─ acquisitions.resources
   └─ 每种收购货物的价格修正、繁荣度经验修正、门槛和消耗库存
```

当前固定货物体系中，`sales.resources` 的键与 `CargoType` 一一对应，并解析为同路径的 `CargoMaterialDefinition`，例如 `ore` 对应 `cargoverse:ore`。

因此，贸易点是否出售某种货物只由以下条件决定：

1. 货物存在于 `sales.resources`。
2. 对应 `CargoMaterialDefinition` 存在。
3. 当前贸易点繁荣等级达到货物门槛。
4. 当前产出库存至少还有一个单位。

## 2. 已删除的定义字段

以下字段已从 `sales` 中删除，并在数据加载时明确拒绝：

- `list_count_by_level`
- `cargo_pool`
- `cargo_pool.entries[].cargo_definition`
- 货柜模板权重、固定可用标记和货柜模板繁荣度门槛

贸易点定义不再引用 `cargo_containers` 或旧 `cargo_definitions`。

## 3. 运行时库存

贸易点运行时只保存货物单位库存：

```text
TradePointState
├─ outputCargoUnits[cargoType]  贸易点产出库存
└─ inputsCargoUnits[cargoType]  贸易点消耗/生产输入库存
```

装货时直接扣除对应产出货物的单位数；卸货时直接增加对应收购库存。系统不再执行以下换算：

```text
货柜模板 + 货物类型 → 成品货柜出售槽位
货物单位库存 ÷ 模板装载量 → 可出售货柜数量
```

## 4. 装载终端解析

装载终端打开时执行：

```text
贸易点 sales.resources
        ↓
当前贸易点全部产出货物
        ↓
逐项检查所选货柜的 CargoCompatibilitySnapshot
        ↓
生成可选或禁用的装载选项
```

货柜不兼容、已装载其他货物、容量已满、库存不足或繁荣度不足时，货物仍可显示，但选项不可交易。这里生成的是即时界面判定，不是持久化的出售货柜列表。

## 5. 货柜搭建台边界

货柜搭建台制造空货柜，报价直接来自 `cargo_containers` 与制造商解析结果。它不扣除贸易点货物产出库存，也不读取 `sales.resources` 来拼接货柜商品。

设备购买仍可以计入贸易点交易统计，但设备供应与货物供应是两套独立系统。

## 6. 已删除的旧运行结构

- `CargoSaleDefinition`
- `TradePointSaleSlot`
- `TradePointDynamicState`
- `TradePointDynamicStateStore`
- `TradePointDynamicStateService`
- `CargoSpawnerSaleRound`
- `CargoSpawnerStockService`
- SavedData 中的 `TradePointDynamicStates` / `SaleSlots`

贸易点网络快照中的 `initialListCount` 和 `displayCount` 也已删除。
