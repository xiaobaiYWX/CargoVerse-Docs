# 货柜运行时结构完全切换

> 历史记录（2026-08-28 整编标记）：本页保留原设计／阶段实现文字，可能含已替代字段、版本和当时的验收结论，不是当前数据包规范。现行“已实现／预留／待验收”边界见[正式文档中心](../../README.md)和[状态清单](../../00_重构状态与验收清单.md)。
> 本页原文中的“正式文档暂不合并／当前实现契约”等表述仅代表记录当时状态；现行契约已分阶段整编。

> 分类重构补充：本文涉及的旧 CargoType、cargo_materials、单层货物 ID 与旧存档版本，以 [CargoClass / CargoGood 二级分类重构](16_货物二级分类重构.md) 为准；其余设计及历史记录保留。

> 本文记录 2026-08-26 完成的运行时 v2 切换。本方案是当前代码的唯一运行时结构，不兼容也不迁移旧存档。

## 1. 唯一权威记录

```text
CargoContainerInstance
├─ containerId / ownerId / instanceId / containerDefinitionId
├─ CargoContainerSnapshot equipment
├─ durability
├─ CargoLoad? load
├─ CargoPhysicalState? physical
├─ status / invalidReason
└─ createdGameTime / statusSinceEpochMillis / sourceTerminal
```

一个货柜资产只对应一条 `CargoContainerInstance`。玩家归属、设备参数、当前货物、物理装配和生命周期不再分散到多套 SavedData 中。

## 2. 设备快照

`CargoContainerSnapshot` 是货柜创建时固化的设备事实：

- 显示名、描述和结构模板。
- 制造商 ID、尺寸级和接口类型。
- 持有上限、通用容量、空重、最大耐久和设备价值。
- 每种可运货物的 `CargoCompatibilitySnapshot`，其中固化了该货物对应的最大装载量。
- 购入货币和购入成本。

当货柜实例已存在时，物理质量、装载限制和交易界面都以这份快照为准，不再把货柜反解析成旧货物模板。

## 3. 货物装载

```text
CargoLoad
├─ CargoMaterialSnapshot material
│  ├─ materialId / displayName
│  ├─ unitMass / baseValuePerUnit
│  ├─ licenseExperiencePerUnit / prosperityExperiencePerUnit
│  ├─ baseIntegrity
│  └─ affixIds / affixDefinitions
├─ units / integrity
├─ affixState
├─ settlementCurrencyId / acquisitionCost
└─ loadedGameTime / status / invalidReason / statusSinceEpochMillis
```

- 空柜不写入 `Load` 节点。
- 总质量、总基础价值和总经验由单位数值与数量计算，不再重复存储多份总量。
- 现有词条的定义快照和运行状态只属于货物。
- 货物失效只改变 `CargoLoad`；卸空后货柜仍是可复用的活动资产。

## 4. 物理状态

`CargoPhysicalState` 只保存维度、物理提供者、物理 ID、模板、原点、尺寸和方块数。它不包含货物种类、价格、词条、玩家归属或交易状态。

物理适配器、空间索引、扫描终端、移除队列和质量刷新都直接使用 `CargoPhysicalState`。

## 5. 存档和无兼容策略

新的全局存档名是：

```text
cargoverse_container_runtime_v2
```

- SavedData `DataVersion = 2`。
- 单条实例 `FormatVersion = 2`。
- 版本不等时直接拒绝读取，不尝试字段兜底或旧数据转换。
- 旧 `cargoverse_cargo_runtime`、`cargoverse_cargo_boxes` 和 v1 统一存档不会被扫描。
- `LegacyMigrationComplete`、`fromLegacy` 和迁移流程已删除。

因此此次切换后，旧世界中的货柜运行时记录会被视为不存在，这是明确设计行为。

## 6. 已删除的旧运行时结构

- `CargoRuntimeSavedData`
- `CargoRuntimeEntryCodec`
- `CargoRuntimeIndex`
- `CargoRuntimeOrphanTracker`
- `CargoRuntimeLocationIndex`
- `CargoBoxSavedData`
- `CargoInstanceSnapshot`
- 旧的 `CargoDefinitionSpawner`

GUI 仍需要扁平化的网络展示数据，已改用不参与持久化和业务判定的 `CargoDisplaySnapshot`。

## 7. 业务切换范围

- 货柜搭建台制造与管理员生成命令直接创建新资产。
- 装载终端将货物定义固化为 `CargoMaterialSnapshot`。
- 卸货终端的价值、经验、质量和完整度结算直接读取已装载快照。
- 运输终端、扫描器、货物详情、回购、删除和词条调度直接读取 `CargoContainerInstance`。
- 空间索引和 Sable 物理适配器不再接受旧 `CargoBoxEntry`。

## 8. 验证

- 设备、货物快照、装载状态和物理状态的 NBT 往返。
- 不支持的 SavedData 版本和实例版本会被拒绝。
- 玩家归属索引、待移除物理队列和分批空间索引。
- 货物失效后货柜仍可卸空并重复使用。
- 生产代码已不再引用旧 Runtime、Box 或 InstanceSnapshot 类。
