# 基础测试货柜数据

> 历史记录（2026-08-28 整编标记）：本页保留原设计／阶段实现文字，可能含已替代字段、版本和当时的验收结论，不是当前数据包规范。现行“已实现／预留／待验收”边界见[正式文档中心](../../README.md)和[状态清单](../../00_重构状态与验收清单.md)。
> 本页原文中的“正式文档暂不合并／当前实现契约”等表述仅代表记录当时状态；现行契约已分阶段整编。

> 分类重构补充：本文涉及的旧 CargoType、cargo_materials、单层货物 ID 与旧存档版本，以 [CargoClass / CargoGood 二级分类重构](16_货物二级分类重构.md) 为准；其余设计及历史记录保留。

> 本文记录第一批测试基线以及随后完成的旧货柜定义批量迁移。数值用于跑通制造、装载、卸载、制造商修正和统一存档流程，不代表最终经济平衡。

## 1. 覆盖范围

旧 `cargo_definitions` 中 23 个系列、52 个具备实际 NBT 结构的型号，现已全部建立对应的 `cargo_containers` 定义：

| 制造商 | 基础测试型号 |
|---|---|
| AUI | Atlas S/M/L/X、Hermes S/M/L、Nomad L/X、Titan L/X/XL、Vulcan M/L/X |
| SPL | Courier S/M、Cargo M/L、Express S |
| DMC | Boreal M/L、TitanHaul L/X/XL、CoreVault S/M |
| VBS | BioPod S/M、Harvest M/L、Eden X/XL |
| HEC | Apollo M/L、Reactor L/X、CryoVault S/M |
| HRI | Archive S/M、Explorer S/M/L |
| BDS | Bastion L/X、Sentinel S/M、Fortress XL |
| REX | Salvage S/M/L |

覆盖规格为 S、M、L、X、XL。型号名称与资源 ID 中保留历史接口缩写作为显示和策划命名，但货柜定义与运行时均不再保存或解析接口参数。

## 2. 默认字段

每个测试货柜均已给出：

- 真实存在的结构模板 ID；
- 制造商引用和规格；
- 数据包货币组引用；
- 最大持有数量；
- 基础制造价值；
- 基础容量、空重和最大耐久；
- 从旧 `cargo_type` 迁移的可装载货物集合；
- 直接写入 JSON 的名称与完整说明，不再使用语言键；
- 从旧 `blocked_affixes` 迁移的 `special_designs`；
- 从旧 `base_affixes` 迁移的 `design_defects`；
- `migrated_legacy` 与系列用途标签。

数值是应用制造商参数之前的型号基础值。机械台显示和实际装载容量仍通过 `CargoDataSet` 叠加制造商倍率及货物专属倍率，例如：

```text
DMC Boreal SD-M 基础矿石容量 24
× DMC ore capacity_multiplier 1.3
= 实际矿石容量 31（向下取整）

VBS Harvest LM-M 基础农业容量 28
× VBS agriculture capacity_multiplier 1.25
= 实际农业容量 35
```

## 3. 缺失型号数值补齐规则

原定义没有空柜制造价格、标称容量和空柜质量。迁移时保留每个系列已经调试过的代表型号作为锚点，并沿用旧规格常量计算同系列的其他规格：

| 规格 | 容量与空重系数 | 制造价格系数 |
|---|---:|---:|
| S | 10 | 1.0 |
| M | 20 | 2.2 |
| L | 40 | 4.5 |
| X | 80 | 8.5 |
| XL | 160 | 15.0 |

计算时使用“目标规格系数 ÷ 锚点规格系数”，不会修改已经存在的 23 个锚点数值。缺失型号沿用同系列锚点的最大耐久，持有上限则采用旧定义的原值。

## 4. 测试边界

- 52 个旧型号均存在一一对应的新定义。
- 52 个型号合计至少支持一次全部 20 种固定货物。
- 每家制造商至少有一个可购买测试货柜。
- 所有定义均指向随模组打包的 NBT 结构。
- 当前 `special_designs` 和 `design_defects` 是旧货物运输词条配置的等价迁移，仍只参与装入货物后的货物词条解析。
- 后续加入货柜专用词条体系时，应使用独立字段和运行时状态，不能复用上述货物词条字段。

迁移核对完成后，旧 `cargo_definitions` 源文件及其加载器已删除。货柜搭建台和新运行时只读取 `cargo_containers`；原 `cargo_value_constants` 的货物数值与运输要求职责由 `cargo_materials` 接管，规格和制造商修正由 `cargo_containers` 与 `manufacturers` 接管。
