## 1. 目录与标识

```text
data/<namespace>/trade_points/
├─ trade_points_definitions/trade_points_type/
│  ├─ resource/<分类>/<名称>.json
│  ├─ factory/<分类>/<名称>.json
│  └─ market/<分类>/<名称>.json
├─ type/production_line_pools/
│  ├─ resource/<分类>/<池名>.json
│  ├─ factory/<分类>/<池名>.json
│  └─ market/<分类>/<池名>.json
└─ shop_definitions/<贸易点定义相对路径>.json
```

- 贸易点 ID 从 `trade_points_type/` 后取完整路径，例如 `cargoverse:resource/general/default`。
- 分组使用 `resource`，将请求中的 `esource` 视为拼写遗漏。
- 三个分组固定；至少有一个分类目录，可继续嵌套；命名空间可由数据包添加。
- 生产线池保留上一版指定的 `type/production_line_pools` 路径，与新贸易点目录独立扫描，不再混在一个加载列表中筛选。
- 旧 `trade_points/type/resource/default.json` 已迁移，新默认 ID 同步到结构绑定默认值与商店镜像绑定。
- 旧 `sales`、`acquisitions`、内嵌生产/库存配置及旧次数窗口活跃度不再参与解析，也不做旧字段转换。

## 2. 定义结构

实际无注释 JSON 示例见：
`src/main/resources/data/cargoverse/trade_points/trade_points_definitions/trade_points_type/resource/general/default.json`。

| 分区 | 实现职责 |
| --- | --- |
| 基础字段 | schema_version=1，直接显示 display_name，保留 node_role，ticks_per_day，tech_level |
| prosperity | 初始繁荣等级与逐级经验门槛 |
| activity | 当日有效交易价值、日负载上限、双向权重、响应率、生产倍率范围 |
| pricing | 贸易点收购/出售倍率；可独立关闭动态价格 |
| inventory_profile | 输入/输出槽位数、每槽基础容量、每级容量增幅 |
| production_pools | 按数组顺序执行 fixed / random 池引用 |
| modules | 预留对象数组，保存原始参数，不执行模块，也不生成库存 |

输入/输出槽以**具体 CargoGood**为单位，同类不同货物或不同命名空间不会合并：

```text
实际每槽容量 = capacity_per_slot × (1 + 当前繁荣等级 × capacity_growth_per_level)
```

默认输入每槽 120t，输出每槽 160t，每级增长 25%。所有槽初始库存为 0；未添加未定义的“初始库存”参数。

价格方向以贸易点为准：

- `buy_price_multiplier`：贸易点从玩家收购，即卸货价。
- `sell_price_multiplier`：贸易点向玩家出售，即装货价。
- `dynamic_price.enabled=false` 时不应用动态修正，但仍应用上述基础倍率。
- `dynamic_price` 支持只写 `enabled`，其余字段使用 0.7 / 1.3 / 0.03 / 0.05 默认值。
- 活跃度不再参与价格计算。

数量和比例严格校验，不把字符串数字、负值、非有限值静默转换。输入/输出各最多 256 个槽；最多 256 个池引用、合计 1024 条请求产线。固定模式必须指定 line_ids，随机模式必须指定 draw_count，混用字段或引用不存在的池/固定内部 ID 会使本轮加载失败。

## 3. 初始化解析

首次创建贸易点经济实例时解析产线；实例 ID 提供稳定随机种子。只在初始化判断初始繁荣等级及贸易点 tech_level。

1. 按 production_pools 数组顺序处理，fixed 尝试指定内部 ID，允许 weight=0；random 按正权重无放回抽取。
2. 全局去重键为“完整池 ID + 内部产线 ID”；不同池的同名内部 ID 不冲突。
3. 候选先解析输入：优先复用已有 input_goods；否则尝试新增具体输入。
4. 输入选择顺序固定为科技等级、基础价值、分类常规程度、完整 ID 字典序。
5. 同一货物不能同时出现在输入与输出，输入也不能匹配该候选自身的输出。
6. 在临时集合中完成整条候选校验，失败不占槽，不污染后续候选。
7. 随机阶段输出未满只接收新增输出；输出满但输入未满才允许复用输出；两侧都满停止，包括后续固定引用。
8. 无可用候选时结束当前随机引用，不无限重试。

分类常规程度仅作为科技等级与价值相同后的选择顺序：普通分类 → 环境危害 → 特殊资源/科研样本 → 异常货物 → none。它不改变 CargoClass 的图标或分类定义。

设计稿的状态机示例有“输出未满且无候选时也可进入复用阶段”的表述，本版按最终定稿第 10 条执行：**只有输出槽已满，才允许随机复用输出**。

`all` 仍为标签集合完全一致，`any` 为至少一个标签匹配，空标签列表为不限制标签；都需满足科技范围。消费率为 0 的输入仍要绑定槽位，但不实际扣库存。

## 4. 运行时与日结

持久化的是初始化结果，而非 selector：

```text
TradePointState
├─ 贸易点实例 ID、繁荣等级/经验
├─ activity / lastActivityDay / currentDayTradeValue
├─ productionLayout.selectedLines[]
│  ├─ poolId / lineId / displayName
│  ├─ output: cargoGood + amount
│  └─ inputs[]: cargoGood + consumptionRate + 每批数量
├─ inputsCargoUnits: 具体货物 ID → double 库存
├─ outputCargoUnits: 具体货物 ID → double 库存
└─ 累计交易统计、各货物动态价格状态
```

selectedLines 内嵌具体输入绑定；input_goods/output_goods 由该布局派生，并要求库存键与布局完全一致。NBT 保存产出量和消费率，读取时恢复每批消耗量，不查 selector。

- 产线按保存顺序执行，不发生 output 回流 input。
- 每条线产出与所有输入消耗使用**相同倍率**。
- 输入不足或输出余量不足时，按可执行比例缩小批次；不先扣输入再丢弃溢出产出。
- 库存保留小数，不向上取整产生免费货物；玩家现有整数 t 交易输入方式不变。
- 长时间离线按公式汇总每天生产倍率，再按产线数处理库存；不会按离线天数循环。
- 已有库存高于重载后的新容量时不删除库存，只暂停向该槽继续生产。
- 已保存的产线、绑定、批次量在重载后保持不变；新增/修改 selector 不触发旧点重抽。
- 若某绑定货物在新数据中不存在，该产线暂停，保留库存和绑定；恢复货物后继续运行。
- 升级只改变容量/经验，不在升级时自动抽取高等级新产线。本版未引入重抽接口。

### 活跃度

每次货物交易仅累积：

```text
有效交易价值 = 实际交易 t 数 × CargoGood 基础价值 × 输入/输出方向权重
```

不使用付款金额、折扣或交易点击次数；货柜制造购买不计入货物活跃度。贸易点终端原“近期交易次数”显示已替换为“当日有效交易价值”。

跨日时先结算未结算交易日，再一次性计算其余空白天：

```text
load = clamp(currentDayTradeValue / expectedDailyTradeValue, 0, maxDailyLoad)
first = activity + responseRate × (clamp(load, 0, 1) - activity)
final = first × (1 - responseRate) ^ (elapsedDays - 1)
```

同日或世界时间回退不结算、不清空待结算价值。日结后将 currentDayTradeValue 清零并记录当前日期。

生产倍率为 `min + activity × (max - min)`，用等比级数求和计算离线区间总倍率。文档未定义 random_multiplier 的范围，因此本版固定为 **1.0**，未添加额外随机配置字段。

## 5. 默认测试内容

默认点 `cargoverse:resource/general/default`：

- 固定矿石自然线：每批 12t，无输入。
- 固定木材自然线：每批 6t，无输入。
- 随机候选农业线：每批 12t 农业产品，消耗 6t 化工原料、12t 能源原料。
- 输入槽实际占用 2/4，输出槽实际占用 3/3，不强行填满输入。
- 化工原料补充 `fertilizer`，能源原料补充 `energy` 标签，供此测试链选择；其他货物的原有数据不因此泛化为可消耗物资。
- 0 活跃度时倍率 0.8，自然线一天分别生成 9.6t 矿石、4.8t 木材；没有输入时农业线不产出。
- 原 resource/agriculture/default 示例池仍保留，但不会自动绑定到所有贸易点。

## 6. 加载、存档和网络

货物/制造商/容器 → 生产线池 → 贸易点引用在同一 prepare 阶段校验，整体发布不可变快照。任何一步失败均不发布部分新货物/产线/贸易点数据。

`TradePointDefinitionReloadListener` 现在只作为读取与解析门面，不再独立注册重载监听器；唯一发布入口为 `CargoDataReloadListener`。

- 贸易点 SavedData：**DataVersion=8**，不读取旧版本 7 的状态和注册记录。
- 货柜实例存档格式本次未修改，不删除用户世界文件。
- 网络协议：**10**，客户端与服务端必须同步更新。
- 装载、卸载、贸易点终端和旧收购入口已统一使用运行时库存；旧整柜收购会在支付和移除前检查完整货物量是否放得下。
- 现有商店/搭建台定义系统保留，未擅自合并进预留 modules。

6. 提高繁荣等级、修改数据包并重载，确认容量变化，但已有输入绑定不变。
7. 对库存满、非需求货物、无输入、多个终端同点共享库存分别检查交易限制。
