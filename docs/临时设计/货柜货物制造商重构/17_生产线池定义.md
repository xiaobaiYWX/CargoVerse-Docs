本版独立实现生产线池的数据定义、加载校验、标签筛选、加权抽取和批次消耗量解析。解释性注释仅保留在文档文字中，实际数据包为无注释 JSON，不新增注释解析逻辑。

> 后续接入已完成：贸易点使用新的稳定输入绑定与槽位解析器，见 [贸易点定义与运行时重构](18_贸易点定义与运行时重构.md)。本页第 4 节介绍的独立 draw 接口仍保留，但不再代表贸易点的完整初始化规则。

## 1. 目录和 ID

```text
data/<namespace>/trade_points/type/production_line_pools/
├─ resource/<分类目录>/<池名>.json
├─ factory/<分类目录>/<池名>.json
└─ market/<分类目录>/<池名>.json
```

- 池 ID 由 `production_line_pools/` 后的相对路径组成，不包含 `.json`。
- 例如 `data/cargoverse/trade_points/type/production_line_pools/resource/agriculture/wheat.json` → `cargoverse:resource/agriculture/wheat`。
- 三个分组名固定；分组后必须有分类目录与文件名，分类目录可继续嵌套。分类目录仅用于组织生产线池，不注册 CargoClass，也不限制输出货物必须属于同名分类。
- 任意命名空间均可定义池；同一完整池 ID 按数据包优先级覆盖，不合并 `lines` 数组。
- `lines[].id` 是池内唯一标识，只使用小写字母、数字、下划线、短横线和点。不同池可以使用相同的内部 ID；运行时同时保存池 ID 和内部 ID，不相互混淆。
- 贸易点定义已迁到独立的 `trade_points/trade_points_definitions/trade_points_type`，与生产线池分别扫描，不把池 JSON 当作贸易点。

## 2. 完整结构示例

```json
{
  "schema_version": 1,
  "lines": [
    {
      "weight": 1,
      "id": "wheat_basic",
      "display_name": "初级小麦生产线",
      "min_prosperity_level": 1,
      "tech_level": 1,
      "output": {
        "cargo_good": "cargoverse:agriculture/wheat",
        "amount": 12.0
      },
      "inputs": [
        {
          "consumption_rate": 0.5,
          "selector": {
            "match_mode": "all",
            "tags": ["fertilizer"],
            "min_tech_level": 0,
            "max_tech_level": 2
          }
        },
        {
          "consumption_rate": 1.0,
          "selector": {
            "match_mode": "any",
            "tags": ["energy"],
            "min_tech_level": 0,
            "max_tech_level": 2
          }
        }
      ]
    },
    {
      "weight": 0,
      "id": "wheat_natural",
      "display_name": "自然生长小麦生产线",
      "min_prosperity_level": 0,
      "tech_level": 0,
      "output": {
        "cargo_good": "cargoverse:agriculture/wheat",
        "amount": 6.0
      },
      "inputs": []
    }
  ]
}
```

此示例使用前需定义 `cargoverse:agriculture/wheat`，并为输入货物配置相应标签和科技等级。当前默认 CargoGood 没有独立小麦条目，不能直接把示例放入现有数据包，否则输出引用校验会失败。

## 3. 字段规则

| 字段 | 规则 |
| --- | --- |
| `schema_version` | 必填整数，当前只接受 `1` |
| `lines` | 必填数组，可为空；池内 ID 不可重复 |
| `weight` | 必填有限非负数，支持小数；`0` 保留定义但不参与随机抽取，不是自动兜底 |
| `display_name` | 必填非空字符串，直接显示；不支持多语言组件对象 |
| `min_prosperity_level` | 必填非负整数，调用方繁荣度必须大于或等于它 |
| `tech_level` | 必填非负整数，调用方科技等级必须大于或等于它；不自动改用输出 CargoGood 的科技等级 |
| `output.cargo_good` | 必填完整 CargoGood ID，必须在同轮货物数据中成功定义 |
| `output.amount` | 必填有限正数，一次生产的货物数量，单位 `t`；保留小数 |
| `inputs` | 必填数组；`[]` 表示无输入消耗，不等于禁用生产线 |
| `consumption_rate` | 每项输入必填有限非负数；`0` 不扣该项库存，仍要求 selector 可以解析出具体货物 |
| `selector.match_mode` | 可省略，默认 `all`；只接受 `all` 和 `any` |
| `selector.tags` | 字符串数组，可省略或 `[]`，表示不限制标签；去首尾空白、区分大小写、拒绝重复/空白标签 |
| `selector.min_tech_level` | 必填非负整数，包含下界 |
| `selector.max_tech_level` | 必填非负整数，包含上界，不能小于下界 |

加载上限：4096 个池、每池 1024 条生产线、每条 64 项输入。无效数值和数值溢出报错，不静默截断或修正。

## 4. 标签筛选和抽取

`all` 是标签集合完全一致，不是“至少包含这些标签”。标签顺序不影响匹配。

| selector | 货物 tags | 结果 |
| --- | --- | --- |
| `all: [fertilizer]` | `[fertilizer]` | 匹配 |
| `all: [fertilizer]` | `[fertilizer, organic]` | 不匹配 |
| `any: [fertilizer, energy]` | `[energy, battery]` | 匹配 |
| `all` 或 `any: []` | 任意标签，包括空集合 | 标签条件通过，仍需满足科技范围 |

流程：

1. 在同轮 CargoGood 定义中编译每个 selector 的候选集合。
2. 调用抽取接口时，过滤权重为零、繁荣度不足、科技等级不足，以及任一输入无候选货物的生产线。
3. 在剩余生产线之间按权重随机抽取一条。
4. 每项输入独立、等概率抽取一个符合条件的具体 CargoGood，候选按完整 ID 排序，使相同种子不受注册顺序影响。
5. 返回不可变的批次描述，不修改任何贸易点库存。

候选来自货物定义目录，而不是根据当前库存重新随机挑选；库存是否充足属于后续生产执行层。selector 无候选时不使整池加载失败，只让对应生产线暂不可抽取，后续添加匹配货物并重载即可恢复。

池不存在、池为空、全部权重为零或没有满足条件的生产线时返回空结果，不擅自选中零权重产线。

未知 CargoClass 的 CargoGood 仍按 `none` 分类解析，保留其完整 ID、科技等级与标签，同样可以匹配 selector。不同货物不会因分类兜底而合并。

## 5. 数量关系

每项输入一次生产的消耗量：

```text
输入消耗 = output.amount × consumption_rate
```

示例生产 `12t` 小麦时，肥料消耗 `6t`，能源消耗 `12t`。产出 `1.5t` 且比例为 `0.5` 时消耗 `0.75t`，不取整。

多个输入 selector 若抽中同一 CargoGood，它们的消耗累加，而不是覆盖，也不强制改抽其他货物。例如同一货物两项比例分别 `0.5`、`1.0`，产出为 `12t`，该货物总消耗为 `18t`。

解析结果同时保留每项输入的具体 ID、比例、数量，并提供合并后的每批消耗表。完整库存检查、实际扣减和产出写入已由后续贸易点运行时接入，详见第 18 篇。

## 6. 实现及重载

- `trade.production.CargoGoodSelector`：科技范围和标签匹配。
- `ProductionLineDefinition` / `ProductionLinePoolDefinition`：不可变定义与结构校验。
- `ProductionLinePools`：独立池目录、跨货物引用校验、候选编译及抽取。
- `ResolvedProductionLine`：具体输入和产出解析结果，保留池 ID 与内部 ID。
- `CargoDataReloadListener`：货物、编译后的生产线池与新贸易点定义在同一 prepare 阶段校验，通过后一次发布完整快照；定义删除会替换整个池目录，不保留陈旧候选。
- `TradePointDefinitionReloadListener`：新贸易点定义解析与读取门面，不再单独发布定义。

调用示例：

```java
var snapshot = CargoDataReloadListener.INSTANCE.snapshot();
var selected = snapshot.productionLinePools().draw(
    ResourceLocation.parse("cargoverse:resource/agriculture/default"),
    prosperityLevel, techLevel, randomSource);
```

需要货物与池两种数据的调用方应先捕获一次 `snapshot()`，避免分别读取时跨越一次重载。删除被某条产线引用的输出货物会导致本轮校验失败，即使该产线权重为零；必须同步移除或修改对应产线。失败时不发布新的货物/池组合。

## 7. 默认数据与本版边界

- 提供已可加载的 `resource/agriculture/default.json`，输出当前已有的 `cargoverse:agriculture/agriculture`，自然生产量 `6t`，无输入，权重 `1`。
- `factory`、`market` 目录先保留占位，不增加虚构货物、标签或工厂配方。
- 新增测试覆盖用户示例、多命名空间、三分组目录隔离、数字校验、精确匹配、等级门槛、零权重、消耗累加、未知分类、重载及已有默认数据。
- 第一版曾只提供独立池；现在第 18 篇已接通贸易点引用、稳定输入绑定、按活跃度日结、库存与存档，旧内嵌生产字段已移除。未被贸易点引用的池仍不会自动产生库存。
